## 文档说明

本文档为数据集管理模块的后端代码设计方案，覆盖数据集管理、图片展示与浏览、图片查看与标注、图片上传与管理四大功能模块。

### 设计原则

1. **增量改造**：在现有代码架构基础上进行扩展，复用已有的 Service、Entity 和工具类
2. **低耦合设计**：新增功能通过独立的 Query/VO/Form 类实现，不影响现有接口的兼容性
3. **性能优先**：针对图片列表、搜索、下载等高频场景，设计合理的分页、缓存和异步策略
4. **Redis缓存**：统计信息和场景类型引入Redis缓存，提升查询性能
5. **接口精简**：合并功能相近的接口，减少API数量

## 3. 代码设计与修改方案

### 3.1 数据集下载功能

#### 3.1.1 接口设计

**【建议方案】新增数据集下载接口**

```
POST /api/v1/dataset/{id}/download
功能：创建数据集下载任务（异步打包）

请求参数：
- id: 数据集ID（路径参数）
- organizeByItem: 是否按数据项分目录（可选，默认true）

响应结构：
{
  "code": "00000",
  "data": {
    "taskId": "uuid-xxx",
    "status": "processing",
    "message": "正在打包..."
  }
}
```

```
GET /api/v1/dataset/download/{taskId}
功能：查询下载任务状态

响应结构：
{
  "code": "00000",
  "data": {
    "taskId": "uuid-xxx",
    "status": "completed",  // processing/completed/failed
    "progress": 100,
    "downloadUrl": "http://xxx/download/xxx.zip",
    "expireTime": "2024-12-08 12:00:00"
  }
}
```

#### 3.1.2 Service 层扩展

**SysDatasetService 新增方法**

| 方法签名 | 说明 |
|---------|------|
| `String createDownloadTask(Long id, boolean organizeByItem)` | 创建下载任务，返回taskId |

**【建议方案】新增 DownloadService**

| 方法签名 | 说明 |
|---------|------|
| `void processDownloadTask(String taskId, Long datasetId, boolean organizeByItem)` | 异步处理下载任务 |
| `DownloadTaskVO getTaskStatus(String taskId)` | 获取任务状态 |

**实现逻辑**：

1. 创建下载任务时，生成唯一taskId，存入Redis（状态：processing）
2. 使用 `@Async` 异步执行打包逻辑
3. 获取数据集所有叶子节点的图片文件
4. 使用 ZipOutputStream 打包文件
5. 按数据项名称分目录组织（可选）
6. 打包完成后更新Redis状态为completed，设置下载URL和过期时间
7. 下载链接有效期24小时

#### 3.3.3 配对图片上传

**【建议方案】新增配对上传接口**

```
POST /api/v1/dataset/image/pair
功能：上传配对图片（一张清晰图+多张有雾图）

请求参数（multipart/form-data）：
- datasetId: 数据集ID
- itemName: 数据项名称（可选）
- clearImage: 清晰图文件（必填）
- hazyImages: 有雾图文件列表（至少一张）
- hazeLevels: 对应的雾霾程度列表（与hazyImages一一对应）
- sceneType: 场景类型（可选）

响应结构：
{
  "code": "00000",
  "data": {
    "itemId": 123,
    "clearImageId": 456,
    "hazyImageIds": [457, 458, 459]
  }
}
```

**校验规则**：

| 校验项 | 规则 | 错误码 |
|-------|------|--------|
| 清晰图必填 | clearImage 不能为空 | A0400 |
| 有雾图必填 | hazyImages 至少一张 | A0400 |
| 分辨率一致 | 所有图片宽高必须相同 | A0401 |
| 雾霾程度必填 | 每张有雾图必须指定 hazeLevel | A0400 |
| 文件格式 | 仅支持 jpg/png/gif | A0402 |
| 文件大小 | 单张不超过 10MB | A0403 |

**实现逻辑**（`SysItemFileService.saveImagePair`）：

1. 创建数据项（DatasetItem）
2. 解析清晰图宽高，作为基准分辨率
3. 逐张校验有雾图分辨率是否与清晰图一致
4. 保存清晰图（type=clear）
5. 逐张保存有雾图（type=hazy, hazeLevel=对应值）
6. 如果指定了sceneType，更新所有图片的sceneType并添加到缓存
7. 返回创建结果

```
POST /api/v1/dataset/image/pair/batch
功能：批量上传配对图片（按文件名自动匹配）

请求参数（multipart/form-data）：

{
  "code": "00000",

    "totalGroups": 10,

    "failedGroups": 1,

        "itemId": 123

      {
        "groupName": "scene_002",

```

**文件名匹配规则**：

| 后缀模式 | 识别为 |
|---------|-------|
| `*_clear.*` / `*_gt.*` | 清晰图 |
| `*_hazy.*` | 有雾图（需手动指定程度） |
| `*_hazy_light.*` | 有雾图（轻度） |
| `*_hazy_medium.*` | 有雾图（中度） |
| `*_hazy_heavy.*` | 有雾图（重度） |

**实现逻辑**：

1. 解析所有文件名，按前缀分组
2. 对每组进行配对校验
3. 逐组调用 `saveImagePair` 保存
4. 汇总结果返回

### 4.3 下载任务异常

### 4.4 空数据处理

| 统计数据为空 | 返回各项为0或空Map的统计对象 |

## 5. 安全与性能注意事项

### 5.1 安全方面

- **ID参数校验**：所有ID参数必须为正整数，使用 `@Positive` 注解
- **文件类型校验**：上传时校验文件MIME类型，仅允许图片格式
- **文件大小限制**：单文件不超过10MB，批量上传总大小不超过100MB
- **路径安全**：文件存储路径使用UUID或MD5，防止路径遍历攻击
- **权限控制**：所有接口需要登录认证

### 5.2 性能方面

- **分页查询**：所有列表接口必须分页，默认每页20条，最大100条
- **缓存策略**：
  - 统计信息缓存10分钟
  - 场景类型缓存1小时
  - 下载任务状态缓存24小时
- **异步处理**：大文件打包使用 `@Async` 异步执行
- **懒加载**：图片列表返回缩略图URL，原图按需加载
- **虚拟滚动**：前端配合实现，后端提供分页支持
