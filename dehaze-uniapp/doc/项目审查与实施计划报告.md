## 三、存在缺失或偏差的部分

### 3.1 核心架构缺失（严重）

#### 3.1.1 API 调用层完全缺失 ❌

**设计文档要求**（02-系统架构/04-API规范.md + 11-前端额外说明.md）：
- 统一的 HTTP 请求封装（基于 `uni.request`）
- 请求拦截器：自动添加 `Authorization: Bearer <token>` 头
- 响应拦截器：统一处理 `code: "00000"` 成功逻辑、非零错误码逻辑
- Token 过期自动刷新（RefreshToken 机制）
- 统一错误提示
- 请求取消（防重复提交）
- baseURL 配置（开发 `http://localhost:8989/api/v1`，生产可切换）

**当前实现**：`src/api/` 目录为空，无任何 API 封装。所有页面数据来自 Mock 函数（`fetchDatasets`、`fetchDatasetDetail` 等均为本地 Promise 模拟）。

#### 3.1.2 状态管理层完全缺失 ❌

**设计文档要求**：
- 使用 Pinia 进行状态管理
- 用户状态（token、用户信息、权限列表）
- 全局配置状态（后端地址、主题等）
- 处理任务状态（当前处理任务、队列）

**当前实现**：`src/store/` 目录为空，未安装 Pinia（`package.json` 无 pinia 依赖），未创建任何 store。图像输入页面通过 `getApp().globalData` 和 `uni.setStorageSync` 传递数据，不符合设计规范。

#### 3.1.3 路由守卫完全缺失 ❌

**设计文档要求**：

**当前实现**：`src/routers/` 目录为空，无任何路由守卫。所有页面均可直接访问，无登录保护。

### 5.2 任务拆解与交付标准

---

#### 阶段一：基础设施搭建（P0-紧急）

**目标**：建立 API 层、状态管理层、路由守卫，使项目具备对接后端的能力。

| 任务编号 | 任务名称 | 详细内容 | 预期交付标准 |
|---------|---------|---------|-------------|
| T01 | 安装 Pinia 依赖 | `pnpm add pinia` | `package.json` 包含 pinia 依赖 |
| T02 | 创建 HTTP 请求封装 | `src/api/request.ts`：基于 `uni.request`，包含请求拦截器（自动添加 token）、响应拦截器（统一处理 `code:"00000"` 成功/非零错误）、token 过期自动刷新、错误提示、防重复提交 | 通过单元测试验证拦截器逻辑 |
| T03 | 创建 API 配置 | `src/api/config.ts`：baseURL 配置（开发/生产环境切换）、超时时间、错误码映射 | 配置文件可区分环境 |
| T04 | 创建认证 Store | `src/store/auth.ts`：token 存储（AccessToken + RefreshToken）、用户信息、权限列表、登录/登出 action | 登录后 token 持久化到 Storage，刷新页面不丢失 |
| T05 | 创建用户 Store | `src/store/user.ts`：用户信息、角色、部门、权限标识列表 | 支持权限校验方法 `hasPerm(perm)` |
| T06 | 创建路由守卫 | `src/routers/guard.ts`：页面切换时校验登录状态、token 过期跳转登录、白名单页面放行 | 未登录访问受保护页面自动跳转登录页 |
| T07 | 全局样式文件 | `src/styles/variables.scss`（主题变量）、`src/styles/common.scss`（通用样式类） | 样式变量可在所有页面引用 |
| T08 | main.ts 注册 Pinia | 修改 `src/main.ts`，注册 pinia 实例 | 应用启动无报错 |

**预计工期**：3-5 天

### 核心结论

dehaze-uniapp 项目目前处于 **"UI 原型阶段"**，完成了首页、登录页、数据集管理、图像输入四个页面的视觉还原，但 **缺少所有核心业务逻辑**：

1. **无 API 层**：所有数据为前端 Mock，未对接后端
2. **无状态管理**：无 Pinia，数据传递使用全局变量
3. **无认证流程**：登录页表单为空壳
4. **核心处理流程断裂**：算法选择、去雾处理、效果对比三个核心页面未实现
5. **WebSocket 缺失**：无实时进度推送

要使项目完全契合设计文档，需按上述 9 个阶段、约 50 个任务、预计 29-41 天的工作量进行系统性补全。
