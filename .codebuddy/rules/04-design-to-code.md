# 设计稿还原准则

## 一、定位：设计稿只是视觉参考

设计稿（HTML / Figma / 视觉稿）只传达**视觉效果**：布局、色彩、间距、圆角、阴影、字号、动效意图。它不含工程思想：

- 没有组件边界与组件库概念，没有路由导航、主题机制、状态管理、数据流、权限
- 不关心可复用性、可读性、可维护性；页面可能是一个巨型单文件
- 数据是写死的假数据；图片是占位图；导航、登录注册区往往只是示意
- 暗色模式常常缺失、未打磨，甚至直接照搬会破坏视觉

**因此：还原「视觉意图」，绝不照搬「实现细节」。设计稿的不良代码风格——内联样式、原子类堆砌、自定义 token 体系、整页 CSS——一律不得进入项目代码。设计稿中的元信息（交互说明、开发标注、占位文本、注释框）是写给开发看的指导信息，不是页面内容，不得还原为页面元素。**

### 1.1 元信息与用户可见内容的区分

设计稿里的文字分为两类，必须先区分再还原：

- **用户可见内容**：面向用户的最终文案（标题、正文、按钮文字、提示语），应保留并实现，与真实业务对应的位置替换为真实 API 数据。
- **元信息（面向开发）**：交互说明（"点击此处跳转""此区域展示图片""鼠标悬停显示"）、开发标注（"示例：xxx""占位""TODO"）、注释框、角标标注、示意虚线框中的文字、Lorem/示例数据。**这些是指导开发如何实现交互的参考，不是页面的一部分，必须排除，不得渲染出来。**

判断方法：位于注释框、角标、虚线标注区的文字；含"点击 / 此处 / 区域 / 示意 / 示例 / 占位"等描述性措辞；与业务无关的示例性数据 → 一律视为元信息。拿不准时与产品确认，不臆造、不照搬。

## 二、核心原则

1. **视觉对齐，工程自主**：最终视觉结果向设计稿对齐（色、间距、圆角、字号、排版节奏），实现方式完全由项目工程规范决定。
2. **复用优先，造轮子拒绝**：项目已有的布局、导航、组件、图标、主题机制是默认选择；设计稿中的同类元素一律映射到项目现有能力。
3. **克制设计，代码简单**：不为一个页面定义全局 token，不做无谓抽象，不为视觉还原引入新依赖。
4. **真实业务，拒绝假数据**：页面内容与交互必须对接真实 API 与业务逻辑。

## 三、还原前分析（先想后做）

1. **提取视觉规范**：从设计稿提炼主色、背景/前景色、圆角、阴影、间距节奏、字号层级，形成本页视觉语言；注意区分「设计系统级值」（全站复用，如品牌主色）与「页面级值」（仅本页用）。
2. **划分内容区块**：按语义切分区块（如 Hero、特性、案例、CTA、页脚），每个区块是组件的候选边界。
3. **技术映射**：逐一回答——该区块走哪个路由？数据来自哪个 API？哪些是装饰元素（删除）？哪些是真实交互（保留并实现）？哪些是元信息（交互说明 / 占位文本，识别排除）？设计稿里的导航/登录/占位内容应映射到哪里？

## 四、通用还原准则

### 4.1 技术栈适配

- 必须基于目标项目已集成的框架、组件库、依赖实现；禁止为还原设计稿引入新的第三方库（除非项目评审同意）。
- 交互行为（按钮、表单、弹窗、Toast、上传）使用项目组件库能力实现；禁止自造与组件库重复的基础组件。
- 组件行为差异时，以项目组件库的行为为准，通过样式定制对齐视觉，而非替换组件。

### 4.2 导航与布局

- 项目如果已经包含标准导航系统（路由菜单 / 侧边栏 / 顶栏 / 底部 Tab 等），设计稿中的导航元素**仅作为页面内容示意**，不得直接照搬。
- 设计稿导航指向的页面应映射到项目真实路由
- 页面布局参照项目现有页面结构（页面容器、内容区宽度、间距基准），保持整体视觉一致。

### 4.3 组件化拆分

- 按设计稿区块 + 单一职责拆分组件，页面容器只负责组合与数据编排，不承载具体区块实现。
- 避免超大文件：单文件超过约 400 行（或逻辑与样式都很重）时评估拆分；跨页面复用的 UI 提升为公共组件。
- 组件命名遵循目标项目约定；仅单页使用且不复用的区块保留在页面目录内。

### 4.4 样式规范

- 使用项目本身样式方案（如 SCSS / Less / CSS Modules / styled-components / ThemeData / 样式文件等）与项目 lint 规范；不得不加考虑直接将设计稿的 Tailwind 类、内联样式、整页 CSS 原样搬入。
- 合理使用变量、混合宏、嵌套等语言特性，但遵守「变量克制」（见 4.5）。
- 无意义的纯装饰视觉（装饰性光晕、渐变纹理等）按需简化，保留视觉氛围即可，不为还原设计稿引入复杂技术。

### 4.5 变量与主题（克制原则）

- **禁止将设计稿色板全局 token 化**。分析CSS变量区分全局样式和本地样式，有些设计稿的完整色板多数值只在本页用到，全局定义会造成污染与冗余；令牌体系应由设计系统统一管理，而不是由单个页面引入。
- 只定义页面内**高复用**的值（如主色阶、页面级圆角/阴影），且作用域收敛：组件根元素局部变量 > 页面级变量 > 全局变量，能收敛就不上提。
- 低频值（仅出现一两次）直接使用字面量，遵循《通用项目规则》「禁止定义复用度不高的常量」。
- 语义色（背景/前景/边框/文字）优先使用项目主题变量，保证暗色等主题自动适配。

### 4.6 暗色 / 多主题

- 项目已有完整主题机制时，**优先使用项目主题变量**，设计稿暗色仅作参考。
- 设计稿暗色模式缺失或不完善（对比不足、视觉脏乱）时，以亮色为主实现，暗色交给主题变量自然适配；不要复刻有问题的暗色值。
- 禁止因设计稿引入与项目主题机制冲突的第二套暗色体系。

### 4.7 资源（图片 / 图标 / 字体）

- **禁止占位图**；真实图片按项目资源方案生成并托管（或由后端下发），禁止硬编码外部 URL（遵守项目「外部图片 URL 必须通过配置或后端获取」约束）。
- 图标：优先使用项目组件库/图标库；设计稿独有新图标，加入项目图标体系（SVG symbol 目录、iconfont、VectorDrawable 等），经项目图标组件使用；禁止 Base64 内联。
- 字体：使用项目已有字体体系。

### 4.8 内容与交互（真实业务）

- 数据必须对接真实 API 与状态管理；禁止假数据、假进度、假状态、无意义计算。
- 路由跳转、表单提交、文件上传、权限校验等交互使用项目既有基础设施。
- 设计稿未明确说明的交互按业务合理实现或与产品确认，不臆造逻辑、不加多余兜底。

### 4.9 响应式与多端

- 桌面端按项目断点体系适配（如 md/lg）；移动端与小程序按平台规范（rpx、vw、安全区、沉浸式状态栏）适配。
- 跨端项目注意平台差异 API 与组件差异，以「一套逻辑、平台适配」为目标，不因设计稿引入平台特有写法。

### 4.10 代码质量

- 遵守《通用项目规则》代码编写规范：清晰命名、杜绝重复、禁止过度设计、避免嵌套三元、简单问题简单做。
- 新页面需在项目路由/菜单体系中正确注册；影响架构/API/数据流时同步更新 `dehaze-doc` 文档。

## 五、易错点提醒（对照自查）

以下错误在真实开发中反复出现，照搬设计稿极易触发：

2. **整套色板全局 token 化**：把设计稿十几个颜色定义为全局 CSS 变量，其他页面根本用不到，污染全局、增加心智负担。只在页面作用域定义高复用值。
3. **复刻不完善的暗色模式**：设计稿暗色通常只改了几个背景色，文字对比、层次都未打磨。照搬会导致暗色下文字看不清。交给项目主题机制。
4. **整页内联样式 / 原子类堆砌**：设计稿单文件几万字节、内联样式满天飞。直接复制 = 超大文件 + 样式失控。必须组件化 + 项目样式方案。
5. **占位图与硬编码外链**：设计稿图片是占位/外链，上线即坏。必须替换为项目资源方案生成的真实图片。
6. **假数据假交互**：把设计稿写死的数据、假进度条当业务实现，无法对接后端。数据一律走真实 API。
7. **自造基础组件**：设计稿里的按钮、输入框、标签看着独特，但项目组件库可样式定制。自造会导致风格不一、维护双份。
8. **为视觉引入新依赖**：设计稿用了某动画库/图表库，项目已有替代品。先查项目依赖，禁止直接安装。
9. **不注册路由/菜单**：页面做完却无法访问。新页面必须按项目约定注册，并处理权限白名单。
10. **忽略响应式与暗色走查**：只在亮色宽屏下自测。交付前必须验证暗色、窄屏、移动端。
11. **把交互说明当页面内容**：设计稿的交互标注（"点击此处跳转""此区域显示 XX"）、占位文本、注释框是写给开发看的，不是页面的一部分。还原时必须识别排除，只有用户可见文案才属于页面内容（见 1.1）。
12. **逐像素对齐，写死像素偏移**：设计稿是静态图，浏览器渲染必有差异。不要用 transform、负 margin、微调 hack 逐像素对齐静态稿；还原「视觉感受」而非像素级一致，间距走项目体系。
13. **照搬固定尺寸与断点**：设计稿常按固定宽度（如 1440px）出图。不要将固定宽度、固定 px 间距当作响应式体系搬入，须适配项目断点与布局基准。
14. **照搬装饰动效**：设计稿的 hover 位移、背景动画、滚入动效等是装饰；按需简化，不为还原引入动画库或复杂 CSS 动画。
15. **示例文案当正式文案**：设计稿文案多为占位示例（"XXX 平台""一键 XX"），不是最终文案；正式文案与业务确认或由后端下发，不原样上生产。
16. **只做静态还原，交互逻辑缺失**：筛选、Tab、分页、表单等元素只有外观、点击无真实逻辑。每个可交互元素都要落地真实逻辑（无法实现时明确标注）。
17. **忽略项目既有页面范式**：项目已有同类页面结构（列表 / 表单 / 详情 / 工作台等范式）时，不参考直接新写，导致风格与实现不一致。先复用范式，再差异化。

## 六、工作流

1. **提取**视觉规范（主色、间距、圆角、字号、阴影）
2. **划分**内容区块（即组件边界）
3. **映射**：导航→真实路由、数据→真实 API、装饰→删、交互→保留、元信息→排除
4. **设计**组件树（容器编排 + 区块组件）
5. **实现**并过 lint
6. **走查**对齐（视觉、暗色、响应式、真实数据）
