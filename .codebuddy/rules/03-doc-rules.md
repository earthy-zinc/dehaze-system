# 文档编写、整理与优化

## 一、核心原则

- **单一信息源**：同一事实只写一处
- **引用代替复制**：避免多处维护同一内容
- **按业务领域组织**：不按技术栈拆散同一模块
- **扁平化**：目录深度建议 ≤ 3 层

## 二、项目文档位置

所有项目文档存放在 `dehaze-doc/docs/` 目录下

```
dehaze-doc/docs/
├── 01-产品设计/          # 产品概述、UI-UX 设计规范
├── 02-系统架构/          # 总体架构、环境兼容性、数据库设计、API 规范、测试架构、部署架构
├── 03-模块设计/          # 各模块的需求规格、API 接口、后端/前端实现、测试用例
│   ├── 基础模块/
│   └── 核心模块/
├── 04-项目实现/          # 各技术栈的架构文档
│   ├── 前端/
│   ├── 后端/
│   └── 算法/
└── 05-改造计划/
```
