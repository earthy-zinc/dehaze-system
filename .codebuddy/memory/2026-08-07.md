## dehaze-sdk-js 小程序环境兼容验证 + 测试锁定

### 背景
SDK 同时服务 RN（yarn file: 副本）和 taro/uniapp（pnpm workspace 软链），运行时覆盖浏览器/RN/微信小程序/支付宝/抖音等。昨日 RN 兼容重构后需确认小程序端不回归。

### 验证结论（分支推演）
| 环境 | url | onError | performance | storage |
|------|-----|---------|-------------|---------|
| 微信（wx） | wx.getCurrentPages | wx.onError | wx.getPerformance | wx.getStorageSync |
| uniapp（uni） | uni 分支 | uni.onError | uni.getPerformance | uni.getStorageSync |
| 裸小程序（支付宝/抖音，无 wx/uni/window） | 降级 "" | 跳过 | return | MemoryStorage |
| Taro H5 | isBrowser Web 分支 | window.onerror | PerformanceObserver | localStorage |

全部安全，无回归。`env.ts` 的 isBrowser()/isRN() 均为 typeof 判断，任意环境天然不崩。

### 关键事实
- **ESM 产物动态 require 安全**：tsup/esbuild 把 `require("@react-native-async-storage/async-storage")` 转为 `__require` shim（字符串函数调用），vite/webpack 打包时不做静态解析；运行时非 node 环境抛 "Dynamic require not supported" 被 try-catch 捕获降级 MemoryStorage。taro/uniapp 构建与运行时均安全。
- **node 22 自带全局 navigator**（userAgent="Node.js/22"）：单测模拟裸小程序必须显式 `vi.stubGlobal("navigator", undefined)`，否则 currentUserAgent 兜底分支会返回 Node.js 标识。
- **taro/uniapp 引用 SDK 的方式**：pnpm workspace 软链（pnpm-workspace.yaml 含 dehaze-sdk-js），`npx tsup` 重建 dist 后自动生效；RN 是 yarn v1 `file:` 协议**复制**，需手动 `cp -R dist` 同步 node_modules。

## RN 登录页 API_ERROR 排查（iOS 连不上后端 + 日志不可读）

### 用户疑问
iOS 打开登录页就 API_ERROR 红屏，日志只有 `[dehaze][ERROR] API_ERROR trace_id=xxx` 看不出原因，怀疑 Logger 捕获掩盖了错误。

### 结论：不是 Logger 掩盖
红屏是 `console.error` 经 LogBox 正常暴露的。真正问题是**诊断信息在传递链上丢失**：
1. `reportApiError` message 固定 `"API_ERROR"`，axios 原始 error.message（Network Error / 后端 msg）没带上
2. `ConsoleTransport` 只输出 message+trace_id+error_stack，fields（method/path/status/duration）全部丢弃

### 修复（3+1）
1. **SDK request.ts**：message 改 `API_ERROR: ${error.message}`（业务错误=后端 msg，网络错误=Network Error/timeout）
2. **SDK transports.ts**：ConsoleTransport 用 BASE_KEYS 集合过滤后输出附加字段（key=value 拼接）
3. **RN env.ts（iOS 连不上后端的根因）**：`DEV_HOST` 写死 `10.0.2.2`（Android 模拟器专属宿主机别名，iOS 不可达），改 `Platform.OS === 'android' ? '10.0.2.2' : '127.0.0.1'`
4. **RN login/index.tsx（用户最初诉求）**：验证码区域从 `{captcha && ...}` 条件渲染改为始终展示，加载失败显示"重试"占位可点击——原实现 getCaptcha 失败时输入框静默消失无任何提示

### 验证
iOS 模拟器截图：验证码输入框+图片正常加载（后端 8989 在跑时）。36 单测通过。

### 关键教训
- **Android 模拟器访宿主机用 10.0.2.2，iOS 模拟器与 Mac 共享网络栈用 127.0.0.1**，跨端 RN 项目必须按 Platform 分流 DEV_HOST
- 条件渲染隐藏表单区域时，失败分支必须有可见的降级 UI（重试占位），否则后端故障时用户面对的是"缺功能"假象
- 日志 transport 必须输出附加字段，只输出 message 会让结构化日志失去诊断价值
