## 修复算法列表页状态展示 bug（Vue + React 前端）

**问题**：`dehaze-front-vue/src/views/algorithm/list/index.vue` 页面加载时疯狂调用 `PUT /api/v1/algorithms/{id}/status`，后端返回 400 "终态算法不允许修改状态"。

**根因**：算法有 6 种生命周期状态（0-5），但前端用 `el-switch`（active=1/inactive=0）展示。当算法处于终态（3/4/5）时，`model-value` 不匹配 active/inactive，Element Plus 归一化触发 `@change`，调用 API 失败后 catch 回滚 `row.status` 在 0/1 间切换，再次触发 `@change`，形成无限循环。

**修复**：
- Vue (`dehaze-front-vue/src/views/algorithm/list/index.vue`)：删除 `handleStatusChange`，用 `el-tag` + `statusMap` 展示 6 种状态
- React (`dehaze-front-react/src/pages/algorithm/index.tsx`)：删除 `handleStatusChange` 和 `Switch` import，用 `Tag` + `statusMap` 展示 6 种状态
- 两端详情弹窗同步更新为 Tag 展示

## 修复编辑表单 status 字段（Vue EditDialog + React AlgorithmFormDialog）

**问题**：`EditDialog` 组件（数据集/算法共用）用 `el-switch`（0/1）展示算法状态，无法承载 6 种生命周期状态。

- React (`dehaze-front-react/src/pages/algorithm/components/AlgorithmFormDialog.tsx`)：`Switch` 改为 `Select` 展示 6 种状态
- 新增算法默认状态从 1(测试中) 改为 0(草稿)，符合需求规格

## 修复 options 接口返回空的问题（三端后端）

**问题**：`/api/v1/algorithms/options` 返回空数组，实际数据库中有多条算法记录。

**根因**：三端后端的 options 接口都硬编码 `status = 1`（测试中），但数据库中算法可能处于其他状态（0/2/3/4/5）。同时 Java 的 `addAlgorithm` 强制覆盖 status 为 1，忽略前端传入值。

**修复**：
- Java (`SysAlgorithmServiceImpl.java`)：`getOption()` 过滤条件从 `StatusEnum.ENABLE(1)` 改为 `AlgorithmStatusEnum.PUBLISHED(3)`；`addAlgorithm()` 移除 `sysAlgorithm.setStatus(StatusEnum.ENABLE.getValue())` 覆盖行，尊重前端传入的 status
- Go (`algorithm_repository.go`)：`FindOptions()` 过滤条件从 `status = 1` 改为 `status = 3`
- Python (`algorithm_repository.py`)：`get_algorithm_options()` 过滤条件从 `status == 1` 改为 `status == AlgorithmStatus.PUBLISHED(3)`；`algorithm_service.py`：`create_algorithm()` 的 `status=1` 硬编码改为 `status=data.get("status", 0)`

## 修复 /model/prediction 404 错误（SDK + 前端）

**问题**：前端调用 `POST /model/prediction` 返回 404 "No static resource model/prediction"。

**根因**：SDK 旧方法 `ModelAPI.prediction()` 使用不存在的 `/model/prediction` URL，三个后端都没有这个路由。正确路由是 `/api/v1/prediction`，对应 `ModelAPI.predict()`（已存在）。

**修复**：
- SDK `dehaze-sdk-js`：
  - 删除废弃的 `prediction()` 方法（调用 `/model/prediction`）
  - 删除废弃的 `evaluation()` 方法（调用 `/model/evaluation`，同样不存在）
  - 删除废弃类型 `PredParam`、`PredResult`、`EvalParam`、`EvalResult`
- React (`dehaze-front-react`)：4 处 `ModelAPI.prediction({modelId, url})` → `ModelAPI.predict({algorithmId, imageUrl})`；`res.predUrl`/`res.hazeUrl` → `res.resultUrl`/输入图片 URL
  - `pages/compare/overlap/index.tsx`
  - `pages/presentation/dehaze/index.tsx`（2处）
  - `pages/presentation/segmentation/index.tsx`
- Vue (`dehaze-front-vue`)：
  - `views/presentation/dehaze/index.vue`：2 处 prediction→predict；`modelParam`(Object)→`params`(JSON.stringify)
  - `views/compare/overlap/index.vue`：evaluation→evaluate，`EvalResult`→局部 `MetricItem`，模板去掉 better/description 列
  - `views/evaluation/index.vue`：同 overlap，雷达图/柱状图/导出报告移除 baseline 引用

**遗留问题**：Android SDK (`dehaze-android/sdk`) 的 URL 正确但 `PredParam`/`PredResult` 字段名不匹配（`modelId`→`algorithmId`，`url`→`imageUrl` 等），需另外修复。

## 修复预测/评估的 imageUrl 相对路径问题（Java 端）

**问题**：前端传 `imageUrl: "/dataset-api/NH-HAZE-2023/hazy/001.JPG"`（Vite 代理的相对路径），Java 原样传给 Python，Python 无法解析为本地文件，报 400 "图片文件不存在"。

**根因**：`/dataset-api/` 是 nginx-dataset 容器（端口 9000）的代理前缀，Python 服务无法直接访问。应解析为完整 HTTP URL `http://127.0.0.1:9000/...`。

**修复**（Java 端）：
- `SysPredLogServiceImpl.java`：注入 `@Value("${file.datasetBaseUrl}")`，新增 `toAbsoluteUrl()` 方法，在 `resolveImageUrl()` 中调用
- `SysEvalLogServiceImpl.java`：同上，`predUrl`/`gtUrl` 也经过 `toAbsoluteUrl()` 解析
- `toAbsoluteUrl()` 逻辑：已是完整 HTTP(S) URL 直接返回；`/dataset-api/` 前缀映射到 `datasetBaseUrl`；其他保持原样
