## IDE 环境：Java 插件 JDK 配置（警告 → 更严重报错 → 定案）

**背景事实**：本机 JDK 三套并存 `/usr/local/java/{jdk17,jdk21,jdk25}`，默认 `JAVA_HOME=jdk17`；jdk25 是 Temurin **四段式版本号 25.0.4.1**。当前 IDE 用的是 `/root/.codebuddy-server-cn/`，其 Machine settings 为 `/root/.codebuddy-server-cn/data/Machine/settings.json`；`/root/.vscode-server/data/Machine/settings.json`（旧官方 VS Code Server）**与之互不相通** —— 排查"改了却不生效"先确认 IDE 实际使用的 server 目录。插件为 `redhat.java 1.56.0`（不内置 JRE）。

**坑 1：`java.configuration.runtimes` 管不到插件自身。** 它只决定**项目**编译/运行用哪个 JDK；插件（JDT.LS）自己的启动 JVM 由 `java.jdt.ls.java.home` → `java.home` → `JAVA_HOME` → `PATH` 决定。原配置只写了 `runtimes: JavaSE-25`，插件回退到 `JAVA_HOME=jdk17` ⇒ 报 "Java 21 or more recent is required"。该设置 scope 为 `machine-overridable`，**只能写 User / Remote-Machine 级，写进工作区 `.vscode/settings.json` 不生效**。

**坑 2（更重要）：`jdt.ls.java.home` 不能用 jdk25。** 改成 jdk25 后警告消失，但引出：
`org.gradle.tooling.BuildActionFailureException: The supplied phased action failed with an exception.` + `Caused by: java.lang.IllegalArgumentException: 25.0.4.1`
（堆栈：`org.jetbrains.kotlin.com.intellij.util.lang.JavaVersion.parse` ← `JavaVersion.current()` ← `kotlin.cli.jvm.compiler.KotlinCoreEnvironment.<init>`）
根因：`dehaze_flutter/android/gradle/wrapper/gradle-wrapper.properties` 用 **Gradle 8.12**，其内嵌 **Kotlin 2.0.21** 的 `JavaVersion.parse` 无法解析四段式 `25.0.4.1`，编译 `build.gradle.kts` 时抛异常 ⇒ Gradle 模型拉取失败。插件会把 LS 的 JDK 默认当作 Gradle 导入 JVM，故 LS 的 JDK 会连累 Gradle。

**已实测复现**（最小 Kotlin DSL 工程 + 本地缓存的 gradle-8.12）：`JAVA_HOME=jdk21` → `BUILD SUCCESSFUL`；`JAVA_HOME=jdk25` → `BUILD FAILED ... * What went wrong: 25.0.4.1`，与插件报错同源。

**定案配置**（`/root/.codebuddy-server-cn/data/Machine/settings.json`）：
```json
"java.jdt.ls.java.home": "/usr/local/java/jdk21",
"java.import.gradle.java.home": "/usr/local/java/jdk21",
"java.configuration.runtimes": [{ "name": "JavaSE-25", "path": "/usr/local/java/jdk25", "default": true }]
```
即**插件运行 JDK 与 Gradle 导入 JDK 都固定为 21**（满足 redhat.java ≥21，且在 Gradle 8.12 兼容范围内；8.12 最高支持运行到 Java 23，Java 25 支持要到 8.14.4+/9.x），项目编译仍由 `runtimes` 决定（注意 `dehaze-java` 自身是 `maven.compiler.release=17`）。
**不要**走"升级 Gradle wrapper 到 9.x 以支持 Java 25"这条路：`dehaze_flutter/android` 的 wrapper 由 Flutter 生成，且 AGP 8.9.1 同样不支持 Java 25。

**通用教训**：`JAVA_HOME` / `jdt.ls.java.home` 是全局 JDK 开关，任何内嵌 Kotlin/Groovy 的工具链（Gradle、Android 构建）都会跟着走；本机不要指向非 LTS 且带四段版本号的新 JDK。

### 续：`dehaze-react-native/android` 同源报错与"为什么改了没用"

用户随后在 `dehaze-react-native/android` 又报同类错误（`The supplied phased action failed with an exception.` / `settings.gradle line: 18` / `Error resolving plugin [id: 'com.facebook.react.settings']` / `25.0.4.1`）。

- **实测**：`cd dehaze-react-native/android && JAVA_HOME=/usr/local/java/jdk21 ./gradlew help -q` → `EXIT=0`，第 18 行插件解析通过。

```json

    "**/node_modules/**", "**/.metadata/**", "**/archetype-resources/**", "**/META-INF/maven/**",
```

**该文件最终状态**（`/root/.codebuddy-server-cn/data/Machine/settings.json`）：`java.jdt.ls.java.home` / `java.import.gradle.java.home` = `/usr/local/java/jdk21`；`java.configuration.runtimes` = `JavaSE-21`(jdk21, default)（用户随后把 25 改成了 21）；`java.server.launchMode` = `Standard`；外加上面的 exclusions。改动生效同样需要重启语言服务器。

### 排查：Python 没有 Cmd/Ctrl+点击跳转定义（Pylance 语言服务器从未启动）

**结论：不是 `python.analysis.*` 配置的问题，是 Pylance 语言服务器在本环境从未跑起来。** 用户选中的 `autoImportCompletions` / `languageServerMode: "full"` / `typeCheckingMode: "standard"` 三条都是合法 ID（validator 校验通过），都不影响跳转定义。

### pyright 对 pydantic `alias` 的误报（a2a，已定案）
