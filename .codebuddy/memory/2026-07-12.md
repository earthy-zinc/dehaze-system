# 2026-07-12 工作日志

## dehaze-uniapp 依赖修复与升级

### 问题
Vite 报错 `Failed to resolve import "@vue/devtools-api" from "node_modules/pinia/dist/pinia.mjs"`

### 根因分析
1. **Pinia 3.x 与 vue 版本不兼容**：Pinia 3.0.4 要求 `vue ^3.5.11`，但 `@dcloudio/uni-h5` 硬编码依赖 `vue: 3.4.21`，不能升级 vue
2. **pnpm 不提升 transitive dep**：`@vue/devtools-api` 是 Pinia 的依赖，pnpm 不会提升到顶层 `node_modules`，导致 Vite 无法解析

### 解决方案
1. **降级 Pinia 到 2.2.4**（精确版本）：
   - pinia 2.2.0-2.2.4 支持 `vue ^3.3.0` ✅
   - pinia 2.2.5+ 要求 `vue ^3.5.11` ❌
   - pinia 2.3.x 要求 `vue ^3.5.11` ❌
   - pinia 3.x 要求 `vue ^3.5.11` ❌
2. **显式安装 `@vue/devtools-api: ^6.6.4`** 作为直接依赖，让 pnpm 提升到顶层
3. 清除 `node_modules/.vite` 缓存

### uni-app 主依赖升级
- 用户要求执行 `npx @dcloudio/uvm@latest` 更新，但该命令强制交互模式（选择包管理器），无法非交互运行
- 手动查询 npm registry 的 `vue3` dist-tag 获取最新版本
- 更新内容：
  - @dcloudio 主包（16个 dependencies + 4个 devDependencies）：`3.0.0-4070620250821001` → `3.0.0-alpha-5020120260710001`（vue3 tag 最新）
  - @dcloudio/uni-ui：`^1.5.11` → `^1.5.12`
  - @dcloudio/types：`^3.4.8` → `^3.4.32`
- 新版 uni-h5 仍锁定 `vue: 3.4.21`，pinia 2.2.4 仍兼容

## dehaze_harmory 鸿蒙应用完善与接入真实后端

### 背景
dehaze_harmory 原为 Hello World 模板，需根据设计文档（03-模块设计）完善并接入真实后端（dehaze-go，端口 8989/8999）。

### dehaze-sdk-harmony 修复（禁止兼容历史烂逻辑，直接改）
原有 SDK 有多处与后端实际路由/响应结构不一致，已全部修正：
1. **Result 模型**：`code: number=0` + `message` → `code: string="00000"` + `msg`（与后端 `common.Response` 对齐）
2. **HttpManager**：`fetch` → `@kit.NetworkKit` 的 `http` 模块；增加 Token 自动注入、业务码处理、Token 失效回调
3. **TokenManager**：`localStorage` → `@kit.ArkData` 的 `preferences`；需在 EntryAbility.onCreate 中 `await TokenManager.initialize(context)`
4. **auth.ets**：logout 从 DELETE 改 POST；新增 `getMe()`（GET /auth/me）和 `refreshToken()`（POST /auth/refresh）
5. **dataset.ets 路径全修**：`/dataset` → `/datasets`、`/dataset/item` → `/dataset-items`、`/dataset/image` → `/item-files`
6. **model.ets 拆分**：`/model/prediction` → `/prediction`（prediction.ets）、`/model/evaluation` → `/evaluation`（evaluation.ets）；删除 model.ets
7. **新增 inputHistory.ets**：图像输入历史记录 API（/api/v1/image-input/history）
8. **模型字段修正**：PredParam 用 algorithmId/fileId/imageUrl；PredResult 用 resultUrl/resultThumbnailUrl/time

### 后端真实路由（dehaze-go，确认来源：internal/router/*.go）
- auth: login(POST), captcha(GET), logout(POST), me(GET), refresh(POST)
- algorithms(复数): GET列表, /options, /:id, /compare, /favorites, POST, PUT /:id, PUT /:id/status, DELETE
- datasets(复数): GET, /tree, /options, /:id, POST, PUT /:id, DELETE /:id, DELETE /batch
- dataset-items: GET, /:id, POST, POST /upload, POST /batch, PUT /:id, DELETE /:id, DELETE /batch
- item-files: GET /:id, POST, PUT /:id, DELETE /:id, DELETE /batch
- files: GET /check, GET /page, GET /download/*, GET /:id, POST, DELETE
- prediction: POST, GET /:id, GET /logs
- evaluation: POST, GET /:id, GET /logs
- image-input/history: GET, GET /:id, POST, PUT /:id, DELETE /:id, DELETE /batch, DELETE /clear

### 应用实现（dehaze_harmory）
- **配置**：oh-package.json5 引入 `dehaze-sdk-harmony`（file:相对路径）；module.json5 添加 INTERNET/READ_MEDIA/WRITE_MEDIA/CAMERA 权限；main_pages.json 配置 6 个页面
- **状态管理**：`common/AppState.ets` 基于 AppStorage 管理全局状态（登录态、用户信息、去雾处理上下文）
- **页面**：Login（验证码登录）→ Home（功能入口）→ ImageInput（上传/样例/历史）→ AlgorithmSelect（树形算法）→ Processing（进度展示+确认对话框）→ Compare（并排/重叠对比+滑动分隔线）
- **入口逻辑**：EntryAbility.onCreate 初始化 SDK + TokenManager，根据 TokenManager.isLoggedIn() 决定加载 Login 或 Home
- 后端地址：`http://127.0.0.1:8989`（Windows 必须用 127.0.0.1）
