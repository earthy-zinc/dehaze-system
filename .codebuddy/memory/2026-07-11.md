## Python 启动问题修复（根因分析）

### 问题
Python 服务启动时 MinIO 检查耗时 21 秒（`00:39:59` → `00:40:20`）。

### 根因（不是 DNS 慢，是 IPv6 回退超时）
1. Windows 上 `localhost` 解析为 IPv6 `::1`（优先）+ IPv4 `127.0.0.1`
2. Docker Desktop 端口映射只绑定 IPv4 `127.0.0.1`，不监听 IPv6 `::1`
3. Python `socket.create_connection` 串行尝试地址列表：先连 `::1:9000` → TCP SYN 无响应 → 等待 Windows TCP SYN 重传超时（约 21 秒）→ 回退到 IPv4 `127.0.0.1:9000` → 成功
4. Go 不受影响：net 包实现 Happy Eyeballs（RFC 8305），并行尝试 IPv4/IPv6，快速回退
5. Java 不受影响：JVM 默认偏好 IPv4 或有类似快速回退机制

### 验证证据
- `socket.getaddrinfo('localhost', 9000)` 返回 `IPv6 ::1`（优先）+ `IPv4 127.0.0.1`
- `socket.create_connection(('localhost', 9000))` → 21.03s，最终连到 127.0.0.1
- `socket.create_connection(('127.0.0.1', 9000))` → 0.00s

### 修复
1. `config.py`：`Settings` 基类和 `DevelopmentSettings` 中所有 `localhost` 改为 `127.0.0.1`
2. `DevelopmentSettings.XXLJOB_ENABLED` 改为 `False`（Docker 中未运行 xxl-job-admin）
3. 启动耗时从 21+ 秒降至 1 秒内

### Go config.yaml 同步修复
- MySQL/PostgreSQL/Redis/RabbitMQ 的 `localhost` 改为 `127.0.0.1`

### 修复（Python 对齐 Java/Go）
- `jwt.py` create_access_token：`sub` 改为 username，`user_id` 改为 `userId`，`roles` 改为 `authorities` 数组
- `auth.py` _extract_roles：从 `authorities` 提取角色（去掉 ROLE_ 前缀）
- `auth.py` get_current_user：从 `userId` 字段获取用户ID，从 `sub` 获取 username
- `jwt.py` extract_token_data / get_user_id：只从 `userId` 获取
- `schema/user.py` CurrentUserVO.nickname：改为 Optional（Java/Go token 不含此字段）

## Java captcha 阻塞项解决

Java captcha 存在 Redis db0，key 格式 `captcha_code:{id}`。值用 Jackson 序列化，带外层双引号（如 `"pRSIMr5d489ITna0mlJKfu23"`），读取时需去掉引号。

Java login 用 `@RequestParam` 表单参数而非 JSON body，需用 form-data 格式发送。
