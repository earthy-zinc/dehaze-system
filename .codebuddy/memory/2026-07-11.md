## Python 启动问题修复（根因分析）

### 问题
Python 服务启动时 MinIO 检查耗时 21 秒（`00:39:59` → `00:40:20`）。

### 根因（不是 DNS 慢，是 IPv6 回退超时）
1. Windows 上 `localhost` 解析为 IPv6 `::1`（优先）+ IPv4 `127.0.0.1`
2. Docker Desktop 端口映射只绑定 IPv4 `127.0.0.1`，不监听 IPv6 `::1`
3. Python `socket.create_connection` 串行尝试地址列表：先连 `::1:9000` → TCP SYN 无响应 → 等待 Windows TCP SYN 重传超时（约 21 秒）→ 回退到 IPv4 `127.0.0.1:9000` → 成功
4. Go 不受影响：net 包实现 Happy Eyeballs（RFC 8305），并行尝试 IPv4/IPv6，快速回退
5. Java 不受影响：JVM 默认偏好 IPv4 或有类似快速回退机制

### 验证证据
- `socket.getaddrinfo('localhost', 9000)` 返回 `IPv6 ::1`（优先）+ `IPv4 127.0.0.1`
- `socket.create_connection(('localhost', 9000))` → 21.03s，最终连到 127.0.0.1
- `socket.create_connection(('127.0.0.1', 9000))` → 0.00s

### 修复
1. `config.py`：`Settings` 基类和 `DevelopmentSettings` 中所有 `localhost` 改为 `127.0.0.1`
2. `DevelopmentSettings.XXLJOB_ENABLED` 改为 `False`（Docker 中未运行 xxl-job-admin）
3. 启动耗时从 21+ 秒降至 1 秒内

### Go config.yaml 同步修复
- MySQL/PostgreSQL/Redis/RabbitMQ 的 `localhost` 改为 `127.0.0.1`

## POST /roles 路由/权限修复

### 问题
1. **Go `A0300 权限不足`**: JWT `Authorities` 只存角色（`["ROLE_ADMIN"]`），但权限中间件把它当权限列表去匹配 `sys:role:add`，永远匹配不上
2. **Python `307 重定向`**: `@router.post("/")` 导致 `/api/v1/roles` → `/api/v1/roles/` 307 重定向
3. **Python `TypeError: missing 'user'`**: `@require_permission` 装饰器要求函数签名包含 `user: UserContext`，但 role.py 中 5 个写端点都缺少此参数

### 修复

**Go — JWT 权限缺失**：
- `jwt.go`: `Authorities` 同时存储角色（`ROLE_` 前缀）和权限（`authInfo.Perms`）

- `menu_repository.go`: 添加 `"strings"` import

**Python — 路由/装饰器签名**：
- `role.py`: `@router.post("/")` → `@router.post("")` 修复 307 重定向
- `role.py`: `add_role`/`update_role`/`delete_roles`/`update_role_status`/`assign_menus_to_role` 5 个端点添加 `user: UserContext = Depends(get_current_user)` 参数

### 关键发现
- Go `UserAuthInfo.Perms` 包含实际权限（如 `sys:role:add`），但 `CreateClaims` 只用 `Roles` 不用 `Perms`
- Go `menu_repository` 的 `isRoot` 检查直接对带 `ROLE_` 前缀的字符串做 `==` 比较，永远不匹配
