## 三端（Java/Go/Python）API 一致性规范（长期约定，MEMORY.md 未覆盖部分）
- 统一响应：`code=00000`、`msg="一切ok"`；token 失效统一 `HTTP 401 + A0230`
- null 字段不序列化：Java `non_null` / Go `omitempty` / Python `NonNullJSONResponse`
- `PageResult` 仅 `{list, total}`（无 `pageNum`/`pageSize`）
- 批量删除统一 `RequestBody {ids:[...]}`（非 Query）；删除参数统一 Query 而非 Path
- 端点尾斜杠 `/` 会导致 Python 307 重定向，写端点用 `@router.post("")` 而非 `("/")`
- `@require_permission` 装饰器要求函数签名含 `user: UserContext = Depends(get_current_user)` 参数

## Java 开发注意
- devtools 热重载 XML 需手动复制到 `target/classes/mapper/`
- MapStruct 编译时生成转换代码；`isRoot` 从 JWT `authorities` 检查 `ROLE_ROOT`，admin 的 authorities 为 `["ROLE_ADMIN"]`

## dehaze-java 性能优化（数据集管理 + 算法管理）

### 已修复的性能问题
1. **SysDatasetItemServiceImpl 全表扫描无缓存**：`getLeafDatasetIdsByMapper`/`getAllLeafDatasetIdsByMapper` 原来用 `sysDatasetMapper.selectList(null)` 每次查库，改为使用 `@Lazy` 注入 `SysDatasetService` 调用缓存的 `getAllDatasets()`
2. **SysAlgorithmServiceImpl N+1 查询**：`getRootAlgorithm`/`getAlgorithmById` 原来逐级 `getById` 查父节点，改为一次性加载全部算法构建 Map 遍历；新增 `getAllAlgorithms()` 带 `@Cacheable`
3. **算法树构建 O(n²)**：`buildAlgorithmTree`/`buildAlgorithmOptions` 原来每次递归遍历全部列表，改为 `Collectors.groupingBy` 预构建 Map
4. **数据集选项构建 O(n²)**：`buildDatasetOptions` 同样改为 Map 分组
5. **loadStatisticsForDatasets 5 次查询合并为 2 次**：新增 `countDatasetStatsBatch` SQL 用条件聚合（SUM(CASE WHEN...)）一次查出图片数/总大小/清晰图数/有雾图数，加上 `countItemsPerDataset` 共 2 次
6. **calculateStatistics 8 次查询减少到 5 次**：新增 `countDatasetStatsSingle` 合并原来 4 次单独 count 查询为 1 次
7. **batchDeleteDatasets 嵌套循环 N+1**：原来逐叶子查询 items、逐 item 查询 files，改为批量 `IN` 查询所有 items 和 files
8. **batchDeleteDatasetItemsCascade N+1**：同样改为批量查询 files
9. **evictDatasetAndAncestorStatsCache 递归**：改为迭代向上遍历
10. **算法服务无缓存**：`getList`/`getOption`/`addAlgorithm`/`updateAlgorithm`/`deleteAlgorithms` 添加 `@Cacheable`/`@CacheEvict`

### 清理的废弃代码
- 移除 `SysDatasetMapper` 中 12 个被替代的统计方法及其 XML
- 更新 `SysDatasetServiceTest` 中对应的 mock 引用
