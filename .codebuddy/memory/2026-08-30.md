  3. 切换会话（route watch）与空态新建会话时同步记录记忆

## 实时SSE流"永久正在思考"修复（2026-08-30）
### 症状
- 刷新后历史加载正常（status=2/content 完整）；**实时流式**时后端已回复但前端一直"正在思考"（content 不渲染、status 不清）
- 后端完全正常（消息落库 status=2、content 完整）；问题在前端流式渲染链路
### 根因
- 流式占位消息（负数 id）依赖 `findMessage(s.messageId)` 定位，**一旦 messages.value 被并发 `fetchMessages` 整体覆盖**（页面加载/路由切换触发），占位对象丢失 → onStart/flush/onEnd 的 findMessage 全部返回 null → content 不写入、status 保持 1 → AssistantMessage `isStreaming(message.status===1)` 永久 true + content 空 → 界面永久"正在思考…"
- 我上一轮加的 onMounted「恢复上次会话」跳转会在等待加载期间打断刚发起的流（router.replace → fetchMessages → teardownStream），加剧该竞态
### 修复（dehaze-front-vue/src/store/modules/chat.ts + views/chat/index.vue）
1. `StreamSession` 新增 `message: AiMessageVO | null`（流式消息对象引用），`openStream` 时绑定占位消息
2. `onStart`：优先 `s.message`，找不到时回退查找 role=assistant&&status===1 的消息并更新 `s.message`
3. `flush`/`onEnd`/`failMessage`：统一 `s.message ?? findMessage(s.messageId)`——content/status 直接写持有引用的对象，不依赖数组查找
4. `fetchMessages`：流式进行中（同会话）合并保留流式消息对象（`!list.some(m=>m.id===live.id)` 时 push），防整体覆盖丢占位
5. `onMounted`（chat/index.vue）：`fetchConversations` 后若 `chatStore.isStreaming` 则 return，跳过恢复/默认跳转，避免打断正在进行的流
- 坑：`let msg = s.message ?? findMessage(...)` 类型推断丢失 null → 后续赋 null 报 TS2322，需显式 `let msg: AiMessageVO | null = ... ?? null`
### 验证
- lint 0 错；vite build 成功（54.56s）

## qwen3 思考内容被当作正文输出 bug 修复（2026-08-30）
### 现象
- 消息正文残留模型思考（如 1443："好的，用户发来'你好'，我需要以亲切、可靠的态度回应。首先...\n你好！有什么可以帮助你的吗？"——前半是思考、后半才是回复）
- 用户确认：后端把 `<thinking>` 思考内容作为 text_delta 传给前端（前端当正文渲染）
### 根因
- `local_llm_server._clean_content` 流式**逐 chunk** 调用：`text.replace("<think>","")` 只去掉开标签但**保留思考内容**，仅当该 chunk 恰好含 `</think>` 才 `split` 丢弃。流式场景思考内容 chunk 不含闭合标签 → 思考内容全部作为正文输出
- 上游 `openai_compat._ThinkSplitter`（本可跨 chunk 识别 `<think>`）因标签被本地剥掉而完全失效
### 修复
- `local_llm_server._clean_content` 移除 `<think>`/`</think>` 处理（只剥离 STOP_TOKENS），思考标签原样保留给上游 `_ThinkSplitter` 跨 chunk 识别 → thinking_delta（前端思考区）+ text_delta（正文）
- 组合验证：`_clean_content(raw)==raw` + `_ThinkSplitter` 跨 chunk 产出 thinking="思考内容"/text="正文" ✓
- 全量 1500 passed；存量含思考消息（1443 等）不自动清理（用户数据），新消息不再残留思考
### 教训
- 流式逐 chunk 做"标签剥离"处理是反模式：标签可跨 chunk 拆分、内容 chunk 无边界标签，必须把状态化解析（如 <think> 缓冲）放到能跨 chunk 的消费端（_ThinkSplitter），本地只做无状态兜底
