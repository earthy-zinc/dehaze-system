### 经验教训（重要，用户反复强调）
1. **注入最佳实践**：默认参数直接引用模块级对象（`def __init__(self, repo=repo)`）+ 直接赋值；**不要** `None + or 兜底`（吞 falsy 值、冗余）、**不要** `globals()["x"]`（类型不透明、重构不安全）
2. **循环导入是设计缺陷的症状**：用惰性 import/延迟 import 只是回避；根源是跨层反向依赖（builder→service、工具层→repository、service↔service 互引）。修复=打破环（下沉共享能力到独立模块/依赖倒置参数注入），使 import 图为 DAG
3. **强行兜底隐藏真实问题**：推理失败伪装成功态、子 Agent 静默失效、缓存失效当成功——应显式暴露（raise/error 日志/语义区分）
4. 构造注入改造易出半成品：加了 `__init__` 但方法体仍引用模块全局（DocumentService 案例）——改造后必须全局搜索方法体内残留的模块级单例引用
5. 工具坑：replace_in_file replace_all 偶发静默不落盘，需回读文件确认
