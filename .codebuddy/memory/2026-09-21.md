## pyright CLI 与 IDE 版本不一致导致"门禁漏检"（lead，承接 09-20 的类型检查治理）

**现象**：用户在 IDE 里收到 `app/utils/ssrf.py:73` 报错 `无法将"str | int"类型的参数分配给 "str" 参数 "ip"`，但 `dehaze-python/scripts/check.sh` 全绿（CLI pyright 1.1.408 报 0 error）。

**根因（精确定位到 typeshed 差异）**：`asyncio.BaseEventLoop.getaddrinfo` 的返回类型在两版 typeshed 不同——
- 1.1.408：`list[tuple[AddressFamily, SocketKind, int, str, tuple[str, int] | tuple[str, int, int, int]]]` ⇒ `info[4][0]` 推出 `str`，不报错；
- 1.1.414：补上了 `| tuple[int, bytes]`（与 `socket.getaddrinfo` 对齐）⇒ `info[4][0]` 变成 **`str | int`**，于是报 `reportArgumentType`。

**修法（不抑制、不 fail-open）**：`_resolve_reaches_internal` 里对取到的地址做显式收窄 + 保守拒绝——
```python
addr = info[4][0]
if not isinstance(addr, str):
    logger.warning("SSRF 解析得到非字符串地址，保守拒绝 %s: %r", host, info[4])
    return True
```
**绝对不能写 `str(info[4][0])`**：若真取到 int，会得到 `"123"` 这种伪地址，`ipaddress.ip_address` 抛 ValueError 被上层吞掉 → **fail-open（SSRF 放行）**。这与该函数 docstring 已写的"解析失败保守拒绝"口径一致。

**门禁修正（这次事故的根治项）**：`dehaze-python/scripts/check.sh` 固定 `PYRIGHT_VERSION`（默认 `1.1.414`，与 IDE 的 `ms-pyright` 扩展对齐；可用环境变量覆盖），并 `export PYRIGHT_PYTHON_FORCE_VERSION`。pyright pip 包装器支持按版本拉取（实测 `PYRIGHT_PYTHON_FORCE_VERSION=1.1.414 pyright --version` → `pyright 1.1.414`）。**教训：类型检查器的"绿"必须绑定版本号，否则 CLI 与 IDE 口径分裂，用户看到的红没人拦。** 已在 `dehaze-doc/docs/02-系统架构/05-测试架构.md` §5.3 记录。

**复验（1.1.414，853 文件）**：`pyright` **0 error / 0 warning**；`ruff` 0、`format` 850 文件全绿；`pytest` **3250 passed / 0 failed**；`tests/infrastructure/a2a/test_ssrf.py` 13 passed。
