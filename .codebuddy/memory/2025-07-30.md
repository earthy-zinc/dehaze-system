在早间并行化基础上，继续修复所有后端 bug 与三端一致性，最终三端全量 580/580、0 跳过。

### 后端 bug 修复

1. **Python 中间件顺序 bug**：`ApiKeyAuthMiddleware` 注册在 `DBSessionMiddleware` 之前，`request.state.db` 恒为 None → 任何 Bearer dhak_* 调用 401「认证服务不可用」，预测/评估任务 status=3。修复 `middleware/__init__.py` 注册顺序（ApiKeyAuth 先注册使其在 DBSession 之后执行）
2. **Python SSL 证书**：pyiqa 初始化 LPIPS/NIQE 模型从 HTTPS 下载预训练权重，系统 CA 缺失导致 `CERTIFICATE_VERIFY_FAILED`。`config.py` 顶部兜底 `SSL_CERT_FILE=certifi.where()`（未设置时）
3. **Python import-export 模块名**：algorithm handler `get_module()` 返回单数 `algorithm`，SDK/Java 用复数 `algorithms` → 400。改为 `algorithms`；同时导入导出路由 `/{module}/template|_export|_import` 移到算法 CRUD `/{algorithm_id}` 之前注册（否则被路径参数吞掉）
4. **Python monitor/stats 返回类型**：Java 返回日期序列数组（最近 days 天每天一条，含无数据天），Python 返回单个 dict。`algorithm_service.get_monitor_stats_report` 改为返回数组 + repository 加 `get_monitor_stats_by_date` 按日期分组聚合
5. **Python 预测 fileId**：router 把 fileId 拼成 `/api/v1/files/download/{fileId}`（用 ID 非 objectName）走本地路径读不到 MinIO 文件。改为 service 层 resolveImageUrl（fileId 查文件取真实 URL），对齐 Java
6. **Go 文件上传权限**：Go 要求 `sys:file:add`，但 API 规范明确「文件管理模块不实现权限控制，仅需登录态」（Java/Python 均无）。`router/file.go` 移除 sys:file:add/sys:file:delete 权限
7. **Go 预测不支持 fileId**：`sys_prediction.go` 只收 imageUrl（required）。加 FileID 可选参数 + fileService 查文件取 URL（controller 层 resolveImageUrl）
8. **Go Result time omitempty**：评估快（<1s）时 log.Time=0 被 omitempty 省略 → result.time undefined。去掉 evaluation/prediction Result 的 time omitempty
9. **Go 限流**：`ip-limit-count` 调大到 100000；Python `REDIS_MAX_CONNECTIONS=100`
10. **Java 登录限流**：`@RateLimit maxRequests` 10→100（注解硬编码无法配置注入）
11. **export-task 错误码对齐**：规范 `B0301` 任务不存在，Java(A0500)/Go(A0401) 不符 → 三端统一 B0301（Java ResultCode + Go result_code 新增 TASK_NOT_FOUND，测试期望改 B0301）

### 关键坑：Redisson 限流配置残留

`@RateLimit maxRequests` 改大后不生效——Redisson 限流配置（`rate:limit:login:{ip}` 的 `rate` 值）只在**首次初始化**时写入 Redis，注解改了不更新。需删除该配置 key 让 Redisson 用新注解值重新初始化（globalSetup 的 clearLoginRateLimit 只删计数子 key 不删配置 key，故阈值变更时需手动清配置）。

### run.py 改进

`stop` 用 `os.killpg`（进程组 kill）+ `_kill_port_occupants`（清理 go run/uvicorn --reload 残留的孤儿子进程，它们 PPID=1 不在 PID 文件的进程组），解决 restart 杀不干净导致 `Address already in use`。
