## 后端 useMultiPoint 多端登录修复 + SDK 测试并行化

### 后端修复（Java/Python 对齐 Go）

三端「多点登录踢旧 session」实现不一致：Go 有 `useMultiPoint` 开关，Java/Python 无条件踢旧。修复：

- **Java** `AuthServiceImpl.java`：`@Value("${system.use-multi-point:false}")` 注入，`handleMultiPointSession` 调用处加 `if (useMultiPoint)` 判断
- **Java** `application-dev.yml`：`system.use-multi-point: false`（开发允许多端）；`application-prod.yml`：`true`（生产踢旧）
- **Python** `config.py`：`USE_MULTI_POINT: bool = False`；`auth_service.py` 加 `if settings.USE_MULTI_POINT:` 判断
- **Go** 已有 `use-multi-point: false`，无需修改
- **文档**：`认证管理/后端实现.md` 和 `测试用例.md` 修正为三端均已实现

### SDK 测试并行化

- **vitest.config.ts**：恢复默认 forks pool 并行（去掉 `fileParallelism: false` 和 `singleFork`），每文件独立进程，sessionStore 天然隔离
- **登录限流**：`clearLoginRateLimit` 导出并在 `vitest.setup.ts` beforeAll 中预防性清理
- **限流清理 bug**：原 pattern `*rate:limit:login:*` 误删 Redisson 配置 key（`rate:limit:login:{ip}`），导致 "RateLimiter is not initialized" HTTP 500。修正为只删计数子 key `{rate:limit:login:*` 和 `rate:limit:/api/v1/auth/login:*`（globalSetup 同步修正）
