## 基础设施 IP 统一为 DEHAZE_HOST 环境变量

将项目中所有硬编码的 `127.0.0.1`/`localhost` 基础设施连接地址统一改为使用 `.env` 中的 `DEHAZE_HOST` 环境变量，解决共同开发时远程连接基础设施不便的问题。

**关键区分**：基础设施（MySQL/Redis/MongoDB/MinIO/RabbitMQ/Nginx/XXL-Job）运行在远程 `DEHAZE_HOST` 上；后端服务（dehaze-java/dehaze-go/dehaze-python）本地启动调试，因此服务间调用地址和自身 URL 保持 `127.0.0.1`。

## dehaze-sdk-js 集成测试环境变量归并到根 .env

将 SDK 测试的环境变量配置从 `dehaze-sdk-js/.env.{java,python,go}` 三份文件 + `TEST_BACKEND` 选择器，简化为统一从 monorepo 根 `.env` 加载。

### 修改范围

**`dehaze-sdk-js/`**
- `package.json`：`test:java/python/go` 脚本由 `cross-env TEST_BACKEND=xxx` 改为 `cross-env BACKEND_URL=http://127.0.0.1:8989/8991/8990`，直接注入本地后端地址
- `vitest.globalSetup.ts`：加载 `../.env`（唯一加载点），Redis 清理复用 `test/utils/redis.ts` 的 `getRedis/disconnectRedis`（不再手写 new Redis，连接配置只维护一处）
- `vitest.setup.ts`：删除重复的 dotenv 加载（globalSetup 已加载且同进程），baseURL 直接读 `BACKEND_URL`
- `test/utils/redis.ts`：Redis 连接改用 `DEHAZE_HOST`/`DEHAZE_PASSWORD`，端口/db 内联默认值（含 `maxRetriesPerRequest:3`）
- `test/utils/mysql.ts`：MySQL 连接改用 `DEHAZE_HOST`/`DEHAZE_PASSWORD`，其余配置内联默认值
- `test/utils/auth.ts`：验证码 key 前缀 `captcha_code:` 内联为字面值
- `.env.example`：改为配置说明，指向根 `.env`

### 关键设计原则
- **基础设施（Redis/MySQL）远程**：通过根 `.env` 的 `DEHAZE_HOST`/`DEHAZE_PASSWORD` 连接，不在 SDK 目录维护
- **被测后端本地启动**：`BACKEND_URL` 始终指向 `127.0.0.1:<port>`，由 npm 脚本按后端类型注入，**不与 DEHAZE_HOST 耦合**（曾误用 DEHAZE_HOST 拼接 baseURL 导致远程地址连不上本地后端）
- **dotenv 只加载一次**：globalSetup 在 setupFiles 之前同进程运行，setup 无需重复加载

### 教训
- 后端选择（java/go/python）与基础设施连接是两个正交关注点，不要用一个环境变量同时驱动两者
- dotenv 在同进程多次加载属冗余，process.env 已填充后无需重复
