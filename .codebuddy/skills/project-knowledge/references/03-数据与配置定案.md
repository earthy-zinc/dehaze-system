# 数据与配置定案

## 环境与配置原则

- 根 `.env` 旧名零回退、勿再引入（改迁移前核对，勿留旧名）：`DEHAZE_HOST`/`DEHAZE_PASSWORD`、python `DB_*`/`MINIO_BUCKET_NAME`/`RABBITMQ_USER`/`_apply_derived_credentials`（无自动守卫）。
- 加载顺序：环境变量优先于 `.env`；`dotenv` 只加载一次（vitest globalSetup 与 setupFiles 同进程 ⇒ `vitest.setup.ts` 不重复加载）。
- 配置项判定标准：仅"管理员/运营有明确修改动机"的参数才字典化（`sys_dict`），纯技术参数（缓存 TTL/分页/批次/轮询/锁定/心跳/cron/线程池）一律代码常量；个性化由实体级配置覆盖，不设第三层全局字典默认。典型判定：推理默认值＝代码常量 `agent_config_resolver.REASONING_DEFAULTS`（不是字典 `ai_reasoning_defaults`）；`ai_guardrail_defaults` 保留（安全合规有运维场景），缓存键 `ai:config:guardrail_defaults`。字典增删改即时失效缓存；缺键 warn + 回退默认值（不保留旧常量转发）。新增 `sys_dict` 种子须同步 `config/sql/data/*.sql` + python 种子 + `SYSTEM_PRESET_DICT_TYPE_CODES` + seed contract 测试。字典项的 `status`：`status=0` 视同缺项（停用即不生效、回落调用方默认）——python 统一在 `dict_service.get_dict_value` 兜底（`item.status == 1` 才取值；不要改共享仓储 `get_by_type_code_and_name` 的活跃行口径，种子判重必须能看到停用行），go/java 在各自字典读取层过滤。
- Windows/macOS 必须用 `127.0.0.1` 而非 `localhost`（localhost 优先解析 IPv6 `::1`，Docker Desktop 只映射 IPv4，Python `socket.create_connection` 串行尝试 → 等 SYN 超时约 21s 才回退）。模拟器访问宿主机：Android `10.0.2.2`，iOS/Mac `127.0.0.1`（RN `DEV_HOST` 必须按 `Platform.OS` 分流）。

## 数据库 / 种子 / 迁移

- 库表基线：`config/sql/schema/*.sql`（`xxl_job.sql` 只允许放 `config/sql/schema-external/`（自带 `DROP DATABASE xxl_job`，混入 `schema/` 会被 `schema/*.sql` 通配误执行删库），唯一执行入口＝`docker-compose.yml:25` 单文件挂载；各消费方仍用 `sys_*.sql` glob 过滤，conftest 同款）；测试库构造与隔离见 skill `testing`；集成测试连开发库 `dehaze`（schema 变更须手工 ALTER，缺列会让 python 整套件 beforeAll 500 并大面积 skip ⇒ `1054 Unknown column` 先怀疑 dev 库落后 schema）。
- 迁移脚本位置：DDL/数据迁移收敛在 `config/sql/migration/*.sql`（`config/sql/migration/` 不在 compose 初始化挂载里，须手工 `mysql <` 执行；幂等性见各文件头，如 `2026-09-11_uk_deleted_aware.sql` 为一次性不可重跑）；一次性迁移须先落 DDL 再重启后端（后端启动时查新列会启动失败）；`clarity_test` 由 schema+data 全量重建、不跑 migration；dev 库执行迁移须待三端停机（文件头注明"须待 python 侧停读旧表后执行"）。Mongo 键名迁移 `clarity-test/scripts/mongo_key_migrate.js`（幂等，含回滚段，执行权留用户）。
- 迁移 SQL 注意：中文注释内含半角分号时不能按 `;` 拆分执行。`sys_api_key` 等种子必须落 `dehaze` 运行库（非 `clarity_test`）。
- 种子/初始化：dev 环境初始化＝权限系种子 + 业务种子（`config/sql/data/*.sql`）+ embedding 模型注册 + 清 Redisson 污染 key（如 `rate:limit:register:{ip}` WRONGTYPE）+ 清 favorite 残留。
- 登录类全挂先查 `sys_user.deleted` 与 `login:fail:*` 锁（deleted 被污染时 `UPDATE sys_user SET deleted=0`）。
- 迁移/种子改动必须自证幂等与双环境一致：①全新环境（schema+data 重建）与遗留 dev 库执行结果逐行业务列一致；②连续执行两次第二次 diff=0；③口径切换必须写幂等清理段（先 `DELETE ... WHERE model_id LIKE '<旧前缀>%'` + 关联字典值 `UPDATE`，再插入，两边都用存在性守卫）——只靠人工在库里补救不算。
- 种子固定 id 会与测试造号相撞：`config/sql/data/*.sql` 用固定主键 id（provider `180–182`、model `500–505` 等），而 pre/dev 存量库中同 id 常已被测试批量创建的行（`test_prov_*` / `test_model_*` / `favmodel_*`）占用（成因：SDK/契约测试批量创建带随机后缀的行，自增 id 恰好落进种子号段）⇒ ① 存量库重跑 `data/*.sql` 会 `ERROR 1062` 整条中止；② 若用「固定 id + `ON DUPLICATE KEY UPDATE`」会按主键命中那些无关行、把其业务列整列改脏（2026-10-01 在 pre 实测）。存量环境补种子一律走 `config/sql/migration/*.sql`，写法 `INSERT ... SELECT ... WHERE NOT EXISTS(业务键)`（provider 用 `provider_code`、model 用 `(model_id,provider_id)`，`provider_id` 按 `provider_code` 反查），绝不写固定 id、绝不按主键 ODKU；`data/*.sql` 只供全新库。另注意 `rebuild_mysql.py --import <table>.sql` 会先整表 DELETE，会清掉管理端自建行。
- 插入守卫 `NOT EXISTS` 只判"存在"、不更新已有行 ⇒ 改口径时必须另补修数据语句（如 `UPDATE ... SET status=CASE WHEN status IN (2,3,4) THEN 1 ELSE 0 END ... AND status NOT IN (0,1)`，`NOT IN (0,1)` 守卫是幂等关键）；把 SQL 重构成多层子查询时务必核对投影表达式仍在最外层。
- MySQL 迁移三坑：①`IF()` 会 eager 求值全部参数（子查询写在"未被选中"的分支里一样会执行 → 1146）⇒ 先用用户变量取子查询结果再判定；②动态 SQL（PREPARE）字符串里转义引号跨行书写会被错误解析出表名 → 单行 + 零引号（值用会话变量注入）；③`CREATE PROCEDURE` 建时不校验表存在、过程体执行到缺失表才 1146，且本仓 `rebuild_mysql.py` 切分器不认 `DELIMITER` ⇒ 迁移优先 PREPARE 守卫式。
- 删字典行必须与删代码里的默认播种项同批（py `DictService` 默认项不同步删 → 后端一重启就把删掉的字典行种回来）；清业务缓存的标准入口 `rebuild_mysql.py --skip-mysql`（须在主工作区跑），后端不健康时它会回退"裸删 Redis"、连 session key 一起删（已登录会话失效）。

## 会员 / 权益 / 配额

- 会员档案必须登录兜底初始化（注册是唯一自动入口，种子与后台建用户不走）：python `auth_service.login` 加 `get_or_init_member`、Go `EnsureMemberProfile` 查 nil 才 init；Java `MemberServiceImpl.ensureMemberProfile` 先查活跃行再 initMember——其 `upsertByUser` 冲突分支会降级 `level_0` 并清零 `total_consumption`，绝不可对活跃会员调用（无测试守卫 `[待补守卫]`）。
- 配额 fail-closed：无 `sys_member` 行 ⇒ `get_limits` 返回 None ⇒ 拒绝（"配额不足"实为"无会员权益档案"）；等级限额 `0`＝管理员显式不限额。

## 计费 / 定价 / 积分

- 本地 `qwen3-0.6b` 费率配置为 0（刻意免费）：chat 记录 tokens 正常入账但 credits/dailyUsed 不变，测试断言须按此设计。
- 计价统一入口 `AiModelPriceService.calculate_unit_credits(db, model_id, provider_id, at_time, quantity)` → `{credits, configured, billing_unit}`（chat/语音/图像共用）；`voice_billing_service` 只取数落账、不自己读价格表；billing 记录的 `model` 字段记统一 model_id（`sensevoice`/`paraformer`/`huayan`），不记 engine/provider code。
- `sys_ai_model_price_detail.token_type` 不扩 `unit`：`usage_kind='unit'` 时 `token_type` 复用 `'input'`（该列参与唯一键 `uk_price_token_time_range`，扩值域会改唯一性语义；引入 `unit` 档须作契约变更单独裁决并同步 py schema / DB 注释 / SDK / Java / Go）。
- `sys_ai_provider_key` 唯一键＝`uk_provider_key(provider_id, key_hash)`（`config/sql/schema/sys_ai_provider_key.sql:41`；local/local-voice/local-modal 共用一把 `INTERNAL_SERVICE_KEY` 依赖此口径，守卫 `clarity-python/tests/infrastructure/llm/test_model_seeder.py:158`）⇒ 三端按 hash 定位密钥必须带 provider 维度（py `ai_provider_key_repository.get_by_provider_and_hash`、go `GetByProviderAndHash`、java `.eq(providerId).eq(keyHash)`）。注意 `sys_api_key.uk_key_hash` 是另一张表，勿误改。

## 订单 / 支付 / 退款 / 续费

- 计量单位按 `model_type` 派生，不新增必填校验层（派生映射见 `基础模块/AI模型管理/后端实现.md`）；涉及钱的字段例外：禁止把非 token 模型静默落成 token 计量。

- 支付履约 `on_order_paid` 口径（勿混）：成长值 = 实付 1:1（分→成长值）；积分卡支付即完成（status 3，不动等级）；会员卡等级只升不降、`level_source=purchase`。余额扣减是相对值 UPDATE（`balance >= amount` 由 SQL 守卫，原子求值、无需 version 乐观锁）：java `SysBalanceMapper.deductBalance`、python `balance_account_service` 均如此；`sys_balance.version` 列存在但扣减不用它，勿据列注释改成版本 CAS。
- 退款记录字段唯一口径：`used_quota` 勿用；`sys_refund_record` 三端字段名统一为 `reason_type/used_days/used_credits`（camel `reasonType/usedDays/usedCredits`，`reason` 仅补充说明；三端+SDK `RefundRecordVO` 一致，守卫 `clarity-sdk-js/test/modules/order/order-edge.test.ts:364`）。
- 促销范围唯一权威＝`sys_promotion_package` 关联表（`sys_promotion.applicable_scope` 不存在，`sys_coupon.applicable_scope` JSON 保留）。

## 缓存键与 TTL

- TTL 不在 `clarity-python/tests/test_cache_key_contract.py`（只守卫键名/跨端声明一致性）覆盖内 ⇒ 改键须同步核 TTL 与清缓存（改费率须清 `ai:rate:{model_id}`）。
- `redis_operation_with_fallback` 首参必须可无参调用（入口校验见 `app/infrastructure/cache/redis_fallback.py:169/183/228`：非可调用 / 带必填参数 / 返回非 awaitable 一律 `TypeError`，守卫 `clarity-python/tests/infrastructure/test_redis_fallback.py`）。校验不得用 `inspect.iscoroutinefunction` 硬卡：`cache.py` 多处传 `lambda: self.redis.get(key)`（零参可调用返回 awaitable，合法且大量使用），只能校验"零参可绑定 + 调用后 `isawaitable`"。

## 业务常量 / 指标 / 环境

- 数值口径：费率档位过度小会被 int 截断致 credits=0；积分计算须 Decimal 四舍五入取整且单次至少 1 积分。会员成长值流水 `reason` 三端原样存储、不加前缀（无自动守卫 `[待补守卫]`）。
- 测试资源：`scripts/gen_test_resources.py`（根 scripts，渐变+噪声纹理，非纯色以便 NIQE 等无参考指标可算）；SDK 集成资源由 `test/config/ensure-test-resources.ts` 在 `vitest.globalSetup` 首行保障，清单必须与 `IMAGES/PNG_IMAGES` 严格对齐（test/hazy 只有 41/42/43）。
- 环境路径：macOS `ANDROID_HOME=~/Library/Android/sdk`（PATH 需含 `cmdline-tools/latest/bin`、`platform-tools`、`emulator`、`build-tools/<v>`）；Android `local.properties` 需 `sdk.dir`（被根 `.gitignore` 的 `*.properties` 忽略），`app/build.gradle` 默认 `BASE_URL=http://10.0.2.2:8989`；Python 依赖用 `uv`（`.venv` 在项目目录），测试依赖在 `[project.optional-dependencies].test` ⇒ 日常 `uv sync --extra test`。
