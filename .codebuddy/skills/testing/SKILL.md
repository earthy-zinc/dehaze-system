| 任务 | 读取 | 重点 |
| --- | --- | --- |
| SDK 集成测试 | `references/sdk-集成测试.md` | 七步流程、用例类别、基建与硬约束 |
| 单元测试 | `references/python-测试与门禁.md` | 强制约束、fixture 口径、运行方式 |
| 静态检查门禁 | `references/python-测试与门禁.md` | 唯一判定入口、交付前必须跑通 |
| 跨端测试基建与举证 | `references/跨端测试基建与举证.md` | 各端门禁、质量红线、举证纪律 |

失败排查先划范围定位，再决定改 SDK、改测试还是报后端 bug，划范围信号见 `references/sdk-排查手册.md`；输出格式、日志查询与运行期进度见 `references/sdk-运行与日志.md`。

## 共性纪律

- 只跑当前范围：写完一个用例立刻跑一个，只跑当前文件或用例，全量留到收尾跑一次，避免上下文爆、避免并行争用。
- 并行数据隔离：每个套件只建自己的专用数据、只清理自己创建的资源，别误删并行套件的。
- 交付前自证：改到的命令与脚本必须真实跑通并给出退出码或输出；不靠 IDE 诊断，不改断言迁就实现。
- 先定位再改：失败先划范围，锁定问题在 SDK、测试、后端还是 DB 层再动手，别急着改 SDK 或测试代码。
