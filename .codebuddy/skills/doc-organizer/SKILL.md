# 文档编写、整理与优化专家（doc-organizer）

## 一、核心原则

- **单一信息源**：同一事实只写一处
- **引用代替复制**：避免多处维护同一内容
- **按业务领域组织**：不按技术栈拆散同一模块
- **扁平化**：目录深度建议 ≤ 3 层

## 二、项目文档位置

所有项目文档存放在 `dehaze-doc/docs/` 目录下：

```
dehaze-doc/docs/
├── 01-产品设计/          # 产品概述、UI-UX 设计规范
├── 02-系统架构/          # 总体架构、环境兼容性、数据库设计、API 规范、测试架构、部署架构
├── 03-模块设计/          # 各模块的需求规格、API 接口、后端/前端实现、测试用例
│   ├── 基础模块/
│   └── 核心模块/
├── 04-项目实现/          # 各技术栈的架构文档
│   ├── 前端/
│   ├── 后端/
│   └── 算法/
└── 05-改造计划/
```

编写新文档时，参考 `dehaze-doc/docs/` 中同类型的现有文档风格和结构，保持一致性。

## 三、工作流程

根据任务规模自动选择执行深度：

| 任务类型 | 触发词示例 | 执行要点 |
|---------|-----------|---------|
| **轻量**（编写/补全/修复） | 写文档、补全、修复、评审 | 查阅同类现有文档 → 生成内容 → 自查 SSOT |
| **中量**（整理/去重/迁移） | 整理、去重、合并、迁移 | 扫描范围 → 识别问题 → 制定迁移计划 → 执行 → 验证完整性 |
| **重量**（重构/信息架构） | 目录重构、结构优化、体系规划 | 全面分析 → 设计目标结构 → 分批迁移 + 风险评估 → 分阶段执行 → 全面验证 |

轻量任务产出符合现有风格的文档内容；中量任务额外产出问题清单与迁移计划；重量任务额外产出量化指标报告与目标目录结构。

## 四、SSOT 内容边界

### SSOT 位置速查

| 内容类型 | 唯一权威位置 | 其他文档做法 |
|---------|------------|------------|
| **API 规范** | `03-模块设计/[模块]/API接口.md` | 只放链接 |
| **UI-UX 通用规范** | `01-产品设计/02-UI-UX设计规范.md` | 只引用，写差异点 |
| **模块级交互** | `03-模块设计/[模块]/需求规格.md` | 前端写实现落位，测试写验证方法 |
| **性能/安全目标** | `需求规格.md` 验收标准章节 | 实现写策略，测试写方法 |
| **数据库 ER/表结构** | `02-系统架构/03-数据库设计.md` | 只列依赖与约束 |
| **全局 API 规范** | `02-系统架构/04-API规范.md` | 只引用 |

### 各文档内容边界

**需求规格.md**：功能点列表（`F-XX-001`）、页面结构与交互规则、权限/角色矩阵、性能/安全目标。禁止写前端组件拆分、后端缓存实现、复述通用架构规范。

**后端实现.md**：DTO 校验规则、核心业务规则与流程、事务边界、缓存规则。禁止粘贴 DB DDL、写测试用例矩阵、写运维排障手册。

**前端实现.md**：组件拆分与职责、状态字段、表单校验、API 调用方式（契约必须引用）。禁止复述需求中的交互规范、写后端实现细节。

**测试用例.md**：测试点/步骤/断言、引用需求章节和性能阈值。禁止写独立接口清单、重复需求大段描述。
