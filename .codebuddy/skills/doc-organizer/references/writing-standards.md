# 文档撰写标准

所有由本 skill 产出的文档必须遵守以下标准。

## 文档结构

- 每篇文档必须有独立的 **H1 标题**，即使是从大文档拆分出来的
- 禁止生成元信息区块（作者、更新时间、版本号等），由 git 管理
- 禁止生成目录索引页（README.md 中的文档清单），维护成本高于收益
- 禁止使用章节编号（`一、`、`1.1` 等），直接用标题层级表达结构
- 从大文档拆分出的子文档，章节标题从头开始，不延续原文档的层级

## 格式要求

- 流程图、架构图、ER 图统一使用 **mermaid**；目录结构树用 `text` 代码块；禁止 ASCII art 画图
- 简单对比使用表格
- 代码块必须标注语言类型（`go`、`python`、`typescript`、`bash`、`json` 等），禁止无语言标记的代码块
- 摘录的代码示例应标注来源文件路径；同一段代码整个文档体系中只出现一次

## 质量标准

- **SSOT（单一信息源）**：同一段内容只在一处维护。如需引用其他文档的内容，用一句话概括并说明出处，不复制原文
- 专注内容本身，精简格式和模板化内容，保持高密度文字风格
- 禁止滥用 emoji；mermaid 图中禁止使用 emoji
- 禁止注水/膨胀内容（如过于细化的 mermaid 图、把简单线性流程拆成多个节点、极低信息密度）
- 聚焦本项目特有内容，除摘要/背景/基本概念章节外，避免科普/通识教育内容

## SSOT 内容边界

定义各文档**允许写什么、禁止写什么**，确保跨文档不重复。

### 位置速查

| 内容类型 | 唯一权威位置 | 其他文档做法 |
|---------|------------|------------|
| API 规范 | `03-模块设计/[模块]/API接口.md` | 只放链接 |
| 系统架构/技术栈 | `02-系统架构/` 下对应文档 | 只引用，写差异点 |
| 模块级交互 | `03-模块设计/[模块]/需求规格.md` | 前端写实现落位，测试写验证方法 |
| 性能/安全目标 | `需求规格.md` 验收标准章节 | 实现写策略，测试写方法 |
| 数据库 ER/表结构 | `02-系统架构/03-数据库设计.md` | 只列依赖与约束 |

> 文档目录根路径：`dehaze-doc/docs/项目文档/图像去雾系统/新结构/`

### 各文档禁区

**需求规格.md**：功能点列表（`F-XX-001`）、页面结构与交互规则、权限/角色矩阵、性能/安全目标。禁止写前端组件拆分、后端缓存实现、复述通用架构规范。

**后端实现.md**：DTO 校验规则、核心业务规则与流程、事务边界、缓存规则。禁止粘贴 DB DDL、写测试用例矩阵、写运维排障手册。

**前端实现.md**：组件拆分与职责、状态字段、表单校验、API 调用方式（契约必须引用）。禁止复述需求中的交互规范、写后端实现细节。

**测试用例.md**：测试点/步骤/断言、引用需求章节和性能阈值。禁止写独立接口清单、重复需求大段描述。
