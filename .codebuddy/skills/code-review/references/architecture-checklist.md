# 架构设计评审清单

## 模块职责划分

- 遵循单一职责原则
- 业务模块放置在正确位置
- 是否需要独立为新子模块

## 依赖方向

```
正确依赖：
业务组件 → common组件 → 框架组件
业务组件 → 本模块services → BaseService
业务组件 → 本模块hooks

禁止依赖：
业务模块A → 业务模块B 直接引用
common → 业务模块
```

> 项目具体的模块结构和目录约定，通过 `read_rules` 工具加载对应项目规范获取（如 `03-cbm-web-rules`）。

## 代码复用检查

- 是否有重复逻辑可抽取到 common
- 是否有可复用 hooks 未抽取
- 工具函数是否放在正确位置

## 分层架构

```
Components (视图层)
    ↓
Hooks / Store (状态层)
    ↓
Services (服务层)
    ↓
Types / Constants (定义层)
```

## 常见架构问题

1. **模块边界模糊**：功能跨多个模块，职责不清
2. **循环依赖**：模块间相互引用
3. **过度耦合**：组件直接调用其他模块内部实现
4. **大文件反模式**：单文件超过 500 行未拆分
