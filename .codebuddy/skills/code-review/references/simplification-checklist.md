# 代码简化评审清单

## 复杂度消减

| 检查项 | 说明 |
|--------|------|
| 嵌套层级 | 函数体内嵌套超过 3 层应考虑重构 |
| 嵌套三元 | 禁止嵌套三元运算符，改用 switch/if-else |
| 条件链长度 | 超过 3 个 `&&` / `\|\|` 的表达式应抽取为具名变量或函数 |
| 卫语句 | 优先使用 early return 减少嵌套 |

## 冗余消除

| 检查项 | 说明 |
|--------|------|
| 重复逻辑 | 两处以上相同逻辑应抽取为共享函数/hook |
| 无用变量 | 声明后未使用或仅赋值一次即传参的中间变量 |
| 冗余类型断言 | TypeScript 可推断的类型无需显式标注 |
| 过度封装 | 仅 1-2 行且无复用场景的代码不应抽为独立函数 |
| 死代码 | 注释掉的代码块、unreachable 分支应移除 |

## 命名与可读性

| 检查项 | 说明 |
|--------|------|
| 命名清晰度 | 变量/函数名应准确表达意图，无需额外注释解释"做什么" |
| 布尔命名 | 使用 `is`/`has`/`should`/`can` 等前缀 |
| 函数命名 | 使用动词开头，明确表达行为 |
| 注释质量 | 注释应阐明"为什么"而非"做什么"，删除描述显而易见行为的注释 |

## 结构优化

| 检查项 | 说明 |
|--------|------|
| 职责单一 | 单个函数/组件只做一件事 |
| 相关逻辑整合 | 分散在多处的关联逻辑应归拢到一起 |
| 合理拆分 | 超过 50 行的函数或 300 行的组件应考虑拆分 |
| 导入排序 | 按框架 → 第三方 → 项目内部 → 相对路径排列 |

## 常见代码异味

1. **过度链式调用**：`a?.b?.c?.d?.e` 超过 3 层应考虑中间变量或提前校验
2. **密集单行代码**：单行包含多个操作，为减少行数牺牲可读性
3. **God Component**：单个组件承担过多职责，状态和逻辑混杂
4. **Copy-Paste 编程**：多处相似但略有差异的代码块
5. **魔术数字/字符串**：硬编码的值应提取为具名常量

## 简化红线

以下情况**不应**简化，避免过度优化：

- 有助于代码组织的合理抽象
- 提升可调试性的中间状态保留
- 清晰的职责边界划分
- 有意义的类型标注（即使 TS 能推断）
- 为未来扩展预留的合理结构
