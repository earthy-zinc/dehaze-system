# dehaze 项目知识库

本 skill 只收录**程序性知识**——AI 不读就会做错的操作知识：坑与禁区、命令顺序、校验规则、实测反直觉口径、验收与排查纪律。

同一事实只存一处，各自落位：

- **陈述性知识**（是什么 / 为什么 / 架构与模块设计 / 接口与数据契约）→ `dehaze-doc/docs/`（VitePress 站点，人 / AI / 团队共读，新内容须与已有篇章合并去重）
- **程序性知识** → 本 skill（本页只放路由与元规则，事实进 `references/`）
- **强制红线** → `.codebuddy/rules/`
- **每会话基础口径**（仓库定位 / 端口 / 日志 / 生命周期纪律 / 文档入口）→ `CODEBUDDY.md`
- **环境事实**（机器 / 网段 / 端口准入 / K8s / 本容器工具链）→ `dehaze-doc`（陈述性知识）；**个人偏好与跨项目协作纪律** → 用户级长期记忆（远端 LongMemory，各机器共享）

本 skill 不写"详见 X"式引用（普通文档互引对模型基本无效）；只有 SKILL.md → 自身 `references/` 的路由是加载机制、必须保留。

## 二、读取元规则

1. 以磁盘代码 / 编译 / 实测为唯一裁决依据，成员自述与任务报告口径不可采信。
2. 结论性判断（范围、数量、"零引用 / 未实现"）须实测 + 计数基 + 时间戳；python 端"零引用"≠废弃，必须跨端核实。
3. 本 skill 无记录时，不凭直觉补默认值——先确认设计文档与代码的实际口径。

## 三、维护约定（面向维护本 skill 的 agent）

1. **准入**：新条目先过三问——①是陈述性知识（设计 / 契约 / 架构）吗？→ 写 `dehaze-doc`；②是强制红线吗？→ 写 `rules/`；③是环境事实或个人偏好吗？→ 环境事实写 `dehaze-doc`，个人偏好写用户级长期记忆。三问皆否则才进本 skill，且必须是"AI 不读就会做错"的程序性知识。
2. **单一信息源**：`SKILL.md` 只放路由与元规则，事实进 `references/` 对应主题文件；陈述性内容一律不重复，发现 docs 缺失或过时**先补 / 修文档**，再核验 docs 已有等价内容后删除 skill 条目；一事一行，保留可检索锚点（文件名 / 字段名 / 键名 / 错误码 / 命令）。
3. **写入与冲突**：只做增量插入 / 定点替换，禁止整体重写（多 agent 并发整体重写会因旧快照写回静默删除既有条目），写入后 grep 复核关键串；冲突优先级 `rules/` > 本 skill 事实记录，与 docs / 代码冲突时以磁盘代码与实测为准。一次性事件、测试数字、进行中待办写 agent 用户级记忆，**不进本仓库**。
4. **守卫优先（条目的退场条件）**：坑被机制化覆盖后（单测 / 轮末 hook 检查 / 静态校验脚本），条目压缩为"判据一句 + 守卫锚点"，删除实现细节与复现过程；新增坑时先问"能否加守卫"——能加就同时加守卫，加不了才写细节。声称"已修复"前必须找到守卫或实测证据（无守卫的"已修"最易腐烂）。
