# dehaze 项目知识库

本 skill 只收录**跨会话稳定、读代码看不出来、违反就出错的"项目事实与坑"**。行为规范（编码/注释/文档撰写/测试流程/设计稿）与每会话基础口径（端口、日志、账号、响应信封）由 rules 与 `MEMORY.md` 两层承载，**本 skill 既不重复也不引用它们**。动手写代码、评审、排查、做计划前，先按下面路由取用，不要凭印象猜契约。

## 一、按任务类型读取参考文件

| 任务类型 | 读取 | 重点小节 |
|---|---|---|
| 改接口/字段/错误码/分页、跨端对齐、写断言 | `references/02-跨端契约与一致性.md` | §1 parity 判据、§2 错误码与信封、§3 分页、§4 命名与值域 |
| 改模块、AI 域、推理链、MCP/KB/Skill/语音/可观测/评测 | `references/01-架构与模块定案.md` | §1 系统架构、§2 模块定案、§3 AI 推理机制 |
| 改表/字段/种子/迁移、定价计费、会员配额、缓存键、环境变量 | `references/03-数据与配置定案.md` | 全篇 |
| 写/跑测试、验收举证、多 agent 协作、改共享文件 | `references/04-测试与工程纪律.md` | §2 质量红线、§3 举证、§4 排查、§6 待裁决 |
| 写 Java/Go/Python/TS/Vue/RN/Flutter/Harmony 代码遇到怪问题 | `references/05-语言栈与工具链坑.md` | 对应语言段 |

组合场景：AI 对话 wire 契约（interrupt / plan / SSE）需同时读 `01` 与 `02`（前者管形状与机制，后者管跨端口径）；改任何 API 参数需读 `02` + `03`，并同步检查三端后端、SDK、各前端、文档与测试。

## 二、读取元规则

1. 以磁盘代码 / 编译 / 实测为唯一裁决依据，成员自述与任务报告口径不可采信。
2. 结论性判断（范围、数量、"零引用 / 未实现"）须实测 + 计数基 + 时间戳；python 端"零引用"≠废弃，必须跨端核实。
3. 本 skill 无记录时，不凭直觉补默认值——先确认设计文档与代码的实际口径。

## 三、维护约定

- 新增条目前自问：该事实是否已属更高层（行为规范 / 基础口径）？是否只是"读代码即知"？是则不写。
- **同一事实只存一处**：`SKILL.md` 与 `references/` 之间也不重复——SKILL.md 只放路由与元规则，事实进 `references/` 对应主题文件。
- **只做增量插入 / 定点替换**，禁止整体重写（多 agent 并发整体重写会因旧快照写回静默删除既有条目）；写入后 grep 复核关键串。
- 一事一行，保留可检索锚点（文件名 / 字段名 / 键名 / 错误码 / 命令）；一次性事件、测试数字、进行中待办写 `.codebuddy/memory/YYYY-MM-DD.md`。
