# 明细：测试与工程纪律
> `dehaze-project-knowledge` skill 的参考文件（按需 read_file）。收录：测试基建、测试质量红线、验收与举证、排查方法论、协作与文件写入纪律、文档/记忆治理、待裁决清单。

## 1. 测试基建
- **pytest（dehaze-python）**：`pytest.ini`＝`asyncio_mode=auto` / `testpaths=tests` / `--strict-markers`；conftest 每轮 DROP+CREATE `dehaze_test` 并全量导入 `config/sql/{schema,data}/*.sql`（`sys_*.sql` glob 过滤）；**`conftest.py` 必须在 import app 前强制 `os.environ` 覆盖测试库/端口**（pydantic-settings 中 dotenv 优先于类默认值，否则会 DROP 开发库）；并发开发用 `PYTEST_MYSQL_DATABASE=dehaze_test_xxx` 隔离（含 conftest `GET_LOCK` 按库名区分）；**三个 `_run` 文件禁用 `asyncio.run()`**。
- **SDK 集成测试基建事实**：vitest `fileParallelism:false`（并行互踢 A0230）；`expectBizError` 严格模式（业务码必须精确命中）；登录失败 5 次锁 30 分钟；改权限后清 `role:perms:*` 并重新登录；`test/utils/quota.ts` 自愈配额；离线单测放 `test/unit/`；`tsconfig` include `test/**` + strict + `exactOptionalPropertyTypes` ⇒ `npx tsc --noEmit` 校验契约；**`test/modules/*` 与 `test/factories/*` 有非 AI 域存量类型错（2026-09-19 实测 23 处，2026-09-19 晚 22→23 处口径一致，`git diff HEAD` 为空佐证非当次引入）会污染全量结果 ⇒ 判定自身改动须按文件过滤**。
- **开关依赖型用例**：默认套件仅 `test/modules/**`；开关 e2e 放 `test/e2e/**` + `vitest.e2e.config.ts` + `pnpm test:e2e`、两态无条件断言（禁 skip/runIf）；开窗勿改共享 `.env`：`USE_MULTI_POINT=true python3 scripts/run.py restart python`。
- **java 测试基建事实**：test-compile 失败会先清空 `target/surefire-reports` ⇒ 转述失败须以报告 mtime + `Tests run` + maven 摘要对齐；**改 parent 版本后必须 `mvn clean`**（增量编译不重编译未变更文件 → 陈旧类 `NoSuchMethodError`）；JDK 25 上必须 mockito 5.23.0 + byte-buddy 1.18.14（旧版全挂）、lombok 1.18.48、mapstruct 1.6.3。
- **go**：`DEHAZE_PASSWORD=... go test ./...`；`go test -count=1 ./...`；Go build cache **按内容哈希**（不需 `touch`），危险的是"纯新增不影响编译"的改动（路由/装配/文档）⇒ 必须 grep 计数复核；`make mocks`（mockery + `.mockery.yaml`），**禁 `--name/--dir` CLI**（会写进源码目录致双包编译红）；`mock_IAuthService.go` 为 mockery testify 风格，**不可用 mockgen 重新生成**。
- **测试库与种子**：pytest 每轮 DROP+CREATE `dehaze_test`；集成测试连开发库 `dehaze`（schema 变更须手工 ALTER）；种子同步 `test/integration/sync_seed_data.py`。
- **dehaze-test＝开发工作台**：人工触发、产物是数据报告非 pass/fail，不承载 CI/回归/SDK 契约测试；BACKENDS＝{java:8989, go:8990, python:8991}；验证码从 Redis 直读 `captcha_code:{captchaKey}` 避免 OCR；`utils/api.request` 请求体校验失败(400) 会 `raise_for_status`，探查原始响应需 httpx 直连。

## 2. 测试质量红线（用户确立，已入 `05-测试架构.md §6.4.5 反模式第 8 条`）
- **禁"环境未就绪型"skip**（模型未加载/引擎不可用/前置资源缺失/后端待重启）——必须让用例失败暴露；引擎自带自动下载/冷加载的用事件驱动等待 + 充足超时覆盖（禁固定 sleep）。仅允许两类 skip：**"功能确认未实现（规划中）"** 与 **"依赖能力设计上不存在"**。同理禁 `console.warn + return` 伪通过，改为前置断言（`expect(x).toBeGreaterThan(0)`）。
- **测试先行契约策略**：后端未实现时保留用例、**不 skip、不迁就后端**，文件头注释"后端未实现，测试先行契约"。
- **语料必须含对抗性脏数据**：全半角混杂/CRLF/BOM/零宽/emoji/超长行 + 格式变体 + 参数边界与不变量（固定 seed）+ 文件对抗（0 字节/随机字节/伪装扩展名/GBK）+ 性能烟测。脏语料必须用**合法 Unicode 码点**（`\U0001F600`），孤立代理 `\ud83d\ude00` 致 DB 驱动 UnicodeEncodeError。
- **"断言不存在"守卫须自带检测器自证**（负向断言有假绿风险 ⇒ 用"故意写旧键名让 tsc 报错"自证）；新增约束后须回看既有用例是否因约束前置而**假绿**。
- **等待 fire-and-forget 后台 task 用 task 注册集合差集 + `await`**（源码 `_pending_tasks` 模式），禁用 `asyncio.sleep`（"去 sleep"后须做**变异验证**）
- **mock 的 SimpleNamespace 属性名必须与实体列名一致**；"字段名错但默认值碰巧通过"＝契约错误须修；修 mock 目标必须是**模块级 import**（方法内局部 import 无法 mock）。

## 3. 验收与举证
- **禁"注解/配置存在"即通过**：须"注解 + 触发条件 + 兜底 + 必填性"四层同核 + **摘除反证**（删注解→用例必须红）+ 行为级负向用例（断 code + `verifyNoInteractions`）+ 必填/越界各一条"未落库"断言。
- **pytest 服务层断言不触发 `response_model` 校验 ⇒ VO 契约缺陷必须在 router/SDK 层覆盖**（eval result 双重编码正是由 SDK 500 暴露）。
- **改断言前先跑 python 基准单文件确认真实行为**（比读源码推演更快更准）；"测试断言与基准实现冲突"类（favorite 复活、dict 软删占键、package 删除后同名重建）**按方案 a 改测试对齐 python 实际行为，不改实现**。
- **修复引入行为变化（余额扣减/校验收紧）前先查测试数据前置依赖与自愈机制**，否则"越修越挂"假回归；**模块间依赖修复会"解锁"新失败面**，勿把上轮失败清单当完备。
- **复跑必须带时间戳 + 类集清单**，且排在所有域最后编辑之后；`brief.json`/日志 mtime＝结束时刻，归属须用 `/tmp/runN_started_at` 标记；**`brief.json` 失败分布文件名带行号（如 `menu.test.ts:43`）⇒ 必须先 `split(':')` 再匹配**。
- **范围/数量声明必须实测 + 附"计数基 + 时间戳"**（gofmt 事故：43 = 计数基 `find internal -name '*.go' -newermt 01:35 ! -newermt 01:39` + 上界 01:40 + 取数时刻）。

## 4. 排查方法论
- **`test/logs/<backend>/detail.log`（NDJSON）按时间序定位首个失败 traceId 及前序请求**，不要猜；SDK 登录会话权限快照在 redis `session:{uuid}` 可解码核对；DB 侧用 `dehaze-test db_query`/pymysql 直查 `sys_role_menu`。
- **判定"回归"前先排除自身并行造成的资源争用**：把 python pytest 与 front-vue vitest 放同一批次并发执行，会让 `test_deep_agent_builder_e2e.py` 3 例偶发失败（单跑 556 passed/0 failed）；`vitest --reporter=basic` 在 vitest 4 不存在（勿误判为测试失败）。
- **`-k` 子集运行有跨测试顺序干扰**（子集偶发失败、单文件全绿）⇒ 先单文件复跑，终验用全量。
- 排查法：编译/资源类批量失败用 **git stash 二分逐步恢复** 远快于逐个检查文件（`git stash pop` 不恢复 untracked，用 `git show "stash@{0}^3:<path>"` 提取）；**Lombok 类海量假错**先找第一条真实语法错误（重复注解 `@Valid @Valid` → javac 早失败 → Lombok 整轮失效）；`jdb -attach` + `catch java.lang.StackOverflowError` + `where` 是定位 SOE 自递归的终局手段。
- **subagent 报告与任务书均不可轻信**：可能虚构用例名、误读配置值、按字段名字面直觉解读语义（`actual_model` 误报）；**Python 端"零引用"≠废弃，必须跨端核实**。
- **推理类排查**：`[runtime not ready]` 前缀表示错误在 JS runtime ready 前的模块加载期 → 优先查入口链模块顶层代码；**双端（iOS+Android）同错＝JS bundle 层问题，不是原生链接问题**。

## 5. 协作细则
- **append-only 文件**（日志/记忆）用 shell `cat >>`/`printf >>` 原子追加，避免并发旧快照写回；未跟踪文件无 git 基线，重写前先 read_file 只增量。
- **误用 `git stash`/`reset` 后的恢复法**：`git stash show` 定位 + `git checkout 'stash@{n}' -- <files>` 精准恢复。
- **跨成员细则**：同一文件禁并行编辑（stale buffer 回退）；SDK 测试严禁两端同时跑（共享开发库+Redis）；重启只动自己负责的后端；改共享测试文件前先广播；删模块顶层 import 前 grep 全部引用点（含返回类型注解）。
- **越界与非本人改动**：越界改动宁可留 diff 噪音也不 `git checkout`；域内非本人改动先按"团队在途中间态"排查，上报不擅自恢复；**"同域同时被改 ≠ 同一人"**，勿归因幽灵写入者。
- `git commit` 后必须 `git show --stat` 核对（曾 `dehazi-java` typo 致 commit 静默缺文件）。
- 命令执行：含 `sleep 50+`/`pgrep` 的复合内联命令易审批超时 ⇒ 写脚本 + 单条 `bash /tmp/x.sh`；跨轮归属用标记文件 + 产物 mtime + 首末请求交叉确认；用户偏好**不要多次无意义重试**测试/命令。成员触达 500 请求上限暂停后，用 Task 同名 + 同 team_name 重生（会话历史自动载回）。
- **subagent 任务粒度不能太大**（一个模块/功能点逐个验证）；免费 code agent 并发 9 个时 4 个失败 ⇒ 单独派发 + 任务书强调"直接进入编辑并落盘" + `max_turns 150`。
