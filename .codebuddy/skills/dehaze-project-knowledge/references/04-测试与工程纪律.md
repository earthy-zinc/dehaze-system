# 明细：测试与工程纪律

> **边界**：本文件只收程序性知识（判据 / 坑与禁区 / 实测口径 / 操作纪律）；陈述性知识以 `dehaze-doc/docs/` 为唯一权威源，不重复转述；冲突时以磁盘代码 + 实测为准。

## 1. 测试基建

- **pytest（dehaze-python）**：`pytest.ini`＝`asyncio_mode=auto` / `testpaths=tests` / `--strict-markers`；conftest 每轮 DROP+CREATE `dehaze_test` 并全量导入 `config/sql/{schema,data}/*.sql`（`sys_*.sql` glob 过滤）；**`conftest.py` 必须在 import app 前强制 `os.environ` 覆盖测试库/端口**（pydantic-settings 中 dotenv 优先于类默认值，否则会 DROP 开发库）；并发开发用 `DEHAZE_TEST_DB=dehaze_test_xxx` 隔离（含 conftest `GET_LOCK` 按库名区分；**xdist `-n N` 下 conftest 自动派生 `{DEHAZE_TEST_DB}_gw{i}` 每 worker 独立库**，跨 worker 零行锁争用，worker 库可留存复用）；**三个 `_run` 文件禁用 `asyncio.run()`**。
- **SDK 集成测试基建事实**：vitest `fileParallelism:false`（并行互踢 A0230）；`expectBizError` 严格模式（业务码必须精确命中）；登录失败 5 次锁 30 分钟；改权限后清 `role:perms:*` 并重新登录；`test/utils/quota.ts` 自愈配额；离线单测放 `test/unit/`；`tsconfig` include `test/**` + strict + `exactOptionalPropertyTypes` ⇒ `npx tsc --noEmit` 校验契约；Stop hook 以指纹去重、只报新增；但 `tsc` 是项目级、无法按文件裁剪，**"某错是否本次改动引入"仍须按文件/基线过滤判定**。
- **SDK 集成测试并行的硬约束**（并行方案据此设计）：`member` / `member-edge` / `order` / `order-edge` / `package` / `billing` / `billing-edge` / `ai-schedule` / `knowledge-base` 会改写全局权益/等级/配额，**必须同组串行**；18 处"性能烟测"（200/500/1000/2000ms 阈值）依赖空载，并行或叠加负载必然 flaky ⇒ 须剥离到独立串行套件；登录侧不撞防重复（`/api/v1/auth` 前缀豁免）、不互踢（`USE_MULTI_POINT` 默认 False）。
- **java 测试基建事实**：test-compile 失败会先清空 `target/surefire-reports` ⇒ 转述失败须以报告 mtime + `Tests run` + maven 摘要对齐；**改 parent 版本后必须 `mvn clean`**（增量编译不重新编译未变更文件 → 陈旧类 `NoSuchMethodError`）；JDK/mockito/byte-buddy/lombok/mapstruct 的版本口径以 `dehaze-java/pom.xml` 为单点（JDK 25 上旧版 mockito 全挂）。
- **go**：`go test ./...`——测试库凭证由 `internal/testutil/mysql.go` 用 `godotenv` 显式读**仓库根 `.env`**（与 CWD 解耦）的 `MYSQL_USERNAME`/`MYSQL_PASSWORD`；**不存在 `DEHAZE_PASSWORD`**（根 `.env` 零 `DEHAZE_*` 变量）；库名取 `DEHAZE_TEST_DB`、默认 `dehaze_test`；`go test -count=1 ./...`；Go build cache **按内容哈希**（不需 `touch`），危险的是"纯新增不影响编译"的改动（路由/装配/文档）⇒ 必须 grep 计数复核；`make mocks`（mockery + `.mockery.yaml`），**禁 `--name/--dir` CLI**（会写进源码目录致双包编译红）；`mock_IAuthService.go` 为 mockery testify 风格，**不可用 mockgen 重新生成**。
- **测试库 / 种子基建**（pytest 每轮 DROP+CREATE `dehaze_test`、集成测试连开发库 `dehaze` 且 schema 变更须手工 ALTER）见 `02-系统架构/05-测试架构.md`；`dehaze-test` 工作台的验证码从 Redis 直读 `captcha_code:{captchaKey}` 免 OCR，其 `utils/api.request` 对 400 会 `raise_for_status` ⇒ 探查原始响应须 httpx 直连。
- **各端门禁口径**：front-vue 跑 `pnpm lint` + `pnpm test:unit` + `pnpm exec vue-tsc --noEmit`（`pnpm build` 含 vue-tsc）；taro `tsc --noEmit`、uniapp `vue-tsc --noEmit`；**TS 项目类型检查全量纳入 Stop hook**（`.codebuddy/hooks/verify-on-stop.mjs` 的 `TYPE_CHECK_PROJECTS`；纳入口径＝"默认分支类型干净"，不按耗时排除；**改 SDK 源码会触发 hook 先重建产物、再连带检查所有下游**）；react-native `jest.config.js` 已就位（`transformIgnorePatterns` 已放行 `@react-navigation`，`moduleNameMapper` 指向 SDK `dist/index.cjs`）。**Stop hook 另含四类检查**（触发面见 hook 内 `GO_GUARDS`/`REPO_GUARD_SCRIPTS`）：go 契约守卫（权限↔种子/mock、GORM `default:` 零值扫描、`model_type` 跨端值域）、仓库铁律脚本（`scripts/check_dockerfiles.py`）、**eslint 只读分组**（只报 error；`--fix` 不可自动修复的规则由此在轮末可见，如 front-vue `ai-chat` 四禁 import）、上游 `dist` 陈旧自动重建（避免下游假绿/假错）。
- **本工作区未全量 `pnpm install` 时前端类型检查会出环境性假错**：front-vue/front-react 会报 `dotenv`/`ioredis` 的 `TS2307`（声明在 package.json 但未安装）；且 `dehaze-sdk-js/dist` 未重建时 front-vue `vue-tsc` 会多报大量 SDK 契约错，`pnpm --filter dehaze-sdk-js build` 后即消失 ⇒ 判定此类失败前先分辨"环境" vs "真实回归"（先补 `pnpm install` + 重建 SDK dist 再下结论）。
- **按 md5 去重的上传类用例必须用每轮唯一内容**（`f"…{uuid.uuid4()}".encode()`）：`upload_file` 命中残留 `sys_file` 行即秒传早返回，不再写本次 `tmp_path` 物理文件 ⇒ 物理断言假失败、或断言在残留命中时静默变弱。
- **`dehaze-mcp-gateway` 收集纪律**：模块级禁副作用（勿在 import 期连真实网关或 `sys.exit`）；`pyproject.toml` 已配 `[tool.pytest.ini_options]`（防 `*_test.py` 误收），改动后用 `pytest --collect-only` 验证；live 校验手动跑 `tests/live_test.py`（连真实网关 8082，不入收集）。
- **java 编译/测试一律走 /tmp 副本（硬纪律）**：dev-profile 下 `mvn test`/`test-compile` 会重写 `target/classes`，与运行中的 `spring-boot:run` 不可并存。完整事故链（2026-10-04 实测）：**在途编译错误 → 编译不产出新类 → devtools 重载时 MyBatis 解析不到 `target/classes` 的类（`ClassNotFoundException`）→ Application run failed → 进程在但端口不监听**；并发 maven 互毁则表现为整类 `NoClassDefFoundError` / `bad class file`。**prod（含复用 prod 的 pre）** 由 `run.py` 以 `mvn package` + `java -jar` 启动，jar 已载入 JVM、不受 `mvn test` 影响。
- **SDK 集成测试的基建事实**：`test/config/vitest.setup.ts` 的全局 `beforeAll` 调 `login()`，其用户名默认 **admin** 且无环境变量开关（`test/utils/auth.ts`）⇒ 跑任一 SDK 测试文件都会以 admin 登录入队，会挤掉同账号的并行持有者会话（排查见 §4）。
- **Node undici 会 percent-encode 上传文件名**：SDK 层测不出"文件名含控制字符"（`\x00-\x1f` 等）的真实行为，这类对抗语料必须由 pytest 层覆盖。
- **语音流式 ASR 的孤儿会话会占并发名额**：失败运行留下的会话堆在 `voice:asr:sessions`（30 分钟剪枝、上限 50），表现为后续运行全部"ASR 并发会话数已达上限"⇒ 先查 Redis（dev `db=1`）`zcard` 并清理。
- **本工作区（pre）作业口径**：pre 是"只测不开发"的共享环境，**不在本环境跑集成测试**（`dehaze-test/` 等，交 dev 环境 agent）；单测必须落独立 `DEHAZE_TEST_DB=<独立库>`（勿写 `dehaze_pre`/`dehaze_dev`，`tests/conftest.py` 按 `config/sql` 指纹重建，与 pre 隔离），临时库用完自 DROP；污染 pre 后的复位口径（重建即从 `config/sql` 全量导入，属破坏性操作须先经用户确认）见 `02-系统架构/10-多环境部署实践.md`。
- **前端 e2e（Playwright）口径**：权威 lockfile 是**仓库根的 `pnpm-lock.yaml`**（`pnpm install --frozen-lockfile` 在根跑）；各前端目录内残留的旧 `pnpm-lock.yaml` **非事实源**，曾据此误判"版本漂移、要降版本"。**Playwright 浏览器缓存与版本强绑定**（如 1.61.1 需 `/root/.cache/ms-playwright/chromium-1228`）⇒ 判版本看根 lockfile + `node_modules/.pnpm/playwright-core@*/browsers.json` 的 `revision` 再核对缓存目录；缺浏览器用 `npx playwright install chromium`，**勿改 `package.json` 版本**。
- **前端页面测试先侦察再动手**：先摸清入口端口（front-vue `vite preview --mode test`=5274 / dev=5174）、鉴权方式（HttpOnly cookie `X-Session-Id`，需浏览器内登录）、默认口令 `SEED_PASSWORD`（`dehaze-test/utils/config.py`、`dehaze-sdk-js/test/config/constant.ts`）；探索/取证用 chrome-devtools MCP（含 `evaluate_script` 兜底 el-switch 等 `click` actionability 失败），确认的问题**补成 Playwright 页面级断言入回归**，不要只口头报告。
- **pre 跑 Python 负向 SDK 套件的已知噪音**：prod profile 下 `settings.DEBUG=False`，Python(8991) `app.middleware.ip_blacklist` 会自封回环 IP（统计的是**响应 status≥400 的请求数**，阈值 100/60s、封 3600s），`pnpm test:python` 前几个文件即可凑满 ⇒ 跑前外挂看门狗轮询 `EXISTS ip:blacklist:127.0.0.1` 以便命中即停；判据 `redis-cli -n 2 TTL ip:blacklist:127.0.0.1` / `ZCARD ip:errors:127.0.0.1`；解封需删键（破坏性，须用户确认，勿擅自做）。
- **pre 判定 AI 功能失败前先分"环境缺口"与"真实缺陷"**：DB 重建后 `sys_ai_provider_key` 为 0 行（密钥不入 git）、`dehaze-llm/voice/modal`（8992/8993/8994）常未启动 ⇒ `A0600 该供应商无可用 API Key` / `A0500 供应商 local-voice 无可用 API Key` 多为环境缺口，非真实缺陷；补 Key 属改数据，须先经用户确认。

## 2. 测试质量红线（用户确立；dehaze-python 反模式第 8 条）

- 前端测试禁 `console.warn + return` 伪通过，改为前置断言（`expect(x).toBeGreaterThan(0)`）。
- **语料必须含对抗性脏数据**：全半角混杂/CRLF/BOM/零宽/emoji/超长行 + 格式变体 + 参数边界与不变量（固定 seed）+ 文件对抗（0 字节/随机字节/伪装扩展名/GBK）+ 性能烟测。脏语料必须用**合法 Unicode 码点**（`\U0001F600`），孤立代理 `\ud83d\ude00` 致 DB 驱动 UnicodeEncodeError。
- **"断言不存在"守卫须自带检测器自证**（负向断言有假绿风险 ⇒ 用"故意写旧键名让 tsc 报错"自证）；新增约束后须回看既有用例是否因约束前置而**假绿**。
- **等待 fire-and-forget 后台 task 用 task 注册集合差集 + `await`**（源码 `_pending_tasks` 模式），禁用 `asyncio.sleep`（"去 sleep"后须做**变异验证**）
- **mock 的 SimpleNamespace 属性名必须与实体列名一致**；"字段名错但默认值碰巧通过"＝契约错误须修；修 mock 目标必须是**模块级 import**（方法内局部 import 无法 mock）。

## 3. 验收与举证

- **禁"注解/配置存在"即通过**：须"注解 + 触发条件 + 兜底 + 必填性"四层同核 + **摘除反证**（删注解→用例必须红）+ 行为级负向用例（断 code + `verifyNoInteractions`）+ 必填/越界各一条"未落库"断言。
- **pytest 服务层断言不触发 `response_model` 校验 ⇒ VO 契约缺陷必须在 router/SDK 层覆盖**（eval result 双重编码正是由 SDK 500 暴露）。
- **改断言前先跑 python 基准单文件确认真实行为**（比读源码推演更快更准）；"测试断言与基准实现冲突"类（favorite 复活、dict 软删占键、package 删除后同名重建）**按方案 a 改测试对齐 python 实际行为，不改实现**。
- **修复引入行为变化（余额扣减/校验收紧）前先查测试数据前置依赖与自愈机制**，否则"越修越挂"假回归；**模块间依赖修复会"解锁"新失败面**，勿把上轮失败清单当完备。
- **复跑必须带时间戳 + 类集清单**，且排在所有域最后编辑之后；`brief.json`/日志 mtime＝结束时刻，归属须用 `/tmp/runN_started_at` 标记；**`brief.json` 失败分布文件名带行号（如 `menu.test.ts:43`）⇒ 必须先 `split(':')` 再匹配**。
- **范围/数量声明必须实测 + 附"计数基 + 时间戳"**（示例：`find internal -name '*.go' -newermt <起> ! -newermt <止>` ＋上界与取数时刻）。
- **"零命中 / 零残留"结论必须带对照组**：本容器无 `rg`（`rg ... 2>/dev/null` 会把报错吞成假阴性 0 命中）⇒ 用 `grep -rIl`（排除 node_modules/.venv/target/build/.git/logs/.pytest_cache/.codebuddy/.vitepress）或 `search_content`，并同时给出对照组命中数（对照组也为 0 ⇒ 本次搜索无效，须换工具重跑）。**搜索串本身也会失效**：文档里是反引号包裹的 `` `modelId` 关联 ``，用裸串 grep 得 0 时先自证搜索串（剥掉 markdown 格式符再试）。**`search_content` 只传纯排除 glob（如 `!*.lock`）会静默 0 命中**（同一串传 `glob=!*.log` 得 0，改传显式包含 glob 才命中）⇒ 必须给**显式包含 glob**，并同时给对照组命中数。
- **禁 `grep | head -N` 后下"不存在"结论**（`| head` 会在同类文件里截断，曾据此误判"全仓无路由守卫"）：先 `| wc -l` 看总数，或对照一个已知存在的模式。
- **编辑 / 写入工具"报 success"不证明落盘**：必须回读或对该处关键串逐个 grep；同一文件在**一次批量**里发多处编辑会丢失首处，文件字节数变大也不能替代逐处核验；工具有秒级延迟，"立即 grep 得 0"不等于丢失（隔 1-2s 复核）。
- **`git diff --stat <path>` 对被 `git add` 过的改动返回空**（假阴性"没改"）⇒ 用 `git diff --cached --stat` 或 `git status --porcelain`（首列 `M ` = 已暂存、第二列 `M` = 未暂存）。
- **交接清单与文档陈述必须回代码抽检两类**：①数量断言（`ls <dir>/*.java | wc -l`，注意口径——`ui/system/` 顶层 15 文件是 14 Activity + 1 Fragment）②构件名（"已删除 X"先 `git show HEAD:<path>` / `find -iname` 确认曾存在；"零残留"要逐个类名/资源名单独 grep）。这两类会静默腐烂且关键词 grep 抓不到（例：交接文档里的类名从未存在、API 类计数被静默改动）。
- **"内容一致 / 不一致"结论必须同时给响应长度 + 差异行数**（`wc -c` + `diff | grep -c '^[<>]'`），并先归一化时间戳类噪声（Vite 产物内嵌 `?t=<HMR 时间戳>`）；`curl <大文件> | md5sum` 会因响应截断伪造"不一致"。
- **浏览器 `performance.getEntriesByType('resource')` 有 250 条上限**：页面资源多时（本项目 element-plus 数百模块）会丢早期条目 ⇒ 查首屏资源得假空；改用 CDP 网络面板 + 服务端 curl + DOM/CSS 引用三查互证，并注意面板可能残留上一轮加载记录。
- **改动用"三件套"交叉验证：`read_file` 复核改动点 → `read_lints` → grep 残留引用（含旧符号名）**；需要类型验证时用**范围化 tsc（指定文件/模块）**、不手跑全仓（全量类型检查由 Stop hook 轮末自动做，见 §1）；**被调用到的函数/命令必须真实执行一次才算验证通过**（`bash -n` 只验语法，查不出缺失定义）。

## 4. 排查方法论

- **`test/logs/<backend>/detail.log`（NDJSON）按时间序定位首个失败 traceId 及前序请求**，不要猜；SDK 登录会话权限快照在 redis `session:{uuid}` 可解码核对；DB 侧用 `dehaze-test db_query`/pymysql 直查 `sys_role_menu`。
- **判定"回归"前先排除自身并行造成的资源争用**：把 python pytest 与 front-vue vitest 放同一批次并发执行，会让 `test_deep_agent_builder_e2e.py` 3 例偶发失败（单跑即全绿）；`vitest --reporter=basic` 在 vitest 4 不存在（勿误判为测试失败）。
- **`-k` 子集运行有跨测试顺序干扰**（子集偶发失败、单文件全绿）⇒ 先单文件复跑，终验用全量。
- **SDK 集成测试成片 `A0230 会话失效` 先查残留 vitest 进程**：`timeout`/工具超时杀掉 pnpm·vitest 父进程后其 worker 可继续跑，与新进程抢同一账号 session（单点互踢）⇒ 跑前 `pgrep -af vitest.mjs` 确认无残留再串行单跑复验（干净串行单跑即全绿）。
- 排查法：编译/资源类批量失败用 **git stash 二分逐步恢复** 远快于逐个检查文件（`git stash pop` 不恢复 untracked，用 `git show "stash@{0}^3:<path>"` 提取）；**Lombok 类海量假错**先找第一条真实语法错误（重复注解 `@Valid @Valid` → javac 早失败 → Lombok 整轮失效）；`jdb -attach` + `catch java.lang.StackOverflowError` + `where` 是定位 SOE 自递归的终局手段。
- **subagent 报告与任务书均不可轻信**：可能虚构用例名、误读配置值、按字段名字面直觉解读语义（`actual_model` 误报）；**Python 端"零引用"≠废弃，必须跨端核实**。
- **推理类排查**：`[runtime not ready]` 前缀表示错误在 JS runtime ready 前的模块加载期 → 优先查入口链模块顶层代码；**双端（iOS+Android）同错＝JS bundle 层问题，不是原生链接问题**。
- **判定"某目录未动、归我独占"前先跑并发写者探针**：`git status --porcelain <dir>` + `find <dir> -type f -newermt '-15 minutes' -printf '%TH:%TM:%TS %p\n'`；有他人近期 mtime ⇒ 停手并上报（派单口径可能已过期）。队友**通常**跑在隔离 git worktree（`.codebuddy/worktrees/bg-<hash>`、分支 `worktree-bg-<hash>`；若其自行 commit，主工作区 `git status` 会是空的），但**也实测出现过队友直接写主工作区同一目录** ⇒ 两种都要按探针判断。核实队友产出：`git worktree list` + 逐 worktree `git status --porcelain` / `git diff master --stat`，主工作区 grep 为空不能作为"没干活"的依据；跨面集成由主 agent 在主工作区做（`git -C <worktree> diff > /tmp/x.patch` 后 `git apply`，未跟踪文件单独拷贝；让队友"不 commit、留未提交改动"便于取 diff）。
- **会话莫名 401 / A0230 先查会话队列**：三端共库 `session:user:{userId}` ZSet（上限 admin=10 / 普通=1，登录时按 score 升序踢最早）——任何以同账号登录的套件都会挤掉更早的持有者（SDK 套件每轮都会以 admin 登录，足以打断并行的页面遍历）⇒ `zcard` / `zrange ... WITHSCORES` 核实，不要先怀疑 TTL 或 Redis 清理。
- **Java(8989) 全局鉴权过滤器在路由匹配之前**：无会话时对**任意路径**（含不存在的路由）一律返回 `401 A0230`，无法区分"路由不存在"与"缺 token" ⇒ 探测端点是否存在必须带真实会话（从对应 Redis DB 的 `captcha_code:<key>` 取明文登录），并配对照组（如 `/api/v1/ai/models` → 200）才能证明"路由不存在"。
- **超时 / 日志空窗先排除持续性故障再下结论**：先用证据区分「持续故障」与「偶发阻塞」，别先假设应用层问题；**判定网络类故障最有效的分界是「超时（多为 DROP 隔离）vs 连接拒绝（端口拒绝）」**，逐目标在真实运行环境内直连对比更可靠；探测内网域名要在能解析它的主机/Pod 上跑，`curl` 用 `-sS` 并看 `http_code` + exit code（`-s` 吞错会误判"无响应"）；用户给出反证时立即复核自己的结论，不做辩解式重申。

## 5. 协作细则

- **append-only 文件**（日志/记忆）用 shell `cat >>`/`printf >>` 原子追加，避免并发旧快照写回；未跟踪文件无 git 基线，重写前先 read_file 只增量。
- **误用 `git stash`/`reset` 后的恢复法**：`git stash show` 定位 + `git checkout 'stash@{n}' -- <files>` 精准恢复。
- **跨成员细则**：同一文件禁并行编辑（stale buffer 回退）；SDK 测试严禁两端同时跑（共享开发库+Redis）；重启只动自己负责的后端；改共享测试文件前先广播；删模块顶层 import 前 grep 全部引用点（含返回类型注解）。
- **越界与非本人改动**：越界改动宁可留 diff 噪音也不 `git checkout`；域内非本人改动先按"团队在途中间态"排查，上报不擅自恢复；**"同域同时被改 ≠ 同一人"**，勿归因幽灵写入者。
- `git commit` 后必须 `git show --stat` 核对（文件名笔误会致 commit 静默缺文件）。
- 命令执行：含 `sleep 50+`/`pgrep` 的复合内联命令易审批超时 ⇒ 写脚本 + 单条 `bash /tmp/x.sh`；跨轮归属用标记文件 + 产物 mtime + 首末请求交叉确认；用户偏好**不要多次无意义重试**测试/命令。成员触达 500 请求上限暂停后，用 Task 同名 + 同 team_name 重生（会话历史自动载回）。
- **subagent 任务粒度不能太大**（一个模块/功能点逐个验证）；免费 code agent 并发 9 个时 4 个失败 ⇒ 单独派发 + 任务书强调"直接进入编辑并落盘" + `max_turns 150`。
- **共享工作区禁 `git stash`/`reset`/`checkout`**（会卷走队友未提交改动）；越界改动宁可留 diff 噪音也不 `git checkout`；域内非本人改动按"团队在途中间态"排查，**上报不擅自恢复**（误用后的精准恢复见上文）。
- **`TaskOutput(block=true)` 轮询后台 agent 会把它们全部杀掉**（等自动回报即可）；`Subagent 'xxx' not found` 通常是 `.codebuddy/agents/*.md` frontmatter 的 `model` 指向已失效的模型 ID（改 ID 后须重启 IDE/会话才在 Task 生效），不是文件缺失或名称问题。
- **范围纪律三条**：①不因"顺手"扩大范围——无消费者的预置基建属提前消费（落地前先问"执行者/受害者是谁"）；②跨技术栈不可生搬硬套（taro 底层是 webpack5，`vite preview` 经验套过去不成立；先确认该端实际构建器与产物形态再动手）；③重建 todo 列表不得丢失主线待办（新任务用 `merge=true` 追加；必须重建时先把主线未完成项原样抄进新列表）。
- **架构级 / 跨端改造默认交付物是设计文档**（放 `dehaze-doc/docs/05-改造计划/`），列明待用户裁决的决策点并声明"未改任何代码，待审核"；**用户明确批准后才进入实现**，不要"文档写完顺手开改"。
- **agent-home 多 worktree 协作纪律**：①开工先 `git merge master` 拿阶段基线（不要基于旧基点改）；②**严禁把主工作区/别的 worktree 的文件复制进自己 worktree**（会镜像污染合并基准）；③合并口径＝每个 worktree 相对 master 的 diff **只含自己任务增量**；④**同路径同名文件双份产出高危**（只保留一份、由 lead 裁定，另一份整包不合入）；⑤判断"改动是否生效"要 **grep 主工作区内容**（worktree 的 commit 不是 master 祖先，但内容可能已在基线），"是否需再合"用 `git merge-base`——两者结论可相反；⑥worktree 内**无 `.env`/`.venv`**（需 symlink），pytest conftest 从**本 worktree 的 `config/sql`** 重建测试库 ⇒ 新列未合入时含新列的 DB 用例会 `Unknown column` 假失败（只跑免 DB 子集自证）。
- **回报"完成"必须自带磁盘证据**：worktree 路径 + `git status --porcelain` 原文 + `git rev-parse HEAD` + 关键验证命令的**真实退出码** + 显式列出"未做的事"；无磁盘证据的完成不被采信。
- **取退出码必须 `cmd > log 2>&1; echo $?`**（`(cmd | tail); echo ${PIPESTATUS[0]}` 拿到的是 `tail` 的码，曾因此作废一轮证据）。
- **计量单位按 `model_type` 派生，不新增必填校验层**（派生映射见 `基础模块/AI模型管理/后端实现.md`）——**涉及钱的字段例外：禁止把非 token 模型静默落成 token 计量**。
- **pre 环境只读 + git 同步纪律**：pre（21.6.51.87 / `ssh earthy-pre`）**不改被 git 跟踪的项目文件**——改代码/脚本/文档一律本地改 → `git push origin master` → pre `git pull --ff-only` 同步，改完回报两边 commit hash；**例外**：`.gitignore` 覆盖的配置（如 `.env`）与项目目录之外的文件可直接在 pre 改（含 `run.py` 重启生效）。
- **提交范围纪律：禁 `git add -A` / `git commit -a` / push**——工作区长期混有多条并行线（他人或其它 agent）的在途改动，整体提交会静默带走未验证、未归属的改动；任何 commit 前先 `git status` 分类归属、把"哪些线可提交、由谁提交"列给用户裁决，用**显式路径清单**提交，跨线同文件（如 `app/config.py`）先与归属人协调或做 hunk 级拆分。

- **环境 / 基础设施级阻塞先做 1–2 次轻量探测就上报，别自行长时间试凑配置**：报错指向内网域名 / 代理 / 证书，或需要企业内网地址、VPN、企业凭据时（实例：2026-09-23 `git.code.oa.com` 域名失效致 Go 内部依赖拉不下来、需配 GOPROXY），先用 1–2 次轻量探测（如 `ls-remote`、HTTP discovery）确认事实，随即停下来告知用户并给出可选方案，把精力留在能自主推进的部分。内网服务地址、凭据、VPN 状态掌握在用户侧，靠探测穷举成本高且不可靠。
- **imate 项目沉淀仓（dehaze）在 `D:\imate_project-dehaze-system`**（工蜂 `IMateTeamGroup/imate_project-dehaze-system`，默认分支 `release`）：形态为 OKF v0.2 concept 文档（frontmatter `type` 必填、`sources` 溯源、`generated`/`verified` 分离）+ markdownlint 零警告（行长 80、表格长行用 `<!-- markdownlint-disable MD013 -->` 局部包裹、中文标签、标题唯一）；分层 `docs/`（管理视角）· `rules/`（技术规约）· `skills/custom/`（Agent 技能，入口 `SKILL.md`）· `memories/`（项目记忆）；写入流程（仓内 `rules/pm/doc-repo-workflow.md` 强制）：从 `release` 拉 `agent/imate-{YYYYMMDD}-{8位uuid}` 分支 → commit → push → 向 `release` 提 MR，同一时刻仅一个在途 MR。项目对开发环境无特殊要求，云桌面只是历史上部分时段用过的环境，任何"本机环境"结论只能作有条件线索。
