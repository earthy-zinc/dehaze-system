# 明细：数据与配置定案

> **边界**：本文件只收程序性知识（判据 / 坑与禁区 / 实测口径 / 操作纪律）；陈述性知识以 `dehaze-doc/docs/` 为唯一权威源，不重复转述；冲突时以磁盘代码 + 实测为准。

## 1. 环境与配置原则

- **根 `.env` 分区与命名（改迁移前核对，勿留旧名）**：`MYSQL_*`/`REDIS_*`/`MONGODB_*`/`ES_*`/`MINIO_*`/`RABBITMQ_*`/`XXLJOB_*`/`NGINX_STATIC_*` + `JWT_SECRET_KEY`/`DEFAULT_PASSWORD`/`ADMIN_PASSWORD`。**旧名零回退、勿再引入**：`DEHAZE_HOST`/`DEHAZE_PASSWORD`、python `DB_*`/`MINIO_BUCKET_NAME`/`RABBITMQ_USER`/`_apply_derived_credentials`（无自动守卫）。
- **加载顺序：环境变量优先于 `.env`**；`dotenv` 只加载一次（vitest globalSetup 与 setupFiles 同进程 ⇒ `vitest.setup.ts` 不重复加载）。
- **配置项判定标准**：仅"管理员/运营有明确修改动机"的参数才字典化（`sys_dict`），纯技术参数（缓存 TTL/分页/批次/轮询/锁定/心跳/cron/线程池）一律代码常量；个性化由实体级配置覆盖，**不设第三层全局字典默认**。典型判定：推理默认值＝代码常量 `agent_config_resolver.REASONING_DEFAULTS`（不是字典 `ai_reasoning_defaults`）；`ai_guardrail_defaults` 保留（安全合规有运维场景），缓存键 `ai:config:guardrail_defaults`。字典增删改即时失效缓存；缺键 warn + 回退默认值（**不保留旧常量转发**）。新增 `sys_dict` 种子须同步 `config/sql/data/*.sql` + python 种子 + `SYSTEM_PRESET_DICT_TYPE_CODES` + seed contract 测试。**字典项的 `status`**：`status=0` 视同缺项（停用即不生效、回落调用方默认）——python 统一在 `dict_service.get_dict_value` 兜底（`item.status == 1` 才取值；**不要**改共享仓储 `get_by_type_code_and_name` 的活跃行口径，种子判重必须能看到停用行），go/java 在各自字典读取层过滤。
- **推理默认值唯一声明处**＝`agent_config_resolver.REASONING_DEFAULTS`（内部键 snake、对外 camel），经 `GET /api/v1/ai/agents/config-defaults`（登录可读，**须注册在 `/{agent_id}` 之前**）只读透出；批次常量 `BATCH_MAX_PARALLEL/STRATEGY/MAX_IMAGES/ASYNC_THRESHOLD` 在 `batch_process_service` 模块常量，**不在 `app/config.py`**。
- **基础服务 volumes 是普通命名卷**（`mysql-data`/`mysql-logs`/`redis-data`/`mongo-data`/`minio-data`/`es-data`/`rabbitmq-data`/`xxl-job-logs`/监控栈若干，`docker-compose.yml` 末段由 compose 自动创建，无 `external: true`）⇒ 防重建丢数据靠"不删卷"：**禁止 `docker compose down -v`、`docker volume rm/prune`**；要用 `external: true` 必须先手工建卷并同步改运维流程，**当前刻意不改**（一键启动依赖 compose 自动建卷）。启动 `docker compose --env-file .env up -d`；MySQL 初始化＝compose 把 `config/sql/schema` 挂 `docker-entrypoint-initdb.d`（另有单文件挂载的 `schema-external/xxl_job.sql`）、`config/sql/data` 挂 `/docker-init-data` 由 `zz_load_data.sh` 按序加载（库名由 `MYSQL_DATABASE` 自动建）。
- Windows/macOS 必须用 `127.0.0.1` 而非 `localhost`（localhost 优先解析 IPv6 `::1`，Docker Desktop 只映射 IPv4，Python `socket.create_connection` 串行尝试 → 等 SYN 超时约 21s 才回退）。模拟器访问宿主机：**Android `10.0.2.2`，iOS/Mac `127.0.0.1`**（RN `DEV_HOST` 必须按 `Platform.OS` 分流）。

## 2. 数据库 / 种子 / 迁移

- **库表基线**：`config/sql/schema/*.sql`（`xxl_job.sql` 只允许放 **`config/sql/schema-external/`**（自带 `DROP DATABASE xxl_job`，混入 `schema/` 会被 `schema/*.sql` 通配误执行删库），唯一执行入口＝`docker-compose.yml:25` 单文件挂载；各消费方仍用 `sys_*.sql` glob 过滤，conftest 同款）；测试库 `dehaze_test`（pytest 每轮 DROP+CREATE 全量导入，故 SQL 必须最新可执行）；集成测试连开发库 `dehaze`（**schema 变更须手工 ALTER**，缺列会让 python 整套件 beforeAll 500 并大面积 skip ⇒ `1054 Unknown column` 先怀疑 dev 库落后 schema）。
- **迁移脚本位置**：DDL/数据迁移收敛在 `config/sql/migration/*.sql`（`config/sql/migration/` 不在 compose 初始化挂载里，须手工 `mysql <` 执行；幂等性见各文件头，如 `2026-09-11_uk_deleted_aware.sql` 为一次性不可重跑）；一次性迁移须**先落 DDL 再重启后端**（后端启动时查新列会启动失败）；`dehaze_test` 由 schema+data 全量重建、**不跑 migration**；dev 库执行迁移须待三端停机（文件头注明"须待 python 侧停读旧表后执行"）。Mongo 键名迁移 `dehaze-test/scripts/mongo_key_migrate.js`（幂等，含回滚段，**执行权留用户**）。
- 迁移 SQL 注意：中文注释内含半角分号时不能按 `;` 拆分执行。`sys_api_key` 等种子必须落 `dehaze` 运行库（非 `dehaze_test`）。
- **软删 uk 迁移（方案 A）执行纪律**：`config/sql/migration/2026-09-11_uk_deleted_aware.sql`，**三段式强制顺序（以脚本头为准）**：①数据修复 `SET deleted=id WHERE deleted=1`（历史软删行补行 id，避免重建唯一键时同键冲突）→ ②改列 `deleted` tinyint→bigint → ③重建唯一键（索引名不变）；一次性不可重跑（`DROP INDEX` 无 `IF EXISTS`）。
- **种子/初始化**：dev 环境初始化＝权限系种子 + 业务种子（`config/sql/data/*.sql`）+ embedding 模型注册 + 清 Redisson 污染 key（如 `rate:limit:register:{ip}` WRONGTYPE）+ 清 favorite 残留。种子纪律：**权限码必须存在于 `config/sql/data/sys_menu.sql` 种子**（幽灵权限码＝无人可写 ⇒ 非 ROOT 管理员一律 A0301/403），由 `dehaze-go/internal/router/permission_seed_contract_test.go` 机器护栏（路由/代码/mock 引用 ⊆ 种子、代码所用码必有角色可授、`sys_role_menu` 无孤儿授权行）。
- 登录类全挂先查 `sys_user.deleted` 与 `login:fail:*` 锁（deleted 被污染时 `UPDATE sys_user SET deleted=0`）。
- **迁移/种子改动必须自证幂等与双环境一致**：①全新环境（schema+data 重建）与遗留 dev 库执行结果**逐行业务列一致**；②连续执行两次**第二次 diff=0**；③口径切换必须写**幂等清理段**（先 `DELETE ... WHERE model_id LIKE '<旧前缀>%'` + 关联字典值 `UPDATE`，再插入，两边都用存在性守卫）——只靠人工在库里补救不算。
- **种子固定 id 会与测试造号相撞**：`config/sql/data/*.sql` 用固定主键 id（provider `180–182`、model `500–505` 等），而 pre/dev 存量库中同 id 常已被测试批量创建的行（`test_prov_*` / `test_model_*` / `favmodel_*`）占用（**成因**：SDK/契约测试批量创建带随机后缀的行，自增 id 恰好落进种子号段）⇒ ① 存量库重跑 `data/*.sql` 会 `ERROR 1062` 整条中止；② 若用「固定 id + `ON DUPLICATE KEY UPDATE`」会按**主键**命中那些无关行、把其业务列整列改脏（2026-10-01 在 pre 实测）。**存量环境补种子一律走 `config/sql/migration/*.sql`**，写法 `INSERT ... SELECT ... WHERE NOT EXISTS(业务键)`（provider 用 `provider_code`、model 用 `(model_id,provider_id)`，`provider_id` 按 `provider_code` 反查），**绝不写固定 id、绝不按主键 ODKU**；`data/*.sql` 只供全新库。另注意 `rebuild_mysql.py --import <table>.sql` 会先整表 DELETE，会清掉管理端自建行。
- **插入守卫 `NOT EXISTS` 只判"存在"、不更新已有行** ⇒ 改口径时必须另补修数据语句（如 `UPDATE ... SET status=CASE WHEN status IN (2,3,4) THEN 1 ELSE 0 END ... AND status NOT IN (0,1)`，`NOT IN (0,1)` 守卫是幂等关键）；把 SQL 重构成多层子查询时**务必核对投影表达式仍在最外层**。
- **MySQL 迁移三坑**：①`IF()` 会 **eager 求值全部参数**（子查询写在"未被选中"的分支里一样会执行 → 1146）⇒ 先用用户变量取子查询结果再判定；②动态 SQL（PREPARE）字符串里转义引号**跨行书写**会被错误解析出表名 → **单行 + 零引号**（值用会话变量注入）；③`CREATE PROCEDURE` 建时不校验表存在、过程体执行到缺失表才 1146，且本仓 `rebuild_mysql.py` 切分器**不认 `DELIMITER`** ⇒ 迁移优先 PREPARE 守卫式。
- **删字典行必须与删代码里的默认播种项同批**（py `DictService` 默认项不同步删 → 后端一重启就把删掉的字典行种回来）；清业务缓存的标准入口 `rebuild_mysql.py --skip-mysql`（须在主工作区跑），后端不健康时它会回退"裸删 Redis"、**连 session key 一起删（已登录会话失效）**。

## 3. 会员 / 权益 / 配额

- **配额口径 = fail-closed**：无 `sys_member` 行 → `get_limits` 返回 None → 拒绝（"配额不足"实为"无会员权益档案"）；等级限额 `0`＝管理员显式不限额。**会员档案必须登录兜底初始化**（注册是唯一自动入口，种子/后台建用户永不走）：python `auth_service.login` 加 `get_or_init_member`；**Java `MemberServiceImpl.ensureMemberProfile`（:604）先查活跃行再 `initMember`**（`upsertByUser` 冲突分支会降级 level_0 并清零 `total_consumption`，**绝不可对活跃会员调用**；无测试守卫 `[待补守卫]`）；Go `EnsureMemberProfile` FindByUserID→nil 才 init。
- **等级/配额快照刷新纪律**：`monthly_*_quota` 快照仅随等级联动路径刷新（等级定义与成长值阈值以 `docs/03-模块设计/基础模块/会员管理/需求规格.md` 为准）。
- **套餐权益 `benefit_overrides`**：权威＝java `BenefitOverrides`（字段全集见 docs）；**读写两侧都要核**（python 写侧字段少 + `extra="ignore"` ⇒ 读侧宽的 key 静默被抹）；key 统一 camelCase。字典化升级项：`favorite_capacity`（键 level_0..3）、`member_growth_rules`（`sign_in_value`/`sign_in_streak_bonus`/`rating_growth_value`/`rating_growth_daily_limit`）。
- **批量/历史配额**：批量上限与历史保留条数取 `sys_member_benefit.batch_limit`、`history_retention`；`totalQty` 不限量＝`ge=0`（**不是 `-1`**）。
- 反馈 priority：1 普通 / 2 紧急 / 3 高优；统计时间单位统一**小时**；`supplement` reply_type 固定 `"info"`。

## 4. 计费 / 定价 / 积分

- **兑换率（1 元 = 100 积分）不是配置项**（无对应字典/开关键）：它是定价/估值口径，只体现为两处**数据**——①积分卡 `sys_package.credit_amount`（可得积分）+ `sale_price`/`original_price`（单位分），下单快照进 `sys_order.credit_amount`，支付即按快照到账（**无 元→积分 换算代码**）；②AI 用量售价 `sys_ai_model_price_detail.unit_price`（积分/计量单位）。调整该锚＝改这两处数据（价格版本/套餐档位），不涉及开关或字典。
- **定价公式（勿漏/勿重）**：`credits = (input−cached)×input档/1M + cached×cached档/1M + output×output档/1M`（Decimal 四舍五入，单次 ≥1 积分；缓存命中段单计、勿重复进 input 档，由 `dehaze-python/tests/service/test_ai_model_price.py:124` 断言锁定）。定价模型（版本主表 + 档位明细、用户侧与成本侧对称、三维匹配）见 docs。
- **毛利双口径修正**：收入线/成本线分离——整体毛利（官方）= 全部订单实收 − ΣAI 调用成本；AI 参考毛利 = 积分卡实收 + 会员卡实收×`ai.billing.membership-ai-ratio` − Σ成本。
- **`ai_consume` 激励**：每次完成一次 AI 对话 +1，每日上限 10 次、无月上限；计次口径＝一次对话完成（发布 `ai.chat.completed`，多步推理多次 LLM 调用仅计一次）；不参与退款扣减。
- **本地 `qwen3-0.6b` 费率配置为 0（刻意免费）**：chat 记录 tokens 正常入账但 credits/dailyUsed 不变，测试断言须按此设计。
- **`sys_ai_model` 关键字段语义**：`extra_request_params`（JSON 厂商私有参数，模型级管理员配置，合并时**核心键保护**：model/messages/stream/stream_options/temperature/max_tokens/tools 不可覆盖）；`model_id varchar(64)`（无外键，可直插造数）；`LOCAL_LLM_CTX_SIZE=16384`（模型真实 40960，CPU 推理保守取值），截断预算 ≈16384−2048−200 且**从模型配置动态计算**。`sys_ai_provider.user_identity_forward`（JSON `{"enabled":true,"field":"user_id","prefix":"u_","max_len":512}`，支持嵌套路径如 `metadata.user_id`，生成 `prefix + sha256(userId)` 截断；NULL＝不启用，守卫 `dehaze-python/tests/infrastructure/llm/call/test_user_identity_forward.py`）。
- **知识库常量**：`KB_MAX_CHUNKS=10000`（架构防单库爆炸）、`KB_MAX_TEXT_CHARS=1_000_000`（create_text 超长/空内容拒绝）；`_clean_text` 清洗控制字符/零宽/BOM/**NBSP `\xa0`** + 空白压缩。`/kb/{id}/index-stats` 索引阈值默认 1GB。
- **计费落账口径（统一模型阶段 2，钱相关勿自行改）**：`quantity` **按价格行 `billing_unit` 的计量单位记**（asr=秒、tts=字符数÷10000 的万字符小数、image=张），`quantity_unit` 直接取该 `billing_unit` ⇒ `credits = round(quantity × unit_price)` 恒成立、对账可复算；**不做"数值记字符、unit 写字面万字符"的混合口径**。精度：`credits` 用 `Decimal` 精确乘后 `ROUND_HALF_UP` 取整（禁 float），`quantity` 入库前量化 4 位小数（列 `decimal(18,4)`）；预校验 `estimate_*` 用 `ceil` 保守高估（与旧语音路径 `math.ceil` 的差异属预期，单次至少 1 积分见本节上文/§7）。
- **未配置价格＝不扣费 + 不阻断 + 仍落账（`credits=0`）**；可观测三件套：warning 日志（带 `model_id/provider_id/billing_unit`）+ 指标 `dehaze_voice_unpriced_total{model_type}` + 对账特征 `bill_type IN ('asr','tts') AND quantity>0 AND credits=0`。**禁用 `error_code='no_price'` 之类配置标记**——`sys_ai_billing.error_code` 的语义是"调用失败错误码（成功为 NULL）"，写配置标记会把成功计费行标成失败、制造静默错账；要更显式须新增专用列并同步三端实体。**（`_charge` 显式传 `error_code=None`，不写 `NO_PRICE_ERROR_CODE`/`'no_price'`；守卫：`dehaze-python/tests/service/test_voice_billing_service.py:175` 断言旧常量不存在、`tests/service/prediction/test_image_link.py:180` 断言成功行 NULL。指标在 `app/infrastructure/metrics/billing_metrics.py`，由 `unit_billing._charge` 统一发，名为 `voice_` 但 asr/tts/image 都计数，label 取计费类型。）**
- **计价统一入口** `AiModelPriceService.calculate_unit_credits(db, model_id, provider_id, at_time, quantity)` → `{credits, configured, billing_unit}`（chat/语音/图像共用）；`voice_billing_service` 只取数落账、不自己读价格表；billing 记录的 `model` 字段记**统一 model_id**（`sensevoice`/`paraformer`/`huayan`），不记 engine/provider code。
- **`sys_ai_model_price_detail.token_type` 不扩 `unit`**：`usage_kind='unit'` 时 `token_type` 复用 `'input'`（该列参与唯一键 `uk_price_token_time_range`，扩值域会改唯一性语义；引入 `unit` 档须作契约变更单独裁决并同步 py schema / DB 注释 / SDK / Java / Go）。
- **`sys_ai_provider_key` 唯一键＝`uk_provider_key(provider_id, key_hash)`**（`config/sql/schema/sys_ai_provider_key.sql:41`；local/local-voice/local-modal 共用一把 `INTERNAL_SERVICE_KEY` 依赖此口径，守卫 `dehaze-python/tests/infrastructure/llm/test_model_seeder.py:158`）⇒ **三端按 hash 定位密钥必须带 provider 维度**（py `ai_provider_key_repository.get_by_provider_and_hash`、go `GetByProviderAndHash`、java `.eq(providerId).eq(keyHash)`）。注意 `sys_api_key.uk_key_hash` 是**另一张表**，勿误改。

## 5. 订单 / 支付 / 退款 / 续费

- **支付履约 `on_order_paid` 口径（勿混）**：成长值 = 实付 1:1（分→成长值）；积分卡支付即完成（status 3，不动等级）；会员卡等级只升不降、`level_source=purchase`；余额 CAS 版本乐观锁 + 流水。
- **退款策略（用户强调）**：退款是兜底保障非用户常规权益，默认不可退；仅售后/不可抗/商家原因快速审核 + "其他原因"人工裁量（制度从严、执行从宽）；入口命名"售后申请"；会员卡按天折算、积分卡按用量折算（售后/不可抗）或全额（商家原因）；充值后未消费余额可退回（原路、不含冻结）。`used_quota` 勿用；`sys_refund_record` 三端字段名统一为 `reason_type/used_days/used_credits`（camel `reasonType/usedDays/usedCredits`，`reason` 仅补充说明；三端+SDK `RefundRecordVO` 一致，守卫 `dehaze-sdk-js/test/modules/order/order-edge.test.ts:364`）。
- **自动续费＝"半自动语义"**：微信/支付宝无真实代扣；到期创建待支付续费订单（95 折）→ 用户主动支付 → 回调生效；未支付超时取消 → `fail_count+1` → 2h 重试 → 3 次关闭。
- **促销范围唯一权威＝`sys_promotion_package` 关联表**（`sys_promotion.applicable_scope` 不存在，`sys_coupon.applicable_scope` JSON 保留）。

## 6. 缓存键与 TTL（含典型值）

- **TTL 数值（键名/跨端声明一致性由 `dehaze-python/tests/test_cache_key_contract.py` 守卫，TTL 不在其覆盖内 ⇒ 改键须同步核 TTL）**：**5s** 反重复提交；**60s** 语音引擎；**300s** 供应商健康阈值；**600s** KB 列表；**1800s** 等级 / 知识库详情 / 已发布 Agent / 流式 `pending`；**3600s** AI 模型·供应商列表、菜单路由·选项、`role:options`、余额；**24h** 评测任务；**90d** 账单月缓存；其余（`role:perms:*`、`ai:quota:*`、在售列表等）无 TTL、随写入失效（**改费率须清 `ai:rate:{model_id}`**）。
- **`dept:tree` 不是死键**：go 端写（`dehaze-go/internal/service/dept/dept_service.go:22`），python 不写但须按 `dept:tree*` 失效（`DeptCacheKeys.all_patterns()`），守卫 `dehaze-python/tests/infrastructure/test_cache.py:109`。
- `redis_operation_with_fallback` 首参必须**可无参调用**（入口校验见 `app/infrastructure/cache/redis_fallback.py:169/183/228`：非可调用 / 带必填参数 / 返回非 awaitable 一律 `TypeError`，守卫 `dehaze-python/tests/infrastructure/test_redis_fallback.py`）。**校验不得用 `inspect.iscoroutinefunction` 硬卡**：`cache.py` 多处传 `lambda: self.redis.get(key)`（零参可调用返回 awaitable，合法且大量使用），只能校验"零参可绑定 + 调用后 `isawaitable`"。
