# 明细：数据与配置定案
> `dehaze-project-knowledge` skill 的参考文件（按需 read_file）。收录：环境与配置原则、数据库/种子/迁移、会员权益配额、计费定价、订单支付退款、缓存键与 TTL、业务常量与账号。

## 1. 环境与配置原则
- **根 `.env` 按基础设施分区**：`MYSQL_*` / `REDIS_*` / `MONGODB_*` / `ES_*` / `MINIO_*` / `RABBITMQ_*` / `XXLJOB_*` / `NGINX_STATIC_*` / `GRAFANA_ADMIN_PASSWORD` / `ALERTMANAGER_PASSWORD` + 应用级 `JWT_SECRET_KEY` / `DEFAULT_PASSWORD` / `ADMIN_PASSWORD`；**`DEHAZE_HOST`/`DEHAZE_PASSWORD` 已彻底删除（零回退）**。Python 字段改名 `DB_*→MYSQL_*`、`MINIO_BUCKET_NAME→MINIO_BUCKET`、`RABBITMQ_USER→RABBITMQ_USERNAME`，删 `_apply_derived_credentials`。
- **加载顺序：环境变量优先于 `.env`**（Java spring-dotenv / Go godotenv+viper / Python pydantic-settings）；`dotenv` 只加载一次（vitest globalSetup 与 setupFiles 同进程，`vitest.setup.ts` 不重复加载）；三端共享 JWT 密钥。
- **配置项判定标准**：仅"管理员/运营有明确修改动机"的参数才字典化（`sys_dict`），纯技术参数（缓存 TTL/分页/批次/轮询/锁定/心跳/cron/线程池）一律代码常量；个性化由实体级配置覆盖，**不设第三层全局字典默认**。典型判定：`ai_reasoning_defaults` 字典**整体删除** → `REASONING_DEFAULTS` 常量；`ai_guardrail_defaults` 保留（安全合规有运维场景），缓存键 `ai:config:guardrail_defaults`。字典增删改即时失效缓存；缺键 warn + 回退默认值（**不保留旧常量转发**）。新增 `sys_dict` 种子须同步 `config/sql/data/*.sql` + python 种子 + `SYSTEM_PRESET_DICT_TYPE_CODES` + seed contract 测试。
- **推理默认值唯一声明处**＝`agent_config_resolver.REASONING_DEFAULTS`（内部键 snake、对外 camel）：`maxStepsReact=20/maxStepsPlan=30/maxStepsReflexion=15/maxIterationsReflexion=3/reflexionThreshold=0.8/maxParallel=5/toolTimeout=60/tokenBudget=500000/retryMax=2`；经 `GET /api/v1/ai/agents/config-defaults`（登录可读，须注册在 `/{agent_id}` 之前）只读透出。批次常量 `BATCH_MAX_PARALLEL/STRATEGY/MAX_IMAGES/ASYNC_THRESHOLD`（5/auto/20/3）在 `batch_process_service` 模块常量，**不在 `app/config.py`**。
- 基础服务 volumes 用 `external: true` 防重建丢数据；`docker compose --env-file .env up -d`；MySQL 初始化由 compose 挂 `schema.sql→01_schema.sql`、`data.sql→02_data.sql` 按序执行（库名由 `MYSQL_DATABASE` 自动建，schema 内已移除 `CREATE DATABASE`/`USE`）。
- Windows/macOS 必须用 `127.0.0.1` 而非 `localhost`（localhost 优先解析 IPv6 `::1`，Docker Desktop 只映射 IPv4，Python `socket.create_connection` 串行尝试 → 等 SYN 超时约 21s 才回退）。模拟器访问宿主机：**Android `10.0.2.2`，iOS/Mac `127.0.0.1`**（RN `DEV_HOST` 必须按 `Platform.OS` 分流）。

## 2. 数据库 / 种子 / 迁移
- **库表基线**：`config/sql/schema/*.sql`（注意 `xxl_job.sql` 是**独立库 schema 混放同目录**且自带删库重建语义 ⇒ 导入必须用 `sys_*.sql` glob 过滤，conftest 同款）；测试库 `dehaze_test`（pytest 每轮 DROP+CREATE 全量导入，故 SQL 必须最新可执行）；集成测试连开发库 `dehaze`（**schema 变更须手工 ALTER**，缺列会让 python 整套件 beforeAll 500 并大面积 skip ⇒ `1054 Unknown column` 先怀疑 dev 库落后 schema）。
- **开发库迁移脚本**：`dehaze-test/scripts/migrate_*.py`（幂等，SHOW TABLES/COLUMNS 判定）；一次性迁移须**先落 DDL 再重启后端**（后端启动时查新列会启动失败）。Mongo 键名迁移 `dehaze-test/scripts/mongo_key_migrate.js`（幂等，含回滚段，**执行权留用户**）。
- 迁移 SQL 注意：中文注释内含半角分号时不能按 `;` 拆分执行。`sys_api_key` 等种子必须落 `dehaze` 运行库（非 `dehaze_test`）。
- **软删 uk 迁移**（方案 A）：`config/sql/migration/2026-09-11_uk_deleted_aware.sql`，范围 61 表 `deleted` tinyint→bigint、37 表 41 唯一键追加 `deleted`（索引名不变）；**三段式强制顺序**：①改列 bigint → ②数据修复 `SET deleted=id WHERE deleted=1`（必须先改列，否则 tinyint 溢出 id>127 失败）→ ③重建索引；一次性不可重跑。
- **种子/初始化**：dev 环境初始化＝权限系种子 + 业务种子 28 脚本 + embedding 模型注册 + 清 Redisson 污染 key（如 `rate:limit:register:{ip}` WRONGTYPE）+ 清 favorite 残留；**本地模型播种**：内置 `qwen3-0.6b`(chat) + `qwen3-embedding-0.6b`(embedding)，语音 local provider 由 `voice_engine_seeder` 运行时幂等播种。种子缺陷教训：`sys_role_menu.sql` 从未给 ADMIN 分配反馈菜单 88-96 ⇒ go/python admin 一律 A0301（java 因 isRoot bypass 未暴露）；**权限码必须存在于种子 menu**（Go 曾用 `sys:file:edit/delete` 幽灵权限码＝无人可写）。
- 登录类全挂先查 `sys_user.deleted` 与 `login:fail:*` 锁（admin 曾被旧 go/java 二进制真删污染 deleted=1/2 ⇒ `UPDATE sys_user SET deleted=0`）。

## 3. 会员 / 权益 / 配额
- **等级**：`level_0` 普通 / `level_1` VIP1 / `level_2` VIP2 / `level_3` SVIP；成长值 5000 升 level_2、20000 升 level_3；`level_0` ai_credits=10000/100000（与需求 §2.8.2 一致）；`monthly_*_quota` 快照仅随等级联动路径刷新。
- **配额口径 = fail-closed**：无 `sys_member` 行 → `get_limits` 返回 None → 拒绝（"配额不足"实为"无会员权益档案"）；等级限额 `0`＝管理员显式不限额。**会员档案必须登录兜底初始化**（注册是唯一自动入口，种子/后台建用户永不走）：python `auth_service.login` 加 `get_or_init_member`；**Java `ensureMemberProfile` 先查活跃行再 `initMember`**（`initMember` 的 `upsertByUser` 冲突分支会降级 level_0 并清零 `total_consumption`，**绝不可对活跃会员调用**）；Go `EnsureMemberProfile` FindByUserID→nil 才 init。
- **表结构**：多任务配额用**宽表**（`sys_member` 16 配额列 / `sys_member_benefit` 8 quota 列 / `sys_member_quota` 8 类归档；`sys_member.quota_reset_month` 防重置竞态）；`sys_member_benefit.max_devices int NOT NULL DEFAULT 1`（种子 1/3/5/10）；人民币余额独立账户 `sys_balance`/`sys_balance_log`（乐观锁 `version`，与 AI 积分账户职责分离）；`sys_package` +`package_type`/`credit_amount`。
- **套餐权益 `benefit_overrides`**：权威＝java `BenefitOverrides` 17 字段；读写两侧都要核（python 写侧 9 字段 + `extra="ignore"` ⇒ 读侧宽的 key 静默被抹）；key 统一 camelCase。字典化升级项：`favorite_capacity`（default/vip1/vip2/svip＝200/500/1000/3000，键 level_0..3）、`member_growth_rules`（sign_in_value=3 / sign_in_streak_bonus=20 / rating_growth_value=5 / rating_growth_daily_limit=5）。
- **批量/历史配额**：批量上限与历史保留条数取 `sys_member_benefit.batch_limit`、`history_retention`（等级口径 100/500/2000/10000）；`totalQty` 不限量＝`ge=0`（原 `-1` 作废）。
- 反馈 priority：1 普通 / 2 紧急 / 3 高优；统计时间单位统一**小时**；`supplement` reply_type 固定 `"info"`。

## 4. 计费 / 定价 / 积分
- **兑换率：1 元 = 100 积分**（1 积分 = 0.01 元），落地 `ai.billing.credit-value=0.01`（积分价值锚，非落表）。
- **定价模型（最终定案）= 版本主表 + 档位明细，用户侧与成本侧完全对称**：`sys_ai_model_price` / `sys_ai_model_cost`（`model_id` + `provider_id` + `price_version` + 有效期）+ `sys_ai_model_price_detail` / `sys_ai_model_cost_detail`（唯一键 `price_id + token_type(input/cached/output) + time_slot(peak/idle) + min_tokens + max_tokens`，`unit_price`）；三维匹配（时段 + 输入总长度分段 + token 类型）。计价公式 `credits = (input−cached)×input档/1M + cached×cached档/1M + output×output档/1M`（Decimal 四舍五入，单次 ≥1 积分；已修正缓存命中双重计费）。`sys_ai_model` 旧的 `input_rate/output_rate/cached_rate/peak_multiplier` 四字段**已退役**。
- **高峰时段全局配置** `ai.billing.peak-hours`（默认北京时间 周一至周五 9:00-12:00、14:00-18:00，不写死）；**会员卡收入归属 AI 分摊** `ai.billing.membership-ai-ratio`（默认 0.3，不落表）。毛利双口径：整体毛利（官方）= 全部订单实收 − ΣAI 调用成本；AI 参考毛利（辅助）= 积分卡实收 + 会员卡实收×比例 − Σ成本（**收入线/成本线分离**，原"计费比例是售价"口径作废）。
- **`ai_consume` 激励**：每次完成一次 AI 对话 +1，每日上限 10 次、无月上限；计次口径＝一次对话完成（发布 `ai.chat.completed`，多步推理多次 LLM 调用仅计一次）；不参与退款扣减。
- **本地 `qwen3-0.6b` 费率配置为 0（刻意免费）**：chat 记录 tokens 正常入账但 credits/dailyUsed 不变，测试断言须按此设计。
- `sys_ai_model` 字段：`model_type` / `dimension` / `extra_request_params`（JSON，厂商私有参数，**模型级管理员配置**，合并时**核心键保护**：model/messages/stream/stream_options/temperature/max_tokens/tools 不可覆盖）/ `model_id varchar(64)`（无外键，可直插造数）/ `max_context_tokens`（qwen3-0.6b＝16384）；`LOCAL_LLM_CTX_SIZE=16384`（模型真实 40960，CPU 推理保守取值），截断预算 ≈16384−2048−200 且**从模型配置动态计算**。`sys_ai_provider.user_identity_forward`（JSON `{"enabled":true,"field":"user_id","prefix":"u_","max_len":512}`，支持嵌套路径如 `metadata.user_id`，生成 `prefix + sha256(userId)` 截断；NULL＝不启用；原 `pass_user_id` 布尔/`user_id_forward_enabled` 中间态作废）。
- **知识库常量**：`KB_MAX_CHUNKS=10000`（架构防单库爆炸）、`KB_MAX_TEXT_CHARS=1_000_000`（create_text 超长/空内容拒绝）；`_clean_text` 清洗控制字符/零宽/BOM/**NBSP `\xa0`** + 空白压缩。`/kb/{id}/index-stats` 索引阈值默认 1GB。

## 5. 订单 / 支付 / 退款 / 续费
- **支付履约 `on_order_paid` 口径**：成长值 = 实付 1:1（分→成长值）；积分卡支付即完成（status 3，不动等级）；会员卡等级只升不降、`level_source=purchase`；余额 CAS 版本乐观锁 + 流水。
- **退款策略（用户强调）**：退款是兜底保障非用户常规权益，默认不可退；仅售后/不可抗/商家原因快速审核 + "其他原因"人工裁量（制度从严、执行从宽）；入口命名"售后申请"；会员卡按天折算、积分卡按用量折算（售后/不可抗）或全额（商家原因）；充值后未消费余额可退回（原路、不含冻结）。退款表字段 `reason_type(after_sale/force_majeure/merchant/other)`/`used_days`/`used_credits`（`used_quota` 已废）。**`sys_refund_record` 三端字段名仍不一致**（SDK/文档 `reason_type/used_days/used_credits` vs Java/Go `reason/used_quota`）→ 待订单管理改造时统一。
- **自动续费＝"半自动语义"**：微信/支付宝无真实代扣；到期创建待支付续费订单（95 折）→ 用户主动支付 → 回调生效；未支付超时取消 → `fail_count+1` → 2h 重试 → 3 次关闭。
- **促销范围唯一权威＝`sys_promotion_package` 关联表**（`sys_promotion.applicable_scope` 已删、`sys_coupon.applicable_scope` JSON 保留）。

## 6. 缓存键与 TTL（含典型值）
- `dict:data:{typeCode}`（三端）、`menu:routes`/`menu:options`（1h）、`role:options`（1h）、`role:perms:*`、`user:level:{id}`(1800)、`ai:model:list`(3600，snake JSON)、`ai:provider:list`(3600)、`ai:provider:{id}:circuit_open|circuit_recovery|half_open_probe|fail_streak|window|latency|health|health_enabled`、`ai:provider:health:thresholds`(300)、`ai:balance:{uid}`(整数,1h)、`ai:arrears:{uid}`、`ai:quota:daily|monthly:{uid}:{日期}`、`ai:bill:{uid}:{yyyy-MM}`(90d)、`kb:list:{uid}`|`kb:list:admin`(600)、`kb:detail:{id}`(1800)、`ai:agent:{id}:published`(1800)、`package:onsale:{package_type or "all"}`、`ai:price:{modelId}:{providerId}`、`ai:rate:{model_id}`（**改费率须清**）、`pending:{stream_session_id}`(1800)、`ai:eval:task:{id}`(24h)、`voice:engine:{asr|tts}`(60s)、`ai:config:guardrail_defaults`。
- 未落地/已删登记：`file:meta`、`dict:type:{code}`、`dept:tree`（已删行）、`algo:recommend:{userId}`（迁移残留，代码无此 key）。
- `redis_operation_with_fallback` 首参**必须是无参 async 函数**（传错签名引发缓存失效路径异常）。

## 7. 业务常量 / 指标 / 账号
- **账号种子细节**：admin 密码 bcrypt 固化在 `sys_user.sql`（dev 实测 `Dehaze2026`，SDK 测试默认取 `test/config/constant.ts`）；`sys_user.sql` 加 `credits_balance`（admin=100000，其余 0，**root 不给**）；`sys_member.sql` 加 admin level_0 行。管理员判定 `sys_user.is_admin`；会话默认 `MESSAGES_PAGE_SIZE=50`。
- **数值口径**：费率档位过度小会被 int 截断致 credits=0；积分计算须 Decimal 四舍五入取整且单次至少 1 积分。会员成长值流水 `reason` python **原样存储**（java 曾加"管理员调整成长值："前缀 ⇒ 脏语料原样保留用例失败）。
- **测试资源**：`scripts/gen_test_resources.py`（根 scripts，渐变+噪声纹理，非纯色以便 NIQE 等无参考指标可算）；SDK 集成资源由 `test/config/ensure-test-resources.ts` 在 `vitest.globalSetup` 首行保障，清单必须与 `IMAGES/PNG_IMAGES` 严格对齐（test/hazy 只有 41/42/43）。
- 环境路径：macOS `ANDROID_HOME=~/Library/Android/sdk`（PATH 需含 `cmdline-tools/latest/bin`、`platform-tools`、`emulator`、`build-tools/<v>`）；Android `local.properties` 需 `sdk.dir`（被根 `.gitignore` 的 `*.properties` 忽略），`app/build.gradle` 默认 `BASE_URL=http://10.0.2.2:8989`；Python 依赖用 `uv`（`.venv` 在项目目录），测试依赖在 `[project.optional-dependencies].test` ⇒ 日常 `uv sync --extra test`。
