# 明细：跨端架构禁区与实测口径

> **边界**：本文件只收程序性知识（判据 / 坑与禁区 / 实测口径 / 操作纪律）；陈述性知识以 `dehaze-doc/docs/` 为唯一权威源，不重复转述；冲突时以磁盘代码 + 实测为准。

## 1. 工程结构禁区

- 基础设施配置**真源＝根 `config/`**，三端共享（见 `02-系统架构/03-数据库设计.md`）；Java 测试 SQL 由 `maven-resources-plugin` 构建期复制 ⇒ **禁止手维护 `src/test/resources/db/` 副本**。
- 开发模式启动：Go **必须在 `dehaze-go` 目录**执行 `go run ./cmd/main.go`（viper 按 CWD 找 config）；Python `uvicorn --reload --host 0.0.0.0`；Java **dev** 用 `mvn spring-boot:run -DskipTests`、**prod（含 pre）** 用 `mvn package` + `java -jar`（`run.py` 按 `SPRING_PROFILES_ACTIVE` 自动分流）。Java 两者不可混用同一形态：`spring-boot-devtools` 只在胖 jar 打包时被排除，`spring-boot:run` 直跑 classpath 会加载它，共享机上任何 maven 构建改写 `target/classes` 都会触发热重启、丢 `.env` 而启动失败。
- **项目根/仓根定位＝标记文件向上查找**（Go `go.mod`、Python `pyproject.toml`），**不用 `.env`**（精简部署可能缺失）；禁止数 `__file__` 的目录层数（见 `02-系统架构/06-部署架构.md`）。
- `run.py` 控制台日志是**追加模式**（`scripts/run.py:215,275` `open(..., "a")`），勿改回 `"w"`（无守卫 [待补守卫]）。
- **改接口前以后端路由权威为准**：dehaze-go `internal/router/*.go`（统一前缀 `/api/v1`、资源路径复数、认证五件套 `login/captcha/logout/me/refresh`）——不要凭文档里的接口清单判断现存路由。

## 2. 跨端架构禁区（AI 域 / 转发 / 图像 / 语音）

- **AI 域分 A/B 两类（勿再按"只在 python"理解）**：A 类＝同套 `sys_ai_*` 契约由 **java/go/python 各自原生实现**（会话/消息 CRUD、模型/供应商/密钥、计费/账单/余额、偏好、**可观测查询**、评测中心等）⇒ **改动必须三端同步**；B 类＝**只有 python 实现**（对话推理 SSE、agent/skill/模型/供应商试运行与发布门禁、知识库索引与文档处理/检索、MCP 探测、评测派发、语音 ASR/TTS、兼容协议入口）⇒ 改动面＝python + 转发清单。**同一模块可两类并存**（知识库：库列表 A / 建删与检索 B；评测：中心 A / 派发 B），**B 类清单以各端转发白名单为唯一口径**（java `service/client/AiProxyRoutes.java`、go `internal/router/ai_proxy.go` + `voice_proxy.go`，共用 `pkg/aiclient`），且两端白名单**并非逐条相同**（如供应商熔断解除：java 转发、go 原生）。未登记路径一律 404、禁止按客户端路径盲转发（防 SSRF）。
- **AI 对话前端只在 front-vue**（消费端清单见 `核心模块/AI对话/API接口.md`）⇒ SSE 契约改动影响面仅 front-vue + SDK。
- **转发四形态各有坑**：JSON / multipart（java 须以 `@Component("multipartResolver")` 覆盖 Boot 自动配置跳过 Spring multipart 解析，由 `AiProxyMultipartResolverTest` 守卫）/ 二进制响应（**禁当 JSON 解包**）/ WebSocket（go `pkg/aiclient.ForwardWebSocket`）。
- **熔断只计"服务不可用"**（连接层/超时/5xx）：业务 4xx（A0401/A0410 等）须走 `protection.MarkBusiness`（`pkg/algorithm/client.go` `classifyBusinessError`）——已由 `client_business_test.go`、`breaker_business_test.go` 守卫（400×N 不熔断 / 502×N 必熔断）。
- **图像链路（统一模型阶段 3）**：口径 `/api/v1/images/*` 且 `model` 传 **slug**；go 路由**文件名仍叫 `prediction.go`（已挂 `/images`）** ⇒ **勿凭文件名判断新旧**；字面量 `"algorithm_recommend"`（会话场景/artifact 类型）保留不改名。
- **image_edit 的 `model_id`（slug）＝自描述标识**：规则已固定在 `dehaze-service/dehaze-modal/app/artifacts.json` + `catalog.py`（基名=import_path 模块名小写、同基名多 weights 追加相对路径后缀，如 `aecrnet`/`c2pnet-its`），由 `dehaze-modal/tests/test_images_api.py:27`、`scripts/validate_algorithms.py` 守卫；**否决 `algo-<sys_algorithm.id>`**——modal「服务侧不查库」，model_id 必须由权重路径自推导。
- **`model_type` 扩值域的运行时症状**：库里出现新 `model_type` 行后，python 响应模型 `AiModelType` Literal 未扩会 **500**、go `ValidateModelType` 会 **400**、java 是客户端白名单；`task_tags` 由中文 `type` 映射（去雾→dehaze、去雨→derain、去噪→denoise、去模糊→deblur），不预留未出现的值 ⇒ **扩值域后必须跑跨端守卫 `dehaze-go/internal/service/ai/model_type_cross_end_contract_test.go`（三端值域集合相等 + 变异自证）**。
- **语音 WS 转发的两处刻意设计**：①java `@EnableWebSocketMessageBroker` 给 `/ws` 注册了 SockJS 通配 `/ws/**`，与裸 handler `/ws/asr` 同 order 命中不确定 ⇒ 必须 `setOrder(0)` 压过 SockJS；②go 的 `wsDialer` **刻意不设** `HandshakeTimeout`（python `/ws/asr` 要等 ASR 引擎就绪才 accept，首次 20~40s）——看似漏配实为设计，勿当缺陷改掉。

## 3. AI 推理机制的实测禁区（LangGraph / SSE / plan）

- **LangGraph**：`Command(goto="end")` 被忽略 ⇒ 用 `jump_to="end"`（`abefore_agent` 标 `__can_jump_to__=["end"]`）；`ainvoke` 的 ContextVar 副本上下文**不可见** ⇒ 图路径必须读最终 AIMessage 的 `response_metadata`；langgraph 4.2.0 `CheckpointTuple` 无 `pending_sends`、`aput_writes` 按 (task_id, idx) upsert；shell 沙箱白名单不含解释器、弱隔离；**v2 事件 ns**：主图 `ns=()`、子图 ns 非空（段格式 `父图节点名:task_id`，可嵌套）⇒ "ns 非空即子 Agent"，`agent_code` = 末段 `split(":")[0]`（**以实测为准，文档描述不符**）。
- **plan 禁区**：`PlanEvent` 全域不存在（**再现即回退**；守卫 `dehaze-python/tests/test_plan_wire_contract.py`：AST 扫描禁用标识 + `to_wire_plan` 唯一出口白名单）；对外 camel / 内部 snake，唯一归一出口 `plan_execute.to_wire_plan()`，上行入口 `apply_plan_edit` 读 camel 写内部 snake。
- **SSE 禁区**：空闲超时**只断流不停推理**（心跳直连 yield、不入队列，否则超时永不触发）；error 事件唯一出口 `send_error()`；thinking 块固定 `content_block index=1`、converter `finish()` 必发 `stop(1)`、**direct 路径必须把 chunk 无条件交 converter**（`if chunk.content:` 会丢弃 content="" 的思考块）——后三项已由 `tests/infrastructure/sse/test_sse_thinking.py`、`test_sse_event_converter.py`、`test_sse_emitter_manager.py` 守卫。
- **本地推理数值坑**：llama.cpp 流式**无 usage**（工具固有）⇒ prompt 按 tokenize 计数、completion 按 chunk 数累计，并在 `[DONE]` 前发 usage-only chunk（payload 须带 `stream_options.include_usage`）；`<think>` 跨 chunk 切分（`_ThinkSplitter` 必须放跨 chunk 消费端）与 usage 键名规范化（`prompt/completion_tokens` ↔ `input/output_tokens`）两坑分别由 `dehaze-python/tests/infrastructure/llm/client/test_think_splitter.py`、`dehaze-service/dehaze-llm/tests/test_streaming.py:53`（usage-only 尾块 + 计数）、`dehaze-python/tests/service/ai/middleware/test_extract_usage.py`（内部 `input/output_tokens`）守卫。

## 4. 其它易错禁区

- **java 文件存储＝多后端共存**（刻意设计）：`StorageServiceFactory.get(storage)` 供历史文件按记录取后端、`getDefault()`＝`file.type` 为新上传默认 ⇒ **勿按 `file.type` 条件化 bean**（会让非默认后端消失）；单实现注入点须注入 Factory 用 `getDefault()`；URL 白名单要遍历 `List<FileService>` 收集全后端 baseUrl——由 `FileStorageBackendActivationTest` 守卫。
- **front-vue AI 对话组件层红线**（已由 eslint `no-restricted-imports` 锁定，见 `eslint.config.js`）：`src/components/ai-chat/` 零 store、零 `dehaze-sdk-js`、零 vue-router、零 ElMessage；`adapters/**` 是唯一允许直连 SDK 的块（wire→VM 翻译处）；状态在 `store/modules/chat/`，宿主绑定 `composables/useChatVmBinding.ts`。
- **front-vue 枚举规范**：≥3 处消费须单源常量数组 `{label,value,tag}`（`src/enums/TagType.ts`），约束见 `04-项目实现/前端/01-Vue架构文档.md`。
- **SCAN `session:*` 必须排除 `session:user:*`**（`SessionUserPrefix`；前者是会话值、后者是设备数 ZSet 索引，混扫会误删索引）——三端均有守卫：python `tests/service/test_auth_session_management.py`、go `internal/service/auth/auth_service_miniredis_test.go`、java `AuthServiceImplSessionLimitTest`。
