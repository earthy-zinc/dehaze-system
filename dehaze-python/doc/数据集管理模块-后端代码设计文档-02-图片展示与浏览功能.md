# 代码设计文档

## 文档说明
- **对应需求**：`demo/docs/07-数据集管理模块需求-02-图片展示与浏览功能.md`
- **适用版本**：dehaze-python Flask 后端 V2.0。
- **设计原则**：
  1. **单接口多模式**：统一的查询接口通过 `mode` + `projection` 参数返回列表/瀑布流/网格所需字段，避免重复 SQL。
  2. **分页与游标并存**：传统页码用于列表模式，游标（`cursor`）用于无限滚动，均由同一 Service 输出。
  3. **批量操作安全**：对批量删除/下载设置限流、参数校验、后台任务支撑，防止拖垮进程。

## 1. 修改目标与范围定位
- 提供满足多展示模式、筛选、排序、批量操作的图片查询与管理接口。
- 主要涉及：`app/route/dataset.py`（新增图片查询/偏好接口）、`app/route/item_file.py`（下载/批量操作）、`app/service/dataset_service.py`/`DatasetItemService`（分页/筛选实现）、`app/service/item_file_service.py`（批量下载、URL 构建）、`app/models.py`（字段同步）、`config.py`（分页/排序限制）。

## 2. 现有实现概览
- `GET /api/v1/dataset/<id>/images` 仅支持简单分页、无筛选/排序；返回 `imgUrl` 数组，无法满足列表列（文件名/大小/场景/雾霾/状态）。
- `DatasetService.get_image_items`：
  - 只按 dataset 叶子节点查询 `SysDatasetItem`，未 join `SysItemFile/SysFile`。
  - 无统计字段（resolution、processStatus、usageCount），也无瀑布流 cursor。
- 路由缺少批量删除/下载接口。
- 配置层未限制分页大小、排序字段。

## 3. 代码设计与修改方案

### 3.1 路由与 API
1. **查询接口**：
   - `GET /api/v1/dataset/<datasetId>/images`：query 参数 `mode`, `pageNum`, `pageSize`, `cursor`, `sceneType`, `hazeLevel`, `processStatus`, `keywords`, `minWidth`, `maxWidth`, `minSize`, `maxSize`, `sortField`, `sortOrder`。
   - `GET /api/v1/dataset/item/search`：跨数据集搜索，`datasetIds` 支持逗号列表，返回分页或游标结果。
   - `GET /api/v1/dataset/item/preferences` / `POST /api/v1/dataset/item/preferences`：读取/保存用户模式、排序偏好（Redis hash `user:dataset:pref:{userId}`），默认从 JWT 解 userId。
2. **批量操作**：
   - `DELETE /api/v1/dataset/item/batch`：Body `{ "itemIds": [], "deletePairs": false }`，删除 DataSetItem + SysItemFile。
   - `POST /api/v1/dataset/item/batch/download`：Body `{ "itemFileIds": [], "groupBy": "item" }`，调用下载任务服务（与 01 文档共享）。
   - `POST /api/v1/dataset/image/export`（若需导出 XLSX）：触发后台任务。
3. **单张下载**：`GET /api/v1/dataset/image/<itemFileId>/download?variant=current|clear|hazy|all` 位于 `item_file_blueprint`。

### 3.2 Service/查询实现
1. **`ImageQuerySchema`** 校验参数范围（pageSize ≤ 200、sortField 白名单 `upload_time|usage_count|width|height`、`mode` 限定 `list|waterfall_v|waterfall_h|grid`）。
2. **`DatasetItemService.query_images(query)`**：
   - `base_query = mysql.session.query(SysDatasetItem, SysItemFile, SysFile)` join 结构。
   - 根据 query 增加 where：datasetId、sceneType、hazeLevel、processStatus、width/height 范围、size（由 `SysFile.size` 转换为数字）。
   - 列表模式：`paginate()` + `count()`；瀑布流模式：按 `upload_time DESC, id DESC` 排序，拼接 `cursor=base64(f"{upload_time}|{id}")`。
   - 返回 `records`（含 ID、datasetId、fileName、fileSize、width、height、sceneType、hazeLevel、processStatus、imageType、uploadTime、usageCount、thumbnailUrl）。
3. **缓存**：
   - 将查询结果（列表 + cursor）缓存 5 分钟：key `dataset:image:list:{datasetId}:{hash(query)}`；上传/删除/标注后失效。
4. **批量删除**：
   - 获取 itemIds -> 删除 `SysItemFile` -> 删除 `SysDatasetItem` -> 触发统计缓存失效；返回 `{successCount, failedIds}`。
5. **批量下载**：
   - `ItemFileService.prepare_download_bundle` 根据 `itemFileIds` 拉取真实 URL + 元信息 -> 交给 `DatasetDownloadTask` 产出 zip；任务类型标记 `scope=imageSelection`。

## 4. 异常处理与边界情况
- `pageSize` 超限、`sortField` 非白名单 -> 400。
- `cursor` 非法/过期 -> 返回 400 并提示刷新；服务端不抛栈。
- 批量删除/下载超出阈值 -> 429 + `BATCH_LIMIT_EXCEEDED`。
- 跨数据集访问：`datasetId` 与 `itemIds` 不匹配时 409。
- 缓存宕机：降级直接查询数据库并在 response 加 `cache:false`。

## 5. 安全与性能注意事项
- 新接口沿用 JWT，中台需要在 `DatasetService` 内校验用户是否有数据集访问权限（预留 `dataset_scope`）。
- SQL 注入防护：排序字段通过 Python 枚举映射到 SQLAlchemy column；不允许直接拼接字符串。
- Redis 缓存 key 带用户 id，避免不同用户偏好互窜。
- 大列表使用 `yield_per` + `streaming`（如导出/下载）避免一次加载所有记录。

## 6. 测试建议
- **功能**：
  - 四种展示模式下的响应结构；
  - 场景/雾霾/状态/尺寸/大小组合筛选；
  - 搜索权重排序（关键词命中不同字段）；
  - 批量删除/批量下载成功 & 错误提示；
  - 用户偏好保存 & 登录后读取。
- **性能**：
  - 10w 张图片下分页响应（缓存命中/未命中）；
  - 无限滚动 5 次后 cursor 的准确性；
  - 批量下载 500 张图片任务耗时。
- **兼容**：
  - 横屏模式（`mode=waterfall_h`）返回的图片宽高比例是否正确；
  - Redis 不可用时接口仍可工作。

## 7. 待确认事项与风险
- 关键词相关度排序是否由后端负责，如需实现需提供明确权重算法（当前可在 Python 实现 Scored Query）。
- 横向瀑布流是否需要按“行”分组返回（当前设计返回扁平数组）；如需分组需增加 `rowIndex` 字段。
- 大批量导出是否必须生成 XLSX（若需要需引入异步导出任务）。
- 用户偏好持久化范围（仅后端 Redis 还是需要同步到用户表）需产品确认。
