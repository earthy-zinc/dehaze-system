# 代码设计文档

## 文档说明
- **对应需求**：`demo/docs/07-数据集管理模块需求-03-图片查看与标注功能.md`
- **适用版本**：dehaze-python Flask 后端 V2.0。
- **设计原则**：
  1. **读写分离**：查看接口聚焦数据聚合、配对导航；标注/修改接口聚焦写操作并具备乐观锁。
  2. **配对一致性**：同一 `SysDatasetItem` 下的清晰图/有雾图/去雾图需在服务层内强约束（宽高一致、唯一清晰图）。
  3. **日志留痕**：所有标注、删除、下载、配对调整写入审计日志，方便回溯。

## 1. 修改目标与范围定位
- 扩充图片详情、配对切换、上一张/下一张导航、标注/编辑、使用次数 API。
- 涉及：`app/route/item_file.py`（新增若干 GET/PUT/PATCH 路由）、`app/route/dataset.py`（上一张/下一张导航接口）、`app/service/item_file_service.py`、`DatasetItemService`、`app/service/file.py`、`app/models.SysItemFile`、`config.py`（操作日志开关）、`utils/error_handlers`（乐观锁异常）。

## 2. 现有实现概览
- `item_file_blueprint` 仅有上传/更新（TODO）/删除，缺少详情、配对、下载、标注等接口。
- `ItemFileService` 只实现 `save_item_file`、`get_image_urls`、`delete_item_file`，没有 metadata 更新、usage 统计、配对导航。
- `DatasetItemService` 未提供上一张/下一张逻辑。
- 模型缺少 `scene_type/haze_level/process_status/width/height/usage_count/create_time/update_time` 字段，导致无法记录元数据。
- 没有操作日志或事件表。

## 3. 代码设计与修改方案

### 3.1 路由与 API
1. **查看接口**（受 `jwt_required`）：
   - `GET /api/v1/dataset/image/<itemFileId>`：返回 `ImageDetailVO`（含 dataset 信息、文件信息、配对摘要、元数据、usage）。
   - `GET /api/v1/dataset/image/<itemFileId>/peers`：列出同一数据项内的所有配对图片，区分 clear/hazy/dehazed。
   - `GET /api/v1/dataset/<datasetId>/item/<itemId>/navigation`：返回上一张/下一张 `itemId`、`currentIndex`、`total`、`defaultImageId`。
2. **标注与元数据**：
   - `PUT /api/v1/dataset/image/<itemFileId>/meta`：Body `ImageMetadataForm`（场景类型、雾霾程度、图片类型、描述、processStatus、tags），支持乐观锁字段 `updateTime`。
   - `PATCH /api/v1/dataset/image/meta/batch`：Body `{ "itemFileIds": [], "sceneType": "", ... }`，用于批量标注。超过阈值需异步任务。
   - `POST /api/v1/dataset/image/<itemFileId>/usage`：Body `{ "event": "view|download|process", "delta": 1 }`，用于使用次数上报。
3. **日志查询（可选）**：`GET /api/v1/dataset/image/<itemFileId>/events?limit=20` 返回近期操作记录，若产品需要。

### 3.2 Service 层
1. **`ItemFileService`** 扩展：
   - `get_detail(item_file_id)`：join `SysItemFile`, `SysDatasetItem`, `SysDataset`, `SysFile`，补充：`fileName`, `fileSize`, `width`, `height`, `resolution`, `sceneType`, `hazeLevel`, `processStatus`, `usageCount`, `uploadTime`, `updateTime`, `thumbnailUrl`, `description`，再拼 `pairSummary`（clearCount/hazyCount/dehazedCount）。
   - `list_peers(item_file_id)`：查询同 `item_id` 的所有 `SysItemFile`，按 `type` + `haze_level` 排序；校验 `clear` 唯一性，如不唯一返回 `pairStatus=broke`。
   - `update_metadata(item_file_id, payload)`：校验字典值（`haze_level` 必须在 `sys_dict` 中），写入 `scene_type`、`haze_level`、`process_status`、`description`、`type`；使用 `update_time` 做乐观锁。
   - `touch_usage(item_file_id, event)`：`SysItemFile.usage_count += delta` 并驱动 `DatasetService.touch_usage(dataset_id)`。
   - `log_event(item_file_id, event, operator, before, after)`：写入 `image_event` 表或 reuse `mongodb` 集合。
2. **`DatasetItemService`**：
   - `get_navigation(dataset_id, current_item_id)`：按 `SysDatasetItem.create_time` 排序，返回 prev/next id、index、total。
   - `validate_pair(item_id)`：校验配对完整度（上传/编辑、批量操作后调用）。
3. **`file.py`**：增加 `get_image_dimension(sys_file_id)` / 将上传时解析的宽高写入 `SysItemFile`。

### 3.3 数据结构与工具
- **模型**：`SysItemFile` 添加字段：
  ```python
  scene_type = Column(String(64))
  haze_level = Column(String(32))
  process_status = Column(String(32), default='unprocessed')
  width = Column(Integer)
  height = Column(Integer)
  usage_count = Column(BigInteger, default=0)
  create_time = Column(DateTime, default=datetime.utcnow)
  update_time = Column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)
  ```
- **VO/Form**：
  - `ImageDetailVO`、`ImagePairVO`、`NavigationVO`；
  - `ImageMetadataForm` 使用 Marshmallow + `oneof` 校验；
  - `BatchAnnotationForm` 可选字段全部 `allow_none=True`。
- **日志表（建议）**：`image_event (id, item_file_id, dataset_id, operator, event_type, payload, created_at)`，若短期不建表，可存 Mongo 集合 `image_events`。

## 4. 异常处理与边界情况
- 图片不存在 -> 404；
- 元数据编辑时 `update_time` 不匹配 -> 409 `RESOURCE_CONFLICT`；
- 配对校验失败（缺清晰图/分辨率不一致） -> 返回 `pairStatus=broke` + 详细信息；
- 批量标注部分失败 -> 返回 `failedIds`，成功的照常提交；
- 日志写入失败要降级但不影响主流程。

## 5. 安全与性能注意事项
- 标注接口仅允许具备“数据管理员”或上传者本人操作，需在 service 层校验 `create_by` vs JWT userId。
- 防止 SQL 注入：更新以 `SysItemFile.query.filter_by(id=...).update({...})` + `synchronize_session=False` 完成。
- 操作日志敏感信息过滤（如下载 URL）；如写入 Mongo，需设置 TTL 索引避免无限增长。
- 大图片详情查询尽量单 SQL 完成（使用 `joinedload` 或子查询），减少 N+1。

## 6. 测试建议
- **功能**：
  - 查看接口字段完整性；
  - 配对切换、上一张/下一张导航；
  - 标注单条/批量更新（含乐观锁冲突场景）；
  - 使用次数在查看/下载/处理后的累加；
  - 日志记录与查询（如启用）。
- **性能**：
  - 单次详情请求在配对数量较多时（>10 张）耗时；
  - 批量标注 500 张图片耗时与数据库压力；
  - 多用户同时标注时的乐观锁冲突比例。
- **兼容**：
  - 场景类型的多语言/emoji；
  - Redis/日志服务不可用时接口降级表现。

## 7. 待确认事项与风险
- 使用次数是否区分事件类型（查看 vs 下载），若需要需在 schema 中增加 `event_type` 字段并更新统计口径。
- 操作日志保留策略（本地 MySQL vs Mongo vs 第三方日志），需运维确认。
- 批量标注是否需要事务包裹（若任何一条失败是否整体回滚），需产品确认。
- 是否需要对清晰图/雾图数量做硬性校验（例如清晰图缺失是否禁止上架）。
