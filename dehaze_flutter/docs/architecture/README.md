## 🎯 项目概述

### 产品定位

**Flutter图像去雾系统**是基于跨平台Flutter技术开发的移动端应用，专注于提供**用户友好**的图像去雾体验。本应用作为完整去雾系统的前端部分，与后端服务（dehaze-java、dehaze-go、dehaze-python）协同工作，为用户提供从图像输入到效果评估的完整闭环体验。

### 核心价值主张

- **用户体验优先**：简洁直观的界面设计，降低用户使用门槛
- **前端功能聚焦**：专注于用户交互和界面展示，后端服务处理复杂算法
- **跨平台一致性**：一套代码适配多个平台，保证统一的用户体验
- **响应式设计**：适配不同屏幕尺寸，从手机到桌面的完整支持

### 技术特色

- **Flutter跨平台框架**：单一代码库支持多平台
- **现代化UI设计**：基于Material Design 3.0设计规范
- **丰富的交互模式**：支持手势操作、动画效果、实时预览
- **智能化用户体验**：智能推荐算法、一键处理、快速体验

## 🏗️ 整体架构设计

### 架构模式

采用**Clean Architecture + Feature-First**架构模式，结合**Riverpod**状态管理，专注于前端用户体验优化。

```
dehaze_flutter/
├── lib/
│   ├── main.dart                    # 应用入口
│   ├── app/                         # 应用层
│   │   ├── app.dart                 # App根组件
│   │   ├── router/                  # 路由配置
│   │   ├── theme/                   # 主题配置
│   │   └── widgets/                 # 全局Widget
│   ├── core/                        # 核心层（跨功能共享）
│   │   ├── constants/               # 常量定义
│   │   ├── utils/                   # 工具类
│   │   ├── extensions/              # 扩展方法
│   │   └── errors/                  # 错误处理
│   ├── features/                    # 功能模块层
│   │   ├── home/                    # 首页模块
│   │   ├── image_input/             # 图像输入模块
│   │   ├── algorithm_select/        # 算法选择模块
│   │   ├── dehaze_processing/       # 去雾处理模块
│   │   └── effect_comparison/       # 效果对比模块
│   └── services/                    # 全局服务
│       ├── api/                     # API客户端
│       ├── storage/                 # 本地存储
│       └── providers/               # 全局Provider
```

### 模块划分与职责

| 模块名称 | 核心功能 | 用户价值 | 优先级 |
|---------|----------|----------|--------|
| **home** | 产品介绍、功能引导、快速入口 | 帮助用户了解产品功能 | P0 |
| **image_input** | 图像输入（上传、拍照、样例） | 提供便捷的图像获取方式 | P0 |
| **algorithm_select** | 算法选择（推荐、搜索、详情） | 智能选择最适合的算法 | P0 |
| **dehaze_processing** | 去雾处理（进度、预览、控制） | 实时查看处理进展 | P0 |
| **effect_comparison** | 效果对比（并排、重叠、放大镜） | 全面评估去雾效果 | P0 |

### 依赖关系

```
presentation → provider → usecase → repository
     ↓
  UI Components
     ↓
  Global Services (API, Storage)
```

**依赖规则**：
- 功能模块内部使用Clean Architecture分层
- 跨模块通信通过全局状态管理或事件总线
- 所有模块依赖core层的通用功能

## 👥 用户旅程设计

### 完整用户旅程（5阶段闭环）

Flutter前端负责以下交互阶段：

```
【阶段1：图像输入】
用户打开APP → 选择输入方式 → 预览确认 → 进入下一阶段

支持的输入方式：
├── 上传图片：相册选择 → 格式验证 → 预览确认
├── 拍照：相机 → 拍摄 → 预览确认
├── 样例库：浏览样例 → 选择样例 → 自动加载
└── 历史记录：查看历史 → 选择记录 → 重新处理

【阶段2：算法选择】
进入算法选择 → 查看智能推荐 → 浏览算法列表 → 选择算法

智能推荐功能：
├── 图像特征分析（雾霾浓度、场景类型）
├── 最适合算法推荐（1-3个选项）
├── 推荐理由说明
└── 一键选择功能

【阶段3：去雾处理】
参数确认（可选）→ 开始处理 → 实时进度展示 → 处理完成

处理过程控制：
├── 进度条显示（0-100%）
├── 预估剩余时间
├── 暂停/继续控制
└── 实时预览（可选）

【阶段4：效果对比】
自动进入对比 → 选择对比模式 → 查看效果 → 结果确认

6种对比模式：
├── 并排对比：左右分屏显示
├── 重叠对比：透明度调节
├── 放大镜：局部细节查看
├── 滑镜对比：拖动分割线
├── 滤镜调节：亮度/对比度调整
└── 指标评估：SSIM、PSNR等数据

【阶段5：结果处理】
用户确认结果 → 选择操作 → 完成流程

结果操作选项：
├── 保存到相册
├── 分享到社交平台
├── 导出对比报告
└── 添加到收藏/重新处理
```

### 快捷操作流程

**快速体验流程（样例图片）**
```
点击"快速体验" → 选择样例图片 → 自动推荐算法 → 直接查看对比结果
（预计用时：<10秒）
```

**重复处理流程（历史记录）**
```
历史记录 → 选择记录 → 更换算法 → 重新处理 → 对比新旧结果
（预计用时：<30秒）
```

## 📱 底部导航栏设计

### 导航结构（精简型）

采用5个主要入口：

```
┌─────────┬─────────┬─────────┬─────────┬─────────┐
│ 🏠首页  │ 📷输入  │ 🧠算法  │ ⚙️处理  │ 📊对比  │
└─────────┴─────────┴─────────┴─────────┴─────────┘
```

### 功能说明

#### 1. 🏠 首页
- **产品介绍**：展示产品核心价值
- **功能引导**：快速入口帮助用户了解功能
- **效果展示**：去雾前后对比展示
- **快速体验**：一键进入样例体验流程

#### 2. 📷 图像输入
- **多种输入方式**：上传、拍照、样例库、历史记录
- **格式支持**：JPG、PNG、WEBP、HEIC等主流格式
- **智能压缩**：大图片自动压缩，优化上传体验
- **预览功能**：缩略图和全屏预览

#### 3. 🧠 算法选择
- **智能推荐**：基于图像特征推荐最适合算法
- **算法浏览**：按类型、效果、速度等维度浏览
- **搜索筛选**：关键词搜索和条件筛选
- **详情展示**：算法原理、参数、样例效果

#### 4. ⚙️ 去雾处理
- **处理控制**：开始、暂停、继续、取消操作
- **进度展示**：实时进度条和预估时间
- **参数调节**：动态调整算法参数
- **批量处理**：支持多图片批量处理

#### 5. 📊 效果对比
- **多种对比模式**：并排、重叠、放大镜等6种模式
- **指标评估**：SSIM、PSNR等专业指标
- **交互优化**：手势操作、实时反馈
- **结果分享**：保存、导出、分享功能

## 🔄 后端服务集成

### 后端服务架构

Flutter前端作为整个去雾系统的一部分，与以下后端服务协同工作：

```
Flutter Frontend (dehaze_flutter)
    ↓ HTTP/WebSocket API
┌─────────────────────────────────────┐
│         API Gateway                  │
├─────────────────────────────────────┤
│  dehaze-java  │ dehaze-go │ dehaze-python  │
│  (Spring Boot) │ (Gin)     │ (Flask)         │
│  主要业务服务  │ 备选服务  │ 算法服务        │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│  MySQL  │  Redis  │  MongoDB  │ MinIO │
│  业务数据 │  缓存   │  文档数据 │ 文件存储 │
└─────────────────────────────────────┘
```

### API集成策略

#### 主要API服务

| 服务类型 | 推荐后端 | 主要功能 | 通信协议 |
|---------|----------|----------|----------|
| **用户认证** | dehaze-java | 登录、注册、权限管理 | HTTP + JWT |
| **算法管理** | dehaze-java | 算法列表、详情、推荐 | HTTP REST |
| **图像处理** | dehaze-python | 去雾算法执行 | WebSocket |
| **文件管理** | dehaze-java | 图像上传、下载、存储 | HTTP Multipart |
| **数据统计** | dehaze-go | 处理统计、性能数据 | HTTP REST |

#### 通信协议设计

**HTTP REST API**
- 标准RESTful接口设计
- JSON格式数据交换
- JWT认证和权限控制
- 统一错误处理和响应格式

**WebSocket实时通信**
- 处理进度实时推送
- 算法状态更新通知
- 批量处理状态同步
- 错误和异常通知

**文件上传下载**
- 支持大文件分片上传
- 断点续传功能
- 进度反馈和错误重试
- 多格式文件支持

## 📊 响应式设计策略

### 设备断点定义

定义4个主要断点：

| 断点类别 | 屏幕宽度 | 主要设备 | 布局特点 | 导航方式 |
|---------|---------|----------|----------|----------|
| **Mobile** | < 768px | 手机 | 单列垂直布局 | 底部导航栏 |
| **Tablet** | 768px - 1024px | 平板 | 双列网格布局 | 侧边导航栏 |
| **Desktop** | 1024px - 1440px | 桌面 | 多列布局 | 侧边导航栏 |
| **Large Desktop** | > 1440px | 大屏 | 宽屏优化布局 | 侧边导航栏 |

### 适配策略

#### 移动端优先
- 以手机端体验为基础设计
- 保证核心功能在小屏幕上的可用性
- 触摸友好的交互设计（最小44px触摸区域）
- 底部导航便于单手操作

#### 渐进增强
- 平板端增加信息密度，双列布局
- 桌面端充分利用屏幕空间，多列布局
- 大屏端限制最大宽度，避免内容过度拉伸
- 根据屏幕尺寸调整字体、间距、组件尺寸

## 🎨 UI设计系统

### 设计原则

遵循以下核心原则：

#### 平台无关性
- 基于Flutter跨平台特性，确保多平台一致性
- 使用Material Design 3.0设计规范
- 避免平台特定的UI模式，采用通用交互范式

#### 简洁高效
- 界面简洁清晰，突出核心功能
- 操作流程简短，减少用户学习成本
- 信息层级分明，重要信息突出显示

#### 专业可靠
- 现代化的视觉设计，渐变和阴影系统
- 准确的数据展示，多维度指标评估
- 完整的状态反馈和错误处理

#### 友好易用
- 符合用户习惯的交互模式
- 清晰的操作反馈和状态提示
- 智能设备检测，自动优化交互方式

### 核心设计规范

#### 色彩系统
- **主色调**：#3B82F6 (Tailwind Blue-500)
- **渐变主色**：linear-gradient(135deg, #3B82F6, #6366F1)
- **功能色**：成功(#4CAF50)、警告(#FF9800)、错误(#F44336)
- **中性色**：基于Tailwind Gray色阶的灰度系统

#### 字体系统
- **系统字体栈**：自动适配各平台原生字体
- **响应式字号**：根据屏幕尺寸动态调整（12px-20px）
- **层级规范**：标题、正文、辅助文字的清晰层级

#### 间距系统
- **基础单位**：4px，采用8px倍数系统
- **响应式间距**：移动端(8-16px)、桌面端(16-48px)
- **组件间距**：统一的内外边距规范

#### 圆角和阴影
- **圆角规范**：按钮(8-12px)、卡片(16px)、对话框(16px)
- **阴影系统**：5个层级的阴影效果，移动端适度减轻
- **交互反馈**：点击缩放、悬停上移等视觉反馈
