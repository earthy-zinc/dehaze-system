# 代码设计文档

## 文档说明
- **对应需求**：`demo/docs/07-数据集管理模块需求-01-数据集管理功能.md`
- **适用版本**：dehaze-front-react（Vite + React 18 + Ant Design + Redux Toolkit）
- **设计原则**：
  1. **状态统一**：数据集列表/详情/统计共享同一状态源（Redux + React Query 缓存）并与 `dehaze-sdk-js` API 能力解耦。
  2. **可观测性**：所有下载/统计的异步任务需有可视化进度、错误提示与可回溯日志。
  3. **渐进增强**：树结构、统计面板与下载面板在 API 失败时提供降级文案，保持基础 CRUD 可用。

## 1. 修改目标与范围定位
- 构建满足新增统计与下载能力的数据集管理界面，支持树形展示、详情弹窗、统计弹窗、整体打包下载、使用次数展示。
- 涉及层次：页面（`src/pages/dataset`）、组件（`src/components/dataset`）、状态（`src/store/modules/datasetSlice.ts` + React Query）、API 封装（`dehaze-sdk-js` 或 `src/api/dataset.ts`）、全局 UI（通知、Modal）。
- **需修改/新增文件**：
  | 路径 | 调整内容 |
  | --- | --- |
  | `src/pages/dataset/index.tsx` | 重构列表为“树 + 面板”布局，接入缓存、批量操作入口。 |
  | `src/pages/dataset/DatasetDetail.tsx` | 拆分出概览、统计、图片标签页，支持下载按钮。 |
  | `src/pages/dataset/components/` | 新增 `DatasetTreePanel.tsx`、`DatasetOverviewCard.tsx`、`DatasetStatisticsDrawer.tsx`、`DatasetDownloadDrawer.tsx`、`DatasetUsageBadge.tsx`。 |
  | `src/store/modules/datasetSlice.ts` | 扩展 state（树形数据、统计缓存、下载任务 Map），增加 thunk `fetchDatasetStatistics`、`pollDownloadTask`。 |
  | `src/api/dataset.ts`（若新增） | 统一封装新的 REST 调用：`getDatasetDetail`, `getDatasetStatistics`, `createDownloadTask`, `getDownloadTask`. |
  | `src/hooks/useDownloadTask.ts` | 自定义 Hook 轮询下载任务并推送全局通知。 |
  | `src/components/TaskProgress` | 渲染任务进度条，复用于下载/批量操作。 |

## 2. 现有实现概览
- **列表页** `DatasetList`：
  - 直接调用 `DatasetAPI.getList` 并以 AntD Table 展示；列设置仅通过 `Checkbox.Group`；无统计、使用次数、下载或缓存；`新增` 按钮逻辑与 UI 混杂。
  - 状态存于组件本地，不利用 `datasetSlice` 的缓存能力。
- **详情页** `DatasetDetail`：
  - 展示描述 + 基本的图片瀑布流；无统计、无下载按钮、无使用次数；搜索逻辑嵌入页面。
- **全局状态**：`datasetSlice` 仅保存 `datasetList`，无统计/下载信息；也未与 `persist` 同步树结构。
- **SDK**：`dehaze-sdk-js` 仅暴露既有接口（`getList`, `getDatasetInfoById`, `getImageItem` 等），缺少 V2.0 新能力。

## 3. 代码设计与修改方案

### 3.1 页面与组件
1. **DatasetList 改造**
   - 布局拆分为：左侧 `DatasetTreePanel`（树 + 搜索 + 状态筛选）+ 右侧 `DatasetOverviewCard`（统计摘要 + 操作按钮 + 子表）。
   - 使用 `@tanstack/react-query`（或 `useRequest`）请求树数据并写入 Redux 缓存；首次加载失败时显示降级提醒。
   - 操作区新增：
     - “下载数据集”按钮 -> 打开 `DatasetDownloadDrawer`。
     - “查看统计” -> 打开 `DatasetStatisticsDrawer`。
     - “使用记录” -> `DatasetUsageBadge` + Tooltip。
   - 列表改为 `VirtualTable`，支持 Lazy Render；列配置持久化到 `localStorage`。
2. **DatasetDetail 拆分标签页**
   - Tab1“图片浏览”复用文档 02 设计；Tab2“统计”内联图表；Tab3“下载/导出”展示任务。
   - Header 显示 `DatasetOverviewCard`（复用），包含 `usageCount`, `imageCount`, `sceneDistribution` 简图。
   - 详情页中调用 `useDownloadTask` Hook 显示下载任务进度（使用 AntD Alert + Steps）。
3. **新增组件**
   - `DatasetTreePanel`: `Tree` + `Search Input` + `Status Tag` + `usageCount` 二级标签。
   - `DatasetStatisticsDrawer`: `Drawer` 内使用 `@ant-design/plots` 绘制饼图/柱状图，支持“刷新”按钮。
   - `DatasetDownloadDrawer`: 表单（组织结构、压缩方式、含配对）+ 任务列表，可触发下载并展示 `TaskProgress`。
   - `TaskProgress`: 通用组件渲染状态 `processing/completed/failed`。

### 3.2 数据流与状态
- **Redux Slice** 扩展：
  ```ts
  interface DatasetState {
    tree: Dataset[];
    statsMap: Record<number, DatasetStatistics>;
    downloadTasks: Record<string, DownloadTaskVO>;
    loadingTree: boolean;
  }
  ```
- `fetchDatasetTree` thunk：并行获取树 + options，缓存到 `tree`。
- `fetchDatasetStatistics(datasetId)` thunk：若 `statsMap[datasetId]` 为空或 `forceRefresh`，请求 `/dataset/:id/statistics` 并存储。
- `createDatasetDownloadTask(payload)` thunk：提交后将任务插入 `downloadTasks`，并触发 `pollDownloadTask(taskId)`（使用 `createAsyncThunk` + `condition`）。
- React Query 用于详情页（`useDatasetDetail(datasetId)`）以避免重复 dispatch。

### 3.3 API 封装与错误处理
- 在 `src/api/dataset.ts` 内新增 `getDatasetDetail`, `getDatasetStatistics`, `createDownloadTask`, `getDownloadTask`, `patchDatasetUsage`，与后端 V2.0 接口一一对应。
- 接口错误通过 `App.useApp().message.error` 提示，500 级别错误触发全局通知。
- 下载任务完成后，自动调起浏览器下载（若返回 URL），同时 `message.success`。

## 4. 异常处理与边界情况
- 树加载失败：显示空状态 + “重试”按钮；允许用户手工刷新。
- 统计接口失败：Drawer 中展示错误插画，避免阻塞其它功能。
- 下载任务失败：状态卡片显示错误信息，并允许点击“重新下载”重新发起任务。
- 使用次数接口 429：提示稍后重试，界面上不立即回滚本地计数。

## 5. 安全与性能注意事项
- 所有写操作（下载、删除、编辑）均需检测权限标签（从用户信息或接口返回）并决定按钮显隐。
- 树结构启用虚拟滚动和懒加载，防止一次性渲染上千节点。
- 统计接口结果缓存 30 分钟；手动刷新时通过 `forceRefresh` 参数绕过缓存。
- 下载任务轮询间隔指数退避（3s/5s/8s），防止接口轰炸。

## 6. 测试建议
- **功能**：
  - 树搜索、过滤、展开收起；
  - 详情页面统计/下载/使用次数展示；
  - 下载任务全链路（成功、失败、取消）；
  - 缓存与刷新（统计、树）是否符合预期。
- **性能**：
  - 1k+ 数据集节点时渲染与操作延迟；
  - 下载任务并发 3 个时的 UI 响应；
  - React Query 缓存命中率。
- **兼容**：
  - 小屏（<1024px）下 Drawer、Tree 的可用性；
  - 无权限账号是否隐藏下载/统计入口。

## 7. 待确认事项与风险
- 下载任务发起人是否能看到他人任务列表，需要产品确认权限范围。
- `usage_count` 是否实时刷新还是固定周期刷新，影响 UI 文案。
- `dehaze-sdk-js` 是否由前端维护，如需扩展需同步 SDK 仓库；否则临时在 `src/api` 增加自定义请求。
- 统计图表需要的指标（格式分布、分辨率区段）是否已在后端实现，若缺需与后端确认。
