# 代码设计文档

## 文档说明
- **对应需求**：`demo/docs/07-数据集管理模块需求-04-图片上传与管理功能.md`
- **适用版本**：dehaze-front-react
- **设计原则**：
  1. **流程化上传**：单张 / 配对 / 批量上传采用向导式表单，提示校验、进度与回滚策略。
  2. **实时反馈**：上传与批量管理任务全部进入统一的“任务中心”并支持暂停/重试。
  3. **可扩展存储**：封装上传 SDK，未来可切换到直传 OSS / MinIO 预签名。

## 1. 修改目标与范围定位
- 前端需提供单张上传、配对上传、批量上传、批量删除、批量更新、批量下载等管理界面，与后端 V2.0 行为一致。
- 涉及文件：
  | 路径 | 调整 |
  | --- | --- |
  | `src/pages/dataset/DatasetDetail.tsx` | 新增“上传”按钮入口，唤起上传向导。 |
  | `src/pages/dataset/components/upload/UploadWizard.tsx` | 多步骤上传组件。 |
  | `src/pages/dataset/components/upload/PairUploadForm.tsx` | 清晰图+多雾霾图配置。 |
  | `src/pages/dataset/components/upload/BatchUploadTaskPanel.tsx` | 展示批量任务进度。 |
  | `src/components/task-center/TaskCenterDrawer.tsx` | 统一展示下载/上传任务。 |
  | `src/hooks/useUploadTask.ts` | Hook，负责任务状态轮询、取消、重试。 |
  | `src/api/upload.ts` | 封装 `uploadSingle`, `uploadPair`, `uploadBatch`, `getUploadTask`, `cancelUploadTask` 等接口。 |
  | `src/utils/uploader.ts` | 封装分片上传 / 直传 / MD5 计算。 |

## 2. 现有实现概览
- 目前只有 `DatasetImageSelect` 组件（选取图片用），页面内部没有上传能力；
- `ItemFileService.save_item_file` 的前端实现仅上传单文件，缺少表单字段（场景类型、雾霾程度、图片类型、描述等）；
- 无配对上传、批量上传、任务进度展示，也没有批量删除 / 批量标注入口。

## 3. 代码设计与修改方案

### 3.1 上传向导（UploadWizard）
1. **步骤**：
   - Step1：选择上传类型（单张 / 配对 / 批量） + 选择目标数据集/数据项；
   - Step2：上传文件（支持拖拽 + 进度条）。
     - 单张：填写 `sceneType/hazeLevel/imageType/description`；
     - 配对：清晰图 + 多雾霾图，提供雾霾程度选择、文件分辨率校验提示；
     - 批量：上传多个文件或 zip，提供命名规则说明；
   - Step3：确认信息 + 提交，跳转到任务中心查看进度。
2. **技术实现**：
   - 使用 `AntD Upload.Dragger` + 自定义 `beforeUpload` 做校验；
   - 与后端约定：单/配对上传使用表单直传；批量上传需先调用 `/upload/batch` 获取 `taskId`，再分片上传（如需）。
   - 上传前计算 MD5（使用 `spark-md5`），可用以断点续传和去重。

### 3.2 任务中心
- `TaskCenterDrawer` 固定在布局右下角或通过按钮打开；
- 存储结构：
  ```ts
  interface Task {
    id: string;
    type: 'upload-single'|'upload-pair'|'upload-batch'|'delete-batch'|'download';
    name: string;
    progress: number;
    status: 'processing'|'completed'|'failed'|'cancelled';
    meta?: Record<string, any>;
  }
  ```
- `useUploadTask` Hook：
  - 创建任务时写入 Redux / React Query 缓存；
  - 定时轮询 `/dataset/image/upload-task/:id`；
  - 任务完成后弹出通知，可一键查看日志或打开图片列表。

### 3.3 表单校验与提示
- **场景类型**：`AutoComplete` + “新增”按钮，支持本地缓存历史输入；
- **雾霾程度**：`Select`（light/medium/heavy/unknown）；未选时提示；
- **分辨率校验**：配对上传时读取 `Image` 对象的宽高并在 UI 上展示对比结果（绿色通过 / 红色失败）。
- **批量模式**：
  - 解析文件名（`scene_001_clear.jpg`），自动匹配清晰图/雾霾图，提供可编辑表格；
  - 若文件数超出限制，阻止提交并提示 `UPLOAD_POLICY.batch_total_mb`。

### 3.4 批量删除/更新入口
- 在 `ImageBrowser` 的 `BatchActions` 中，调用以下 API：
  - 批量删除 -> `POST /dataset/image/batch-delete`，操作完成后刷新列表；
  - 批量更新 -> 打开 `BatchAnnotateModal`；
  - 批量下载 -> 复用下载任务。
- UI 需提示操作影响（示例：删除时确认“同时删除配对?”）。

### 3.5 上传 SDK 封装
- `src/utils/uploader.ts`：
  - `uploadFile({ file, onProgress })`：默认走后端普通接口；
  - 若后端提供预签名，调用 `/upload/presign` -> 直接 PUT 到 OSS，再回调后端确认；
  - 支持分片（大于 50MB 时自动拆分）和暂停/恢复。

## 4. 异常处理与边界情况
- 文件超大小/格式限制：在 `beforeUpload` 阶段阻止，并使用 `notification.error` 提示；
- 配对校验失败：指出具体哪张图片不匹配（宽高/雾霾程度缺失）；
- 批量任务中断：任务中心显示 `failed`，允许“重新上传剩余文件”；
- 删除/更新操作部分失败：弹出结果列表（成功/失败明细）。

## 5. 安全与性能注意事项
- 上传接口需附带 JWT token，若使用预签名需限制有效期；
- `UploadPolicy` 配置来自 `config.ts`，可根据环境覆盖；
- 大文件上传分片后需顺序合并，避免占用过多内存；
- 任务轮询需指数退避，避免洪泛；
- 所有文件名在展示前需转义，防止 XSS。

## 6. 测试建议
- **单张上传**：场景/雾霾/描述填写、预览、提交；
- **配对上传**：缺清晰图、缺雾霾程度、分辨率不一致等异常；
- **批量上传**：文件命名自动匹配、任务进度、失败重试、取消操作；
- **批量删除/更新**：权限校验、部分失败反馈；
- **任务中心**：并发多个任务的状态展示、暂停/继续、重试。

## 7. 待确认事项与风险
- 批量上传是否必须支持 zip 解压（如需，前端需提示命名规则）；
- 任务中心是否需要持久化（刷新页面后是否还需显示历史任务）；
- 上传直传策略（预签名 vs 通过后端转发）需与后端确认；
- 场景类型字典是否由前端维护缓存或调用后端接口。
