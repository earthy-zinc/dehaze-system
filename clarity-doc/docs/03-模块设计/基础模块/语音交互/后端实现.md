# 语音交互模块 - 后端实现设计

## 文档概述

### 架构概览

语音交互模块不维护独立的语音引擎注册表：ASR/TTS 模型与供应商统一登记在 AI 模型管理域（`sys_ai_model` + `sys_ai_provider` + `sys_ai_provider_key`），`model_type` 为 `asr` / `tts`。本模块是统一模型路由的消费方——`resolve_voice_model` 按类型解析出目标模型，经统一模型注册表（`model_registry`，含供应商 fallback、Key 轮换、熔断）拿到调用路由，再由 OpenAI Audio 兼容适配器（`OpenAiAudioAdapter`）调用服务。

语音推理由独立推理服务 `clarity-service/clarity-voice` 承担（8993，内网专用，零 DB/Redis/存储依赖），以主流协议对外提供 API（`POST /v1/audio/transcriptions`、`POST /v1/audio/speech`，流式 ASR 为 `local-voice` 协议族的 `WS /v1/asr/stream` 扩展）。平台侧用与云厂商相同的适配器调用它，无本地特判：`local-voice` 只是 `sys_ai_provider` 中一条 `protocol_type=openai_audio` 的普通供应商行（`api_base_url` 指向 clarity-voice，密钥为 `INTERNAL_SERVICE_KEY`）。编排侧只保留并发、计费、会话态与超时控制。服务边界与接口契约见[《AI 能力链路协作设计》](../../../02-系统架构/09-AI能力链路协作设计.md)。

核心数据流：

1. 前端录音 → WebSocket（业务后端）→ AsrService 两跳代理 → 解析出的 ASR 模型（本地 `local-voice` / 云厂商，经适配器）→ 文本 → AI 对话模块消息管道
2. 后端文本 → TtsService → 解析出的 TTS 模型（本地 / 云厂商）→ 音频加密落文件管理 → 前端播放

| 适配对象                | 实现要点                                                                                                                                                                                                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 本地 ASR（local-voice） | `protocol_type=openai_audio`：离线经 `POST /v1/audio/transcriptions`（multipart，`file` + `model` + `hotwords` 扩展字段）→ `{text}`；流式经协议族扩展 `WS /v1/asr/stream`（SenseVoice-Small 分段增量，自定义帧协议）。推理与权重缓存均在 clarity-voice                    |
| 本地 TTS（local-voice） | `protocol_type=openai_audio`：经 `POST /v1/audio/speech`（`model` + `input` + `voice` + `response_format` + `speed`）→ 音频字节；合成在 clarity-voice，编排侧只做 AES 加密缓存与计费                                                                                      |
| 云厂商 ASR/TTS          | 按供应商 `protocol_type` 分派协议族：`openai_audio`（OpenAI 兼容端点）经 `OpenAiAudioAdapter`，`dashscope_realtime`（阿里云百炼）经 `dashscope_audio_client`，`volc_realtime`（火山引擎）经 `volc_audio_client`；密钥统一经 `sys_ai_provider_key` 管理 |

### 服务状态监控

管理端服务监控面板查询 ASR/TTS 运行状态，接口见 [API接口.md](./API接口.md)：

| 维度     | 数据来源                                                                             | 说明                                                                                           |
| -------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| ASR 状态 | 默认 ASR 模型所属供应商的连通性探测（经适配器）+ Redis `voice:asr:sessions` 并发计数 | 供应商状态（online/offline）、concurrentSessions、maxConcurrentSessions、流式/离线模型加载状态 |
| TTS 状态 | 默认 TTS 模型所属供应商的连通性探测（经适配器）                                      | 供应商状态（online/offline）、当前音色模型加载状态                                             |

- 数据源为模型路由统计（默认 ASR/TTS 模型 → 供应商），无独立引擎注册表
- 供应商不可达或未配置默认模型时按 offline 上报（不抛异常，状态接口始终可用，T-VS-067）
- 并发会话数实时读取 Redis 有序集合 `voice:asr:sessions`（按时间戳剪枝后计数）
- 管理端定时轮询刷新；权限 `voice:service:monitor`（仅管理员），普通用户访问返回 A0301

### 统一模型路由消费（默认模型与解析链）

本模块不维护自己的模型表，ASR/TTS 模型即 `sys_ai_model` 中 `model_type=asr` / `model_type=tts` 的行，供应商与密钥即 `sys_ai_provider` / `sys_ai_provider_key`：

| 数据         | 来源                                     | 说明                                                                                                                                                                   |
| ------------ | ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ASR/TTS 模型 | `sys_ai_model`（`model_type=asr`/`tts`） | 任务标签 `task_tags`：ASR 为 `["stream"]`/`["offline"]`，TTS 音色即模型（`["voice"]` 或不设）；`extra_request_params` 承载厂商私有请求参数                             |
| 供应商       | `sys_ai_provider`                        | 语音协议族 `protocol_type`：`openai_audio`（内置 `local-voice` 与 OpenAI 兼容云厂商）/ `dashscope_realtime`（百炼）/ `volc_realtime`（火山）；`provider_code` 单列唯一 |
| 密钥         | `sys_ai_provider_key`                    | 统一密钥表，`ProviderKeySelector` 单实例（priority/weight/额度/冷却）供全模态复用                                                                                      |

本地供应商 `local-voice`：`protocol_type=openai_audio` 的普通供应商行，`api_base_url` 取种子数据 `config/sql/data/sys_ai_provider.sql`（`init-builtin` 首次按 `VOICE_ENGINE_BASE_URL` 写入，已有行不覆盖；指向外置推理服务 clarity-voice），密钥明文即 `INTERNAL_SERVICE_KEY` 并落 `sys_ai_provider_key`——由显式命令 `clarity-python/.venv/bin/python -m app.cli init-builtin` 写入（幂等、绝不覆盖已有行，密钥变更时自动停用旧行），进程启动不写库；与云厂商一同管理，编排侧透明。配置 `VOICE_LOCAL_ENABLED`（默认 true）为 false 表示本部署不提供本地语音引擎：`init-builtin` 不初始化 `local-voice` 供应商与对应模型并禁用已有行，ASR/TTS 全部由云厂商模型提供。

默认模型（解析链）：`sys_dict` 组 `ai_model` 提供 `default_model.asr` 与 `default_model.tts`。解析次序为请求显式 `model` > 平台默认（dict，须 `status=1`）> A0500，不回退代码常量；用户偏好（`sys_ai_user_preference`）不覆盖语音模型（语音模型用户无感）。

运行时路由：`resolve_voice_model(model_type)` 解析出模型 → `model_registry.get_call_routes(model_id)` 得到候选调用路由（多供应商 fallback + Key 轮换 + 熔断）→ 语音分派层（`audio_dispatch`）按供应商 `protocol_type` 选择适配器，按 `api_base_url` 与解密后的供应商密钥调用。编排侧不区分本地与云厂商。

模型可用性：路由不对所选供应商做可用性预检，调用不可用时按其自身错误暴露——本地为「语音服务不可用」或鉴权失败（提示检查 `INTERNAL_SERVICE_KEY`），云厂商为对应调用错误。语音链路不做独立熔断/健康统计（复用统一模型路由的熔断口径）。

密钥与连通性：密钥存储、查重、额度预留、冷却与失败重试由统一 `ProviderKeySelector` 承担（AI 域与语音域共用单实例，键前缀统一 `provider_key:*`）；管理端连通性测试对本地供应商按库内地址与密钥真实探测服务就绪（模型懒加载，探测不触发加载；探测只取第一条可用 Key，不占额度、不计冷却）。`voice_asr`/`voice_tts` 与 `/health/ready` 直接取默认模型供应商的运行时探测结果。

模型切换：管理端修改 dict 默认模型或模型 `status` 后，`VoiceModelResolver` 缓存（Redis `voice:model:asr` / `voice:model:tts`，短 TTL 60s）失效即时生效。


## ASR 实现

本地 ASR 引擎外置为 clarity-voice 服务，经语音分派层（`audio_dispatch`）按 `protocol_type=openai_audio` 调用；云厂商 ASR 按其协议族（`dashscope_realtime`、`volc_realtime`、`openai_audio`）分派适配器。以下描述本地引擎实现。

### FunASR 部署架构

FunASR 以独立推理服务运行（`clarity-service/clarity-voice`，实现于 `app/engines/asr.py`，默认端口 8993，仅绑内网）：GPU 优先推理（torch CUDA 可用时卸载至 GPU，否则纯 CPU），模型与推理依赖只随该服务分发，与业务后端进程解耦（业务进程 reload/重启不影响引擎）。

| 维度         | 说明                                                                                                                                                        |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 流式识别     | SenseVoice-Small 分段增量识别（每累计 1 秒音频触发一次分段转写，累计文本覆盖式下行）                                                                        |
| 离线识别     | SeACo-Paraformer-Large（Paraformer-Large 热词增强版，原生热词加权）                                                                                         |
| 热词         | 按请求/会话生效，引擎侧不保存任何跨请求热词状态，多用户并发互不覆盖                                                                                         |
| 模型来源     | 模型清单技术事实源为 clarity-voice `/v1/models` 目录扫描（import_path、权重由服务端按 `model` 解析）；DB 行只承载启停、展示、计费、归因，运行时工件不落库      |
| 懒加载与缓存 | 流式在会话建立前预加载、离线在首个请求时加载，服务进程内单例；权重缓存于 `MODEL_CACHE_DIR/modelscope`（需持久化卷，重启不重复下载）；多实例部署时每实例一份 |
| 依赖         | funasr / modelscope / torchaudio 为 clarity-voice 服务的依赖（延迟导入控制启动成本），不随 clarity-python 分发                                               |
| 设备与线程   | `ASR_DEVICE`（auto 时按 torch CUDA 可用性选择）、`ASR_INFERENCE_THREADS` 由服务侧配置                                                                       |

### 流式 ASR 流程

编排侧作为客户端把「前端 WS」与「服务 WS」两跳串起来转发，识别结果经同一通道回推。

1. 前端 `POST /asr/stream-session` 获取 sessionId + wsUrl（相对路径 `/ws/asr?...`，内嵌当前登录会话凭证 `sid`——浏览器 WS 握手无法携带自定义 Header。后端不拼绝对地址：反代场景下后端无法可靠感知外部可见 origin，由客户端按自身 origin 解析，反代/vite 代理只需转发 `/ws`）
2. 前端建立 WebSocket，服务端建连时校验 `sid` 对应登录会话有效且与 ASR 会话归属一致，失败以 4001 关闭
3. 编排侧经 `resolve_voice_model('asr')` 解析默认/显式 ASR 模型，建立服务侧会话 `WS /v1/asr/stream?model_id=`（握手头 `Authorization: Bearer`），并随即下发首条控制消息 `{"type":"config","hotwords":[...],"session_id":"<sessionId>"}`：热词随会话生效；`session_id` 作为服务侧幂等键，重复建连被拒绝（`SESSION_CONFLICT`，WS 关闭码 4409），避免双份识别
4. 前端每 100ms 推送 PCM 音频块（16kHz/16bit/mono），编排侧原样转发至服务（`await` 发送，由 websockets 高水位挂起天然形成上行反压），不做转码/重采样
5. 服务按分段返回 `{"text", "is_final"}`，编排侧转换为前端契约 `{"text", "isFinal"}` 下行；收到最终结果后结束下行
6. 结束：前端 `EOS` / 达最长时长（60s）/ 接收空闲超时（60s）/ 任一侧断开 → 编排侧向服务发 `EOS` 并等待终态（≤10s）→ 按累计已收字节实扣 → 会话置 completed 并关闭两端连接

| 方向      | 消息格式                                                     | 说明                                                              |
| --------- | ------------------------------------------------------------ | ----------------------------------------------------------------- |
| 编排→服务 | 文本 `{"type":"config","hotwords":[...],"session_id":"..."}` | 首条控制消息（热词可达百词，不入 URL 以免长度上限与访问日志泄露） |
| 前端→编排 | 二进制 PCM 音频块                                            | 16kHz, 16bit, mono                                                |
| 编排→服务 | 二进制 PCM 音频块 / 文本 `"EOS"`                             | 原样转发，不改帧类型                                              |
| 服务→编排 | JSON `{"text": "...", "is_final": bool}`                     | 增量 / 最终结果；错误帧为 `{"code","message"}`                    |
| 编排→前端 | JSON `{"text": "增量", "isFinal": false}`                    | 中间结果                                                          |
| 编排→前端 | JSON `{"text": "完整文本", "isFinal": true}`                 | 最终结果                                                          |
| 前端→编排 | 文本 `"EOS"`                                                 | 结束信号                                                          |

下行字段为 `isFinal`（camelCase），与 SDK 契约（`AsrStreamMessage`）一致；编排侧负责把服务的 `is_final` 转换为此契约。

服务错误帧（如模型加载失败、推理失败），或建连后未产出任何识别结果即断开时，编排侧判定识别未起效：会话置 `failed` 并向前端以 4001 关闭，已收音频仍按计费不变式实扣（此场景通常为 0 秒，不产生费用）。

### 离线 ASR 流程

前端 multipart 直传完整音频文件（WAV/PCM，16kHz/16bit/mono），编排侧校验格式后经 `OpenAiAudioAdapter` 调用 `POST /v1/audio/transcriptions`（multipart：`file` + `model` + `hotwords` 扩展字段），服务以 Paraformer-Large 高精度识别，返回含标点断句的完整文本；音频不落盘，处理完即弃。

### 热词配置

| 热词类型   | 生效范围 | 管理权限                         | 接口归属                        |
| ---------- | -------- | -------------------------------- | ------------------------------- |
| 全局热词   | 所有用户 | 管理员（`voice:hotword:edit`）   | `/api/v1/voice/hotwords/global` |
| 用户级热词 | 当前用户 | 用户本人（`voice:hotword:edit`） | `/api/v1/voice/hotwords`        |

生效与下发：热词合并（全局热词在前 + 用户级热词追加、去重；另在写入时 `html.escape` 清洗，单用户上限 100）在编排侧完成，结果随请求下发——流式经建连后首条 `config` 控制消息，离线经 `hotwords` 表单字段（对齐 DashScope `vocabulary_id` 的厂商扩展参数做法）。热词变更对新建会话即时生效，无需重启服务。接口见 [API接口.md](./API接口.md)。

### ASR 结果处理

文本规范化在服务侧完成：SenseVoice 定向中文并启用 ITN（"八十"→"80"）、剥离语言、情感、事件标签；热词加权仅 SeACo-Paraformer 系支持（按空格拼接去重后的热词，空热词不传参）。编排侧不做标点修正与数字规范化后处理，直接使用服务返回文本。

### 云厂商 ASR 接入

云厂商 ASR 按供应商 `protocol_type` 经语音分派层（`audio_dispatch`）接入：`openai_audio` 走 `OpenAiAudioAdapter`，`dashscope_realtime`（百炼）走 `dashscope_audio_client`，`volc_realtime`（火山）走 `volc_audio_client`（协议族与帧协议见 [AI模型管理/后端实现.md](../AI模型管理/后端实现.md) 的协议适配器表）：

- 协议适配：`api_base_url`（厂商 API 地址，库内配置）+ 供应商密钥组装请求；密钥经 `sys_ai_provider_key` 由统一 `ProviderKeySelector` 选取（priority 优先 + 同优先级按 `weight` 加权随机，额度超限或冷却中的 Key 自动跳过）
- 流式/离线：离线对齐 `POST /v1/audio/transcriptions`；流式按协议族各自实现（`local-voice` 私有 WS 扩展、百炼 run-task 指令框架、火山二进制帧协议），统一会话语义（`send_audio` / `send_eos` / `recv_messages` / `aclose`）由分派层向上屏蔽
- 结果契约：统一转换为与本地一致的 `{text, isFinal}` 增量协议，Service 层不感知厂商差异
- 计费：与本地同口径——按模型价格表 `billing_unit=second` 计价，计费记录 `model` 记实际模型标识


## TTS 实现

本地 TTS 引擎外置为 clarity-voice 服务，经语音分派层（`audio_dispatch`）按 `protocol_type=openai_audio` 调用；云厂商 TTS 按其协议族分派适配器。以下描述本地引擎实现。

### TTS 引擎部署架构

Piper TTS 以独立推理服务运行（`clarity-service/clarity-voice`，实现于 `app/engines/tts.py`）；GPU 优先（onnxruntime 带 CUDAExecutionProvider 时启用，否则纯 CPU），对齐 FunASR 部署形态。

| 维度         | 说明                                                                                                                                                          |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 模型         | piper-voices 开源库 zh_CN-huayan-medium（约 60MB，CC-BY-4.0）                                                                                                 |
| 音色即模型   | TTS 音色登记为 `sys_ai_model`（`model_type=tts`）行；运行时工件（onnx 文件名、size、下载 URLs）不落库，由 clarity-voice `/v1/models` 目录按 `model` 服务端解析 |
| 懒加载与下载 | 首个合成请求时加载，服务进程内单例；权重缺失时经 hf-mirror 下载（回退 huggingface.co）落 `MODEL_CACHE_DIR/piper`（需持久化卷）                                |
| 输出编码     | PCM 重采样 → WAV 封装 / MP3 编码（lameenc）/ 裸 PCM，均在服务侧完成                                                                                           |
| 依赖         | piper-tts / lameenc / torchaudio 为 clarity-voice 服务的依赖，不随 clarity-python 分发                                                                          |

### TTS 合成流程

1. TtsService 按 `SHA256(text + model + speed)` 查缓存，命中直接返回音频 URL（不合成、不扣费）
2. 未命中 → 积分余额预校验 → 经 `resolve_voice_model('tts')` 解析模型 → `OpenAiAudioAdapter` 调用 `POST /v1/audio/speech`（请求体 `model`、`input`、`voice`、`response_format`、`speed`，扩展字段放顶层或 `extra`）；语速映射（`length_scale=1/speed`）与输出编码在服务侧完成
3. 音频 AES 加密存文件管理 → 写入缓存 → 实扣积分
4. 返回音频 URL（`GET /api/v1/voice/tts/audio/{cacheKey}` 解密后流式返回）

服务不可用、合成失败或音频存储失败均返回 A0500，不存储不扣费，前端降级纯文本。合成完成后返回 audioUrl。

### TTS 缓存策略

| 配置项     | 说明                           | 值           |
| ---------- | ------------------------------ | ------------ |
| 缓存位置   | 文件管理（sys_file）           | —            |
| 缓存 Key   | `SHA256(text + model + speed)` | —            |
| TTL        | 24 小时                        | 过期自动清理 |
| 最大缓存数 | 单用户 100 条                  | LRU 淘汰     |

缓存适合 AI 对话常见开场语与系统提示语等重复文本。

### 云厂商 TTS 接入

云厂商 TTS 按供应商 `protocol_type` 经语音分派层（`audio_dispatch`）接入（协议族见本节 ASR 云厂商接入与 [AI模型管理/后端实现.md](../AI模型管理/后端实现.md) 的协议适配器表）：

- 协议适配：`api_base_url` + 供应商密钥组装合成请求，密钥经 `sys_ai_provider_key` 统一管理；音色映射到 `sys_ai_model`（`model_type=tts`）注册的厂商音色模型
- 输出归一：厂商返回音频（mp3/wav/pcm）统一落为与本地一致的 `{audioUrl, format}` 契约；语速、采样率由模型 `extra_request_params` 映射
- 缓存复用：TTS 缓存对本地、云厂商一致——缓存 Key 含音色模型，命中不合成不扣费；合成音频仍经 AES 加密存储
- 计费：与本地同口径——按模型价格表 `billing_unit=ten_thousand_chars` 计价，计费记录 `model` 记实际模型标识
- 音色目录：`GET /api/v1/voice/tts/voices` 返回平台默认 tts 模型所属供应商 `protocol_type` 对应的音色目录（`voice_tts.get_voice_catalog`：内置 `openai_audio` 为本地 Piper 音色，`volc_realtime` 为火山 voice_type）；合成时 `voice` 按同一目录校验。`TtsForm.voice` 上限 128 字符（火山 voice_type 如 `zh_female_*_uranus_bigtts` 超旧 32 上限）


## 流式并发控制与资源回收

| 维度         | 设计                                                | 说明                                                                                         |
| ------------ | --------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 并发会话上限 | 最大 50 并发                                        | Redis `voice:asr:sessions` 有序集合计数，超过上限拒绝新会话并提示                            |
| 超时归属     | 空闲 60s / 最长 60s / 下行收尾 10s 全部在编排侧     | 属前端契约语义；服务侧仅 `ASR_STREAM_IDLE_TIMEOUT`（30s）无输入自动收尾兜底                  |
| 上行背压     | 编排侧 `await` 服务发送（websockets 高水位挂起）    | 录音快于识别速度时向上反压前端，不额外引入队列、不丢弃音频                                   |
| 资源回收     | 会话结束即关闭服务侧连接（无连接池）                | 每会话一条服务 WS；结束、断开、异常统一走收尾（EOS → 终态 ≤10s → 计费 → 置终态），不跨会话复用 |

已知限制：

- 并发上限校验为 Redis `zcard` 检查 + `zadd` 登记两步非原子操作，突发高并发下实际并发可能超出上限 1-2 个；该上限属资源保护类限流（非业务配额），超出后由服务侧推理线程池兜底，已评估可接受，如需严格化可改为 Lua 脚本原子执行
- 离线 ASR 无独立并发上限，依赖 clarity-voice 服务侧推理线程池（默认 2 线程）排队消化；高峰期大量离线转写请求会排队等待，极端情况排队超时


## 安全设计

### 认证授权

| 防护项             | 说明                                                                                                                                                                                                                             |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 服务间鉴权         | 编排侧调用 clarity-voice（HTTP 全端点与 WS 握手）一律携带 `Authorization: Bearer ${INTERNAL_SERVICE_KEY}`（作为 `local-voice` 供应商密钥经统一密钥表下发）；服务侧密钥缺失/错误返回 401（WS 握手 4401），密钥未配置时 fail closed |
| WebSocket 连接鉴权 | 流式 ASR 的前端 WebSocket 建立时校验登录态（`sid`），未认证拒绝建连并以 4001 关闭                                                                                                                                                |
| 会话 ID 绑定用户   | sessionId 与 userId 绑定，建立会话时校验身份，后续操作验证归属                                                                                                                                                                   |
| 跨用户访问拦截     | 查询、操作语音数据时校验归属，仅允许操作本人数据                                                                                                                                                                                  |

### 音频安全

| 防护项       | 说明                                                                                                                                                                                                                        |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 音频格式校验 | 流式 ASR 仅接受 16kHz/16bit/mono PCM，离线 ASR 仅接受 WAV/PCM，非合规格式拒绝处理；裸 PCM 校验偶数字节（16bit 对齐）并按常见二进制魔数（PNG/JPEG/PDF/ZIP/MP3/OGG 等）拒绝伪装音频文件，防止垃圾输入占用推理线程池并被误扣费 |
| 时长限制     | 单次录音最长 60 秒（`voice.asr.max-duration`）；结束方式为客户端 `EOS` / 时长上限 / WS 接收空闲 60s 兜底                                                                                                                    |
| 文件大小限制 | 离线 ASR 上传音频大小由文件管理模块统一控制                                                                                                                                                                                 |
| 音频不落盘   | ASR 音频在编排侧与服务侧均为流式处理，处理完即弃，不持久化原始音频                                                                                                                                                          |
| 传输加密     | 前端 ↔ 业务后端经 HTTPS/WSS；业务后端 ↔ clarity-voice 为内网调用（同机部署用 HTTP/WS，跨机部署须启用 HTTPS/WSS）                                                                                                             |
| 缓存加密     | TTS 缓存音频经 AES 加密存储，防止缓存文件被直接读取                                                                                                                                                                         |

### ASR 安全

| 防护项       | 说明                                                                                           |
| ------------ | ---------------------------------------------------------------------------------------------- |
| 热词注入安全 | 热词由管理员、用户配置，存储前转义（`html.escape`）、下发服务前校验内容合法性，防止注入恶意热词 |


## 模块间协作

### 与 AI 对话模块

| 集成点   | 说明                                                                  |
| -------- | --------------------------------------------------------------------- |
| 语音输入 | ASR 文本传入 MessageService 的消息输入管道，由 LLM 统一理解意图并执行 |

### 与 AI 计费管理

| 能力 | 计费维度         | bill_type | billing_unit         | 挂接点                                                                                                                                                     |
| ---- | ---------------- | --------- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ASR  | 按音频时长（秒） | `asr`     | `second`             | 流式：按编排侧累计已收字节折算秒数（向上取整）在会话终态实扣，与服务是否成功返回最终文本解耦（服务断连时用最后一次增量文本）；离线：按上传音频字节折算 |
| TTS  | 按合成文本字符数 | `tts`     | `ten_thousand_chars` | TTS 合成完成时按实际合成字符数计量                                                                                                                         |

调用前校验用户余额与限额，不足时拒绝并提示；单价读模型价格表（`sys_ai_model_price`，`billing_unit` 维度化）。计费记录 `model` 记实际模型标识、`provider_id` 记供应商标识，供运营按模型、供应商对账。

未配置价格（无生效价格版本，或价格版本只有 token 档而无 `unit` 档）为不阻断调用 + 计 0 积分 + 仍落计费行（`credits=0` / `quantity` 照记，由管理端补齐价格），可观测三件套（实现见 `app/service/billing/unit_billing.py`，与图像按张计费共用）：

| 观测面 | 形态 |
| ------ | ---- |
| 日志 | WARNING「模型未配置价格，本次不计费」，带 `model_id` / `provider_id` / `bill_type` / `billing_unit` / `raw_quantity` |
| 指标 | `dehaze_voice_unpriced_total{model_type}`（`model_type` 取计费类型：asr / tts / image，`unit_billing` 共用路径统一计数） |
| 对账特征 | `bill_type IN ('asr','tts') AND quantity>0 AND credits=0` |

未配置与显式 0 价（内置免费模型）不同：后者 `configured=true`、不计入上述指标。

未定价不得在计费行写标记：`sys_ai_billing.error_code` 的语义是"调用失败错误码（成功为 NULL）"，写入 `no_price` 之类配置状态会把成功计费行标成失败、制造静默错账。未定价的可观测性只走上表三件套。


## 三端部署形态（代理转发）

本模块是唯一不以三端独立实现为形态的模块：ASR（FunASR）、TTS（Piper）推理由独立服务 `clarity-service/clarity-voice`（8993）承担，模型与推理依赖只随该服务分发，java/go 无等价实现。因此：

| 端            | 形态                                                                         | 落地位置                                                                   |
| ------------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| clarity-python | 唯一业务实现（编排：会话、并发、超时、计费、热词，服务经统一适配器远端调用） | `app/router/voice.py`（含 `/ws/asr`）、`app/service/voice/`                |
| clarity-go     | 纯转发（`/api/v1/voice/**` + `/ws/asr`）                                     | `internal/router/voice_proxy.go`、`pkg/aiclient`                           |
| clarity-java   | 纯转发（`/api/v1/voice/**` + `/ws/asr`）                                     | `AiProxyRoutes` 白名单、`VoiceAsrWebSocketConfig` + `VoiceAsrProxyHandler` |

不部署 `clarity-voice` 的部署置 `VOICE_LOCAL_ENABLED=false`：执行 `init-builtin` 时不初始化 `local-voice` 供应商与本地语音模型，并禁用已有供应商行，ASR/TTS 全部由云厂商模型提供，管理端需指定默认模型（dict `ai_model.default_model.asr/.tts`）。

转发面契约：

| 形态       | 端点示例                                 | 转发要求                                                                        |
| ---------- | ---------------------------------------- | ------------------------------------------------------------------------------- |
| JSON       | `POST /api/v1/voice/tts`、热词 CRUD      | 请求体与响应体原样透传，不做字段解包                                            |
| multipart  | `POST /api/v1/voice/asr/offline`         | 音频文件按原始字节流转发，保留 boundary（java 侧须跳过 Spring multipart 解析）  |
| 二进制响应 | `GET /api/v1/voice/tts/audio/{cacheKey}` | 音频字节与 `Content-Type`/`Content-Disposition` 原样回传，禁止当 JSON 解包      |
| WebSocket  | `/ws/asr`                                | 双向帧透传（二进制 PCM / 文本 `EOS` / 文本 JSON），不改帧类型、不解析应用层协议 |

转发侧的鉴权与身份：

- HTTP 端点的鉴权与权限（`voice:hotword:edit` / `voice:service:monitor`）不在转发侧重复实现，Go/Java 只透传 `Authorization` / `Cookie` / `X-Session-Id` 等身份头，由 python 终审；三端共享 Redis session，python 鉴权零改动。
- `/ws/asr` 的登录凭证随 query 的 `sid` 传递（浏览器 WS 握手无法携带自定义头），转发必须原样保留 query；转发侧不拦鉴权（Go 不在鉴权中间件内注册该路径，Java 在 `SecurityConfig` 与 `AuthenticationFilter` 放行），由 python 校验 `sid` 是否有效且与 ASR 会话归属一致。
- Java 转发 `/ws/asr` 时映射 order 必须严格小于 STOMP 端点：`@EnableWebSocketMessageBroker` 为 `/ws` 注册了 SockJS 通配 `/ws/**`，同序时 `/ws/asr` 会被 SockJS 抢先匹配并按非法 transport 报错。
- 首次连接 `/ws/asr` 不阻塞于引擎模型冷加载：编排侧建连时只建立服务会话（握手快速），模型预加载在服务侧进行，慢加载/首次下载仅延迟首个增量文本，转发侧握手超时按常规设置即可。

| 项             | 一致性要求                                                                                                                        |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 对外接口       | 三端对外暴露相同的 ASR/TTS HTTP 与 WebSocket 路径与报文契约（见 [API接口.md](./API接口.md)）；Go/Java 由转发保证形态一致          |
| ASR / TTS 逻辑 | 编排只有 python 一处实现，本地服务实现外置于 clarity-voice（经语音分派层，云厂商协议族见 [AI模型管理/后端实现.md](../AI模型管理/后端实现.md)） |
| 模型与供应商   | ASR/TTS 模型与供应商、API Key 统一存 `sys_ai_model`/`sys_ai_provider`/`sys_ai_provider_key`，三端共享同一份数据                   |
