## 架构设计

### 模块定位

收藏管理模块为系统提供统一的收藏能力基础设施。通过统一的 `sys_favorite` 表和通用接口为所有可收藏对象提供一致的收藏体验，替代各模块自行实现的独立收藏逻辑。

### 模块分层架构

| 层级          | 组件                                                                                | 职责                                                               |
| ------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| Controller 层 | FavoriteController（Java）、favorite router（Python）、favorite.go（Go）            | 收藏操作（添加、取消、列表、状态、计数）                           |
| Service 层    | FavoriteService                                                                     | 收藏核心服务（添加、取消、列表查询、状态查询、计数、容量校验、失效标记） |
| 数据层        | SysFavoriteMapper（Java）、favorite_repository（Python）、favorite_repository（Go） | `sys_favorite` 表数据访问                                          |

三端均基于统一 `sys_favorite` 表实现，Go 端无独立模型收藏表；表结构、业务逻辑与 API 契约一致（Java 权威，Go/Python 对齐）。

### 核心组件职责

| 组件            | 职责描述     | 关键能力                                                                                                            |
| --------------- | ------------ | ------------------------------------------------------------------------------------------------------------------- |
| FavoriteService | 收藏核心服务 | 添加、取消收藏、收藏列表分页查询（类型筛选、关键词搜索、时间排序）、收藏状态查询、收藏计数、会员容量校验、失效对象标记 |


## 数据模型设计

表结构权威定义详见 [03-数据库设计.md](../../../02-系统架构/03-数据库设计.md) 及 `config/sql/schema/sys_favorite.sql`。

### 统一收藏表（sys_favorite）

通过 `target_type` + `target_id` 实现多态收藏，支持 model/result/dataset/image/preset 五类对象，避免为每种收藏对象维护独立收藏表。`is_invalid` 标记收藏对象是否失效（对象删除时置 1）；`deleted` 为逻辑删除标识（取消收藏置 1，重新收藏时复活）。`(user_id, target_type, target_id)` 唯一约束保证收藏幂等，`(user_id, target_type, create_time)` 复合索引支撑按类型筛选的列表分页查询。

### 收藏对象类型

| 类型编码    | 类型名称 |    收藏校验    |    删除标记失效     |
| ----------- | -------- | :------------: | :-----------------: |
| `algorithm` | 模型     | 是（存在校验） | 是（模型删除时触发） |
| `result`    | 处理结果 | 是（存在校验） |          否          |
| `dataset`   | 数据集   | 是（存在校验） | 是（数据集删除时触发） |
| `image`     | 图片     | 否（预留跳过） |          否          |
| `preset`    | 参数方案 | 否（预留跳过） |          否          |


## 核心业务流程

### 添加收藏

| 步骤        | 说明                                                                                                 | 异常处理                                  |
| ----------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| 1. 类型校验 | targetType 必须为 algorithm/result/dataset/image/preset 五类之一，非法类型直接拒绝                   | `A0400` 参数错误                          |
| 2. 对象校验 | algorithm/dataset/result 类型校验目标存在（targetId 为空或对象不存在抛 A0401）                       | `A0401` 资源不存在                        |
| 3. 幂等短路 | 已存在未删除记录（同一用户 + 同一对象）直接返回原记录 ID，先于容量校验（重复收藏不因容量满而失败）   | 幂等成功                                  |
| 4. 容量校验 | 查询用户未删除收藏数，与会员等级对应上限比较（普通 200 / VIP1 500 / VIP2 1000 / SVIP 3000）          | 超限抛 `A0500`，提示"收藏已达上限（X条）" |
| 5. 写入收藏 | upsert：唯一键冲突时复活软删行（deleted=0、is_invalid=0、更新收藏时间），返回记录 ID                 | 幂等成功，无冲突错误                      |

三端均使用 `INSERT ... ON DUPLICATE KEY UPDATE` 实现 upsert（Java 经 MyBatis 注解 SQL + LAST_INSERT_ID 回填原行 id；Python 经 SQLAlchemy mysql insert 方言 + 冲突后重查回填；Go 经 GORM OnConflict 子句 + 冲突后重查回填），保证"取消后重新收藏"复活原记录而非新增。容量校验与 upsert 写入在同一事务内执行；并发下若他人先写入致当前用户收藏数超限，当前事务在写入前基于事务内可见计数复核容量，超限则回滚并抛 `A0500`。

### 取消收藏

| 步骤        | 说明                                                                    |
| ----------- | ----------------------------------------------------------------------- |
| 1. 逻辑删除 | 按记录 ID + 当前用户 ID 标记软删除（deleted 写为行 id；越权记录不生效） |
| 2. 幂等     | 重复取消不报错（更新 0 行静默成功）                                     |

### 收藏列表查询

| 步骤          | 说明                                                                                                                         |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 1. 分页查询   | 按 user_id + target_type（可选）分页，LEFT JOIN 业务表取对象名称                                                             |
| 2. 名称关联   | algorithm 取模型名称；dataset 取数据集名称；其余类型名称为空（SQL 层 CASE WHEN，JOIN 条件带 deleted=0，对象删除后名称为空）  |
| 3. 缩略图     | 仅 dataset 类型关联数据集缩略图；其余类型无                                                                                  |
| 4. 关键词过滤 | 按模型、数据集名称 LIKE 匹配（SQL 层）                                                                                       |
| 5. 排序       | 仅支持按收藏时间（create_time），默认倒序；`sortOrder=asc` 时正序，其余值倒序（`sortBy` 仅 `createTime` 有意义，其他值忽略） |

无按评分、使用频率排序：前端传入 rating/usageCount 时后端回退按时间排序。收藏对象摘要（targetSummary）字段预留但恒为空。

### 收藏状态查询

按 targetType + targetId 查询当前用户是否存在未删除记录，返回已收藏、未收藏状态（前端图标状态判断）。

### 收藏数量统计

按收藏类型分组统计当前用户各类型收藏数，固定返回五类（algorithm/result/dataset/image/preset，数量为 0 也返回），支持按单类型过滤。


## 会员容量阶梯

### 容量规则

| 会员等级 | 等级编码 | 收藏容量上限 |
| -------- | -------- | ------------ |
| 普通用户 | level_0  | 200 条       |
| VIP1     | level_1  | 500 条       |
| VIP2     | level_2  | 1000 条      |
| SVIP     | level_3  | 3000 条      |

### 容量校验

| 校验时机   | 校验逻辑                                     | 失败处理                     |
| ---------- | -------------------------------------------- | ---------------------------- |
| 收藏操作前 | 统计用户未删除收藏数，与会员等级对应上限比较 | 超限抛 `A0500`，引导升级会员 |

容量上限由字典配置维护，键与默认值见「配置项与常量」。


## 失效对象处理

### 失效标记（markInvalid）

| 触发场景                   | 触发方                         | 说明                            |
| -------------------------- | ------------------------------ | ------------------------------- |
| 模型被删除（含级联删除）   | AI模型管理模块删除模型时调用   | 相关收藏条目标记 `is_invalid=1` |
| 数据集被删除（含级联删除） | 数据集管理模块删除数据集时调用 | 相关收藏条目标记 `is_invalid=1` |

### 失效展示

收藏列表返回 `is_invalid` 字段，前端卡片展示"已失效"标签并禁用跳转；用户可手动取消收藏失效条目。

对象删除为逻辑删除，收藏记录保留，无物理级联删除；处理结果类型无失效标记；无一键清理失效的接口与按钮。

## 数据访问层设计

表结构与索引定义见 [03-数据库设计.md](../../../02-系统架构/03-数据库设计.md)。查询优化关注点：收藏列表按用户 + 类型 + 时间倒序分页查询；列表名称关联查询时过滤软删对象（deleted=0），保证对象删除后名称为空。

## 缓存策略

本模块不使用缓存：收藏状态与收藏列表均直接查库，列表分页实时关联业务表。

## 安全设计

### 数据隔离

| 操作          | 隔离规则                                       |
| ------------- | ---------------------------------------------- |
| 收藏、取消收藏 | WHERE 强制带 user_id，越权记录不生效           |
| 收藏列表查询  | 仅查询当前登录用户的收藏（user_id = 当前用户） |
| 收藏状态查询  | 仅查询当前用户对目标对象的收藏状态             |
| 收藏数量统计  | 仅统计当前用户的收藏数                         |

### 目标校验

| 收藏类型                                                 | 校验规则                    | 失败处理         |
| -------------------------------------------------------- | --------------------------- | ---------------- |
| 非 algorithm/result/dataset/image/preset 五类的值        | 非法 targetType 直接拒绝    | `A0400` 参数错误 |
| algorithm                                                | 校验模型存在（未删除）      | A0401 资源不存在 |
| dataset                                                  | 校验数据集存在（deleted=0） | A0401 资源不存在 |
| result                                                   | 校验处理结果存在            | A0401 资源不存在 |
| image / preset                                           | 预留类型，跳过校验          | -                |

### 幂等性

| 场景               | 处理方式                                            |
| ------------------ | --------------------------------------------------- |
| 重复收藏（已收藏） | 直接返回原记录 ID（先于容量校验的幂等短路）         |
| 重复取消（已取消） | 更新 0 行静默成功，不报错                           |
| 取消后重新收藏     | 原记录复活（deleted=0、is_invalid=0），收藏时间更新 |

幂等性通过 (user_id, target_type, target_id) 唯一约束加 upsert 机制保证，三端一致（均使用 `INSERT … ON DUPLICATE KEY UPDATE`）。

## 配置项与常量

### 收藏容量（sys_dict 配置）

各会员等级的收藏容量上限属于商业策略参数，运营有明确调整动机，统一由字典配置 `sys_dict`（字典类型 `favorite_capacity`）维护：

| 字典键    | 会员等级            | 默认值  |
| --------- | ------------------- | ------- |
| `default` | 普通用户（level_0） | 200 条  |
| `vip1`    | VIP1（level_1）     | 500 条  |
| `vip2`    | VIP2（level_2）     | 1000 条 |
| `svip`    | SVIP（level_3）     | 3000 条 |

运行时按用户当前会员等级读取对应字典键作为容量上限（升级后容量立即扩展）。

### 代码常量

| 常量         | 说明                                            | 值                                                                            |
| ------------ | ----------------------------------------------- | ----------------------------------------------------------------------------- |
| 收藏类型取值 | `algorithm`/`result`/`dataset`/`image`/`preset` | 仅用于收藏数量统计的零值补齐，Python 端内联于 `get_count_by_type`，不另设常量 |
