## 文档概述

该模块在 clarity-java（权威实现）、clarity-go、clarity-python 三端实现，逻辑保持一致。

- API 接口：[API接口.md](./API接口.md)
- 数据库设计：[03-数据库设计.md](../../../02-系统架构/03-数据库设计.md)


## 架构设计

### 模块分层架构

| 层级          | 组件                                                                              | 职责                                                                             |
| ------------- | --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Controller 层 | RecommendationController（Java）/ recommendation router（Go、Python）             | 路由与请求处理，路由清单见 [API接口.md](./API接口.md)                            |
| Service 层    | RecommendationServiceImpl / RecommendationService（单服务类承载全部逻辑）          | analyze、getModelRecommendations、submitFeedback、getRules、updateRule、getReport |

### 核心组件职责

| 组件                    | 职责描述     | 关键能力                                                                                   |
| ----------------------- | ------------ | ------------------------------------------------------------------------------------------ |
| analyze                 | 图像特征分析 | 校验 imageUrl 与扩展名；产出 7 维特征（确定性派生，非模型推理；三端实现口径见「图像特征分析的三端实现口径」） |
| getModelRecommendations | 模型推荐     | 已启用图像模型候选池、启用规则匹配、匹配度计算、推荐记录落库、回填 recommendationId        |
| submitFeedback          | 推荐反馈     | 按 recommendationId 校验推荐记录存在性与归属（仅本人）、写入 feedback（1 有用/2 无用）     |
| getRules/updateRule     | 规则管理     | 规则查询（weight 升序）、新增（query id=0）、更新、权重、场景类型、模型列表校验、内存缓存刷新 |
| getReport               | 效果度量     | 推荐总量、采纳率、满意度、覆盖率、冷启动成功率、按日趋势统计                                |


## 数据模型设计

表结构与字段定义详见 [03-数据库设计.md](../../../02-系统架构/03-数据库设计.md)。

### 推荐记录（sys_recommendation）

推荐记录只追加，不使用逻辑删除，过期数据由定时任务物理清理；`top_models` 与 `analysis_result` 用 JSON 存储，避免拆子表。写入时 `target_type` 固定为 `model`，`top_models` 记 Top 3（model/modelName/matchScore）；`image_md5` 记分析接口返回的图像 MD5，三端均为图像 URL 的 MD5（Java 由 Python 端点计算返回，Go/Python 本端计算）；`feedback` 取 0（未反馈）、1（有用）、2（无用）；`analysis_result` 与 `model_id` 不写入；`user_id` 取当前登录用户，未登录时回退系统用户。

### 推荐规则（sys_recommendation_rule）

`enabled` 为运行时启用、禁用开关（1 启用、0 禁用）；`deleted` 为逻辑删除标记，三端查询均过滤 `deleted = 0`。模块只暴露启用、禁用（enabled），未暴露显式删除规则的接口。


## 核心业务流程

### 图像特征分析（analyze）

1. 接收 AnalyzeForm（imageId / imageUrl）。
2. resolveImageUrl：`imageId > 0` 抛业务异常"imageId方式暂不支持，请使用imageUrl"（A0401）；`imageUrl` 为空抛参数错误（A0400）。
3. validateImageFormat：校验扩展名（合法扩展名见配置项，忽略 query string），不合法抛 A0701 文件格式不支持。
4. 按各端口径产出 7 维特征（确定性派生，三端实现方式见「图像特征分析的三端实现口径」）。
5. 映射为 ImageFeatureAnalysisVO 返回（imageMd5 等 7 维特征）。

### 模型推荐（getModelRecommendations）

输入 `analysisId` 或 `imageMd5`，依次执行：

1. 候选池：已启用图像模型（`status=1`）。
2. 启用规则：Java/Go 从内存缓存加载启用规则（`enabled=1` 且 `deleted=0`，缓存为空时回源并回填）；Python 实时查询。
3. 场景确定：`analysisId > 0` 时查推荐记录的 `analysis_result.sceneType`；传 `imageMd5` 时查最近推荐记录的 `analysis_result.sceneType`；两者均落空则默认 `urban`。
4. 规则匹配：`scene_type` 相同，按 `weight` 降序，聚合 `model_ids` 候选集。
5. 候选过滤：候选集与已启用图像模型求交集。
6. 匹配度：该模型在匹配规则中的最高权重，取 `min(100, maxWeight)`。
7. 构建 VO：model/modelName/matchScore/reason/effectDescription（文案模板见 [需求规格.md](./需求规格.md)）；rating 与 estimatedTime 置 null，无真实评分与耗时数据源。
8. 排序：matchScore 降序，同分按 model 升序（跨端排序一致性），截取 TOP_N（3）。
9. 落库：写入 `sys_recommendation`（`target_type="model"`、`top_models`、`feedback=0`）。
10. 回填 recommendationId 到各 VO。

每次调用均写入新记录（非幂等）。同用户、同 imageMd5 短时间内的重复请求会产生多条推荐记录，需由调用方防抖去重，避免重复落库。

### 推荐反馈（submitFeedback）

1. 接收 recommendationId 与 useful。
2. 按 recommendationId 查询推荐记录，不存在或非本人（`rec.user_id != 当前用户`）时抛 A0401，不泄露存在性。
3. `feedback = useful ? 1 : 2`，更新记录。

三端均按 recommendationId 校验记录存在性与归属（仅本人可反馈本人产生的推荐记录），无按 model 回退匹配的兜底逻辑。

### 规则管理（getRules / updateRule）

**getRules**：查询全部规则（`deleted=0`），按 weight 升序返回。

**updateRule**：`PUT /rules?id=<ruleId>`，`id` 通过 query 传递，0 表示新增（三端契约一致）。`id` 为 0 时新增（ruleName/sceneType/modelIds/weight/enabled）；非 0 时更新，规则不存在抛 A0401。参数校验均为 A0400：权重为 null 或小于 0 或大于 100 报"规则权重必须在0-100之间"（Python 端由表单 schema 拦截）；场景类型不在 urban/landscape/building/night/backlight/indoor 内报参数错误；modelIds 为空报参数错误。防重校验返回 A0501：同场景（sceneType）下已存在相同模型集合（modelIds 顺序无关比对）的规则时拒绝保存，新增与更新均校验，更新时排除自身。Java/Go 端在新增/更新后刷新内存规则缓存，Python 端无缓存无需刷新。

### 效果报表（getReport）

输入 `startDate` / `endDate`（`yyyy-MM-dd`，可空；格式非法抛 A0400），统计以下口径：

| 统计量            | 计算方式                                                                  |
| ----------------- | ------------------------------------------------------------------------- |
| totalRecommendations | 全部推荐记录条数                                                       |
| recommendedPredCount | `sys_pred_log` 中 `recommended_by IS NOT NULL` 的图像任务记录数（带推荐来源，三端 predict 落库） |
| usefulCount       | `feedback=1` 的条数                                                       |
| feedbackTotal     | `feedback!=0` 的条数                                                      |
| adoptedDistinct   | `COUNT(DISTINCT model_id)`，恒 0                                          |
| publishedCount    | 已启用图像模型数                                                          |

指标计算：`adoptionRate = recommendedPredCount / totalRecommendations`（采纳口径为用户从推荐入口真正发起去雾处理的比例，无推荐记录则 0）；`satisfactionRate = usefulCount / feedbackTotal`（有用反馈占比，无反馈则 0）；`coverageRate = adoptedDistinct / publishedCount`（恒 0）；`coldStartSuccessRate = 0.0`；`trend` 为按日采纳率（当日 recommendedPredCount / 当日 totalRecommendations）。


## 推荐策略

### 冷启动策略

无冷启动机制：新模型通过规则配置加入候选集后即可被推荐。

### 推荐结果字段

| 字段              | 值                              | 说明                         |
| ----------------- | ------------------------------- | ---------------------------- |
| rating            | null                            | 无真实评分数据源             |
| estimatedTime     | null                            | 无真实处理耗时数据源（毫秒） |
| effectDescription | "该模型在{scene}场景下表现稳定" | 模板                         |


## 模块间协作

### 与AI模型管理模块的集成

| 调用场景           | 说明                               |
| ------------------ | ---------------------------------- |
| 已启用图像模型列表 | 获取 status=1 的模型作为推荐候选池 |
| 模型名称           | 推荐结果展示模型名称               |

排序仅基于规则权重，不聚合 `sys_rating` 评分与 `sys_pred_log` 处理成功率。

### 图像特征分析的三端实现口径

特征分析是零模型的确定性派生：以图像 URL 的 MD5 为种子取模生成各维取值，不读取图像内容、不加载模型、不占 GPU，三端产出逐字段一致。

| 端     | 实现方式              | 说明                                                                                                                                                                                                        |
| ------ | --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Java   | HTTP 调用 Python 端点 | `RecommendationServiceImpl.analyze` 通过 `PythonAlgorithmClient.analyzeImage` 调用 `POST /api/v1/recommendations/analyze`，复用模型服务 HTTP 客户端的重试、熔断、幂等机制；服务不可用时抛业务异常，不做本端兜底 |
| Go     | 本端复刻同一模型      | `RecommendationService.Analyze` 调用 `pkg/algorithm.AnalyzeImage`（与 Python 逐位对齐，有单测对齐）；不经 Python 端点，该端点要求用户态鉴权，内部调用必然 A0230                                             |
| Python | 本端实现              | `recommendation_service.analyze`：同一 URL 的特征跨进程、跨重启稳定                                                                                                                                        |

该能力不属 AI 推理，也不随推理能力服务拆分外置（[AI 能力链路协作设计](../../../02-系统架构/09-AI能力链路协作设计.md)）。


## 推荐效果度量

指标定义与目标值见 [需求规格.md](./需求规格.md)。

| 指标         | 计算方式                                                        |
| ------------ | --------------------------------------------------------------- |
| 推荐采纳率   | usefulCount / feedbackTotal（无反馈为 0），以"有用"反馈近似采纳 |
| 推荐满意度   | 等于采纳率                                                      |
| 推荐覆盖率   | adoptedDistinct / publishedCount（采纳未落库，恒 0）            |
| 冷启动成功率 | 0.0（无冷启动机制）                                             |
| 趋势         | 按日采纳率（date + adoptionRate）                               |


## 缓存设计

| 缓存对象              | 实现                                                                         | 更新策略              |
| --------------------- | ---------------------------------------------------------------------------- | --------------------- |
| 启用规则（Java 端）   | `CopyOnWriteArrayList` 内存缓存（enabled=1 且 deleted=0）                    | updateRule 后全量刷新 |
| 启用规则（Go 端）     | `ruleCache` 切片 + `sync.RWMutex` 内存缓存，读时双检（缓存为空则回源并回填） | updateRule 后全量刷新 |
| 启用规则（Python 端） | 无缓存，实时查询                                                             | -                     |

推荐结果与规则配置不使用 Redis 缓存。
