# 角色管理模块

## 1. 概述

### 1.1 文档目的
本文档详细描述图像去雾系统角色管理模块的代码设计，包括架构设计、模块划分、接口定义、数据结构和关键算法等技术实现细节。

### 1.2 适用范围
本文档适用于角色管理模块的后端和前端开发人员，为代码实现提供技术指导和参考。

### 1.3 架构设计
本文档遵循《总体系统架构文档》中定义的分层架构设计原则，采用前后端分离的架构模式。

## 2. 技术架构设计

### 2.1 整体架构
角色管理模块采用前后端分离的架构设计：
- 后端：基于Spring Boot的RESTful API服务
- 前端：基于Vue3 + Element Plus的单页应用

### 2.2 后端分层架构
```
Controller层 (SysRoleController)
    ↓
Service层 (SysRoleService)
    ↓
Mapper层 (SysRoleMapper)
    ↓
数据库 (MySQL)
```

### 2.3 前端架构
```

    ↓
API调用层 (dehaze-sdk-js)
    ↓

```

## 3. 后端详细设计

### 3.1 控制层设计 (SysRoleController)

#### 3.1.1 类结构
```java
@RestController
@RequestMapping("/api/v1/roles")
@RequiredArgsConstructor
@Tag(name = "04.角色接口")
public class SysRoleController {
    private final SysRoleService roleService;
}
```

#### 3.1.2 接口设计

| 接口URL | 请求方法 | 功能描述 | 权限控制 |
|---------|---------|---------|---------|
| /api/v1/roles/page | GET | 获取角色分页列表 | 无特殊权限 |
| /api/v1/roles/options | GET | 获取角色下拉列表 | 无特殊权限 |
| /api/v1/roles | POST | 新增角色 | @PreAuthorize("@ss.hasPerm('sys:role:add')") |
| /api/v1/roles/{roleId}/form | GET | 获取角色表单数据 | 无特殊权限 |
| /api/v1/roles/{id} | PUT | 修改角色 | @PreAuthorize("@ss.hasPerm('sys:role:edit')") |
| /api/v1/roles/{ids} | DELETE | 删除角色 | @PreAuthorize("@ss.hasPerm('sys:role:delete')") |
| /api/v1/roles/{roleId}/status | PUT | 修改角色状态 | @PreAuthorize("@ss.hasPerm('sys:role:edit')") |
| /api/v1/roles/{roleId}/menuIds | GET | 获取角色的菜单ID集合 | 无特殊权限 |
| /api/v1/roles/{roleId}/menus | PUT | 分配菜单权限给角色 | @PreAuthorize("@ss.hasPerm('sys:role:edit')") |

#### 3.1.3 关键注解说明
- `@PreAuthorize`：Spring Security权限控制注解，用于方法级别的权限验证
- `@Valid`/`@Validated`：用于请求参数校验

### 3.2 服务层设计 (SysRoleService)

#### 3.2.1 接口定义
```java
public interface SysRoleService extends IService<SysRole> {
    // 分页查询角色列表
    IPage<SysRole> getRolePage(RolePageQuery queryParams);
    
    // 获取角色下拉选项
    List<OptionVO> listRoleOptions();
    
    // 保存角色（新增或更新）
    boolean saveRole(RoleForm roleForm);
    
    // 获取角色表单数据
    RoleForm getRoleForm(Long roleId);
    
    // 更新角色状态
    boolean updateRoleStatus(Long roleId, Integer status);
    
    // 删除角色
    boolean deleteRoles(String ids);
    
    // 获取角色拥有的菜单ID集合
    List<Long> getRoleMenuIds(Long roleId);
    
    // 为角色分配菜单权限
    boolean assignMenusToRole(Long roleId, List<Long> menuIds);
    
    // 获取最大范围的数据权限
    Integer getMaximumDataScope(Set<Long> roleIds);
}
```

#### 3.2.2 核心业务逻辑

##### 角色权限分配
- 支持为角色分配菜单权限（包括按钮权限）
- 通过角色ID和菜单ID集合进行权限关联

##### 数据权限控制
- 根据角色的数据权限范围控制用户可访问的数据范围
- 支持多种数据权限模式：全部数据、部门数据、个人数据等

##### 角色删除逻辑
- 检查角色是否存在关联用户
- 支持批量删除角色

## 5. 数据库设计

### 5.1 角色表 (sys_role)
```sql
CREATE TABLE `sys_role` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '角色ID',
  `name` varchar(64) NOT NULL COMMENT '角色名称',
  `code` varchar(32) NOT NULL COMMENT '角色编码',
  `data_scope` tinyint NOT NULL DEFAULT '2' COMMENT '数据权限范围(0:全部数据;1:部门及子部门数据;2:本部门数据;3:本人数据)',
  `status` tinyint NOT NULL DEFAULT '1' COMMENT '角色状态(1:启用;0:禁用)',
  `sort` int NOT NULL DEFAULT '1' COMMENT '排序',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_code` (`code`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='角色表';
```

### 5.2 角色菜单关联表 (sys_role_menu)
```sql
CREATE TABLE `sys_role_menu` (
  `role_id` bigint NOT NULL COMMENT '角色ID',
  `menu_id` bigint NOT NULL COMMENT '菜单ID',
  PRIMARY KEY (`role_id`, `menu_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='角色菜单关联表';
```

### 5.3 索引设计
- 主键索引：角色表id字段，角色菜单关联表(role_id, menu_id)组合索引
- 唯一索引：角色表code字段，确保角色编码唯一性
- 普通索引：角色表status字段，优化状态查询性能

## 6. 关键算法设计

### 6.1 分页查询算法
采用MyBatis-Plus提供的分页插件实现分页查询功能，通过IPage接口封装分页结果。

### 6.2 权限分配算法
使用角色菜单关联表实现权限分配：
1. 删除角色原有的菜单权限关联记录
2. 插入新的菜单权限关联记录

### 6.3 数据权限算法
通过数据权限范围字段控制用户可访问的数据范围：
1. 全部数据：不限制数据访问范围
2. 部门及子部门数据：只能访问所在部门及其子部门的数据
3. 本部门数据：只能访问所在部门的数据
4. 本人数据：只能访问自己的数据
