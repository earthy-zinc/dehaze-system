# 部门管理模块代码详细设计文档

## 1. 概述

### 1.1 文档目的
本文档详细描述图像去雾系统部门管理模块的代码设计，包括架构设计、模块划分、接口定义、数据结构和关键算法等技术实现细节。

### 1.2 适用范围
本文档适用于部门管理模块的后端和前端开发人员，为代码实现提供技术指导和参考。

### 1.3 架构设计
本文档遵循《总体系统架构文档》中定义的分层架构设计原则，采用前后端分离的架构模式。

## 2. 技术架构设计

### 2.1 整体架构
部门管理模块采用前后端分离的架构设计：
- 后端：基于Spring Boot的RESTful API服务
- 前端：基于Vue3 + Element Plus的单页应用

### 2.2 后端分层架构
```
Controller层 (SysDeptController)
    ↓
Service层 (SysDeptService)
    ↓
Mapper层 (SysDeptMapper)
    ↓
数据库 (MySQL)
```

### 2.3 前端架构
```
页面组件 (index.vue)
    ↓
API调用层 (dehaze-sdk-js)
    ↓
状态管理 (Vuex/Pinia)
    ↓
UI组件 (Element Plus)
```

## 3. 后端详细设计

### 3.1 控制层设计 (SysDeptController)

#### 3.1.1 类结构
```java
@RestController
@RequestMapping("/api/v1/dept")
@RequiredArgsConstructor
@Tag(name = "03.部门接口")
public class SysDeptController {
    private final SysDeptService deptService;
}
```

#### 3.1.2 接口设计

| 接口URL | 请求方法 | 功能描述 | 权限控制 |
|---------|---------|---------|---------|
| /api/v1/dept | GET | 获取部门列表 | 无特殊权限 |
| /api/v1/dept/options | GET | 获取部门下拉选项 | 无特殊权限 |
| /api/v1/dept/{deptId}/form | GET | 获取部门表单数据 | 无特殊权限 |
| /api/v1/dept | POST | 新增部门 | @PreAuthorize("@ss.hasPerm('sys:dept:add')") |
| /api/v1/dept/{deptId} | PUT | 修改部门 | @PreAuthorize("@ss.hasPerm('sys:dept:edit')") |
| /api/v1/dept/{ids} | DELETE | 删除部门 | @PreAuthorize("@ss.hasPerm('sys:dept:delete')") |

#### 3.1.3 关键注解说明
- `@PreAuthorize`：Spring Security权限控制注解，用于方法级别的权限验证
- `@Valid`/`@Validated`：用于请求参数校验

### 3.2 服务层设计 (SysDeptService)

#### 3.2.1 接口定义
```java
public interface SysDeptService extends IService<SysDept> {
    // 查询部门列表
    List<SysDept> listDepartments(String name, Integer status);
    
    // 获取部门下拉选项
    List<OptionVO> listDeptOptions();

    boolean saveDept(DeptForm deptForm);
    
    // 更新部门信息

    // 删除部门

    // 获取部门表单数据

}
```

#### 3.2.2 核心业务逻辑

##### 部门树构建
- 通过递归算法构建部门树形结构

##### 部门删除逻辑
- 检查部门是否存在关联用户
- 支持批量删除部门

## 5. 数据库设计

### 5.1 部门表 (sys_dept)
```sql
CREATE TABLE `sys_dept` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '部门ID',
  `name` varchar(64) NOT NULL COMMENT '部门名称',
  `parent_id` bigint NOT NULL DEFAULT '0' COMMENT '父级部门ID',
  `sort` int NOT NULL DEFAULT '1' COMMENT '排序',
  `status` tinyint NOT NULL DEFAULT '1' COMMENT '部门状态(1:启用;0:禁用)',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='部门表';
```

### 5.2 索引设计
- 主键索引：id字段
- 普通索引：parent_id字段，优化树形查询性能

## 6. 关键算法设计

### 6.1 部门树构建算法
通过递归算法构建部门树形结构：
1. 查询所有部门数据
2. 根据parent_id字段构建父子关系
3. 递归构建完整的树形结构

### 6.2 部门删除检查算法
在删除部门前检查是否存在关联用户：
1. 查询该部门及其子部门下的所有用户
2. 如存在关联用户，则禁止删除并提示错误信息
