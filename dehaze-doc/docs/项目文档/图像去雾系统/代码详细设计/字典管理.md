# 字典管理模块代码详细设计文档

## 1. 概述

### 1.1 文档目的
本文档详细描述图像去雾系统字典管理模块的代码设计，包括架构设计、模块划分、接口定义、数据结构和关键算法等技术实现细节。

### 1.2 适用范围
本文档适用于字典管理模块的后端和前端开发人员，为代码实现提供技术指导和参考。

### 1.3 架构设计
本文档遵循《总体系统架构文档》中定义的分层架构设计原则，采用前后端分离的架构模式。

## 2. 技术架构设计

### 2.1 整体架构
字典管理模块采用前后端分离的架构设计：
- 后端：基于Spring Boot的RESTful API服务
- 前端：基于Vue3 + Element Plus的单页应用

### 2.2 后端分层架构
```
Controller层 (SysDictController)
    ↓
Service层 (SysDictService, SysDictTypeService)
    ↓
Mapper层 (SysDictMapper, SysDictTypeMapper)
    ↓
数据库 (MySQL)
```

### 2.3 前端架构
```
页面组件 (index.vue, dict-item.vue)
    ↓
API调用层 (dehaze-sdk-js)
    ↓
状态管理 (Vuex/Pinia)
    ↓
UI组件 (Element Plus)
```

### 3.1 控制层设计 (SysDictController)

#### 3.1.1 类结构

#### 3.1.2 接口设计

| 接口URL | 请求方法 | 功能描述 | 权限控制 |
|---------|---------|---------|---------|
| /api/v1/dict/page | GET | 获取字典分页列表 | 无特殊权限 |
| /api/v1/dict/{id}/form | GET | 获取字典表单数据 | 无特殊权限 |
| /api/v1/dict | POST | 新增字典 | @PreAuthorize("@ss.hasPerm('sys:dict:data:add')") |
| /api/v1/dict/{id} | PUT | 修改字典 | @PreAuthorize("@ss.hasPerm('sys:dict:data:edit')") |
| /api/v1/dict/{ids} | DELETE | 删除字典 | @PreAuthorize("@ss.hasPerm('sys:dict:data:delete')") |
| /api/v1/dict/{typeCode}/options | GET | 获取字典下拉列表 | 无特殊权限 |
| /api/v1/dict/types/page | GET | 获取字典类型分页列表 | 无特殊权限 |
| /api/v1/dict/types/{id}/form | GET | 获取字典类型表单数据 | 无特殊权限 |
| /api/v1/dict/types | POST | 新增字典类型 | @PreAuthorize("@ss.hasPerm('sys:dict:type:add')") |
| /api/v1/dict/types/{id} | PUT | 修改字典类型 | @PreAuthorize("@ss.hasPerm('sys:dict:type:edit')") |
| /api/v1/dict/types/{ids} | DELETE | 删除字典类型 | @PreAuthorize("@ss.hasPerm('sys:dict:type:delete')") |

#### 3.1.3 关键注解说明
- `@PreAuthorize`：Spring Security权限控制注解，用于方法级别的权限验证
- `@Valid`/`@Validated`：用于请求参数校验

## 5. 数据库设计

### 5.1 字典数据表 (sys_dict)
```sql
CREATE TABLE `sys_dict` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '字典ID',
  `name` varchar(64) NOT NULL COMMENT '字典标签',
  `value` varchar(64) NOT NULL COMMENT '字典键值',
  `type_code` varchar(32) NOT NULL COMMENT '字典类型编码',
  `css_class` varchar(128) DEFAULT NULL COMMENT '样式属性',
  `sort` int NOT NULL DEFAULT '1' COMMENT '字典排序',
  `status` tinyint NOT NULL DEFAULT '1' COMMENT '状态(1:启用;0:禁用)',
  `remark` varchar(255) DEFAULT NULL COMMENT '备注',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  KEY `idx_type_code` (`type_code`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='字典数据表';
```

### 5.2 字典类型表 (sys_dict_type)
```sql
CREATE TABLE `sys_dict_type` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '字典类型ID',
  `name` varchar(64) NOT NULL COMMENT '字典名称',
  `code` varchar(32) NOT NULL COMMENT '字典编码',
  `status` tinyint NOT NULL DEFAULT '1' COMMENT '状态(1:启用;0:禁用)',
  `remark` varchar(255) DEFAULT NULL COMMENT '备注',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_code` (`code`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='字典类型表';
```

### 5.3 索引设计
- 主键索引：字典数据表id字段，字典类型表id字段
- 唯一索引：字典类型表code字段，确保字典类型编码唯一性
- 普通索引：字典数据表type_code字段，优化按类型查询性能

## 6. 关键算法设计

### 6.1 分页查询算法
采用MyBatis-Plus提供的分页插件实现分页查询功能，通过IPage接口封装分页结果。

### 6.2 字典类型删除检查算法
在删除字典类型前检查是否存在关联的字典数据：
1. 查询该字典类型下的所有字典数据
2. 如存在字典数据，则禁止删除并提示错误信息

### 6.3 字典下拉选项构建算法
根据字典类型编码查询对应的字典数据并构建成下拉选项：
1. 根据type_code查询启用状态的字典数据
2. 按sort字段排序
3. 构建成OptionVO对象列表
