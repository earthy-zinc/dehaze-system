### 数据库迁移脚本

```sql
-- V2.1__add_task_table.sql
CREATE TABLE sys_task (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    task_id VARCHAR(64) NOT NULL UNIQUE COMMENT '任务ID（UUID）',
    task_type VARCHAR(32) NOT NULL COMMENT '任务类型',
    status VARCHAR(16) NOT NULL COMMENT '任务状态',
    progress INT DEFAULT 0 COMMENT '进度',
    total_files INT COMMENT '总文件数',
    processed_files INT DEFAULT 0 COMMENT '已处理文件数',
    params JSON COMMENT '任务参数',
    result JSON COMMENT '任务结果',
    error_message TEXT COMMENT '错误信息',
    created_by BIGINT COMMENT '创建人',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    started_at DATETIME COMMENT '开始时间',
    completed_at DATETIME COMMENT '完成时间',
    expires_at DATETIME COMMENT '过期时间',
    INDEX idx_task_id (task_id),
    INDEX idx_status_created (status, created_at),
    INDEX idx_expires (expires_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT '异步任务表';

-- 新增 Mapper 方法所需字段
ALTER TABLE sys_item_file ADD COLUMN thumbnail_path VARCHAR(512) COMMENT '缩略图路径（冗余字段）';
ALTER TABLE sys_file MODIFY COLUMN size BIGINT COMMENT '文件大小（字节）';
```

## 监控与告警

### 关键监控指标

| 指标       | 类型  | 告警阈值     | 监控方式                 |
|----------|-----|----------|----------------------|
| 上传接口响应时间 | P99 | > 1s     | Prometheus + Grafana |
| 异步任务失败率  | 百分比 | > 5%     | 日志统计                 |
| 缓存命中率    | 百分比 | < 80%    | Redis Monitor        |
| 补偿任务重试次数 | 计数  | > 100/小时 | Redis 集合大小           |
| 任务清理延迟   | 时间  | > 2小时    | 定时任务执行日志             |

### 告警规则

```yaml
# Prometheus 告警规则示例
groups:
  - name: dataset_module
    rules:
      - alert: HighAsyncTaskFailureRate
        expr: rate(dataset_async_task_failures[5m]) > 0.05
        for: 10m
        annotations:
          summary: "异步任务失败率过高"
          
      - alert: LowCacheHitRate
        expr: rate(redis_cache_hits[5m]) / rate(redis_cache_requests[5m]) < 0.8
        for: 15m
        annotations:
          summary: "缓存命中率低"
```

## 总结

本方案通过三个核心 ADR 解决当前数据集模块的关键问题：

1. **ADR-001**：事务后事件机制解耦副作用，提升响应速度与容错能力
2. **ADR-002**：两级缓存策略优化统计与树查询，解决性能瓶颈
3. **ADR-003**：统一任务中心修复异步失效，建立任务生命周期管理

预计总工期 **12 天**，核心改造集中在前 5 天（P0+P1），可优先上线。所有改造均保持现有代码结构，不引入过度分层，确保可维护性与团队接受度。
