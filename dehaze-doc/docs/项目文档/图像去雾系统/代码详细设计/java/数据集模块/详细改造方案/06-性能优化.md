## 二、Top 1：统计计算无缓存

### 2.1 问题分析

**当前实现**（`SysDatasetServiceImpl.java`）：

```java
public DatasetVO getDatasetById(Long id) {
    // ... 查询数据集基本信息

    // 每次请求都计算统计
    DatasetStatistics stats = calculateStatistics(id);  // ❌ 无缓存

    vo.setStatistics(stats);
    return vo;
}

private DatasetStatistics calculateStatistics(Long datasetId) {
    // 1. 递归查子数据集（N+1 查询）
    List<Long> leafIds = getLeafDatasetIds(datasetId);

    // 2. 遍历每个叶子数据集查数据项
    for (Long leafId : leafIds) {
        List<SysDatasetItem> items = itemMapper.selectByDatasetId(leafId);
        // ...
    }

    // 3. 再查每个数据项的文件
    // ...
}
```

**性能问题**：

- 热点数据集（被列表接口频繁查询）每次都重新计算
- 查询链路：数据集 → 子数据集（递归）→ 数据项 → 文件 → 聚合统计
- 深度 3 层的数据集，单次查询可能触发 **10+ 次数据库查询**

### 2.2 优化方案

#### 方案 A：Redis 缓存（推荐）

**Redis Key 设计**：

```
dataset:stats:{datasetId}  → JSON 格式统计信息
TTL: 30 分钟
```

**缓存内容**：

```json
{
  "itemCount": 120,
  "fileCount": 450,
  "totalSize": 15360000000,
  "clearCount": 120,
  "hazyCount": 330,
  "sceneDistribution": {"outdoor": 280, "indoor": 170},
  "hazeDistribution": {"light": 150, "medium": 120, "heavy": 60},
  "formatDistribution": {"jpg": 400, "png": 50}
}
```

**更新策略**：
| 操作 | 缓存策略 | 触发方式 |
|------|---------|---------|
| 创建数据项 | 失效父数据集缓存 | 事务后事件 |
| 删除数据项 | 失效父数据集缓存 | 事务后事件 |
| 上传文件 | 失效数据集缓存 | 事务后事件 |
| 删除文件 | 失效数据集缓存 | 事务后事件 |
| 查询统计 | Cache-Aside | 查不到再计算 |

**实现代码**：

```java

@Service
@RequiredArgsConstructor
public class SysDatasetServiceImpl extends ServiceImpl<SysDatasetMapper, SysDataset>
        implements SysDatasetService {

    private final RedisTemplate<String, Object> redisTemplate;
    private final SysDatasetMapper datasetMapper;

    private static final String CACHE_KEY_STATS = "dataset:stats:";
    private static final Duration STATS_TTL = Duration.ofMinutes(30);

    @Override
    public DatasetStatistics getStatistics(Long datasetId) {
        String cacheKey = CACHE_KEY_STATS + datasetId;

        // 1. 尝试从缓存获取
        DatasetStatistics cached = (DatasetStatistics) redisTemplate.opsForValue().get(cacheKey);
        if (cached != null) {
            log.debug("统计信息命中缓存: datasetId={}", datasetId);
            return cached;
        }

        // 2. 缓存未命中，计算统计信息
        log.info("统计信息未命中缓存，开始计算: datasetId={}", datasetId);
        DatasetStatistics stats = calculateStatisticsFromDB(datasetId);

        // 3. 写入缓存
        redisTemplate.opsForValue().set(cacheKey, stats, STATS_TTL);

        return stats;
    }

    /**
     * 从数据库计算统计信息（优化后：一次聚合查询）
     */
    private DatasetStatistics calculateStatisticsFromDB(Long datasetId) {
        // 1. 获取叶子节点（使用优化后的方法，见 Top 2）
        Set<Long> leafIds = getLeafDatasetIdsOptimized(datasetId);

        // 2. 一次聚合查询完成统计
        return datasetMapper.aggregateStatistics(leafIds);
    }
}
```

**Mapper 聚合查询**：

```xml
<!-- SysDatasetMapper.xml -->
<select id="aggregateStatistics" resultType="com.pei.dehaze.model.vo.DatasetStatistics">
    SELECT
    COUNT(DISTINCT di.id) AS itemCount,
    COUNT(DISTINCT sif.id) AS fileCount,
    COALESCE(SUM(sf.size), 0) AS totalSize,
    SUM(CASE WHEN sif.type = 'clear' THEN 1 ELSE 0 END) AS clearCount,
    SUM(CASE WHEN sif.type = 'hazy' THEN 1 ELSE 0 END) AS hazyCount
    FROM sys_dataset_item di
    LEFT JOIN sys_item_file sif ON di.id = sif.item_id
    LEFT JOIN sys_file sf ON sif.file_id = sf.id
    WHERE di.dataset_id IN
    <foreach collection="datasetIds" item="id" open="(" separator="," close=")">
        #{id}
    </foreach>
</select>
```

**缓存失效**（事件驱动）：

```java

@Component
@RequiredArgsConstructor
public class DatasetEventHandler {

    private final RedisTemplate<String, Object> redisTemplate;

    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    public void handleCacheInvalidation(DatasetEvent.ItemFilesUploaded event) {
        // 失效当前数据集及所有祖先数据集的缓存
        invalidateStatsCache(event.getDatasetId());
    }

    private void invalidateStatsCache(Long datasetId) {
        // 失效当前数据集缓存
        redisTemplate.delete("dataset:stats:" + datasetId);

        // 失效父数据集缓存（递归向上）
        SysDataset dataset = datasetMapper.selectById(datasetId);
        if (dataset != null && dataset.getParentId() != null) {
            invalidateStatsCache(dataset.getParentId());
        }
    }
}
```

## 三、Top 2：叶子节点递归查库

### 3.1 问题分析

**当前实现**（`SysDatasetServiceImpl.java`）：

```java
private List<Long> getLeafDatasetIds(Long datasetId) {
    List<Long> leafIds = new ArrayList<>();

    // 查询子数据集
    List<SysDataset> children = this.list(
            new LambdaQueryWrapper<SysDataset>()
                    .eq(SysDataset::getParentId, datasetId)
    );

    if (children.isEmpty()) {
        // 叶子节点
        leafIds.add(datasetId);
    } else {
        // 递归查询每个子数据集
        for (SysDataset child : children) {
            leafIds.addAll(getLeafDatasetIds(child.getId()));  // ❌ N+1 查询
        }
    }

    return leafIds;
}
```

**性能问题**：

- 深度 5 层，每层 3 个子数据集 → 需要查询 **1 + 3 + 9 + 27 + 81 = 121 次**
- 每次查询都是新的 SQL，无法利用索引批量查询

### 3.2 优化方案

#### 方案 A：一次性查询 + 内存计算（推荐）

**实现代码**：

```java

@Service
@RequiredArgsConstructor
public class SysDatasetServiceImpl extends ServiceImpl<SysDatasetMapper, SysDataset>
        implements SysDatasetService {

    private final RedisTemplate<String, Object> redisTemplate;

    /**
     * 优化后的叶子节点计算（一次查询 + 内存 BFS）
     */
    public Set<Long> getLeafDatasetIdsOptimized(Long datasetId) {
        String cacheKey = "dataset:leaf:" + datasetId;

        // 1. 尝试从缓存获取
        Set<Long> cached = (Set<Long>) redisTemplate.opsForValue().get(cacheKey);
        if (cached != null) {
            return cached;
        }

        // 2. 一次性查询所有数据集
        List<SysDataset> allDatasets = this.list();

        // 3. 构建父子映射（Map<parentId, List<childId>>）
        Map<Long, List<Long>> parentToChildren = allDatasets.stream()
                .filter(d -> d.getParentId() != null)
                .collect(Collectors.groupingBy(
                        SysDataset::getParentId,
                        Collectors.mapping(SysDataset::getId, Collectors.toList())
                ));

        // 4. BFS 计算叶子节点
        Set<Long> leafIds = new HashSet<>();
        Queue<Long> queue = new LinkedList<>();
        queue.offer(datasetId);

        while (!queue.isEmpty()) {
            Long current = queue.poll();
            List<Long> children = parentToChildren.getOrDefault(current, Collections.emptyList());

            if (children.isEmpty()) {
                leafIds.add(current);  // 叶子节点
            } else {
                queue.addAll(children);  // 继续遍历子节点
            }
        }

        // 5. 写入缓存（TTL 1小时）
        redisTemplate.opsForValue().set(cacheKey, leafIds, Duration.ofHours(1));

        return leafIds;
    }
}
```

**缓存失效**：

```java

@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
public void handleTreeStructureChange(DatasetEvent.DatasetDeleted event) {
    // 删除所有叶子节点缓存
    Set<String> keys = redisTemplate.keys("dataset:leaf:*");
    if (keys != null && !keys.isEmpty()) {
        redisTemplate.delete(keys);
    }
}
```

## 四、Top 3：文件大小字符串存储

### 4.1 问题分析

**当前表结构**（`sys_file` 表）：

```sql
CREATE TABLE sys_file
(
    id   BIGINT PRIMARY KEY,
    size VARCHAR(50) COMMENT '文件大小（如 "1.2MB"）', -- ❌ 字符串存储
    -- ...
);
```

**当前搜索 SQL**（`SysDatasetMapper.xml`）：

```xml

<select id="searchDatasetItems" resultType="com.pei.dehaze.model.vo.DatasetItemVO">
    SELECT di.*, sf.size
    FROM sys_dataset_item di
    LEFT JOIN sys_item_file sif ON di.id = sif.item_id
    LEFT JOIN sys_file sf ON sif.file_id = sf.id
    WHERE 1=1
    <if test="minSize != null">
        AND CAST(REPLACE(REPLACE(sf.size, 'MB', ''), 'KB', '') AS DECIMAL(10,2)) >= #{minSize}
    </if>
    ORDER BY di.create_time DESC
</select>
```

**性能问题**：

- `REPLACE` + `CAST` 无法使用索引
- 每行都需要字符串清洗，全表扫描
- 排序需要临时表

### 4.2 优化方案

#### 字段类型改造

**SQL 迁移脚本**：

```sql
-- V2.2__optimize_file_size.sql

-- 1. 新增数值字段
ALTER TABLE sys_file
    ADD COLUMN size_bytes BIGINT COMMENT '文件大小（字节）';

-- 2. 数据迁移：将字符串转换为字节数
UPDATE sys_file
SET size_bytes = CASE
                     WHEN size LIKE '%MB' THEN CAST(REPLACE(size, 'MB', '') AS DECIMAL(10, 2)) * 1024 * 1024
                     WHEN size LIKE '%KB' THEN CAST(REPLACE(size, 'KB', '') AS DECIMAL(10, 2)) * 1024
                     WHEN size LIKE '%GB' THEN CAST(REPLACE(size, 'GB', '') AS DECIMAL(10, 2)) * 1024 * 1024 * 1024
                     ELSE 0
    END
WHERE size_bytes IS NULL;

-- 3. 添加索引
CREATE INDEX idx_size_bytes ON sys_file (size_bytes);

-- 4. 保留原字段用于展示（向后兼容）
-- 后续可在应用层废弃 size 字段
```

**实体类改造**：

```java

@Data
@TableName("sys_file")
public class SysFile implements Serializable {

    private Long id;

    /**
     * 文件大小（字节）
     * 用于筛选、排序、统计
     */
    private Long sizeBytes;

    /**
     * 文件大小（格式化字符串，仅用于展示）
     * @deprecated 建议使用 sizeBytes 并在前端格式化
     */
    @Deprecated
    private String size;

    /**
     * 获取格式化的文件大小（用于VO展示）
     */
    @TableField(exist = false)
    public String getFormattedSize() {
        if (sizeBytes == null) return "0B";

        if (sizeBytes < 1024) return sizeBytes + "B";
        if (sizeBytes < 1024 * 1024) return String.format("%.2fKB", sizeBytes / 1024.0);
        if (sizeBytes < 1024 * 1024 * 1024) return String.format("%.2fMB", sizeBytes / 1024.0 / 1024.0);
        return String.format("%.2fGB", sizeBytes / 1024.0 / 1024.0 / 1024.0);
    }
}
```

**优化后的搜索 SQL**：

```xml

<select id="searchDatasetItems" resultType="com.pei.dehaze.model.vo.DatasetItemVO">
    SELECT di.*, sf.size_bytes
    FROM sys_dataset_item di

    WHERE 1=1
    <if test="minSize != null">
        AND sf.size_bytes >= #{minSize} -- ✅ 可走索引
    </if>
    <if test="maxSize != null">
        AND sf.size_bytes<= #{maxSize}
    </if>

```

## 五、Top 4：搜索 SQL 无索引

### 5.1 问题分析

**当前表结构**（`sys_item_file` 表）：

```sql
CREATE TABLE sys_item_file
(
    id         BIGINT PRIMARY KEY,
    item_id    BIGINT,      -- 单列索引
    type       VARCHAR(20), -- 无索引
    haze_level VARCHAR(20), -- 无索引
    scene_type VARCHAR(50), -- 无索引

```

**常见查询场景**：

-- 场景 3：组合条件筛选

FROM sys_item_file
WHERE item_id IN (1, 2, 3)

```

+------+-------+---------------+------+---------+-------+
| type | key   | key_len       | rows | Extra   |
+------+-------+---------------+------+---------+-------+
| ref  | idx_item_id | 8       | 10   | Using where |  ← 走索引但仍需扫描 10 行
+------+-------+---------------+------+---------+-------+
```

### 5.2 优化方案

#### 索引优化策略

**SQL 迁移脚本**：

```sql
-- V2.3__optimize_item_file_index.sql

-- 1. 删除单列索引
DROP INDEX idx_item_id ON sys_item_file;

-- 2. 创建组合索引（按查询频率和选择性排序）
CREATE INDEX idx_item_file_composite ON sys_item_file (item_id, type, haze_level, scene_type);

-- 3. 覆盖索引（包含常用查询字段）
CREATE INDEX idx_item_file_covering ON sys_item_file (item_id, type, file_id, created_at);

-- 4. 场景类型单独索引（用于全局筛选）
CREATE INDEX idx_scene_type ON sys_item_file (scene_type);
```

**索引选择原则**：

| 查询条件组合                                             | 使用索引                      | 预期扫描行数    |
|----------------------------------------------------|---------------------------|-----------|
| `item_id = ?`                                      | `idx_item_file_composite` | 2-10      |
| `item_id = ? AND type = ?`                         | `idx_item_file_composite` | 1-3       |
| `item_id IN (...) AND type = ? AND haze_level = ?` | `idx_item_file_composite` | 精确匹配      |
| `scene_type = ?`                                   | `idx_scene_type`          | 1000-5000 |

**验证执行计划**：

```sql
EXPLAIN
SELECT *
FROM sys_item_file
WHERE item_id = 1
  AND type = 'hazy'
  AND haze_level = 'heavy';

+------+-------------------------+------+---------+-------+
| type | key                     | rows | Extra   |
+------+-------------------------+------+---------+-------+
| ref  | idx_item_file_composite | 1    | Using index |  ← 覆盖索引
+------+-------------------------+------+---------+-------+
```

## 六、Top 5：缩略图同步生成

### 6.1 问题分析

**当前实现**（`SysItemFileServiceImpl.java`）：

```java

@Override
@Transactional
public ItemFileVO uploadFile(MultipartFile file, Long itemId) {
    // 1. 上传原图
    String originalPath = fileService.upload(file);

    // 2. 同步生成缩略图（阻塞）
    String thumbPath = ImageUtils.generateThumbnail(originalPath, 200);  // ❌ 耗时 500-2000ms

    // 3. 保存文件记录
    SysFile sysFile = new SysFile();
    sysFile.setUrl(originalPath);
    sysFile.setThumbnailUrl(thumbPath);
    fileMapper.insert(sysFile);

    return buildVO(sysFile);
}
```

**性能问题**：

- 单张图片缩略图生成：500ms - 2s（取决于分辨率）
- 批量上传 10 张图片：10-20s（串行生成）
- 用户体验差，感觉"卡住"

### 6.2 优化方案

#### 异步生成 + 补偿机制

**改造后的实现**（详见 ADR-001）：

```java

@Override
@Transactional
public ItemFileVO uploadFile(MultipartFile file, Long itemId) {
    // 1. 上传原图
    String originalPath = fileService.upload(file);

    // 2. 保存文件记录（thumbnailPath 暂时为 null）
    SysFile sysFile = new SysFile();
    sysFile.setUrl(originalPath);
    sysFile.setThumbnailPath(null);  // ✅ 先不生成
    fileMapper.insert(sysFile);

    // 3. 发布事件：异步生成缩略图
    eventPublisher.publishEvent(new DatasetEvent.ItemFilesUploaded(
            this, datasetId, itemId, List.of(sysFile.getId()), List.of(originalPath)
    ));

    return buildVO(sysFile);
}
```

**异步处理**（`DatasetEventHandler.java`）：

```java

@Async("datasetTaskExecutor")
@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
@Retryable(maxAttempts = 3, backoff = @Backoff(delay = 2000))
public void handleThumbnailGeneration(DatasetEvent.ItemFilesUploaded event) {
    for (int i = 0; i < event.getFilePaths().size(); i++) {
        String filePath = event.getFilePaths().get(i);
        Long fileId = event.getFileIds().get(i);

        try {
            // 生成缩略图
            String thumbPath = ImageUtils.generateThumbnail(filePath, 200);

            // 更新数据库
            itemFileMapper.updateThumbnailPath(fileId, thumbPath);

            log.info("缩略图生成成功: fileId={}", fileId);
        } catch (Exception e) {
            log.error("缩略图生成失败: fileId={}", fileId, e);
            // 记录失败，由补偿任务处理
            recordThumbnailFailure(fileId, filePath);
        }
    }
}
```

## 九、风险与回滚

### 9.1 风险点

| 风险       | 可能性 | 影响 | 缓解措施          |
|----------|-----|----|---------------|
| 缓存雪崩     | 中   | 高  | 随机 TTL + 降级查库 |

| 索引占用空间过大 | 低   | 低  | 定期监控表大小       |

**场景 1：缓存故障**

```java
// 临时关闭缓存
@Override

    // return cached;  // 注释掉
    return calculateStatisticsFromDB(datasetId);  // 直接查库
}
```

```sql

    DROP COLUMN size_bytes;

```

    // ...
