# API接口测试规范

## 一、测试目的与范围

### 1.1 测试目的

- 验证API接口功能正确性，确保符合接口设计文档
- 验证接口参数校验、错误处理机制
- 验证接口响应结构与数据格式
- 验证接口安全性（认证、授权）
- 发现接口潜在缺陷，保障系统质量

### 1.2 测试范围

| 模块     | 接口数量 | 测试优先级 |
|--------|------|-------|
| 数据集管理  | 6    | P0    |
| 数据项管理  | 8    | P0    |
| 图片文件管理 | 4    | P1    |
| 导出任务管理 | 3    | P1    |

## 三、测试用例设计规范

### 3.1 用例编号规则

```
TC-{模块}-{接口}-{序号}
```

示例：`TC-DS-001-01` 表示数据集模块第1个接口的第1个用例

### 3.2 用例分类

| 类型   | 说明          | 优先级 |
|------|-------------|-----|
| 正向测试 | 正常参数，预期成功   | P0  |
| 参数校验 | 缺失/非法参数测试   | P0  |
| 边界测试 | 边界值、极限值测试   | P1  |
| 异常测试 | 资源不存在、权限不足等 | P1  |
| 安全测试 | 未认证、越权访问测试  | P0  |

### 3.3 用例模板

```markdown
#### TC-{编号}: {用例名称}

**测试目的**: {简述测试目的}

**前置条件**: {测试前需满足的条件}

**请求信息**:
- 方法: GET/POST/PUT/DELETE
- 路径: /api/v1/xxx
- 请求头: Authorization: Bearer {token}
- 请求体: {JSON格式}

**预期结果**:
- 状态码: 200/400/404
- 响应体: {JSON格式}

**实际结果**: {PASS/FAIL}

**备注**: {补充说明}
```

## 四、响应验证规范

### 4.1 状态码验证

| 状态码 | 场景    | 验证要点                |
|-----|-------|---------------------|
| 200 | 请求成功  | code为"00000"，data非空 |
| 400 | 参数错误  | code为错误码，msg包含错误信息  |
| 401 | 未认证   | 无Token或Token过期      |
| 403 | 无权限   | 已认证但无操作权限           |
| 404 | 资源不存在 | 访问不存在的资源            |
| 500 | 服务器错误 | 系统异常                |

### 4.2 响应结构验证

```json
{
  "code": "00000",      // 必须存在，业务状态码
  "msg": "一切ok",       // 必须存在，提示信息
  "data": {}            // 根据接口定义验证
}
```

### 4.3 数据类型验证

| 字段类型         | 验证规则           |
|--------------|----------------|
| Long/Integer | 数值类型，非null时为整数 |
| String       | 字符串类型，验证长度限制   |
| Date         | ISO 8601格式或时间戳 |
| List         | 数组类型，验证元素结构    |
| Object       | 对象类型，验证必填字段    |

## 五、测试执行流程

### 5.1 执行步骤

1. **环境准备**: 确认服务启动、数据库连接正常
2. **获取Token**: 调用登录接口获取认证Token
3. **数据准备**: 创建测试所需的前置数据
4. **执行测试**: 按用例执行接口调用
5. **结果验证**: 对比预期与实际结果
6. **数据清理**: 清除测试产生的数据

### 5.2 测试数据管理

- 测试数据应具有唯一标识（如前缀 `TEST_`）
- 每轮测试后清理测试数据
- 避免依赖生产数据

{发现的问题及状态}

| 复现步骤 | 问题复现的具体步骤     |

## 七、安全测试要点

### 7.1 认证测试

- 无Token访问受保护接口 → 401
- 过期Token访问 → 401
- 无效Token访问 → 401

### 7.2 授权测试

- 普通用户访问管理员接口 → 403
- 用户访问他人资源 → 403

### 7.3 输入验证

- SQL注入测试: `' OR '1'='1`
- XSS测试: `<script>alert(1)</script>`
- 路径遍历: `../../../etc/passwd`

## 八、附录

### 8.1 常用断言

| 断言类型   | 示例                              |
|--------|---------------------------------|
| 状态码    | `response.status == 200`        |
| JSON路径 | `response.data.code == "00000"` |
| 数组长度   | `response.data.list.length > 0` |
| 字段存在   | `response.data.id != null`      |

- **Postman**: 接口调试与测试
- **cURL**: 命令行测试
