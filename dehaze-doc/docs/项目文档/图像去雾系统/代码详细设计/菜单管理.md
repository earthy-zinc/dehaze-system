# 菜单管理模块

## 1. 概述

### 1.1 文档目的

本文档详细描述图像去雾系统菜单管理模块的代码设计，包括架构设计、模块划分、接口定义、数据结构和关键算法等技术实现细节。

### 1.2 适用范围

本文档适用于菜单管理模块的后端和前端开发人员，为代码实现提供技术指导和参考。

### 1.3 架构设计

本文档遵循《总体系统架构文档》中定义的分层架构设计原则，采用前后端分离的架构模式。

## 2. 技术架构设计

### 2.1 整体架构

菜单管理模块采用前后端分离的架构设计：

- 后端：基于Spring Boot的RESTful API服务
- 前端：基于Vue3 + Element Plus的单页应用

### 2.2 后端分层架构

```
Controller层 (SysMenuController)
    ↓
Service层 (SysMenuService)
    ↓
Mapper层 (SysMenuMapper)
    ↓
数据库 (MySQL)
```

### 2.3 前端架构

```
页面组件 (index.vue)
    ↓
API调用层 (dehaze-sdk-js)
    ↓
状态管理 (Vuex/Pinia)
    ↓
UI组件 (Element Plus)
```

## 3. 后端详细设计

### 3.1 控制层设计 (SysMenuController)

#### 3.1.1 类结构

```java
@RestController
@RequestMapping("/api/v1/menus")
@RequiredArgsConstructor
@Tag(name = "05.菜单接口")
public class SysMenuController {
    private final SysMenuService menuService;
}
```

#### 3.1.2 接口设计

| 接口URL                   | 请求方法   | 功能描述     | 权限控制                                            |
|-------------------------|--------|----------|-------------------------------------------------|
| /api/v1/menus           | GET    | 获取菜单列表   | 无特殊权限                                           |
| /api/v1/menus/options   | GET    | 获取菜单下拉选项 | 无特殊权限                                           |
| /api/v1/menus/routes    | GET    | 获取路由列表   | 无特殊权限                                           |
| /api/v1/menus/{id}/form | GET    | 获取菜单表单数据 | 无特殊权限                                           |
| /api/v1/menus           | POST   | 新增菜单     | @PreAuthorize("@ss.hasPerm('sys:menu:add')")    |
| /api/v1/menus/{id}      | PUT    | 修改菜单     | @PreAuthorize("@ss.hasPerm('sys:menu:edit')")   |
| /api/v1/menus/{id}      | DELETE | 删除菜单     | @PreAuthorize("@ss.hasPerm('sys:menu:delete')") |
| /api/v1/menus/{menuId}  | PATCH  | 修改菜单显示状态 | @PreAuthorize("@ss.hasPerm('sys:menu:edit')")   |

#### 3.1.3 关键注解说明

- `@PreAuthorize`：Spring Security权限控制注解，用于方法级别的权限验证
- `@Valid`/`@Validated`：用于请求参数校验

### 3.2 服务层设计 (SysMenuService)

#### 3.2.1 接口定义

```java
public interface SysMenuService extends IService<SysMenu> {
    // 查询菜单列表
    List<SysMenu> listMenus(String name);
    
    // 获取菜单下拉选项
    List<OptionVO> listMenuOptions();
    
    // 构建前端路由列表
    List<RouteVO> listRoutes();
    
    // 保存菜单（新增或更新）
    boolean saveMenu(MenuForm menuForm);
    
    // 获取菜单表单数据
    MenuForm getMenuForm(Long id);
    
    // 更新菜单显示状态
    boolean updateMenuVisible(Long menuId, Integer visible);
    
    // 删除菜单
    boolean deleteMenu(Long id);
}
```

#### 3.2.2 核心业务逻辑

##### 菜单树构建

- 通过递归算法构建菜单树形结构
- 支持按条件筛选菜单节点

##### 路由构建

- 根据菜单配置构建前端路由信息
- 支持多种菜单类型的路由处理

##### 菜单删除逻辑

- 检查菜单是否存在子菜单
- 删除菜单及其关联的角色权限数据

## 5. 数据库设计

### 5.1 菜单表 (sys_menu)

```sql
CREATE TABLE `sys_menu` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '菜单ID',
  `parent_id` bigint NOT NULL DEFAULT '0' COMMENT '父级菜单ID',
  `name` varchar(64) NOT NULL COMMENT '菜单名称',
  `type` tinyint NOT NULL COMMENT '菜单类型(1:目录;2:菜单;3:按钮;4:外链)',
  `path` varchar(128) DEFAULT NULL COMMENT '路由路径',
  `component` varchar(128) DEFAULT NULL COMMENT '组件路径',
  `perm` varchar(128) DEFAULT NULL COMMENT '权限标识',
  `visible` tinyint NOT NULL DEFAULT '1' COMMENT '显示状态(1:显示;0:隐藏)',
  `sort` int NOT NULL DEFAULT '1' COMMENT '排序',
  `icon` varchar(64) DEFAULT NULL COMMENT '菜单图标',
  `redirect` varchar(128) DEFAULT NULL COMMENT '跳转路径',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='菜单表';
```

### 5.2 菜单角色关联表 (sys_role_menu)

```sql
CREATE TABLE `sys_role_menu` (
  `role_id` bigint NOT NULL COMMENT '角色ID',
  `menu_id` bigint NOT NULL COMMENT '菜单ID',
  PRIMARY KEY (`role_id`, `menu_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='角色菜单关联表';
```

### 5.3 索引设计

- 主键索引：菜单表id字段，角色菜单关联表(role_id, menu_id)组合索引
- 普通索引：菜单表parent_id字段，优化树形查询性能

## 6. 关键算法设计

### 6.1 菜单树构建算法

通过递归算法构建菜单树形结构：

1. 查询所有菜单数据
2. 根据parent_id字段构建父子关系
3. 递归构建完整的树形结构

### 6.2 路由构建算法

根据菜单配置构建前端路由信息：

1. 遍历菜单树
2. 根据菜单类型生成对应路由配置
3. 构建完整的路由列表

### 6.3 菜单删除检查算法

在删除菜单前检查是否存在子菜单：

1. 查询该菜单下的所有子菜单
2. 如存在子菜单，则禁止删除并提示错误信息
