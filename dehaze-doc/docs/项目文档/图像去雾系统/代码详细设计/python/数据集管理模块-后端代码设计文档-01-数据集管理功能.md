# 代码设计文档

## 文档说明
- **对应需求**：`demo/docs/07-数据集管理模块需求-01-数据集管理功能.md`
- **适用版本**：dehaze-python Flask 后端 V2.0（数据库以 `new_dehaze.sql` / `V2.0__dataset_module_extend.sql` 为准）。
- **设计原则**：
  1. **最小侵入**：在现有 `Blueprint + Service + SQLAlchemy` 分层基础上增量改造，避免重写路由注册与认证逻辑。
  2. **统一统计**：所有统计/使用次数数据经由 Redis 缓存 + SQL 聚合产出，保持与前端图表一致。
  3. **可观测 & 可回滚**：下载打包、批量操作等耗时任务必须可监控、可取消，异常状态对业务方可见。

## 1. 修改目标与范围定位
- 为 Flask 端补齐数据集详情、统计、下载、使用次数等接口，配合 GO 端保持一致的响应结构。
- 需涉及的技术层次：`app/route/dataset.py` 路由、`app/service/dataset_service.py` / `DatasetItemService` / 新增 `DatasetStatisticsService`、`app/service/file.py`、`app/models`（字段同步）、`config.py`（新增下载配置）、Redis 缓存、MinIO 文件服务、异步任务（`app/job.py`）。
- **需修改文件**：
  | 文件 | 作用 |
  | --- | --- |
  | `app/route/dataset.py` | 新增详情、统计、下载、使用次数、任务查询路由；老接口迁移到统一 schema 校验。 |
  | `app/service/dataset_service.py` | 输出树 + 详情 + 下载准备逻辑；新增缓存、统计、使用次数封装。 |
  | `app/service/dataset_item_service.py` | 暴露叶子节点查询、数据项 usage 更新、批量删除等辅助方法。 |
  | `app/models.py` | 同步 `sys_dataset.usage_count`、`sys_item_file.scene_type/haze_level/process_status/...` 等新字段。 |
  | `app/service/file.py` | 补充 ZIP 打包、流式写文件到本地/MinIO 的函数。 |
  | `config.py` | 引入 `DATASET_DOWNLOAD` / `CACHE_TTL` 等配置项。 |
- **需新增文件/目录**：
  | 建议路径 | 说明 |
  | --- | --- |
  | `app/service/dataset_statistics_service.py` | 封装统计 SQL、Redis 读写、缓存失效。 |
  | `app/tasks/dataset_download.py` | 使用 `ThreadPoolExecutor` / `Celery` 处理打包任务，暴露 `submit_download_task`。 |
  | `app/cache/__init__.py` + `app/cache/keys.py` | 统一 Key 规范 `dataset:tree`、`dataset:stats:{id}`、`dataset:download:{task}`。 |
  | `app/schemas/dataset.py` | Marshmallow/Pydantic 校验：`DatasetForm`, `DownloadRequest`, `UsagePatch`。 |

## 2. 现有实现概览
- **路由**：`dataset_blueprint` 仅覆盖列表/下拉/单体 CRUD/分页图片/数据项 CRUD，且 query 解析依赖 `request.args`，无类型校验、无分层统计或下载接口。
- **服务**：
  - `DatasetService`：树构造、选项、CRUD、分页 `get_image_items`（仅返回 `imgUrl`），无统计/缓存，使用次数未落库。
  - `DatasetItemService`：增删改数据项，删除时只删 `SysItemFile`，无批量/校验逻辑。
- **模型**：`SysDataset`、`SysItemFile` 未包含 V2.0 字段（usage_count、scene_type、process_status、width/height 等），导致 Python 层无法感知。
- **基础设施**：`config.py` 已配置 Redis、MinIO，但当前功能未使用 Redis 缓存，也没有后台任务（`app/job.py` 空文件）。

## 3. 代码设计与修改方案

### 3.1 路由与 API
1. **新增接口**（均走 `jwt_required`）：
   - `GET /api/v1/dataset/<id>/detail`：返回 Dataset 基本信息 + 统计（包含场景/雾霾/格式分布）。
   - `GET /api/v1/dataset/<id>/statistics`：仅获取统计数据（供弹窗复用）。
   - `POST /api/v1/dataset/<id>/download`：创建下载任务，Body `{"organizeByItem": true, "includePairs": true}`。
   - `GET /api/v1/dataset/download/<taskId>`：查询任务状态。
   - `PATCH /api/v1/dataset/<id>/usage`：自增使用次数，Body `{ "delta": 1 }`。
2. **参数校验**：
   - 基于 `app/schemas/dataset.py`（Marshmallow）统一校验 Body/query/path，减少 `request.args` 手写逻辑。
   - 错误时抛 `BusinessException`，由 `utils/error_handlers` 捕获。
3. **响应结构**：统一 `success()` 返回的 `data` 字段，确保前端树、统计、下载进度可以直接消费。

### 3.2 Service 层
1. **`DatasetService` 改造**：
   - `get_dataset_list`：增加 `include_stats` 参数；优先读 Redis `dataset:tree`，未命中时查询 `SysDataset` + 统计表并回填 caches。
   - `get_dataset_detail`：联合 `SysDataset`、`DatasetStatisticsService.fetch(dataset_id)`、`DatasetItemService.fetch_recent_items(dataset_id)`。
   - `touch_usage(dataset_id, delta)`：`SysDataset.usage_count += delta`（SQL `update`），同时刷新缓存。
   - `create_download_task`：调用 `DatasetDownloadTask.submit(dataset_id, options)`，写入 Redis 任务状态。
2. **`DatasetStatisticsService`**：
   - `build(dataset_id)`：SQLAlchemy + 原生 SQL 聚合 `SysDatasetItem -> SysItemFile -> SysFile`，产出：图片数量、不同场景/雾霾/格式/分辨率区段、usage_count、最近更新时间。
   - 结果缓存 TTL 30 min，CRUD/上传/删除/标注后调用 `invalidate(dataset_id)`。
3. **`DatasetDownloadTask`（新）**：
   - 调用链：`submit()` -> 将任务写入 Redis `dataset:download:{taskId}` = `{status, progress, total, zipPath}` -> 在线程池异步执行 `_zip_dataset(dataset_id, options)` -> 打包完成后上传 Zip 至 MinIO（或存本地 `DATASET_DOWNLOAD['base_dir']`） -> 更新任务状态。
   - 失败时记录 `error` 字段，API 查询到 `status=failed`。
   - 任务执行需复用 `DatasetService._get_leaf_dataset_ids` + `ItemFileService` 取文件 URL，再使用 `file.py` 新增的 `stream_zip(files)`。
4. **`DatasetItemService`**：
   - 新增 `get_leaf_dataset_ids(dataset_id)`、`list_items(dataset_ids, pagination, filters)` 以供统计、下载、图片浏览共用。

### 3.3 配置与数据存储
- **模型**：
  - `SysDataset` 新增 `usage_count = Column(BigInteger, default=0)`；
  - `SysItemFile` 补齐 `scene_type`, `haze_level`, `process_status`, `width`, `height`, `usage_count`, `create_time`, `update_time`，并新增索引（见 SQL 脚本）。
- **配置**：`config.py` 加入：
  ```python
  class DevelopmentConfig(Config):
      DATASET_DOWNLOAD = {
          "base_dir": path.join(Config.PROJECT_PATH, "runtime/download"),
          "public_domain": "http://localhost:8989/static/download",
          "expire_hours": 24,
          "max_parallel_tasks": 3
      }
      CACHE_TTL = {
          "dataset_tree": 1800,
          "dataset_stats": 1800,
          "download_task": 86400
      }
  ```
- **Redis Key 规范**：
  - `dataset:tree`：缓存序列化树；
  - `dataset:stats:{datasetId}`：统计 JSON；
  - `dataset:download:{taskId}`：任务状态；
  - `dataset:usage:lock:{datasetId}`：防止并发更新。

## 4. 异常处理与边界情况
- 数据集不存在/被禁用 -> 404 + `DATASET_NOT_FOUND`。
- 下载任务尚未完成 -> 返回 progress（0-100），未创建 -> 404。
- 打包过程中文件缺失：记录缺失文件清单并标记 `status=failed`。
- Redis 不可用：降级为立即查询数据库但在响应体中标识 `cache=false`，下载任务则拒绝创建并提示稍后重试。
- 并发删除：若任务执行中数据集被删除，任务立即终止并回写失败状态。

## 5. 安全与性能注意事项
- 继续复用 JWT + 角色校验；新增接口需要 `管理员/数据管理员` 权限检查（在路由或 service 层加入装饰器）。
- 所有 SQL 使用 SQLAlchemy 参数化；对 `sortField`、`order` 做白名单限制。
- 使用 Redis `SETNX` 锁防止多用户同时创建相同数据集的下载任务（task 复用）。
- ZIP 打包流式写入，避免将全部文件读入内存；限制单任务最大文件总量（通过配置）。

## 6. 测试建议
- **功能**：
  - 树接口携带缓存时与数据库一致性；
  - 详情/统计接口字段完整；
  - 下载任务创建 → 查询进度 → 完成 → 下载链接可访问；
  - 使用次数在算法调用、下载后正确自增；
  - 缓存失效（上传/删除图片后统计刷新）。
- **性能**：
  - 3 万条数据集记录下树接口响应（缓存命中/未命中）；
  - 下载大数据集（>1GB）时的内存、CPU、耗时；
  - Redis 恢复后缓存自动填充。
- **兼容**：
  - 不同部署环境（development/production）下 `DATASET_DOWNLOAD` 路径和 URL 正确；
  - Redis 不可用时接口降级提示。

## 7. 待确认事项与风险
- 下载产物最终托管方式（本地静态目录 vs MinIO 公开桶）需产品/运维确认，以决定 Zip URL 生成逻辑。
- `usage_count` 计数口径是否包含“浏览详情”行为，需产品明确；否则需在接口里控制调用场景。
- 任务持久化：如需跨进程恢复，是否需要将下载任务写入 MySQL（目前仅 Redis）。
- 统计口径是否与 Java/Go 端完全一致，若存在差异需统一 SQL 与枚举值。
