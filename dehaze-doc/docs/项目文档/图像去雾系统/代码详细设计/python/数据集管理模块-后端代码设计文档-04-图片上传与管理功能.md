# 代码设计文档

## 文档说明
- **对应需求**：`demo/docs/07-数据集管理模块需求-04-图片上传与管理功能.md`
- **适用版本**：dehaze-python Flask 后端 V2.0。
- **设计原则**：
  1. **统一上传管线**：单张上传、配对上传、批量上传共用同一 Pipeline，确保校验、解析、持久化一致。
  2. **可恢复任务**：批量上传/删除任务状态写入 Redis（必要时落库），可查询、可重试。
  3. **去重与引用**：通过 MD5 去重和引用计数避免重复占用存储；删除时尊重引用关系。

## 1. 修改目标与范围定位
- 支持单张、配对、批量上传；自动解析宽高/雾霾程度；提供批量删除、批量更新、批量下载配套能力。
- 涉及：`app/route/item_file.py`（上传/批量管理路由）、`app/service/item_file_service.py`、`app/service/dataset_item_service.py`、`app/service/file.py`、`app/extensions`（队列/线程池初始化）、`app/models.SysItemFile/SysFile`、`config.py`（上传策略）、`app/utils/file.py`（解析工具）。

## 2. 现有实现概览
- 上传接口 `POST /api/v1/dataset/image/`：
  - 直接调用 `upload_file_from_request`，未校验 dataset/item 关系、图片类型限制、文件大小。
  - 使用 `file.read()` 后未复位文件指针，无法多次读取。
  - 没有解析宽高、雾霾程度、场景类型等字段。
- 无配对/批量上传；`item_file_service.SaveItemFile` 缺少引用计数、异常回滚。
- `SysFile` 仅记录基础信息；`SysItemFile` 缺少 V2.0 字段。
- 没有批量删除/批量更新接口。

## 3. 代码设计与修改方案

### 3.1 上传管线
1. **Pipeline 结构**（新增 `app/service/upload/pipeline.py`）：
   - `ValidateStep`：检查参数（datasetId/datasetItemId/type/sceneType/hazeLevel）、文件大小/格式、同名冲突；若 `datasetItemId` 为空则创建新数据项并返回 ID。
   - `MetadataStep`：解析宽高、MD5、文件大小、EXIF（可选），并检查清晰图/雾图配对要求。
   - `StorageStep`：通过 `file.py` 上传至 MinIO，使用 MD5 去重；同时生成缩略图。
   - `PersistStep`：写入 `SysFile` / `SysItemFile`，带事务；若 fail 则回滚并删除已上传文件。
   - `PostStep`：刷新缓存、写入操作日志、触发统计失效。
2. **配对上传**：`POST /api/v1/dataset/image/pair-upload`
   - Body JSON：`{"datasetId": 1, "sceneType": "城市", "pair": {"clear": {"file": <file_id>}, "hazies": [{"file": <file_id>, "hazeLevel": "light"}, ...]}}`（前端通过 multipart + JSON 传输）。
   - `PairValidator` 校验：1 个清晰图、>=1 个雾图、所有图片宽高一致、文件格式允许。
   - 上传成功后将同组图片写入同一 `SysDatasetItem`，`type` = `clear|hazy|dehazed`。
3. **批量上传**：`POST /api/v1/dataset/image/batch-upload`
   - 接收压缩包或多文件；命名规则 `<prefix>_(clear|hazy_light|hazy_medium|...).ext`。
   - 上传任务写入 Redis `dataset:upload:{taskId}`：`{status,total,success,failed,currentFile}`；后台 worker（`ThreadPoolExecutor` 或 Celery）处理。
   - 支持暂停/取消（将 status 改为 `cancelled`）。
4. **断点续传（建议方案）**：若需直接将文件上传到 MinIO，由后端签发临时凭证；本期如未实现，文档中标记 `【建议方案】`。

### 3.2 批量管理
- **批量删除**：`POST /api/v1/dataset/image/batch-delete`，Body `{ "itemFileIds": [], "deletePhysical": false }`
  - 步骤：校验权限 -> 判断是否还有其他数据项引用该文件（按 MD5） -> 删除 `SysItemFile` 记录 -> 根据 `deletePhysical` 决定是否在 MinIO 删除对象。
- **批量更新**：`POST /api/v1/dataset/image/batch-update`，Body `{ "itemFileIds": [], "sceneType": "", "hazeLevel": "", ... }`
  - 通过 SQLAlchemy `update` + `where(SysItemFile.id.in_(...))` 实现；若 `applyToPairs=true` 则扩展到同 item 下所有图片。
- **批量下载**：沿用 01 文档的下载任务服务，`scope=imageSelection`，zip 结构可按 `dataset/{itemId}/{type}_{filename}` 组织。

### 3.4 数据校验 & 业务规则
- `sceneType` 字段允许自由输入但长度 ≤ 64；服务层把新值写入 Redis Set（供搜索建议）。
- `hazeLevel` 只能为 `light|medium|heavy|unknown`（与字典保持一致）。
- `processStatus` 默认 `unprocessed`，批量处理成功后更新为 `processed`。
- 上传时自动生成 MD5 和缩略图。若文件已存在（同 MD5），重用 `SysFile` 记录并仅创建新的 `SysItemFile`，同时记录 `reference_count`（新列，或复用 `SysFile` 的 `usage_count`）。

## 4. 异常处理与边界情况
- 单文件超过 `max_size_mb` -> 413。
- 批量任务超过文件数或总大小限制 -> 429 `BATCH_LIMIT_EXCEEDED`。
- 配对校验失败：返回详细列表（缺清晰图、分辨率不一致、雾霾未标注）。
- 上传过程中 Redis 失效：任务状态写入 MySQL 兜底（可选）。
- 删除文件但仍有引用 -> 拒绝删除并返回引用列表。

## 5. 安全与性能注意事项
- 上传接口必须验证 JWT，并校验当前用户是否有该数据集写权限；大批量操作需额外的管理员角色。
- 使用 `werkzeug` 的 `stream` 方式处理大文件，读写时避免一次性载入内存；缩略图生成使用 Pillow 并限制输出格式。
- MinIO 上传使用分片/断点续传（若大文件），并设置合理的连接超时。
- 进度查询接口使用 Redis `HGETALL`，避免深度序列化；并在任务完成后设置过期时间。

## 6. 测试建议
- **功能**：
  - 单张上传、配对上传（包含异常场景）、批量上传（含进度查询、失败重试、取消）；
  - 上传后自动解析宽高、生成缩略图、写入场景/雾霾信息；
  - 批量删除/更新权限校验、引用校验；
  - 批量下载与数据集下载任务共用服务是否正常。
- **性能**：
  - 50MB 文件上传耗时；
  - 批量上传 200 张图片（总 1GB）的任务耗时、CPU、内存占用；
  - 多任务并发情况下的队列压力；
  - Redis 断连后任务恢复流程。
- **兼容**：
  - 不同图片格式（jpg/png/gif）及含透明通道图；
  - Windows/Linux/Mac 客户端上传路径差异；
  - 多语言场景类型输入。

## 7. 待确认事项与风险
- 批量上传是否需要支持压缩包（当前设计支持单文件列表），需产品明确。
- 是否允许一个文件被多个数据项引用，如允许需实现引用计数和防误删策略。
- 断点续传/直传 OSS 是否属于本期范围，如需要需追加签名接口与回调。
