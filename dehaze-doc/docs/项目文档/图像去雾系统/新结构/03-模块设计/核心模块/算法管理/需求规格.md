# 算法管理模块需求规格

## 1. 模块概述

### 1.1 模块定位

算法管理模块是图像去雾系统的核心管理模块，负责管理系统中用于图像去雾处理的各种深度学习算法模型的全生命周期。该模块提供算法的创建、浏览、编辑、删除、发布、停用等完整管理功能，包括算法的版本控制、性能监控、效果评估等核心功能。

作为系统核心模块之一，算法管理模块为【算法选择模块】提供算法数据源，为【去雾处理模块】提供模型预测服务，为【效果对比模块】提供效果评估支持，是整个系统算法资产管理的中枢。

### 1.2 核心价值

| 价值维度 | 具体内容 |
|---------|---------|
| **全生命周期管理** | 支持算法从创建、测试、审核到发布、下架、归档的完整流程管理 |
| **版本控制** | 支持算法多版本管理、版本对比、版本回滚和版本归档 |
| **性能监控** | 实时监控算法处理时间、成功率、图像质量指标和资源使用情况 |
| **效果评估** | 支持PSNR、SSIM等图像质量指标的自动计算和可视化展示 |
| **权限管理** | 细粒度的操作权限控制和数据权限隔离 |
| **缓存机制** | 基于MD5的处理结果缓存，避免重复计算，提升系统性能 |

### 1.3 用户角色分析

| 用户类型 | 特征 | 使用偏好 | 功能需求 |
|---------|------|---------|---------|
| **算法研究员** | 负责算法开发、测试和优化，熟悉深度学习模型 | 频繁上传/管理模型 | 模型上传+版本控制+效果评估+性能监控 |
| **系统管理员** | 拥有完整操作权限，管理全局算法配置 | 权限控制+数据清理 | 全量管理+权限配置+审计+发布审核 |
| **算法开发者** | 负责新算法的集成和配置 | 快速集成+调试 | 模型新增+参数配置+测试验证 |
| **运营人员** | 关注算法使用情况和用户反馈 | 数据分析+报表 | 使用统计+性能监控+用户反馈管理 |
| **普通用户** | 使用公开算法进行去雾处理 | 浏览+选择+使用 | 算法浏览+参数调整+结果预览 |

## 2. 功能需求

### 2.1 算法列表展示 (F-M05-001)

#### 2.1.1 功能描述

以树形结构展示所有算法列表，支持查看算法基本信息、技术信息和统计数据，提供搜索、筛选和排序功能。

#### 2.1.2 算法类型

> 算法类型通过字典表 `sys_algorithm_type` 管理，用户可自行扩展。

| 类型值 | 类型标签 | 说明 | 典型模型 | 可见性 |
|--------|----------|------|---------|--------|
| `traditional` | 传统算法 | 基于物理模型的去雾算法 | DCP, CAP | 公开 |
| `deep_learning` | 深度学习 | 基于深度学习的去雾算法 | RIDCP, WPXNet, Dehamer | 公开/受限 |
| `transformer` | Transformer | 基于 Transformer 的算法 | Dehamer, ViT | 公开/受限 |
| `custom` | 用户自定义 | 用户上传的私有算法模型 | 不限 | 私有 |
| `experimental` | 实验性 | 处于测试阶段的算法 | 不限 | 算法开发者可见 |

#### 2.1.3 算法状态

> 对应数据库字段：`sys_algorithm.status`（tinyint），详见 [数据库设计](../../02-系统架构/03-数据库设计.md#算法表)

| 状态值 | 状态名称 | 说明 | 可执行操作 |
|--------|---------|------|-----------|
| 0 | 草稿 | 新创建，尚未完成配置 | 编辑、删除、提交测试 |
| 1 | 测试中 | 正在进行功能测试 | 编辑、提交审核 |
| 2 | 待审核 | 已提交审核，等待审核员处理 | 审核通过、审核驳回 |
| 3 | 已发布 | 审核通过，对外可用 | 停用、编辑（生成新版本） |
| 4 | 已停用 | 暂时下线，不可使用 | 启用、删除 |
| 5 | 已归档 | 永久归档，只读 | 查看 |

**状态流转规则**

```
草稿(0) ──提交测试──▶ 测试中(1)
测试中(1) ──提交审核──▶ 待审核(2)
待审核(2) ──审核通过──▶ 已发布(3)
待审核(2) ──审核驳回──▶ 测试中(1)
已发布(3) ──停用──▶ 已停用(4)
已停用(4) ──启用──▶ 已发布(3)
已停用(4) ──归档──▶ 已归档(5)
草稿(0) ──删除──▶ [物理删除]
已停用(4) ──删除──▶ [物理删除]
```

#### 2.1.4 列表信息展示

**基本信息**

| 字段 | 说明 | 示例 |
|------|------|------|
| 算法ID | 系统唯一标识 | 1001 |
| 算法名称 | 支持中英文，支持树形展示 | "AOD-Net" |
| 算法类型 | 传统/深度学习/用户自定义/实验性 | "深度学习" |
| 算法状态 | 草稿/测试中/待审核/已发布/已停用/已归档 | 🟢 已发布 |
| 版本号 | 格式：主版本.次版本.修订号 | "v2.1.3" |
| 创建时间 | YYYY-MM-DD HH:mm | 2025-01-15 10:30 |
| 最后更新时间 | YYYY-MM-DD HH:mm | 2025-01-17 14:20 |

**统计信息（Redis缓存）**

- 使用次数（被用于去雾处理的次数）
- 平均评分（用户评分）
- 成功率（处理成功次数/总处理次数）
- 平均处理时间（毫秒）
- 平均PSNR/SSIM（图像质量指标）

**技术信息**

| 字段 | 说明 | 示例 |
|------|------|------|
| 模型大小 | 权重文件大小 | "45.6MB" |
| 参数量 | 模型参数总数 | "5.2M" |
| FLOPs | 浮点运算量 | "12.3G" |
| 输入分辨率 | 支持的输入图像分辨率 | "512×512" |

#### 2.1.5 树形结构管理

**功能要求**

算法列表页面需提供：
- 搜索功能：按算法名称、ID、标签搜索，支持重置
- 筛选功能：按类型、状态、创建时间筛选
- 排序功能：按创建时间、使用次数、评分、名称排序
- 操作功能：新增算法（权限：sys:algorithm:add）
- 展示内容：算法树、算法名称、算法类型、算法状态、版本号、使用次数
- 操作按钮：查看、编辑、停用/启用、删除、版本管理（各需对应权限控制）

**树形结构规则**

- 支持算法分类树形展示（按算法类型分类）
- 算法名称在系统中必须唯一
- 支持节点展开/收起
- 支持按关键字搜索过滤

### 2.3 新增算法 (F-M05-003)

#### 2.3.2 新增流程

```mermaid
graph TD
    A[填写基本信息] --> B[上传模型文件]
```

### 2.4 审核算法 (F-M05-004)

#### 2.4.1 功能描述

对提交审核的算法进行审核，支持审核通过和审核驳回操作。

#### 2.4.2 审核角色

| 角色 | 权限 | 说明 |
|------|------|------|
| 算法管理员 | `sys:algorithm:audit` | 可审核所有待审核算法 |
| 超级管理员 | `sys:algorithm:audit` | 可审核所有待审核算法 |

#### 2.4.3 审核操作

**审核通过**

| 项目 | 说明 |
|------|------|
| 前置状态 | 待审核(2) |
| 后置状态 | 已发布(3) |
| 操作效果 | 算法对外可见，可被用户选择使用 |

**审核驳回**

| 项目 | 说明 |
|------|------|
| 前置状态 | 待审核(2) |
| 后置状态 | 测试中(1) |
| 必填信息 | 驳回原因（文本，必填） |
| 操作效果 | 算法返回测试阶段，开发者可修改后重新提交 |

#### 2.4.4 审核标准

| 检查项 | 标准 | 必须通过 |
|--------|------|---------|
| 测试验证 | 算法已通过功能测试 | ✅ |
| 基本信息完整 | 名称、描述、类型等必填项完整 | ✅ |
| 模型文件可用 | 模型文件存在且可正常加载 | ✅ |
| 处理效果 | 处理成功率 ≥ 95% | ✅ |
| 性能达标 | 平均处理时间 ≤ 配置阈值 | ⚠️ 建议 |

#### 2.4.5 审核流程

```mermaid
graph TD
    A[进入待审核列表] --> B[选择待审核算法]
    B --> C[查看算法详情和测试报告]
    C --> D{审核决策}
    D -->|通过| E[点击审核通过]
    E --> F[算法状态变更为已发布]
    D -->|驳回| G[填写驳回原因]
    G --> H[点击审核驳回]
    H --> I[算法状态变更为测试中]
    F --> J[通知算法创建者]
    I --> J
```

### 2.5 修改算法 (F-M05-005)

#### 2.5.1 功能描述

修改已有算法的信息，支持版本控制和变更日志记录。

#### 2.5.2 可修改内容

**基本信息修改**

- 算法描述
- 适用场景
- 标签
- 推荐指数
- 使用说明

**技术信息修改**

- 参数配置
- 样例图片
- 算法原理
- 硬件要求

**版本升级**

- 上传新模型文件
- 更新版本号
- 记录变更日志
- 保留历史版本

#### 2.5.3 版本控制

**版本号规则**

- 格式：主版本.次版本.修订号
- 示例：v2.1.3
- 主版本（Major）：不兼容的API修改
- 次版本（Minor）：向下兼容的功能性新增
- 修订号（Patch）：向下兼容的问题修正

**版本管理**

- 查看历史版本：展示所有历史版本列表
- 版本对比：对比两个版本的差异（参数、模型文件等）
- 版本回滚：回滚到指定的历史版本
- 版本归档：将旧版本归档（只读，不可恢复）

**变更日志**

每次修改算法时，需记录变更日志：

| 字段 | 说明 |
|------|------|
| 变更类型 | 新增/修改/删除 |
| 变更字段 | 修改的字段名 |
| 修改前值 | 修改前的值 |
| 修改后值 | 修改后的值 |
| 变更时间 | 变更发生时间 |
| 变更人 | 执行变更的用户 |
| 变更说明 | 变更说明文本 |

### 2.6 停用/删除算法 (F-M05-006)

#### 2.6.1 停用算法

**停用条件**

- 算法存在问题（性能不达标、处理失败率高）
- 需要维护升级
- 不再推荐使用

**停用效果**

- 用户端不可见
- 不可选择使用
- 保留历史数据和模型文件
- 可以重新启用

**停用流程**

1. 用户触发停用操作
2. 系统弹出确认对话框，显示影响范围
3. 用户确认后执行停用
4. 刷新算法列表并显示成功提示

#### 2.6.2 删除算法

**删除条件**

- 算法已停用
- 确认不再使用
- 管理员权限

**删除效果**

- 从系统中移除
- 删除模型文件
- 保留使用记录
- 不可恢复（需二次确认）

**删除流程**

1. 用户触发删除操作
2. 系统弹出确认对话框，明确提示：
   - 删除后将不可恢复
   - 删除影响的范围（使用次数、关联任务等）
3. 用户确认后执行删除
4. 刷新算法列表并显示成功提示

### 2.7 算法导入/导出 (F-M05-007)

#### 2.7.1 功能描述

支持算法配置和模型的导入导出，便于系统迁移和备份。

#### 2.7.2 导出功能

**导出内容**

| 内容 | 格式 | 说明 |
|------|------|------|
| 算法配置 | JSON | 基本信息、技术参数、config_json |
| 模型文件 | 原始格式 | .pth/.onnx/.h5 等模型文件 |
| 版本历史 | JSON | 版本信息列表（可选） |

**导出格式**：`.zip` 压缩包，包含 `algorithm.json` + 模型文件

**导出限制**
- 仅支持导出自己创建的算法或已发布的公开算法
- 私有算法需管理员权限导出

#### 2.7.3 导入功能

**导入流程**

1. 上传 `.zip` 格式的算法包
2. 系统校验包结构完整性
3. 解析 `algorithm.json` 配置
4. 校验模型文件有效性
5. 创建新算法（状态为草稿）
6. 用户补充/修改信息后提交

**导入校验**

| 校验项 | 说明 |
|--------|------|
| 包格式 | 必须为 `.zip` 格式 |
| 配置文件 | 必须包含 `algorithm.json` |
| 必填字段 | name、type、import_path 不能为空 |
| 模型文件 | 必须存在且可读取 |
| 名称唯一 | 算法名称不能与已有算法重复 |

**冲突处理**
- 名称冲突：提示用户修改名称
- 版本冲突：作为新版本导入（可选）

### 2.9 模型预测处理 (F-M05-009)

#### 2.9.1 功能描述

根据指定算法模型对输入图像进行去雾处理，返回处理后的图像结果，支持处理结果缓存机制。

#### 2.9.2 处理流程

```mermaid
graph TD
    A[选择算法和图像] --> B[调用模型预测接口]
    B --> C[验证算法ID有效性]
    C --> D{检查缓存?}
    D -->|有缓存| E[返回缓存结果]
    D -->|无缓存| F[读取输入图像文件]
    F --> G[调用Python服务处理]
    G --> H[加载模型并处理图像]
    H --> I[保存预测结果]
    I --> J[记录预测日志]
    J --> K[返回预测图像URL]
    E --> L[前端展示处理结果]
    K --> L
```

#### 2.9.3 缓存机制

**缓存策略**：LRU（最近最少使用）淘汰机制

**验收口径**：
- 相同图像 + 相同算法的重复请求应命中缓存，不重复调用 Python 服务
- 算法更新后，该算法的历史缓存应自动失效
- 缓存空间不足时，自动淘汰最久未使用的缓存条目

#### 2.9.4 预测日志

记录字段：日志ID、算法ID、用户ID、原始文件信息、预测文件信息、处理时间、创建时间

### 2.10 效果评估计算 (F-M05-010)

#### 2.10.1 功能描述

根据预测图像和参考图像计算图像质量指标，支持多种评估指标的计算，提供评估结果的可视化展示。

#### 2.10.2 评估指标

| 指标名称 | 英文名称 | 说明 | 取值范围 |
|---------|---------|------|---------|
| 峰值信噪比 | PSNR | 衡量图像质量的常用指标 | 越高越好（通常>30dB为好） |
| 结构相似性 | SSIM | 衡量结构相似性的指标 | 0-1，越接近1越好 |
| 学习感知图像块相似度 | LPIPS | 基于深度学习的感知相似度指标 | 0-1，越低越好 |
| 信息熵 | Entropy | 衡量信息丰富度 | 越高越好 |
| 自然图像质量评价 | NIQE | 无参考质量评价 | 越低越好 |

#### 2.10.3 评估流程

```mermaid
graph TD
    A[选择预测图像和参考图像] --> B[调用效果评估接口]
    B --> C[验证参数有效性]
    C --> D{检查缓存?}
    D -->|有缓存| E[返回缓存结果]
    D -->|无缓存| F[调用Python服务评估]
    F --> G[计算图像质量指标]
    G --> H[PSNR计算]
    H --> I[SSIM计算]
    I --> J[其他指标计算]
    J --> K[保存评估结果]
    K --> L[记录评估日志]
    L --> M[返回评估结果]
    E --> N[前端展示评估结果]
    M --> N
```

#### 2.10.4 缓存机制

**缓存策略**：LRU（最近最少使用）淘汰机制

**验收口径**：
- 相同预测图像 + 相同参考图像的重复评估请求应命中缓存
- 评估结果应永久有效
- 缓存空间不足时，自动淘汰最久未使用的缓存条目

#### 2.10.5 评估日志

记录字段：日志ID、算法ID、用户ID、预测文件信息、参考文件信息、处理时间、评估结果JSON、创建时间
