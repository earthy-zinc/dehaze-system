## 1. 测试策略

### 1.1 改造目标

引入 Repository 模式和依赖注入后，测试能力显著提升：

| 测试层级 | 改造前 | 改造后 |
|----------|--------|--------|
| **Repository 单元测试** | ❌ 不存在此层 | ✅ 使用 SQLite 内存库验证 GORM 操作 |
| **Service 单元测试** | ❌ 必须连接真实 DB/Redis | ✅ Mock Repository/Cache，纯逻辑测试 |
| **API 单元测试** | ❌ 必须启动完整应用 | ✅ Mock Service，隔离测试 |
| **集成测试** | ✅ 使用测试数据库 | ✅ 使用真实 Repository + 测试数据库 |

### 1.2 测试分层架构

四层架构对应四层测试策略：

```
┌─────────────────────────────────────────────────────────────────┐
│                        E2E 测试（可选）                          │
│                   完整流程验证，启动真实服务                       │
└─────────────────────────────────────────────────────────────────┘
                                ▲
┌─────────────────────────────────────────────────────────────────┐
│                        集成测试                                  │
│         真实 Repository + SQLite，验证多层协作                    │
└─────────────────────────────────────────────────────────────────┘
                                ▲
┌─────────────────────────────────────────────────────────────────┐
│                   Service 单元测试（重点）                        │
│            Mock Repository/Cache，隔离测试业务逻辑                │
└─────────────────────────────────────────────────────────────────┘
                                ▲
┌─────────────────────────────────────────────────────────────────┐
│                   Repository 单元测试                            │
│              SQLite 内存库，验证 GORM 操作正确性                  │
└─────────────────────────────────────────────────────────────────┘
```

### 1.3 各层测试职责

| 层级 | 测试重点 | Mock 策略 | 数据库 |
|------|----------|-----------|--------|
| **Repository** | GORM 操作、SQL 逻辑、软删除 | 不 Mock | SQLite 内存库 |
| **Service** | 业务逻辑、规则校验、异常处理 | Mock Repository/Cache | 无 |
| **API** | 参数验证、响应格式、错误码 | Mock Service | 无 |
| **集成** | 多层协作、事务、端到端流程 | 不 Mock | SQLite 或测试 MySQL |

## 2. Repository 层测试

### 2.1 测试目标

Repository 层直接操作 GORM，测试重点：
- CRUD 操作正确性
- 软删除条件是否统一应用
- 分页、排序逻辑
- 复杂查询条件

### 2.2 测试方法

使用 SQLite 内存数据库，无需 Mock，直接验证 SQL 执行结果。

**优点**：
- 真实执行 SQL，发现 GORM 用法错误
- 内存数据库速度快，测试隔离性好
- 每个测试前重建表结构，数据互不干扰

### 2.3 测试示例

```go
// internal/repository/user_repo_test.go
type UserRepoTestSuite struct {
    suite.Suite
    db   *gorm.DB
    repo IUserRepository
}

func (s *UserRepoTestSuite) SetupTest() {
    db, _ := gorm.Open(sqlite.Open(":memory:"), &gorm.Config{})
    db.AutoMigrate(&model.SysUser{})
    s.db = db
    s.repo = NewUserRepository(db)
}

func (s *UserRepoTestSuite) TestFindByID_SoftDeleteFiltered() {
    ctx := context.Background()
    
    // 创建一条已删除的记录
    s.db.Create(&model.SysUser{ID: 1, Username: "deleted", Deleted: 1})
    
    // 查询应返回 nil（软删除过滤）
    user, err := s.repo.FindByID(ctx, 1)
    
    s.NoError(err)
    s.Nil(user, "软删除记录应被过滤")
}
```

### 2.4 测试场景清单

| 方法 | 必测场景 |
|------|----------|
| `FindByID` | 记录存在、记录不存在、软删除过滤 |
| `List` | 分页正确、条件过滤、排序、空结果 |
| `Create` | 正常创建、唯一约束冲突 |
| `Update` | 部分字段更新、乐观锁（如有） |
| `Delete` | 软删除标记正确 |

## 3. Service 层测试

### 3.1 测试目标

Service 层承载核心业务逻辑，测试重点：
- 业务规则校验（如密码比对、状态检查）
- 多 Repository 协作逻辑
- 缓存策略（先查缓存、缓存失效）
- 异常处理和错误返回

### 3.2 Mock 策略

Mock 所有依赖（Repository、Cache），隔离测试纯业务逻辑。

使用 `mockery` 自动生成：
```bash
mockery --dir=internal/repository --name=IUserRepository --output=internal/repository/mock
mockery --dir=internal/cache --name=ICacheService --output=internal/cache/mock
```

### 3.3 测试示例

```go
// service/user_service_test.go
func TestUserService_Login_Success(t *testing.T) {
    ctx := context.Background()
    hashedPwd, _ := bcrypt.GenerateFromPassword([]byte("password123"), bcrypt.DefaultCost)

    mockUserRepo := new(repomock.MockUserRepository)
    mockUserRepo.On("FindByUsername", ctx, "admin").Return(&model.SysUser{
        ID: 1, Username: "admin", Password: string(hashedPwd), Status: 1,
    }, nil)

    mockRoleRepo := new(repomock.MockRoleRepository)
    mockRoleRepo.On("FindByUserID", ctx, int64(1)).Return([]*model.SysRole{{Code: "ADMIN"}}, nil)

    mockCache := new(cachemock.MockCacheService)
    mockCache.On("Set", ctx, mock.Anything, mock.Anything, mock.Anything).Return(nil)

    svc := NewUserService(mockUserRepo, mockRoleRepo, mockCache, zap.NewNop())

    result, err := svc.Login(ctx, "admin", "password123")

    assert.NoError(t, err)
    assert.Equal(t, "admin", result.Username)
    mockUserRepo.AssertExpectations(t)
}
```

### 3.4 测试场景清单

每个核心方法至少覆盖：

| 场景类型 | 示例 |
|----------|------|
| **正常路径** | 登录成功、创建成功 |
| **业务异常** | 用户不存在、密码错误、账号禁用 |
| **边界条件** | 空参数、超长字符串 |
| **依赖异常** | Repository 返回错误、缓存不可用 |

## 4. API 层测试

### 4.1 测试目标

API 层测试重点：
- 参数绑定和验证
- 响应格式和错误码
- 中间件行为（如权限校验）

### 4.2 测试方法

Mock Service 接口，使用 `httptest` 模拟 HTTP 请求。

### 4.3 测试示例

```go
// api/user_api_test.go
func TestSysUserApi_ListPagedUsers_ParamError(t *testing.T) {
    mockService := new(servicemock.MockUserService)
    api := NewSysUserApi(mockService)

    router := gin.New()
    router.GET("/users", api.ListPagedUsers)

    req, _ := http.NewRequest("GET", "/users?pageNum=abc", nil)  // 参数错误
    resp := httptest.NewRecorder()
    router.ServeHTTP(resp, req)

    assert.Equal(t, 400, resp.Code)
    assert.Contains(t, resp.Body.String(), "参数错误")
}
```

## 5. 集成测试

### 5.1 测试目标

验证多层协作：
- Repository → Service 数据流转
- 事务提交/回滚
- 端到端业务流程

### 5.2 测试基类

```go
// test/integration/base.go
type BaseTestSuite struct {
    suite.Suite
    DB          *gorm.DB
    Container   *container.Container
}

func (s *BaseTestSuite) SetupSuite() {
    db, _ := gorm.Open(sqlite.Open(":memory:"), &gorm.Config{})
    db.AutoMigrate(&model.SysUser{}, &model.SysRole{})
    s.DB = db

    // 使用真实 Repository + 内存 Cache
    s.Container = container.NewTestContainer(db)
}

func (s *BaseTestSuite) TearDownTest() {
    s.DB.Exec("DELETE FROM sys_users")
}
```

### 5.3 测试示例

```go
// test/integration/user_flow_test.go
func (s *UserFlowTestSuite) TestCreateAndLogin() {
    ctx := context.Background()

    // 创建用户
    err := s.Container.UserService.CreateUser(ctx, &bo.UserFormBO{
        Username: "newuser", Password: "password123",
    })
    s.NoError(err)

    // 登录验证
    result, err := s.Container.UserService.Login(ctx, "newuser", "password123")
    s.NoError(err)
    s.Equal("newuser", result.Username)
}
```
