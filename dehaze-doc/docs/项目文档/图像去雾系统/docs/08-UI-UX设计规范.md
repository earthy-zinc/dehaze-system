## 一、设计原则

### 1.1 核心设计原则

**平台无关性（Platform Agnostic）**

- 基于Web标准技术，确保跨平台一致性
- 使用响应式设计，自适应不同设备和屏幕
- 避免平台特定的UI模式，采用通用交互范式
- 通过渐进增强策略，在各平台提供最佳体验

**简洁高效**

- 界面简洁清晰，避免冗余元素
- 操作流程简短，减少用户学习成本
- 信息层级分明，重点突出
- 单页应用架构，页面切换流畅无刷新

**专业可靠**

- 专业的视觉呈现，采用现代渐变和阴影系统
- 准确的数据展示，支持多维度指标评估
- 可靠的功能体验，完整的错误处理和状态反馈

**友好易用**

- 符合用户习惯的交互，支持触控和鼠标操作
- 清晰的操作反馈，视觉、触觉、听觉多维度反馈
- 友好的错误提示，提供解决方案和重试机制
- 智能设备检测，自动优化交互方式

**美观现代**

- 现代化的视觉风格，借鉴Apple设计语言
- 流畅的动画效果，基于性能分级优化
- 精致的细节处理，圆角、阴影、渐变统一规范

### 1.2 设计目标

- **效率优先**：让用户快速完成任务，单页应用架构减少页面跳转
- **体验流畅**：提供流畅的操作体验，60fps动画性能目标
- **信息清晰**：信息展示清晰易懂，采用卡片式布局和视觉层级
- **视觉统一**：保持视觉风格统一，模块化CSS架构确保一致性
- **全平台兼容**：在iOS、Android、Windows、Mac等平台提供一致体验
- **性能优化**：根据设备性能自动调整动画复杂度和渲染策略

### 2.2 字体规范

#### 2.2.1 字体家族（跨平台系统字体栈）

**统一字体栈（基于实际代码）**

```css
font-family: -apple-system, BlinkMacSystemFont, 'Segoe UI', 
             'PingFang SC', 'Hiragino Sans GB', 
             'Microsoft YaHei', sans-serif;
```

**平台回退策略**

- **iOS/Mac**: -apple-system (San Francisco)
- **Android**: Roboto (通过BlinkMacSystemFont)
- **Windows**: Segoe UI
- **中文优先**: PingFang SC (Mac) → Hiragino Sans GB (旧版Mac) → Microsoft YaHei (Windows)
- **通用回退**: sans-serif

**特点**

- 自动适配各平台原生字体
- 无需加载外部字体文件，性能最优
- 保持各平台原生视觉风格
- 中英文混排优化

### 2.5 阴影规范（基于实际代码）

**阴影层级**

| 层级    | 阴影值                       | Tailwind类 | 用途             |
| ------- | ---------------------------- | ---------- | ---------------- |
| Level 1 | 0 2px 8px rgba(0,0,0,0.08)   | shadow-sm  | 卡片、按钮       |
| Level 2 | 0 4px 12px rgba(0,0,0,0.15)  | shadow-md  | 悬浮卡片、工具栏 |
| Level 3 | 0 8px 24px rgba(0,0,0,0.12)  | shadow-lg  | 对话框、侧边菜单 |
| Level 4 | 0 12px 24px rgba(0,0,0,0.15) | shadow-xl  | 悬停增强效果     |
| Level 5 | 0 16px 32px rgba(0,0,0,0.16) | shadow-2xl | 模态框、顶层元素 |

**响应式阴影策略**

- **移动端**：使用较浅阴影（Level 1-2），避免视觉过重
- **PC端**：使用较深阴影（Level 2-4），增强层次感
- **悬停效果**：PC端悬停时阴影加深，提升交互反馈
- **性能优化**：低性能设备减少阴影复杂度

**特殊阴影**

- 底部导航：`0 -2px 8px rgba(0,0,0,0.1)` (向上投影)
- 顶部Header：`shadow-lg` (固定定位增强)

## 四、响应式设计

### 4.1 断点定义（基于实际代码）

| 断点 | 宽度范围    | 设备类型 | layoutManager检测 | CSS Media Query                         |
| ---- | ----------- | -------- | ----------------- | --------------------------------------- |
| XS   | ≤375px      | 小屏手机 | phone-small       | max-width: 375px                        |
| SM   | 376-767px   | 标准手机 | phone             | min-width: 376px and max-width: 767px   |
| MD   | 768-1023px  | 平板     | tablet            | min-width: 768px and max-width: 1023px  |
| LG   | 1024-1439px | PC小屏   | desktop-small     | min-width: 1024px and max-width: 1439px |
| XL   | 1440-1919px | PC标准   | desktop           | min-width: 1440px and max-width: 1919px |
| 2XL  | 1920-2559px | PC大屏   | desktop           | min-width: 1920px and max-width: 2559px |
| 3XL  | ≥2560px     | PC超大屏 | desktop           | min-width: 2560px                       |

**设备检测策略**

- 使用`layoutManager.js`模块进行智能设备检测
- 结合屏幕宽度、UserAgent、触控支持等多维度信息
- 动态添加CSS类名：`device-{type}`、`orientation-{landscape|portrait}`
- 支持实时响应窗口大小和方向变化

### 4.2 设备适配策略

#### 4.2.1 手机竖屏（默认）

**布局特点**

- 单列垂直流布局，充分利用纵向空间
- 底部导航栏（64px高），固定定位
- 主内容区下内边距72px，避免被导航栏遮挡
- 功能卡片单列布局，间距12px

**交互优化**

- 拇指热区优化：按钮最小48px高度
- 单手操作友好：底部导航位于拇指可达区域
- 手势操作支持：左右滑动切换页面
- 触控反馈：点击缩放效果（scale 0.95）

**实际CSS实现**

```css
@media (min-width: 376px) and (max-width: 767px) {
  main { padding: 12px; padding-bottom: 72px; }
  nav { height: 64px; }
  .btn { min-height: 48px; border-radius: 12px; }
}
```

#### 4.2.2 手机横屏

**布局特点**

- 紧凑型横向布局，最大化内容展示
- 底部导航栏压缩至48px，紧凑模式
- Header压缩，图标和文字减小
- 卡片间距减小至12px
- 图片对比区域高度限制250-300px

**交互优化**

- 左右滑动切换页面，支持手势导航
- 双手操作优化，工具栏横向滚动
- 快捷手势支持，滑动阈值50px
- 按钮和文字进一步缩小，避免占用过多空间

**实际CSS实现**

```css
@media (orientation: landscape) and (max-height: 600px) {
  .app-header .container { padding: 6px 12px; }
  nav { height: 3rem; }
  .card { padding: 0.75rem; }
  .image-grid img { max-height: 250px; }
}
```

#### 4.2.3 平板竖屏

**布局特点**

- 充分利用纵向空间，单列布局
- 功能卡片双列布局（grid-cols-2）
- 底部导航栏64px，图标和文字适度增大
- 侧边菜单宽度360px，更好利用屏幕宽度

**交互优化**

- 增大触控目标：按钮最小48px高度
- 优化触控间距：卡片间距16px
- 支持手势操作：滑动、缩放、长按
- 支持分屏多任务（浏览器原生支持）

**实际CSS实现**

```css
@media (min-width: 768px) and (max-width: 1023px) and (orientation: portrait) {
  main { padding: 16px; padding-bottom: 80px; }
  .feature-grid { grid-template-columns: repeat(2, 1fr); }
  .btn { min-height: 48px; padding: 14px 24px; }
}
```

#### 4.2.4 平板横屏

## 七、性能优化规范

### 7.1 性能分级策略

#### 7.1.1 性能检测

**检测指标**

```javascript
const cores = navigator.hardwareConcurrency || 2;
const memory = navigator.deviceMemory || 4;
const deviceType = layoutManager.deviceType;
```

**分级标准**

- **高性能**：PC端 + 4核+ + 8GB+
- **中等性能**：2核+ + 4GB+
- **低性能**：其他设备

#### 7.1.2 动画优化

**高性能设备**

```css
.full-animations .feature-card {
  transition: all 0.3s cubic-bezier(0.4, 0, 0.2, 1);
}
```

**中等性能设备**

```css
.simplified-animations .feature-card:hover {
  transform: translateY(-4px);
}
```

**低性能设备**

```css
.reduce-animations * {
  animation-duration: 0.1s !important;
  transition-duration: 0.1s !important;
}
```

### 7.2 加载优化

#### 7.2.1 资源加载策略

**关键资源**

- Tailwind CSS：CDN加载，全局缓存
- Font Awesome：CDN加载，全局缓存
- 系统字体：无需加载，直接使用

**模块化加载**

- CSS模块化：7个独立模块
- JS模块化：ES6 Module按需加载
- 图片懒加载：使用Intersection Observer

#### 7.2.2 渲染优化

**首屏优化**

- 关键 CSS inline
- 首屏内容优先渲染
- 骨架屏占位
- 延迟加载非关键资源

**滚动优化**

- 虚拟滚动（大列表）
- 防抖处理
- 节流处理
- 无限滚动分页

### 7.3 交互性能

#### 7.3.1 响应时间目标

| 操作类型 | 目标时间 | 用户感知     |
| -------- | -------- | ------------ |
| 点击反馈 | <100ms   | 即时响应     |
| 页面切换 | <300ms   | 流畅切换     |
| 数据加载 | <1s      | 可接受等待   |
| 图片处理 | <3s      | 需要进度提示 |

#### 7.3.2 动画性能

**60fps目标**

- 使用transform和opacity
- 避免布局抖动（Layout Thrashing）
- 使用will-change提示
- GPU加速动画

**性能监控**

```javascript
// 帧率监控
const fps = 1000 / (performance.now() - lastTime);

// 长任务监控
const observer = new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    if (entry.duration > 50) {
      console.warn('Long task detected:', entry);
    }
  }
});
```
