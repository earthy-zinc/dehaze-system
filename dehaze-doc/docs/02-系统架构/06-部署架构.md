# 部署架构

## 1. 文档概述

### 1.1 文档目的

描述图像去雾系统的部署架构设计，包括部署模式、环境规划、服务编排和监控体系。

### 1.2 适用范围

本文档适用于运维人员、DevOps 工程师和需要进行系统部署的开发人员。

## 5. 请求路由

### 5.1 路由规则

**入口访问**：前端静态资源（Vue/React）与后端 API 由各前端构建产物按环境配置访问（开发环境直连各后端端口，生产环境经反向代理统一入口）。

**静态文件服务**（`nginx-dataset` 容器，端口 9000，配置见 `config/nginx/dataset.conf`）：

| 路径前缀 | 服务内容 | 说明 |
|---------|---------|------|
| `/datasets/*` | 数据集图片 | 托管 `datasets/` 目录，URL：`http://{host}:9000/datasets/{path}` |
| `/models/*` | 模型权重 | 托管 `models/` 目录，URL：`http://{host}:9000/models/{path}` |
| `/` | 静态文件根 | 仅精确匹配，防目录遍历 |

> 该静态服务配置 CORS 通配（GET/OPTIONS）、图片 7 天缓存、隐藏文件拒绝访问；后端文件上传（用户结果图等）走 MinIO（9110），二者职责分离。

### 5.2 特殊配置

| 配置项 | 值 | 说明 |
|--------|-----|------|
| 请求体大小限制 | 100MB | 支持大文件上传 |
| 算法接口超时 | 300s | 去雾处理耗时较长 |
| WebSocket | 支持 | 实时进度推送（消息通知模块） |

## 6. CI/CD 流程

### 6.1 流程概览

```
代码提交 → 代码构建 → 自动化测试 → 打包制品 → 自动部署 → 验证测试 → 发布上线
```

### 6.2 构建产物

| 项目 | 构建命令 | 产物 |
|------|---------|------|
| **Vue 前端** | `pnpm build:prod` | `dist/` 目录 |
| **React 前端** | `pnpm build` | `dist/` 目录 |
| **Java 后端** | `mvn package` | `target/*.jar` |
| **Go 后端** | `go build` | 二进制（Linux amd64） |
| **Python 后端** | - | 源码 + `requirements.txt`（含算法服务） |

### 6.3 部署检查清单

- [ ] 环境变量已配置（数据库密码、密钥等）
- [ ] 数据库已初始化
- [ ] 存储目录已挂载
- [ ] ES 启动后执行 `bash scripts/init-security.sh` 初始化安全（设置 kibana_system / logstash_system / beats_system 密码 + 生成 Alertmanager 凭证）
- [ ] 端口未被占用
- [ ] 健康检查通过
- [ ] 时区已固化 Asia/Shanghai（见 6.4，策略定义见 API 规范 §6.2）

### 6.4 时区部署要求

服务端统一 **Asia/Shanghai (UTC+8)**（API 规范 §6.2），部署时需显式固化，防止容器默认 UTC 导致三端写入/展示错位：
- **应用容器/进程**：`TZ=Asia/Shanghai` 环境变量（Docker Compose `environment:` 或 K8s env）；Java 进程追加 `-Duser.timezone=Asia/Shanghai`，保证 `datetime.now()` / `time.Now()` / `LocalDateTime.now()` 语义一致
- **MySQL**：`default-time-zone='+08:00'`（my.cnf 或容器 `command: --default-time-zone=+08:00`），当前开发实例为 `SYSTEM`/CST 等价
- 三端连接层已固化（Python `init_command=SET time_zone='+08:00'`、Go DSN `loc=Asia/Shanghai`、Java `serverTimezone=Asia/Shanghai`），读回解释不再依赖服务器 SYSTEM

## 7. 监控与告警

### 7.1 监控体系

```
应用服务 → 指标采集(Prometheus) → 存储(TSDB) → 可视化(Grafana)
    ↓
日志输出 → 日志采集(Filebeat) → 管道(Logstash) → 存储(ES) → 分析(Kibana)
    ↓
异常检测 → 告警管理(AlertManager) → 通知(邮件/钉钉)
```

- 指标：Prometheus 抓取三端 `/metrics` 及各 Exporter，Grafana 自动加载 `config/grafana/dashboards/` 下的面板（Dehaze 文件夹）
- 日志：
  - **后端日志**：Filebeat 采集三端 `logs/{yyyy-MM-dd}/*.log`（NDJSON 解析，`fields.service: java/python/go`）→ Logstash → ES 索引 `dehaze-logs-{yyyy.MM.dd}`
  - **前端日志**：前端 SDK 批量上报 `POST /api/v1/logs/client` → 后端写 `logs/{yyyy-MM-dd}/client.log` → Filebeat 新增 filestream input（`fields.service: client`）→ Logstash 按 `fields.service` 分流 → ES 索引 `dehaze-client-logs-{yyyy.MM.dd}`
  - Kibana 分别建 `dehaze-logs-*` / `dehaze-client-logs-*` 索引模式；以 `trace_id` 可跨索引串联前后端日志
- 链路追踪：SkyWalking OAP（11800 gRPC / 12800 HTTP）采集三端 Agent 上报的调用链，UI 访问 `http://{host}:18080`，存储复用 ES（`SW_STORAGE=elasticsearch`，保留 7 天）
- 告警：Prometheus 按 `config/prometheus/rules/dehaze-alerts.yml` 评估，推送 AlertManager（`config/alertmanager/alertmanager.yml` 配置邮件通知，支持钉钉/企业微信 Webhook 扩展）

### 7.2 关键告警指标

告警规则已实现于 `config/prometheus/rules/dehaze-alerts.yml`：

| 指标 | 阈值 | 持续 | 级别 |
|------|------|------|------|
| CPU 使用率 | > 85% | 5min | warning |
| 内存使用率 | > 90% | 5min | critical |
| 磁盘使用率 | > 85% | 10min | warning |
| 服务宕机 | up == 0 | 1min | critical |
| Java 5xx 错误率 | > 5% | 2min | critical |
| P99 延迟 | > 5s | 5min | warning |
| MySQL 连接数 | > 80% max | 3min | warning |
| Redis 内存 | > 80% maxmemory | 5min | warning |

> 部署前需将 `config/alertmanager/alertmanager.yml` 中的 SMTP 占位配置替换为真实值。
>
> Alertmanager 已启用 Basic Auth（账号 `admin` / 密码 `${ALERTMANAGER_PASSWORD}`），凭证文件 `config/alertmanager/web.yml` 由 `scripts/init-security.sh` 生成（bcrypt）；Prometheus 在 `prometheus.yml` 中以 `basic_auth` 携带该凭证推送告警（密码经启动脚本从 `__ALERTMANAGER_PASSWORD__` 占位符替换，因 prometheus.yml 不支持环境变量）。

### 7.3 业务指标命名规范

三端业务指标统一 `dehaze_` 前缀，跨端聚合面板（`Dehaze 业务监控`）基于以下命名：

| 维度 | 指标 | 埋点端 |
|------|------|--------|
| 预测 | `dehaze_prediction_total{status}`、`dehaze_prediction_duration_seconds` | Java、Go |
| 推理（算法侧） | `dehaze_inference_requests_total{algorithm,status}`、`dehaze_inference_duration_seconds` | Python |
| 评估 | `dehaze_evaluation_total{status}`、`dehaze_evaluation_duration_seconds` | Java、Go |
| 任务 | `dehaze_task_total{task_type,status}`、`dehaze_task_duration_seconds` | Java、Go、Python |
| 缓存 | `dehaze_cache_hits_total{layer}`、`dehaze_cache_misses_total{layer}`、`dehaze_cache_loader_total` | Go、Python |
| GPU | `dehaze_gpu_*`（利用率/显存/温度/功耗） | Python（算法服务独有） |
| 文件上传 | `dehaze_file_upload_total` | Java |
| HTTP 请求 | `http_server_requests_seconds`（Java/Go）、`http_request_duration_seconds`（Python） | 三端 |

### 7.4 日志规范

日志的存储/切割/保留、字段 schema、请求上下文注入、分类与内容规范统一见 [`07-日志架构设计.md`](./07-日志架构设计.md)，其中 §3.5 记录前端日志（client）的接收链路与字段规范要点。日志采集链路（Filebeat → Logstash → ES → Kibana）见 §7.1。

## 9. 安全加固

### 9.1 网络安全

| 措施 | 说明 |
|-----|------|
| 防火墙规则 | 仅开放必要端口（80/443） |
| 内网隔离 | 数据库等服务仅内网访问 |
| HTTPS | 生产环境强制 HTTPS |
| WAF | Web 应用防火墙防护 |
| Elasticsearch 认证 | `xpack.security.enabled=true`，elastic 超级用户密码 = `${ES_PASSWORD}`，HTTP 层关闭 SSL 保持内网 http 访问 |
| Alertmanager 认证 | 启用 Basic Auth（账号 `admin` / 密码 `${ALERTMANAGER_PASSWORD}`），容器启动时动态生成 bcrypt 凭证；Prometheus 推送告警需同步配置 `basic_auth` |

### 9.2 部署安全检查清单

- [ ] 修改默认密码（MySQL、Redis、MinIO 等）
- [ ] 配置 HTTPS 证书
- [ ] 限制数据库远程访问
- [ ] 配置防火墙规则
- [ ] 启用日志审计
- [ ] 定期更新系统和依赖
- [ ] 容器使用非 root 用户运行
