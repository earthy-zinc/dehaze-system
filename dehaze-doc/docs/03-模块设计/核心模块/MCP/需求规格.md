# MCP 能力网关模块需求规格

## 1. 模块概述

### 1.0 概念界定（先读）

MCP（Model Context Protocol）是连接 AI 应用（MCP 客户端）与工具服务（MCP Server）的开放标准协议。**任何符合 MCP 协议的服务都可以被 MCP 客户端接入调用**——协议本身是通用的，与本项目实现无关。

本项目中 MCP 落地为两条独立通道，术语严格区分、不可混用：

| 术语 | 实现 | 方向 | 说明 |
|------|------|------|------|
| **内部 MCP 能力网关** | `dehaze-mcp-gateway`（本项目自建 MCP Server） | 系统能力出口 | 读取后端 OpenAPI，以 3 个元 tool（`lookup_tool`/`lookup_tool_param_schema`/`execute_tool`）把系统 API 暴露给大模型。**本文档仅覆盖此通道** |
| **MCP Server 管理** | AI 对话模块能力扩展域（`sys_ai_mcp_server`/`sys_ai_mcp_namespace`/`sys_ai_mcp_tool`/`sys_ai_mcp_call` 四表 + `AiMcpServerService`/`McpManageService`） | 外部能力进口 | 管理员注册任意符合 MCP 协议的第三方服务（GitHub/数据库/搜索/浏览器等），支持 stdio/streamable-http/sse 三种传输协议、凭据 AES 加密、健康探测、`tools/list` 工具清单拉取、命名空间授权 |

两条通道互不替代，都作为 Agent 的工具来源统一纳入命名空间预筛选，详见 [AI对话/能力扩展/需求规格.md](../AI对话/能力扩展/需求规格.md) §2.6.13 与 [AI对话/能力扩展/后端实现.md](../AI对话/能力扩展/后端实现.md) §5。

dehaze-python 推理引擎在两条通道中都是 **MCP 客户端**：对内部能力网关经 `McpGatewayClient` 连接（JSON-RPC 调元 tool），对外部 Server 经 `McpToolFetcher` 连接（标准 `tools/list`/`tools/call`）。

### 1.1 模块定位

内部 MCP 能力网关是一个轻量协议适配器，基于 [MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk) 构建。它读取后端 OpenAPI 文档，通过 **3 个元 tool** 供大模型按需发现和调用后端 API。

**核心设计**：不把每个 API 注册为独立 MCP tool（后端 API 成百上千时会导致 LLM 上下文爆炸），而是暴露 3 个元 tool，LLM 通过它们按需发现、理解、调用任意后端 API。

**不是什么**：内部 MCP 能力网关不是 API 网关——不做认证校验、限流、VIP 过滤、结果缓存，这些是后端职责。它只做协议转换：MCP JSON-RPC ↔ HTTP REST。"能力网关"的"网关"指它是**系统内部能力对大模型暴露的统一出口**，而非承担流量治理职能的 API 网关。

### 1.2 核心价值

| 价值 | 说明 |
|------|------|
| 自动发现 | 读取后端 OpenAPI，自动解析 API 供大模型发现（OpenAPI 在网关启动时一次性加载，见 §2.3.1；新增 API 后重启网关即生效，无定时同步） |
| 零代码接入 | 后端新增 API 后无需修改网关与 AI 对话模块代码，重启网关自动发现 |
| 上下文友好 | 无论后端多少 API，MCP 只暴露 3 个元 tool，上下文占用固定 |
| 认证透传 | 透传 API Key 到后端，后端负责校验和鉴权 |

### 1.3 工作原理

```
AI 对话模块 LLM  <--JSON-RPC 2.0 / HTTP-->  MCP 工具  <--HTTP + API Key-->  后端 API
                                                ↓
                                         读取 OpenAPI 文档
                                         解析为内部 API 注册表
```

LLM 调用流程：
1. `lookup_tool("去雾预测")` → 发现可用 API（工具名 + 描述 + 参数名概要）
2. `lookup_tool_param_schema("post_api_v1_prediction")` → 查看完整参数定义（类型/必填/枚举/嵌套示例）
3. `execute_tool("post_api_v1_prediction", '{"algorithmId": 1, ...}')` → 执行调用

> Java/Go/Python 三端后端 API 完全相同，MCP 工具只需读取 Java 端 OpenAPI 文档即可覆盖全部 API。

### 1.4 依赖关系

| 模块 | 依赖说明 |
|------|---------|
| 认证管理 | 透传 API Key（`dhak_` 前缀），后端负责校验 |
| AI 对话模块 | 调用方，通过 MCP 客户端连接 |

## 2. 功能需求

### 2.1 协议服务 (F-M07-001)

基于 MCP Python SDK 的 MCPServer，使用 Streamable HTTP 传输（`POST /mcp`），SDK 内置 JSON-RPC 2.0 解析/路由/错误码、`@mcp.tool()` 装饰器自动生成 JSON Schema 和参数校验（协议通用事实见 [02-系统架构/04-API规范.md](../../../02-系统架构/04-API规范.md)）。

本模块暴露 3 个元 tool，通过 MCP 标准方法 `initialize`（能力协商）、`tools/list`（返回元 tool 定义）、`tools/call`（调用元 tool）对外提供服务。

### 2.2 三个元 tool

| 元 tool | 职责 | 关键参数 |
|---------|------|---------|
| `lookup_tool` | **发现**：搜索后端 API | `query`（搜索关键词） |
| `lookup_tool_param_schema` | **理解**：查看 API 完整参数定义 | `tool_name` |
| `execute_tool` | **执行**：调用 API | `tool_name` + `arguments`（JSON 字符串） |

三个元 tool 的分词、计分、校验、返回结构等实现细节见 [后端实现.md §5](./后端实现.md)。

### 2.3 API 解析与过滤

#### 2.3.1 启动加载

启动时一次性读取后端 OpenAPI 文档，解析为内部 API 注册表（含方法/路径/参数/描述/命名空间）。

#### 2.3.2 API 过滤

| 过滤规则 | 说明 |
|---------|------|
| HTTP 方法过滤 | 仅保留 GET/POST/PUT/PATCH，排除 DELETE 等危险操作 |
| 参数类型过滤 | 排除含 binary/file 类型参数的 API |
| 显式排除列表 | 排除登录/注册/上传等不适合 LLM 调用的接口（路径后缀匹配） |

#### 2.3.3 Tool 命名规则

```
POST /api/v1/prediction         -> post_api_v1_prediction
PUT  /api/v1/presets/{id}       -> put_api_v1_presets_by_id
GET  /api/v1/prediction/{taskId}-> get_api_v1_prediction_by_taskid
```

path 中 `{placeholder}` 替换为 `by_xxx`（统一小写），tool name 取 `{method}_{path_segments_joined}`。

### 2.4 请求转发与响应转换 (F-M07-004)

#### 2.4.1 请求转换

LLM 传入参数按 OpenAPI 定义的参数位置（path/query/body）映射为 HTTP 请求，API Key 以 `Authorization: Bearer dhak_xxx` 透传到后端（后端负责校验、鉴权和配额扣减）。映射契约见 [API接口.md §2.4](./API接口.md)。

#### 2.4.2 响应转换

响应转换规则（HTTP 200/超长截断/4xx/5xx）以 [API接口.md §2.4](./API接口.md) 契约为准。

## 3. 配置

环境变量及默认值定义见 [后端实现.md §6](./后端实现.md)。server 模式可通过请求头 `x-backend-url` / `x-dehaze-api-key` 覆盖后端地址和 API Key；CLI 模式通过环境变量传递配置。

## 4. 运行管理

通过 `scripts/run.py` 统一管理：

```
python3 scripts/run.py start/stop/restart mcp
python3 scripts/run.py ps
python3 scripts/run.py logs mcp
```

CLI 模式：

```
cd dehaze-mcp-gateway
uv run python server.py cli lookup <keyword>
uv run python server.py cli schema <tool_name>
uv run python server.py cli execute <tool_name> '{"key":"value"}'
uv run python server.py cli list
```
