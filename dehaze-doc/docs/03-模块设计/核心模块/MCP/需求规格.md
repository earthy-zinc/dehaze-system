# MCP 能力网关模块需求规格

## 1. 模块概述

### 1.1 模块定位

MCP（Model Context Protocol）工具是一个轻量协议适配器，基于 [MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk) 构建。它读取后端 OpenAPI 文档，通过 **3 个元 tool** 供大模型按需发现和调用后端 API。新增 API 后无需修改 MCP 层代码，工具自动发现。

**核心设计**：不把每个 API 注册为独立 MCP tool（后端 API 成百上千时会导致 LLM 上下文爆炸），而是暴露 3 个元 tool，LLM 通过它们按需发现、理解、调用任意后端 API。

**不是什么**：MCP 工具不是网关，不做认证校验、限流、VIP 过滤、结果缓存。这些是后端职责。MCP 工具只做协议转换：MCP JSON-RPC ↔ HTTP REST。

### 1.2 核心价值

| 价值 | 说明 |
|------|------|
| 自动发现 | 读取后端 OpenAPI，自动解析 API 供大模型发现 |
| 零配置接入 | 后端新增 API 后 MCP 工具自动发现，无需修改代码 |
| 上下文友好 | 无论后端多少 API，MCP 只暴露 3 个元 tool，上下文占用固定 |
| 认证透传 | 透传 API Key 到后端，后端负责校验和鉴权 |

### 1.3 工作原理

```
AI 对话模块 LLM  <--JSON-RPC 2.0 / HTTP-->  MCP 工具  <--HTTP + API Key-->  后端 API
                                                ↓
                                         读取 OpenAPI 文档
                                         解析为内部 API 注册表
```

LLM 调用流程：
1. `lookup_tool("去雾预测")` → 发现可用 API（工具名 + 描述 + 参数名概要）
2. `lookup_tool_param_schema("post_api_v1_prediction")` → 查看完整参数定义（类型/必填/枚举/嵌套示例）
3. `execute_tool("post_api_v1_prediction", '{"algorithmId": 1, ...}')` → 执行调用

> Java/Go/Python 三端后端 API 完全相同，MCP 工具只需读取 Java 端 OpenAPI 文档即可覆盖全部 API。

### 1.4 依赖关系

| 模块 | 依赖说明 |
|------|---------|
| 认证管理 | 透传 API Key（`dhak_` 前缀），后端负责校验 |
| AI 对话模块 | 调用方，通过 MCP 客户端连接 |

## 2. 功能需求

### 2.1 协议服务 (F-M07-001)

基于 MCP Python SDK 的 MCPServer，使用 Streamable HTTP 传输（`POST /mcp`），SDK 内置 JSON-RPC 2.0 解析/路由/错误码、`@mcp.tool()` 装饰器自动生成 JSON Schema 和参数校验。

| MCP 标准方法 | 说明 |
|-------------|------|
| `initialize` | 能力协商，返回 capabilities（tools） |
| `tools/list` | 返回 3 个元 tool 定义 |
| `tools/call` | 调用元 tool |

### 2.2 三个元 tool

| 元 tool | 职责 | 关键参数 |
|---------|------|---------|
| `lookup_tool` | **发现**：搜索后端 API | `query`（搜索关键词） |
| `lookup_tool_param_schema` | **理解**：查看 API 完整参数定义 | `tool_name` |
| `execute_tool` | **执行**：调用 API | `tool_name` + `arguments`（JSON 字符串） |

#### 2.2.1 lookup_tool

按关键词搜索后端 API，返回工具名、描述、参数名列表（`*` 标必填）。

分词方式：英文按单词，中文按双字 bigram（避免单字噪声导致误匹配）。加权计分（工具名+路径 > 参数名 > 接口描述 > namespace > 参数描述），得分按 query 词数归一化（长 query 需命中多数词才高分，避免宽泛召回），同分按工具名字典序稳定排序。无匹配时返回相近候选，引导 LLM 调整关键词。

#### 2.2.2 lookup_tool_param_schema

返回指定 API 的结构化 JSON：描述、HTTP 方法、路径、命名空间、每个参数的含义/位置/必填/示例、必填参数的完整 `arguments_example`（嵌套 object/array 结构直接可用）。

#### 2.2.3 execute_tool

调用指定 API，执行本地必填参数校验（缺失时报"缺少参数 X"），参数按 OpenAPI 定义映射到 path/query/body，透传 API Key。

### 2.3 API 解析与过滤

#### 2.3.1 启动加载

启动时一次性读取后端 OpenAPI 文档，解析为内部 API 注册表（含方法/路径/参数/描述/命名空间）。

#### 2.3.2 API 过滤

| 过滤规则 | 说明 |
|---------|------|
| HTTP 方法过滤 | 仅保留 GET/POST/PUT/PATCH，排除 DELETE 等危险操作 |
| 参数类型过滤 | 排除含 binary/file 类型参数的 API |
| 显式排除列表 | 排除登录/注册/上传等不适合 LLM 调用的接口（路径后缀匹配） |

#### 2.3.3 Tool 命名规则

```
POST /api/v1/prediction         -> post_api_v1_prediction
PUT  /api/v1/presets/{id}       -> put_api_v1_presets_by_id
GET  /api/v1/prediction/{taskId}-> get_api_v1_prediction_by_taskid
```

path 中 `{placeholder}` 替换为 `by_xxx`（统一小写），tool name 取 `{method}_{path_segments_joined}`。

### 2.4 请求转发与响应转换 (F-M07-004)

#### 2.4.1 请求转换

LLM 传入的参数按 OpenAPI 定义的参数位置分类映射：

| 参数位置 | HTTP 请求位置 |
|---------|-------------|
| `in: path` | 替换 URL path `{placeholder}` |
| `in: query` | URL query parameter |
| `in: body` | JSON request body |

API Key 透传：MCP 工具将 API Key 作为 `Authorization: Bearer dhak_xxx` 透传到后端，后端负责校验、鉴权和配额扣减。

#### 2.4.2 响应转换

| 后端响应 | MCP 响应 |
|---------|---------|
| HTTP 200 | 返回响应体 |
| HTTP 200 + 超长响应（>8000 字符） | 截断并明确提示"响应过长已截断（共N字符）" |
| HTTP 4xx | 返回错误信息和响应体 |
| HTTP 5xx / 超时 | 返回"后端服务不可用" + 响应体中的可诊断信息（如熔断原因） |

## 3. 配置

| 环境变量 | 说明 | 默认值 |
|---------|------|--------|
| `MCP_OPENAPI_URL` | 后端 OpenAPI 文档 URL（启动时读取） | `http://127.0.0.1:8989/v3/api-docs` |
| `MCP_BACKEND_URL` | 后端 API 基础 URL（可被请求头覆盖） | `http://127.0.0.1:8989` |
| `DEHAZE_API_KEY` | 透传到后端的 API Key（可被请求头覆盖） | 内置 M2M key |
| `MCP_PORT` | MCP 服务端口 | 8082 |

**server 模式**：请求头 `x-backend-url` / `x-dehaze-api-key` 可覆盖后端地址和 API Key（用于多后端/多用户场景）。
**CLI 模式**：通过环境变量传递配置。

## 4. 运行管理

通过 `scripts/run.py` 统一管理：

```
python3 scripts/run.py start/stop/restart mcp
python3 scripts/run.py ps
python3 scripts/run.py logs mcp
```

CLI 模式：

```
cd dehaze-mcp-gateway
uv run python server.py cli lookup <keyword>
uv run python server.py cli schema <tool_name>
uv run python server.py cli execute <tool_name> '{"key":"value"}'
uv run python server.py cli list
```
