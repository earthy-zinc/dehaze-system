# MCP 能力网关 - 后端实现

## 1. 文档概述

本文档描述**内部 MCP 能力网关**（dehaze-mcp-gateway，系统能力出口）的实现。它与"MCP Server 管理"（外部能力进口，属 AI 对话模块能力扩展域）是两条独立通道，概念界定见 [需求规格.md](需求规格.md) §1.0。

基于 [MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk) 的 FastMCP 构建，SDK 内置 Streamable HTTP 传输、JSON-RPC 2.0 解析/路由/错误码、`@mcp.tool()` 装饰器自动生成 JSON Schema 和参数校验。MCP 工具只需实现业务逻辑：OpenAPI 解析、元 tool 逻辑、HTTP 请求转发。

**技术选型**：Python + MCP Python SDK + httpx

**依赖**：`mcp`、`httpx`（仅两个外部依赖）。mcp 固定在与 dehaze-python 相同的 1.24.x 线上：客户端侧 `langchain-mcp-adapters` 限制 mcp<2.0.0，两端同版本可避免协议与类型分裂（2.0 把 `mcp.server.fastmcp` 改名为 `mcp.server.mcpserver`）

## 2. 架构

```
MCP Python SDK（FastMCP）
├── Streamable HTTP 传输（POST /mcp）
├── JSON-RPC 2.0 解析/路由/错误码
├── @mcp.tool() 装饰器 -> 自动 JSON Schema + 参数校验

业务层（单文件 server.py）
├── OpenAPI 解析 + $ref 展开 + API 过滤
├── lookup_tool: 关键词搜索（Jaccard + 中文 bigram）
├── lookup_tool_param_schema: 完整参数定义 + 示例生成
├── execute_tool: 参数映射 + 必填校验 + 转发 + 响应转换
└── CLI 模式（env 传配置）
```

## 3. 启动流程

```
server.py 启动
    ↓
httpx.get(OPENAPI_URL) 获取 OpenAPI 文档（失败重试 3 次；仍失败不阻断启动，
注册表保持为空，首次元 tool 调用时按需补载一次）
    ↓
_parse_spec: 解析 paths -> $ref 展开 -> 过滤管道 -> 生成 API 注册表
    ↓
注册 3 个元 tool（lookup_tool / lookup_tool_param_schema / execute_tool）
    ↓
MCP_GATEWAY_KEY 校验（未配置则拒绝启动——网关持有 M2M 凭证，禁止无鉴权裸奔）
    ↓
uvicorn 启动 ASGI 应用（X-MCP-Key 共享密钥鉴权中间件 + MCP SDK streamable-http app，
host=MCP_BIND_HOST 默认 127.0.0.1, port=8082）
```

## 4. API 解析与过滤

### 4.1 $ref 引用展开

OpenAPI 文档中 `$ref: "#/components/schemas/xxx"` 递归展开为实际 schema 定义（`_resolve` 函数）。

### 4.2 过滤管道

```
OpenAPI 所有 paths
    ↓
HTTP 方法过滤（仅保留 GET/POST/PUT/PATCH）
    ↓
写操作白名单（非 GET 工具仅在白名单内才注册，见 §6.2）
    ↓
参数类型过滤（排除含 binary/file 参数的 API）
    ↓
显式排除列表（路径后缀匹配：/login、/register、/logout、/upload、/api-docs）
    ↓
最终保留的 API 列表
```

### 4.3 Tool 命名规则

```
POST /api/v1/prediction          -> post_api_v1_prediction
PUT  /api/v1/presets/{id}        -> put_api_v1_presets_by_id
GET  /api/v1/prediction/{taskId} -> get_api_v1_prediction_by_taskid
```

path 中 `{placeholder}` 替换为 `by_xxx`（统一小写），tool name 取 `{method}_{path_segments_joined}`。

### 4.4 参数提取

每个参数提取 name / location（path|query|body）/ required / schema 描述（`_describe_schema` 递归转文本，含枚举/默认/嵌套结构）/ 原始 schema（用于生成 example）。

## 5. 三个元 tool 实现

### 5.1 lookup_tool

```
分词 _tokenize：
  英文 -> 单词
  中文 -> 双字 bigram（避免单字噪声，如"日"误匹配"每日签到"）
    ↓
遍历 API 注册表，按 5 个字段加权计分（score 越大越相关）：
  name+path（权重3） > 参数名（权重2） > 接口描述（权重1）
  > namespace 分类标签（权重0.5） > 参数描述（权重0.3，弱"蹭词"信号）
  （支持前缀匹配：model 可命中 models）
    ↓
得分按 query 词数归一化（score / 词数）：
  长 query 需命中多数词才有高分，避免命中单个常见词（如"去雾"）即宽泛召回整个模块
    ↓
同分按工具名字典序，排序稳定可复现
    ↓
取 top 10，返回 "工具名: 描述 | 参数: 参数名列表（* 必填）"
    ↓
无匹配 -> 按子串包含找相近候选或提示"尝试更简短的关键词"
```

### 5.2 lookup_tool_param_schema

返回结构化 JSON：description / method / path / namespace / params[]（name、location、required、schema 文本、example）/ arguments_example。

`_schema_example` 从原始 schema 递归生成示例值（object/array 嵌套结构直接产出可用 JSON，`$ref` 用保存的 `_SPEC` 展开）。

### 5.3 execute_tool

```
参数校验：arguments 必须是 JSON 对象；必填参数缺失 -> 返回"缺少必填参数: xxx"
    ↓
路径参数值整体 URL 编码（防路径注入），按 path/query/body 位置映射
    ↓
透传 Authorization: Bearer {M2M_API_KEY}，发送 HTTP 请求（后端地址/密钥仅来自环境变量，
不接受请求头覆盖——可被客户端伪造导致 M2M 凭证外泄）
    ↓
响应转换（映射规则见 API接口.md §2.4）
```

参数映射（path/query/body 位置）与响应转换（5xx/4xx/超长截断）的契约定义见 [API接口.md §2.3-2.4](./API接口.md)，本节仅描述执行流程。

## 6. 配置项

| 环境变量 | 说明 | 默认值 |
|---------|------|--------|
| `MCP_OPENAPI_URL` | 后端 OpenAPI 文档 URL | `http://127.0.0.1:8989/v3/api-docs` |
| `MCP_BACKEND_URL` | 后端 API 基础 URL | `http://127.0.0.1:8989` |
| `M2M_API_KEY` | 透传到后端的 M2M API Key（仓库根 .env 统一供给，无代码内置值） | 无（必填） |
| `MCP_GATEWAY_KEY` | 客户端访问网关的共享密钥（X-MCP-Key 请求头），未配置时网关拒绝启动 | 无（必填） |
| `MCP_WRITE_TOOLS` | 写操作白名单扩充（逗号分隔工具名，叠加在默认白名单之上） | 空 |
| `MCP_PORT` | MCP 服务端口 | 8082 |
| `MCP_BIND_HOST` | 监听地址（网关持有 M2M 凭证，默认仅回环；跨机部署时显式设置） | `127.0.0.1` |

server 与 CLI 模式配置一致，均通过环境变量传递（网关自行加载仓库根 .env，已设置的
shell 环境变量优先），不接受请求头覆盖。

### 6.1 网关访问鉴权（X-MCP-Key）

网关持有后端 M2M 凭证（映射 admin 用户），仅靠回环绑定不构成访问控制。所有 HTTP 请求
（MCP 协议端点 `/mcp`）必须携带 `X-MCP-Key` 请求头，网关以**常量时间比较**校验（防时序
攻击逐位猜测），缺失/错误一律返回 401。客户端（dehaze-python `McpGatewayClient`）从同源
配置 `MCP_GATEWAY_KEY`（根 .env）读取并在每个请求携带；客户端密钥未配置时直接拒绝连接，
不做降级。

**会话初始化前置**：MCP 协议要求客户端建会话后先发 `initialize` 完成能力协商，否则
`tools/list`/`tools/call` 会被网关拒绝。`McpGatewayClient._McpSessionContext.__aenter__` 在建立
streamable-http 连接与 `ClientSession` 后立即 `await session.initialize()`，之后才把会话交给调用方
（`lookup_tool`/`lookup_tool_param_schema`/`execute_tool`/`list_tools` 全部经此路径）。

### 6.2 写操作白名单

M2M key 映射 admin 用户，若无限制，提示注入场景下 LLM 可借网关改写任意管理数据（DELETE
已被方法过滤排除，但 POST/PUT/PATCH 仍敞开）。故注册表层面收敛为**方法白名单**：

- GET（只读）全量保留；
- 非 GET 仅白名单内工具可注册，LLM 从源头不可见其余写接口；
- 默认白名单：`post_api_v1_prediction`（发起去雾预测——需求规格 §2.3.1 定义的唯一常规
  LLM 写场景；批量处理等高频写路径绕开网关直连业务服务，无需经网关开放）；
- 运维可用 `MCP_WRITE_TOOLS`（逗号分隔工具名）按需扩充，工具名粒度精确到单个端点。

### 6.3 M2M Key 密钥管理

M2M API Key 与网关共享密钥均遵循 secrets env-only 原则：仅存于仓库根 `.env`（不入库，
模板见 `.env.example`），三端（java `algorithm.python.api-key` / go `algorithm.apiKey` /
网关 `M2M_API_KEY`）均从环境变量读取，代码与配置文件中不保留任何硬编码默认值。

## 7. 文件结构

```
dehaze-mcp-gateway/
├── server.py          # 全部实现
├── pyproject.toml     # uv 依赖管理（mcp + httpx）
└── uv.lock
```

单文件实现，无模块拆分。MCP 工具本质是协议适配器，逻辑简单，不需要拆分为多个模块。
