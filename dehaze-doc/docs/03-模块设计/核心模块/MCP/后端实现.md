# MCP 能力网关 - 后端实现

## 1. 文档概述

本文档描述**内部 MCP 能力网关**（dehaze-mcp-gateway，系统能力出口）的实现。它与"MCP Server 管理"（外部能力进口，属 AI 对话模块能力扩展域）是两条独立通道，概念界定见 [需求规格.md](需求规格.md) §1.0。

基于 [MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk) 的 MCPServer 构建，SDK 内置 Streamable HTTP 传输、JSON-RPC 2.0 解析/路由/错误码、`@mcp.tool()` 装饰器自动生成 JSON Schema 和参数校验。MCP 工具只需实现业务逻辑：OpenAPI 解析、元 tool 逻辑、HTTP 请求转发。

**技术选型**：Python + MCP Python SDK + httpx

**依赖**：`mcp`、`httpx`（仅两个外部依赖）

## 2. 架构

```
MCP Python SDK（MCPServer）
├── Streamable HTTP 传输（POST /mcp）
├── JSON-RPC 2.0 解析/路由/错误码
├── @mcp.tool() 装饰器 -> 自动 JSON Schema + 参数校验

业务层（单文件 server.py）
├── OpenAPI 解析 + $ref 展开 + API 过滤
├── lookup_tool: 关键词搜索（Jaccard + 中文 bigram）
├── lookup_tool_param_schema: 完整参数定义 + 示例生成
├── execute_tool: 参数映射 + 必填校验 + 转发 + 响应转换
└── CLI 模式（env 传配置）
```

## 3. 启动流程

```
server.py 启动
    ↓
httpx.get(OPENAPI_URL) 获取 OpenAPI 文档（失败仅打印，不阻断服务）
    ↓
_parse_spec: 解析 paths -> $ref 展开 -> 过滤管道 -> 生成 API 注册表
    ↓
注册 3 个元 tool（lookup_tool / lookup_tool_param_schema / execute_tool）
    ↓
mcp.run(transport="streamable-http", port=8082)
```

## 4. API 解析与过滤

### 4.1 $ref 引用展开

OpenAPI 文档中 `$ref: "#/components/schemas/xxx"` 递归展开为实际 schema 定义（`_resolve` 函数）。

### 4.2 过滤管道

```
OpenAPI 所有 paths
    ↓
HTTP 方法过滤（仅保留 GET/POST/PUT/PATCH）
    ↓
参数类型过滤（排除含 binary/file 参数的 API）
    ↓
显式排除列表（路径后缀匹配：/login、/register、/logout、/upload、/api-docs）
    ↓
最终保留的 API 列表
```

### 4.3 Tool 命名规则

```
POST /api/v1/prediction          -> post_api_v1_prediction
PUT  /api/v1/presets/{id}        -> put_api_v1_presets_by_id
GET  /api/v1/prediction/{taskId} -> get_api_v1_prediction_by_taskid
```

path 中 `{placeholder}` 替换为 `by_xxx`（统一小写），tool name 取 `{method}_{path_segments_joined}`。

### 4.4 参数提取

每个参数提取 name / location（path|query|body）/ required / schema 描述（`_describe_schema` 递归转文本，含枚举/默认/嵌套结构）/ 原始 schema（用于生成 example）。

## 5. 三个元 tool 实现

### 5.1 lookup_tool

```
分词 _tokenize：
  英文 -> 单词
  中文 -> 双字 bigram（避免单字噪声，如"日"误匹配"每日签到"）
    ↓
遍历 API 注册表，按 5 个字段加权计分（score 越大越相关）：
  name+path（权重3） > 参数名（权重2） > 接口描述（权重1）
  > namespace 分类标签（权重0.5） > 参数描述（权重0.3，弱"蹭词"信号）
  （支持前缀匹配：model 可命中 models）
    ↓
得分按 query 词数归一化（score / 词数）：
  长 query 需命中多数词才有高分，避免命中单个常见词（如"去雾"）即宽泛召回整个模块
    ↓
同分按工具名字典序，排序稳定可复现
    ↓
取 top 10，返回 "工具名: 描述 | 参数: 参数名列表（* 必填）"
    ↓
无匹配 -> 按子串包含找相近候选或提示"尝试更简短的关键词"
```

### 5.2 lookup_tool_param_schema

返回结构化 JSON：description / method / path / namespace / params[]（name、location、required、schema 文本、example）/ arguments_example。

`_schema_example` 从原始 schema 递归生成示例值（object/array 嵌套结构直接产出可用 JSON，`$ref` 用保存的 `_SPEC` 展开）。

### 5.3 execute_tool

```
参数校验：必填参数缺失 -> 返回"缺少必填参数: xxx"
    ↓
配置：backend_url / api_key 从 ctx.headers（x-backend-url / x-dehaze-api-key）或默认值
    ↓
透传 Authorization: Bearer {api_key}，发送 HTTP 请求
    ↓
响应转换（映射规则见 API接口.md §2.4）
```

参数映射（path/query/body 位置）与响应转换（5xx/4xx/超长截断）的契约定义见 [API接口.md §2.3-2.4](./API接口.md)，本节仅描述执行流程。

## 6. 配置项

| 环境变量 | 说明 | 默认值 |
|---------|------|--------|
| `MCP_OPENAPI_URL` | 后端 OpenAPI 文档 URL | `http://127.0.0.1:8989/v3/api-docs` |
| `MCP_BACKEND_URL` | 后端 API 基础 URL | `http://127.0.0.1:8989` |
| `DEHAZE_API_KEY` | 透传到后端的 API Key | 内置 M2M key |
| `MCP_PORT` | MCP 服务端口 | 8082 |

server 模式请求头 `x-backend-url` / `x-dehaze-api-key` 可覆盖 `MCP_BACKEND_URL` / `DEHAZE_API_KEY`。

## 7. 文件结构

```
dehaze-mcp-gateway/
├── server.py          # 全部实现（~340 行）
├── pyproject.toml     # uv 依赖管理（mcp + httpx）
└── uv.lock
```

单文件实现，无模块拆分。MCP 工具本质是协议适配器，逻辑简单，不需要拆分为多个模块。
