# 去雾处理模块 - 前端实现设计

## 1. 文档概述

本文档描述去雾处理模块的前端实现方案（dehaze-front-vue），聚焦组件结构、页面状态机、关键交互决策（模拟进度、取消/重试、批量处理、结果保存）。

---

## 2. 组件设计

### 2.1 组件结构

```
去雾处理模块
└── PresentationDehaze（views/presentation/dehaze/index.vue）  # 页面容器，单值状态机
    ├── AlgorithmToolBar        # 左侧工具栏（算法选择/参数面板/操作入口）
    │   ├── el-tree-select      # 去雾模型树选择
    │   └── dehaze 参数面板     # 去雾强度/色彩饱和度/对比度/锐化
    ├── ExampleImageSelect      # 样例图片选择（NH-HAZE-2023 数据集）
    ├── Camera                  # 拍照上传
    ├── DatasetImageSelect      # 数据集图片选择（弹窗）
    ├── SingleImageShow         # 单图展示（上传后原图预览）
    ├── OverlapImageShow        # 重叠对比展示（原图+结果图，效果对比模块组件）
    └── 内嵌功能面板
        ├── 处理进度面板        # 5 阶段模拟进度条 + 取消处理按钮
        ├── 失败重试面板        # 自动重试倒计时 + 手动重试
        ├── 批量任务面板        # 批量任务列表（el-table）+ 整体进度
        └── 结果操作区          # 保存结果 / 评估结果按钮
```

> **说明**：早期设计稿中的 PredictionPage 双栏布局、predictionStore、`/prediction` 路由、预设选择器（PresetSelector）等**未落地**——实际页面为 `presentation/dehaze`，预设后端接口已实现但前端未接入入口。

### 2.2 页面状态机

页面通过**单值状态机**（`activePage`）管理交互，替代多个布尔标志：

| 状态 | 触发场景 | 说明 |
|------|---------|------|
| `example` | 默认/重置后 | 展示样例图片 |
| `camera` | 点击拍照 | 拍照上传 |
| `singleImage` | 上传/选择图片后 | 单图预览（含失败重试面板叠加） |
| `loading` | 点击开始处理 | 5 阶段模拟进度 + 取消按钮 |
| `overlap` | 处理完成 | 重叠对比展示 + 保存/评估入口 |
| `batch` | 批量任务列表有数据 | 批量处理面板 |

## 3. 关键交互设计

### 3.1 处理确认与配额检查

- 点击"开始处理"后，先调用 `ModelAPI.getQuota()` 检查剩余次数，`remaining === 0` 时弹窗引导升级
- 再弹确认对话框（`ElMessageBox.confirm`），展示图片文件名、算法名称、参数值（去雾强度/色彩饱和度/对比度/锐化），确认后提交

### 3.2 模拟进度展示

处理期间展示 **5 阶段模拟进度**（非后端真实进度）：

```
stages 常量：预处理(0-10) / 算法初始化(10-20) / 去雾处理(20-90) / 后处理(90-95) / 保存(95-100)
```

- 定时器每 300ms 在阶段范围内随机递增进度（封顶 95%）
- `el-steps` 步骤条高亮当前阶段 + `el-progress` 百分比
- 任务完成时进度置 100 并跳转 `overlap` 页面
- 任务失败时停止模拟，展示失败重试面板

### 3.3 取消处理

- `loading` 页面提供"取消处理"按钮，点击后设置 `cancelFlag` 并忽略后续回调、重置进度、返回 `singleImage`
- **取消为前端本地行为**：后端任务仍继续执行至完成/失败（无后端中断接口）

### 3.4 失败重试

- 处理失败后展示重试面板：错误提示 + 重试按钮
- **自动重试倒计时 3 秒**（按钮文案"自动重试(3/2/1)"），倒计时结束可点击；也可点击"取消"关闭面板
- 重试复用 `handleGenerateImage` 全流程

### 3.5 结果保存与评估

- **保存结果**：`fetch` 结果图 → 转 Blob → `FileAPI.upload` 重新上传至文件系统（固定格式，无格式/质量选项）
- **评估结果**：跳转 `/evaluation/index`，携带当前模型 ID 与图片（原图/结果图/清晰图）进入效果评估页

### 3.6 批量处理（前端串行）

- 批量任务列表（`el-table`）：每张图片一行，含名称/状态标签/进度条/错误信息，操作支持重试失败任务、移除、清空列表
- 批量入口：`batchDialogVisible` 弹窗选择图片（`el-upload` 多选）→ 确认添加至任务列表
- 开始批量：**前端 for 循环串行执行**——每张先 `FileAPI.upload` 上传原图，再 `ModelAPI.predictAndWait` 提交预测并等待完成；单张失败标记 failed 不影响后续
- 整体进度 = 各任务进度平均值；支持"取消全部"（剩余 pending/processing 任务标记 cancelled）
- **不调用后端 `/prediction/batch` 接口**（接口与 SDK 已实现，供其他端/后续使用）

### 3.7 图片输入入口

- 样例图片：`exampleImages.ts` 常量（NH-HAZE-2023 数据集 haze/clean 配对）
- 从图像输入页跳转：通过 `route.query.imageUrl` 传入图片 URL，加载后清空 query 参数（keepAlive 激活时重新检查）
- 历史记录：图像输入页 localStorage 历史（20 条，按时间分组），点击"重新处理"携带 `imageUrl` 跳转

## 4. 状态管理

### 4.1 imageShow Store（共享）

| 状态字段 | 说明 |
|---------|------|
| imageInfo.images.urls | 图片列表（HAZE/PRED/CLEAN，含标签与颜色） |
| imageInfo.brightness/contrast/saturate | 滤镜参数（对比页展示） |
| dehazeParams | 去雾参数（dehazeStrength/colorSaturation/contrast/sharpen），处理时使用、评估页参数对比展示 |
| modelId | 当前选中算法 ID |
| magnifierInfo | 放大镜配置（形状/倍数/大小） |

> 页面局部状态（activePage/处理进度/批量任务/配额等）在组件内管理，未单独抽取 predictionStore。

## 5. 数据流

### 5.1 单张处理流程

```
选择图片/算法 → 配额检查（getQuota）→ 确认对话框 → 开始处理
    ↓
activePage=loading，启动模拟进度（封顶 95%）
    ↓
ModelAPI.predictAndWait({ algorithmId, imageUrl, params: JSON })
    ├─ 完成：置原图+结果图 → progress=100 → activePage=overlap
    └─ 失败：停止模拟 → 重试面板（3s 倒计时）→ activePage=singleImage
```

### 5.2 模块间数据交互

| 交互方向 | 数据 | 说明 |
|---------|------|------|
| 图像输入 → 去雾处理 | imageUrl | 上传/拍照/样例/历史记录选择图片后跳转 |
| 去雾处理 → 效果评估 | modelId + 图片 | "评估结果"按钮跳转 `/evaluation/index` |
| 去雾处理 → 文件存储 | 原图/结果图/清晰图 | 上传与保存走 FileAPI |

## 6. 权限与会员控制

| 功能 | 控制方式 |
|------|---------|
| 配额检查 | 处理前 `getQuota()` 检查，`remaining=0` 弹窗引导升级 |
| 批量上限 | 后端接口校验（Java `getBatchLimit` / Python 20 张硬编码），前端不强制限制 |

> 权益数值以 [会员管理模块 §2.2.1](../../基础模块/会员管理/需求规格.md) 与 `sys_member_benefit` 配置为权威。

---

## 7. 性能优化

| 优化项 | 实现方式 |
|--------|---------|
| 模拟进度 | 定时器随机递增，避免高频率 UI 更新 |
| keepAlive 缓存 | 页面缓存 + `onActivated` 重新检查 query 参数 |
| 批量串行 | for 循环逐张处理，避免并发请求压垮后端 |
| 图片预加载 | 样例图/上传后由组件内部 `onload` 管理 |

---

## 8. 错误处理

| 错误类型 | 处理方式 |
|---------|---------|
| 配额不足 | 弹窗提示已用/剩余次数，引导升级 |
| 处理失败 | 重试面板（自动重试倒计时 3s + 手动重试 + 取消） |
| 图片格式/大小 | 上传前校验（仅 JPG/PNG，≤20MB） |
| 网络异常 | predictAndWait 抛错 → 走失败重试面板 |
