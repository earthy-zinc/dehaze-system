# 去雾处理模块需求规格

## 1. 模块概述

### 1.1 模块定位

去雾处理模块是图像去雾系统的核心处理引擎，负责调用算法对图像进行去雾处理，并管理处理过程和结果。该模块承接图像输入和算法选择，输出处理结果至效果对比模块，是整个系统业务流程的关键环节。

### 1.2 核心价值

- **高效处理**：优化的处理流程，快速完成单张/批量去雾
- **实时反馈**：完整的进度监控，清晰展示处理阶段
- **参数可调**：高级用户可调节算法参数，实现个性化效果
- **结果管理**：完善的结果保存、分享、导出功能
- **容错机制**：断点续传、自动重试，保障处理稳定性

### 1.3 用户角色分析

| 用户类型 | 特征 | 使用偏好 | 功能需求 |
|---------|------|---------|---------|
| **轻度用户** | 偶尔使用，对参数不了解 | 默认参数，一键处理 | 单张处理+自动保存 |
| **中度用户** | 定期使用，有一定了解 | 参考默认+微调参数 | 单张/批量处理+手动调参 |
| **重度用户** | 高频使用，专业需求 | 精确控制参数 | 批量处理+高级参数+队列管理 |
| **VIP用户** | 付费用户，更高权益 | 高效批量处理 | 更多次数+历史记录+优先处理 |

### 1.4 模块依赖关系


## 2. 功能需求

### 2.1 单张处理功能 (F-M04-001)

#### 2.1.1 功能描述

对单张图片进行去雾处理，支持异步任务模式、真实用时展示和处理控制。计算密集型任务在后端异步执行，前端通过 WebSocket 实时推送获取任务状态（轮询作为降级兜底），从根本上避免长耗时请求超时。

#### 2.1.2 异步任务流程

```
确认图片和算法
    ↓
点击"开始去雾"
    ↓
显示确认对话框
    ↓
用户确认处理
    ↓
┌─────────────────────────────────────┐
│          任务提交阶段                │
│  • 前端调用 POST /api/v1/prediction │
│  • 后端保存日志(status=processing)  │
│  • 后端提交异步任务（线程池/goroutine）│
│  • 立即返回 { logId, status }        │
│  • 前端建立 WebSocket 连接（logId）   │
│  • 前端显示 indeterminate loading     │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│          异步执行阶段（后端）        │
│  • 调用 Python 算法服务              │
│  • Python 端可能再次异步化           │
│  • Java/Go 后端轮询 Python 状态      │
│  • 通过 WebSocket 推送阶段变更事件    │
│  • 完成后更新日志(status=completed)  │
│  • 失败时更新日志(status=failed)     │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│          实时推送阶段（WebSocket）   │
│  • 后端通过 WebSocket 推送任务事件    │
│  • 事件类型：stage_changed /         │
│    completed / failed                │
│  • 前端 onMessage 回调更新 UI        │
│  • 真实用时计时器同步运行            │
│  • 连接断开时自动降级为轮询          │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│          结果处理阶段                │
│  • status=completed：跳转对比页面    │
│  • status=failed：展示错误信息+重试  │
│  • 超时：抛出异常由调用方处理        │
└─────────────────────────────────────┘
```

#### 2.1.3 任务状态机

| 状态 | 说明 | 触发条件 | UI 表现 |
|------|------|---------|---------|
| `processing` | 任务执行中 | POST 提交后立即进入 | loading spinner + 真实用时计时 |
| `completed` | 任务成功完成 | Python 算法返回结果 | 自动跳转对比页面 |
| `failed` | 任务失败 | 异常或超时 | 错误提示 + 重试按钮 |

**僵尸任务恢复**：后端定时任务每 60s 扫描 `status=processing AND update_time < NOW() - 10min` 的记录，标记为 `failed`，避免服务重启后任务永远停留在 `processing` 状态。

#### 2.1.4 处理控制

**开始处理**

开始处理前显示确认对话框，包含图片信息（文件名、尺寸、大小）、算法信息（算法名称、预估时间、参数配置）和处理提示，用户可选择取消或开始处理。

**取消处理**

- 支持取消正在进行的处理
- 取消后前端忽略后续轮询结果
- 后端任务仍会执行完成，仅前端不再处理结果

#### 2.1.5 进度反馈（实时推送）

处理过程中通过 WebSocket 实时推送任务状态变更，替代原有的轮询机制。同时保留轮询作为降级方案，确保 WebSocket 不可用时功能不受影响。

**WebSocket 连接管理**

| 阶段 | 行为 |
|------|------|
| 连接建立 | 任务提交后，前端使用 logId 建立 WebSocket 连接，订阅该任务的状态变更 |
| 心跳保活 | 每 30 秒发送一次 ping 帧，连续 3 次未收到 pong 则判定连接断开 |
| 自动重连 | 连接断开后自动重连，最多重试 3 次，间隔 2s → 5s → 10s |
| 降级轮询 | 3 次重连均失败后，自动降级为 HTTP 轮询（2s 间隔），确保功能可用 |
| 连接关闭 | 任务完成或取消后，前端主动关闭 WebSocket 连接 |

**推送事件定义**

| 事件类型 | 触发时机 | 推送内容 | 前端响应 |
|---------|---------|---------|---------|
| `stage_changed` | 处理阶段变更（如：图片加载→模型推理→后处理） | `{ logId, stage, stageName, timestamp }` | 更新阶段提示文案 |
| `completed` | 任务成功完成 | `{ logId, resultUrl, metrics, duration }` | 停止计时，跳转对比页面 |
| `failed` | 任务失败 | `{ logId, errorCode, errorMessage }` | 停止计时，展示错误信息+重试按钮 |

**UI 展示规则**

- 显示当前处理阶段名称（如"正在加载图片..." → "模型推理中..." → "后处理..."）
- 真实用时计时器（毫秒精度）与 WebSocket 推送同步运行
- 计算密集型任务无真实进度百分比，不显示预估剩余时间
- 阶段切换时有简短过渡动画，避免界面突变
- WebSocket 降级为轮询时，UI 不变，用户无感知

**后端推送机制**

后端在任务状态变更时，通过 WebSocket 向订阅了该 logId 的客户端推送事件。推送逻辑与任务执行逻辑解耦，任务状态变更先写入数据库，再异步推送 WebSocket 事件，推送失败不影响任务正常执行。

#### 2.1.6 预测流程插件化（拦截器链）

预测主流程采用 **责任链模式** 支持可插拔拦截器，与算法调用主流程解耦。新增预查询/快速返回逻辑无需修改主流程，只需实现 `PredictionInterceptor` 接口并在拦截器链中注册。

**执行顺序**

```
POST /api/v1/prediction
    ↓
1. 拦截器链 intercept(context)
    ├─ 命中 → 直接写 completed 日志，返回完整结果（不调用算法）
    └─ 未命中 → 继续
    ↓
2. Redis 运行时缓存（algorithmId + imageMd5，24h TTL）
    ├─ 命中 → 写 completed 日志，返回完整结果
    └─ 未命中 → 继续
    ↓
3. 创建 processing 日志，异步调用算法
```

**已实现的拦截器**

| 拦截器 | 命中条件 | 命中后行为 | 数据来源 |
|--------|---------|-----------|---------|
| `WpxNetPredictionInterceptor` | 算法根节点为 `WPXNet` 且原图 MD5 在 `sys_wpx_file` 表中存在映射 | 返回预处理的 WPX 去雾图 URL，跳过算法推理 | `scripts/init_wpx_file.py` 预建立的 MD5 映射 |

**WPXNet 预查询业务价值**

WPXNet 系列算法（DENSE-HAZE、O-HAZE、NH-HAZE 等）推理耗时较长（单张数秒），但其处理对象是固定的标准数据集，结果可预先计算并入库。通过拦截器查表短路，将响应时延从秒级降至毫秒级，同时节省 GPU 资源。

**三端一致性**

Java / Python / Go 三端均实现相同的拦截器接口与责任链机制，拦截器命中规则、返回结果结构完全一致。详见各端架构文档：
- Java：[dehaze-java 系统架构文档](../../../04-项目实现/后端/01-Java应用架构文档.md)
- Python：[Python 算法服务架构文档 - 2.17 预测流程插件化](../../../04-项目实现/后端/05-Python算法服务架构文档.md)
- Go：[Go 应用架构文档](../../../04-项目实现/后端/03-Go应用架构文档.md)

### 2.2 批量处理功能 (F-M04-002)

#### 2.2.1 功能描述

支持一次性处理多张图片（最多20张），提高处理效率，适用于批量去雾需求场景。

#### 2.2.2 批量处理流程

```
选择多张图片（最多20张）
    ↓
显示图片列表预览
    ↓
选择统一算法
    ↓
设置处理参数（可选）
    ↓
点击"批量处理"
    ↓
显示确认对话框
    ↓
用户确认处理
    ↓
逐张/并行处理
    ↓
显示整体进度和单张进度
    ↓
处理完成
    ↓
生成处理报告
    ↓
查看批量结果
```

#### 2.2.3 批量处理策略

**处理模式**

| 模式 | 说明 | 适用场景 | 并发数 |
|-----|------|---------|--------|
| 串行处理 | 逐张处理，稳定可靠 | 内存有限的设备 | 1 |
| 并行处理 | 同时处理多张，速度快 | 高性能设备（GPU显存≥16G） | 2-4 |
| 智能模式 | 根据设备性能自动选择 | 推荐模式 | 自适应 |

**失败处理策略**

- 单张失败不影响其他图片处理
- 记录失败原因和失败图片
- 支持重试失败的图片
- 生成详细处理报告

#### 2.2.4 批量进度显示

批量处理过程中显示整体进度（完成数量、成功数、失败数、预估剩余时间）、当前正在处理的图片进度和状态。处理列表展示所有图片的处理状态和用时，支持暂停全部、取消全部和重试失败的操作。

### 2.3 参数调节功能 (F-M04-003)

#### 2.3.1 功能描述

为高级用户提供算法参数调节功能，实现个性化处理效果。支持实时预览调参效果。

#### 2.3.2 参数类型

**通用参数**

| 参数名称 | 类型 | 范围 | 默认值 | 说明 |
|---------|------|------|--------|------|
| 去雾强度 | 滑块 | 0-100 | 50 | 控制去雾程度，值越大去雾效果越强 |
| 色彩饱和度 | 滑块 | 0-200 | 100 | 调整色彩鲜艳度，100为原始值 |
| 对比度 | 滑块 | 0-200 | 100 | 调整明暗对比，100为原始值 |
| 锐化程度 | 滑块 | 0-100 | 30 | 增强细节清晰度 |

**算法特定参数**

**DCP算法（暗通道先验）**

| 参数名称 | 类型 | 范围 | 默认值 | 说明 |
|---------|------|------|--------|------|
| ω值 | 滑块 | 0.85-0.95 | 0.95 | 去雾系数，控制保留雾的程度 |
| 窗口大小 | 选择 | 3/5/7/9/11/13/15 | 15 | 暗通道估计窗口大小 |
| 引导滤波半径 | 滑块 | 20-60 | 40 | 引导滤波的平滑半径 |

**深度学习算法**

| 参数名称 | 类型 | 选项 | 默认值 | 说明 |
|---------|------|------|--------|------|
| 推理精度 | 选择 | FP16/FP32 | FP16 | 浮点精度，FP16更快 |
| 批处理大小 | 选择 | 1/2/4 | 1 | 同时处理的图片数量 |

#### 2.3.3 参数调节界面

参数调节界面提供通用参数和算法特定参数的设置区域，支持滑块、选择等输入方式。提供预设方案（推荐配置、风景优化、夜景增强）和自定义方案保存功能，支持实时预览调参效果（原图与效果对比）。

### 2.4 处理结果管理 (F-M04-004)

#### 2.4.1 功能描述

管理处理结果，支持保存、分享、导出等操作，满足不同场景下的结果使用需求。

#### 2.4.2 自动保存

- 处理完成自动保存到应用服务器
- 保存原图和处理结果图
- 保存处理参数和元数据
- 关联预测日志记录

**文件命名规则**

```
格式：原文件名_算法名_时间戳.格式
示例：IMG_20250117_AODNet_143024.jpg
```

#### 2.4.3 手动保存

**保存选项**

| 选项 | 说明 | 可选值 |
|------|------|--------|
| 保存位置 | 保存到相册/自定义目录 | 相册/自定义路径 |
| 保存格式 | 图片文件格式 | JPG/PNG |
| 保存质量 | 图片压缩质量 | 60%/80%/90%/100% |
| 元数据 | 是否包含EXIF信息 | 是/否 |

#### 2.4.4 结果分享

**分享方式**

- 分享到社交平台（微信、QQ、微博等）
- 生成分享链接（有效期可设置）
- 生成二维码
- 发送到邮箱

**分享内容选项**

- 仅处理后的图片
- 对比图（原图+处理后并排/上下）
- 处理信息（算法、参数、时间）

#### 2.4.5 结果导出

**导出格式**

| 格式 | 说明 | 适用场景 |
|------|------|---------|
| 单张图片 | JPG/PNG格式 | 日常使用 |
| 对比图 | 原图+结果并排/上下 | 效果展示 |
| PDF报告 | 包含详细处理信息 | 专业报告 |
| 批量打包 | ZIP压缩包 | 批量处理结果 |

**导出选项**

导出设置支持选择导出格式，并提供分辨率选项（原始尺寸、1920×1080、1280×720、自定义）、质量设置（高质量90%等）、水印选项（是否添加系统水印）和元数据选项（是否包含处理参数），显示预计文件大小。

### 2.5 处理队列管理 (F-M04-005)（规划中，未实现）

#### 2.5.1 功能描述

管理处理任务队列，支持任务优先级和并发控制，适用于多任务处理场景。

#### 2.5.2 队列功能

**任务管理**

- 查看队列中的所有任务
- 调整任务优先级（拖拽排序）
- 暂停/恢复单个任务
- 取消任务
- 清空队列

**队列状态**

| 状态 | 图标 | 说明 |
|------|------|------|
| 等待中 | ⏳ | 排队等待处理 |
| 处理中 | 🔄 | 正在处理 |
| 已暂停 | ⏸️ | 用户手动暂停 |
| 已完成 | ✅ | 处理成功 |
| 已失败 | ❌ | 处理失败 |

#### 2.5.3 并发控制

**并发策略**

- 根据设备性能自动调整并发数
- 最大并发数：1-3（根据GPU显存）
- 优先处理高优先级任务
- VIP用户享有优先处理权

**重试机制**

- 失败任务自动重试（最多3次）
- 重试间隔递增：2s → 5s → 10s
- 支持手动触发重试

#### 2.5.4 队列界面

队列界面显示当前并发设置和所有任务列表，包括任务优先级、图片名称、算法、状态、进度和操作按钮。支持清空已完成和清空全部操作，已完成任务可折叠显示。

### 2.6 错误处理与恢复 (F-M04-006)

#### 2.6.1 错误类型及处理

| 错误类型 | 错误代码 | 错误提示 | 处理方式 |
|---------|---------|---------|---------|
| 内存不足 | E001 | "设备内存不足，请关闭其他应用后重试" | 释放资源，提示用户清理 |
| 算法加载失败 | E002 | "算法加载失败，请检查网络连接" | 重试加载，提供离线备用算法 |
| 处理超时 | E003 | "处理超时，建议更换算法或降低图片分辨率" | 取消处理，提供优化建议 |
| 图片损坏 | E004 | "图片文件损坏，无法处理" | 跳过该图片，继续后续 |
| 存储空间不足 | E005 | "存储空间不足，请清理后重试" | 提示清理空间 |
| 网络异常 | E006 | "网络连接异常，请检查网络设置" | 自动重试/提示用户 |
| GPU资源不足 | E007 | "GPU资源不足，已切换到CPU处理" | 自动降级到CPU |
| 权限不足 | E008 | "去雾次数已达上限，请升级VIP" | 引导升级VIP |

#### 2.6.2 恢复机制

**断点续传**（规划中，未实现）

- 每处理完一个阶段自动保存进度
- 应用重启后检测未完成任务
- 支持从断点恢复处理
- 保留处理上下文和参数

**自动重试**

```
重试策略：
├── 重试次数：最多3次
├── 重试间隔：2s → 5s → 10s（指数退避）
├── 重试条件：网络错误、临时性失败
└── 不重试：图片损坏、权限不足、用户取消
```

**错误恢复界面**

检测到未完成的处理任务时，显示中断原因、图片信息、算法名称、已完成的进度和中断时间，提供放弃或从断点恢复的选项。

### 2.7 处理历史 (F-M04-007)

#### 2.7.1 功能描述

记录用户的所有去雾处理结果，支持历史记录查询、筛选、查看对比、重新处理等操作。处理历史是用户回溯处理效果、对比不同算法结果的核心入口，也是个人中心的重要功能模块。

#### 2.7.2 存储范围

每条处理历史记录包含以下数据：

| 数据类别 | 具体内容 | 存储方式 |
|---------|---------|---------|
| 原图信息 | 文件名、图片URL、尺寸、大小、MD5 | MinIO 对象存储 + 数据库记录 |
| 结果信息 | 结果图URL、处理耗时 | MinIO 对象存储 + 数据库记录 |
| 算法信息 | 算法ID、算法名称、算法版本 | 数据库记录 |
| 处理参数 | 通用参数、算法特定参数（JSON） | 数据库记录 |
| 评估指标 | PSNR、SSIM（如有GT参考图） | 数据库记录 |
| 用户评价 | 评分、评价内容（如有） | 关联评价表 |
| 元数据 | 处理时间、处理状态、用户ID | 数据库记录 |

#### 2.7.3 查询方式

**筛选条件**

| 条件类型 | 字段 | 说明 |
|---------|------|------|
| 时间范围 | 处理时间 | 开始日期~结束日期 |
| 算法筛选 | 算法ID | 按算法筛选历史记录 |
| 评分筛选 | 评分范围 | 1-5 星（含"未评价"选项） |
| 状态筛选 | 处理状态 | 成功/失败 |
| 关键字搜索 | 原图文件名 | 模糊匹配 |

**排序方式**

| 排序字段 | 默认方向 | 说明 |
|---------|---------|------|
| 处理时间 | 倒序 | 默认按时间倒序，最新记录在前 |
| 评分 | 倒序 | 高分记录优先 |
| 处理耗时 | 正序 | 快速处理记录优先 |

#### 2.7.4 展示形式

**列表视图（默认）**

时间线形式展示，每条记录包含：

| 展示项 | 说明 |
|--------|------|
| 缩略图 | 原图和结果图的并排缩略图（可点击放大） |
| 算法名称 | 使用的算法名称和版本 |
| 处理时间 | 精确到分钟 |
| 处理耗时 | 如"3.2s" |
| 评分 | 星级展示（未评价显示"去评价"） |
| 评估指标 | PSNR/SSIM（如有） |
| 操作 | 查看对比 / 重新处理 / 删除 |

**网格视图**

卡片式布局，以结果图缩略图为主体，适合快速浏览大量记录。每张卡片展示结果图缩略图、算法名称和评分，点击进入对比页面。

**视图切换**

列表视图和网格视图可通过右上角按钮切换，默认列表视图。

#### 2.7.5 数据管理策略

**保留条数控制**

历史记录保留条数受会员等级控制：

| 会员等级 | 保留条数 | 超出处理 |
|---------|---------|---------|
| 普通用户 | 10 条 | 自动删除最早的记录（含文件） |
| VIP1 | 50 条 | 同上 |
| VIP2 | 100 条 | 同上 |
| SVIP | 500 条 | 同上 |

**自动清理机制**

- 定时任务每天凌晨 2:00 扫描超限用户
- 删除最早的记录，同步删除 MinIO 中的原图和结果图文件
- 清理前推送通知，告知用户历史记录即将清理
- 被评价过的记录优先保留（评价数据有分析价值）

**手动管理**

- 用户可手动删除单条或多条历史记录
- 删除时同步删除关联的图片文件
- 删除操作需二次确认
- 删除后不可恢复

#### 2.7.6 重新处理

从历史记录可发起重新处理，支持两种模式：

| 模式 | 说明 | 参数 |
|------|------|------|
| 同算法重处理 | 使用原算法重新处理同一张图片 | 沿用原参数或重新配置 |
| 换算法处理 | 使用不同算法处理同一张图片 | 选择新算法+配置参数 |

重新处理流程复用单张处理流程（§2.1），原图从历史记录中获取，无需重新上传。处理完成后生成新的历史记录，与原记录通过 `parent_log_id` 关联，支持查看同一原图不同算法的处理效果对比。

#### 2.7.7 历史记录对比

支持选择 2-3 条历史记录进行横向对比：

| 对比维度 | 说明 |
|---------|------|
| 结果图并排 | 不同算法处理同一原图的结果并排展示 |
| 指标对比 | PSNR/SSIM 指标表格对比 |
| 参数对比 | 各算法使用的参数对比 |
| 评分对比 | 用户对各算法结果的评分对比 |

## 3. 用户交互流程

### 3.1 单张处理完整流程

用户选择或上传图片，系统加载预览并自动分析图像特征。用户选择算法（或使用推荐）并可选调整参数，系统显示算法信息和预估处理时间。点击开始去雾后显示确认对话框，用户确认后开始处理，显示进度条、处理阶段、预估时间和可选的实时预览。处理完成后显示提示并自动跳转到对比页面，用户查看对比效果后可保存或分享结果。

### 3.2 批量处理完整流程

```
【用户操作】                      【系统响应】
    │
选择多张图片（最多20张）
    │                            ← 显示图片列表
    │                            ← 显示总大小和数量
    │
选择统一算法
    │                            ← 显示算法信息
    │                            ← 计算预估总时间
    │
设置参数（可选）
    │                            ← 预览参数效果
    │
点击"批量处理"
    │                            ← 显示确认对话框
    │
确认处理
    │                            ← 开始批量处理
    │                            ├─ 显示整体进度
    │                            ├─ 显示单张进度
    │                            ├─ 显示成功/失败数
    │                            └─ 显示预估时间
    │
    │                            ← 全部处理完成
    │                            ← 显示处理报告
    │
查看批量结果
    │                            ← 展示所有结果
    │
批量导出/分享
    │                            ← 打包下载/分享
```
