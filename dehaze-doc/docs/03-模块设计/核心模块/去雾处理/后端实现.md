## 2. 架构设计

### 2.1 模块分层架构

图像处理模块是用户处理流程的编排中心，负责串联图像输入、算法选择、Python 算法服务调用与结果存储。模块本身不直接执行推理，通过 WPXNet 预查询拦截器链与 Python 算法服务完成预测（Python 端另有 Redis MD5 缓存加速重复请求，见 §6）：

```
Controller 层
├── PredictionController      # 预测任务提交/状态查询/取消/日志列表/批量处理/配额查询
├── PresetController          # 参数预设管理
├── InputHistoryController    # 图像输入历史查询/删除
└── EvaluationController      # 效果评估提交/状态查询/指标历史/日志列表

Service 层
├── SysPredLogService         # 预测编排（单张/批量/取消）、预测日志管理、配额查询
├── SysPresetService          # 参数预设管理（system/custom 类型）
├── SysInputHistoryService    # 图像输入历史查询、删除
└── SysEvalLogService         # 效果评估编排、评估日志管理

执行层
├── PredLogAsyncTask          # 异步执行：调用 Python 算法服务 + 轮询（2s/300s 超时）
└── EvalLogAsyncTask          # 异步执行：调用 Python 评估服务

依赖模块
├── PythonAlgorithmClient（算法管理） # 模型预测/评估接口调用
├── MemberService（会员管理）         # 配额查询（benefit 等级权益）
├── FavoriteService（收藏管理）       # 结果收藏（target_type=result）
└── RecommendService（推荐管理）      # recommendedBy 推荐来源记录
```

### 2.2 核心组件职责

| 组件 | 职责描述 | 关键能力 |
|------|---------|---------|
| SysPredLogService | 预测编排服务 | 单张/批量预测编排、取消预测（终止推理+配额回滚+幂等）、预测日志分页查询（按算法筛选）、配额查询 |
| SysPresetService | 参数预设管理 | system/custom 预设 CRUD、系统预设只读保护、本人自定义预设归属校验 |
| SysInputHistoryService | 图像输入历史管理 | 分页查询（状态/来源筛选）、单删/批删/清空 |
| SysEvalLogService | 评估编排服务 | 评估提交、评估日志管理 |
| PredLogAsyncTask | 预测异步执行器 | 调用 Python 预测、轮询任务状态（2s 间隔、300s 超时）、更新完成/失败 |
| EvalLogAsyncTask | 评估异步执行器 | 调用 Python 评估、更新评估结果 |

## 3. 核心业务流程

### 3.1 单张预测流程

去雾处理模块作为业务编排层，委托算法管理模块执行实际推理：

```
用户提交预测请求（algorithmId + fileId/imageUrl）
    ↓
SysPredLogService 校验算法存在、解析图片来源
    ↓
构建 PredictionContext → 拦截器链 intercept（MD5 缓存 / WPXNet 预查询）
    ↓
命中缓存：直接返回已完成结果（resultUrl + status=2）
    ↓
未命中：写入 sys_pred_log（status=1 处理中）
    ↓
PredLogAsyncTask.execute（异步）：
  - 调用 PythonAlgorithmClient.predict(algorithmId, imageUrl, params)
  - Python 返回处理中 → 轮询 Python 任务状态（2s 间隔，300s 超时）
  - 完成 → 更新 sys_pred_log（status=2 + predUrl + time）
  - 失败 → 更新 sys_pred_log（status=3 + errorMessage）
    ↓
返回 logId + status=1 给前端，前端轮询任务状态直至完成
```

> **配额说明（两端差异）**：
> - **Python 算法服务侧已接入**：`check_and_deduct_quota("dehaze")`（Redis 原子扣减，失败恢复），配额不足返回业务错误
> - **Java 端未接入**：`GET /quota` 仅统计展示剩余次数（`benefit.monthlyDehazeQuota` - `member.monthlyDehazeUsed`），`MemberService.deductQuota` 已实现但 Java 预测流程未调用

### 3.2 批量预测流程

| 阶段 | 处理内容 | 关键决策 |
|------|---------|---------|
| 数量校验 | 校验图片数量是否超过会员等级批量上限 | Java `getBatchLimit`：level_0 默认 5 张，VIP 按 `benefit.batchLimit`（50/200/1000 张），超限返回 A0500；Python 另有硬编码 20 张上限（有效上限 min(20, 等级配置)） |
| 任务拆分 | 将批量请求拆分为 N 个单张预测子任务（逐张循环调用 `predict`） | 每个子任务独立执行，单张失败不影响其他 |
| 结果聚合 | 聚合各子任务结果（logId 列表） | 返回 `total` + `results`（每张的 logId/status） |

> 批量处理为逐张独立提交，无并行/串行策略配置，无整体进度接口——整体进度由前端聚合各子任务状态展示。

### 3.3 参数预设管理流程

参数预设分为系统预设和用户自定义预设两种类型（`sys_preset.type`：`system`/`custom`）：

| 预设类型 | 来源 | 可见范围 | 管理权限 |
|---------|------|---------|---------|
| 系统预设 | 系统管理员预置 | 所有用户可见 | 只读（修改/删除返回 A0502） |
| 用户自定义 | 用户自行保存 | 仅本人可见 | 本人可增删改（归属校验） |

> 预设数据结构（`sys_preset` 表）见 [03-数据库设计.md](../../../02-系统架构/03-数据库设计.md)。当前无预设数量上限限制；系统预设由管理员通过数据维护或算法管理模块维护。

### 3.4 取消预测流程

用户提交预测后可通过取消接口终止任务，由 `SysPredLogService.cancel(logId)` 承载，对应需求 F-M04-001 §2.1.7 后端取消接口：

```
接收取消请求（logId）
    ↓
查询当前任务状态
    ↓
状态判断：
  - 处理中(1)：执行取消流程 ↓
  - 已完成(2)/已失败(3)/已取消(4)：直接返回当前状态（幂等，不重复回滚配额）
    ↓
调用 PythonAlgorithmClient.cancelPredTask(logId) 终止推理进程
    ↓
回滚已扣减配额（Python 端 Redis 补回扣减次数）
    ↓
更新 sys_pred_log.status = 4（已取消）
    ↓
返回当前状态
```

> 取消接口幂等：对非处理中状态的任务直接返回当前状态，不重复终止推理、不重复回滚配额。

### 3.5 图像输入历史管理

图像输入历史由 `SysInputHistoryService` 承载，记录用户的图片输入（上传/拍照/样例）并支持重新处理，对应需求 F-M04-007：

| 能力 | 说明 |
|------|------|
| 分页查询 | 支持状态筛选（1成功/2失败/3处理中）与来源筛选（upload/camera/sample） |
| 删除管理 | 支持单删/批量删除/清空 |
| 重新处理 | 按记录的 taskType 复用原图 URL 发起重新处理 |

> 历史清理按会员权益 `history_retention`（100/500/2000/10000）配置保留条数；数据结构（`sys_input_history` 表）见 [03-数据库设计.md](../../../02-系统架构/03-数据库设计.md)。

## 4. 模块间协作

### 4.1 与算法管理模块的接口调用

| 调用场景 | 调用接口 | 说明 |
|---------|---------|------|
| 提交预测 | `PythonAlgorithmClient.predict(algorithmId, imageUrl, params)` | 直接调用 Python 算法服务，本模块内维护拦截器链（MD5 缓存/WPXNet 预查询）与 sys_pred_log |
| 轮询预测 | `PythonAlgorithmClient.getPredTaskStatus(logId)` | PredLogAsyncTask 轮询 Python 异步任务 |
| 终止预测 | `PythonAlgorithmClient.cancelPredTask(logId)` | 取消流程终止 Python 端推理进程 |
| 提交评估 | `PythonAlgorithmClient.evaluate(...)` | EvalLogAsyncTask 调用 Python 评估服务 |

> 预测执行（拦截器链、Python 调用、日志落库）在图像处理模块内完成，算法管理模块提供算法元数据与 Python 客户端。

### 4.2 与收藏管理模块的集成

| 集成点 | 触发时机 | 实现方式 |
|--------|---------|---------|
| 收藏事件触发 | 用户在预测日志或对比页面点击收藏 | 调用 FavoriteService.favorite(userId, "result", recordId) |
| 取消收藏 | 用户取消收藏 | 调用 FavoriteService.unfavorite(userId, "result", recordId) |
| 收藏状态查询 | 加载预测日志列表时 | 批量查询 FavoriteService.isFavorited() 标记每条记录的收藏状态 |

收藏能力由收藏管理模块统一管理（`sys_favorite` 表，`target_type='result'`）。

### 4.3 与推荐管理模块的集成

| 集成点 | 说明 |
|--------|------|
| 推荐算法一键使用 | 算法选择页面的推荐结果中，用户点击"立即使用"后携带 `recommendedBy`（推荐记录 ID）进入处理流程 |
| recommendedBy 记录 | 预测请求携带 `recommendedBy` 字段，用于推荐管理模块追踪采纳率 |

### 4.4 与消息通知模块的集成

> 处理完成/失败通知当前未接入——预测流程不发送消息通知（`PredLogAsyncTask` 仅更新日志与指标，无 MessageService 调用），前端通过页面轮询获取结果。通知能力由消息通知模块提供。

### 4.5 与会员管理模块的集成

| 集成点 | 说明 |
|--------|------|
| 配额查询 | `GET /quota` 查询剩余次数：`total` 取 `benefit.monthlyDehazeQuota`（无则 member 字段、兜底 20），`used` 取 `member.monthlyDehazeUsed` |
| 批量上限 | 批量处理校验 `getBatchLimit(member)`：level_0 默认 5，VIP 按 `benefit.batchLimit` |
| 配额扣减 | Python 端 `check_and_deduct_quota("dehaze")`（Redis 原子扣减）已接入；Java 端 `MemberService.deductQuota` 已实现但未接入（见 §3.1） |
| 配额数据源同步 | Python 端 Redis 为扣减权威源，Java 端 `member.monthlyDehazeUsed` 为展示数据源；Python 端扣减成功后异步回写 member 表已用次数，`GET /quota` 展示值以 member 表为准，避免两端数据漂移 |

### 4.6 与任务管理模块的关系

| 任务管理状态 | 预测日志对应状态（`sys_pred_log.status`） |
|------------|----------------|
| PENDING/PROCESSING | 1（处理中） |
| COMPLETED | 2（已完成） |
| FAILED | 3（失败） |
| CANCELLED | 4（已取消） |

当前预测任务不进入 `sys_task` 表，在 `sys_pred_log` 维护四态状态机（1处理中/2已完成/3失败/4已取消）。状态 4（已取消）由取消流程触发（见 §3.4），伴随推理终止与配额回滚。

## 6. 缓存策略

### 6.1 快速返回缓存（双层）

预测请求的快速返回由两层缓存构成：

**① Java/Python 拦截器链（WPXNet 预查询）**

预测请求先经过拦截器链（`PredictionContext` + `PredictionInterceptor`），命中拦截器则跳过算法推理直接返回结果：

| 拦截器 | 作用 | 命中条件 |
|-------|------|---------|
| WPXNet 预查询拦截器 | 标准数据集图片（WPXNet 系列）直接返回预处理结果 | 算法为 WPXNet 系列且原图 MD5 在 `sys_wpx_file` 映射表 |

拦截器链可扩展（实现 `PredictionInterceptor` 接口 + `@Component` 自动注册），当前仅注册 WPXNet 预查询拦截器。

**② Python 端 Redis MD5 缓存**

Python 算法服务在预测流程内实现 MD5 缓存：下载原图后计算 MD5，查 Redis `prediction:{algorithmId}:{imageMd5}`（24h TTL），命中则直接返回缓存结果 URL，不调用算法推理；未命中执行推理后写入缓存。

**特性**：
- 命中缓存时响应时延降至毫秒级（`sys_pred_log` 直接写入已完成记录）

### 6.2 参数预设查询

参数预设列表直接查询 MySQL（`sys_preset`），当前无缓存；数据量小、查询频率低，缓存收益有限。

## 7. 安全设计

### 7.1 配额查询与防穿透

| 防护措施 | 说明 |
|---------|------|
| 配额查询 | `GET /quota` 展示剩余次数（`benefit.monthlyDehazeQuota` - `member.monthlyDehazeUsed`），仅统计不拦截 |
| 配额扣减 | Python 端 `check_and_deduct_quota` 使用 Redis 原子操作（DECR + 阈值回滚）防并发超扣（已接入）；Java 端 `deductQuota` 已实现但未接入（见 §3.1） |
| 配额回滚 | 取消流程回滚已扣减配额（Python 端 Redis 补回），幂等控制避免重复回滚（见 §3.4） |

### 7.2 参数校验

| 校验项 | 规则 | 错误码 |
|--------|------|--------|
| 算法 ID 有效性 | algorithmId 对应的算法必须存在 | A0401 |
| 图片来源 | fileId 与 imageUrl 至少提供一个，来源可解析 | A0500 |
| 批量上限 | 批量图片数量不超过会员等级批量上限（`getBatchLimit`） | A0500 |
| 预设名称冲突 | 同一用户下自定义预设名称不可重复（与系统预设同名亦冲突） | A0501 |
| 预设归属 | 仅本人自定义预设可修改/删除；系统预设只读 | A0502 |
| 预设存在性 | 操作不存在的预设 | A0401 |

### 7.3 数据隔离

- 预测日志列表仅返回当前用户记录（`create_by` 过滤）
- 参数预设仅能管理自己的自定义预设（系统预设只读）
- 所有接口校验用户身份与资源归属

## 8. 配置项

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| 预测轮询间隔 | PredLogAsyncTask 轮询 Python 任务状态间隔 | 2s |
| 预测轮询超时 | Python 任务状态轮询超时 | 300s |
| 配额兜底值 | 无会员/权益配置时的月度配额 | 20 |
| 批量兜底上限 | 非 VIP（level_0）用户的批量上限 | 5 |
| 历史记录配额 | 图像输入历史（`sys_input_history`）默认条数 | 100 |

> 以上为代码内常量/默认值；预测结果保留时长、日志保留策略遵循 `sys_pred_log` 清理定时任务（见 [任务管理/后端实现.md](../../基础模块/任务管理/后端实现.md)）。
