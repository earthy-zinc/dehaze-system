## 2. 架构设计

### 2.1 模块分层架构

去雾处理模块是用户去雾业务流程的编排中心，负责串联图像输入、算法选择、Python 算法服务调用、结果存储与通知推送。模块本身不直接执行推理，而是通过算法管理模块的 PredictionService 调用 Python 算法服务：

```
Controller 层
├── DehazeController          # 预测任务提交/查询/取消
├── PresetController          # 参数预设管理
└── HistoryController         # 处理历史查询/删除/重新处理

Service 层
├── DehazeService             # 预测编排服务（单张/批量）
├── PresetService             # 参数预设管理服务
├── QuotaService              # VIP 配额校验服务
└── DehazeHistoryService      # 处理历史管理服务

依赖模块
├── PredictionService（算法管理）  # 模型预测接口
├── EvaluationService（算法管理）  # 效果评估接口
├── MemberService（会员管理）      # 配额校验、等级权益
├── FavoriteService（收藏管理）    # 结果收藏
├── RecommendService（推荐管理）   # 推荐策略指导默认参数
├── MessageService（消息通知）     # 完成/失败/配额提醒通知
└── TaskService（任务管理）        # 异步任务状态机参考
```

### 2.2 核心组件职责

| 组件 | 职责描述 | 关键能力 |
|------|---------|---------|
| DehazeService | 预测编排服务 | 单张/批量预测流程编排、参数校验、调用 PredictionService、进度追踪 |
| PresetService | 参数预设管理 | 管理员预设 CRUD、用户自定义预设管理、VIP 预设数量限制 |
| QuotaService | VIP 配额校验 | 处理前校验月度配额、扣减次数（原子操作）、配额不足拦截 |
| DehazeHistoryService | 处理历史管理 | 历史记录分页查询、筛选（算法/评分/状态/时间）、重新处理触发 |

## 3. 核心业务流程

### 3.1 单张预测流程

去雾处理模块作为业务编排层，委托算法管理模块执行实际推理：

```
用户提交预测请求
    ↓
DehazeService 接收请求
    ↓
QuotaService 校验 VIP 月度配额 → 不足返回错误码
    ↓
DehazeService 调用 PredictionService（算法管理模块）
    ↓
PredictionService 内部处理：
  - MD5 缓存查询（命中直接返回）
  - 调用 Python 算法服务执行推理
  - 写入 sys_pred_log
    ↓
DehazeService 收到预测结果后：
  - 写入 sys_input_history（处理历史）
  - 触发收藏管理模块初始化收藏状态
  - 扣减 VIP 配额
    ↓
返回任务标识给前端
    ↓
（如为异步模式）前端轮询任务状态直至完成
```

### 3.2 批量预测流程

| 阶段 | 处理内容 | 关键决策 |
|------|---------|---------|
| 参数校验 | 校验图片数量是否超过会员批量上限 | 超限返回错误码，引导升级 |
| 任务拆分 | 将批量请求拆分为 N 个单张预测子任务 | 每个子任务独立执行，单张失败不影响其他 |
| 并行/串行调度 | 根据配置和设备负载选择执行策略 | 智能模式：根据当前系统负载自动切换 |
| 进度汇总 | 聚合各子任务状态，计算整体进度 | 前端轮询整体进度 + 单张进度 |
| 完成通知 | 批量全部完成后触发消息通知 | 成功/失败数量汇总通知 |

### 3.3 参数预设管理流程

参数预设分为管理员预设和用户自定义预设两种类型：

| 预设类型 | 来源 | 可见范围 | 管理权限 |
|---------|------|---------|---------|
| 管理员预设 | 系统管理员预置 | 所有用户可见 | 管理员可增删改 |
| 用户自定义 | 用户自行保存 | 仅本人可见 | 本人可增删改，VIP 数量限制 |

**用户自定义预设数量限制**：

| 会员等级 | 最大预设数量 |
|---------|------------|
| 普通用户 | 3 |
| VIP1 | 10 |
| VIP2 | 20 |
| SVIP | 无限制 |

**预设数据结构**：

| 字段 | 类型 | 说明 |
|------|------|------|
| name | String | 预设名称 |
| type | Enum | 预设类型（admin/user） |
| userId | Long | 所属用户（管理员预设为空） |
| algorithmId | Long | 关联算法 |
| params | JSON | 参数键值对（去雾强度、色彩饱和度等） |
| isDefault | Boolean | 是否为默认预设 |

## 4. 模块间协作

### 4.1 与算法管理模块的接口调用

| 调用场景 | 调用接口 | 说明 |
|---------|---------|------|
| 提交预测 | PredictionService.predict() | 委托执行去雾推理，算法管理模块内部处理 MD5 缓存和 Python 服务调用 |
| 查询预测结果 | PredictionService.getResult() | 查询 sys_pred_log 获取处理结果 |
| 提交评估 | EvaluationService.evaluate() | 委托执行效果评估计算 |

去雾处理模块不直接调用 Python 算法服务，所有算法推理均通过算法管理模块的 PredictionService 完成，遵循单一依赖方向原则。

### 4.2 与收藏管理模块的集成

| 集成点 | 触发时机 | 实现方式 |
|--------|---------|---------|
| 收藏事件触发 | 用户在处理历史或对比页面点击收藏 | 调用 FavoriteService.favorite(userId, "result", recordId) |
| 取消收藏 | 用户取消收藏 | 调用 FavoriteService.unfavorite(userId, "result", recordId) |
| 收藏状态查询 | 加载处理历史列表时 | 批量查询 FavoriteService.isFavorited() 标记每条记录的收藏状态 |

去雾处理模块不直接操作收藏状态，收藏能力由收藏管理模块统一管理（`sys_favorite` 表，`target_type='result'`）。

### 4.3 与推荐管理模块的集成

| 集成点 | 说明 |
|--------|------|
| 推荐算法一键使用 | 算法选择页面的推荐结果中，用户点击"立即使用"后携带 `recommendedBy` 字段进入去雾处理流程 |
| recommendedBy 记录 | 处理历史记录中存储 `recommendedBy` 字段，标识本次处理是否来自推荐引擎 |
| 默认参数方案 | 推荐引擎输出的推荐算法可附带推荐参数方案，作为默认参数预设 |

### 4.4 与消息通知模块的集成

去雾处理模块通过消息通知模块向用户推送以下通知：

| 触发事件 | 消息类型 | 通知内容 | 触发条件 |
|---------|---------|---------|---------|
| 单张处理完成 | 业务通知 | "去雾处理已完成，点击查看效果" | 单张任务状态变为已完成 |
| 批量处理完成 | 业务通知 | "批量去雾任务（共 N 张，成功 X 张）已完成" | 所有子任务完成 |
| 处理失败 | 业务通知 | "去雾处理失败：{失败原因}" | 任务状态变为已失败 |
| 配额即将用尽 | 业务通知 | "本月剩余去雾次数不足 3 次，建议升级会员" | 扣减后剩余次数 ≤ 3 |

消息通知模块通过消息模板机制生成通知内容，使用 `{varName}` 占位符替换变量。去雾处理模块调用消息发送接口时传入业务模块标识和业务 ID 实现幂等去重。

### 4.5 与会员管理模块的集成

| 集成点 | 说明 |
|--------|------|
| 配额校验 | 处理前调用 MemberService.checkQuota(userId, "dehaze") 检查月度去雾次数 |
| 配额扣减 | 处理成功后调用 MemberService.deductQuota(userId, "dehaze") 原子扣减 |
| 批量上限 | 批量处理时校验 MemberService.getBatchLimit(level) 获取当前等级的批量上限 |
| 等级权益 | 查询 MemberService.getBenefit(level) 获取高级参数调节、高清导出等功能开关 |

### 4.6 与任务管理模块的对齐

去雾处理模块的异步任务状态管理参考任务管理模块的状态机设计：

| 任务管理状态 | 去雾处理对应状态 | 存储位置 |
|------------|----------------|---------|
| PENDING | 处理中（status=3） | sys_input_history.status |
| PROCESSING | 处理中（status=3） | sys_input_history.status |
| COMPLETED | 已完成（status=1） | sys_input_history.status |
| FAILED | 已失败（status=2） | sys_input_history.status |

去雾处理任务不进入 sys_task 表，而是在 sys_input_history 中维护处理状态。状态值定义与任务管理模块的语义对齐，保证用户体验一致性。

## 6. 缓存策略

### 6.1 MD5 缓存命中

去雾处理模块本身不实现预测结果缓存，而是依赖算法管理模块的 PredictionService 内部的 MD5 缓存机制：

| 缓存对象 | 缓存 Key | TTL | 说明 |
|---------|---------|------|------|
| 预测结果 | `prediction:{algorithmId}:{imageMd5}` | 24h | 由算法管理模块管理，去雾处理模块透明使用 |

**集成说明**：
- 去雾处理模块调用 PredictionService 时无需关心缓存逻辑，缓存命中/未命中对调用方透明
- 算法版本更新时，算法管理模块负责失效对应算法的所有预测缓存
- 缓存命中可大幅降低重复处理请求的响应时延（从秒级降至毫秒级）

### 6.2 参数预设缓存

| 缓存对象 | 缓存 Key | TTL | 更新策略 |
|---------|---------|------|---------|
| 管理员预设列表 | `preset:admin:list` | 30 分钟 | 管理员增删改时失效 |
| 用户预设列表 | `preset:user:{userId}` | 30 分钟 | 用户增删改时失效 |

## 7. 安全设计

### 7.1 VIP 配额穿透防护

| 防护措施 | 说明 |
|---------|------|
| 原子扣减 | 使用 Redis 原子操作（DECR + 阈值判断）防止并发超扣 |
| 预校验 + 实扣减 | 处理前预校验配额，处理成功后实际扣减，失败不扣减 |
| 配额缓存 | 用户配额缓存在 Redis 中，MemberService 维护一致性 |
| 降级策略 | 缓存不可用时降级为直接查询 MySQL，保证核心功能可用 |

### 7.2 参数校验

| 校验项 | 规则 | 错误码 |
|--------|------|--------|
| 算法 ID 有效性 | algorithmId 对应的算法必须为已发布(4)状态 | A0401 |
| 文件 ID 有效性 | fileId 对应的文件必须存在且属于当前用户 | A0401 |
| 参数范围 | 去雾强度 0-100、色彩饱和度 0-200、对比度 0-200、锐化程度 0-100 | A0400 |
| 批量上限 | 批量图片数量不超过会员等级的批量处理上限 | B0301 |
| 预设名称唯一 | 同一用户下预设名称不能重复 | A0501 |

### 7.3 数据隔离

- 处理历史仅能查询当前用户自己的记录
- 参数预设仅能管理自己的自定义预设（管理员预设只读）
- 所有接口校验用户身份与资源归属
