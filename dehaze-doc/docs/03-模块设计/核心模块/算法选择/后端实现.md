## 2. 架构设计

### 2.1 模块分层架构

算法选择模块是面向用户的算法发现与选择界面，核心职责是从算法管理模块获取已发布算法数据，为用户提供树形浏览、搜索、对比、自定义图片测试、算法推荐匹配等能力。

| 层级 | 组件 | 职责 |
|------|------|------|
| Controller | AlgorithmSelectController | 算法树/详情/测试/搜索/对比/推荐匹配 |
| Service | AlgorithmSelectService | 树构建、搜索匹配、对比预测、测试委托 |
| Service | RecommendService | 推荐匹配编排（F-M03-007：关键词/任务类型/样例算法匹配与降级） |

| 依赖模块 | 调用对象 | 用途 |
|---------|---------|------|
| 算法管理 | SysAlgorithmService | 算法元数据（全部算法列表、详情） |
| 图像处理 | SysPredLogService | 预测调用（详情样例图、对比预测、测试） |
| 评分 | SysRatingMapper | 评分聚合（平均分、评价数） |
| 预测日志 | SysPredLogMapper | 使用次数、样例效果图 |

### 2.2 核心组件职责

| 组件 | 职责描述 | 关键能力 |
|------|---------|---------|
| AlgorithmSelectService | 算法选择编排 | 树形结构构建（task_type 第一级 + parentId 子级，仅已发布）、详情聚合（评分/使用次数/样例图）、搜索匹配（名称/拼音/类型/描述，限定 taskType）、对比预测、自定义测试委托 |
| RecommendService | 推荐匹配编排（F-M03-007） | 按 taskType 过滤候选 → keyword 匹配 → sampleAlgorithmId 相似匹配 → 综合评分排序 → Top N 输出；空入参兜底返回 taskType 评分 Top N |

## 3. 核心业务流程

### 3.1 树形结构

**业务流程**：获取全部算法 → 过滤 status=4（已发布） → 按 `parentId` 自关联构建树 → 过滤空分类节点 → 返回 AlgorithmSelectNodeVO 树。

**关键规则**：

| 规则 | 说明 |
|------|------|
| 仅已发布 | 过滤 `AlgorithmStatusEnum.PUBLISHED`（status=4），软删行经全局逻辑删除过滤排除 |
| 第一级分类 | 规划中：设计目标按 `sys_algorithm.task_type` 分组（表字段尚未落地），当前三端均按 `parent_id` 自关联构建 |
| 子级结构 | 按 `sys_algorithm.parent_id` 自关联递归构建 |
| 空分类过滤 | 规划中：无分类标识字段时无法区分"空分类"与"根下算法"，过滤会把扁平数据形态（算法直接挂根）整树清空（三端曾实现并已撤销），待 `task_type`/节点类型字段落地后恢复 |
| 节点类型 | `leaf` 布尔字段标记叶子算法节点（三端统一字段名 `leaf`，非 `isLeaf`），节点含 `id/parentId/name/type/leaf/children` |
| Tab 联动 | 规划中：接口支持 `taskType` 参数按任务类型过滤（`task_type` 字段未落地，三端暂未实现） |

### 3.2 搜索流程

**业务流程**：空关键词直接返回空列表 → 获取已发布算法列表 → 关键词归一化（trim + 小写） → 逐算法匹配（任一命中即计入） → 返回匹配算法列表。

> taskType 过滤与 Tab 联动规划中（同 §3.1）；拼音搜索为 Java 端运行时转换（Hutool PinyinUtil），Python 端匹配名称（LIKE）/描述/类型，Go 端匹配名称/类型/描述（分页返回）。

| 匹配维度 | 说明 |
|---------|------|
| 名称包含 | 算法名称包含关键词 |
| 拼音全拼 | 名称拼音全拼包含关键词（Hutool `PinyinUtil.getPinyin`） |
| 拼音首字母 | 名称拼音首字母匹配 |
| 类型匹配 | 算法类型包含关键词 |
| 描述匹配 | 算法描述包含关键词 |

> 拼音搜索为运行时转换（非预计算拼音字段）；无标签 JSON 字段（标签检索并入类型/描述匹配）；无组合搜索与搜索历史（见需求规格 §2.3.1）。搜索默认在当前 taskType 范围内执行（与 §3.1 Tab 联动）。

### 3.3 对比流程

**业务流程**：校验算法数量 2-3 个（@Size(min=2,max=3) + 服务层二次校验） → 校验图片输入（fileId/imageUrl 二选一，均空拒绝） → 校验每个算法存在且已发布 → 复用 `SysPredLogService.predict` 对同一图片逐算法执行预测 → 每算法构造 AlgorithmCompareVO（algorithmId/algorithmName/resultUrl/time） → 单算法预测失败通过异常隔离（catch 后置空结果）不影响整体 → 返回对比结果数组（非分页包装）。

**对比维度**：同一测试图片分别预测，对比各算法处理结果图与处理耗时（ms）。评估指标（PSNR/SSIM）为规划中：需清晰参考图，当前三端均未返回 `metrics` 字段。

### 3.4 自定义图片测试流程

**业务流程**：校验算法存在且已发布（未发布返回"算法不存在或未发布"） → 校验图片输入（fileId/imageUrl 二选一，均空拒绝；Python 端额外校验 URL 扩展名） → 委托预测服务 → 返回异步任务契约（logId/status，命中缓存或拦截器时含 resultUrl/time） → 前端按轮询契约查询任务状态。测试不计入用户配额。

> 测试复用图像处理模块的完整预测链路（含拦截器链缓存与预测缓存），结果同时写入 `sys_pred_log`，与算法详情样例图来源一致。

### 3.5 算法详情

**业务流程**：校验算法存在且已发布 → 聚合基础字段（name/type/img/description/path/size/params/flops/version/status） → 评分聚合（sys_rating 按 algorithmId 统计平均分 avgRating 与评价数 ratingCount） → 使用次数（sys_pred_log 按 algorithmId 计数） → 样例效果图（sys_pred_log 取最近 3 条成功记录的结果 URL） → 返回 AlgorithmDetailVO。

### 3.6 算法推荐匹配（F-M03-007）

**业务流程**：按 `taskType` 过滤候选算法（已发布） → `keyword` 匹配（名称/拼音/类型/描述，复用搜索逻辑） → `sampleAlgorithmId` 相似匹配（同 task_type + 同分类 + 标签重合） → 综合评分排序（匹配度 + 算法评分 + 使用次数） → 返回 Top N 推荐列表（含匹配度、推荐理由、预期耗时）。

**降级策略**：业务降级规则见 [需求规格 §2.7.4](./需求规格.md)。实现层补充约定：匹配结果为空时返回 `total=0`、`items=[]`，HTTP 200（非业务错误，由调用方展示空态）。

> 本模块只做算法推荐匹配（结构化参数 → 匹配列表），不实现 LLM 对话与意图理解（由 AI 对话模块 F-M08-004 承载）。与 F-M03-002（图像特征分析推荐）互补：F-M03-002 由图像特征驱动，F-M03-007 由结构化参数匹配驱动。

## 4. 模块间协作

### 4.1 与算法管理模块的集成

| 调用场景 | 调用接口 | 说明 |
|---------|---------|------|
| 算法列表 | `SysAlgorithmService.getAllAlgorithms()` | 获取全部算法，本模块过滤已发布并构建树 |
| 算法详情 | `SysAlgorithmService.getAlgorithmById(id)` | 获取算法元数据，校验存在性 |

**算法可见性规则**：仅已发布（status=4）算法对用户可见；草稿/测试中/待审核/停用/归档均不可见（无 VIP 专属可见算法）。

### 4.2 与图像处理模块的集成

| 调用场景 | 调用接口 | 说明 |
|---------|---------|------|
| 自定义测试 | `SysPredLogService.predict(predForm)` | 复用完整预测链路（异步 + 拦截器缓存） |
| 对比预测 | `SysPredLogService.predict(predForm)` | 各算法并发执行预测 |
| 样例图/使用次数 | `SysPredLogMapper` 查询 | 最近成功记录、计数 |

### 4.3 与收藏管理模块的集成

收藏能力由收藏管理模块统一提供（`sys_favorite`，`target_type='algorithm'`），算法卡片/详情页收藏按钮调用收藏管理接口。

### 4.4 与推荐管理模块的集成

推荐区域数据来自推荐管理模块接口（`F-REC-001` 特征分析 + `F-REC-002` 推荐生成，`TOP_N=3`），推荐算法卡片展示匹配度/评分/推荐理由，`recommendedBy` 携带推荐记录 ID。

## 6. 安全设计

### 6.1 数据隔离

- 推荐结果按用户个性化，不同用户的推荐互不影响
- 自定义图片测试结果仅返回当前用户记录

### 6.2 算法可见性

算法可见性规则见 §4.1（仅已发布算法对用户可见，无 VIP 差异化）。

### 6.3 收藏隔离

算法收藏由收藏管理模块统一管理（`sys_favorite`，`target_type='algorithm'`），用户只能操作自己的收藏记录。
