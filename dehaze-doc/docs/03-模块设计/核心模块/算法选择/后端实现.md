## 2. 架构设计

### 2.1 模块分层架构

算法选择模块是面向用户的算法发现与选择界面，核心职责是从算法管理模块获取已发布算法数据，结合推荐管理模块的推荐结果和收藏管理模块的收藏状态，为用户提供搜索、对比、浏览等能力：

```
Controller 层
├── AlgorithmSelectController     # 算法搜索/对比/详情/树形展示
└── AlgorithmTestController      # 自定义图片测试

Service 层
├── AlgorithmSelectService       # 算法选择编排服务（搜索/对比/详情/树形）
├── AlgorithmSearchService       # 搜索服务（关键词/拼音/标签）
├── AlgorithmCompareService      # 对比服务（最多 3 个算法）
└── AlgorithmTestService         # 自定义图片测试服务

依赖模块
├── SysAlgorithmService（算法管理）    # 已发布算法列表、算法详情、树形结构
├── FavoriteService（收藏管理）       # 收藏状态查询、收藏事件
├── RecommendService（推荐管理）      # 推荐结果展示、推荐效果反馈
└── MemberService（会员管理）         # VIP 实验性算法可见性过滤
```

### 2.2 核心组件职责

| 组件 | 职责描述 | 关键能力 |
|------|---------|---------|
| AlgorithmSelectService | 算法选择编排 | 组合搜索/推荐/收藏状态，构建前端所需的完整算法视图 |
| AlgorithmSearchService | 搜索服务 | 关键词匹配、拼音搜索、标签筛选、多条件组合查询 |
| AlgorithmCompareService | 对比服务 | 多算法多维度数据聚合（基本信息/性能/适用性/用户反馈） |
| AlgorithmTestService | 自定义测试 | 用户上传自定义图片后调用 PredictionService 快速验证算法效果 |

## 3. 核心业务流程

### 3.1 搜索流程

```
用户输入搜索关键词
    ↓
AlgorithmSearchService 接收请求
    ↓
多维度匹配查询：
  ├── 算法名称（中文/英文）模糊匹配
  ├── 算法标签精确匹配（#深度学习）
  ├── 拼音首字母匹配（DCP → Dark Channel Prior）
  └── 算法描述全文检索
    ↓
结果聚合去重 → 按相关度排序
    ↓
批量查询收藏状态（FavoriteService）
    ↓
返回搜索结果列表
```

### 3.2 搜索实现策略

| 搜索方式 | 实现策略 | 说明 |
|---------|---------|------|
| 关键词搜索 | MySQL LIKE + 全文索引 | 匹配算法名称、标签、描述字段 |
| 拼音搜索 | 预计算拼音字段 | sys_algorithm 表冗余存储算法名称的拼音全拼和首字母，搜索时通过 LIKE 匹配 |
| 标签搜索 | 标签字段 JSON 解析 | 标签以 JSON 数组存储，通过 JSON_CONTAINS 精确匹配 |
| 组合搜索 | 多条件 AND 逻辑 | 各搜索维度结果取交集后排序 |

**拼音搜索预计算**：
- 算法创建/更新时，自动计算并存储算法中文名称的拼音全拼（如 `an-tong-dao-xian-yan`）和首字母缩写（如 `atdxy`）
- 搜索时同时匹配拼音字段和原始名称字段

### 3.3 对比流程

```
用户选择 2-3 个算法 → 点击"对比"
    ↓
AlgorithmCompareService 接收请求
    ↓
并行查询各算法数据：
  ├── 基本信息（名称、类型、版本、适用场景、推荐指数）
  ├── 性能指标（处理速度、成功率、平均 PSNR/SSIM）
  ├── 适用性（场景类型匹配度）
  └── 用户反馈（评分分布、好评率）
    ↓
数据聚合 → 构建多维度对比视图
    ↓
返回对比结果
```

**对比维度**：

| 维度 | 数据来源 | 展示形式 |
|------|---------|---------|
| 基本信息 | sys_algorithm | 表格对比 |
| 性能指标 | sys_pred_log 聚合数据 | 柱状图数据 |
| 适用性 | 算法标签 + 推荐规则 | 雷达图数据 |
| 用户反馈 | sys_rating 聚合数据 | 评分对比 |

**对比限制**：最多 3 个算法同时对比。

### 3.4 自定义图片测试流程

```
用户上传自定义测试图片 + 选择算法
    ↓
AlgorithmTestService 接收请求
    ↓
调用 PredictionService（算法管理模块）执行快速预测
    ↓
返回处理结果供用户评估算法效果
    ↓
测试结果不写入 sys_input_history（仅为临时预览）
```

## 4. 模块间协作

### 4.1 与算法管理模块的集成

| 调用场景 | 调用接口 | 说明 |
|---------|---------|------|
| 已发布算法列表 | SysAlgorithmService.listPublished() | 获取 status=4（已发布）的算法列表，支持树形结构 |
| 算法详情 | SysAlgorithmService.getDetail(id) | 获取算法完整信息（基本信息/技术信息/运营信息） |
| 算法树形结构 | SysAlgorithmService.getTree() | 获取按算法类型分类的树形结构 |
| 自定义测试 | PredictionService.predict() | 临时预测，不入历史记录 |

**算法可见性规则**：
- 已发布(4)算法对所有用户可见
- 实验性(experimental)算法仅对 VIP 用户可见
- 已停用(5)/已归档(6)算法不可见

### 4.2 与收藏管理模块的集成

| 集成点 | 触发时机 | 实现方式 |
|--------|---------|---------|
| 收藏事件 | 算法卡片/详情页点击收藏 | 调用 FavoriteService.favorite(userId, "algorithm", algorithmId) |
| 取消收藏 | 算法卡片/详情页取消收藏 | 调用 FavoriteService.unfavorite(userId, "algorithm", algorithmId) |
| 收藏状态查询 | 加载算法列表/详情时 | 批量查询 FavoriteService.batchIsFavorited(userId, "algorithm", ids) |

### 4.3 与推荐管理模块的集成

| 集成点 | 说明 |
|--------|------|
| 推荐结果接收 | 算法选择页面的"推荐"Tab 调用 RecommendService.getRecommendations(imageId) 获取推荐算法列表 |
| 推荐效果反馈 | 用户使用推荐算法后，调用 RecommendService.feedback(recommendId, action) 反馈推荐效果 |
| 推荐标签展示 | 推荐算法在列表中带有"推荐"标签和匹配度百分比 |

### 4.4 与会员管理模块的集成

| 集成点 | 说明 |
|--------|------|
| 实验性算法可见性 | 查询用户会员等级，VIP 用户可见实验性(experimental)类型算法，普通用户隐藏 |
| VIP 专属算法标识 | VIP 可见的算法带"VIP专享"标签 |

## 5. 树形算法结构

### 5.1 数据来源

算法树形结构由算法管理模块的 SysAlgorithmService 提供，基于 `sys_algorithm` 表的 `parent_id` 自关联实现。算法分类（传统算法/深度学习/混合算法）通过字典表 `sys_algorithm_type` 管理。

### 5.2 前端适配

算法选择模块对树形结构进行前端展示适配：

| 适配项 | 说明 |
|--------|------|
| 节点图标 | 分类节点显示文件夹图标，叶子算法显示闪电图标 |
| 选中高亮 | 选中算法时主色+透明度高亮 |
| 数量统计 | 分类节点显示包含的已发布算法数量 |
| 展开/收起 | 支持全部展开/全部收起 |

### 5.3 过滤规则

算法选择模块在获取树形结构后，需过滤非用户可见的算法：

| 过滤条件 | 规则 |
|---------|------|
| 状态过滤 | 仅显示已发布(4)算法 |
| VIP 过滤 | experimental 类型算法仅 VIP 可见 |
| 空分类过滤 | 过滤后无可见算法的分类节点隐藏 |

## 6. 对比功能

### 6.1 数据聚合策略

对比功能需要从多个数据源聚合数据：

| 数据维度 | 数据源 | 聚合方式 |
|---------|--------|---------|
| 基本信息 | sys_algorithm | 直接查询 |
| 性能指标 | sys_pred_log 聚合 | 按 algorithm_id 分组统计 AVG(processing_time)、COUNT(CASE WHEN status=1) |
| 用户评分 | sys_rating 聚合 | 按 algorithm_id 分组统计 AVG(score)、COUNT(*) |
| 收藏数 | sys_favorite 聚合 | 按 target_id 分组统计 COUNT(*)，WHERE target_type='algorithm' |

### 6.2 对比结果结构

```
对比结果：
├── algorithms[]                 # 算法列表（2-3个）
│   ├── basicInfo                # 基本信息
│   ├── performance              # 性能指标
│   ├── applicability            # 适用性
│   └── userFeedback             # 用户反馈
├── comparisonTable              # 多维度对比表格
└── recommendation               # 推荐建议（最优选择 + 理由）
```

## 7. 配置项

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| algorithm.select.search.max-results | 搜索结果最大数量 | 50 |
| algorithm.select.compare.max-count | 对比算法最大数量 | 3 |
| algorithm.select.search.hot-tags | 热门搜索标签列表 | ["深度学习","传统算法","DCP","AOD-Net"] |
| algorithm.select.search.history-max | 搜索历史最大保存条数 | 10 |
| algorithm.select.cache.list-ttl | 算法列表缓存时间 | 30 分钟 |
| algorithm.select.cache.detail-ttl | 算法详情缓存时间 | 1 小时 |
