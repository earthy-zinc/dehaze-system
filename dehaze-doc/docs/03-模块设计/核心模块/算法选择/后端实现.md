## 2. 架构设计

### 2.1 模块分层架构

算法选择模块是面向用户的算法发现与选择界面，核心职责是从算法管理模块获取已发布算法数据，为用户提供树形浏览、搜索、对比、自定义图片测试等能力：

```
Controller 层
└── AlgorithmSelectController   # 算法树/详情/测试/搜索/对比

Service 层
└── AlgorithmSelectService      # 树构建、搜索匹配、对比预测、测试委托

依赖模块
├── SysAlgorithmService（算法管理）   # 算法元数据（全部算法列表、详情）
├── SysPredLogService（图像处理）     # 预测调用（详情样例图、对比预测、测试）
├── SysRatingMapper                  # 评分聚合（平均分、评价数）
└── SysPredLogMapper                 # 使用次数、样例效果图
```

### 2.2 核心组件职责

| 组件 | 职责描述 | 关键能力 |
|------|---------|---------|
| AlgorithmSelectService | 算法选择编排 | 树形结构构建（仅已发布）、详情聚合（评分/使用次数/样例图）、搜索匹配（名称/拼音/标签/描述）、对比预测、自定义测试委托 |

## 3. 核心业务流程

### 3.1 树形结构

```
AlgorithmSelectService.getTree()
    ↓
获取全部算法 → 过滤 status=4（已发布）
    ↓
按 parentId 分组 → 递归构建树（根节点 parentId=0）
    ↓
过滤空分类节点（分类节点无子节点时隐藏）
    ↓
返回 AlgorithmSelectNodeVO 树
```

**关键规则**：

| 规则 | 说明 |
|------|------|
| 仅已发布 | 过滤 `AlgorithmStatusEnum.PUBLISHED`（status=4） |
| 层级结构 | 基于 `sys_algorithm.parent_id` 自关联，根节点 parentId=0 |
| 空分类过滤 | 分类节点（parentId=0）无任何可见子节点时隐藏 |
| 节点类型 | `leaf` 标记叶子算法节点，分类节点含 `children` |

### 3.2 搜索流程

```
AlgorithmSelectService.search(keyword)
    ↓
获取已发布算法列表 → 关键词归一化（trim + 小写）
    ↓
PinyinUtil 计算拼音首字母
    ↓
逐算法匹配（任一命中即计入）：
  ├── 名称包含关键词
  ├── 名称拼音全拼包含关键词（PinyinUtil.getPinyin）
  ├── 名称拼音首字母匹配
  ├── 算法类型包含关键词
  └── 算法描述包含关键词
    ↓
返回匹配的算法节点列表（leaf=true）
```

> **实现说明**：拼音搜索为**运行时转换**（Hutool `PinyinUtil`），非预计算拼音字段；无标签 JSON 字段（标签检索并入类型/描述匹配）；无组合搜索与搜索历史（见需求规格 §2.3.1）。

### 3.3 对比流程

```
AlgorithmSelectService.compare(form)
    ↓
校验算法数量 2-3 个（@Size(min=2,max=3) + 服务层二次校验）
    ↓
校验每个算法存在且已发布
    ↓
逐算法分别执行预测（同一图片 fileId/imageUrl）
    ↓
每算法构造 AlgorithmCompareVO（algorithmId/name/resultUrl/time/metrics）
    ↓
单算法预测失败不影响其他算法（catch 后置空结果）
    ↓
返回对比结果列表
```

**对比维度**：同一测试图片分别预测，对比各算法处理结果图、处理耗时（ms）与评估指标（PSNR/SSIM，含清晰参考图时）。

### 3.4 自定义图片测试流程

```
AlgorithmSelectService.test(algorithmId, form)
    ↓
校验算法存在且已发布（未发布返回"算法不存在或未发布"）
    ↓
构造 PredictionForm（algorithmId + fileId/imageUrl + params）
    ↓
委托 SysPredLogService.predict(predForm)
    ↓
返回 PredictionResultVO（异步任务，前端轮询）
```

> 测试复用图像处理模块的完整预测链路（含拦截器链缓存），结果写入 sys_pred_log。

### 3.5 算法详情

```
AlgorithmSelectService.getDetail(id)
    ↓
校验算法存在且已发布
    ↓
基础字段：name/type/img/description/path/size/params/flops/version/status
    ↓
评分聚合：sys_rating 按 algorithmId 统计平均分与评价数
    ↓
使用次数：sys_pred_log 按 algorithmId 计数
    ↓
样例效果图：sys_pred_log 取最近 3 条成功记录的结果 URL
    ↓
返回 AlgorithmDetailVO
```

## 4. 模块间协作

### 4.1 与算法管理模块的集成

| 调用场景 | 调用接口 | 说明 |
|---------|---------|------|
| 算法列表 | `SysAlgorithmService.getAllAlgorithms()` | 获取全部算法，本模块过滤已发布并构建树 |
| 算法详情 | `SysAlgorithmService.getAlgorithmById(id)` | 获取算法元数据，校验存在性 |

**算法可见性规则**：
- 仅已发布（status=4）算法对用户可见
- 草稿/测试中/待审核/停用/归档均不可见（无 VIP 专属可见算法）

### 4.2 与图像处理模块的集成

| 调用场景 | 调用接口 | 说明 |
|---------|---------|------|
| 自定义测试 | `SysPredLogService.predict(predForm)` | 复用完整预测链路（异步 + 拦截器缓存） |
| 对比预测 | `SysPredLogService.predict(predForm)` | 每算法分别执行预测 |
| 样例图/使用次数 | `SysPredLogMapper` 查询 | 最近成功记录、计数 |

### 4.3 与收藏管理模块的集成

收藏能力由收藏管理模块统一提供（`sys_favorite`，`target_type='algorithm'`），算法卡片/详情页收藏按钮调用收藏管理接口（详见收藏管理模块文档）。

### 4.4 与推荐管理模块的集成

推荐区域数据来自推荐管理模块接口（`F-REC-001` 特征分析 + `F-REC-002` 推荐生成，`TOP_N=3`），推荐算法卡片展示匹配度/评分/推荐理由，`recommendedBy` 携带推荐记录 ID（详见推荐管理模块文档）。

## 5. 关键设计说明

### 5.1 对比中的预测复用

对比功能复用 `SysPredLogService.predict`，同一图片并发/串行执行多个算法预测。单算法失败不影响整体对比结果（异常捕获后 `resultUrl/time` 置空）。

### 5.2 搜索性能

搜索遍历已发布算法列表进行内存匹配（当前算法规模下可行）；算法规模增长后可考虑引入全文索引（待优化项）。

### 5.3 task_type 维度（改造规划）

改造后（[近期改造计划 §3.1](../../05-改造计划/近期改造计划总览.md)）：
- 树形结构第一级按 `task_type` 分类
- 搜索筛选增加 `task_type` 维度
- 对比/测试按 `params.taskType` 路由到对应算法集合
