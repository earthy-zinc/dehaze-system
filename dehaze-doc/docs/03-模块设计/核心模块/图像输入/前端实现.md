# 图像输入模块 - 前端实现设计

## 1. 文档概述

### 1.1 文档目的

本文档描述图像输入模块的前端实现方案，包括组件架构、交互流程、状态管理等，为前端开发提供实现指导。



## 2. 组件架构设计

### 2.1 组件层次结构

```
ImageInputPage (页面容器)
├── ImageInputTabs (输入方式选择器)
│   ├── TabButton (上传)
│   ├── TabButton (拍照)
│   ├── TabButton (样例)
│   └── TabButton (历史)
├── UploadPanel (上传面板)
│   ├── DragDropZone (拖拽上传区域)
│   ├── FileSelector (文件选择器)
│   ├── UploadProgress (上传进度)
│   └── ImagePreview (预览组件)
├── CameraPanel (拍照面板)
│   ├── CameraStream (相机流)
│   ├── CameraControls (相机控制)
│   ├── CaptureButton (拍摄按钮)
│   └── ImagePreview (预览组件)
├── SampleGallery (样例图片库)
│   ├── CategoryFilter (分类过滤器)
│   ├── ImageGrid (网格布局)
│   ├── ImageCard (图片卡片)
│   └── QuickStartButton (快速体验按钮)
└── HistoryList (历史记录列表)
    ├── TimeGroupHeader (时间分组标题)
    ├── HistoryCard (历史记录卡片)
    ├── ActionMenu (操作菜单)
    ├── FavoriteButton (收藏按钮，复用收藏管理模块组件)
    └── EmptyState (空状态提示)
```

### 2.2 组件职责划分

### 2.3 组件通信方式

| 通信场景 | 通信方式 | 说明 |
|---------|---------|------|
| 父子组件 | Props + Emits | 单向数据流 |
| 兄弟组件 | 状态管理（Pinia） | 共享状态 |

| 全局事件 | EventBus | 上传成功、处理完成等 |

| 屏幕尺寸 | 布局方式 | 特殊处理 |

## 5. 状态管理

### 5.1 状态结构

**useImageInputStore**（图像输入状态）：管理当前激活的输入方式（upload/camera/sample/history）、选中的图片、上传队列、样例库筛选、历史记录筛选、相机权限状态。

**useUploadStore**（上传状态）：管理上传队列、上传进度映射、上传结果映射。

**useHistoryStore**（历史记录状态）：管理本地历史记录、云端历史记录、同步状态（idle/syncing/conflict/success/error）、用户配额（used/total）。

### 5.2 状态更新逻辑

**上传流程状态更新**：

1. 用户选择文件 → 添加到 `uploadQueue`
2. 开始上传 → 更新 `progress`
3. 上传成功 → 存储到 `results`，从 `queue` 移除
4. 上传失败 → 记录错误，提供重试

**历史记录同步逻辑**：

1. 用户登录 → 触发自动同步
2. 查询云端记录 → 与本地记录合并
3. 冲突处理：按时间戳保留最新
4. 同步成功 → 更新 `cloudRecords`

## 6. 交互流程设计

### 6.1 上传图片流程

1. 用户点击"上传"Tab 或拖拽文件
2. 触发文件选择器 / 拖拽事件
3. 校验文件格式、大小、数量
4. **校验失败**：→ 显示错误提示 → 停止流程
5. **校验成功**：→ 添加到上传队列 → 显示预览
6. 用户确认 → 开始上传
7. 显示上传进度（百分比、速度、剩余时间）
8. **上传成功**：→ 显示成功提示 → 添加到历史记录 → 跳转到算法选择页面
9. **上传失败**：→ 显示错误提示 → 提供重试按钮

### 6.2 拍照流程

1. 用户点击"拍照"Tab
2. 检查相机权限
3. **无权限**：→ 显示权限说明 → 用户授权 → 授权失败：引导跳转设置
4. **有权限**：→ 打开相机流 → 显示预览
5. 用户调整相机设置（切换摄像头、闪光灯、对焦）
6. 用户点击拍摄按钮 → 拍照
7. 显示拍照结果预览
8. 用户可裁剪、旋转
9. **确认使用**：→ 上传图片 → 跳转到算法选择页面
10. **重新拍摄**：→ 返回相机流

### 6.3 样例图片选择流程

1. 用户点击"样例"Tab
2. 加载样例分类和图片列表
3. 用户可选择分类过滤
4. 网格展示样例图片（延迟加载）
5. 用户点击图片 → 显示详情弹窗
6. 弹窗显示：图片信息、推荐算法（由推荐管理模块动态获取）、去雾难度
7. **使用此图片**：→ 加载到处理区 → 跳转到算法选择页面
8. **快速体验**：→ 自动选择推荐样例 → 调用推荐管理模块获取推荐算法 → 跳转到处理页面

### 6.4 历史记录操作流程

1. 用户点击"历史"Tab
2. 加载历史记录（本地 + 云端）
3. 按时间分组显示
4. 用户选择操作：
   - **重新处理**：→ 跳转到处理页面，自动开始
   - **更换算法**：→ 跳转到算法选择页面
   - **查看详情**：→ 全屏显示对比效果
   - **删除记录**：→ 二次确认 → 删除（本地 + 云端）
   - **添加收藏**：→ 标记收藏，置顶显示

## 9. 关键实现要点

### 9.1 拖拽上传实现策略

使用原生 HTML5 Drag & Drop API，监听以下事件：

- `dragenter`：拖拽进入时显示提示
- `dragover`：阻止默认行为，显示拖拽中样式
- `dragleave`：拖拽离开时恢复样式
- `drop`：获取文件，开始上传

**防抖处理**：拖拽事件高频触发，使用 `debounce` 优化性能。

### 9.2 相机流处理策略

使用系统相机能力 API，配置视频约束（前后置、分辨率）。授权失败时引导用户跳转系统设置。

### 9.3 图片延迟加载策略

使用 Intersection Observer API 实现懒加载：

- 监听图片元素是否进入可视区域
- 进入可视区域时，替换 `src` 为真实 URL
- 加载完成后淡入显示

### 9.4 历史记录同步策略

**本地存储**：使用 IndexedDB 存储本地历史记录（支持离线）

**云端同步**：
- 登录后自动同步云端记录
- 合并本地和云端记录（按时间戳去重）
- 冲突处理：保留最新记录
- 离线修改：缓存操作队列，网络恢复后同步

**同步频率**：
- 实时同步：每次操作后立即同步
- 定时同步：每 5 分钟检查一次
- 手动同步：用户主动触发
