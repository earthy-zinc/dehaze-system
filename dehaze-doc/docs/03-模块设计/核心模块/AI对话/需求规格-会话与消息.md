# AI 对话模块需求规格（会话与消息）

## 功能域概述

通用对话与会话管理是 AI 对话模块的交互底座，承载用户与 LLM 之间的开放式对话能力，以及会话生命周期、消息交互与流式输出的全链路管理。本功能域以主流对话式 AI 产品（ChatGPT、Claude、DeepSeek 等）为对标，围绕"开场引导、对话表达、结果确认、反馈应用"四个交互阶段设计（对齐 Ant Design X RICH 设计范式的 Hybrid UI 混合界面模型）。

### 2.1 通用对话与会话管理 (F-M08-001)

#### 2.1.1 功能描述

接入通用大语言模型，提供开放式对话能力，支持问答、写作、翻译、代码、推理等通用任务。用户通过统一对话入口即可完成通用任务，同时可调度图像处理能力。

#### 2.1.2 对话能力

| 能力 | 说明 | 示例 |
|------|------|------|
| 问答 | 知识问答、事实查询 | "PSNR 是什么意思？" |
| 写作 | 文本生成、润色 | "帮我写一段去雾效果的描述" |
| 翻译 | 多语言翻译 | "把这段算法说明翻译成英文" |
| 代码 | 代码生成、解释 | "写一个调用去雾 API 的 Python 脚本" |
| 推理 | 逻辑推理、分析 | "对比 DCP 和 FFA-Net 的适用场景" |

#### 2.1.3 多轮对话

- 支持上下文记忆，后续对话可引用前文内容
- 增量指令不被摘要压掉（如"再亮一点"能正确理解为对上一次处理的调整），最近若干轮原文始终保留
- 超过上下文容量阈值时自动摘要老消息，保留最近 N 轮原文（摘要策略见 [需求规格-上下文管理](./需求规格-上下文管理.md) §2.3.4）
- 对话末尾可推荐相关问题引导追问（见 §2.1.5 类似问题推荐），降低"对话陷入僵局"的流失风险

#### 2.1.4 会话管理

| 操作 | 说明 | 业务规则 |
|------|------|---------|
| 创建会话 | 用户发起新对话，系统创建会话记录 | 标题默认"新对话"，首条消息发送后自动从内容提取标题；可从会话列表或对话框内"新建"入口发起 |
| 新会话引导 | 新会话展示开场引导，帮助用户快速理解能力范围并开口提问 | 展示问候语 + 2-4 条示例问题（如"帮这张雾图去雾""对比两种去雾算法"）；示例问题点击后自动填入输入框待发送；引导仅首次使用全屏展示，后续新会话以轻量方式提示 |
| 会话列表 | 展示用户历史会话，支持搜索、继续、删除 | 按最后活跃时间倒序排列，置顶会话置于顶部；列表项展示标题、最后一条消息摘要、更新时间与未读数 |
| 会话搜索 | 关键词检索历史会话 | 同时匹配会话标题与消息内容（全文检索，优于仅标题搜索）；支持按"全部/置顶/已归档"范围过滤；搜索结果按最后活跃时间倒序 |
| 会话置顶 | 将高频会话固定至列表顶部 | 置顶上限 10 个，超出时拒绝置顶并提示先取消其他置顶；置顶会话按置顶时间倒序，取消置顶后回到活跃时间排序 |
| 会话标题 | 自动用 LLM 生成标题，支持手动修改 | 首条消息后异步生成标题（不超过 20 字）；手动修改后不再自动生成；生成失败时降级为截取消息前 20 字 |
| 会话归档 | 不活跃的会话自动归档，用户也可手动归档 | 超过 30 天无新消息的会话自动转为归档状态；归档会话不计入活跃列表、仍可被搜索，可随时恢复 |
| 批量管理 | 多选会话批量归档/删除 | 列表支持勾选多个会话后批量操作；批量删除需二次确认；批量归档不改变会话内容 |
| 会话导出 | 将会话完整记录导出为文件 | 支持导出 Markdown/JSON，内容含全部消息（推理过程默认不导出）；用于记录留存与研究复盘 |
| 会话详情 | 展示会话元信息 | 包含会话标题、关联模型、消息数、创建时间；从会话设置入口查看 |
| 会话删除 | 用户删除会话 | 软删除，30 天内可恢复；删除会话不影响关联的图像处理记录 |

#### 2.1.5 消息交互

| 交互 | 说明 | 交互行为 |
|------|------|---------|
| 发送消息 | 文字输入 | 回车发送，Shift+回车换行；发送后用户消息立即上屏，随后展示助手流式回复；发送中按钮转为"停止"态；发送失败（网络异常）时消息标记失败并允许点击重发，不产生重复计费 |
| 多模态输入 | 在消息中附带图片、文档、音视频等文件 | 由支持对应模态的模型理解内容；附件支持图片、PDF/Word/Excel/PPT/Markdown、MP4/MP3 等常见格式；支持粘贴、拖拽上传图片；输入区内附件可预览、可单独撤回，随消息一并发送 |
| 流式输出 | LLM 回复实时逐字展示 | 输出过程中支持点击"停止"终止；网络中断后 5 分钟内重连可继续接收；输出过程自动滚动跟随，用户上滑阅读前文时暂停跟随并出现"回到底部"按钮 |
| 重新生成 | 对助手回复不满意可重新生成 | 仅最后一条助手回复可触发；生成新分支消息，原版本保留，支持在多个分支间切换对比查看 |
| 编辑重发 | 编辑已发送的用户消息并重新触发回复 | 仅最后一条用户消息可编辑；原消息标记"已编辑"并保留原文可见；编辑后重新生成回复分支 |
| 消息引用 | 一键将某条消息内容带入输入区继续对话 | 悬停消息出现"引用"按钮，点击后原文（保留格式）填入输入框，可修改后作为新消息发送；用于对回复局部内容继续追问，不改变原消息 |
| 复制消息 | 一键复制消息内容 | 复制助手与用户消息均可；复制成功后按钮切换为完成态反馈；代码块提供独立复制入口 |
| 消息反馈 | 对助手回复点赞/点踩 | 悬停助手回复展示反馈入口，交互与规则见 [需求规格-消息反馈](./需求规格-消息反馈.md)（F-M08-008），本功能域不重复定义 |
| 朗读消息 | 将助手回复转为语音播报 | 依赖语音交互模块（TTS）；点击开始播放，再次点击停止；仅助手消息可朗读 |
| 类似问题推荐 | 回复末尾推荐相关问题引导深入对话 | 助手回复完成后展示 2-3 条相关问题，点击后作为新消息发送；推荐问题不干扰回复正文展示，可忽略不发送 |
| 消息删除 | 删除单条助手回复 | 仅助手回复可删除；删除后从对话流隐藏，数据软删除保留审计，不参与后续上下文；删除后该分支的"重新生成"入口不再展示 |
| 已读未读 | 多端登录时同步已读状态 | 会话列表显示未读消息数（超过 99 显示"99+"），进入会话后标记为已读并清零 |

#### 2.1.6 交互规范

| 场景 | 交互行为 |
|------|---------|
| 输入框规范 | 占位文字透出产品身份与能力（如"输入消息，或让 AI 帮你处理图片…"）；输入框附近提供模型切换、语音输入（依赖语音交互模块）、附件上传入口；新会话时以示例问题引导开场 |
| 推理过程展示 | 助手回复过程中可展开查看推理步骤（思考内容、工具调用、结果摘要），默认折叠；推理模型的回复分为"分析过程"与"正式回复"两段：分析过程默认折叠为可展开条目（可标注思考耗时），正式回复直接展示；分析过程不参与复制、引用、朗读等操作 |
| 滚动与阅读 | 流式输出时自动滚动跟随最新内容；用户上滑阅读时暂停跟随，底部出现"回到底部"按钮，点击平滑回到最新内容；回复完成且用户停留在前文时不强制滚动 |
| 结果卡片 | 图像处理等任务完成后，在消息中以卡片形式展示结果（缩略图 + 指标 + 算法信息），可点击查看大图 |
| 中断确认 | 推理进入需确认环节时展示确认卡片，用户确认或修改后推理继续 |
| 配额提示 | 积分不足时展示升级引导卡片，用户升级后可从中断点继续 |
| 兜底与出错处理 | LLM 无法理解用户输入时，按预设话术如实说明能力边界并给出示例引导（如"我还不能理解这个需求，您可以试试这样描述…"）；流式失败/网络中断时，消息展示错误状态与"重新生成/重试"入口，避免无反馈的静默失败 |

#### 2.1.7 业务规则

| 规则 | 说明 |
|------|------|
| 单条消息长度 | 用户输入不超过 4000 字符 |
| 流式超时 | 单次流式输出超过 120 秒未产生新内容判定超时，标记消息为失败 |
| 断线恢复 | 网络中断后 5 分钟内可重连恢复未完成的回复；超时未恢复的回复标记为"已取消"，支持重新生成 |
| 防重复发送 | 消息提交需保证网络重试不会产生重复消息和重复计费 |
| 并发限制 | 同一会话同一时间只允许一个回复输出进行中，新消息需等待上一个完成或取消 |
| 消息归属 | 用户只能查看和操作自己的会话和消息 |
| 编辑范围 | 仅最后一条用户消息可编辑重发；编辑仅影响其后新生成的分支，历史分支保留 |
| 重新生成范围 | 仅最后一条助手回复可重新生成；生成失败时保留原回复并提示重试 |
| 引用规则 | 引用消息仅作输入区预填充，不携带对原消息的引用关系；引用后发送即新消息 |
| 消息删除 | 仅助手回复可删除（软删除，30 天内可恢复）；用户消息不提供删除（通过编辑重发调整） |
| 置顶数量 | 置顶会话不超过 10 个 |
| 批量操作 | 批量删除需二次确认；批量归档不改变会话内容与消息 |
| 新会话引导 | 示例问题为平台预设的静态内容，不消耗 Token；首次使用全屏引导展示一次 |
| 类似问题推荐 | 推荐问题由 LLM 随回复生成，计入该条回复 Token 消耗；可通过会话设置关闭该能力 |

#### 2.1.8 设计依据

本功能域的产品交互设计对齐业界主流对话式 AI 产品实践，做工程化取舍：

| 设计点 | 对标实践 |
|--------|---------|
| 四阶段交互模型 | Ant Design X RICH 设计范式 Hybrid UI：唤醒（开场引导）→ 表达（输入与多模态）→ 确认（流式生成与推理过程）→ 反馈（结果操作与消息反馈） |
| 开场引导与示例问题 | ChatGPT 新对话的示例提示词、Kimi/豆包的开场问候，降低新手开口门槛 |
| 流式滚动策略 | ChatGPT/Copilot 一致的"自动跟随 + 上滑暂停 + 回到底部"滚动控制，避免打断阅读 |
| 思考过程分段展示 | DeepSeek/Grok 的推理过程折叠展示，兼顾过程透明与答案直达 |
| 分支与重新生成 | Claude/ChatGPT 的"重新生成=创建分支而非覆盖"，保留不满意版本供切换对比 |
| 消息引用与继续对话 | Ant Design X 结果应用规范的"引用"操作，将回复内容一键带入输入区延续对话 |
| 会话管理 | ChatGPT 会话组织实践：全文检索（优于原生仅标题搜索）、置顶限量、归档优先于删除（可逆）、批量管理 |
| 轻量反馈 | ChatGPT/Claude 的点赞/点踩浮层，反馈驱动模型与提示词持续优化（F-M08-008） |

#### 2.1.9 管理端会话审计（管理员视角）

管理端为管理员提供全平台会话与消息的**只读审计能力**，支撑审计合规、故障排查与 AI 链路追踪（页面设计见 [需求规格.md](./需求规格.md) §3.3.1）：

| 能力 | 说明 | 业务规则 |
|------|------|---------|
| 会话审计列表 | 全量会话检索（按用户/时间/状态/关键词筛选） | 需管理权限 `ai:conversation:audit`；展示模型、消息数、Token 与积分消耗、状态标注 |
| 会话详情浏览 | 只读浏览任一会话的全部消息（含推理步骤、工具调用、模型轨迹） | 需管理权限；不提供删除/重发等操作，与用户所有权边界分离 |
| AI 链路追踪 | 单条消息下钻完整推理链路：用户输入 → 推理步骤（thought）→ 工具调用（参数/结果/耗时）→ 中断/重试 → 最终回复 | 推理步骤与工具调用数据与用户端同源，定位问题根因 |
| 异常会话标注 | 失败/中断/配额拒绝/高风险工具调用会话显著标注 | 支撑故障排查与安全审计 |

**业务规则**：

- 审计接口仅管理员可访问（`ai:conversation:audit`），普通用户越权返回 403（`A0301`）
- 审计数据与用户视角同源：复用同一会话/消息/推理步骤数据，不另建审计副本
- 审计页只读：不提供会话内容操作，保证用户数据安全

> 本功能域不重复定义记忆/上下文压缩、提示词组装、计费配额等能力，分别见 [需求规格-上下文管理](./需求规格-上下文管理.md)、[需求规格-智能调度](./需求规格-智能调度.md) 及 [AI 计费管理模块](../../基础模块/AI计费管理/需求规格.md)。
