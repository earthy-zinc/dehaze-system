# AI 对话模块需求规格（可观测性）

> 功能域定位：本功能域（F-M08-013）为 AI 对话与智能体的运行过程建立"看得见"的透明层——回答三个关键问题：**AI 当时看到了什么（上下文）、AI 做了什么（推理与能力调用）、消耗了多少且是否异常（资源与状态）**。面向用户提供过程可信度，面向平台提供审计、成本与告警能力。

## 2.12 AI 对话可观测性 (F-M08-013)

### 2.12.1 功能描述

AI 对话模块承载平台的核心交互，其运行过程（多步推理、工具调用、上下文组织、模型选择）对使用者与运营者大多是"黑盒"：回复可用时无人关心，一旦回复错误、过程异常或成本异常，便无法定位问题出在哪个环节。

本功能域为对话全过程建立**过程记录**能力，覆盖"上下文构成、推理步骤、能力调用、资源消耗、运行状态"五个维度，按角色提供不同粒度的查看与分析入口：

| 角色 | 关心的核心问题 | 提供的视图 |
|------|--------------|-----------|
| 普通用户 | AI 做了什么、为什么这么做、是否可信 | 对话过程透明（可折叠查看） |
| AI 能力配置者 | 效果差的原因：提示词、模型、工具还是上下文 | 单条回复的完整执行过程回放 |
| 平台管理员 | 谁在何时调用了什么、花了多少、是否异常 | 全量检索、统计报表、异常标注与告警 |
| 审计合规人员 | 平台 AI 行为是否可追溯、可导出 | 全量留痕与导出 |

### 2.12.2 对话过程透明

用户在对话中可查看一次回复的**执行过程**，回答"AI 是怎么得出这个回答的"：

| 能力 | 说明 |
|------|------|
| 过程查看 | 每条助手回复可展开查看执行过程：AI 的理解、分解的步骤、每步做什么、调用了哪些能力、各步骤耗时 |
| 步骤状态 | 每个步骤标注进行中/成功/失败/跳过，失败可查看失败原因与 AI 的应对（重试/跳过/中止） |
| 过程与结果关联 | 过程查看与回复内容联动，用户可定位"哪一步导致了这样的结果" |
| 可见性控制 | 过程默认折叠，用户按需展开，不干扰正常对话阅读 |

> 设计原则：过程透明服务于"可信"，而非信息过载。默认折叠、按需展开、过程只读。

### 2.12.3 上下文可观测（AI 当时看到了什么）

回答"AI 基于什么产生了这条回复"，支撑"为什么答偏了"的归因：

| 能力 | 说明 |
|------|------|
| 上下文构成 | 展示单条回复输入上下文的构成项：对话历史、系统提示、注入的长期记忆、知识库检索内容、能力清单等，及其各自占比 |
| 调用级输入构成 | 单次模型调用可查看本轮输入构成（系统提示、消息角色分布、工具定义、用户信息），支撑"哪一轮调用输入异常"的逐轮归因 |
| 来源追溯 | 每个上下文构成项可追溯到原始来源（哪条历史消息、哪条记忆、哪个知识条目） |
| 上下文压缩提示 | 历史过长被压缩/裁剪时，在过程记录中标注"压缩发生"及影响范围，避免"AI 忘了前文"的误解 |
| 引用可见 | AI 引用知识库内容时，展示引用来源与内容片段，支撑引用可信性核查 |

### 2.12.4 能力调用观测

记录 AI 每次调用平台能力（图像处理、算法选择、知识检索、MCP 外部服务等）的完整信息：

| 维度 | 说明 |
|------|------|
| 调用记录 | 调用了什么能力、传入什么、返回什么、耗时多久 |
| 结果状态 | 成功/失败/超时/被拒绝，失败原因可读（参数错误、权限不足、配额不足、服务异常） |
| 重试链路 | AI 对失败调用的重试/降级/换策略行为，完整串联展示 |
| 风险调用标注 | 涉及外部服务或高风险操作（写操作、花钱的操作）的调用显著标注，供审计与用户知情 |

### 2.12.5 资源消耗透视

对话全过程的资源消耗可统计、可查询、可控制：

| 能力 | 说明 |
|------|------|
| 消耗明细 | 每次对话/每条消息的 Token、积分、费用消耗，与计费口径一致 |
| 调用级消耗 | 每次模型调用的 Token 消耗（含缓存命中）与耗时（首 Token/总耗时）可查，支撑成本与性能逐轮归因 |
| 多维聚合 | 按会话、模型、智能体、用户、时间范围聚合消耗；支持趋势查看 |
| 成本异常发现 | 消耗突增（如单会话费用异常、某模型成本飙升）自动标注并提示管理员 |

### 2.12.6 性能与异常监测

对平台 AI 服务的运行健康度提供持续监测：

| 能力 | 说明 |
|------|------|
| 运行指标 | 回复延迟（首字输出/完整输出）、成功率、失败率、中断率、超时率 |
| 异常标注 | 失败、中断、配额拒绝、高风险调用的会话在管理端显著标注，支持筛选定位 |
| 趋势分析 | 指标按时间维度展示变化趋势，发现性能劣化与能力退化 |

### 2.12.7 告警通知

对异常情况主动通知，而非被动等待排查：

| 告警类型 | 触发场景 | 通知对象 |
|---------|---------|---------|
| 质量告警 | 回复失败率、中断率突增 | 平台管理员 |
| 成本告警 | 单会话/单模型消耗异常突增 | 平台管理员 |
| 能力告警 | 某能力（MCP 服务、算法服务）调用持续失败 | 平台管理员、相关能力负责人 |
| 安全告警 | 检测到敏感信息泄露、越权能力调用风险 | 平台管理员 |

### 2.12.8 审计留痕

满足企业级审计与合规要求：

| 能力 | 说明 |
|------|------|
| 全量留痕 | 对话过程、能力调用、资源消耗全过程记录留存，不因用户删除会话而丢失 |
| 检索定位 | 按用户、时间、模型、智能体、能力、状态等维度检索历史过程记录 |
| 导出能力 | 单会话或批量过程记录可导出，支撑合规审计与离线分析 |
| 权限隔离 | 普通用户仅可查看自己会话的过程记录；管理员可查看全量；审计导出需管理员权限 |

### 2.12.9 业务规则

| 规则 | 说明 |
|------|------|
| 留痕完整性 | 过程记录随会话创建、随执行更新，不依赖用户反馈触发 |
| 保留周期 | 过程记录保留 180 天，超期归档清理；审计要求的记录按合规周期保留 |
| 隐私保护 | 过程记录中的敏感信息（手机号、身份证等）脱敏后存储与展示 |
| 性能隔离 | 过程记录为旁路能力，不阻塞对话主流程，不影响回复体验 |
| 口径一致 | 资源消耗口径与计费模块完全一致，避免对账冲突 |

### 2.12.10 用户交互流程

**异常排查流程**（平台管理员视角）：

```
收到用户反馈"AI 干错了事"
  → 会话审计页检索该会话，查看消息级执行过程
  → 下钻某条消息：AI 看到了什么上下文、做了哪几步、调用了什么能力
  → 定位根因环节（上下文缺失 / 工具参数错误 / 模型理解偏差）
  → 转交 AI 能力配置者修复，并将案例沉淀为评测用例（见 F-M08-014）
```

**用户侧过程查看流程**（普通用户视角）：

```
对话中查看助手回复
  → 展开"查看过程"
  → 浏览 AI 执行的步骤与能力调用
  → 对失败/可疑步骤查看原因，判断回复是否可信
```

### 2.12.11 非功能需求与成功度量

**非功能需求**：

| 维度 | 指标 |
|------|------|
| 查询性能 | 单会话过程记录加载 P95 ≤ 1s；全量检索 P95 ≤ 3s |
| 留痕完整性 | 对话执行过程记录完整率 ≥ 99.9%（不含用户主动删除的权限场景） |
| 性能隔离 | 开启过程记录对首 Token 延迟影响 ≤ 5% |

**成功度量**：

| 指标 | 定义 | 目标 |
|------|------|------|
| 过程透明覆盖率 | 用户查看过过程记录的会话 / 总会话数 | ≥ 20% |
| 问题定位时效 | 从用户反馈到定位根因环节的平均时长 | ≤ 30 分钟 |
| 审计满足度 | 审计人员可检索到所需历史过程记录的比例 | 100% |
| 异常发现率 | 达到告警阈值的事件中系统自动发现的比例 | ≥ 90% |
