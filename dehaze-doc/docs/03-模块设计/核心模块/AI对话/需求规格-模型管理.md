# AI 对话模块需求规格（模型管理）

> 功能域定位：本功能域（F-M08-007）负责平台的 LLM 模型接入与调度——通过供应商管理实现多供应商、多 API Key 的灵活调度，通过模型选择让用户在会话中按需切换不同模型并享受差异化的积分计费。该功能域是 AI 对话底座能力的核心组成部分，涵盖 §2.7 模型供应商管理与 §2.8 模型选择两个子功能。
>
> 本版在对齐既有实现的基础上，依据业界主流大模型平台与 LLM 网关的最佳实践（Dify 供应商/凭据管理、LiteLLM 多 Key 路由与故障转移、LLM 网关模型注册表、火山方舟/阿里百炼模型广场与模型下线迁移）补齐四方面能力：**供应商健康与容错（§2.7.6）**、**模型选择体验增强（§2.8.2）**、**模型生命周期管理（§2.8.4）**，以及标注为远期演进的 **模型分组与智能路由（§2.8.5）**、**用量与成本分析（§2.8.6）**。新增需求是否一期落地见 §2.8.7 待确认事项。

## 2.7 模型供应商管理 (F-M08-007)

### 2.7.1 功能描述

平台接入多个 LLM 供应商（OpenAI、Anthropic、DeepSeek、智谱、通义千问等），通过统一的供应商配置管理实现模型调用的灵活调度。供应商配置由管理员在前端配置界面管理，存储于数据库，支持同一供应商配置多个 API Key 实现负载均衡和 Key 轮换，支持同一模型切换不同供应商实现灵活调度。

供应商管理遵循两项产品原则：

- **配置即接入**：接入新供应商、新模型均为配置操作（数据库记录 + 协议适配），不改代码、不重启服务。
- **不可控性治理**：LLM 供应商是外部不可控依赖（限流、宕机、涨价、停服），通过多 Key 轮换、供应商熔断、模型降级链将不可控抽象为可控配置层，保证平台持续可用（见 §2.7.6）。

### 2.7.2 供应商管理

| 操作 | 说明 | 业务规则 |
|------|------|---------|
| 新增供应商 | 配置供应商编码、名称、API 地址、协议类型、认证方式 | 供应商编码全局唯一且不可复用；删除前校验是否有模型引用；保存后自动发起连通性测试，测试结果仅提示、不阻断保存 |
| 连通性测试 | 以配置的协议与认证方式向 API 地址发送最小探测请求（如查询模型列表），验证供应商可访问、凭据有效 | 测试不产生业务计费；结果展示连通状态、延迟与错误码，便于管理员定位配置问题 |
| 供应商列表 | 查询所有供应商 | 管理员可见全部及健康状态；普通用户查询模型时返回关联供应商基本信息（不含 Key 与配置细节） |
| 更新供应商 | 修改 API 地址、认证方式、默认请求头等 | 更新后对后续调用立即生效；修改 API 地址或认证方式后建议重新连通性测试 |
| 删除供应商 | 软删除 | 校验是否有启用模型引用该供应商；有则提示先禁用模型 |
| 启停供应商 | 启用/禁用供应商 | 禁用后该供应商下的模型不可被选择，进行中的推理不受影响 |
| 健康状态 | 展示供应商近 24h 成功率、429 限流率、P95 延迟与当前熔断状态 | 数据由调用日志聚合，状态分为健康/可疑/熔断（见 §2.7.6），供管理员决策轮换与扩容 |

### 2.7.3 API Key 管理

每个供应商可配置多个 API Key，实现负载均衡、Key 轮换、故障切换：

| 操作 | 说明 | 业务规则 |
|------|------|---------|
| 新增 API Key | 录入 Key，系统安全存储 | Key 明文不可见、不进入日志、不进入 LLM 上下文；重复录入需提示（按哈希查重） |
| Key 列表 | 按供应商查询 Key 列表 | 只展示前缀，不展示完整 Key；展示 Key 健康度（近期失败率、最近使用时间）便于轮换决策 |
| 启停 Key | 启用/禁用单个 Key | 禁用后不再被选取，进行中的推理不受影响 |
| 删除 Key | 物理删除 | 删除前校验是否为该供应商唯一启用 Key，避免全部不可用 |
| 设置优先级 | 配置 Key 的优先级和权重 | 优先级数字越小越优先；同优先级按权重加权随机选取 |
| Key 轮换 | 新增 Key 后旧 Key 可禁用或删除 | 支持平滑轮换，不影响进行中的推理 |
| 调用限额 | 配置 Key 级分钟调用频率（RPM）与日调用额度 | RPM 控制突发并发，日额度控制单日成本；超限后本轮跳过该 Key，分钟级自动恢复 / 日额度次日恢复 |

**Key 选取与容错**：

| 规则 | 说明 |
|------|------|
| 选取规则 | 优先选取最高优先级组内的 Key，同优先级按权重加权随机；仅选取启用且在有效期内、未超调用限额的 Key |
| 故障切换 | 调用失败（如鉴权失败、限流）时自动切换同供应商下一个 Key 重试，避免单 Key 故障拖垮调用；失败的 Key 进入冷却期（Redis 临时不可用标记，默认 5 分钟） |
| 使用记录 | 记录 Key 最近使用时间与调用方，便于排查与轮换决策 |
| 冷却恢复 | 冷却期结束后 Key 自动参与选取；连续高频失败的 Key 逐步提升冷却时长，防止被持续打爆（与 §2.7.6 供应商熔断形成两级容错） |

### 2.7.4 模型与供应商的关系

| 关系 | 说明 |
|------|------|
| 一个供应商提供多个模型 | 如 OpenAI 供应商下有 GPT-4o、GPT-4o-mini、o1 等多个模型 |
| 同一模型标识可关联不同供应商 | 如 `gpt-4o` 可通过 OpenAI 官方或第三方代理接入，通过供应商区分 |
| 模型切换供应商 | 管理员可将模型从供应商 A 切换到供应商 B，切换为配置操作，对调用方透明（用户仍按模型标识选择） |

### 2.7.5 供应商配置项

| 配置项 | 说明 | 示例 |
|--------|------|------|
| 供应商编码 | 全局唯一标识 | `openai`、`anthropic`、`deepseek` |
| API 基础地址 | LLM API 端点 | `https://api.openai.com/v1` |
| 协议类型 | 请求/响应协议 | OpenAI 兼容协议、Claude 原生协议 |
| 认证方式 | 供应商要求的鉴权方式 | Bearer Token、API Key、自定义请求头 |
| 默认请求头 | 供应商特有请求头 | Claude 协议版本号等 |
| 排序序号 | 供应商展示顺序 | 数字越小越靠前 |
| 健康检查配置 | 连通性探测开关、探测间隔、熔断阈值 | 探测间隔 60s，连续失败 3 次进入熔断 |
| 备注 | 运维备注（账号归属、合同号、商务信息） | — |

### 2.7.6 供应商健康与容错

**设计目标**：供应商降级、熔断对用户无感——用户按模型标识发起调用，平台自动路由到当前健康可用的 Key 与供应商，仅在全部可用路径均失败时才报错。

**健康状态机**：

```
健康（正常参与选取）
  → 错误率升高/延迟恶化 → 可疑（降权观察 + 保留探测流量）
  → 连续失败超过熔断阈值 → 熔断（停止选取该供应商 Key，进入冷却期）
  → 冷却期结束 / 管理员手动解除 → 恢复
```

| 状态 | 触发条件（参考阈值，可配置） | 调度行为 |
|------|---------------------------|---------|
| 健康 | 错误率 < 10% | 正常参与选取 |
| 可疑 | 10% ≤ 错误率 < 30%，或 P95 延迟超基线 2 倍 | 降低选取权重，仍参与调用；触发运维告警 |
| 熔断 | 错误率 ≥ 30% 持续 1 分钟，或连续失败 ≥ 5 次 | 停止选取该供应商全部 Key；该供应商下的模型自动走降级链或同模型备用供应商；进行中的推理不受影响 |
| 恢复 | 冷却期结束（默认 60s）或管理员手动解除 | 重新参与选取，先按"可疑"低权重观察一段时间再恢复常态 |

**与其他机制的关系**：

- Key 级失败冷却（§2.7.3）解决单 Key 故障，供应商级熔断（本节）解决供应商整体不可用，两级叠加形成完整容错。
- 供应商熔断期间模型调用自动降级（§2.8.3），用户仅感知响应模型变化，前端可提示"已切换到备用模型"。
- 健康指标聚合自调用日志（计费记录/消息记录），对运维呈现健康看板（§2.8.6），不向普通用户暴露。

## 2.8 模型选择 (F-M08-007)

### 2.8.1 功能描述

用户可在对话中选择不同的 LLM 模型，不同模型的积分消耗不同（按模型计费比例换算）。模型选择在会话级别生效，同一会话内可切换模型。

模型管理遵循业界"模型注册表"实践：模型标识与具体供应商、计费、能力配置解耦，模型升级、下线、切换供应商仅调整模型配置，不改变用户的调用方式。

### 2.8.2 模型展示

| 展示信息 | 说明 |
|---------|------|
| 模型名称 | 显示名称（如"GPT-4o"、"Claude 3.5 Sonnet"） |
| 能力标识 | 标识模型能力（多模态、工具调用、流式输出、结构化输出、Prompt Cache），支持按能力筛选 |
| 积分单价 | 输入/输出积分单价，帮助用户了解成本 |
| 速度档位 | 相对速度标识（快/中/慢），由实测延迟聚合得出，帮助用户权衡速度与质量 |
| 上下文长度 | 最大上下文 / 最大输出 token 数，超出时提示（见 §2.8.3 上下文校验） |
| 推荐场景 | 简要说明模型适用场景（如"通用对话"、"复杂推理"、"代码生成"） |
| 模型标签 | 能力/成本/场景标签，支持筛选（如"多模态"、"低价"、"代码"） |
| 降级标识 | 若该模型常作为其他模型的降级目标，在列表中标识，减少用户对"模型变化"的困惑 |

### 2.8.3 业务规则

| 规则 | 说明 |
|------|------|
| 模型可用性 | 仅启用状态的模型可选择 |
| VIP 限制 | 部分高端模型仅 VIP 用户可用 |
| 多模态校验 | 附带文件输入时，模型必须支持对应模态（图片需视觉能力、文档需文档理解能力） |
| 切换生效 | 会话中切换模型后，下一条消息使用新模型，历史消息保持原模型记录 |
| 默认模型 | 新建会话使用平台默认模型，用户可在设置中配置偏好默认模型 |
| 上下文校验 | 输入超出模型上下文上限时，先由上下文管理模块压缩后再调用；压缩仍超限则拒绝发送并提示 |
| 计费比例版本 | 计费比例（input/output/cached_rate）变更记录价格版本，历史消息按当时的价格版本计费，账单对账有据可查 |

### 2.8.4 模型生命周期管理

模型与供应商一样是长期演进的配置资产，需要完整的生命周期管理，对齐百炼等平台"模型下线公告 + 替换模型推荐"的迁移实践：

| 阶段 | 操作 | 业务规则 |
|------|------|---------|
| 上架 | 新增模型并启用 | 配置模型标识、能力标识、计费比例、VIP 门槛、降级链；上架前建议连通性验证（确认模型在供应商侧真实存在且可调用） |
| 运行 | 正常提供服务 | 会话级选择、降级路由、按计费比例计费 |
| 停用 | 禁用模型 | 新会话不可选择、现有会话切换时不可再选；进行中的推理不受影响；使用中的会话提示用户重新选择 |
| 下线 | 软删除模型 | 校验无活跃会话使用后删除；model_id 不可复用；下线前通知使用方并提供替换模型推荐 |
| 替换迁移 | 供应商停服前的用户引导 | 供应商发布模型停服公告后：管理员将模型标记"即将下线"，系统向使用中的会话/用户推送替换模型推荐（如 `gpt-4o` → `gpt-4o-mini`），引导平滑迁移 |

**模型状态**：`启用` → `禁用`（可逆）→ `已下线`（不可逆，软删除）。供应商侧模型停服时由降级链与同模型备用供应商自动兜底（§2.8.3），管理员在窗口期内完成替换迁移。

### 2.8.5 模型分组与智能路由（远期演进）

> 定位：业界 LLM 网关普遍通过"模型分组 + 路由规则"将模型选择从用户手工挑选升级为平台智能调度（LiteLLM model alias、LLM 网关 tier 分层）。本项为远期规划，**需在已有充足调用 trace 与评测数据后实施**，一期不做，避免过度设计。

| 能力 | 说明 |
|------|------|
| 模型分组 | 将模型按能力/成本划分为分组（如 fast / balanced / flagship），用户可按分组选择，或由平台按任务自动路由 |
| 固定规则路由 | 按任务复杂度/场景/输入长度选择分组内最合适的模型（简单任务走轻量模型、复杂推理走旗舰模型）；日志记录路由原因（route_reason）便于调优 |
| 路由演进 | 简单轮询 → 固定规则路由 → 语义/分类路由逐级演进；无评测集不上学习型路由 |
| 演进门槛 | 先收口统一调用入口并沉淀 trace，再引入规则路由；规则路由稳定后评估是否需要智能路由 |

### 2.8.6 用量与成本分析（运营视角）

> 与 [AI 计费管理模块](../../基础模块/AI计费管理/需求规格.md) 协同：计费模块负责积分计量与账单统计，本小节聚焦供应商/模型的运营健康与成本归因，数据同源（调用日志），面向管理员。

| 分析维度 | 说明 |
|---------|------|
| 供应商健康看板 | 各供应商成功率、429 率、P95 延迟、熔断次数与持续时间 |
| 模型用量分布 | 按模型/供应商统计 Token 消耗、调用次数、积分开销（识别高成本与热销模型） |
| 降级与故障统计 | 各模型降级频率、Key 失败切换次数（识别不稳定供应商/Key，驱动轮换决策） |
| 成本归因 | 每次调用记录 request_id、供应商、模型、Token 明细、计费比例版本、是否降级、错误码、延迟，支撑对账与异常追溯 |

### 2.8.7 待确认事项

| 事项 | 说明 |
|------|------|
| 同模型多供应商的选择 | 同一模型标识关联多个供应商时，用户在会话中按模型标识选择即可，具体走哪个供应商由平台按 Key 可用性与配额自动路由，用户无需感知 |
| 供应商健康与容错（§2.7.6） | 新增需求，待后端落地（健康指标聚合、熔断状态机、健康看板），一期可先实现"可疑/熔断"最小闭环 |
| 模型生命周期（§2.8.4） | 已落地："禁用 + 通知替换推荐"（禁用即标记"即将下线"，`MessageService.send` 向活跃会话用户推送替换模型推荐）；软删除仍要求无活跃会话 |
| 模型分组与智能路由（§2.8.5） | 远期能力，是否推进取决于调用 trace 与评测数据积累 |
| 用量与成本分析一期范围（§2.8.6） | 一期实现供应商健康看板即可，完整成本归因与计费模块统计并轨评估 |
| Key 级 RPM 限流 | 是否一期落地取决于供应商限流策略（部分供应商按 TPM 限流，需按供应商探测） |
| 计费比例版本化 | 是否引入价格版本字段，取决于计费对账精细度要求 |
