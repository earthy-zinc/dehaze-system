# AI 对话模块 - 后端实现设计（Agent 评测）

## 1. 文档概述

本文档描述 F-M08-014 Agent 评测的技术选型与后端实现，包括评测集/样本管理、评测执行、四维评分、发布门禁、评测报告、生产持续评估与 Bad Case 回流。功能需求见 [需求规格.md](./需求规格.md)，接口契约见 [API接口.md](../API接口.md) §2.6。

> 评测执行能力收敛于此功能域；发布门禁的触发与消费在智能体管理（见 [智能体管理/后端实现.md](../智能体管理/后端实现.md) §9）。

### 1.1 技术选型

#### 设计动机

智能体配置（提示词、模型、工具集、推理参数）每次变更都可能引入能力退化，而"变好变差"无法靠零散反馈判断。评测要解决的核心问题：**让变更可量化、可比较、可回归**——发布前用积累的"考题"（评测集）批量验证，用分数决定是否放行。评测的本质是"在受控环境里重放真实场景并对过程与结果打分"，因此必须跑在真实推理链路上，而非孤立验证单个组件。

#### 关键架构取舍

| 取舍点 | 方案对比 | 选择与理由 |
|--------|---------|-----------|
| 评测引擎 | 自研 EvalService/EvalRunner vs 引入 DeepEval 等评测框架 | 选自研。评测必须跑在自有 deepagents 推理链路与四维评分模型上（与 `sys_ai_agent_eval_*` 数据模型绑定）；引入框架需适配本地 LLM、三端后端与自有数据模型，收益低、成本高（遵循最小必要原则） |
| 判分模型 | 平台本地 LLM（qwen3-0.6b，local provider）vs 外部模型 | 选本地 LLM。零成本、数据不出域、判分一致性可控（固定温度 0）；经模型注册表可切换外部模型兜底 |
| 评测执行 | XXL-Job 异步批量 + 手动触发小集 vs 全部同步 | 选异步为主。回归集样本量大，同步执行阻塞发布体验；复用现有 XXL-Job 基础设施，手动触发走小集快速反馈 |
| 结果存储 | 复用 `sys_ai_agent_eval_run`（results JSON）vs 新增结果明细表 | 选复用。四维聚合 + 样本明细 JSON 满足报告与门禁判定，避免为"一次执行的明细"引入额外实体（对齐最小必要表原则） |
| 评测对象 | 固定 Agent 版本 vs 草稿配置直接评测 | 选草稿配置。发布门禁评测的是"即将生效的配置"，与生产版本对比得出退化结论 |

#### 总体规划

评测消费可观测性（F-M08-013）的过程链数据作为轨迹级判定依据：

```
评测集（样本）→ 评测执行（真实推理链路）→ 四维评分 → 报告/门禁
     ↑                                           ↓
消息反馈点踩 / 生产事故 ──脱敏回流──→ 评测集扩充  发布/回滚决策
```

### 1.2 设计思想

| 原则 | 说明 |
|------|------|
| 真实链路 | 评测跑在 Agent 完整推理链路上（含工具调用），不 mock 关键环节，结果可信 |
| 过程结果分开 | 结果质量与过程合规独立评分，不以模糊总分掩盖"答对但过程危险/低效" |
| 确定性优先 | 能明确比对的（工具选择/参数/禁止行为）用规则判定，减少主观波动 |
| 执行隔离 | 评测使用平台专用 Token 池、独立会话上下文，不污染生产会话、不计入用户配额 |
| 结果可信 | 关键用例以 pass@k（重复执行取通过概率）反映真实可靠性，规避多步推理单次波动；固定判分模型与参数保证版本可比 |

## 2. Agent 评测实现 (F-M08-014)

### 2.1 数据模型

表结构详见 [数据库设计 §4.7](../../../../02-系统架构/03-数据库设计.md)，DDL 见 `config/sql/schema/`：

| 表 | 职责 | 逻辑删除 |
|----|------|---------|
| `sys_ai_agent_eval_dataset` | 评测集（`dataset_type`：`dev`/`regression`/`heldout`）+ `agent_id` | 是（类别①） |
| `sys_ai_agent_eval_sample` | 评测样本（任务目标、允许输入、可用工具、期望过程/结果、禁止行为、风险等级） | 否（随数据集管理） |
| `sys_ai_agent_eval_run` | 评测执行记录（触发方式、状态、评分摘要、样本明细 JSON） | 否（只追加，发布审计轨迹） |
| `sys_ai_eval_review` | 人工复核记录（判分判定快照 + 人工判定回填一致/不一致；`(run_id, sample_id)` 唯一幂等） | 否（复核状态机 1 待复核 → 2 已复核） |

**评测表关键设计**（对齐最小必要表原则）：

| 表 | 关键字段设计 |
|----|-------------|
| `sys_ai_agent_eval_dataset` | `dataset_type`（`dev`/`regression`/`heldout`）+ `agent_id`；开发集日常调试、回归集发布门禁、保留集阶段验收 |
| `sys_ai_agent_eval_sample` | `task_goal`/`allowed_input`/`tools`/`expected_process`/`expected_result`/`forbidden_behavior`/`risk_level`，每条样本含可审计的通过/失败条件；`risk_level=high` 的样本失败阻断发布 |
| `sys_ai_agent_eval_run` | `trigger_type`（`manual`/`publish`）+ `status`（1=执行中，2=通过，3=失败）+ `score_summary`（四维评分聚合）+ `results`（样本明细 JSON）；发布审计轨迹，支持回溯每次发布对应的评测结果 |

> 评测结果明细存 `run.results` JSON（每条样本的四维分数 + 通过状态 + 差异说明 + pass@k 的 `attempts`/`passed`），不独立建结果表，避免为"一次执行的明细"引入额外实体。

### 2.2 评测集与样本管理

| 能力 | 实现要点 |
|------|---------|
| 评测集 CRUD | 挂载在 Agent 下（`/agents/{id}/eval/datasets`），`dataset_type` 决定用途与评测频率 |
| 样本 CRUD | 属于评测集（`/eval/datasets/{id}/samples`），含 `risk_level`（高风险样本参与门禁硬阻断） |
| Bad Case 回流 | 复用样本创建接口写入回归集：消息反馈闭环（`processFeedbackLoop`）与生产事故确认后，脱敏后写入（见 §2.7） |
| 去重 | 回流样本按内容指纹查重，控制评测集膨胀 |

### 2.3 评测执行

`EvalRunner` 逐样本执行评测集：为每条样本构造独立会话上下文（不污染生产会话），运行 Agent 完整推理链路（复用 `DeepAgentBuilder`），按四维评分，汇总通过/失败：

```
Trigger（发布门禁 / 手动触发 / XXL-Job 定时）
  → EvalService：创建 eval_run（trigger_type + status=1）
  → EvalRunner 逐样本：
      构造样本上下文（不含用户信息）
      运行 Agent 推理链路（复用生产推理编排）
      收集过程轨迹 + 最终输出
      四维评分（结果/过程/安全/效率）
  → 汇总 score_summary + results（每条样本：分数/通过/差异说明）
  → status=2（通过）/ 3（失败）
```

**执行方式**：

| 触发 | 方式 | 场景 |
|------|------|------|
| 发布门禁 | 发布接口内部同步触发回归集 | Agent 发布前必跑（见 §2.5） |
| 手动触发 | 同步小集（开发集） | 配置迭代快速反馈 |
| 定时回归 | XXL-Job 异步批量（回归集/保留集） | 持续监控能力稳定（见 §2.6） |

**执行策略**（缓解评测波动与成本失控）：

| 策略 | 说明 |
|------|------|
| 稳定性质控 | 发布门禁关键用例重复执行 k 次（默认 1，`pass@k` 取通过概率），`results` 记录 `attempts`/`passed`；多步推理非确定性下以通过概率而非单次结果判定 |
| 失败快停 | 高风险样本（`risk_level=high`）失败即终止后续样本执行，快速返回阻断结论，节省成本 |
| 增量评测 | 配置变更时仅执行变更相关用例（按样本标签/场景圈定），全量回归由定时任务承担 |
| 断点续跑 | 执行中断后从 `results` 已存进度续跑，不整体重跑 |
| 预算上限 | 单次评测 Token 预算超限终止并告警（防评测成本失控） |

### 2.4 评分模型

指标按**结果 / 过程 / 安全 / 效率**四组组织，`score_summary` 存四维聚合值，`results` 存每条样本的指标明细与差异说明：

| 指标组 | 指标 | 评估方式 |
|--------|------|---------|
| **结果质量** | 任务完成率 | 封闭式任务：规则校验 + 判分模型对比 `expected_result`；开放式任务：判分模型推断用户目标后判定完成 |
| 结果质量 | 幻觉检测 | 引用支撑校验（回答的引用是否真实存在且支撑结论）+ 事实核查规则 + 判分模型判定虚构/自相矛盾 |
| 结果质量 | 主观评分 | 判分模型按统一评分标准评估有用性/连贯性（温度 0，见判分治理） |
| **过程合规** | 工具调用准确率 | 确定性比对：实际调用工具集与 `expected_process`/`tools` 匹配、参数正确的次数 / 总调用次数 |
| 过程合规 | 步骤正确性 | 比对推理步骤是否遵循预期过程、是否越权、是否重复调用（对比 `expected_process`/`forbidden_behavior`） |
| 过程合规 | 死循环检测 | 规则判定：推理步数超过阈值，或同一工具名 + 同一参数摘要重复调用 N 次（复用可观测性防循环观测数据） |
| **安全边界** | 安全合规 | 是否泄露敏感信息、是否被注入、是否触发禁止行为 |
| **效率** | 资源与耗时 | token 消耗、总耗时、首 Token 延迟（latency）、推理步数是否在预算内（不直接判死，超预算可设阈值判定失败） |

四维分数聚合为通过/失败：任一**判定组**（结果质量/过程合规/安全边界）低于阈值或 `risk_level=high` 样本失败即判定该样本失败；效率组作为报告与成本观测指标，超预算时按阈值判定。

**判分模型**：默认平台本地 LLM（温度 0，固定 seed），经模型注册表可配置（可切换外部强模型兜底，缓解小模型"难以评估更强生产模型"的局限）；规则可判定的维度（工具/参数/禁止行为）不走模型，降低主观波动（对齐"确定性优先"）。

**判分治理**（保障判分模型自身可靠）：

| 机制 | 说明 |
|------|------|
| 一致性验证 | 判分模型上线前用人工标注样本集验证与人工判定一致性（≥ 90% 方可启用），不达标不启用 |
| 偏见缓解 | 评分时打乱候选顺序、必要时多模型交叉验证，缓解位置偏见与长输出偏好 |
| 定期校准 | 定时用人工复核样本校验判分漂移，漂移超阈值告警并暂停依赖其的门禁判定 |

### 2.5 发布门禁

`AgentService` 发布前调用 `EvalService` 跑回归集（`trigger_type=publish`）：评分下降或高风险样本失败时阻断发布，返回失败样本与差异点；发布成功后，`eval_run` 作为发布审计轨迹保留，支持回溯每次发布对应的评测结果。

**门禁判定**（三档量化）：

| 条件 | 结果 |
|------|------|
| 回归集全部通过（pass@1）且相对上次回归无显著退化且无高风险失败 | 通过，允许发布 |
| 任一维度分数低于绝对阈值 | 阻断发布，返回差异用例 |
| 与上次回归对比总得分下降超过相对退化阈值 | 阻断发布，标注退化差异 |
| `risk_level=high` 样本失败 | 硬阻断，不可发布 |
| 判分模型漂移（judge-status 一致性状态为 `drifted`） | 硬阻断，门禁暂停（A0503），提示联系管理员校准；管理员 `force=true` 可豁免 |
| 豁免 | 管理员确认豁免（`POST /publish` 带 `force=true`）并记录原因（版本 `change_note` 前缀 `[漂移豁免]`，可追溯）；豁免仅跳过漂移阻断，不绕过回归门禁结果 |

### 2.6 生产持续评估

| 能力 | 实现要点 |
|------|---------|
| 定时回归 | XXL-Job 按频率跑回归集/保留集，结果与历史对比，发现渐进式退化 |
| 线上抽样评估 | 生产真实会话按采样率抽取，复用评分模型评估，与离线结果对照（消费可观测性过程链数据） |
| 人工复核 | 失败样本全量 + 通过样本按 `ai_eval.judge_review_ratio`（默认 1%）确定性抽样入复核队列（`sys_ai_eval_review`，`(run_id, sample_id)` 唯一幂等），`POST /eval-center/reviews/{id}` 回填判定一致/不一致（已复核项不可重复回填） |
| 判分漂移检测 | 人工复核一致率低于 `ai_eval.judge_consistency_threshold` 时判分状态置 `drifted`（`GET /eval-center/judge-status`）；`drifted` 时发布门禁**硬阻断**（`AgentVersionService.publish` 返回 A0503，管理员 `force=true` 可豁免并记录于发布版本 `change_note`）；复核不足时为 `insufficient_data`（不阻断，评测手动执行不受漂移影响） |
| 退化告警 | 抽样得分或核心指标持续下降触发告警（对接监控设施） |

**评测中心聚合接口**（`/api/v1/ai/eval-center`，全部 `ai:agent:manage`，契约见 [API接口.md](../API接口.md) §2.6）：

| 端点 | 实现要点 |
|------|---------|
| `GET /overview` | 各 Agent 最近两次已完成 run 经窗口函数一次查询（`list_latest_per_agent`）；门禁状态取 run.status，退化标识按总分（四维均值）相对下降对比 `ai_eval.regression_threshold`，高风险失败标识扫描 run.results |
| `GET /trends` | 已完成 run 时间升序序列（agentId/时间范围/limit 过滤），供 TrendPanel 历史趋势 |
| `GET /runs/{runId}/compare` | 两次 run 四维得分差 + 按 `sample_id` 匹配的样本级差异（added/removed/changed/unchanged_count）；跨 Agent 对比拒绝（A0400） |
| `GET /judge-status` | 轻量判分状态：不做在线验证器，从人工复核一致率 + sys_dict 阈值推导（`normal`/`drifted`/`insufficient_data`） |
| `GET /reviews`、`POST /reviews/{id}` | 复核队列幂等物化（失败样本必入队 + 通过样本确定性抽样 `_sample_hit`）与回填；回填后 judge-status 即时反映 |

### 2.7 Bad Case 回流（反馈闭环）

| 来源 | 回流路径 |
|------|---------|
| 消息反馈点踩 | `processFeedbackLoop` 扫描高价值差评（高频、关键业务、可确认根因），脱敏后写入回归集（`risk_level` 标记） |
| 生产事故 | 事故确认根因后脱敏入库，防止同类问题复发 |
| 门禁失败 | 发布被拦截的失败样本自动沉淀，扩大回归集覆盖 |

### 2.8 配额与执行隔离

- 评测执行使用平台专用 Token 池，**不计入用户配额**（计费口径见 [AI模型管理/后端实现.md §3 计费集成](../../../基础模块/AI模型管理/后端实现.md)）
- 评测消耗单独统计，不影响业务用量报表
- 评测会话上下文独立，不污染生产会话；A2A 外部调用下评测照常生效，不因来源旁路

### 2.9 权限与保留

| 项 | 规则 |
|----|------|
| 权限 | 评测集/样本/执行管理需 `ai:agent:manage`；评测报告对 AI 能力配置者可见 |
| 保留 | `sys_ai_agent_eval_run` 只追加保留（发布审计轨迹）；样本随数据集管理 |

## 3. 配置项与常量

### 配置项（运营/质量决策，来源：sys_dict / AI模型管理 注册表）

判分模型选择与发布门禁/抽样/调度等业务质量决策参数，保留为配置：

| 配置项 | 说明 | 默认值 | 落地状态 |
|--------|------|--------|---------|
| `ai.eval.judge_model` | 判分模型（来源：AI模型管理 注册表，默认本地 LLM，可切换外部强模型） | local 默认模型 | 规划中（当前实现为规则式评分，无独立判分模型调用） |
| `ai.eval.score_threshold` | 四维评分绝对通过阈值 | 60（0-100 分制，代码常量 `eval_runner._PASS_THRESHOLD`） | 代码常量；sys_dict 消费方规划中 |
| `ai_eval.regression_threshold` | 相对退化阈值（总/分维度得分相对上次下降超此百分比判定退化/阻断） | 5（sys_dict `ai_eval`，百分制整数） | 已落地（评测中心 overview 消费） |
| `ai_eval.judge_consistency_threshold` | 判分一致性阈值（人工复核一致率低于此百分比判定漂移） | 90（sys_dict `ai_eval`） | 已落地（评测中心 judge-status 消费） |
| `ai_eval.judge_review_ratio` | 人工复核抽样比例（通过样本确定性抽样百分比，失败样本全量入队） | 1（sys_dict `ai_eval`） | 已落地（评测中心 reviews 消费） |
| `ai.eval.regression_schedule` | 定时回归 Cron | 每日 02:00 | 规划中（XXL-Job 定时回归未落地） |
| `ai.eval.sample_retention` | 线上抽样评估采样率 | 5% | 规划中（线上抽样评估未落地） |

### 常量（纯技术参数，代码内置）

以下为并发/批次/预算等纯技术参数，无运营调整动机，固化为代码常量：

| 常量 | 说明 | 实际值 |
|------|------|--------|
| `ai.eval.pass_k` | 发布门禁关键用例重复执行次数 | 1 |
| `ai.eval.budget_tokens` | 单次评测 Token 预算上限 | 200000 |
| `ai.eval.fail_fast` | 高风险样本失败快停开关 | true |

## 4. 模块间协作

| 模块 | 协作点 |
