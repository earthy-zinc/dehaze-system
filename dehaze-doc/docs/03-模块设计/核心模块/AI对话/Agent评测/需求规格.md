# AI 对话模块需求规格（Agent 评测）

> 功能域定位：本功能域（F-M08-014）为 AI 对话与智能体的能力建立**可量化的质量标准**——回答"这次变更到底变好了还是变差了"。通过评测集、评测执行、评分体系、发布门禁与生产持续评估，支撑 AI 能力迭代的可信决策，替代"改完凭感觉"。

## 2.13 Agent 评测 (F-M08-014)

### 2.13.1 功能描述

智能体、提示词、模型、MCP 工具等配置的每次调整，都可能带来能力提升或退化。当前平台缺少判断手段：没有"改前 vs 改后"的量化对比，没有发布前的质量回归，配置者只能靠零星反馈与主观感受迭代。

本功能域建立三层评测体系，与可观测性（F-M08-013）共享执行轨迹数据，形成"**记录过程 → 判断质量 → 门禁发布 → 持续回归**"的闭环：

| 层级 | 回答的问题 | 应用场景 |
|------|-----------|---------|
| 场景回归 | 核心业务场景是否仍然做对 | 发布门禁、变更回归 |
| 过程质量 | 决策过程是否正确高效（用对能力、不绕路） | 效果归因、配置优化 |
| 生产持续评估 | 线上真实环境是否持续可靠 | 能力退化发现、长期监控 |

### 2.13.2 评测集管理

评测集是质量标准的载体，按智能体/业务场景组织，可版本化管理：

| 能力 | 说明 |
|------|------|
| 用例管理 | 按智能体、业务场景（去雾调度、参数调优、批量摘要、知识问答等）组织测试用例；用例含输入、预期行为、关键校验点（如应调用的能力、应遵守的约束） |
| 用例版本化 | 用例变更保留版本记录，评测结果与用例版本关联，保证历史可比 |
| 分级管理 | 开发集（迭代自测）、回归集（发布门禁）、保留集（长周期监控），分级设置评测频率 |
| 回流机制 | 高价值差评（消息反馈点踩，见 F-M08-008）、生产异常案例经脱敏与确认后自动转入评测集，防止同类问题复发 |
| 去重与质量 | 新用例自动查重、标注来源（人工/反馈/事故），控制评测集膨胀 |
| 过时清理 | 业务场景变化导致失效的用例定期清理或停用，避免"过时考题"误判当前能力 |
| 覆盖度审计 | 评测集按业务场景/边界类型统计覆盖，识别盲区，保障"考题"均衡 |

### 2.13.3 评测执行

| 能力 | 说明 |
|------|------|
| 按需评测 | 配置者可对任一智能体/配置变更手动发起评测，立即得到结果 |
| 定时评测 | 按设定频率（每日/每周）自动执行回归集，持续监控能力稳定 |
| 评测任务管理 | 评测批量异步执行，任务进度、状态、结果可查看；执行不影响线上服务 |
| 失败定位 | 失败用例可查看其完整执行过程（结合 F-M08-013 的过程记录），定位到具体环节 |
| 稳定性质控 | 关键用例支持重复执行取通过概率（pass@k），规避多步推理单次执行的波动，反映真实可靠性 |
| 成本控制 | 失败快停（高风险样本失败即终止后续执行）、增量评测（仅执行变更相关用例）、单次评测 Token 预算上限 |
| 断点续跑 | 执行中断后从已完成样本处续跑，不整体重跑 |

### 2.13.4 评分体系

评测不只看"最终答案对不对"，还评估"过程对不对、效率高不高、安不安全"。指标按**结果 / 过程 / 安全 / 效率**四组组织，结果与过程组指标判定样本通过/失败，效率组作为报告与成本观测指标（超预算可设阈值判定失败）：

| 指标组 | 指标 | 说明 | 判定方式 |
|--------|------|------|---------|
| **结果质量** | 任务完成率 | 封闭式任务对比预期结果是否达成；开放式任务判分模型推断用户目标后判定完成与否 | 预期比对 / 标准判定 |
| 结果质量 | 幻觉检测 | 回答是否虚构事实、与依据/知识不符（引用支撑校验、事实核查） | 规则校验 / 标准判定 |
| 结果质量 | 主观评分 | 回答是否有用、连贯、符合预期质量 | 标准判定（统一评分标准） |
| **过程合规** | 工具调用准确率 | 实际调用工具与预期工具集匹配、参数正确的比例 | 明确比对（正确调用/总调用） |
| 过程合规 | 步骤正确性 | 推理步骤是否遵循预期过程、是否越权、是否重复 | 过程比对 |
| 过程合规 | 死循环检测 | 是否进入死循环（步数超阈值、重复调用同一工具/重复同一推理步骤） | 规则判定 |
| **安全边界** | 安全合规 | 是否泄露敏感信息、是否被注入、是否触发禁止行为 | 规则校验 |
| **效率** | 资源与耗时 | token 消耗、总耗时、首 Token 延迟、推理步数是否在预算内 | 阈值判定 |

**判定方式说明**：

| 方式 | 适用场景 |
|------|---------|
| 明确比对 | 能力调用、参数、结构化输出等有明确预期，可直接比对，结果确定可靠 |
| 标准评估 | 任务完成度、回答质量等需要综合判断，由统一评估标准按规则打分 |

> 设计原则：能明确比对的优先明确比对，避免主观评估的不稳定；主观维度（有用性等）采用统一评分标准与示例校准，降低波动。

> **判分质量保障**：标准判定依赖判分模型的可靠性，须满足三重保障——上线前与人工标注集做一致性验证（不达标不启用）、评分时打乱顺序/多模型交叉缓解位置偏见与长输出偏好、定期抽样人工复核校准判分漂移。

### 2.13.5 评测报告

| 能力 | 说明 |
|------|------|
| 得分总览 | 评测总得分、四维得分（结果质量/过程合规/安全边界/效率）、指标级明细（任务完成率/工具调用准确率/幻觉/死循环/效率指标）、各用例通过情况，含 pass@k 通过率 |
| 用例明细 | 逐用例结果：输入、实际行为、判定结果、失败原因 |
| 版本对比 | 变更前后两版配置的评测结果对比，直接回答"改好了还是改差了"，显著退化（超阈值）显式标注 |
| 历史趋势 | 同一评测集的历史得分趋势，发现渐进式退化，支持与门禁退化阈值对照 |

### 2.13.6 发布门禁

评测结果作为智能体与重要能力变更的发布门槛：

| 规则 | 说明 |
|------|------|
| 门禁触发 | 智能体发布、重要配置变更（提示词、模型、工具集、关键参数）发布前必须通过回归集评测 |
| 门禁判定 | 三档量化：绝对分阈值（维度分数低于阈值）+ 相对退化阈值（与上次回归对比总得分下降超阈值）+ 高风险样本硬阻断，任一命中即阻断 |
| 阻断与差异 | 未通过则阻断发布，展示差异用例与失败原因（含退化对比），指导配置者修复后重测 |
| 豁免流程 | 特殊情况需豁免发布时，须由管理员确认并记录原因，保证可追溯 |

### 2.13.7 生产持续评估

评测不能只在发布时做一次，需持续关注线上真实表现：

| 能力 | 说明 |
|------|------|
| 线上抽样评估 | 对线上真实会话抽样进行质量评估，与离线评测结果对照 |
| 能力退化告警 | 抽样评估得分或核心指标持续下降时告警，主动发现渐进式退化 |
| 素材回流 | 线上暴露的问题案例确认后转入评测集，不断扩大覆盖 |

### 2.13.8 反馈闭环

本功能域与平台既有反馈链路打通，形成质量持续提升的闭环：

```
消息点踩（F-M08-008）
  → 高价值差评确认根因
  → 脱敏后转为评测用例
  → 纳入回归集
  → 变更发布时回归拦截
  → 同类问题不再复发
```

### 2.13.9 业务规则

| 规则 | 说明 |
|------|------|
| 执行隔离 | 评测批量执行不占用用户对话资源，不影响线上体验 |
| 结果可信 | 关键用例以 pass@k 反映真实可靠性（不要求单次 98% 一致）；配置变更前不重新评估已测结果 |
| 判分质量保障 | 判分模型须通过一致性验证并定期校准；判分漂移超阈值时暂停依赖其的门禁判定 |
| 人工复核 | 线上抽样判定按比例抽取人工复核，校准判分模型并防止指标失真 |
| 评测预算 | 单次评测设 Token 预算上限，超预算终止并告警，防评测成本失控 |
| 权限控制 | 评测集管理、评测执行、门禁豁免需管理员权限；评测报告对 AI 能力配置者可见 |
| 消耗归集 | 评测消耗的配额与费用单独统计，不计入业务用量报表，避免污染真实数据 |
| 数据脱敏 | 生产数据转入评测集前必须脱敏（用户信息、敏感内容） |

### 2.13.10 用户交互流程

**配置迭代流程**（AI 能力配置者视角）：

```
修改智能体提示词/模型/工具配置
  → 保存为草稿
  → 发起发布前评测（回归集）
  → 查看评测报告与版本对比
  → 通过 → 发布，新会话生效
  → 未通过 → 查看失败用例执行过程 → 调整配置 → 重新评测
```

**持续监控流程**（平台管理员视角）：

```
查看评测中心
  → 查看各智能体评测趋势与线上抽样评估结果
  → 收到能力退化告警
  → 定位退化用例与执行过程
  → 转交配置者修复或回滚版本
```

### 2.13.11 非功能需求与成功度量

**非功能需求**：

| 维度 | 指标 |
|------|------|
| 评测时效 | 百级用例回归集评测完成 P95 ≤ 10 分钟 |
| 结果可信 | 发布门禁关键用例 pass@1 ≥ 阈值；稳定性质控样本 pass@8 ≥ 阈值（反映真实可靠性，不要求单次一致） |
| 判分一致性 | 判分模型与人工标注集一致率 ≥ 90% 方可启用 |
| 执行隔离 | 评测执行对线上对话指标无可见影响 |

**成功度量**：

| 指标 | 定义 | 目标 |
|------|------|------|
| 门禁执行率 | 智能体发布中实际经过评测门禁的比例 | 100% |
| 回归拦截率 | 发布前评测发现的能力退化/回归用例数 / 发布次数 | ≥ 5% 迭代被拦截后修正 |
| 缺陷回流率 | 生产事故与高价值差评转化为评测用例的比例 | ≥ 80% |
| 迭代周期 | 从发现问题到修复验证通过的平均时长 | ≤ 1 个工作日 |
