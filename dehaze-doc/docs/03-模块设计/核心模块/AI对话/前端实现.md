## 3. 状态管理

### 3.1 Store 模块划分

| Store 模块 | 职责 | 生命周期 |
|-----------|------|---------|
| 全局 Store | 会话列表、可用模型列表、配额信息、定时任务列表 | 应用级，跨会话共享 |
| 会话级 Store | 当前会话 ID、消息列表、流式输出状态、推理步骤、中断点 | 会话级，切换会话时重置流式状态 |

### 3.2 核心状态

| 状态 | 类型 | 说明 |
|------|------|------|
| `conversations` | Conversation[] | 会话列表，含未读消息数 |
| `currentConversationId` | number | 当前会话 ID |
| `messages` | Message[] | 当前会话消息列表 |
| `streamingMessageId` | number \| null | 正在流式输出的消息 ID |
| `availableModels` | Model[] | 可用模型列表 |
| `quota` | QuotaInfo | 配额使用情况 |
| `interrupts` | Interrupt[] | 当前会话未处理的中断点 |
| `scheduledTasks` | ScheduledTask[] | 用户定时任务列表 |

Message 完整数据结构属 API 契约，见 [API接口.md](./API接口.md)；前端关注的核心字段：

| 字段 | 前端用途 |
|------|---------|
| id / conversationId / parentMessageId | 消息定位与分支对话渲染 |
| role | 区分用户/助手/工具消息，选择对应渲染组件 |
| status | 驱动流式状态机（见 §3.4，含 streaming/completed/failed/canceled/paused） |
| agentThoughts | ThoughtChain 推理过程渲染数据源 |
| artifacts | ArtifactCard 产物卡片渲染数据源 |
| feedback | FeedbackBar 反馈状态展示 |
| inputTokens / outputTokens / credits | 配额与计费展示 |

### 3.3 SSE 事件处理

| 事件 | 处理逻辑 |
|------|---------|
| `message.start` | 创建 assistant 消息占位，status=streaming |
| `content_block.start` | 按 type（text/thinking/tool_use）创建对应内容块占位 |
| `content_block.delta` | 按 delta.type 增量更新内容块（text_delta 追加文本、thinking_delta 追加思考、input_json_delta 累积工具参数） |
| `content_block.stop` | 标记内容块完整，工具参数可解析为 JSON |
| `thought` | 追加 agentThoughts 到消息，ThoughtChain 增量渲染 |
| `interrupt` | 显示 InterruptCard，暂停流式，status=paused |
| `ping` | 忽略（仅用于保活） |
| `error` | 标记消息 status=failed，显示错误提示 |
| `message.end` | 标记消息 status=completed，更新 token 统计和 credits（含 stopReason） |

### 3.4 流式输出状态机

```
idle ──(发送消息)──▶ streaming ──(message.end)──▶ completed
                         │
                         ├──(error)──▶ failed
                         │
                         ├──(用户停止)──▶ canceled
                         │
                         └──(interrupt)──▶ paused ──(resume)──▶ streaming
```

## 4. 页面布局设计

### 4.1 页面结构

采用**左侧会话列表 + 右侧对话区**的双栏布局：

| 区域 | 宽度 | 说明 |
|------|------|------|
| 左侧会话列表 | 280px | 会话列表 + 搜索 + 新建按钮 |
| 右侧对话区 | 自适应填充 | 顶部栏 + 消息列表 + 输入区 |

### 4.2 响应式布局

| 屏幕尺寸 | 布局方式 |
|---------|---------|
| 桌面端（>=992px） | 左右双栏，左侧固定宽度可折叠 |
| 移动端（<992px） | 单栏，会话列表抽屉式弹出 |

### 4.3 路由设计

| 路由路径 | 页面 | 权限控制 |
|---------|------|---------|
| `/chat` | ChatPage | 登录用户，默认进入最新会话或新建 |
| `/chat/:conversationId` | ChatPage | 登录用户，指定会话的对话页面 |
| `/chat/models` | ModelManagePage | 管理员（权限标识 `ai:model:manage`），导航守卫校验角色 |
| `/chat/skills` | SkillsManagePage | 管理员，导航守卫校验角色 |
| `/chat/tasks` | ScheduledTaskPage | VIP2 及以上用户，导航守卫校验会员等级 |

管理员路由（`/chat/models`、`/chat/skills`）通过全局导航守卫校验用户角色，非管理员访问时重定向至 `/chat` 并提示无权限。VIP 限制路由（`/chat/tasks`）校验会员等级，不满足时引导升级。

## 5. 核心交互实现

### 5.1 流式消息渲染

| 阶段 | 处理方式 |
|------|---------|
| 发送 | 创建 user 消息立即渲染；创建 assistant 占位（status=streaming，加载动画）；建立 SSE 连接 |
| 事件处理 | 见 §3.3 SSE 事件处理 |
| 渲染优化 | token 增量使用 requestAnimationFrame 批量更新；Markdown 增量渲染只重新解析变化部分；ThoughtChain 默认折叠减少渲染压力 |

### 5.2 推理过程展示

| 展示项 | 说明 |
|--------|------|
| ThoughtChain 默认折叠 | 显示"查看推理过程（N 步）" |
| ThoughtStep 内容 | 步骤序号 + 耗时 + thought 内容 + tool 调用（工具名/参数可展开）+ observation 摘要 + status 标识（成功/失败/跳过） |
| 失败步骤 | 高亮显示错误原因 |
| 子智能体消耗 | SubAgentPanel 实时展示各并行子智能体累计 Token 数与积分占用，与主 Agent 消耗汇总为会话总消耗 |

### 5.3 中断交互

| 中断类型 | 前端展示 | 用户操作 |
|---------|---------|---------|
| `confirm` | 推荐算法卡片（算法名/理由/参数/备选） | 确认使用 / 切换备选 / 修改参数 |
| `quota` | 配额不足提示 + 升级引导 | 升级 VIP / 等待重置 / 放弃 |
| `async_wait` | 处理进度展示（进度条/预计耗时） | 等待完成 / 取消 |

收到 interrupt 事件后根据 type 渲染对应 InterruptCard，展示在消息列表对应位置；用户操作后调用消息发送接口 `POST /api/v1/ai/conversations/{id}/messages`，请求体携带 `resume` 参数恢复中断的推理，恢复 SSE 流式输出。`resume` 参数结构详见 [API接口.md](./API接口.md)。

### 5.4 产物卡片展示

| 产物类型 | 卡片内容 | 交互 |
|---------|---------|------|
| `image_result` | 缩略图 + 算法名 + 参数 + "查看大图"按钮 | 点击跳转图像处理结果页 |
| `metric_report` | 指标数值表格（PSNR/SSIM/LPIPS）+ 评级 | 点击展开详情 |
| `algorithm_recommend` | 算法名 + 推荐理由 + 匹配度 + "使用此算法"按钮 | 点击展开详情 |
| `file_ref` | 文件名 + 类型 + "下载"按钮 | 点击展开详情 |

### 5.5 分支对话交互

| 操作 | 流程 |
|------|------|
| 重新生成 | 助手消息下方"重新生成"按钮 → 调用 `POST /api/v1/ai/messages/{id}/regenerate` → 创建新 assistant 分支 → 渲染新消息，原消息保留 → 分支切换器（< 2/3 >）切换查看 |
| 编辑重发 | 用户消息下方"编辑"按钮 → 内容变为可编辑输入框 → 修改后发送 → 调用 `PUT /api/v1/ai/messages/{id}` → 创建新 user + assistant 分支 |

## 6. 模型选择交互

### 6.1 模型选择器

| 展示项 | 说明 |
|--------|------|
| 模型列表 | 模型名称 + 提供商标识 + 能力图标（多模态/工具调用/流式）+ 积分单价（输入/输出）+ 推荐场景 |
| VIP 限制 | 根据用户 VIP 等级禁用不可用模型 |
| 多模态校验 | 附带文件时校验所选模型是否支持对应模态（图片需视觉能力、文档需文档理解能力、音视频需对应理解能力）；不支持时提示并阻止发送或引导切换模型 |

切换模型后更新会话模型配置，下一条消息使用新模型，历史消息保持原模型记录。

### 6.2 模型参数配置

| 参数 | 控件 | 范围 |
|------|------|------|
| temperature | 滑块 | 0-2 |
| top_p | 滑块 | 0-1 |
| max_tokens | 输入框 | - |

修改后保存到会话 model_config，下一条消息使用新参数。

## 11. 定时任务管理

### 11.1 创建定时任务

用户在对话中确认处理流程后，通过 SaveAsTaskDialog 保存为定时任务：

| 配置项 | 说明 |
|--------|------|
| 触发规则 | Cron 表达式 |
| 输入来源 | 固定输入（预设图片集）/ 动态输入（MCP 拉取监控截图/指定目录新文件） |
| 输出目标 | 结果分发目标 |

仅 VIP2 及以上用户可创建，导航守卫与弹窗入口校验会员等级。

### 11.2 任务管理

| 功能 | 说明 |
|------|------|
| 任务列表 | 按下次触发时间排序，展示启用状态与最近执行结果 |
| 操作 | 启停 / 编辑 / 删除 |
| 执行历史 | 每次执行的结果/消耗/耗时/失败原因，保留 30 天 |

任务执行消耗计入用户配额，配额不足时跳过本次执行并通知用户。

## 12. 安全与性能

### 12.1 XSS 防护

- LLM 输出内容通过 MarkdownRenderer 渲染，自动转义 HTML
- 用户输入内容展示前转义
- 产物卡片中的 URL 校验白名单

### 12.2 性能优化

| 优化项 | 说明 |
|--------|------|
| 虚拟滚动 | 消息列表超 100 条时启用虚拟滚动 |
| 流式批量更新 | content_block.delta 事件使用 requestAnimationFrame 批量更新 |
| Markdown 增量渲染 | 只重新解析变化的文本段 |
| 图片懒加载 | 产物卡片缩略图懒加载 |
| 会话列表缓存 | 会话列表前端缓存，减少接口请求 |
| SSE 重连 | 网络断连后自动重连，携带 `Last-Event-ID` 和 `streamSessionId` 从断点恢复（最大 3 次，间隔 3 秒） |

### 12.3 离线处理

| 场景 | 处理方式 |
|------|---------|
| 发送消息时离线 | 提示网络不可用，消息暂存本地 |
| 流式输出中断连 | 自动重连，从中断点恢复 |
| 重连失败 | 提示用户检查网络，可手动重试 |

### 12.4 多端适配

本项目含 Android / Flutter / Taro / React Native / UniApp 等多端实现。各端参考本 Web 端（React）的组件结构、SSE 事件处理逻辑和状态管理方案，按各端技术栈适配实现，不另行编写独立前端实现文档。
