
## 3. 状态管理

### 3.1 全局状态

| 状态 | 类型 | 说明 |
|------|------|------|
| `conversations` | Conversation[] | 会话列表 |
| `currentConversationId` | number | 当前会话 ID |
| `messages` | Message[] | 当前会话消息列表 |
| `streamingMessageId` | number \| null | 正在流式输出的消息 ID |
| `availableModels` | Model[] | 可用模型列表 |
| `quota` | QuotaInfo | 配额使用情况 |

### 3.2 消息状态

```typescript
interface Message {
  id: number;
  conversationId: number;
  parentMessageId: number | null;
  role: 'system' | 'user' | 'assistant' | 'tool';
  content: string;
  toolCalls?: ToolCall[];
  toolCallId?: string;
  model?: string;
  status: 'streaming' | 'completed' | 'failed' | 'canceled';
  error?: string;
  metadata?: any;
  inputTokens?: number;
  outputTokens?: number;
  credits?: number;
  agentThoughts?: AgentThought[];
  artifacts?: Artifact[];
  feedback?: Feedback;
  createTime: string;
}
```

### 3.3 SSE 事件处理

| 事件 | 处理逻辑 |
|------|---------|
| `message.start` | 创建 assistant 消息占位，status=streaming |
| `content_block.start` | 按 type（text/thinking/tool_use）创建对应内容块占位 |
| `content_block.delta` | 按 delta.type 增量更新内容块（text_delta 追加文本、thinking_delta 追加思考、input_json_delta 累积工具参数） |
| `content_block.stop` | 标记内容块完整，工具参数可解析为 JSON |
| `thought` | 追加 agentThoughts 到消息，ThoughtChain 增量渲染 |
| `interrupt` | 显示 InterruptCard，暂停流式 |
| `ping` | 忽略（仅用于保活） |
| `error` | 标记消息 status=failed，显示错误提示 |
| `message.end` | 标记消息 status=completed，更新 token 统计和 credits（含 stopReason） |

### 3.4 流式输出状态机

```
idle ──(发送消息)──▶ streaming ──(message.end)──▶ completed
                         │
                         ├──(error)──▶ failed
                         │
                         ├──(用户停止)──▶ canceled
                         │
                         └──(interrupt)──▶ paused ──(resume)──▶ streaming
```

## 4. 页面布局设计

### 4.1 页面结构

采用**左侧会话列表 + 右侧对话区**的双栏布局：

| 区域 | 宽度 | 说明 |
|------|------|------|
| 左侧会话列表 | 280px | 会话列表 + 搜索 + 新建按钮 |
| 右侧对话区 | 自适应填充 | 顶部栏 + 消息列表 + 输入区 |

### 4.2 响应式布局

| 屏幕尺寸 | 布局方式 |
|---------|---------|
| 桌面端（>=992px） | 左右双栏，左侧固定宽度可折叠 |
| 移动端（<992px） | 单栏，会话列表抽屉式弹出 |

### 4.3 路由设计

| 路由路径 | 页面 | 说明 |
|---------|------|------|
| `/chat` | ChatPage | 对话主页面（默认进入最新会话或新建） |
| `/chat/:conversationId` | ChatPage | 指定会话的对话页面 |
| `/chat/models` | ModelManagePage | 模型管理（管理员） |

## 5. 核心交互实现

### 5.1 流式消息渲染

```
用户点击发送
    ↓
创建 user 消息（立即渲染）
    ↓
创建 assistant 消息占位（status=streaming，显示加载动画）
    ↓
建立 SSE 连接，监听事件：
  - message.start 事件 → 创建 assistant 消息占位，status=streaming
  - content_block.start 事件 → 按 type 创建内容块占位（text/thinking/tool_use）
  - content_block.delta 事件 → 按 delta.type 增量更新内容块
  - content_block.stop 事件 → 标记内容块完整，工具参数可解析
  - thought 事件 → 追加推理步骤，ThoughtChain 组件增量渲染
  - interrupt 事件 → 渲染 InterruptCard，暂停流式
  - ping 事件 → 忽略（仅保活）
  - message.end 事件 → 更新 status=completed，更新 token 统计和 stopReason
    ↓
渲染优化：
  - token 增量使用 requestAnimationFrame 批量更新，避免频繁重渲染
  - Markdown 增量渲染，只重新解析变化部分
  - ThoughtChain 默认折叠，减少渲染压力
```

### 5.2 推理过程展示

```
ThoughtChain 组件
    ↓
默认折叠状态：显示"查看推理过程（N 步）"
    ↓
展开后按 position 排序展示 ThoughtStep：
  - 步骤序号 + 耗时
  - thought 内容（LLM 思考）
  - tool 调用（工具名 + 参数，可展开查看）
  - observation 结果摘要
  - status 标识（成功/失败/跳过）
    ↓
工具调用参数和结果支持折叠/展开
    ↓
失败步骤高亮显示错误原因
```

### 5.3 中断交互

| 中断类型 | 前端展示 | 用户操作 |
|---------|---------|---------|
| `confirm` | 推荐算法卡片（算法名/理由/参数/备选） | 确认使用 / 切换备选 / 修改参数 |
| `quota` | 配额不足提示 + 升级引导 | 升级 VIP / 等待重置 / 放弃 |
| `async_wait` | 处理进度展示（进度条/预计耗时） | 等待完成 / 取消 |

```
收到 interrupt 事件
    ↓
根据 type 渲染对应 InterruptCard
    ↓
展示在消息列表中对应位置
    ↓
用户操作后调用消息发送接口（POST /conversations/{id}/messages），携带 resume 参数
  - {"resume": {"confirmed": true, "algorithm": "RIDCP", "params": {...}}}
  ↓
恢复 SSE 流式输出
```

### 5.4 产物卡片展示

```
ArtifactCard 组件
    ↓
根据 type 渲染不同卡片：
  - image_result：缩略图 + 算法名 + 参数 + "查看大图"按钮
  - metric_report：指标数值表格（PSNR/SSIM/LPIPS）+ 评级
  - algorithm_recommend：算法名 + 推荐理由 + 匹配度 + "使用此算法"按钮
  - file_ref：文件名 + 类型 + "下载"按钮
    ↓
点击卡片可展开查看详情
    ↓
image_result 点击可跳转到图像处理结果页
```

### 5.5 分支对话交互

```
助手消息下方显示"重新生成"按钮
    ↓
用户点击 → 调用 /regenerate 接口
    ↓
创建新的 assistant 消息（兄弟分支）
    ↓
渲染新消息，原消息保留
    ↓
消息上方显示分支切换器（< 2/3 >）
    ↓
用户可切换查看不同分支的回复
```

```
用户消息下方显示"编辑"按钮
    ↓
用户点击 → 消息内容变为可编辑输入框
    ↓
用户修改后点击"发送"
    ↓
调用 /messages/{id} PUT 接口
    ↓
创建新的 user 消息 + assistant 消息分支
```

```
    ↓
```

## 10. 安全与性能

### 10.1 XSS 防护

- LLM 输出内容通过 MarkdownRenderer 渲染，自动转义 HTML
- 用户输入内容展示前转义
- 产物卡片中的 URL 校验白名单

### 10.2 性能优化

| 优化项 | 说明 |
|--------|------|
| 虚拟滚动 | 消息列表超 100 条时启用虚拟滚动 |
| 流式批量更新 | content_block.delta 事件使用 requestAnimationFrame 批量更新 |
| Markdown 增量渲染 | 只重新解析变化的文本段 |
| 图片懒加载 | 产物卡片缩略图懒加载 |
| 会话列表缓存 | 会话列表前端缓存，减少接口请求 |
| SSE 重连 | 网络断连后自动重连，携带 `Last-Event-ID` 和 `streamSessionId` 从断点恢复（最大 3 次，间隔 3 秒） |

### 10.3 离线处理

| 场景 | 处理方式 |
|------|---------|
| 发送消息时离线 | 提示网络不可用，消息暂存本地 |
| 流式输出中断连 | 自动重连，从中断点恢复 |
| 重连失败 | 提示用户检查网络，可手动重试 |

### 10.4 多端适配

本项目含 Android / Flutter / Taro / React Native / UniApp 等多端实现。各端参考本 Web 端（React）的组件结构、SSE 事件处理逻辑和状态管理方案，按各端技术栈适配实现，不另行编写独立前端实现文档。

> 定时调度配置（企业用户"每天 8 点处理监控截图"）为远期功能，交互入口随定时调度能力落地后补充。
