# AI 对话模块需求规格（能力扩展）

本功能域定义 AI 对话的能力来源体系，LLM 根据任务类型自动选择最合适的能力来源执行，覆盖系统能力调用、文件操作、搜索检索、代码执行、工作流指令、子智能体协作等场景。能力扩展让 AI 对话从"会聊天"走向"能干活"——但能力的可获得性必须以**可见、可控、可审计**为前提，让用户始终"看得到 AI 在做什么、管得住 AI 做什么"（对齐 Claude Code、ChatGPT 工具调用等主流 Agent 产品的交互范式）。

### 2.6 能力扩展 (F-M08-006)

#### 2.6.1 功能描述

AI 对话支持多种能力来源，LLM 根据任务类型自动选择最合适的能力来源执行。能力扩展体系覆盖系统能力调用、文件操作、搜索检索、代码执行、工作流指令、子智能体协作等场景。

#### 2.6.2 能力来源

| 能力来源 | 定位 | 适用场景 | 示例 |
|---------|------|---------|------|
| **系统工具（MCP）** | 调用系统后端 API | 需要访问系统能力 | 图像去雾处理、指标评估、算法推荐查询 |
| **虚拟文件系统** | Agent 内部读写临时文件 | Agent 推理过程中需要暂存中间产物 | 暂存中间分析结果、在 Agent 与子 Agent 间传递数据（规则见 §2.6.6） |
| **任务清单** | 维护结构化任务列表 | 长任务需要跟踪执行进度 | 多步骤任务的进度跟踪、子任务状态管理（规则见 §2.6.7） |
| **搜索工具** | 网络搜索、知识库检索、本地文件检索 | 需要获取实时信息或检索知识 | 搜索最新去雾算法论文、检索 AI 知识库、搜索本地文件（规则见 §2.6.8） |
| **代码执行** | 受限环境中执行代码和命令 | 需要数据计算、自动化处理 | 执行 Python 脚本分析指标分布、执行 Shell 命令（规则见 §2.6.9） |
| **Skills** | 工作流指令包（渐进式加载） | 有固定工作流程，需要按步骤执行 | 代码审查清单、去雾效果评估报告生成流程、算法选型决策树 |
| **子智能体** | 将专用子智能体作为能力调用，支持多智能体协作 | 复杂任务分解、专业能力协作 | 代码审查 Agent、数据分析 Agent、Agent 团队协作 |

> **Skills 渐进式加载**：会话启动时只加载 Skills 的名称和描述（开销极小），LLM 判断需要时才加载完整指令，避免无关指令占用上下文。Skills 可调用其他能力协同工作——Skill 定义"怎么做"，系统工具/代码执行提供"调什么"。
>
> **子智能体协作**：主 Agent 可将子任务委派给专用子智能体执行，子智能体拥有独立的系统提示词、工具集与模型配置。多个子智能体可组成 Agent 团队协作完成复杂任务，主 Agent 负责任务分解、结果汇总和最终回复。子智能体的完整产品规则（协作方式、并行执行、Team 团队）见 [需求规格-智能体管理](../智能体管理/需求规格.md) §2.11.4/2.11.5，本功能域不重复定义。

#### 2.6.3 能力选择

LLM 根据用户意图自动选择能力来源：

| 用户意图 | 能力来源 | 理由 |
|---------|---------|------|
| "帮这张图去雾" | 系统工具（MCP） | 需要调用图像处理 API |
| "帮我审查这段代码" | Skills | 有固定的代码审查清单流程 |
| "分析这批指标的统计分布" | 代码执行 | 需要执行 Python 脚本做数据分析 |
| "查一下最新的去雾算法论文" | 搜索工具（网络搜索） | 需要实时网络信息 |
| "把我上次生成的报告找出来" | 搜索工具（本地文件检索） | 需要检索本地文件 |
| "把分析结果保存成 CSV" | 文件操作 | 需要写入文件 |
| "让专门的代码审查 Agent 检查这个项目" | 子智能体 | 需要专业子智能体执行 |
| "按标准流程评估去雾效果并生成报告" | Skills + 系统工具 | Skill 定义评估流程，MCP 工具调用评估 API |

#### 2.6.4 能力选择失败降级

| 场景 | 处理方式 |
|------|---------|
| 工具调用失败 | 记录失败原因并反馈给 LLM，由 LLM 按多步推理的错误恢复策略处理（修正重试 / 换能力 / 跳过） |
| 所需能力未启用 | LLM 明确告知用户当前不可用，并给出替代建议 |
| 连续失败 | 达到重试上限后停止调用，LLM 向用户说明并征询下一步 |

#### 2.6.5 工具调用的可见性与可控性

工具调用是"AI 替用户干活"的核心环节，必须对用户"看得到、管得住、查得到"。工具调用过程以消息流中的折叠条目呈现（对齐 Claude Code 的工具执行展示、inference.sh tools-ui 的工具生命周期可视化）：

| 交互 | 说明 | 交互行为 |
|------|------|---------|
| 工具调用过程展示 | 工具调用的完整生命周期对用户可见 | 消息流中展示工具调用条目：工具名、参数摘要、执行状态、返回结果摘要；默认折叠，可展开查看详情 |
| 执行状态反馈 | 工具调用状态实时呈现 | 状态：待执行 → 执行中 → 成功 / 失败；执行中可展示进度或耗时，完成/失败后状态徽标更新 |
| 高风险操作确认 | 对影响范围大或不可逆的操作先征求用户确认 | 如批量删除、覆盖写文件、执行任意命令等；展示确认卡片（操作内容 + 影响范围），用户确认或修改后继续，也可拒绝（复用多步推理的中断确认机制） |
| 工具调用审计 | 工具调用记录可追溯 | 会话消息中保留工具调用记录（工具名、参数、结果、耗时），用户可随时回看"AI 刚才做了什么" |

**业务规则**：

| 规则 | 说明 |
|------|------|
| 默认折叠 | 工具调用默认折叠展示，不打断回复阅读；用户可展开查看 |
| 高风险操作判定 | 是否需确认由操作类型与权限配置共同决定；删除、覆盖写、执行任意命令等默认需确认 |
| 失败不阻塞 | 单次工具调用失败不阻塞整个推理，失败结果反馈给 LLM 由其决策重试/换工具/跳过 |

#### 2.6.6 虚拟文件系统

虚拟文件系统是 Agent 推理过程中的"工作区"，让 Agent 像人一样暂存、整理中间产物，但对用户始终安全、可控（对齐 Claude Code/Agent SDK 的文件系统工作区实践）：

| 维度 | 规则 |
|------|------|
| 定位 | Agent 推理过程中读写中间产物的工作区，不操作真实磁盘 |
| 生命周期 | 随会话结束清除，不持久化；推理中断恢复时保留工作区内容 |
| 可见性 | Agent 内部工作区，用户不直接访问；有价值的最终结果通过"产物卡片"机制持久化并展示（见 [需求规格-上下文管理](../上下文管理/需求规格.md) §2.3.7） |
| 容量限制 | 单会话工作区有容量上限，超出时提示 Agent 清理或压缩后再继续 |
| 文件类型 | 文本、代码、CSV、JSON、图片等常见格式 |
| 权限边界 | 读写范围受 Agent 配置的文件系统权限规则约束（只读/指定目录等，见 [需求规格-智能体管理](../智能体管理/需求规格.md) §2.11.2 权限配置） |

#### 2.6.7 任务清单

任务清单让长任务的执行过程"看得见"，提升用户对 Agent 的可控感与信任感（对齐 Claude Code Todo 工具的成熟实践）：

| 维度 | 规则 |
|------|------|
| 定位 | 维护结构化任务列表（待执行 / 执行中 / 已完成），帮助长任务保持正轨 |
| 展示 | 消息流中以带状态清单形式展示（☐ 待执行 / 进行中 / ☑ 已完成），用户随时可见当前进度 |
| 粒度 | 每个任务项用一句话描述，可在 1-3 分钟内完成；过细则管理开销大、过粗则失去追踪意义 |
| 完成标准 | 任务项描述包含明确的完成标准（如"验证结果已保存"而非"处理数据"） |
| 数量限制 | 单次任务列表不超过 32 项，超出时提示 Agent 合并或精简 |
| 更新时机 | Agent 每完成一个步骤即更新任务状态；已完成项保留在列表底部作为过程记录，供用户回溯 |
| 计费边界 | 任务清单是 Agent 的规划辅助能力，不单独计费，Token 消耗并入推理 |

#### 2.6.8 搜索工具

| 能力 | 说明 | 产品规则 |
|------|------|---------|
| 网络搜索 | 获取实时网络信息 | 结果展示标题 + 摘要 + 来源链接；单次返回条数受限（Top 5-10 条），避免输出泛滥 |
| 知识库检索 | 检索 AI 知识库（RAG） | 结果标注引用来源支持溯源；检索命中内容注入上下文参与回答 |
| 本地文件检索 | 检索 Agent 工作区文件 | 仅检索虚拟文件系统工作区与授权的文件范围，不越权访问 |

**产品规则**：

| 规则 | 说明 |
|------|------|
| 结果折叠展示 | 搜索结果默认折叠（标题 + 摘要），可展开查看完整条目，不打断回答阅读 |
| 引用溯源 | 回答中引用检索结果时标注来源（对齐主流产品"带引用回答"实践），用户可核查 |
| 搜索配额 | 网络搜索受频率/次数限制（防滥用）；用尽后提示用户，可降级为知识库检索 |
| 失败降级 | 网络搜索不可用时降级为知识库检索或明确告知不可用并给替代建议（见 §2.6.4） |

#### 2.6.9 代码执行

代码执行在受限安全环境中运行，满足数据计算与自动化处理需求，安全边界是产品红线（对齐 Claude Code 沙箱化 Bash、OpenSandbox 等安全沙箱实践）：

| 维度 | 规则 |
|------|------|
| 定位 | 在隔离的受限环境中执行代码和命令，与用户真实系统隔离 |
| 环境支持 | Python 脚本、Shell 命令等常见执行环境（技术选型见后端实现） |
| 超时与资源 | 单次执行有超时限制与资源上限（CPU/内存/进程数），防止失控执行与资源耗尽 |
| 安全约束 | 不允许访问真实磁盘与敏感网络；通过隔离环境 + 权限校验双重保障 |
| 结果展示 | 执行结果（标准输出/产物文件）返回给 LLM 汇总呈现；错误信息结构化返回，便于 LLM 修正后重试 |
| 确认机制 | 高风险命令（删除操作、写外部资源、任意命令）触发确认卡片，用户确认后才执行（见 §2.6.5） |
| 执行可见 | 代码执行过程与结果以工具调用条目展示，用户可查看执行的命令与产物 |

#### 2.6.10 能力访问与安全

能力扩展遵循最小权限、人工确认、凭据保护、监控审计的业界安全基线（对齐 MCP 生产环境最佳实践），与安全护栏（[需求规格-智能体管理](../智能体管理/需求规格.md) §2.11.10）构成"授权 + 拦截"双层防护：

| 维度 | 规则 |
|------|------|
| 最小权限 | 每个 Agent 仅能访问其配置关联的能力（MCP 命名空间、Skills、子智能体）；未关联的能力不可调用 |
| 文件权限 | 文件系统读写按 Agent 配置的权限规则执行（只读/指定目录等静态授权） |
| 凭据保护 | 工具调用涉及的用户凭据不暴露给 LLM；敏感字段（密钥、Token）不在工具参数、展示与日志中明文呈现 |
| 调用审计 | 所有工具调用记录（谁、何时、调用了什么、参数与结果、耗时）可查询，用于安全审计与问题排查 |
| 输出控制 | 限制工具返回的数据量，敏感信息（PII、密钥）不进入对话上下文与产物 |
| 连续失败保护 | 同一工具连续失败达到上限后停止调用，避免无效重试消耗资源（见 §2.6.4） |
| 工具返回校验 | 工具返回数据在进入推理上下文前做格式与完整性校验：按工具声明的返回 schema 校验结构、必填字段缺失/超大返回截断保护；校验失败以标准化错误反馈给 LLM（重试/换工具/跳过），与连续失败保护衔接（见 §2.6.4） |

#### 2.6.11 Skills 管理

Skills 是**遵循业界 Agent Skills 规范的可复用能力包**（对齐 Anthropic Agent Skills / agentskills 开放规范，Anthropic/Claude、OpenCode、Cline 等主流 Agent 产品均采用），不是简单的"Markdown 指令 + 脚本"。SKILL 的格式规范见 §2.6.11.1。

| 操作 | 说明 | 业务规则 |
|------|------|---------|
| Skills 列表 | 展示可用的 Skills，含名称、描述、适用场景 | 管理员可见全部；普通用户查询时仅返回启用的 Skills |
| Skill 加载 | LLM 自动判断需要时加载，用户也可手动指定"使用 xxx Skill" | 加载的 Skill 在本轮对话中生效，可跨轮持续使用 |
| Skill 执行过程展示 | Skill 按步骤执行时，步骤进度对用户可见 | 与工具调用展示一致（见 §2.6.5），执行中展示当前步骤与完成状态 |
| Skill 上传 | 管理员**以压缩包（zip/tar.gz）上传**遵循规范打包的 SKILL 目录 | 需管理员权限；上传后自动解析校验（见 §2.6.11.1），通过后入库，启用才可被使用 |
| Skill 创建 | 管理员可创建自定义 Skill（遵循规范的最小目录：SKILL.md） | 需管理员权限；与上传等效，创建后需启用才可被使用 |
| Skill 启停 | 管理员可启用/禁用 Skill | 禁用后 LLM 不再自动选择，进行中的对话不受影响 |
| Skill 删除 | 管理员删除 Skill | 软删除；删除前校验是否被 Agent 关联，有则提示先解绑 |

#### 2.6.11.1 SKILL 格式规范（对齐业界 Agent Skills 规范）

**一个 Skill 是一个目录**，至少包含 `SKILL.md` 文件：

```
skill-name/                  ← 目录名 = SKILL.name（命名规范见下）
├── SKILL.md                 ← 必需：YAML frontmatter + Markdown 指令正文
├── README.md                ← 可选：人类可读的说明文档
├── reference/               ← 可选：参考资料（REFERENCE.md、领域文档等，按需加载）
├── script/                  ← 可选：可执行脚本（Python/Bash/JS 等）
└── assets/                  ← 可选：静态资源（模板、图像、数据文件）
```

**SKILL.md 结构**：由 **YAML frontmatter（元数据）+ Markdown 正文（指令）** 两部分组成，frontmatter 字段定义：

| 字段 | 必需 | 约束 |
|------|------|------|
| `name` | ✅ | 最多 64 字符；仅小写字母、数字、连字符（`-`）；不能以连字符开头/结尾；不能含连续连字符（`--`）；**必须与目录名一致** |
| `description` | ✅ | 1–1024 字符；描述功能与使用时机，含有助于 Agent 识别任务的关键词 |
| `license` | ❌ | 许可证名称或引用捆绑的许可证文件 |
| `compatibility` | ❌ | 环境要求（目标产品、系统包、网络访问等），1–500 字符 |
| `metadata` | ❌ | 任意键值映射（版本、作者等） |
| `allowed-tools` | ❌ | 空格分隔的预批准工具列表（实验性） |

frontmatter 之后的 Markdown 正文为 Skill 指令，**无格式限制**；建议保持精简（<5000 tokens / 500 行以内），详细参考资料拆分到 `reference/` 文件，用相对路径引用（如 `[参考指南](reference/REFERENCE.md)`、`script/xxx.py`）。

**渐进披露（三级）**：元数据（`name`+`description`，启动即载，~100 tokens）→ 指令（SKILL.md 正文，激活时载）→ 资源（`reference/`/`script/`/`assets/` 文件，按需载）。`SKILL.md` 保持精简、将详细内容移入独立文件。

**上传校验**：上传压缩包后按上述规范自动校验——frontmatter 有效性、`name` 命名规范、`name` 与目录名一致、`description` 非空、危险操作拦截（脚本中的破坏性 shell 命令）、容量上限；校验失败返回具体原因。

#### 2.6.12 设计依据

本功能域的产品交互设计对齐业界主流 Agent 产品的能力扩展实践，做工程化取舍：

| 设计点 | 对标实践 |
|--------|---------|
| 渐进式披露（工具按需加载） | Claude Code 工具设计复盘：少而精而非多而全，按需暴露能力提升工具可发现性，避免上下文腐蚀 |
| 工具调用生命周期展示 | Claude Code 工具执行展示、inference.sh tools-ui：pending/running/success/error 状态可视化，让用户看到系统正在做什么 |
| 高风险操作人工确认 | MCP 生产最佳实践：human-in-the-loop 人工确认节点，删除/写操作/生产变更等高危动作先确认后执行 |
| 任务清单约束（粒度/上限/完成标准） | Claude Code Todo 工具：任务上限（32 项）、原子化步骤（1-3 分钟可完成）、描述即验收、已完成项保留作为审计轨迹 |
| 代码执行沙箱隔离 | Claude Code 沙箱化 Bash、OpenSandbox：隔离环境 + 超时 + 资源限制，安全运行 AI 生成代码 |
| 最小权限 + 凭据保护 + 审计 | MCP 生产最佳实践：最小权限授权、凭据不落明文、完整调用审计日志 |
| 引用溯源回答 | ChatGPT/Perplexity 带引用回答实践：回答引用来源可核查，提升可信度 |
| 工具设计随模型迭代 | Claude Code 复盘启示：工具是动态的，模型能力进化后及时审视、淘汰过时工具 |

#### 2.6.13 MCP Server 管理（外部接入中心）

MCP 管理面向管理员提供**外部 MCP Server 的通用接入与管理**（页面设计见 [需求规格.md](./需求规格.md) §3.3.3）。任何符合 MCP 规范的外部服务（GitHub、数据库、搜索、浏览器、自建服务等）均可接入平台，供 Agent 按需调用。区别于系统内部 MCP 能力网关（元工具，自动发现内部 API）——内部网关是"系统能力出口"，本小节是"外部能力进口"，两者都是 Agent 的工具来源，统一纳入命名空间授权。

| 能力 | 说明 | 业务规则 |
|------|------|---------|
| Server 注册 | 注册外部 MCP Server（名称/描述/传输协议/端点/鉴权方式） | 需管理权限 `ai:mcp:manage`；注册后自动拉取工具清单 |
| MCP 市场 | 内置常用 MCP Server 目录（名称/描述/能力标签），一键接入 | 预设目录由平台维护；展示已接入状态 |
| Server 启停 | 启用/禁用已接入 Server | 禁用后 Agent 不再调用其工具，进行中会话不受影响 |
| 工具与命名空间 | 查看 Server 工具清单，工具分组为命名空间供 Agent 关联 | 最小权限：Agent 仅可访问配置关联的命名空间 |
| 凭据管理 | 外部服务 API Key 配置 | 加密存储，不落明文、不暴露给 LLM、不在日志中呈现 |
| 调用审计 | 外部 MCP 工具调用记录（谁/何时/调用什么/结果/耗时） | 复用工具调用审计机制，纳入安全审计 |

**业务规则**：

- 外部 MCP Server 的工具与内部网关工具统一纳入命名空间预筛选（见 §2.6.10 与 [后端实现-能力扩展](后端实现.md)）
- Server 健康状态可探测，异常显著标注
- 删除 Server 前校验是否被 Agent 关联，有则提示先解绑

#### 2.6.14 SKILL 市场

在 §2.6.11 Skills 管理基础上，补充**市场分发能力**（页面设计见 [需求规格.md](./需求规格.md) §3.3.4）：

| 能力 | 说明 | 业务规则 |
|------|------|---------|
| SKILL 市场 | 预设/共享 Skill 目录（名称/描述/适用场景/步骤预览），一键启用 | 预设 Skill 由平台维护；展示启用状态与已关联 Agent 数 |
| 市场接入 | 管理员将自建 Skill 共享至市场 | 需管理权限 `ai:skill:manage` |
| 试用验证 | 市场内 Skill 支持输入测试数据试运行验证 | 验证效果后再启用，避免无效 Skill 上架 |

> 本功能域不重复定义子智能体协作、安全护栏、文件权限配置等能力，分别见 [需求规格-智能体管理](../智能体管理/需求规格.md)；工具调用的技术实现（执行器、MCP 命名空间预筛选、Skill 加载机制）见 [后端实现-能力扩展](后端实现.md)。
