# AI 对话模块 - 后端实现设计（第三方兼容）

## 1. 文档概述

本文档描述 F-M08-010 第三方兼容 API 的后端实现，提供与 OpenAI/Claude 官方 API 一致的接口，让第三方工具无缝接入 AI 对话能力。

> 与 [需求规格-定时与兼容 §2.12](需求规格.md) 同步：接入治理（§2.3，Key 级配额、模型白名单、调用审计）的 Key 生命周期（创建/列表/吊销/有效期/哈希存储）由认证管理模块落地（`sys_api_key` + `ApiKeyAuthMiddleware`），调用审计见 §2.3.1。

### 1.1 设计思想

#### 设计动机

本功能域承载的核心价值是：**提供与 OpenAI/Claude 官方 API 一致的接口，让第三方工具无缝接入**。大量现有工具链、脚本、SDK 已经围绕 OpenAI Chat Completions / Anthropic Messages 接口生态构建，若要求它们改接内部自定义 API，接入成本高、迁移阻力大。提供协议兼容层，即可让这些第三方工具以最小改动复用 AI 对话的会话、消息、推理与计费能力。

第三方接入的长期风险是**不可治理**：接入方无法追踪、滥用难约束、成本难对账。因此兼容层在"协议对齐"之外，还必须具备接入治理能力（§2.3）。

#### 核心设计原则

| 原则 | 说明 |
|------|------|
| 协议适配层映射到内部模型 | 兼容 API 不做独立推理链路，仅作为协议适配层（Adapter），复用内部 API 的会话、消息、推理与计费能力，协议转换不改变业务数据模型 |
| 同源复用 | 会话映射、消息模型转换、推理链路、计费均与内部 API 共用，保证行为一致、成本可控 |
| 能力边界收敛 | 仅暴露对话推理相关能力（chat/completions、messages、models），会话管理操作仍走内部 API |
| 接入可治理 | 第三方接入具备独立凭证、Key 级配额、模型白名单与调用审计，防滥用、可对账（详见 §2.3） |

#### 关键架构取舍

| 取舍点 | 方案对比 | 选择与理由 |
|--------|---------|-----------|
| 兼容层实现 | 独立推理链路 vs 协议适配层 | 选协议适配层。兼容 API 不做独立推理链路，仅作为 Adapter 复用内部 API 的会话、消息、推理与计费能力，保证行为一致、成本可控（详见 §2） |
| 会话映射 | 每次请求新建会话 vs `conversation_id` 复用 | 选复用。请求可传 `conversation_id` 复用已有会话，不传则自动创建，兼顾第三方无状态调用与有状态延续（详见 §2.1） |
| 错误码映射 | 透传平台错误码 vs 映射官方语义 | 选映射官方语义。429/403/402 对齐官方协议，便于 SDK 正确处理（详见 §2.1） |

#### 总体规划

```
第三方请求（OpenAI Chat Completions / Anthropic Messages 协议）
    ↓
CompatibleOpenAIController / CompatibleClaudeController（协议解析）
    ↓
CompatibleApiService（认证解析 → 会话映射 → 消息模型转换）
    ↓
MessageService（与内部 API 同一推理链路）
    ↓
内部 SSE 事件 → OpenAI/Claude SSE 事件格式转换
    ↓
流式 [DONE] / 非流式聚合 JSON 响应
```

## 2. 第三方兼容 API（F-M08-010）

**设计原则**：兼容 API 不做独立推理链路，仅作为协议适配层（Adapter），复用内部 API 的会话、消息、推理与计费能力。协议转换不改变业务数据模型。

```
CompatibleOpenAIController / CompatibleClaudeController
    ↓ 协议解析（OpenAI Chat Completions / Anthropic Messages 格式）
CompatibleApiService
    ↓ 认证解析（ApiKeyAuthMiddleware 将 dhak_ Key 解析为 userId）
    ↓ 会话映射：conversation_id 复用已有会话，否则按首条消息自动创建
    ↓ 消息模型转换 → 调用 MessageService（与内部 API 同一推理链路）
    ↓ 内部 SSE 事件 → OpenAI SSE / Claude SSE 事件格式转换
    ↓ 非流式时聚合事件为单次 JSON 响应（{id, object, choices, usage} / {id, type, content, usage}）
```

### 2.1 实现要点

| 实现要点 | 说明 |
|---------|------|
| 认证 | 双轨认证（OpenAI 端点 Bearer Token / Claude 端点 API Key 头），统一解析为 userId；`dhak_` Key 支持吊销与审计（认证管理模块实现，见 [API Key认证.md](../../../基础模块/认证管理/API%20Key认证.md)） |
| 会话映射 | 请求体 `conversation_id` 自定义扩展字段复用已有会话；不传则创建新会话并提取首条消息为标题 |
| 能力边界 | 不暴露 thought 事件；工具调用按 OpenAI `tool_calls` / Claude 原生格式透传；会话管理操作仅走内部 API |
| 计费 | 与内部 API 共用 BillingIntegration，按实际使用模型计量 |
| 模型选择 | 请求中可指定模型，须为启用状态且满足能力要求（如多模态），不满足返回 403；未指定时使用会话默认模型（对齐需求规格 §2.12.3） |
| 模型列表 | 复用 ModelService 查询启用模型并按调用用户 VIP 过滤（与内部 API 一致，含缓存），再叠加 Key 白名单过滤；models 端点同样纳入 Key 级配额/RPM 计数与审计。输出为 OpenAI / Claude 格式 |
| 协议细节 | 流式响应以 `[DONE]` 结束；usage 字段按实际 Token 计量返回（含缓存命中 Token）；`stream`/`temperature`/`max_tokens`/`tool_calls` 等标准参数按官方语义透传 |
| 错误码对齐 | 业务异常按类型映射为官方语义：429 `rate_limit_error`（Key 级配额超限/系统限流）、403 `permission_error`（模型不可用/模型白名单外）、402 `insufficient_quota`（用户积分配额不足，映射 `QUOTA_INSUFFICIENT`/`QUOTA_EXCEEDED`）；OpenAI/Claude 双协议统一错误响应体经 `_format_error` 格式化，便于 SDK 正确处理 |
| 安全 | 复用架构与公共文档 §6 认证授权、内容安全、Prompt 注入防护 |

### 2.2 端点映射

兼容端点与各协议认证头的完整定义属于 API 契约，见 [API接口.md §2.7/§2.8](../API接口.md)。服务端按协议分发：OpenAI 兼容请求走 Chat Completions 解析，Claude 兼容请求走 Messages 解析，模型列表统一复用内部模型查询。

### 2.3 接入治理

| 治理项 | 实现要点 |
|--------|---------|
| Key 生命周期 | 多 Key 支持（按项目/环境隔离，可命名）；Key 状态（启用/禁用）、有效期、吊销；Key 明文仅创建时展示一次，哈希存储 + 前缀展示（`dhak_xxx...`），由认证管理模块落地 |
| Key 级配额 | 每个 Key 可设置日/月调用额度与频率上限（RPM）；超限返回 429。`sys_api_key` 含 `daily_quota`/`monthly_quota`/`rpm_limit` 字段，计数走 Redis（`apikey:{key_id}:daily:{yyyyMMdd}`、`apikey:{key_id}:monthly:{yyyyMM}`、`apikey:{key_id}:rpm:{yyyyMMddHHmm}`，TTL 48h/35d/65s），与用户积分配额双轨控制 |
| 模型白名单 | Key 可绑定可用模型范围（默认继承用户可见模型）；`/v1/models` 按 Key 白名单动态返回；请求白名单外模型返回 403。白名单存储于 `sys_api_key.model_whitelist`（JSON） |
| 调用审计 | 记录每次调用：Key、模型、输入/输出 Token、积分消耗、状态码、耗时、来源 IP、request_id；API Key 脱敏后记录；调用日志可按 Key/模型/时间筛选，支撑对账与异常排查。**MongoDB 集合 `ai_api_call_log`**（见 §2.3.1） |

### 2.3.1 调用审计集合（MongoDB `ai_api_call_log`）

> 新增 MongoDB 集合。审计需记录**所有调用**（含 401/403/429 被拒绝、限流的调用），而 `sys_ai_billing` 仅记录成功计费的调用，无法承载审计；独立存储职责分离、保留策略独立（对齐 OneAPI/NewAPI 中转站独立 `logs` 表实践）。与既有 `login_log`/`audit_log` 同属审计日志库，遵循"只追加、无 JOIN、schema 可演化"原则。

| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | ObjectId | 主键 |
| `user_id` | int | 调用方用户 ID |
| `key_id` | int | 使用的 API Key ID（关联 `sys_api_key.id`） |
| `key_prefix` | string | Key 前缀（`dhak_xxx...`，脱敏展示用，不存完整 Key） |
| `conversation_id` | int | 会话 ID（复用已有会话时记录） |
| `model` | string | 请求模型 |
| `endpoint` | string | 端点（`chat/completions`、`messages`、`models`） |
| `protocol` | string | 协议（`openai`/`claude`） |
| `is_stream` | bool | 是否流式 |
| `input_tokens` | int | 输入 Token 数 |
| `output_tokens` | int | 输出 Token 数 |
| `credits` | float | 积分消耗（成功计费时记录；积分为浮点计费） |
| `status_code` | int | 返回状态码（200/401/403/429/402/5xx） |
| `duration_ms` | int | 调用耗时 |
| `client_ip` | string | 来源 IP |
| `request_id` | string | 请求 ID（串联日志与计费记录） |
| `error_msg` | string | 失败原因（非 2xx 时记录） |
| `create_time` | datetime | 调用时间 |

- 只追加不更新，TTL 索引按 `create_time` 30 天自动过期（无需定时清理任务）
- 索引：`(key_id, create_time)`、`(user_id, create_time)`、`(model, create_time)` 支撑按 Key/用户/模型筛选对账
- 写入时机：兼容 API 请求入口统一记录（含被拒绝的调用），成功计费时回填 `credits`；异步写入，失败不影响主流程（与 `audit_log` 一致）
- 集合定义与三端实现对齐 [日志架构设计 §5.5](../../../../02-系统架构/07-日志架构设计.md)

**错误码映射**（与需求规格 §2.12.3 对齐）：

| 场景 | 平台错误 | 兼容 API 返回 |
|------|---------|--------------|
| Key 级配额超限 / 限流 | 429 语义 | `429 rate_limit_error` |
| 模型白名单外 / 模型不可用 | A0601 | `403 permission_error` |
| 用户配额不足 | A0503 | `402 insufficient_quota`（按官方语义近似） |

### 2.4 权限范围

兼容 API 的对话能力边界与内部 API 保持一致，不额外开放管理类能力（对齐需求规格 §2.12.5）：

| 能力 | 兼容 API 是否暴露 |
|------|-----------------|
| 对话推理（chat/completions、messages） | 暴露 |
| 模型列表（/v1/models） | 暴露（按用户/Key 权限过滤） |
| 会话管理（列表/删除/归档） | ❌ 不暴露，通过内部 API 完成 |
| 智能体/模型/供应商管理 | ❌ 不暴露，仅管理员内部 API |
| 定时任务管理 | ❌ 不暴露，通过内部 API 完成 |

## 3. 模块间协作

| 协作方 | 说明 |
|--------|------|
| MessageService | 协议适配后复用与内部 API 同一推理链路 |
| ModelService | 查询启用模型，输出为 OpenAI / Claude 格式 |
| BillingIntegration | 与内部 API 共用计费，按实际使用模型计量 |
| 认证管理 | `dhak_` API Key 认证（`ApiKeyAuthMiddleware`）；Key 级配额/白名单落地需认证管理模块协同扩展 `sys_api_key` |

**已知限制**：流式响应中途发生用户配额不足（内部 quota 中断）不改变已开始的 HTTP 200 流，402 语义仅在前置校验/非流式路径体现；SDK 侧表现为流正常结束（对齐官方协议流式语义）。
