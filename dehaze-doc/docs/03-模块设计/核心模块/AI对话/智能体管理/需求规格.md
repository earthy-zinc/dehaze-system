# AI 对话模块需求规格（智能体管理）

本功能域承载平台级智能体（Agent）的管理能力，通过数据库驱动的可配置智能体体系（系统提示词、模型、推理参数、Skills、MCP、子 Agent 等），支撑复杂任务的分解与多智能体协作。

### 2.11 智能体管理 (F-M08-011)

#### 2.11.1 功能描述

平台支持智能体（Agent）的全生命周期管理：从创建、配置、版本管理、评测，到发布与安全运行。每个 Agent 拥有独立的系统提示词、模型配置、推理参数、Skills、MCP 命名空间、子 Agent 和安全护栏。Agent 配置由管理员在前端管理界面动态配置，存储于数据库，不硬编码在环境变量中。会话创建时可选择 Agent，不同 Agent 之间可组成子 Agent 调用关系和 Team 团队协作关系，支撑复杂任务的分解与多智能体协作；同时支持通过 A2A 协议对外暴露 Agent 或调用外部 Agent，实现跨进程/跨系统的 Agent 互操作（见 §2.11.13）。

#### 2.11.2 Agent 配置项

| 配置维度 | 说明 | 示例 |
|---------|------|------|
| 基本信息 | Agent 名称、唯一编码、描述、分类标签 | 名称"图像分析专家"、编码 `image-analyst` |
| 系统提示词 | Agent 的指令（System Prompt），Markdown 格式，可从平台提示词模板库选择或自定义（模板库见 [上下文管理 §2.3.3](../上下文管理/需求规格.md)） | "你是一个图像去雾效果分析专家..." |
| 模型配置 | 使用的 LLM 模型 | `gpt-4o` |
| 推理范式 | 自动 / 直接回复 / ReAct / Plan-and-Execute / Reflexion | `auto`（由复杂度评估自动选择） |
| 推理参数 | 最大步数、Token 预算、并行度、工具超时、重试次数、Reflexion 阈值、温度等 | max_steps=20, token_budget=500000 |
| Skills 关联 | 该 Agent 可加载的 Skills 清单 | 代码审查 Skill、报告生成 Skill |
| MCP 命名空间 | 该 Agent 可访问的 MCP 工具分组 | image_processing、evaluation |
| 子 Agent 关联 | 该 Agent 可调用的子 Agent（触发描述复用子 Agent 自身的描述字段） | "数据分析 Agent"——处理数据相关子任务 |
| Agent 类型 | 普通 Agent / 可作为子 Agent / Team 团队 | 可作为子 Agent |
| 权限配置 | 文件系统读写权限规则 | 只读 `/workspace/**` |
| 安全护栏 | 输入/输出护栏规则（Prompt 注入防护、敏感信息脱敏、输出合规校验） | 启用 PII 脱敏、拦截越权查询 |
| 对外暴露 | 是否对外暴露为 A2A 子 Agent（默认不暴露） | `is_exposed=true` |

**推理参数继承机制**：

配置按三级优先级合并，低优先级提供默认值，高优先级覆盖：

```
系统默认（全局可调）
  ← Agent 配置（为空表示继承默认）
    ← 会话级覆盖（用户运行时调整）
```

#### 2.11.3 Agent 类型

| 类型 | 定位 | 示例 |
|------|------|------|
| 普通 Agent | 可被会话直接选择使用 | 平台默认 Agent、图像分析 Agent |
| 子 Agent | 可被其他 Agent 通过委派方式调用，不可被会话直接选择 | 代码审查 Agent、数据分析 Agent |
| Team 团队 | 编排多个 Agent 协作，作为会话入口时由 Team Lead 负责任务分解和汇总 | "去雾效果评估团队"（含分析+报告+审查三个成员） |

#### 2.11.4 子 Agent 协作

主 Agent 可将子任务委派给子 Agent 执行：

- 子 Agent 拥有**独立的上下文窗口**，中间工具调用不污染主 Agent 上下文，仅返回最终结果摘要
- 子 Agent 使用自己的系统提示词、工具集、模型配置（不继承父 Agent）
- 子 Agent **不能再委派子任务**（防递归）
- 同一主 Agent 可关联多个子 Agent，关联关系含优先级

**并行执行**：Plan-and-Execute 范式下，独立的子任务可并行调度多个子 Agent，受并行度参数限制。配额不足时按滚动预算校验策略召回未启动的子 Agent。

#### 2.11.4.1 多 Agent 协作治理

多 Agent（子 Agent 委派、Team 团队）协作中容易出现**沟通冗余、冲突、重复工作与上下文浪费**，通过以下机制治理：

| 机制 | 说明 |
|------|------|
| 委派去重 | 同一子任务（按任务描述 + 参数指纹）不重复委派；命中已执行结果直接复用，避免重复工作 |
| 结果精简 | 子 Agent 只返回结果摘要（§2.11.4 已有）；大结果走产物引用化，不占主 Agent 上下文（防上下文浪费） |
| 冲突消解 | 并行子 Agent/成员对同一资源写入时按优先级仲裁（低优先级让行、同优先级失败重试）；写冲突向用户展示回滚提示 |
| 职责边界 | Team 成员按角色分工（Leader 分解、成员专精），成员间职责不重叠，防止重复处理同一子任务 |
| 冗余巡检 | 重复委派/无用委派在可观测性中标注（消费 F-M08-013），供协作效率评估与优化 |

#### 2.11.5 Team 团队协作

Team 团队用于复杂的多 Agent 协作场景：

| 角色 | 职责 | 示例 |
|------|------|------|
| Team Lead（主 Agent） | 任务分解、结果汇总、最终回复 | "协调数据分析与报告生成" |
| Team Member（成员 Agent） | 专注特定领域子任务 | 数据分析 Agent、报告生成 Agent、质量审查 Agent |

- Team 通过子 Agent 关联关系定义成员关系，Team Lead 的子 Agent 即为团队成员
- Team 成员**异步并行执行**，通过消息传递通信
- Team 成员的消耗归集到主会话配额，计费明细按成员维度分项展示

#### 2.11.6 复杂任务辅助能力

基于推理引擎内置能力，Agent 可使用以下复杂任务辅助能力：

| 能力 | 功能 |
|------|------|
| 任务清单 | 维护结构化任务列表（待执行/执行中/已完成），帮助长任务保持正轨 |
| 虚拟文件系统 | Agent 内部读写中间产物，会话结束即清除，不操作真实磁盘 |
| 子任务委派 | 调用子 Agent 执行隔离子任务，返回结果摘要 |

**临时文件与持久化产物的区别**：

| 维度 | 推理临时文件 | 用户可见产物 |
|------|------------|-------------|
| 用途 | Agent 推理过程中的临时文件 | 持久化用户可见的产物（图像结果、指标报告）|
| 生命周期 | 随会话结束清除 | 跨会话永久保留 |
| 可见性 | Agent 内部 | 用户可见（产物卡片）|

#### 2.11.7 Agent 管理操作

| 操作 | 说明 | 业务规则 |
|------|------|---------|
| Agent 列表 | 展示所有 Agent，含类型标签、状态、关联信息 | 管理员可见全部；普通用户查询时返回启用且非子 Agent 的可选项 |
| 创建 Agent | 配置基本信息、系统提示词、模型、推理参数、Skills、MCP、子 Agent | 需管理员权限；Agent 编码唯一且不可复用 |
| 更新 Agent | 修改任意配置项 | 更新后新会话生效，进行中的会话沿用旧配置 |
| 删除 Agent | 软删除 | 校验是否有会话引用或被其他 Agent 作为子 Agent 引用；有则提示先解绑 |
| 启停 Agent | 启用/禁用 Agent | 禁用后不可被选择；进行中的会话不受影响 |
| 复制 Agent | 基于现有 Agent 复制创建新 Agent | 复制基本信息和配置，不复制关联关系；编码需重新指定 |
| 发布 Agent | 将当前草稿配置发布为正式版本 | 发布前须通过评测集回归（见 [Agent评测](../Agent评测/需求规格.md) F-M08-014）；发布后新会话生效 |
| 版本回滚 | 回滚到任一历史发布版本 | 生成新版本号，保留完整历史；回滚后新会话生效（见 §2.11.8） |
| 测试 Agent | 输入测试消息，即时预览 Agent 响应（不入库不推送） | 仅管理员可用；消耗配额；用于快速调试；发布门禁依赖评测集回归（见 [Agent评测](../Agent评测/需求规格.md) F-M08-014） |

#### 2.11.8 版本管理与发布

Agent 配置变更采用版本化快照管理，支持草稿编辑、发布与回滚，保证配置可追溯、可回退、可复现。

**版本模型**：

| 概念 | 说明 |
|------|------|
| 版本快照 | 每次保存生成不可变快照，涵盖系统提示词、模型、推理参数、Skills/MCP/子 Agent 关联、安全护栏 |
| 版本号 | 自增，记录变更人、变更时间、变更说明 |
| 草稿 | 正在编辑、未对外生效的配置，可反复修改 |
| 已发布 | 对外生效的正式版本，新会话使用最新已发布版本 |

**发布与回滚**：

| 操作 | 规则 |
|------|------|
| 发布 | 草稿通过评测集回归后发布为正式版本（回归门禁见 [Agent评测](../Agent评测/需求规格.md) F-M08-014） |
| 回滚 | 任一历史版本可一键回滚为新发布版本，生成新版本号，完整历史不覆盖 |
| 生效范围 | 发布/回滚仅影响新会话；进行中会话锚定创建时的版本快照，行为一致且可复现 |

#### 2.11.9 评测与发布门禁

评测集/样本管理、评分体系、评测报告与持续评估由独立功能域 **Agent 评测（F-M08-014）** 承载，详见 [Agent评测/需求规格.md](../Agent评测/需求规格.md)。本功能域保留两个协作点：

| 协作点 | 说明 |
|--------|------|
| 发布门禁 | 发布前须跑通回归集；评分下降或高风险样本失败时阻断发布并提示差异点 |
| 即时调试 | 保留"测试 Agent"即时预览（单条消息、不入库不推送），用于快速定位问题；评测集回归承担发布门禁职责 |

#### 2.11.10 安全护栏

安全护栏（Guardrail）在运行时实时拦截异常输入与不合规输出，与文件系统权限（静态授权）互补，构成"授权 + 拦截"双层防护。

**输入护栏**（推理前拦截）：

| 类型 | 说明 |
|------|------|
| Prompt 注入防护 | 拦截用户输入中试图篡改系统提示词或越权指令的内容 |
| 越权查询检测 | 阻止 Agent 访问用户无权访问的数据或 MCP 命名空间 |
| 敏感话题过滤 | 按业务场景屏蔽无关或不当请求 |

**输出护栏**（返回用户前拦截）：

| 类型 | 说明 |
|------|------|
| 敏感信息脱敏 | 检测并脱敏身份证号、手机号、密钥等 PII 与凭据 |
| 事实性校验 | 对关键事实（价格、指标数值）做规则校验，拦截明显错误 |
| 格式合规 | 确保输出符合下游系统与产物卡片的格式要求 |

**护栏与权限的关系**：

| 维度 | 文件系统权限 | 安全护栏 |
|------|------------|---------|
| 对象 | Agent 对文件/工具的访问范围 | 输入内容与输出内容 |
| 时机 | 调用前静态授权 | 运行时实时拦截 |
| 目标 | 防止越权操作 | 防止注入、泄露、违规输出 |

**护栏策略**：护栏规则在 Agent 配置中启用/关闭，支持系统默认 + Agent 级覆盖（复用三级配置合并）；误拦率需可监控，避免过度拦截影响正常使用。

#### 2.11.11 会话级 Agent 选择

- 创建会话时可指定 Agent，未指定时使用平台默认 Agent
- 会话内切换 Agent 后，下一条消息使用新 Agent，历史消息保持原 Agent 记录
- 子 Agent 不可被会话直接选择
- Team 团队可作为会话入口，会话的推理由 Team Lead 编排

#### 2.11.12 内置默认 Agent

系统预置一个默认 Agent，作为未指定 Agent 时的兜底：

- 系统提示词：通用助手指令
- 模型：平台默认模型
- 推理范式：自动
- 推理参数：继承系统默认
- Skills：全部启用的 Skills
- MCP：全部命名空间
- 子 Agent：无
- 安全护栏：继承系统默认
- 不可删除，可修改

#### 2.11.13 A2A 协议（跨 Agent 互操作）

子 Agent 协作（§2.11.4）解决平台**内部** Agent 之间的协作；当 Agent 需要与**外部系统 / 厂商的 Agent** 互操作时，采用业界标准的 Agent2Agent（A2A）协议，与 MCP 互补——MCP 连接 Agent 与工具/上下文，A2A 连接 Agent 与 Agent。

**平台角色**：

| 角色 | 场景 | 能力 |
|------|------|------|
| A2A 服务端 | 平台 Agent 对外暴露，供外部 Agent 调用 | 提供 A2A 协议端点，返回 Agent 能力声明（Agent Card） |
| A2A 客户端 | 平台 Agent 调用外部 Agent 作为子 Agent | 注册外部端点，子 Agent 命中远程时走 A2A 调用 |

**暴露控制**：

- Agent 通过"对外暴露"开关（`is_exposed`）控制是否可作为 A2A 子 Agent 对外服务，默认不暴露（安全默认值）
- 仅启用且非子 Agent 类型的普通 Agent 可暴露，子 Agent 不可独立暴露

**外部端点注册**：

- 管理员注册外部 A2A Agent（端点地址、认证凭证），系统拉取并缓存其 Agent Card 作为发现依据
- 子 Agent 关联支持指向外部端点：本地子 Agent 走进程内调用，远程子 Agent 走 A2A 协议调用；远程子 Agent 须在本地 `sys_ai_agent` 建立影子记录（`is_subagent=1`，承载名称/描述等展示信息），关联表 `subagent_agent_id` 指向影子记录、`endpoint_id` 指向外部端点

**安全与计费**：

- 外部调用平台 Agent 时须通过 API Key 鉴权，且不旁路安全护栏、评测与计费
- 平台调用外部 Agent 的 Token 消耗不计入平台会话配额（外部账单），仅记录调用状态与耗时
