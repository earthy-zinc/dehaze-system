# AI 对话模块需求规格（消息反馈）

> 功能域定位：本功能域（F-M08-008）承载用户对 AI 助手回复的质量反馈能力——通过点赞/点踩及其标签信息，为平台质量分析与效果度量提供数据支撑，帮助持续优化 LLM 提示词和工具调用策略。

## 2.9 消息反馈 (F-M08-008)

### 2.9.1 功能描述

用户可对助手的回复进行点赞或点踩反馈，用于质量分析和效果度量。反馈帮助平台持续优化 LLM 提示词和工具调用策略。

反馈采用"轻反馈 + 重反馈"分层设计，兼顾反馈率与数据质量：

| 层级 | 交互 | 数据价值 |
|------|------|---------|
| **轻反馈** | 点赞/点踩（一键完成） | 满意度信号，点赞率作为成功度量指标（见主文档 §7.2）|
| **重反馈** | 点踩后选择原因标签 + 可选文字说明 | 问题归因，驱动提示词/工具策略优化 |

设计依据：参考 ChatGPT、Claude、Gemini 等主流 AI 产品的反馈交互——点赞/点踩为最轻量入口，点踩后引导选择原因标签（3~6 个），文字说明可选，避免强制填写劝退用户。

### 2.9.2 反馈交互

反馈交互遵循"渐进式"设计：先一键反馈，再按需补充细节，每一步成本递增但用户可随时停止，不打断正常使用流程。

| 交互 | 说明 |
|------|------|
| 点赞 | 一键完成，可附选预设标签（准确、详细、简洁、有创意）|
| 点踩 | 必须选择问题标签（6 类，见 §2.9.3），文字说明可选 |
| 撤销 | 撤销已提交的反馈 |
| 修改 | 修改反馈类型（点赞改点踩或反之）|

> 点踩不强制填写文字说明：用户愿意点踩已很宝贵，强制填写会显著降低反馈率。文字说明作为可选补充，用于沉淀更细粒度的优化素材。

### 2.9.3 反馈标签体系

**点赞标签**（可多选）：

| key | 中文 | 说明 |
|-----|------|------|
| accurate | 准确 | 回答内容正确 |
| detailed | 详细 | 信息充分、覆盖全面 |
| concise | 简洁 | 言简意赅 |
| creative | 有创意 | 思路新颖 |

**点踩标签**（必选其一，贴近问题归因，便于针对性优化）：

| key | 中文 | 说明 | 优化方向 |
|-----|------|------|---------|
| incorrect | 错误 | 内容有误、与事实不符 | 知识库/RAG 检索优化 |
| irrelevant | 答非所问 | 未回答用户问题 | 意图理解/提示词优化 |
| incomplete | 不完整 | 回答不全面、缺关键信息 | 提示词补充约束 |
| too_long | 太长/啰嗦 | 内容冗长 | 提示词精简输出 |
| bad_citation | 引用错误 | 引用来源不可靠或与答案不符 | 引用链路校验 |
| harmful | 有害/不安全 | 内容有害或存在安全风险 | 安全过滤 |

> 标签选项控制在 6 个以内，避免选项过多导致用户放弃反馈。

### 2.9.4 业务规则

| 规则 | 说明 |
|------|------|
| 反馈对象 | 仅助手的回复消息可反馈，用户消息和工具消息不可反馈 |
| 唯一性 | 同一用户对同一消息只能有一条反馈记录 |
| 反馈时效 | 消息发送后 30 天内可反馈 |
| 反馈可见性 | 用户可查看自己已提交的反馈状态（点赞/点踩及标签）|
| 数据完整性 | 反馈需携带 traceId 及上下文快照，支持问题归因（见 §2.9.5）|
| 隐私脱敏 | 反馈中的敏感信息（手机号、身份证等）需脱敏后存储与分析 |

### 2.9.5 反馈数据完整性

点赞/点踩只是反馈入口，不是反馈闭环。仅记录"点赞/点踩"无法定位问题出在哪个环节（意图理解、检索、生成、引用、文档）。反馈数据需携带以下上下文，支持归因分析：

| 字段 | 说明 |
|------|------|
| traceId | 串联前端反馈、后端日志、模型调用与检索记录，实现全链路归因 |
| question | 用户原始问题快照，复盘真实问法 |
| answer | 系统当时的回复快照，复盘回答内容 |
| citations | 引用来源清单（来源 ID、标题、引用片段），判断引用是否支撑答案 |
| retrieval | 检索结果（命中片段、相关性得分），判断问题出在召回、排序还是生成 |
| reason | 用户选择的原因标签 + 可选文字说明 |

> 反馈归因到具体环节（检索/生成/引用/文档），避免"点踩多就归因于模型"的误判——很多问题实际出在文档缺失、检索未召回或引用错误。

### 2.9.6 隐性反馈信号

显性反馈（点赞/点踩）存在样本偏差：多数不满用户不会主动点踩，而是直接离开或转人工。需结合隐性行为信号补充质量判断：

| 信号 | 含义 |
|------|------|
| 复制回答 | 用户采纳回答内容，正向信号 |
| 继续追问 | 用户基于回答继续深入，正向信号 |
| 重新生成 | 用户对回答不满意，负向信号（重新生成交互见 F-M08-001）|
| 转人工/离开 | 用户放弃 AI 回答，负向信号 |

> 隐性信号不直接展示给用户，仅作为质量分析的补充维度，与显性反馈交叉验证。

### 2.9.7 反馈驱动优化闭环

反馈数据用于平台侧的持续优化，不面向用户展示具体分析结果：

| 环节 | 说明 |
|------|------|
| 质量分析 | 按消息、会话、模型、功能域等维度统计点赞率、点踩率及问题标签分布，定位质量短板 |
| 效果度量 | 点赞率作为模块成功度量指标（见主文档 §7.2 用户满意度）|
| 优化输入 | 点踩标签与改进建议沉淀为优化素材，用于调整提示词、工具调用策略与回复风格 |
| 记忆联动 | 点踩附带的偏好类改进建议（如"太冗长"）进入长期记忆（见 F-M08-003 反馈提取）|
| 评测集回流 | 高价值差评（高频、关键业务、可确认根因）转成回归用例，加入评测集，防止问题复发 |
| 闭环时效 | 紧急错误（有害内容、事实错误）24 小时内处理，普通问题 3 天内处理，避免反馈闭环过慢 |
| 改进可见性 | 用户反馈带来的改进在后续对话中可感知（如回复更简洁），形成"反馈→改进→更多反馈"的良性循环 |

**衡量口径**（避免统计失真）：

| 指标 | 定义 |
|------|------|
| 反馈覆盖率 | 有反馈的会话 / 总会话数，衡量反馈入口的触达 |
| 反馈采纳率 | 被采纳的反馈 / 总反馈数，衡量反馈的实际价值 |
| 闭环时效 | 从反馈产生到策略/提示词更新的平均时间 |
| 点赞率 | 点赞 / (点赞 + 点踩)，作为满意度指标（见主文档 §7.2）|

> 统计时注意规避失真：样本偏差（仅极端用户反馈）、交互诱导（按钮位置/默认状态）、重复反馈（同一用户多次操作）、口径不一致（分母是曝光还是有效回答）。
