# AI 对话模块测试用例

## 1. 测试目标

- 验证通用对话与会话管理（F-M08-001）：会话生命周期、流式输出、多轮上下文、消息交互
- 验证多步推理（F-M08-002）：复杂度感知、ReAct/Plan-and-Execute/Reflexion 范式、中断恢复
- 验证上下文与记忆管理（F-M08-003）：分层记忆、长期记忆检索注入、中间产物引用化
- 验证智能算法推荐（F-M08-004）、批量处理摘要（F-M08-005）、能力扩展（F-M08-006，含 MCP Server 管理与 SKILL 市场）
- 验证会话内模型选择（F-M08-007，模型管理用例见 [AI模型管理模块](../../基础模块/AI模型管理/测试用例.md)）、消息反馈（F-M08-008）、定时调度（F-M08-009）
- 验证管理端会话审计（F-M08-001 管理员视角）：全量会话/消息查看、AI 链路追踪、权限隔离
- 验证智能体管理（F-M08-011）：Agent 配置 / 子 Agent 协作 / Team 团队 / 版本发布 / 评测 / 安全护栏 / A2A 协议（详见 `测试用例-智能体管理.md`）
- 覆盖正常流程、边界条件、异常场景、权限控制
- 验证 AI 能力链路跨模块集成（对话 -> 计费/MCP/知识库）

## 2. 测试前置

### 2.1 测试数据

| 数据类型 | 准备内容 | 说明 |
|---------|---------|------|
| **测试用户** | 普通/VIP1/VIP2/SVIP 用户各 1 个，前缀 `test_ac_` | 验证会员等级差异（配额、模型范围、视觉读取限额） |
| **测试会话** | 含多轮历史的活跃会话 | 验证上下文记忆与摘要 |
| **Mock LLM** | 模拟流式 token 输出、tool_calls、推理过程 | 验证 SSE 事件与推理编排 |
| **Mock 工具** | predict_dehaze/evaluate_image/kb_search | 验证能力扩展调度 |
| **多模态文件** | 图片/PDF/音视频样本 | 验证多模态输入 |

### 2.2 数据清理策略

- 测试会话与消息前缀 `test_ac_`，结束后软删除并清理推理状态与中断点
- 测试产生的长期记忆打标 `source=test`，不参与线上检索，测试后软删除
- 配额消耗由测试用户承担，不回退（由定时任务处理）

### 2.3 测试范围

**包含：**
- 会话管理、消息交互、流式输出、推理编排、上下文记忆、模型选择、反馈、定时调度
- OpenAI/Claude 兼容 API 对话补全
- AI 能力链路跨模块集成（计费预扣实扣、MCP 工具调用、知识库 RAG）

**不包含：**
- LLM 模型本身的质量评估（属模型评测）
- MCP 网关内部协议转换（属 MCP 能力网关模块测试）
- AI 计费配额扣减的原子性实现（属 AI 计费管理模块测试）
- 语音 ASR/TTS 算法（属语音交互模块测试）

## 4. 关键边界与异常

| 场景 | 测试点 | 期望行为 |
|------|--------|---------|
| **消息长度边界** | 输入恰好 4000 字符 | 正常发送 |
| **断线重连窗口** | 中断后 5 分 01 秒重连 | 超出窗口，消息标记已取消，支持重新生成 |
| **推理步数边界** | ReAct 第 20 步（上限） | 正常执行；第 21 步终止 |
| **并行度限制** | 8 个独立子任务 | 最多 5 个并行，其余排队 |
| **Token 预算超限** | 单会话累计 Token 超限 | 推理中止，已生成部分以摘要返回 |
| **工具超时** | 单工具调用超阈值 | 自动失败，触发错误恢复策略 |
| **工具白名单** | LLM 尝试调用未注册工具 | 拒绝执行，LLM 改用已注册工具 |
| **沙箱隔离** | 代码执行访问路径白名单外 | 拒绝访问，限制在沙箱内 |
| **多模态视觉读取限额** | 当日视觉读取次数用尽（用户全局日计数） | 切换为结构化摘要文本描述模式，提示升级 VIP |
| **定时任务上限** | 单用户创建第 21 个定时任务 | 拒绝创建，提示上限 20 个 |
| **兼容 API 会话管理** | OpenAI 兼容 API 不传 conversation_id | 自动创建新会话，标题从首条消息提取 |

## 6. 安全性测试

| 测试项 | 验证方式 | 预期结果 |
|--------|---------|---------|
| **会话归属隔离** | 用户 B 访问用户 A 的会话/消息 | 返回 A0401（不暴露资源存在性） |

## 8. 自动化覆盖统计

> 本轮同步后（1056 个集成测试全量通过），覆盖分三层：
> 1. **Python 服务层单测**（`dehaze-python`，`uv run pytest`，mock Redis/SQLite 可离线跑）：覆盖会话生命周期、SSE 全序列、幂等、分支树、推理范式/中断/恢复、上下文/记忆、模型路由/降级、供应商健康、定时调度、评测/门禁、护栏、A2A 协议。
> 2. **Python 路由层单测**（`tests/router/`）：定时调度 `run` 异步受理、评测/审计端点返回结构。
> 3. **SDK 集成测试**（`dehaze-sdk-js`，`npx vitest run test/modules/ai-conversation/`，需后端 + 登录环境）：`ai-conversation`/`ai-model`/`ai-provider`/`ai-agent`/`ai-schedule` 5 个文件 200+ 用例，逐一映射至 T-CV/T-CT/T-MF/T-SC 用例（详见各分册 §SDK 集成覆盖映射）。

**契约修正汇总（本轮文档-实现偏差）**：
- 跨用户访问他人资源统一返回 `A0401`（不暴露存在性），不再使用 `A0403`；管理端接口越权返回 `A0301`（访问未授权）。
- 长期记忆路径统一 `/api/v1/ai/memories`（原 `/users/me/memories`）；产物详情路径 `/artifacts/{id}/detail`。
- 评测/样本/执行路径统一 `/agents/{id}/eval/datasets|samples|runs`（非平铺 `eval-datasets`/`eval-runs`）；更新用 PATCH。
- `message.start` 不再返回 `streamSessionId`；恢复中断走独立 `POST /messages/{id}/resume`。
- 中断类型新增 `plan_approve`；`ThoughtEvent.status` 数值化；`StopReason` 含 `error`。
