# AI 对话模块需求规格（智能调度）

## 功能域概述

智能调度是 AI 对话模块的"专业能力落地层"：将用户模糊的自然语言需求转化为确定性的专业操作。本功能域承载两大能力——**智能算法推荐**（LLM 理解意图并推荐最匹配的算法，让不熟悉算法的用户也能用对算法）与**批量处理摘要**（将统一需求批量调度到多张图片并生成结果摘要，让批量用户高效完成规模化处理）。

核心设计原则是"LLM 负责决策与编排，专业引擎负责执行"：算法匹配、排序、打分由独立的算法选择模块承载，AI 对话只做意图理解、推荐理由解释与调度编排，不重复实现专业逻辑。

### 2.4 智能算法推荐 (F-M08-004)

#### 2.4.1 功能描述

用户用自然语言描述处理需求，LLM 理解用户意图并生成推荐理由，算法的匹配、排序、打分逻辑由独立的"算法选择"模块统一承载，AI 对话通过能力扩展体系调用算法选择模块获取推荐结果。

#### 2.4.2 职责边界

| 关注点 | 归属 | 说明 |
|--------|------|------|
| 用户意图理解 | AI 对话 | 解析自然语言需求，提取任务类型、约束条件、偏好 |
| 图像特征分析 | 算法选择模块 | 图像特征提取与归类，由算法选择模块封装 |
| 算法匹配/排序/打分 | 算法选择模块 | 基于特征与规则的算法推荐核心逻辑，对话侧不重复实现 |
| 推荐理由生成 | AI 对话 | 将算法选择模块的推荐结果转化为自然语言解释 |
| 用户确认与参数调整 | AI 对话 | 展示推荐、接收用户修改、发起处理 |

> AI 对话侧不维护算法知识库与匹配规则，避免与算法选择模块重复建设。

#### 2.4.3 推荐流程

1. 用户描述需求（如"帮我把这张夜景照片变亮"）
2. LLM 解析意图，通过能力扩展体系调用算法选择模块（传入图像特征分析 + 用户约束）
3. 算法选择模块返回推荐算法及匹配依据
4. LLM 结合 AI 知识库检索的算法知识生成推荐理由（自然语言解释为什么选这个算法）
5. 用户确认后自动发起处理

#### 2.4.4 推荐结果展示

推荐结果以卡片形式呈现，采用**渐进式披露**：默认只展示核心信息，详细内容可展开，避免信息过载（对齐 ChatGPT/Claude 推荐与推理展示的"主窗口摘要 + 展开详情"模式）。

**核心信息（默认展示）**：

| 元素 | 说明 |
|------|------|
| 推荐算法 | 算法名称 + 简要说明 |
| 推荐理由 | 一句话自然语言解释（如"该算法针对夜景低光照场景优化，能有效提升亮度且抑制噪声"）|
| 匹配度 | 推荐置信度（0-1），让用户理解推荐的可靠程度 |

**可展开详情**：

| 元素 | 说明 |
|------|------|
| 推荐参数 | 建议的处理参数（如"强度 70，饱和度 120"），可展开调整 |
| 备选方案 | 1-2 个备选算法及各自适用场景 |
| 推荐依据 | 推荐理由引用的图像特征与算法知识要点，支持溯源 |

#### 2.4.5 交互规范

| 场景 | 交互行为 |
|------|---------|
| 推荐确认 | 推荐结果以卡片形式展示，用户确认后直接发起处理；参数可展开调整 |
| 一键采纳 | 推荐卡片提供"使用推荐"主按钮，一键采纳并直接发起处理，降低操作成本 |
| 参数调整 | 参数调整提供即时反馈（如调整强度滑块时同步预览效果），调整后重新发起处理 |
| 无推荐结果 | 算法选择模块无法给出推荐时，LLM 解释原因并向用户征询更多约束（如图片内容、期望效果）|
| 推荐来源可追溯 | 推荐理由中可展示依据的算法知识要点，用户可追问"为什么推荐这个"获得更详细解释 |
| 推荐反馈 | 推荐卡片提供"有用/无用"反馈，反馈数据回流算法选择模块优化推荐质量 |

#### 2.4.6 业务规则

| 规则 | 说明 |
|------|------|
| 多图推荐 | 一次会话中涉及多张图片时，按图片分别推荐并展示各自的推荐结果 |
| 历史习惯参考 | 推荐参数默认值参考用户历史处理习惯（来自长期记忆场景触发注入），用户仍可自由调整 |
| 冷启动 | 新用户无历史习惯时，仅基于图像特征 + 知识库推荐，不报错、不降级体验 |
| 推荐反馈闭环 | 用户采纳/拒绝/修改推荐的数据回流算法选择模块，持续优化推荐质量（对齐推荐系统的反馈驱动优化）|
| 推荐失败降级 | 算法选择模块不可用时，LLM 直接给出常规处理建议并提示用户可稍后重试推荐 |

### 2.5 批量处理摘要 (F-M08-005)

#### 2.5.1 功能描述

用户上传多张图片后，通过自然语言描述统一处理需求，LLM 调度批量处理并生成结果摘要。

#### 2.5.2 批量处理流程

1. 用户上传多张图片 + 描述需求（如"把这 10 张雾图都去雾并评估效果"）
2. LLM 分解为批量任务：每张图片 → 去雾处理 → 指标评估
3. 逐张或并行调度工具执行
4. 全部完成后生成摘要：成功率、平均指标、效果最佳/最差的图片

**批量前确认**：批量处理发起前，LLM 向用户确认处理范围与预期（图片数量、预计耗时、预计消耗），用户确认后执行；用户可调整范围（如排除某张图片）或取消。

#### 2.5.3 批量结果摘要

| 摘要内容 | 说明 |
|---------|------|
| 处理概况 | 总数 / 成功数 / 失败数 |
| 平均指标 | 平均 PSNR、SSIM 等关键指标 |
| 效果最佳 | 指标最高的图片及详情 |
| 效果最差 | 指标最低的图片及详情 |
| 失败原因 | 失败图片的原因汇总 |
| 结果列表 | 每张图片的缩略图 + 指标 + 处理参数 |

**结果对比与导出**：

| 能力 | 说明 |
|------|------|
| 结果对比 | 支持选择多张图片并排对比处理效果与指标 |
| 批量导出 | 支持将批量结果导出为 CSV/Excel（图片名/算法/参数/PSNR/SSIM/耗时）|

#### 2.5.4 交互规范

| 场景 | 交互行为 |
|------|---------|
| 批量进度 | 处理过程中展示逐张图片的处理进度（进行中/成功/失败），已完成的图片可先查看 |
| 结果查看 | 摘要卡片展示处理概况与统计，用户可展开逐张图片的缩略图与指标，点击跳转查看大图 |
| 失败重试 | 部分图片处理失败时，用户可选择仅对失败图片重新发起处理，无需重复全部 |
| 批量停止 | 处理过程中用户可停止剩余未开始的图片，已完成的保留 |
| 中断恢复 | 批量处理中断（断线/离开页面）后，重新进入自动恢复到中断进度，已完成的保留、未开始的继续 |

#### 2.5.5 业务规则

| 规则 | 说明 |
|------|------|
| 批量上限 | 单次批量处理图片数有上限（默认 20 张），超出时提示用户分批处理 |
| 失败隔离 | 单张图片失败不中断整个批量任务，逐项记录失败原因，最后统一汇总 |
| 批量与定时结合 | 批量处理流程可保存为定时任务（见 [需求规格-定时与兼容](./需求规格-定时与兼容.md) F-M08-009），实现"每天定时批量处理" |

### 2.6 设计依据

本功能域的产品交互设计对齐业界主流 AI 产品在"智能推荐"与"批量任务"上的最佳实践，做工程化取舍：

| 设计点 | 对标实践 |
|--------|---------|
| 推荐可解释性 | ChatGPT/Claude 的推荐与解释实践：推荐理由具体、可验证，引用图像特征与算法特性，而非泛泛而谈；用户可追问"为什么"获得更详细解释 |
| 渐进式披露 | ChatGPT 推理轨迹、Claude Code 工具展示的"主窗口摘要 + 展开详情"模式：推荐卡片默认只展示核心信息，详细理由/参数/备选可展开，避免信息过载 |
| 一键采纳 + 可调整 | Canva/AI 设计工具的"一键应用 + 手动调整"：推荐提供一键采纳主路径，同时保留参数调整入口，兼顾效率与掌控感 |
| 推荐反馈闭环 | Netflix/YouTube 等推荐系统的反馈驱动优化：用户采纳/拒绝/修改数据回流，持续优化推荐质量 |
| 冷启动处理 | 推荐系统冷启动实践：新用户/新算法无历史数据时，基于特征与知识库兜底推荐，不降级体验 |
| 批量进度可视化 | 文件上传/下载、Midjourney 排队等批量任务实践：逐张展示进度，已完成可先查看，让用户对长任务有掌控感 |
| 部分失败处理 | 批量上传/下载工具的部分失败实践：单张失败不中断整体，失败原因清晰，支持仅重试失败项 |
| 批量前确认与预估 | 批量操作（批量删除）的确认实践：处理前展示数量/预计耗时/预计消耗，用户确认后执行 |
| 批量中断恢复 | 长任务的中断恢复实践：断线/离开后自动恢复到中断进度，不重复已完成部分 |

> 本功能域聚焦"推荐与批量调度"的产品交互；推荐的技术实现（图像特征分析、规则匹配）见 [算法选择模块](../算法选择/需求规格.md)，批量调度的后端实现（调度策略、产物管理、失败处理）见 [后端实现-智能调度](./后端实现-智能调度.md)。
