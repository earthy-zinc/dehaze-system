## 2. 架构设计

### 2.1 模块分层架构

```
Controller 层（dehaze-java）
├── EvaluationController       # 效果评估：提交 / 状态查询 / 指标历史 / 日志列表
└── CompareController          # 对比报告：生成 / 状态查询 / 下载

Service 层（dehaze-java）
├── SysEvalLogServiceImpl      # 评估任务编排（创建 processing 日志 + 异步执行）
├── EvalLogAsyncTask           # 异步评估执行（调用 Python 算法服务 + 轮询 + 写结果）
└── CompareServiceImpl         # 对比报告生成（校验处理记录 + 异步生成 HTML）

Python 算法服务（dehaze-python）
├── evaluation router/service  # 评估异步任务（配额扣减 + MD5 + 指标计算 + 日志）
├── compare router/service     # 对比报告异步生成（HTML 渲染）
└── algorithm/metrics.py       # 指标计算（pyiqa，配置驱动）
```

> **说明**：早期设计稿中的 ComparisonService/ReportService/QuotaService 等抽象层**不存在**，当前实现直接由上述服务完成。

### 2.2 核心组件职责

| 组件 | 职责描述 | 关键能力 |
|------|---------|---------|
| SysEvalLogServiceImpl | 评估任务编排 | 校验算法、解析图片 URL、创建 processing 日志、触发异步执行 |
| EvalLogAsyncTask | 异步评估执行 | 调用 Python 评估、轮询 Python 任务（2s/300s）、写入指标结果、监控埋点 |
| CompareServiceImpl | 对比报告生成 | 校验处理记录完成态、创建报告任务（复用 sys_eval_log）、异步生成 HTML |
| evaluation_service (Python) | 评估执行 | 权益配额扣减、并行下载图片、MD5 计算、指标计算、日志状态流转 |
| compare_service (Python) | 报告生成 | 校验处理记录、异步渲染 HTML 报告、日志状态流转 |

## 3. 核心业务流程

### 3.1 效果评估流程

效果评估为计算密集型任务，采用异步任务模式避免长耗时请求超时：

```
用户提交评估请求（algorithmId + predUrl + gtUrl）
    ↓
SysEvalLogServiceImpl.evaluate()
  1. 校验算法存在
  2. 解析预测/参考图 URL（支持 predFileId/gtFileId 转 URL）
  3. 创建 sys_eval_log（status=1 处理中）
  4. 触发 EvalLogAsyncTask 异步执行
    ↓
立即返回 { logId, status=1 }
    ↓
EvalLogAsyncTask.execute()
  1. 调用 Python 算法服务 /evaluation（异步）
  2. 轮询 Python 任务状态（2s 间隔，300s 超时）
  3. 完成 → 写入 metrics 到 result 字段，status=2
  4. 失败 → 写入 errorMessage，status=3
  5. 监控埋点 dehaze_evaluation_total{status}
```

**Python 端评估执行**（evaluation_service）：

```
收到评估请求
  1. 会员配额扣减（check_and_deduct_quota("evaluate")，Redis 原子操作；失败恢复配额）
  2. 并行下载预测图/参考图，计算 MD5（记录 pred_md5/gt_md5，为评估缓存预留）
  3. 创建 processing 日志
  4. asyncio.create_task 后台执行
  5. 指标计算（algorithm/metrics.py，线程池执行避免阻塞事件循环）
  6. 更新日志为 completed/failed
```

### 3.2 对比报告生成流程

对比报告为耗时操作，通过异步任务实现：

```
用户请求生成报告（CompareReportForm.logId）
    ↓
CompareServiceImpl.generateReport()
  1. 查询处理记录（sys_pred_log），校验存在且已完成
  2. 创建报告任务（复用 sys_eval_log 表，status=1 处理中）
     - pred_url = 处理结果图 URL，gt_url = 原图 URL
     - result 字段存请求元数据（logId/format/includeMetrics/includeFilters）
  3. 触发异步生成
    ↓
立即返回 { taskId, status=1 }
    ↓
异步生成 HTML（CompareServiceImpl.generateReportAsync）
  1. 查询算法名称
  2. 渲染 HTML 报告（原图+结果图并排、算法名称/ID、生成时间）
  3. 更新日志：status=2，result = {"reportHtml": "...", "generatedAt": "..."}
  4. 异常 → status=3，写入 errorMessage
```

### 3.3 报告下载/查询

```
GET /api/v1/compare/report/{taskId}
  ├─ download=false（默认）→ 返回 JSON 状态：
  │    status=1 → { taskId, status }
  │    status=2 → { taskId, status, downloadUrl: "/api/v1/compare/report/{id}?download=true" }
  │    status=3 → { taskId, status, errorMessage }
  └─ download=true → 返回 HTML 文件流
       - status=1 → 返回处理中状态
       - status=3 → 返回失败错误
       - 已完成 → 读取 result.reportHtml，Content-Type: text/html
```

## 4. 评估指标计算

### 4.1 指标体系

评估指标由 Python 算法服务 `algorithm/metrics.py` 统一配置（`METRICS_CONFIG`），基于 pyiqa 计算，模型按需延迟加载：

| 指标 | 英文名 | 需要参考图 | 越高越好 | 合格阈值 |
|------|--------|-----------|---------|---------|
| 峰值信噪比 | PSNR | 是 | 是 | ≥ 30.0 dB |
| 结构相似性 | SSIM | 是 | 是 | ≥ 0.8 |
| 学习感知相似度 | LPIPS | 是 | 否 | ≤ 0.3 |
| 无参考质量评估 | NIQE | 否 | 否 | ≤ 5.0 |
| 无参考质量预测 | NIMA | 否 | 是 | 统计展示 |
| 无参考质量评估 | BRISQUE | 否 | 否 | 统计展示 |

**计算规则**：需要参考图的指标（PSNR/SSIM/LPIPS）在提供参考图时计算；无参考指标（NIQE/NIMA/BRISQUE）始终计算。合格判定基于阈值（psnr/ssim/lpips/niqe 四项）。

### 4.2 计算流程

```
前端提交评估 → Java/Python 评估服务
    ↓ 下载图片（Python 端并行下载）
    ↓ algorithm/metrics.py calculate()
    遍历 METRICS_CONFIG，按 requires_clear 与 clear 是否提供决定计算
    ↓
返回指标列表 [{label, value, better, description}]
    ↓
写入 sys_eval_log.result（JSON），status=2
```

### 4.3 缓存机制

`sys_eval_log` 表设计预留评估缓存能力（`algorithm_id + pred_md5` 可命中缓存），**当前未实现缓存命中逻辑**，仅记录 MD5 字段。

## 5. 对比报告

### 5.1 报告模板

报告为服务端渲染的 HTML，包含以下内容模块：

| 模块 | 内容 |
|------|------|
| 报告头部 | 标题（去雾效果对比报告）、算法名称、生成时间 |
| 图片对比区 | 原图与处理结果图的并排展示（`<img>` 引用对象存储 URL） |
| 处理信息区 | 算法名称、算法 ID、生成时间、任务状态（已完成） |

> **说明**：评估指标数据、处理参数详情**未纳入报告**（`includeMetrics`/`includeFilters` 参数已预留但未生效）。早期设计稿中"PDF/图片格式、MinIO 存储报告文件"**未实现**——当前报告 HTML 直接存于 `sys_eval_log.result` JSON 字段。

### 5.2 异步生成

| 配置项 | 说明 |
|--------|------|
| 任务载体 | `sys_eval_log` 表（`taskId` 即评估日志 ID） |
| 执行模式 | Java：`@Async("datasetTaskExecutor")`；Python：`asyncio.create_task` |
| 状态流转 | 1 处理中 → 2 已完成 / 3 失败 |
| 报告保留 | 无固定保留时长，随 `sys_eval_log` 记录保留 |

### 5.3 结果存储

| 项目 | 说明 |
|------|------|
| 存储位置 | `sys_eval_log.result`（JSON：`{"reportHtml": "...", "generatedAt": "..."}`） |
| 下载方式 | `GET /api/v1/compare/report/{taskId}?download=true` 返回 HTML 文件流 |
| 下载权限 | 登录用户即可（未按所属用户隔离校验） |

## 6. 模块间协作

### 6.1 与算法管理模块的集成

| 调用场景 | 调用接口 | 说明 |
|---------|---------|------|
| 校验算法存在 | 算法查询接口 | 评估与报告生成前校验算法 |
| 获取算法信息 | 算法详情接口 | 展示算法名称/类型/权重/参数量，报告头部展示算法名称 |

### 6.2 与会员管理模块的集成

| 集成点 | 实现方式 | 状态 |
|--------|---------|------|
| 评估配额扣减 | Python 端 `MemberService.check_and_deduct_quota("evaluate")`，Redis 原子扣减，失败恢复 | ✅ 已实现（Python 端） |
| 报告导出开关 | 权益表 `report_export` 已配置，接口层未按等级校验 | ⏳ 规划中 |

> **说明**：Java 端评估**未接入**配额扣减（与去雾处理模块一致，配额扣减集中在 Python 算法服务侧）。

### 6.3 与收藏管理模块的集成

对比页面**当前未提供收藏入口**，收藏能力通过收藏管理模块独立使用。

### 6.4 与消息通知模块的集成

报告生成完成、评估完成**均无消息通知**，前端通过轮询获取结果。早期设计稿中的"报告生成完成通知"未实现。

### 6.5 与任务管理模块的集成

对比报告**不经过任务管理模块**，报告任务直接复用 `sys_eval_log` 表；无任务列表展示、无消息推送、无结果文件保留策略。
