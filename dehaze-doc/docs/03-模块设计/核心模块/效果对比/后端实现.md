## 2. 架构设计

### 2.1 模块分层架构

效果对比模块承接去雾处理模块的输出结果，通过算法管理模块的 EvaluationService 调用 Python 算法服务执行指标计算，并提供对比报告生成能力：

```
Controller 层
├── ComparisonController      # 效果对比视图（图片对比、指标展示）
├── EvaluationController      # 效果评估任务提交/查询
└── ReportController          # 对比报告生成/下载

Service 层
├── ComparisonService         # 对比编排服务（多模式对比数据聚合）
├── EvaluationService         # 评估任务编排服务
├── ReportService             # 对比报告生成服务
└── QuotaService              # VIP 评估配额校验

依赖模块
├── EvaluationService（算法管理）   # 效果评估指标计算接口
├── MemberService（会员管理）       # 评估配额校验、等级权益
├── FavoriteService（收藏管理）     # 结果收藏
├── RecommendService（推荐管理）    # 替代算法推荐获取
├── MessageService（消息通知）      # 报告生成完成通知
├── RatingService（反馈评价）       # 评分触发、低分告警
└── TaskService（任务管理）         # 报告生成异步任务
```

### 2.2 核心组件职责

| 组件 | 职责描述 | 关键能力 |
|------|---------|---------|
| ComparisonService | 对比编排服务 | 多模式对比数据聚合（并排/重叠/放大镜/指标）、原图与结果图关联查询 |
| EvaluationService | 评估任务编排 | 提交评估请求、轮询评估结果、评估历史管理 |
| ReportService | 对比报告生成 | 异步报告生成、报告模板渲染、结果存储 |
| QuotaService | VIP 配额校验 | 评估次数校验、报告导出权限校验 |

## 3. 核心业务流程

### 3.1 效果评估流程

效果评估为计算密集型任务，采用异步任务模式避免长耗时请求超时：

```
用户提交评估请求（预测图 + 参考图 + 算法ID）
    ↓
EvaluationService 接收请求
    ↓
QuotaService 校验 VIP 评估配额 → 不足返回错误码
    ↓
调用算法管理模块 EvaluationService.evaluate()
    ↓
算法管理模块内部：
  - MD5 缓存查询（命中直接返回）
  - 调用 Python 算法服务计算评估指标
  - 写入 sys_eval_log
    ↓
EvaluationService 收到评估结果后扣减配额
    ↓
返回评估结果（PSNR/SSIM/LPIPS/NIQE/Entropy）
```

### 3.2 对比报告生成流程

对比报告为耗时操作，通过异步任务实现：

```
用户请求生成报告（处理历史记录 ID + 对比维度）
    ↓
ReportService 校验 VIP 报告导出权限
    ↓
创建报告生成任务（复用任务管理模块的异步任务框架）
    ↓
任务执行：
  1. 加载原图和处理结果图
  2. 查询评估指标数据（如有）
  3. 查询算法信息和处理参数
  4. 按报告模板生成 PDF/图片格式报告
  5. 上传报告文件到对象存储
    ↓
任务完成后：
  - 触发消息通知（报告生成完成）
  - 前端可下载报告文件
```

### 3.3 替代算法推荐获取

当用户对当前处理结果不满意时，效果对比模块可向推荐管理模块请求替代算法推荐：

```
ComparisonService 获取替代算法推荐
    ↓
调用 RecommendService.getAlternativeAlgorithms(imageId, currentAlgorithmId)
    ↓
推荐管理模块基于图像特征 + 排除当前算法生成推荐列表
    ↓
返回 Top 3 替代算法及推荐理由
```

## 4. 评估指标计算

### 4.1 指标体系

效果对比模块不直接计算评估指标，而是通过算法管理模块的 EvaluationService 调用 Python 算法服务完成计算：

| 指标 | 英文名 | 说明 | 合格阈值 | 调用方式 |
|------|--------|------|---------|---------|
| 峰值信噪比 | PSNR | 图像质量评价，越高越好 | ≥ 30.0 dB | Python 算法服务 |
| 结构相似性 | SSIM | 结构相似程度 | ≥ 0.8 | Python 算法服务 |
| 学习感知相似度 | LPIPS | 深度学习感知相似度 | ≤ 0.3 | Python 算法服务 |
| 自然图像质量 | NIQE | 无参考质量评价 | ≤ 5.0 | Python 算法服务 |
| 信息熵 | Entropy | 图像信息丰富度 | 统计展示 | Python 算法服务 |

### 4.2 计算流程

```
效果对比模块
    ↓ 调用
算法管理模块 EvaluationService
    ↓ HTTP 调用
Python 算法服务
    ↓
1. 读取预测图像和参考图像
2. 计算各评估指标
3. 返回评估结果 JSON
    ↓
算法管理模块写入 sys_eval_log
    ↓
返回给效果对比模块
```

### 4.3 缓存机制

| 缓存对象 | 缓存 Key | TTL | 说明 |
|---------|---------|------|------|
| 评估结果 | `evaluation:{algorithmId}:{predMd5}:{refMd5}` | 永久 | 相同图片+相同算法的评估结果永久缓存 |

缓存由算法管理模块的 EvaluationService 内部管理，效果对比模块透明使用。

## 5. 对比报告

### 5.1 报告模板

报告包含以下内容模块：

| 模块 | 内容 |
|------|------|
| 报告头部 | 报告标题、生成时间、算法名称、处理参数 |
| 图片对比区 | 原图与处理结果图的并排/重叠对比展示 |
| 指标分析区 | PSNR/SSIM/LPIPS/NIQE/Entropy 的数值和可视化图表 |
| 算法信息区 | 算法名称、类型、版本、适用场景、推荐指数 |
| 性能数据区 | 处理时间、内存占用、输出文件大小 |

### 5.2 异步生成

报告生成复用任务管理模块的异步任务框架：

| 配置项 | 说明 |
|--------|------|
| 任务类型 | `report_generation` |
| 执行模式 | 异步（MQ 消费） |
| 超时时间 | 60 秒 |
| 重试次数 | 3 次 |

### 5.3 结果存储

| 项目 | 说明 |
|------|------|
| 存储位置 | MinIO 对象存储 |
| 文件路径 | `/reports/{userId}/{taskId}/report.pdf` |
| 保留时长 | 24 小时（可配置） |
| 下载权限 | 仅报告所属用户可下载 |

## 6. 模块间协作

### 6.1 与算法管理模块的集成

| 调用场景 | 调用接口 | 说明 |
|---------|---------|------|
| 效果评估 | EvaluationService.evaluate() | 委托执行指标计算 |
| 查询评估历史 | EvaluationService.getEvalLogs() | 分页查询用户评估历史 |

### 6.2 与收藏管理模块的集成

| 集成点 | 触发时机 | 实现方式 |
|--------|---------|---------|
| 收藏事件 | 对比页面点击收藏按钮 | 调用 FavoriteService.favorite(userId, "result", recordId) |
| 取消收藏 | 对比页面取消收藏 | 调用 FavoriteService.unfavorite(userId, "result", recordId) |

### 6.3 与推荐管理模块的集成

| 集成点 | 说明 |
|--------|------|
| 替代算法推荐 | 对比页面提供"换算法重试"入口，调用 RecommendService.getAlternativeAlgorithms() 获取排除当前算法的替代推荐 |
| 推荐效果反馈 | 用户采纳替代算法推荐时，回传推荐采纳事件给推荐管理模块 |

### 6.4 与消息通知模块的集成

| 触发事件 | 消息类型 | 通知内容 |
|---------|---------|---------|
| 报告生成完成 | 业务通知 | "对比报告已生成，点击下载" |
| 评估完成 | 业务通知 | "效果评估已完成，点击查看指标" |

### 6.5 与反馈评价模块的集成

| 集成点 | 说明 |
|--------|------|
| 评分触发 | 对比页面提供评分入口，用户对处理结果打分（1-5星） |
| 低分告警 | 用户评分 ≤ 2 星时触发低分告警，通过消息通知模块通知管理员 |

### 6.6 与任务管理模块的集成

报告生成复用任务管理模块的异步任务能力：

| 集成方式 | 说明 |
|---------|------|
| 任务创建 | 调用 TaskService.createTask("report_generation", params) |
| 策略实现 | ReportGenerationStrategy 实现 TaskStrategy 接口 |
| 进度追踪 | 前端通过任务管理模块接口轮询报告生成进度 |

## 7. VIP 权益校验

### 7.1 权益差异

| 权益项 | 普通用户 | VIP1 | VIP2 | SVIP |
|--------|---------|------|------|------|
| 每月评估次数 | 20 | 100 | 500 | 3000 |
| 评估指标范围 | 基础指标（PSNR/SSIM） | 全部指标 | 全部指标 | 全部指标 |
| 报告导出 | 不支持 | 图片格式 | PDF 格式 | PDF + 数据 |

### 7.2 校验流程

```
用户发起评估/报告请求
    ↓
QuotaService 查询用户会员等级
    ↓
检查权益开关（如报告导出权限）
    ↓
检查本月已用次数 < 配额上限
    ├─ 是 → 执行处理 → 扣减次数
    └─ 否 → 返回次数不足提示 → 引导升级会员
```

## 8. 配置项

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| evaluation.async.mode | 评估是否使用异步模式 | true |
| evaluation.timeout | 评估请求超时时间 | 30s |
| evaluation.cache.ttl | 评估结果缓存时间 | 永久 |
| report.max-size | 报告文件最大大小 | 10MB |
| report.retention.hours | 报告文件保留时长 | 24h |
| report.format | 报告默认格式 | pdf |
