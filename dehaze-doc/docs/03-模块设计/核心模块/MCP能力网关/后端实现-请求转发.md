# MCP 能力网关 - 后端实现设计（请求转发）

## 1. 文档概述

本文档描述 F-M07-004 请求转发与响应转换和 F-M07-005 安全与工程化的后端实现。RequestForwarder 运行在 `@mcp.tool()` 装饰的函数体内部，MCPServer（SDK）已自动完成 JSON Schema 参数校验。

## 2. 请求转发

### 2.1 参数转换

```
LLM 传入 arguments (JSON Object，符合 tool inputSchema)
    ↓
RequestForwarder.forward(toolName, arguments, authContext)
    ↓
获取 tool 的 OpenAPI 原始定义（path template, method, parameter locations）
    ↓
按参数位置分类：
  - in: path   → replace "{placeholder}" in URL path
  - in: query  → append to URL query string
  - in: body   → JSON body of HTTP request
    ↓
示例：
  tool: predict_dehaze
  url: POST /api/v1/predict/dehaze
  arguments: {fileId: 123, algorithm: "RIDCP"}
  ↓
  HTTP Request: POST /api/v1/predict/dehaze?algorithm=RIDCP
  Body: {"fileId": 123}
```

### 2.2 后端调用

```
RequestForwarder.forward(...)
    ↓
构建 HTTP 请求：
  - URL: 拼接后端 base URL + path
  - Method: 从 tool 的 OpenAPI 定义获取
  - Headers:
    · Authorization: Bearer dhak_xxx（从 authContext 获取）
    · X-Trace-Id: {traceId}（透传调用链路 ID）
    · Content-Type: application/json
    · User-Agent: dehaze-mcp-gateway/1.0
  - Body: JSON 序列化的参数
  - Timeout: mcp.request.timeout（默认 30 秒）
    ↓
发起 HTTP 请求
```

### 2.3 超时与重试

```
HTTP 请求
    ↓
正常返回 → 进入响应转换
超时 (30s) → 判断是否可重试
    ↓
重试条件：
  - tool 为 GET 方法（幂等）
  - 重试次数 < mcp.request.retry-count（默认 1）
  - 超时或 5xx 错误
    ↓
重试：等待 1 秒后重新发起请求
不可重试（POST/PUT 或已达最大次数）→ 返回 JSON-RPC error(-32003, "Backend timeout")
```

### 2.4 速率限制

```
tools/call 请求到达
    ↓
RateLimiter.acquire(userId, toolName)
    ↓
令牌桶算法：
  - bucket: mcp:rate:{userId}      → 30 tokens/min（每用户）
  - bucket: mcp:rate:{toolName}    → 10 tokens/min（每 tool）
    ↓
任一桶无 token → JSON-RPC error(-32001, "Rate limited", {retryAfter: seconds})
    ↓
有 token → 放行，进入请求转发
```

**降级**：速率限制 Redis 不可用时降级为内存计数器（单实例限流），保证网关可用性 > 精度。

## 3. 响应转换

### 3.1 成功响应

```
后端返回 HTTP 200 + JSON
    ↓
响应大小 ≤ mcp.response.max-length (8000字符) → 直接提取 JSON body 作 content
    ↓
响应大小 > 8000:
  - 列表类 → 分页截断（返回前 N 条 + "total: XXX results, showing first N"）
  - 详情类 → 提取关键字段 + "{fields} data truncated"
  - 图片处理结果 → 返回引用（URL + 摘要元数据），URL 不下发原图 URL 是通过 FileService.getUrl() 拼接的
    ↓
封装为 MCP content:
  result: {
    content: [{"type": "text", "text": "处理结果描述"}],
    isError: false
  }
```

### 3.2 大体积响应

```
后端返回大体积结果（如图片处理完成后的二进制/大数据）
    ↓
检测：Content-Length > 1MB 或 Content-Type 不是 application/json
    ↓
转换策略：
  - 提取摘要元数据（从 HTTP Header 或关联日志获取）
  - 生成 artifact 引用（不落库，返回 uri + summary）
    ↓
返回 MCP content:
  {"type": "text", "text": "处理完成。result_uri: artifact://pred/456, summary: {psnr: 28.5, ssim: 0.92}"}
```

> 与 AI 对话模块的 artifacts 引用化策略一致，URL 不落库，通过 FileService.getUrl() 运行时拼接。

### 3.3 错误响应

| 后端错误 | → 网关响应 |
|---------|-----------|
| HTTP 400 | JSON-RPC error(-32602, "参数错误: {后端消息}") |
| HTTP 401/403 | JSON-RPC error(-32002, "权限不足: {后端消息}") |
| HTTP 404 | JSON-RPC error(-32002, "资源不存在") |
| HTTP 429 | JSON-RPC error(-32001, "后端频率限制，请稍后重试")，不重试 |
| HTTP 5xx | JSON-RPC error(-32003, "后端服务不可用")，GET 方法重试 1 次 |
| 网络超时 | JSON-RPC error(-32003, "后端响应超时")，GET 方法重试 1 次 |

**统一错误 content 格式**：

```json
{
  "content": [
    {"type": "text", "text": "配额不足：今日处理次数已用完 (100/100)。请升级VIP或等待明日重置。"}
  ],
  "isError": true
}
```

`isError: true` 告诉 LLM 调用失败，LLM 可以据此决定重试、退而求其次或告知用户。

## 4. 异步调用

```
POST /api/v1/predict/dehaze → 后端返回 {taskId: "xxx", status: "processing"}
    ↓
网关判断为非正常结果（结构含 taskId/status=processing）
    ↓
返回 MCP content:
  {"type": "text", "text": "处理已提交 (taskId: xxx)。等待处理完成后获取结果。"}
  isError: false
    ↓
AI 对话模块收到此结果 → Agent 进入 async_wait 中断
  （checkpoint 持久化 taskId，等待回调恢复）
```

## 5. 性能优化

### 5.1 连接池

后端 HTTP 请求使用连接池复用（Keep-Alive），避免频繁 TCP 握手：

| 配置 | 值 | 说明 |
|------|------|------|
| 最大空闲连接 | 50 | 保持活跃的长时间闲置连接 |
| 单主机最大连接 | 20 | 同一后端主机并发连接数 |
| keep-alive 超时 | 60s | 空闲连接保活时间 |

### 5.2 结果缓存

查询类 tool（GET + 幂等 + 无副作用）结果可缓存：

```
tools/call → toolName = "list_algorithms"
    ↓
检查 Redis: mcp:cache:{toolName}:{argsHash}
  - 命中 → 直接返回缓存结果
  - 未命中 → 调用后端 → 缓存结果（TTL 5 分钟）
```

**缓存策略**：
- 仅 GET 请求
- 仅 200 正常响应
- 不含异步 taskId
- TTL 基于 tool 数据变更频率（算法列表 5 分钟，系统配置 30 分钟）

### 5.3 查询类结果分页

```
GET /algorithms → 后端返回 500 条算法
    ↓
ResponseTruncator 保留前 20 条 + 摘要：
  "返回 500 条算法的前 20 条：
   1. RIDCP - 基于颜色衰减先验的去雾算法
   2. FFA-Net - 基于特征融合注意力网络的去雾算法
   ... (剩余 480 条已省略)
   
   如需查询特定算法，可使用参数 algorithmId 或 algorithmName 调用此工具。"
```

> 防止大量数据撑爆 LLM 上下文，同时保留用户的替代检索路径提示。
