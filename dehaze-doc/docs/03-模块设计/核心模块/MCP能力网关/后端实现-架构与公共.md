# MCP 能力网关 - 后端实现设计（架构与公共）

## 1. 文档概述

本文档描述 MCP 能力网关的整体架构设计、传输层实现、安全体系、缓存策略与高可用设计。

**技术选型**：基于 [MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk)（`mcp.server.MCPServer`，原 FastMCP）构建。SDK 已内置 Streamable HTTP 传输、JSON-RPC 2.0 解析/路由/错误码、`@mcp.tool()` 装饰器自动生成 JSON Schema 和参数校验。网关只需实现业务层逻辑（OpenAPI 解析、请求转发、VIP 过滤、速率限制、命名空间分组、工具搜索），不重复造轮子。

| SDK 内置（无需自建） | 网关自建（业务逻辑） |
|---------------------|---------------------|
| Streamable HTTP 传输 | OpenAPI 文档解析 → MCP tool 转换（`ApiDiscoverer`） |
| JSON-RPC 2.0 解析/路由/错误码 | HTTP 请求转发 + 身份透传（`RequestForwarder`） |
| `@mcp.tool()` 装饰器 → 自动 JSON Schema + 参数校验 | VIP 工具可见性过滤（`VipAccessFilter`） |
| `@mcp.resource()` / `@mcp.prompt()` 装饰器 | 速率限制（`RateLimiter`） |
| `notifications/*` 推送 | 命名空间分组（`NamespaceBuilder`） |
| `initialize` 握手 + 能力协商 | `tools/search` 自定义方法（`ToolSearchEngine`） |

各功能域详见分篇文档：

| 分篇文档 | 覆盖功能点 |
|---------|-----------|
| [后端实现-工具注册](./后端实现-工具注册.md) | F-M07-002 API 自动发现与工具注册 + 命名空间分组 + tools/search |
| [后端实现-请求转发](./后端实现-请求转发.md) | F-M07-004 请求转发与响应转换 + F-M07-005 安全与工程化 |

## 2. 架构设计

### 2.1 模块分层

```
MCP Python SDK（官方库，不修改）
├── MCPServer                    # 核心 Server：Streamable HTTP 传输 + JSON-RPC 2.0 处理
├── @mcp.tool()                  # 装饰器注册工具 → 自动 JSON Schema + 参数校验
├── @mcp.resource()              # 装饰器注册资源 → 自动 URI 模板解析
├── @mcp.prompt()                # 装饰器注册提示词模板
└── Middleware Pipeline          # SDK 中间件管道（认证、日志等可插拔）

网关业务层（自建，SDK 之上）
├── ApiDiscoverer                # OpenAPI 文档读取 + 解析 → 动态注册 @mcp.tool()
├── RequestForwarder             # 工具函数体内的 HTTP 请求转发逻辑（参数/响应转换 + 超时 + 重试）
├── NamespaceBuilder             # 按 OpenAPI tags 聚合 tool 生成命名空间摘要
├── ToolSearchEngine             # tools/search 实现：ES BM25 检索 + 同命名空间扩展
├── VipAccessFilter              # SDK 中间件：tools/list 返回时按 VIP 等级过滤
├── RateLimiter                  # SDK 中间件：令牌桶按用户+tool 维度限流
└── AuthMiddleware               # SDK 中间件：解析 Bearer Token（dhak_ 前缀），校验有效性

依赖模块
├── AuthService（认证管理）       # API Key 校验和用户身份解析
├── MemberService（会员管理）     # 查询用户 VIP 等级
└── FileService（文件管理）       # 大体积响应 URL 拼接
```

### 2.2 核心组件职责

| 组件 | 类型 | 职责 |
|------|------|------|
| `MCPServer` | SDK 内置 | 启动时加载所有 `@mcp.tool()` 注册的函数；自动生成 JSON Schema；自动参数校验；自动 JSON-RPC 2.0 处理 |
| `ApiDiscoverer` | 自建 | 读取 OpenAPI → 解析 paths → 动态生成 `@mcp.tool()` 装饰的函数 → 注册到 MCPServer |
| `NamespaceBuilder` | 自建 | 按 OpenAPI tags 聚合 tool 生成命名空间（每组 name + description + tool_count），支撑三层上下文压缩 |
| `ToolSearchEngine` | 自建 | ES BM25 检索匹配 tool + 同命名空间扩展 + ES 不可用时降级 Jaccard 关键词匹配 |
| `RequestForwarder` | 自建 | 每个 `@mcp.tool()` 函数体内部调用：LLM 参数 → HTTP 请求 → 后端响应 → MCP 格式返回 |
| `AuthMiddleware` | 自建 | 提取 Bearer Token，查询 `sys_api_key` 校验有效性，解析 userId |
| `VipAccessFilter` | 自建 | SDK 中间件：`tools/list` 返回前按用户 VIP 等级过滤可见 tool |
| `RateLimiter` | 自建 | SDK 中间件：令牌桶算法按用户+tool 维度限流 |

### 2.3 与自建方案的成本对比

| 层面 | 自建协议层（旧设计） | 复用 SDK（新设计） |
|------|-------------------|-------------------|
| 传输层 | 自建 StreamableHTTPHandler | SDK 内置，`mcp run` 一行启动 |
| JSON-RPC 解析 | 自建 JSONRpcProcessor | SDK 内置 |
| 方法路由 | 自建 8 个 Handler 类 | `@mcp.tool()` 一行装饰器 |
| JSON Schema 生成 | 自建 Schema 转换代码 | SDK 从 Python 类型注解自动生成 |
| 参数校验 | 自建 ParamValidator | SDK 内置 JsonSchema 校验 |
| 能力协商 | 自建 InitializeHandler | SDK 内置 `initialize` 握手 |
| 实际需要写的代码 | ~3000 行全局 | ~1500 行业务逻辑 |

## 3. 基于 SDK 的工具注册流程

### 3.1 核心思路

不手动构造 `McpTool` 对象和 `ToolListHandler`。将每个后端 API 包装为一个 `@mcp.tool()` 装饰的 Python 函数，SDK 自动完成 JSON Schema 提取和参数校验。工具函数体内部调用 `RequestForwarder` 完成 HTTP 转发。

```
ApiDiscoverer 从 OpenAPI 解析出 POST /predict/dehaze
    ↓
动态生成工具函数（闭包）：
    @mcp.tool(
        name="predict_dehaze",
        description="对上传的图片进行去雾处理..."
    )
    async def predict_dehaze(fileId: int, algorithm: str = "RIDCP", strength: int = 70) -> str:
        # 函数体由 RequestForwarder 执行
        return await RequestForwarder.forward("predict_dehaze", {...})
    ↓
MCPServer 自动从 Python 类型注解生成 inputSchema：
    {
        "type": "object",
        "properties": {
            "fileId": {"type": "integer"},
            "algorithm": {"type": "string", "default": "RIDCP"},
            "strength": {"type": "integer", "default": 70}
        },
        "required": ["fileId"]
    }
    ↓
SDK 自动处理：tools/list 返回该工具的完整定义
              tools/call 校验参数 → 调用函数体 → 返回结果
```

### 3.2 优势

- **零样板代码**：JSON Schema 从 Python 类型注解自动生成，不需要手动维护 OpenAPI → JSON Schema 转换
- **自动校验**：SDK 在调用函数前自动按 JSON Schema 校验参数，无需自建 `ParamValidator`
- **无版本偏移**：SDK 跟随 MCP 规范更新，网关自动获得新版本特性（如 2026-07-28 无状态改造）

## 4. RequestForwarder 设计

RequestForwarder 是每个 `@mcp.tool()` 函数体内部调用的转发器：

```
@mcp.tool() 函数体
    ↓
RequestForwarder.forward(tool_name, arguments)
    ↓
Step 1: 查 ToolRegistry 获取该 tool 的后端 API 信息
  - HTTP method、path、参数位置（query/path/body）
    ↓
Step 2: 参数转换
  - arguments → URL query params / path placeholder / JSON body
    ↓
Step 3: 发送 HTTP 请求
  - Authorization: Bearer dhak_xxx（从会话上下文获取）
  - 超时 30 秒、查询类 GET 可重试 1 次
    ↓
Step 4: 响应转换
  - HTTP 200 JSON → 返回 dict（SDK 自动序列化为 MCP result）
  - HTTP 4xx/5xx → 抛出异常（SDK 自动转为 JSON-RPC error）
  - 异步任务（返回 task_id）→ 返回 {"task_id": "xxx", "status": "processing"}
```

> 详见 [后端实现-请求转发](./后端实现-请求转发.md)。

## 5. 安全体系（SDK 中间件集成）

所有安全组件作为 SDK Middleware 插入请求管道：

```
MCPServer 请求管道
    ↓
AuthMiddleware.authenticate()
  - 提取 Authorization: Bearer dhak_xxx
  - 查询 sys_api_key WHERE revoked_at IS NULL
  - 命中 → 注入 userId 到请求上下文
  - 未命中 → 返回 JSON-RPC error(-32000)
    ↓
RateLimiter.acquire(userId, toolName)
  - 令牌桶：30 req/min/用户 + 10 req/min/tool
  - 超限 → 返回 JSON-RPC error(-32001)
    ↓
[tools/list 专用] VipAccessFilter.filter(tools, vipLevel)
  - 按 VIP 等级过滤返回的 tool 列表
    ↓
@mcp.tool() 函数体执行
  - SDK 自动 JSON Schema 校验参数（-32602）
  - RequestForwarder.forward() 执行转发
```

### 5.1 工具级访问控制

```
tools/list 响应返回前
    ↓
VipAccessFilter.filter(tools, userId)
  - MemberService.getVipLevel(userId) → 如 VIP1
  - 从 sys_member_benefit 读取该 VIP 可访问的 tool tags/prefix
  - 过滤 tools 列表 + 过滤命名空间摘要（隐藏无权访问的 namespace）
    ↓
返回仅该 VIP 可见的结果
```

## 6. 工具注册表同步

```
启动时：
  ApiDiscoverer.discoverAll()
    ↓ 读取 OpenAPI URL（配置项）
    ↓ 解析 paths → 为每个 API 生成 @mcp.tool() 函数
    ↓ 注册到 MCPServer（SDK 自动管理 tool 列表）
    ↓ NamespaceBuilder.build() → 按 OpenAPI tags 聚合生成命名空间摘要
    ↓ 存入内存缓存

定时同步（每 5 分钟）：
  ApiDiscoverer.discoverDiff()
    ↓ 重新读取 OpenAPI → 与当前注册对比
    ↓ diff: {added, removed, changed}
    ↓ 新增 API → 动态注册新的 @mcp.tool()
    ↓ 删除 API → 从 MCPServer 注销
    ↓ NamespaceBuilder.rebuild() → 重新计算分组
    ↓ 如有变更 → 推送 notifications/tools/list_changed
```

> 详见 [后端实现-工具注册](./后端实现-工具注册.md)。

## 7. 高可用设计

- **无状态**：工具列表通过定期读取 OpenAPI 重建，不依赖本地状态。基于 SDK 的 MCPServer 天然支持 2026-07-28 无状态 MCP 协议
- **多实例**：通过 Nginx/K8s 负载均衡到多个网关实例（SDK 的 Streamable HTTP 无 session 依赖）
- **健康检查**：`GET /health` 返回 200，含 `{status, uptime, toolCount, lastSyncAt}`

## 8. 缓存策略

| 缓存对象 | 缓存位置 | TTL | 更新策略 |
|---------|---------|------|---------|
| Tool 列表 + 命名空间摘要 | 内存 | 5 分钟 | 定时同步 + 手动刷新（SDK 自动管理 tool 注册） |
| resource 读取结果 | 内存（可选） | 5 分钟 | 首次读取后缓存 |
| Query tool 调用结果 | Redis | 5 分钟 | key: `mcp:cache:{toolName}:{argsHash}` |
| API Key 校验结果 | 内存 | 1 分钟 | 校验通过后缓存 userId |

## 9. 配置项

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `mcp.server.port` | 网关端口 | 8082 |
| `mcp.openapi.url` | OpenAPI 文档 URL | `http://dehaze-java:8080/v3/api-docs` |
| `mcp.openapi.sync-interval` | 定期同步间隔（秒） | 300 |
| `mcp.rate-limit.per-user` | 每用户每分钟 tool 调用数 | 30 |
| `mcp.rate-limit.per-tool` | 每 tool 每分钟调用数 | 10 |
| `mcp.request.timeout` | 后端 HTTP 请求超时（秒） | 30 |
| `mcp.request.retry-count` | 查询类请求最大重试次数 | 1 |
| `mcp.response.max-length` | 响应截断长度（字符） | 8000 |
