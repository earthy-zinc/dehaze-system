# MCP 能力网关 - 后端实现设计（架构与公共）

## 1. 文档概述

本文档描述 MCP 能力网关的整体架构设计、传输层实现、安全体系、缓存策略、可观测性与高可用设计。

**技术选型**：基于 [MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk)（`mcp.server.MCPServer`，原 FastMCP）构建。SDK 已内置 Streamable HTTP 传输、JSON-RPC 2.0 解析/路由/错误码、`@mcp.tool()` 装饰器自动生成 JSON Schema 和参数校验。网关只需实现业务层逻辑（OpenAPI 解析、请求转发、VIP 过滤、速率限制、命名空间分组、工具搜索），不重复造轮子。

| SDK 内置（无需自建） | 网关自建（业务逻辑） |
|---------------------|---------------------|
| Streamable HTTP 传输 | OpenAPI 文档解析 → MCP tool 转换（`ApiDiscoverer`） |
| JSON-RPC 2.0 解析/路由/错误码 | HTTP 请求转发 + 身份透传（`RequestForwarder`） |
| `@mcp.tool()` 装饰器 → 自动 JSON Schema + 参数校验 | VIP 工具可见性过滤（`VipAccessFilter`） |
| `@mcp.resource()` / `@mcp.prompt()` 装饰器 | 速率限制（`RateLimiter`） |
| `notifications/*` 推送 | 命名空间分组（`NamespaceBuilder`） |
| `initialize` 握手 + 能力协商 | `tools/search` 自定义方法（`ToolSearchEngine`） |

本篇覆盖跨功能域的公共架构决策：F-M07-003 认证与访问控制、F-M07-005 安全与工程化公共策略（速率限制/缓存）、F-M07-006 调用可观测性。各功能域实现详见分篇：

| 分篇文档 | 覆盖功能点 |
|---------|-----------|
| [后端实现-工具注册](./后端实现-工具注册.md) | F-M07-002 API 自动发现与工具注册 + F-M07-007 命名空间分组 + tools/search + F-M07-008 后台管理 |
| [后端实现-请求转发](./后端实现-请求转发.md) | F-M07-004 请求转发与响应转换 + F-M07-005 转发侧工程化 |

## 2. 架构设计

### 2.1 模块分层

```
MCP Python SDK（官方库，不修改）
├── MCPServer                    # 核心 Server：Streamable HTTP 传输 + JSON-RPC 2.0 处理
├── @mcp.tool()                  # 装饰器注册工具 → 自动 JSON Schema + 参数校验
├── @mcp.resource()              # 装饰器注册资源 → 自动 URI 模板解析
├── @mcp.prompt()                # 装饰器注册提示词模板
└── Middleware Pipeline          # SDK 中间件管道（认证、日志等可插拔）

网关业务层（自建，SDK 之上）
├── ApiDiscoverer                # OpenAPI 文档读取 + 解析 → 动态注册 @mcp.tool()
├── RequestForwarder             # 工具函数体内的 HTTP 请求转发逻辑（参数/响应转换 + 超时 + 重试）
├── NamespaceBuilder             # 按 OpenAPI tags 聚合 tool 生成命名空间摘要
├── ToolSearchEngine             # tools/search 实现：ES BM25 检索 + 同命名空间扩展
├── VipAccessFilter              # SDK 中间件：tools/list 过滤 + tools/call 权限校验（按 VIP 等级）
├── RateLimiter                  # SDK 中间件：令牌桶按用户+tool 维度限流
└── AuthMiddleware               # SDK 中间件：解析 Bearer Token（dhak_ 前缀），校验有效性

依赖模块
├── AuthService（认证管理）       # API Key 校验和用户身份解析
├── MemberService（会员管理）     # 查询用户 VIP 等级
└── FileService（文件管理）       # 大体积响应 URL 拼接
```

### 2.2 核心组件职责

| 组件 | 类型 | 职责 |
|------|------|------|
| `MCPServer` | SDK 内置 | 启动时加载所有 `@mcp.tool()` 注册的函数；自动生成 JSON Schema；自动参数校验；自动 JSON-RPC 2.0 处理 |
| `ApiDiscoverer` | 自建 | 读取 OpenAPI → 解析 paths → 动态生成 `@mcp.tool()` 装饰的函数 → 注册到 MCPServer |
| `NamespaceBuilder` | 自建 | 按 OpenAPI tags 聚合 tool 生成命名空间（每组 name + description + tool_count），支撑三层上下文压缩 |
| `ToolSearchEngine` | 自建 | ES BM25 检索匹配 tool + 同命名空间扩展 + ES 不可用时降级 Jaccard 关键词匹配 |
| `RequestForwarder` | 自建 | 每个 `@mcp.tool()` 函数体内部调用：LLM 参数 → HTTP 请求 → 后端响应 → MCP 格式返回 |
| `AuthMiddleware` | 自建 | 提取 Bearer Token，查询 `sys_api_key` 校验有效性，解析 userId |
| `VipAccessFilter` | 自建 | SDK 中间件：`tools/list` 按 VIP 等级过滤可见 tool，`tools/call` 校验工具访问权限 |
| `RateLimiter` | 自建 | SDK 中间件：令牌桶算法按用户+tool 维度限流 |

## 3. 基于 SDK 的工具注册流程

### 3.1 核心思路

不手动构造工具对象和列表处理器。`ApiDiscoverer` 将每个后端 API 包装为一个 `@mcp.tool()` 装饰的 Python 函数，SDK 自动完成 JSON Schema 提取和参数校验；工具函数体内部调用 `RequestForwarder` 完成 HTTP 转发。

| 阶段 | 处理方 | 产出 |
|------|--------|------|
| 工具函数生成 | ApiDiscoverer | 闭包函数：签名由 OpenAPI 参数/请求体转换，文档由 OpenAPI 描述填充，函数体调用 RequestForwarder |
| inputSchema 生成 | SDK | 从函数类型注解自动生成 JSON Schema（类型、必填、默认值） |
| 参数校验 | SDK | 调用函数前按 inputSchema 校验，失败返回 -32602 |
| tools/list | SDK | 返回工具定义（命名空间摘要/展开，详见 [后端实现-工具注册](./后端实现-工具注册.md)） |
| tools/call | SDK + RequestForwarder | 校验 → 调用函数体 → 转发后端 → 返回结果 |

### 3.2 优势

- **零样板代码**：JSON Schema 从 Python 类型注解自动生成，不需要手动维护 OpenAPI → JSON Schema 转换
- **自动校验**：SDK 在调用函数前自动按 JSON Schema 校验参数，无需自建 ParamValidator
- **无版本偏移**：SDK 跟随 MCP 规范更新，网关自动获得新版本特性

## 4. RequestForwarder 设计

RequestForwarder 是每个 `@mcp.tool()` 函数体内部调用的转发器：

```
@mcp.tool() 函数体
    ↓
RequestForwarder.forward(tool_name, arguments)
    ↓
Step 1: 查 ToolRegistry 获取该 tool 的后端 API 信息
  - HTTP method、path、参数位置（query/path/body）
    ↓
Step 2: 参数转换
  - arguments → URL query params / path placeholder / JSON body
    ↓
Step 3: 发送 HTTP 请求
  - Authorization: Bearer dhak_xxx（从 authContext 获取，AuthMiddleware 已校验）
  - 超时 30 秒、GET 请求可重试 1 次
    ↓
Step 4: 响应转换
  - HTTP 200 JSON → 返回 dict（SDK 自动序列化为 MCP result）
  - HTTP 4xx/5xx → 抛出异常（SDK 自动转为 JSON-RPC error）
  - 异步任务（返回 task_id）→ 返回 {"task_id": "xxx", "status": "processing"}
```

> 详见 [后端实现-请求转发](./后端实现-请求转发.md)。

## 5. 安全体系（SDK 中间件集成）

所有安全组件作为 SDK Middleware 插入请求管道：

```
MCPServer 请求管道
    ↓
AuthMiddleware.authenticate()
  - 提取 Authorization: Bearer dhak_xxx
  - 查询 sys_api_key WHERE revoked_at IS NULL
  - 命中 → 注入 userId 到请求上下文
  - 未命中 → 返回 JSON-RPC error(-32001, "Authentication failed")
    ↓
RateLimiter.acquire(userId, toolName)
  - 令牌桶：30 req/min/用户 + 10 req/min/tool
  - 超限 → 返回 JSON-RPC error(-32004, "Rate limited")
    ↓
VipAccessFilter 校验
  - tools/list: 按 VIP 等级过滤返回的 tool 列表
  - tools/call: 校验目标 tool 权限，无权返回 -32002（不存在）/ -32003（VIP 不足）
    ↓
@mcp.tool() 函数体执行
  - SDK 自动 JSON Schema 校验参数（-32602）
  - RequestForwarder.forward() 执行转发
```

**速率限制降级**：RateLimiter 默认基于 Redis 令牌桶；Redis 不可用时降级为内存计数器（单实例限流），保证网关可用性优先于限流精度。

### 5.1 工具可见性控制

VipAccessFilter 在 tools/list 与 tools/call 两个路径上执行 VIP 等级校验：

| 路径 | 校验逻辑 | 失败响应 |
|------|---------|---------|
| tools/list | MemberService.getVipLevel(userId) → 从 sys_member_benefit 读取可访问的 tool tags/prefix → 过滤 tool 列表 + 隐藏无权命名空间 | 静默过滤，不报错 |
| tools/call | 校验被调用 tool 是否在当前 VIP 可访问范围内 | tool 不存在 → -32002；VIP 等级不足 → -32003 |

> tools/call 校验在 AuthMiddleware 之后、RequestForwarder 之前执行，确保无权 tool 不会消耗后端资源。

### 5.2 工具管理权限

工具注册/下线/过滤规则配置属管理操作，需 `mcp:tool:manage` 权限：

| 管理操作 | 权限要求 | 说明 |
|---------|---------|------|
| 过滤规则在线配置 | `mcp:tool:manage` | 路径白名单、标签过滤、显式排除列表的在线编辑 |
| 手动刷新工具注册表 | `mcp:tool:manage` | 触发即时重新发现并返回 diff 结果 |
| 工具列表查看 | 登录用户 | 管理端查看已注册的全部 tool/resource/prompt 列表 |

定时同步（每 5 分钟自动发现）为系统行为，无需管理员权限。

### 5.3 命名空间隔离

| 隔离维度 | 说明 |
|---------|------|
| 命名空间分组 | 工具按 OpenAPI tags 自动聚合为命名空间，每个命名空间独立控制可见性 |
| VIP 等级过滤 | `tools/list` 按用户 VIP 等级过滤可见命名空间，低等级用户不可见高级工具分组 |
| 调用级校验 | `tools/call` 校验目标工具所在命名空间的访问权限，跨命名空间调用需对应 VIP 等级 |
| 隐藏策略 | 无权命名空间在 `tools/list` 中静默过滤，不暴露工具名称和描述 |

### 5.4 第三方 API 安全

网关向后端 API 转发请求时的安全控制：

| 安全项 | 说明 |
|--------|------|
| 认证透传 | 使用调用方的 API Key（`dhak_` 前缀）向后端发起请求，不使用网关自有凭证 |
| 超时控制 | HTTP 请求默认 30 秒超时，防止后端慢响应阻塞网关线程 |
| 重试策略 | 仅 GET 幂等请求可重试 1 次，写操作（POST/PUT/DELETE）不重试，避免重复执行 |
| 响应截断 | 响应体超过 `mcp.response.max-length`（默认 8000 字符）时截断，防止大响应消耗过多上下文 |
| 错误隔离 | 后端 4xx/5xx 错误转换为 JSON-RPC error 返回调用方，不暴露后端内部堆栈信息 |

### 5.5 上下文压缩安全

| 安全项 | 说明 |
|---------|------|
| 命名空间摘要完整性 | 命名空间摘要由网关从 OpenAPI tags 自动生成，调用方不可篡改摘要内容 |
| 工具搜索安全 | `tools/search` 返回的工具定义与 `tools/list` 权限过滤一致，搜索结果同样受 VIP 等级约束 |
| 预筛选隔离 | AI 对话模块的 `before_model` 钩子按意图预筛选命名空间，预筛选结果不影响网关侧的权限校验 |

## 6. 工具注册表同步

```
启动时：
  ApiDiscoverer.discoverAll()
    ↓ 读取 OpenAPI URL（配置项）
    ↓ 解析 paths → 为每个 API 生成 @mcp.tool() 函数
    ↓ 注册到 MCPServer（SDK 自动管理 tool 列表）
    ↓ NamespaceBuilder.build() → 按 OpenAPI tags 聚合生成命名空间摘要
    ↓ 存入内存缓存

定时同步（每 5 分钟）：
  ApiDiscoverer.discoverDiff()
    ↓ 重新读取 OpenAPI → 与当前注册对比
    ↓ diff: {added, removed, changed}
    ↓ 新增 API → 动态注册新的 @mcp.tool()
    ↓ 删除 API → 从 MCPServer 注销
    ↓ NamespaceBuilder.rebuild() → 重新计算分组
    ↓ 如有变更 → 推送 notifications/tools/list_changed
```

> 详见 [后端实现-工具注册](./后端实现-工具注册.md)。

## 7. 高可用设计

- **无状态**：工具列表通过定期读取 OpenAPI 重建，不依赖本地状态。基于 SDK 的 MCPServer 天然支持无状态 MCP 协议
- **多实例**：通过 Nginx/K8s 负载均衡到多个网关实例（SDK 的 Streamable HTTP 无 session 依赖）
- **多实例缓存一致性**：工具列表与命名空间摘要为各实例内存缓存，定时同步（5 分钟）保证最终一致。手动刷新触发时通过 Redis Pub/Sub 广播失效事件，各实例收到后立即重新发现并重建缓存，将不一致窗口从 5 分钟压缩到秒级
- **健康检查**：`GET /health` 返回 200，含 `{status, uptime, toolCount, lastSyncAt}`

## 8. 缓存策略

| 缓存对象 | 缓存位置 | TTL | 更新策略 |
|---------|---------|------|---------|
| Tool 列表 + 命名空间摘要 | 内存 | 5 分钟 | 定时同步 + 手动刷新（SDK 自动管理 tool 注册） |
| resource 读取结果 | Redis | 5 分钟 | key: `mcp:cache:{userId}:{toolName}:{argsHash}`，含 userId 隔离用户数据 |
| 幂等 tool 调用结果 | Redis | 5 分钟 | key: `mcp:cache:{userId}:{toolName}:{argsHash}`，仅缓存 GET 类幂等调用 |
| API Key 校验结果 | 内存 | 1 分钟 | 校验通过后缓存 userId |
| 单个工具详情 | 内存 | 5 分钟 | 随工具列表同步刷新，工具变更时与 Tool 列表同步失效 |

**结果缓存条件**（resource 读取与幂等 tool 调用）：
- 仅 GET 类幂等调用
- 仅 HTTP 200 正常响应
- 异步响应（含 task_id）不缓存
- TTL 默认 5 分钟，按数据变更频率调整（系统配置类 30 分钟）

## 9. 可观测性设计（F-M07-006）

网关复用现有日志与监控架构，不单独建表。

| 维度 | 策略 |
|------|------|
| trace_id 透传 | 网关为每次 tools/call 生成 trace_id（或透传客户端 X-Trace-Id），通过 HTTP 头 X-Trace-Id 透传至后端，串联网关→后端调用链路 |
| 应用日志 | NDJSON 结构化日志记录每次工具调用（userId、toolName、后端 path、耗时、状态码、trace_id），由 Filebeat 采集至 ELK 检索 |
| 审计日志 | 业务操作类 API 的审计由后端统一记录，网关不重复记录 |
| 监控指标 | 暴露网关维度指标：tool 调用 QPS、平均耗时、错误率（按 toolName 维度）、限流触发次数（-32004）、后端不可用次数（-32005），接入现有监控体系 |
