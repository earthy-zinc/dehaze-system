# AI 计费管理模块需求规格

## 1. 模块概述

### 1.1 模块定位

AI 计费管理是 AI 工作平台的计费基础模块，负责大语言模型对话的 Token 消耗计量、积分换算、配额管理与扣减。以**积分（credits）**为面向用户的统一计量单位，内部按模型计费比例将原始 Token 换算为积分。对齐 OpenAI/Anthropic 等主流大模型平台的预付费 + 层级限额计费模式。

### 1.2 与会员管理的关系

AI 计费管理负责 AI 对话积分的**计量与扣减逻辑**，会员管理负责 VIP 等级与权益的**配置**（各等级的日限额/月限额在 `sys_member_benefit` 中定义）。两者协作：AI 对话前由计费管理校验配额（从会员管理获取用户等级对应的限额），对话后由计费管理扣减并记录。

### 1.3 核心价值

| 价值维度 | 具体内容 |
|---------|---------|
| **统一计量** | 以积分（credits）为统一单位，用户切换模型时积分消耗自动反映成本差异 |
| **模型差异** | 按模型计费比例换算原始 Token，支持不同模型的输入/输出/缓存命中差异化定价 |
| **限额分层** | 日限额（成本控制）+ 月限额（预算控制），防异常消耗与预算管理 |
| **降级计费** | 模型路由降级时按实际使用的降级模型计费，用户不亏（降级模型通常更便宜） |
| **缓存节约** | Prompt Caching 命中时按折扣价计费，节省的积分透明展示 |
| **异常检测** | 异常 Token 消耗（突发峰值/单次超高开销）检测与告警 |

```

│  AI 对话模块  │────▶│  AI 计费管理  │────▶│  会员管理    │
│  (消耗 Token) │     │  (计量+扣减)  │     │  (VIP限额)   │
└──────────────┘     └──────┬───────┘     └──────────────┘

```

| 模块 | 依赖说明 |

## 2. 功能需求

### 2.1 积分计量 (F-MB-001)

#### 2.1.1 功能描述

将 LLM 对话的原始 Token 消耗按模型计费比例换算为积分，作为面向用户的统一计量单位。

#### 2.1.2 计量维度

| 项目 | 说明 |
|------|------|
| 计量单位 | 积分（credits），面向用户的统一计量单位 |
| 输入 Token | 用户消息 + 上下文（system prompt、长期记忆、摘要、知识库检索结果、多模态输入等） |
| 输出 Token | LLM 回复内容（含工具调用参数输出），单价通常高于输入 |
| 缓存命中 | Prompt Caching 命中时按折扣价计费（cached_rate），节省的积分 transparent 展示 |

#### 2.1.3 积分换算

```
credits = inputTokens × inputRate + cachedInputTokens × cachedRate + outputTokens × outputRate + toolCredits
```

- `inputRate`/`outputRate`/`cachedRate`：模型计费比例，从模型计费配置读取
- `credits_saved`：缓存命中的积分节省量 = `cachedInputTokens × (inputRate - cachedRate)`
- `toolCredits`：工具调用中额外消耗的 LLM Token 积分（如工具观察步骤），单独记录便于分析

#### 2.1.4 降级模型计费

模型路由降级（主模型不可用时自动切换 fallback）时的计费规则：

| 场景 | 计费模型 | 理由 |
|------|---------|------|
| 主模型正常调用 | 主模型 | 用户选择了主模型 |
| 主模型降级到 fallback | **降级模型**（更便宜） | 用户不应为服务降级多付积分 |
| 降级链（A→B→C） | 最终使用的降级模型 | 逐级降级按最终实际模型计费 |

计费记录中记录实际使用的降级模型与用户原选模型，统计可对比"用户期望成本 vs 实际成本"。

#### 2.1.5 Prompt Caching 积分节约

| 场景 | 说明 |
|------|------|
| 缓存命中 | 按 `cached_rate`（折扣价）计费，`credits_saved` 记录节省量 |
| 用户可见 | 配额消耗明细中展示"本次节省 X 积分（缓存命中）" |
| 不增加配额 | 节省的积分不退回或增加配额，仅信息展示 |

#### 2.1.6 工具调用计费分离

不同工具类型的 LLM 调用按 `bill_type` 区分记录：

| bill_type | 场景 | 计费单元 |
|-----------|------|---------|
| `message` | 用户消息的 LLM 回复 | 消息记录积分 |
| `tool_llm` | 工具推理步骤的 LLM 调用 | 计费记录工具积分 |
| `subagent` | 子智能体独立执行 | 计费记录独立积分行 |

工具执行的底层 API 配额（图像处理次数、评估次数）由底层 API 独立扣减，不在 AI 计费中重复记录。

#### 2.1.7 子智能体并行计费

多个子智能体并行执行时各自独立消耗 LLM Token：

- 每个子智能体的 LLM 调用创建独立的计费记录（按子智能体类型标记，关联同一会话）
- 主智能体汇总所有子智能体的积分消耗，更新消息的积分（消息级汇总）
- 配额扣减以消息级汇总积分为准

### 2.2 配额管理 (F-MB-002)

#### 2.2.1 功能描述

管理 AI 对话积分的限额校验与扣减，支持日限额（成本控制）和月限额（预算控制）两层。采用预扣减（pre-deduct）+ 实扣减（actual-deduct）模式，确保配额原子性和准确性。

#### 2.2.2 限额分层

| 限额类型 | 说明 | 重置周期 | 扣减方式 |
|---------|------|---------|---------|
| 日限额 | 控制单日消耗（防异常调用），各 VIP 等级差异化 | 每日 0 点 | 原子计数 + 阈值判断 |
| 月限额 | 月度预算控制，各 VIP 等级差异化 | 每月 1 日 | 原子计数 + 阈值判断 |

> **TPM/RPM**（每分钟 Token/请求数）是平台级运行时并发控制，在 API 网关层统一限制，不进 VIP 配额。

#### 2.2.3 配额扣减流程（预扣 + 实扣）

采用预扣减 + 实扣减两步模式，确保配额原子性和准确性：

1. 发送消息前**预估积分消耗**，预扣减日/月配额（不足则拒绝发送）
2. 对话完成后按**实际 Token 消耗**实扣减，**退还预扣与实际之间的差额**

> 具体实现流程（预估算法、原子扣减、差额退补计算）详见 [后端实现 §4 计费流程](./后端实现.md#4-计费流程)。

#### 2.2.4 配额不足处理

配额不足时暂停 Agent 执行并保留上下文：

```
LLM Agent 对话 → 配额检查失败
    ↓
暂停 Agent，保留对话上下文
    ↓
前端展示配额不足提示 + 升级引导
    ↓
用户升级 VIP → 配额刷新 → 恢复推理
用户等待重置 → 上下文保留至重置（或超时清理）
用户放弃 → 清除上下文
```

### 2.3 计费预估 (F-MB-003)

#### 2.3.1 功能描述

发送消息前提供积分预估，帮助用户了解本次对话的大致消耗。

#### 2.3.2 预估算法

| 预估项 | 算法 |
|--------|------|
| 预估输入 Token | 历史 10 轮平均上下文大小 × 0.8 + 当前消息 Token × 1.2（含上下文注入） |
| 预估输出 Token | 模型 max_output_tokens × 0.3（保守估计） |
| 预估积分 | estimatedInputToken × inputRate + estimatedOutputToken × outputRate |
| 预估范围 | 展示为范围："预计消耗 1000 - 3000 积分" |

#### 2.3.3 预估值展示

| 展示场景 | 内容 |
|---------|------|
| 对话发送前 | "本次对话大约消耗 1000 - 3000 积分" |
| 配额不足警告 | "本次对话预计 3000 积分，今日剩余 2500 积分，可能超额" |
| 计费明细 | 实扣积分 vs 预估积分对比（偏高/正常/偏低） |

### 2.4 异常检测与告警 (F-MB-004)

#### 2.4.1 功能描述

检测异常的 Token 消耗行为，及时告警防止恶意调用或 Bug 导致的费用失控。

#### 2.4.2 异常规则

| 异常类型 | 触发条件 | 处理方式 |
|---------|---------|---------|
| 单次超高消耗 | 单次消息积分 > 月限额 × 10% | 告警 + 记录异常标记 |
| 突发峰值 | 5 分钟内消耗 > 日限额 × 50% | 临时限流（减少 TPM）+ 告警 |
| 连续配额不足 | 24 小时内配额不足触发 > 10 次 | 告警（可能是恶意测试） |
| 空回复高消耗 | LLM 输出 0 token 但输入 > 10000 token | 告警（可能是无效 prompt） |

#### 2.4.3 告警渠道

| 渠道 | 对象 | 说明 |
|------|------|------|
| 站内通知 | 管理员 | 异常计数仪表盘 |
| 日志标记 | 系统日志 | 异常标记 + 计费明细关联查询 |
| 用户提示 | 用户 | 单次超高消耗时前端提示"本次消耗较高，建议简化需求" |

### 2.5 VIP 配额配置 (F-MB-005)

#### 2.5.1 功能描述

在会员管理的权益配置基础上扩展 AI 对话积分限额（日限额、月限额、多模态读取频次）三个字段，各 VIP 等级差异化配置。配置管理复用会员管理的权益配置功能，字段落地见[会员管理需求规格 §5](../会员管理/需求规格.md)。

#### 2.5.3 各等级建议配额

| 权益项 | 普通用户 | VIP1 | VIP2 | SVIP |
|--------|---------|------|------|------|
| AI 对话积分（日限额） | 10,000 | 50,000 | 200,000 | 1,000,000 |
| AI 对话积分（月限额） | 100,000 | 500,000 | 2,000,000 | 10,000,000 |
| 多模态视觉读取（次/会话） | 5 | 10 | 20 | 50 |

> VIP 配额字段的配置管理复用会员管理的权益配置功能，不单独开发配置界面。

---

### 2.6 计费记录与统计 (F-MB-006)

#### 2.6.1 功能描述

记录每次对话的 Token 消耗明细，区分模型降级/缓存节省/工具调用/子智能体等计费类型，支撑成本分析和异常审计。表结构见 [02-系统架构/03-数据库设计.md](../../../02-系统架构/03-数据库设计.md)（AI 对话相关表）。

#### 2.6.3 统计维度

| 统计维度 | 说明 |
|---------|------|
| 用户维度账单 | 日/月积分消耗趋势、模型分布 |
| 模型成本分析 | 按模型维度统计 token 消耗和积分开销（识别高成本模型） |
| 降级统计 | 各模型降级频率（识别不稳定的模型提供商） |
| 缓存命中率 | Prompt Caching 命中率和积分节省统计 |
| 异常消费 | 异常标记的计费记录列表和趋势 |

## 3. 与现有体系的关系

| 现有能力 | 关系 |
|---------|------|
| 月度处理/评估次数 | 继续保留，工具调用走底层 API 的配额扣减，逻辑不变 |
| 成长值体系 | 对话行为同样获得成长值（AI 对话每次 +1，上限另定） |
| 权益校验流程 | 新增 AI 对话积分日限额 + 月限额校验，工具调用配额由底层 API 校验 |
| 次数重置规则 | AI 对话积分日限额每日 0 点重置，月限额每月 1 日重置 |
