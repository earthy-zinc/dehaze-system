# AI 计费管理模块 - 后端实现设计

## 1. 文档概述

本文档描述 AI 计费管理模块的后端实现，包括积分计量与换算、配额预扣实扣管理、异常检测告警、计费统计查询。

## 2. 架构设计

### 2.1 分层架构

```
Controller 层
├── BillingController           # 配额查询、计费明细查询
└── BillingStatController       # 计费统计（管理员）

Service 层
├── BillingService              # 计费总入口（计量 + 扣减 + 记录）
├── QuotaService                # 配额管理（预扣/实扣/退还/查询）
├── EstimateService             # 积分预估
├── BillingRecordService        # 计费记录 CRUD
├── BillingAnomalyService       # 异常检测与告警
└── BillingStatService          # 计费统计（按用户/模型/降级/缓存维度）

内部组件
├── QuotaCache                  # Redis 配额缓存（日/月限额，原子操作）
├── RateProvider                # 计费比例查询（sys_ai_model 缓存）
└── AnomalyDetector             # 异常规则引擎
```

### 2.2 核心组件职责

| 组件 | 职责 |
|------|------|
| BillingService | 计费总入口：计量（Token→积分）→扣减（预扣+实扣）→记录（sys_ai_billing） |
| QuotaService | 配额原子操作（Redis INCR/DECR）、日/月限额校验、差额退还 |
| EstimateService | 基于历史 Token + 当前消息长度预估本次积分消耗 |
| RateProvider | 从 `sys_ai_model` 缓存读取计费比例，支持降级模型比例查询 |
| BillingAnomalyService | 异常规则匹配、告警触发、异常标记 |
| QuotaCache | Redis 数据结构：`ai:quota:daily:{userId}:{date}`（日）、`ai:quota:monthly:{userId}:{month}`（月） |

## 4. 计费流程

### 4.1 配额校验

```
before_agent 钩子触发配额预校验
    ↓
QuotaService.checkQuota(userId)
    ↓
获取用户 VIP 等级 → 查询 sys_member_benefit → ai_credits_daily / ai_credits_monthly
    ↓
从 Redis 读取已用配额：
  - ai:quota:daily:{userId}:{date}
  - ai:quota:monthly:{userId}:{month}
    ↓
日已用 >= 日限额？ → 返回 false（配额不足）
月已用 >= 月限额？ → 返回 false（配额不足）
    ↓
返回 true（配额充足）
```

### 4.2 预扣减

```
配额校验通过，开始预扣
    ↓
EstimateService.estimateCredits(userId, conversationId, content)
    ↓
预估输入 Token：
  - 历史上下文 Token：从 Redis 读取会话近 10 轮消息 Token 均值 × 0.8
  - 当前消息 Token：tiktoken 编码 content
  - 记忆注入 Token：估算 200
  - 工具定义 Token：估算 500
  - 预估输入 = 上下文 + 当前 + 记忆 + 工具
    ↓
预估输出 Token：模型 max_output_tokens × 0.3
    ↓
预估积分 = 预估输入 × inputRate + 预估输出 × outputRate
    ↓
QuotaService.preDeduct(userId, estimatedCredits)
  - Redis DECR 日配额
  - Redis DECR 月配额
  - 任一返回负数 → 回滚 INCR → 返回配额不足
    ↓
创建 sys_ai_message.credits = estimatedCredits（预估值）
记录 sys_ai_billing.pre_deduct = estimatedCredits
```

### 4.3 实扣减

```
after_agent 钩子触发实扣
    ↓
获取 LLM 实际 Token 用量
    ↓
RateProvider.getRates(actualModel)
    ↓
积分换算：
  actualCredits = inputTokens × inputRate
                + cachedInputTokens × cachedRate
                + outputTokens × outputRate
    ↓
差额退补：
  difference = estimatedCredits - actualCredits
  if difference > 0: Redis INCR 日/月配额 + difference（退还多扣的）
    ↓
更新 sys_ai_message.credits = actualCredits
    ↓
写入 sys_ai_billing：
  - credits = actualCredits（含 tool_credits 子智能体汇总）
  - quota_consumed = actualCredits
  - credits_saved = cachedInputTokens × (inputRate - cachedRate)
```

### 4.4 降级计费

```
模型路由降级发生时
    ↓
BillingService 获取实际降级模型（fallback_model_id 链最终成功模型）
    ↓
RateProvider.getRates(actualModel) → 降级模型的计费比例
    ↓
按降级模型比例换算积分（实际消耗 = 降级模型价格，用户不亏）
    ↓
sys_ai_billing.model = 降级模型
sys_ai_billing.actual_model = 用户原选模型（NULL 不可）
```

### 4.5 子智能体计费汇总

```
子智能体并行执行
    ↓
SubagentManager 每个子智能体独立创建计费行（bill_type=subagent）
    ↓
子智能体完成后各自写入 sys_ai_billing
    ↓
主 Agent 汇总：
  totalCredits = SUM(childBilling.credits)
  + 主 Agent 自身 message/tool_llm 计费
    ↓
更新 sys_ai_message.credits = totalCredits
配额扣减以 totalCredits 为准
```

### 4.6 异常检测

```
after_agent 钩子 + 定时任务
    ↓
AnomalyDetector.check(billingRecord)
    ↓
规则匹配：
  1. 单次超高：credits > 月限额 × 10% → 告警
  2. 突发峰值：5 分钟内总消耗 > 日限额 × 50% → 临时限流
  3. 连续不足：24 小时内配额不足触发 > 10 次 → 告警
  4. 空回复高耗：outputTokens==0 && inputTokens > 10000 → 告警
    ↓
触警处理：
  - 写入 AnomalyEvent 到 ELK（tag=ai_billing_anomaly）
  - 告警计数更新 Redis：incr ai:anomaly:count:{ruleType}:{userId}
  - 突发峰值：设置临时限流 EX 10 分钟
```

## 5. 缓存策略

| 缓存对象 | 缓存 Key | TTL | 更新策略 |
|---------|---------|------|---------|
| 日配额已用 | `ai:quota:daily:{userId}:{date}` | 至当日 0 点 | 每次预扣/实扣更新 |
| 月配额已用 | `ai:quota:monthly:{userId}:{month}` | 至当月 1 日 | 每次预扣/实扣更新 |
| 模型计费比例 | `ai:rate:{modelId}` | 30 分钟 | 模型速率更新时失效 |
| 会话 Token 均值 | `ai:ctx:avg:{conversationId}` | 10 分钟 | 每次消息完成后更新 |
| 异常告警计数 | `ai:anomaly:count:{type}:{userId}` | 24 小时 | 每次异常触发 incr |

## 6. 配置项

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `ai.billing.estimate-input-factor` | 预估输入 Token 的保守系数 | 1.2 |
| `ai.billing.estimate-output-factor` | 预估输出 Token 的保守系数 | 0.3 |
| `ai.billing.anomaly.single-high-threshold` | 单次超高阈值（月限额百分比） | 0.1 |
| `ai.billing.anomaly.burst-threshold` | 突发峰值阈值（日限额百分比） | 0.5 |
| `ai.billing.anomaly.burst-window-minutes` | 突发检测时间窗口（分钟） | 5 |
| `ai.billing.anomaly.consecutive-quota-fail` | 连续配额不足告警阈值（次） | 10 |
| `ai.billing.quota-cache.warm-up` | 配额缓存预热（首次查询加载到 Redis） | true |
