# 套餐管理模块 - 后端实现设计

## 1. 文档概述

本文档描述套餐管理模块的后端实现方案，包括数据传输对象、服务层设计、核心业务逻辑（价格计算/促销管理/优惠券/销售统计）与缓存设计。Java/Go/Python 三后端 API 契约完全一致（Java 权威，Go/Python 对齐）。

- **需求规格**：[需求规格.md](./需求规格.md)
- **API 接口**：[API接口.md](./API接口.md)
- **订单管理**：[订单管理/后端实现.md](../订单管理/后端实现.md)（订单创建/支付/退款/自动续费）

### 2.4 优惠券表单 (CouponForm) / 用户优惠券 VO (UserCouponVO)

| CouponForm 字段 | 说明 | UserCouponVO 字段 | 说明 |
|------|------|------|------|
| name/type/faceValue/threshold | 名称/类型/面值/门槛 | couponName/type/faceValue/threshold | 名称/类型/面值/门槛 |
| validType/validStart/validEnd/validDays | 有效期配置 | status | 状态（1未使用/2已使用/3已过期/4已锁定） |
| totalQty/perUserLimit | 总量/每人限领 | receiveTime/expireTime | 领取/过期时间 |
| applicableScope | 适用套餐ID列表 | usedOrderId | 使用订单ID |
| status | 启用状态 | applicableScope | 适用套餐 |

### 2.5 日均价格精度策略

三端统一：`dailyPrice = (2 * salePrice + periodDays) / (2 * periodDays)`（整数运算四舍五入到分）；`periodDays <= 0` 时返回 0。

### 2.6 计费周期显示名称

三端统一映射：`monthly → 月卡`、`quarterly → 季卡`、`yearly → 年卡`。

| calculatePrice | 价格计算（促销折扣 + 优惠券抵扣） |
| getSalesStats | 销售统计 |

### 3.2 优惠券服务 (CouponService)

| 方法 | 说明 |
|------|------|
| create/update/deleteByIds | 优惠券模板 CRUD（删除校验已使用） |
| batchDistribute | 批量发放（全部用户/指定等级/指定用户） |

> **说明**：优惠券的锁定/核销/释放逻辑内聚在[订单服务](../订单管理/后端实现.md)（下单锁定、支付核销、取消释放），不在套餐模块的 CouponService 中重复实现。

### 3.3 促销活动管理（PromotionService）

促销活动提供独立 Service/Controller，支持运营自助管理：

| 方法 | 说明 |
|------|------|
| getPage | 后台分页查询活动（按类型/状态/时间筛选） |
| save / update | 创建/修改活动 |
| updateStatus | 上架/下架；**变更后联动失效所有关联套餐的 `package:detail:{id}` 缓存**（详情含 activePromotions 字段） |
| deleteByIds | 删除活动（校验关联套餐） |
| bindPackages | 维护活动-套餐关联关系；**变更后联动失效关联套餐的 `package:detail:{id}` 缓存** |
| 计算促销折扣 | 遍历套餐关联的进行中活动，按 percent/fixed/full_reduction 计算折扣，取最大折扣值 |
| 查询进行中活动 | 套餐详情展示活动列表（仅 status=1 且时间在活动期内） |
| 下架保护 | 套餐下架前查询进行中活动，存在则拒绝 |
| 新用户校验 | 购买 `new_user` 活动关联套餐时校验购买者无历史付费订单 |

## 4. 核心业务逻辑

### 4.1 套餐新增逻辑

1. **参数校验**：促销价 ≤ 原价（否则"促销价不能高于原价"）；周期为 monthly/quarterly/yearly 之一（否则"计费周期非法"）
2. **名称唯一校验**：查询同名记录（**含软删行**），命中即抛"套餐名称已被历史记录占用，无法重复创建"（DATA_EXISTS）
3. **默认状态**：`status` 缺省为 0（下架）
4. **销量初始化**：sales_count = 0
5. **权益覆盖序列化**：benefit_overrides 存 JSON
6. **缓存失效**：删除在售列表缓存

### 4.2 套餐修改逻辑

1. 存在性校验（不存在抛套餐不存在）
2. 参数校验（同新增）
3. 名称唯一校验：**仅当名称发生变更时**查重
4. 字段更新：name/levelCode/period/periodDays/originalPrice/salePrice/description/benefitOverrides/sort（sort 仅传入时更新）
5. **忽略 form.status**：上下架状态只能通过 `updateStatus` 接口修改
6. 缓存失效：删除详情缓存

### 4.3 套餐上下架逻辑

1. 存在性校验
2. **下架促销校验（事务内）**：status=0 时开启事务，在事务内查询进行中活动（promotion.status=1 且当前时间在活动期），存在则抛"套餐参与进行中促销活动，无法下架"；校验通过后于同一事务内更新 status，避免校验与更新之间存在活动绑定导致的 TOCTOU 竞态
3. 缓存失效

### 4.4 套餐删除逻辑

1. 存在性校验（单个校验，任一不存在即抛）
2. **订单关联校验**：统计该套餐关联的订单实体记录数，>0 抛"套餐已存在订单，无法删除"
3. 逻辑删除（deleted=1）
4. 缓存失效

### 4.5 价格计算逻辑（calculatePrice）

只读预览接口，按以下步骤计算应付金额：

1. **读取套餐促销价**：以套餐促销价作为计算基数。
2. **新用户专享校验**：若套餐关联 new_user 类型活动，校验购买者无历史付费订单，否则抛"该套餐仅限新用户购买"。
3. **促销折扣计算**：遍历促销-套餐关联实体中 status=1 且时间有效的活动，按活动类型计算折扣——percent 按比例、fixed 按固定金额、full_reduction 按满减门槛（多档位取命中最高档）；同时段多活动不叠加，取最大折扣值为 discount_amount。
4. **优惠券抵扣**（userCouponId 非空时）：校验券实例归属本人且状态为未使用/已锁定、模板启用且适用套餐包含当前套餐、有效期未过；按类型抵扣——full_reduction 满减、discount 比例、no_threshold 面值；trial 类型不走价格计算，直接激活权益。抵扣金额超过促销后价时截断为促销后价。
5. **计算应付金额**：应付金额 = 促销价 - 促销折扣 - 优惠券抵扣，结果为负时按 0 处理。
6. **返回计算明细**：包含促销价、折扣明细、优惠券抵扣、应付金额，供前端预览展示。

> **价格快照与下单一致性**：calculatePrice 仅用于前端预览；订单创建时须在**事务内重新调用同一计算逻辑**生成明细，并将计算明细与套餐 ID/等级/周期/有效期写入订单快照字段，支付按快照金额收款（见 [订单管理后端实现](../订单管理/后端实现.md)）。续费叠加校验最大有效期 1095 天，超限拒绝。

### 4.6 优惠券领取逻辑（receive）

1. **模板校验**：券存在且启用（status=1）
2. **有效期校验**：fixed 类型且当前时间超过 valid_end → 已过期
3. **频率限制**：Redis INCR `coupon:receive:rate:{userId}`（限频 5 次/60 秒，可配置），超限抛限流
4. **限领校验**：用户已领数量 < per_user_limit，否则抛"超过每人限领数量"
5. **库存乐观锁**：`UPDATE sys_coupon SET issued_qty=issued_qty+1 WHERE id=? AND status=1 AND (total_qty=-1 OR issued_qty<total_qty)`，0 行影响抛"优惠券已领完"
6. **生成实例**：插入 sys_user_coupon，计算 expire_time（relative → receive_time + valid_days；fixed → valid_end）
7. **事务保证**：库存扣减与实例生成同一事务

### 4.7 批量发放逻辑（batchDistribute）

1. 校验券存在且启用
2. **解析目标用户**：all（全部启用用户）/ level（指定等级会员）/ users（指定用户）
3. **分批处理**：目标用户按 500/批分页加载，每批独立事务执行发放（避免长事务锁竞争）；"all" 场景异步执行，接口立即返回任务 ID，结果通过任务查询获取
4. 逐用户发放：重复执行领取逻辑中的限领/库存校验，单用户失败记 failCount 不中断
5. 返回成功/失败数量

### 4.8 销售统计逻辑（getSalesStats）

1. **订单过滤**：仅统计 status in (2,3)（已支付/已完成）的订单，排除退款中/已退款
2. **总额**：totalSales = 订单数；totalRevenue = SUM(paid_amount)
3. **套餐维度**：按 package_id 分组统计销量与实付金额
4. **等级维度**：按订单 package_level 分组，等级名称关联权益配置
5. **周期维度**：JOIN 套餐表按 period 分组（月/季/年）
6. **优惠券统计**：totalIssued = Σissued_qty、totalUsed = Σused_qty、usageRate = used / issued（无发放时 0）

## 5. 缓存设计

| 缓存对象 | 缓存 Key | 过期时间 | 实现端 |
|---------|---------|---------|--------|
| 在售套餐列表 | package:onsale | 5 分钟 | Python 端 |
| 套餐详情 | package:detail:{id} | 10 分钟 | Python 端 |
| 套餐缓存失效 | 套餐变更或关联促销活动变更时删除对应 Key | - | Python 端（Java 端无套餐缓存） |

> **说明**：Java 端套餐查询无缓存（直查数据库）；Python 端缓存不可用时通过 Redis 降级回退逻辑直查。**无**促销活动/用户优惠券缓存（早期设计稿内容未实现）。
