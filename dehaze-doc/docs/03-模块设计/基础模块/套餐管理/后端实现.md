### 3.4 核心业务逻辑

#### 套餐新增逻辑

1. **参数校验**：名称唯一、价格规则、周期匹配
2. **价格存储**：分单位 bigint
3. **权益覆盖处理**：`benefit_overrides` JSON 序列化
4. **默认状态**：status=0（下架）
5. **缓存刷新**：清除套餐列表缓存

#### 价格计算逻辑

```
读取套餐价格（sale_price）
    ↓
查询促销活动（限时折扣/满减）
    ├─ 有活动 → 计算促销折扣金额
    └─ 无活动 → discount_amount=0
    ↓
查询优惠券（如使用）
    ├─ 满减券 → 校验门槛 → coupon_amount=face_value
    ├─ 折扣券 → coupon_amount = payable × (1 - face_value/100)
    └─ 无门槛券 → coupon_amount=face_value
    ↓
计算应付金额 = sale_price - discount_amount - coupon_amount
    ↓
校验应付金额 ≥ 0
```

#### 优惠券领取逻辑

1. **状态校验**：券 status=1（启用）
2. **库存校验**：total_qty ≠ -1 时检查 issued_qty &lt; total_qty
3. **限领校验**：查询用户已领数量 &lt; per_user_limit
4. **频率限制**：Redis 计数（每用户每分钟 ≤5 次）
5. **乐观锁扣减库存**：`UPDATE sys_coupon SET issued_qty = issued_qty + 1 WHERE id = ? AND issued_qty < total_qty`
6. **生成实例**：插入 `sys_user_coupon`，计算 expire_time
7. **事务保证**：库存扣减与实例生成同一事务

#### 优惠券过期处理（定时任务）

1. 扫描 `sys_user_coupon` WHERE `expire_time < NOW() AND status = 1`
2. 批量更新 status=3（已过期）

### 3.5 事务管理

| 操作类型 | 事务级别 | 说明 |
|---------|---------|------|
| 查询操作 | 只读事务 | 优化性能 |
| 套餐CRUD | 读写事务 | 单表操作 |
| 优惠券领取 | 读写事务 | 库存扣减+实例生成 |
| 优惠券核销 | 读写事务 | 状态变更+订单关联 |
| 促销活动关联 | 读写事务 | 多表操作 |

## 4. 数据访问层设计

### 4.1 查询优化

#### 在售套餐查询

- 索引 `idx_status` 过滤上架套餐
- 关联查询促销活动（LEFT JOIN）

#### 优惠券库存扣减

- 乐观锁：`WHERE issued_qty < total_qty` 条件更新
- 失败重试 3 次

### 4.2 缓存策略

| 缓存对象 | 缓存 Key | 过期时间 | 更新策略 |
|---------|---------|---------|---------|
| 在售套餐列表 | package:onsale | 5 分钟 | 套餐变更时删除 |
| 套餐详情 | package:detail:{id} | 10 分钟 | 修改时删除 |
| 进行中促销 | promotion:active | 5 分钟 | 活动变更时删除 |
| 用户优惠券 | coupon:user:{userId} | 5 分钟 | 领取/使用时删除 |

## 7. 安全设计

### 7.1 防护机制

| 防护项 | 实现方式 |
|--------|---------|
| 价格防篡改 | 订单创建时后端重新校验套餐价格 |
| 优惠券防刷 | 领取频率限制（每用户每分钟 ≤5 次） |
| 库存并发控制 | 乐观锁 + Redis 原子操作 |
| 防重复提交 | 自定义注解 + Redis 分布式锁 |
