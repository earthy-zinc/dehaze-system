### 2.8 日均价格精度策略

`PackagePageVO.dailyPrice` 与 `PackageDetailVO.dailyPrice` 字段（Long，单位：分）的计算口径三端统一如下：

- **计算公式**：`dailyPrice = round(salePrice / periodDays)`，四舍五入到分（long）。
- **`periodDays ≤ 0` 时**：返回 0，避免除零。
- **三端统一实现**（整数四舍五入，避免浮点精度问题）：
    - Java：`(2 * salePrice + periodDays) / (2 * periodDays)`
    - Python：`(2 * sale_price + period_days) // (2 * period_days)`
    - Go：`(2*salePrice + int64(periodDays)) / (2 * int64(periodDays))`
- **示例**：年卡 `salePrice=960 分`、`periodDays=365`，日均 `960/365=2.63`，四舍五入后 `dailyPrice=3 分`。

### 2.9 PackageForm 字段校验规则

三端 form/schema 层对 `PackageForm` 字段校验统一如下（校验失败抛 `PARAM_ERROR`，关系校验在 service 层 `validatePackageForm` 中执行）：

| 字段 | 类型 | 必填 | 校验规则 |
|------|------|------|---------|
| id | Long | 否 | 无 |
| name | String | 是 | 长度 2-32 |
| levelCode | String | 是 | 非空 |
| period | String | 是 | 枚举：monthly/quarterly/yearly |
| periodDays | Integer | 是 | 1-365 |
| originalPrice | Long | 是 | ≥1 |
| salePrice | Long | 是 | ≥1（且 ≤ originalPrice，关系校验在 service 层） |
| description | String | 否 | 长度 ≤256 |
| benefitOverrides | JSON | 否 | 无 |
| sort | Integer | 否 | 0-999 |
| status | Integer | 否 | 0 或 1 |

**三端实现**：
- Java：`jakarta.validation` 注解（`@Size`、`@Min`、`@Max`、`@Pattern`、`@NotBlank`、`@NotNull`）
- Python：`pydantic.Field`（`min_length`、`max_length`、`ge`、`le`）+ `Literal` 枚举
- Go：`binding` 标签（`required`、`min`、`max`、`oneof`、`omitempty`）

### 3.4 核心业务逻辑

#### 套餐新增逻辑

1. **参数校验**：
    - 价格规则：`salePrice ≤ originalPrice`，否则抛 PARAM_ERROR
    - 计费周期：`period` 必须为 `monthly`/`quarterly`/`yearly` 之一，否则抛 PARAM_ERROR
2. **名称唯一性校验**：查询 `sys_package` 同名记录，存在则抛 DATA_EXISTS
3. **价格存储**：分单位 bigint
4. **权益覆盖处理**：`benefit_overrides` JSON 序列化
5. **默认状态**：强制 `status=0`（下架），忽略前端传入的 status 值，需手动上架
6. **缓存刷新**：清除套餐列表缓存

#### 套餐修改逻辑

1. **存在性校验**：套餐不存在抛 PACKAGE_NOT_FOUND
2. **参数校验**：同新增，`salePrice ≤ originalPrice`、`period` 必须为 `monthly`/`quarterly`/`yearly`
3. **名称唯一性校验**：当 name 发生变更时，查询是否存在同名且 id 不同的记录，存在则抛 DATA_EXISTS
4. **字段更新**：name、levelCode、period、periodDays、originalPrice、salePrice、description、benefitOverrides、sort（仅在 form 传入时更新）；**忽略 form.status**，上下架状态只能通过 updateStatus 接口修改
5. **缓存刷新**：清除套餐详情缓存

#### 套餐上下架逻辑

1. **存在性校验**：套餐不存在抛 PACKAGE_NOT_FOUND
2. **下架促销校验**：`status=0`（下架）时，查询 `sys_promotion_package` 关联的进行中促销活动（`promotion.status=1` 且当前时间在 `start_time`~`end_time` 之间），存在则抛 PACKAGE_IN_PROMOTION
3. **更新状态**：更新 `sys_package.status`
4. **缓存刷新**：清除套餐详情缓存

#### 套餐删除逻辑

1. **存在性校验**：套餐不存在抛 PACKAGE_NOT_FOUND
2. **订单关联校验**：查询 `sys_order` 表 `package_id = id` 的订单数量，存在则抛 PACKAGE_HAS_ORDERS
3. **逻辑删除**：批量场景逐个校验，全部通过后执行逻辑删除（`deleted=1`）
4. **缓存刷新**：清除套餐列表与详情缓存

#### 价格计算逻辑

```
读取套餐价格（sale_price）
    ↓
查询促销活动（限时折扣/满减）
    ├─ 遍历套餐关联的进行中活动（status=1 且在有效期内）
    ├─ percent 类型 → discount = sale_price × discount_value / 100
    ├─ fixed 类型 → discount = discount_value
    └─ 取所有活动中的最大折扣值作为 discount_amount
    ↓
查询优惠券（如使用）
    ├─ 校验用户券状态 ∈ {1, 4}，否则抛 COUPON_ALREADY_USED
    ├─ 校验未过期（expire_time ≥ NOW()），否则抛 COUPON_EXPIRED
    ├─ 校验适用套餐范围，否则抛 COUPON_NOT_APPLICABLE
    ├─ 计算基数 = sale_price - discount_amount
    ├─ 满减券 → 校验门槛 → coupon_amount = face_value
    ├─ 折扣券 → coupon_amount = 基数 × (100 - face_value) / 100
    ├─ 无门槛券 → coupon_amount = face_value
    └─ 体验券 → coupon_amount = 基数
    ↓
计算应付金额 = sale_price - discount_amount - coupon_amount
    ↓
校验应付金额 ≥ 0（小于 0 则取 0）
```

#### 优惠券领取逻辑

1. **状态校验**：券 status=1（启用）
2. **库存校验**：total_qty ≠ -1 时检查 issued_qty &lt; total_qty
3. **限领校验**：查询用户已领数量 &lt; per_user_limit
4. **频率限制**：Redis 计数（每用户每分钟 ≤5 次）
5. **乐观锁扣减库存**：`UPDATE sys_coupon SET issued_qty = issued_qty + 1 WHERE id = ? AND issued_qty < total_qty`
6. **生成实例**：插入 `sys_user_coupon`，计算 expire_time
7. **事务保证**：库存扣减与实例生成同一事务

#### 优惠券过期处理（定时任务）

1. 扫描 `sys_user_coupon` WHERE `expire_time < NOW() AND status = 1`
2. 批量更新 status=3（已过期）

#### 销售统计逻辑

1. **订单状态过滤**：仅统计 `sys_order.status in (2, 3)` 的订单（已支付、已完成），排除退款订单（5=退款中、6=已退款）
2. **收入计算**：`totalRevenue = SUM(sys_order.paid_amount)`，按过滤后的订单求和（非 `sales_count × sale_price` 估算）
3. **套餐维度统计**：按 `package_id` 分组统计订单数与 `paid_amount` 求和
4. **等级维度统计**：按订单的 `package_level` 分组统计订单数与 `paid_amount` 求和
5. **周期维度统计**：`sys_order` JOIN `sys_package` 按 `period` 分组统计订单数与 `paid_amount` 求和，`periodName` 取 `月卡/季卡/年卡`（对应 monthly/quarterly/yearly）
6. **优惠券统计**：`totalIssued = SUM(sys_coupon.issued_qty)`、`totalUsed = SUM(sys_coupon.used_qty)`、`usageRate = totalUsed / totalIssued`

## 4. 数据访问层设计

### 4.1 查询优化

#### 在售套餐查询

- 索引 `idx_status` 过滤上架套餐
