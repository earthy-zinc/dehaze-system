## 3. 测试前置

### 3.1 测试数据

| 数据类型 | 准备内容 | 说明 |
|---------|---------|------|
| **套餐数据** | 各等级（VIP1/VIP2/SVIP）、各周期（月/季/年）套餐 | 覆盖完整套餐矩阵 |
| **状态套餐** | 在售、下架套餐各若干 | 用于上下架测试 |
| **促销活动** | 各类型活动（限时折扣/新用户专享/节日促销/满减） | 用于促销测试 |
| **优惠券** | 各类型券（满减/折扣/无门槛/体验券），含不同库存状态 | 用于券测试 |
| **用户优惠券** | 不同状态（未使用/已使用/已过期/已锁定） | 用于券实例查询 |

### 3.2 数据清理策略

- 测试套餐使用统一前缀 `test_pkg_` 标识
- 测试优惠券使用统一前缀 `测试券-` 标识
- 测试结束按前缀清理套餐、促销活动、优惠券模板与实例

### 3.3 测试范围

**包含的功能点：**
- 套餐列表查询（用户端/后台）
- 套餐CRUD与上下架
- 促销活动管理
- 优惠券管理（创建/发放/领取/查询）
- 销售统计

**不包含的功能点：**
- 订单创建与支付（订单模块测试）
- 会员等级变更（会员模块测试）
- 优惠券核销（订单模块测试）

| T-PM-085 | 异常：优惠券已过期 | 用户券 expire_time &lt; NOW() | GET /calculate-price?userCouponId=10 | 抛 COUPON_EXPIRED | P0 |
| T-PM-086 | 异常：券不适用该套餐 | coupon.applicable_scope 不含 packageId | GET /calculate-price?packageId=1&userCouponId=10 | 抛 COUPON_NOT_APPLICABLE | P0 |
| T-PM-087 | 边界：应付金额非负 | 折扣+券抵扣超过 salePrice | GET /calculate-price | payableAmount=0（不出现负数） | P0 |
| T-PM-088 | 异常：套餐不存在 | packageId 无效 | GET /calculate-price?packageId=999 | 抛 PACKAGE_NOT_FOUND | P1 |

## 5. 关键边界与异常场景

| 场景 | 测试点 | 期望行为 |
|------|--------|---------|
| **套餐数量边界** | 套餐达到100+ | 列表查询响应时间仍&lt;500ms |
| **价格计算边界** | 套餐原价/促销价/优惠券叠加 | 后端重新校验，不信任前端金额 |
| **优惠券并发领取** | 100用户同时领取1张券 | 乐观锁保护，仅1人成功 |
| **上下架并发** | 同时上架和下架同一套餐 | 状态最终一致，无脏数据 |
| **促销活动时间切换** | 多个活动时间重叠 | 允许但订单仅能用一张券 |
| **缓存与DB一致性** | 套餐修改后 | Redis 缓存主动刷新 |

## 7. 安全性测试

| 测试项 | 验证方式 | 预期结果 |
|--------|---------|---------|
| **价格防篡改** | 前端传入修改后的金额 | 后端重新校验套餐价格，不信任前端 |
| **优惠券防刷** | 高频领取 | 频率限制（每用户每分钟 ≤5 次） |
| **权限控制** | 无权限用户调用套餐CRUD接口 | 返回403 |
| **SQL注入** | 参数中包含 `1' OR '1'='1` | 参数化查询转义 |
| **XSS攻击** | 套餐名称注入脚本 | 输出时编码 |
| **库存并发控制** | 并发扣减优惠券库存 | 乐观锁或 Redis 原子操作 |
| **防重复提交** | 快速连续点击提交 | Token机制防护，仅执行一次 |
