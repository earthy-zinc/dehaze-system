## 2. 架构设计

### 2.1 模块定位

收藏管理模块为系统提供统一的收藏能力基础设施。通过统一的 `sys_favorite` 表和通用接口为所有可收藏对象提供一致的收藏体验，替代各模块自行实现的独立收藏逻辑。

### 2.2 模块分层架构

| 层级 | 组件 | 职责 |
|------|------|------|
| Controller 层 | FavoriteController | 收藏操作（添加/取消/列表/状态查询/计数） |
| Service 层 | FavoriteService | 收藏核心服务（添加/取消/列表查询/状态批量查询/计数） |
| 数据层 | FavoriteRepository | `sys_favorite` 表数据访问 |

### 2.3 核心组件职责

| 组件 | 职责描述 | 关键能力 |
|------|---------|---------|
| FavoriteService | 收藏核心服务 | 添加/取消收藏、收藏列表查询（分页/筛选/排序）、收藏状态批量查询、收藏计数、VIP 容量校验、失效对象标记 |

## 3. 数据模型设计

> 表结构权威定义详见 [03-数据库设计.md](../../../02-系统架构/03-数据库设计.md) 及 `config/sql/schema/sys_favorite.sql`

### 3.1 统一收藏表（sys_favorite）

**设计决策**：通过 `target_type` + `target_id` 实现多态收藏，支持 algorithm/result/dataset 等任意业务实体，避免为每种收藏对象维护独立收藏表。

**核心约束**：

| 约束 | 类型 | 说明 |
|------|------|------|
| (user_id, target_type, target_id) | UNIQUE | 同一用户对同一对象只能收藏一次 |
| target_type | VARCHAR(32) | 收藏对象类型（algorithm/result/dataset/image/preset） |
| deleted | TINYINT | 逻辑删除标识，支持用户取消后重新收藏的历史追溯 |

**索引设计**：

| 索引名 | 字段 | 用途 |
|--------|------|------|
| uk_user_target | (user_id, target_type, target_id) | 唯一约束 + 收藏状态查询 |
| idx_user_type_time | (user_id, target_type, create_time DESC) | 按类型筛选的收藏列表分页查询 |

### 3.2 收藏对象类型

| 类型编码 | 类型名称 | 来源模块 | 状态 |
|---------|---------|---------|:----:|
| `algorithm` | 算法 | 算法选择/算法管理 | 实现 |
| `result` | 处理结果 | 去雾处理/效果对比 | 实现 |
| `dataset` | 数据集 | 数据集管理 | 实现 |
| `image` | 图片 | 图像输入 | 预留 |
| `preset` | 参数方案 | 去雾处理 | 预留 |

## 4. 核心业务流程

### 4.1 收藏操作

| 步骤 | 说明 | 异常处理 |
|------|------|---------|
| 1. 容量校验 | 查询用户当前收藏数，与 VIP 等级对应上限比较 | 超限返回 `A0500`，提示升级 VIP |
| 2. 写入收藏记录 | 插入 `sys_favorite`，依赖唯一约束防重 | 唯一约束冲突视为"已收藏"，幂等返回成功 |
| 3. 失效缓存 | 清除用户收藏数量缓存、收藏状态缓存 | - |

### 4.2 取消收藏

| 步骤 | 说明 |
|------|------|
| 1. 逻辑删除 | 更新 `sys_favorite.deleted = 1`（WHERE user_id + target_type + target_id） |
| 2. 失效缓存 | 清除用户收藏数量缓存、收藏状态缓存 |

### 4.3 收藏列表查询

| 步骤 | 说明 |
|------|------|
| 1. 分页查询 | 按 user_id + target_type（可选）查询 `sys_favorite` 分页数据，支持按收藏时间排序 |
| 2. 对象摘要聚合 | 根据 target_type 批量查询收藏对象摘要信息（algorithm → 算法名/评分/类型；result → 缩略图/算法名/处理时间；dataset → 名称/图片数量/描述） |
| 3. 失效标记 | 标记 `is_invalid=1` 的对象为"已失效"，前端展示失效样式 |
| 4. 返回列表 | 返回带对象摘要和失效标记的收藏列表 |

### 4.4 收藏状态批量查询

各业务模块加载列表时，通过批量查询接口获取当前用户的收藏状态：

| 步骤 | 说明 |
|------|------|
| 1. 查询已收藏 ID | 按 user_id + target_type + target_id IN(...) 查询，返回当前用户已收藏的对象 ID 集合 |
| 2. 状态映射 | 业务模块将 ID 集合转为 Map<targetId, Boolean>，用于前端图标状态渲染 |

## 5. VIP 容量限制

### 5.1 容量规则

| 会员等级 | 收藏容量上限 |
|---------|------------|
| 普通用户 | 200 条 |
| VIP 用户 | 500 条 |

### 5.2 容量校验

| 校验时机 | 校验逻辑 | 失败处理 |
|---------|---------|---------|
| 收藏操作前 | 统计用户未删除收藏数，与会员等级对应上限比较 | 超限返回 `A0500`，引导升级 VIP |

---

## 6. 失效对象处理

### 6.1 失效场景

| 场景 | 处理方式 |
|------|---------|
| 算法被逻辑删除 | 收藏条目标记 `is_invalid=1`，列表中显示"已失效" |
| 算法被物理删除 | 级联删除关联收藏条目 |
| 处理结果被清理 | 收藏条目标记 `is_invalid=1` |
| 数据集被删除 | 收藏条目标记 `is_invalid=1` |

### 6.2 清理策略

| 操作 | 说明 |
|------|------|
| 用户手动清理 | 用户可在收藏列表中选择清理失效收藏 |
| 一键清理 | 提供"清理已失效"按钮，批量逻辑删除所有 `is_invalid=1` 的收藏条目 |

## 7. 模块间协作

### 7.1 被依赖模块

| 模块 | 集成方式 | 收藏类型 |
|------|---------|---------|
| 算法选择 | FavoriteService.favorite(userId, "algorithm", algorithmId) | algorithm |
| 去雾处理/效果对比 | FavoriteService.favorite(userId, "result", recordId) | result |
| 数据集管理 | FavoriteService.favorite(userId, "dataset", datasetId) | dataset |

### 7.2 依赖模块

| 模块 | 依赖说明 |
|------|---------|
| 会员管理 | 查询用户会员等级对应的收藏容量上限 |

### 7.3 为推荐引擎提供数据

收藏行为作为用户偏好的强正向信号，推荐管理模块通过查询收藏数据获取用户偏好：

| 数据维度 | 说明 |
|---------|------|
| 算法类型分布 | 用户收藏的算法按类型聚合，反映用户算法偏好 |
| 收藏时间分布 | 用户收藏行为的时间趋势，反映近期兴趣 |
| 收藏频率 | 用户收藏活跃度，作为推荐权重调节因子 |

## 8. 缓存设计

| 缓存对象 | 缓存 Key | TTL | 更新策略 |
|---------|---------|------|---------|
| 用户收藏数量 | `favorite:count:{userId}` | 10 分钟 | 收藏/取消时失效 |
| 用户收藏状态集合 | `favorite:status:{userId}:{targetType}` | 10 分钟 | 收藏/取消时失效 |

**收藏状态集合存储格式**：Value 为当前用户在该 target_type 下已收藏的 target_id 集合（Set 结构），支持 O(1) 判断单个对象收藏状态和 O(N) 批量判断。
