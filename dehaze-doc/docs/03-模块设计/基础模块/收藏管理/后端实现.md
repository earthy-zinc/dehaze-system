## 2. 架构设计

### 2.1 模块定位

收藏管理模块为系统提供统一的收藏能力基础设施。通过统一的 `sys_favorite` 表和通用接口为所有可收藏对象提供一致的收藏体验，替代各模块自行实现的独立收藏逻辑。

### 2.2 模块分层架构

| 层级 | 组件 | 职责 |
|------|------|------|
| Controller 层 | FavoriteController（Java）/ favorite router（Python）/ favorite.go（Go） | 收藏操作（添加/取消/列表/状态/计数） |
| Service 层 | FavoriteService | 收藏核心服务（添加/取消/列表查询/状态查询/计数/容量校验/失效标记） |
| 数据层 | SysFavoriteMapper（Java）/ favorite_repository（Python）/ favorite_repository（Go） | `sys_favorite` 表数据访问 |

> **三端一致性**：三端均基于统一 `sys_favorite` 表实现，Go 端无独立算法收藏表；表结构、业务逻辑与 API 契约一致（Java 权威，Go/Python 对齐）。

### 2.3 核心组件职责

| 组件 | 职责描述 | 关键能力 |
|------|---------|---------|
| FavoriteService | 收藏核心服务 | 添加/取消收藏、收藏列表分页查询（类型筛选/关键词搜索/时间排序）、收藏状态查询、收藏计数、会员容量校验、失效对象标记 |

## 3. 数据模型设计

> 表结构权威定义详见 [03-数据库设计.md](../../../02-系统架构/03-数据库设计.md) 及 `config/sql/schema/sys_favorite.sql`

### 3.1 统一收藏表（sys_favorite）

**设计决策**：通过 `target_type` + `target_id` 实现多态收藏，支持 algorithm/result/dataset/image/preset 五类对象，避免为每种收藏对象维护独立收藏表。

**核心约束**：

| 约束 | 类型 | 说明 |
|------|------|------|
| (user_id, target_type, target_id) | UNIQUE | 同一用户对同一对象仅一条记录（防重 + 幂等 upsert 支撑） |
| target_type | VARCHAR(32) | 收藏对象类型（algorithm/result/dataset/image/preset） |
| is_invalid | TINYINT | 收藏对象是否已失效（对象删除时置 1） |
| deleted | TINYINT | 逻辑删除标识（取消收藏置 1，重新收藏时复活） |

**索引与约束**：表结构与索引定义见 [03-数据库设计.md](../../../02-系统架构/03-数据库设计.md) §4.6。关键约束：(user_id, target_type, target_id) 唯一约束保证收藏幂等；(user_id, target_type, create_time) 复合索引支撑按类型筛选的列表分页查询。

### 3.2 收藏对象类型

| 类型编码 | 类型名称 | 收藏校验 | 删除标记失效 |
|---------|---------|:------:|:------:|
| `algorithm` | 算法 | ✅ 存在校验 | ✅ 算法删除时触发 |
| `result` | 处理结果 | ✅ 存在校验 | ❌ |
| `dataset` | 数据集 | ✅ 存在校验 | ✅ 数据集删除时触发 |
| `image` | 图片 | ❌（预留跳过） | ❌ |
| `preset` | 参数方案 | ❌（预留跳过） | ❌ |

## 4. 核心业务流程

### 4.1 添加收藏

| 步骤 | 说明 | 异常处理 |
|------|------|---------|
| 1. 对象校验 | algorithm/dataset/result 类型校验目标存在（targetId 为空或对象不存在抛 A0401） | `A0401` 资源不存在 |
| 2. 容量校验 | 查询用户未删除收藏数，与会员等级对应上限比较（普通 200 / VIP1 500 / VIP2 1000 / SVIP 3000） | 超限抛 `A0500`，提示"收藏已达上限（X条）" |
| 3. 写入收藏 | upsert：唯一键冲突时复活软删行（deleted=0、is_invalid=0、更新收藏时间），幂等返回记录 ID | 幂等成功，无冲突错误 |

> **upsert 实现**：Java 使用 `INSERT ... ON DUPLICATE KEY UPDATE`（LAST_INSERT_ID 回填原行 id）；Python/Go 采用先查后更，并发下若另一事务先插入同一 (user_id, target_type, target_id) 触发唯一约束冲突，捕获冲突后回退复活逻辑（更新 deleted=0、is_invalid=0、收藏时间），与 Java 等价保证幂等。三端均保证"取消后重新收藏"复活原记录而非新增。
>
> **并发控制**：容量校验与 upsert 写入在同一事务内执行；并发下若他人先写入致当前用户收藏数超限，当前事务在写入前基于事务内可见计数复核容量，超限则回滚并抛 `A0500`。

### 4.2 取消收藏

| 步骤 | 说明 |
|------|------|
| 1. 逻辑删除 | 按记录 ID + 当前用户 ID 更新 `deleted=1`（越权记录不生效） |
| 2. 幂等 | 重复取消不报错（更新 0 行静默成功） |

### 4.3 收藏列表查询

| 步骤 | 说明 |
|------|------|
| 1. 分页查询 | 按 user_id + target_type（可选）分页，LEFT JOIN 业务表取对象名称 |
| 2. 名称关联 | algorithm → 算法名称；dataset → 数据集名称；其余类型名称为空（SQL 层 CASE WHEN，JOIN 条件带 deleted=0，对象删除后名称为空） |
| 3. 缩略图 | 仅 dataset 类型关联数据集缩略图；其余类型无 |
| 4. 关键词过滤 | 按算法/数据集名称 LIKE 匹配（SQL 层） |
| 5. 排序 | 仅支持按收藏时间（create_time），默认倒序；`sortBy=createTime & sortOrder=asc` 时正序，其余条件均回退倒序 |

> **说明**：当前实现**无按评分/使用频率排序**（前端传入 rating/usageCount 时后端回退按时间排序）；收藏对象摘要（targetSummary）字段预留但恒为空。

### 4.4 收藏状态查询

按 targetType + targetId 查询当前用户是否存在未删除记录，返回已收藏/未收藏状态（前端图标状态判断）。

### 4.5 收藏数量统计

按收藏类型分组统计当前用户各类型收藏数，固定返回五类（algorithm/result/dataset/image/preset，数量为 0 也返回），支持按单类型过滤。

## 5. 会员容量阶梯

### 5.1 容量规则

| 会员等级 | 等级编码 | 收藏容量上限 |
|---------|---------|------------|
| 普通用户 | level_0 | 200 条 |
| VIP1 | level_1 | 500 条 |
| VIP2 | level_2 | 1000 条 |
| SVIP | level_3 | 3000 条 |

### 5.2 容量校验

| 校验时机 | 校验逻辑 | 失败处理 |
|---------|---------|---------|
| 收藏操作前 | 统计用户未删除收藏数，与会员等级对应上限比较 | 超限抛 `A0500`，引导升级会员 |

> **实现说明**：容量上限为三端代码常量（`DEFAULT_CAPACITY=200` / `VIP1_CAPACITY=500` / `VIP2_CAPACITY=1000` / `SVIP_CAPACITY=3000`），按用户当前会员等级实时判断（升级后容量立即扩展）；**非配置文件可调项**。

## 6. 失效对象处理

### 6.1 失效标记（markInvalid）

| 触发场景 | 触发方 | 说明 |
|---------|--------|------|
| 算法被删除（含级联删除） | 算法管理模块删除算法时调用 | 相关收藏条目标记 `is_invalid=1` |
| 数据集被删除（含级联删除） | 数据集管理模块删除数据集时调用 | 相关收藏条目标记 `is_invalid=1` |

### 6.2 失效展示

收藏列表返回 `is_invalid` 字段，前端卡片展示"已失效"标签并禁用跳转；用户可手动取消收藏失效条目。

> **说明**：对象删除为逻辑删除，收藏记录**保留**（无物理级联删除）；处理结果类型当前**无失效标记**；**无"一键清理失效"接口/按钮**。
