# 消息通知模块测试用例

## 1. 测试目标

- [x] 验证核心功能符合需求规格（消息接收、列表展示、已读管理、删除、搜索、通知设置、公告管理）
- [x] 覆盖正常流程、边界条件、异常分支
- [x] 验证消息推送的多渠道触达与降级策略
- [x] 验证幂等去重与消息不丢失
- [x] 验证权限控制与数据隔离
- [x] 验证过期清理与生命周期管理

---

## 3. 测试前置

### 3.1 测试数据

| 数据类型 | 准备内容 | 说明 |
|---------|---------|------|
| **用户数据** | 普通用户、管理员各至少1名 | 用于权限验证和消息接收测试 |
| **消息数据** | 各类型消息（站内信/公告/业务/会员/告警）各若干条 | 用于列表查询、筛选测试 |
| **公告数据** | 各状态公告（草稿/待发送/已发送/已取消） | 用于公告管理测试 |
| **模板数据** | 至少3个消息模板（启用/禁用） | 用于模板管理测试 |

### 3.2 数据清理策略

- 测试消息使用 `biz_module='test'` 标识，测试结束后按前缀批量删除
- 测试公告使用标题前缀 `test_` 标识，测试结束后按前缀批量删除
- 测试通知设置在测试结束后恢复为默认值

### 3.3 测试范围

**包含的功能点：**
- 消息列表查询（分页、筛选、排序）
- 消息详情查看与已读管理
- 消息删除（单条/批量）
- 消息搜索
- 通知偏好设置（推送开关、免打扰、模块开关）
- 系统公告管理（CRUD、发送、取消）
- 消息模板管理（查看、编辑）
- 内部消息发送接口（幂等去重）
- 未读消息数查询

**不包含的功能点（未实现/外部依赖）：**
- APP推送真实送达测试（`PushChannel.doPush` 未接真实推送平台，仅记录日志）
- 邮件/短信网关测试（EmailChannel/SmsChannel isAvailable=false，未接入外部服务）
- 渠道失败重试（无重试机制，失败仅记录日志）
- 重要公告置顶（消息排序无 importance 置顶逻辑）
- 内容过滤（敏感词过滤未实现）、推送频率限制（未实现）
- 内部接口 API Key 鉴权（无，登录即可）
- WebSocket 连接测试（依赖基础设施）

## 5. 关键边界与异常场景

| 场景 | 测试点 | 期望行为 |
|------|--------|---------|
| **消息量边界** | 单用户消息达10000+ | 列表查询响应时间仍&lt;500ms |
| **并发发送** | 多业务模块同时触发消息 | 消息均正确生成，无丢失 |
| **幂等去重** | 同一业务事件重复触发 | 仅生成一条消息 |
| **幂等键为NULL** | bizModule或bizId为空时发送消息 | 不防重，允许重复生成多条 |
| **推送降级** | APP推送通道不可用 | 自动降级为仅站内信，消息不丢失 |
| **免打扰跨天** | 免打扰时段22:00-08:00 | 跨天逻辑正确，22:00后至次日08:00前不推送 |
| **公告批量投递** | 全体用户公告发送 | 批量生成消息记录，sentCount正确 |
| **过期清理** | 消息过期后（expires_at < NOW()） | 定时任务物理删除，列表不再展示 |
| **过期清理-未读消息** | 未读消息到期后 | 定时任务同样物理删除，不保留至已读 |
| **过期清理-已软删除** | 消息已软删除(deleted=1)且到期 | 定时任务物理删除，无论deleted=0或1 |
| **免打扰延迟推送** | 免打扰时段结束后 | DelayedPushJob弹出messageId并调用dispatch实际推送 |
