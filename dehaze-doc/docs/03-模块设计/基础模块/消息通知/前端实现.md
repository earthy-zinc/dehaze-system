# 消息通知模块 - 前端实现设计

## 1. 文档概述

本文档描述消息通知模块的前端实现方案，包括组件设计、状态管理、API调用、实时消息推送等实现要点。

- **API 接口规范**：参见 [API接口.md](./API接口.md)
- **需求规格**：参见 [需求规格.md](./需求规格.md)
- **UI-UX 设计规范**：参见 [01-产品设计/02-UI-UX设计规范.md](../../../01-产品设计/02-UI-UX设计规范.md)

## 2. 组件架构设计

### 2.1 组件层次结构

```
消息中心页面 (MessageCenter/index.vue)
├── 消息入口组件
│   ├── 消息图标 (MessageIcon)
│   └── 未读角标 (UnreadBadge)
└── 消息列表区域
    ├── 类型筛选器 (TypeFilter)
    ├── 操作栏 (ActionBar)
    │   └── 全部已读按钮
    ├── 消息列表 (MessageList)
    │   └── 消息卡片 (MessageCard)
    └── 分页组件 (Pagination)
```

### 2.2 弹窗/子页面结构

```
消息详情页 (MessageDetail/index.vue)
├── 消息头部（类型标签 + 标题 + 时间）
├── 消息正文
├── 跳转按钮
└── 删除按钮

通知设置页 (NotificationSettings/index.vue)
├── 通知方式偏好 (ChannelPreferences)
├── 免打扰设置 (DndSettings)
└── 消息通知开关 (ModuleSwitches)

公告管理页 (AnnouncementManagement/index.vue)
├── 公告列表区域
│   ├── 搜索容器
│   └── 公告表格 (AnnouncementTable)
├── 公告编辑弹窗 (AnnouncementFormDialog)
└── 公告详情弹窗 (AnnouncementDetailDialog)
```

### 2.3 组件职责划分

| 组件名称 | 职责描述 | 复用性 |
|---------|---------|--------|
| **MessageIcon** | 顶部导航栏消息图标 + 未读角标 | 全局组件 |
| **UnreadBadge** | 未读消息数量角标展示 | 可复用 |
| **TypeFilter** | 消息类型筛选 Tab | 页面内部组件 |
| **MessageList** | 消息列表展示，支持下拉刷新和上滑加载 | 页面内部组件 |
| **MessageCard** | 单条消息卡片展示 | 可复用组件 |
| **AnnouncementFormDialog** | 公告创建/编辑表单弹窗 | 页面内部组件 |

## 3. 组件详细设计

### 3.1 消息图标与角标组件

#### 组件属性

| 属性 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| unreadCount | Number | 0 | 未读消息数 |
| maxDisplay | Number | 99 | 最大显示数字，超过显示"99+" |

#### 角标显示规则

| 未读数 | 显示 |
|--------|------|
| 0 | 隐藏角标 |
| 1-99 | 显示数字 |
| >99 | 显示"99+" |

#### 实时更新机制

```
页面加载 → 调用 GET /messages/unread-count
    ↓
建立 WebSocket 连接（或 SSE）
    ↓
收到新消息事件 → 角标数+1 → 播放提示动画
    ↓
用户点击消息图标 → 打开消息列表 → 角标数按实际未读数同步
```

### 3.2 类型筛选器组件

| 筛选Tab | 值 | 说明 |
|---------|-----|------|
| 全部 | null | 显示所有消息 |
| 系统公告 | announcement | 筛选公告类型 |
| 业务通知 | business | 筛选业务通知 |
| 会员通知 | member | 筛选会员通知 |
| 未读 | unread | 仅显示未读消息（特殊Tab） |

### 3.3 消息卡片组件

#### 展示字段

| 字段 | 说明 | 特殊处理 |

| type | 消息类型 | 类型标签（带颜色） |
| title | 消息标题 | 截断显示 |

| readStatus | 已读状态 | 未读显示蓝色圆点 |

#### 类型标签样式

| 类型 | 标签颜色 | 图标 |

| announcement | 蓝色 | 喇叭 |
| business | 青色 | 信封 |
| member | 金色 | 皇冠 |

#### 交互行为

| 操作 | 行为 |
|------|------|
| 点击卡片 | 进入消息详情页 |
| 左滑（移动端） | 显示删除按钮 |

### 3.4 公告编辑弹窗

#### 表单字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| title | 输入框 | ✅ | 公告标题，2-50字符 |
| content | 文本域 | ✅ | 公告内容 |
| type | 下拉选择 | ✅ | 公告类型 |
| importance | 单选 | ✅ | 普通/重要 |

## 5. API 调用设计

### 5.1 API 接口封装

使用 `dehaze-sdk-js` 提供的 MessageAPI 进行接口调用：

| 方法 | 功能 | 参数 |
|------|------|------|
| MessageAPI.getList | 消息列表 | queryParams |
| MessageAPI.getUnreadCount | 未读消息数 | - |
| MessageAPI.getDetail | 消息详情 | id |
| MessageAPI.markRead | 标记已读 | id |
| MessageAPI.markAllRead | 全部已读 | type |
| MessageAPI.deleteByIds | 删除消息 | ids |
| MessageAPI.search | 搜索消息 | keyword, pageNum, pageSize |

通知设置：

| 方法 | 功能 | 参数 |
|------|------|------|
| NotificationSettingAPI.get | 获取设置 | - |
| NotificationSettingAPI.update | 更新设置 | formData |

公告管理：

| 方法 | 功能 | 参数 |
|------|------|------|
| AnnouncementAPI.getPage | 公告分页列表 | queryParams |
| AnnouncementAPI.create | 创建公告 | formData |
| AnnouncementAPI.getDetail | 公告详情 | id |
| AnnouncementAPI.update | 编辑公告 | id, formData |
| AnnouncementAPI.deleteById | 删除公告 | id |
| AnnouncementAPI.send | 发送公告 | id |
| AnnouncementAPI.cancel | 取消公告 | id |

消息模板：

| 方法 | 功能 | 参数 |
|------|------|------|
| MessageTemplateAPI.getPage | 模板列表 | queryParams |
| MessageTemplateAPI.getDetail | 模板详情 | id |

### 5.2 请求错误处理

| 错误类型 | 处理方式 |
|---------|---------|
| A0550（消息不存在） | 从列表移除该消息，提示消息不存在 |
| A0551（无消息权限） | 提示无权操作此消息 |
| A0553（公告状态无效） | 提示公告状态不允许此操作 |
| A0555（模板不存在） | 提示模板不存在 |
| 网络错误 | 显示网络连接失败提示 |
| 未授权错误 | 跳转登录页 |

## 6. 交互流程设计

> **交互规范**：详见 [需求规格.md](./需求规格.md) 第 6 节

### 6.1 页面初始化流程

1. 进入页面，显示加载状态
2. 并行请求未读数和消息列表
3. 数据加载完成，渲染列表和角标
4. 建立 WebSocket 连接监听新消息

### 6.2 实时消息推送机制

```
用户登录 → 建立 WebSocket 连接
    ↓
服务端推送新消息事件
    ↓
前端处理：
    ├─ 未读角标数 +1
    ├─ 播放提示音/震动（如开启）
    ├─ 如果当前在消息列表页 → 插入新消息到列表顶部
    └─ 如果不在消息列表页 → 显示消息提示 Toast
    ↓
用户点击查看 → 标记已读 → 角标数 -1
```

#### WebSocket 消息格式

```json
{
  "event": "new_message",
  "data": {
    "id": 1,
    "type": "member",
    "title": "恭喜您升级至 VIP2",
    "priority": 2
  }
}
```

#### 连接管理

| 场景 | 行为 |
|------|------|
| 连接成功 | 开始监听消息事件 |
| 连接断开 | 自动重连（指数退避，最多5次） |
| 重连失败 | 降级为轮询（每30秒查询未读数） |
| 页面不可见 | 保持连接，但暂停UI更新 |
| 用户登出 | 关闭连接 |

### 6.3 消息列表加载流程

```
进入消息列表页
    ↓
显示加载状态
    ↓
调用 GET /messages (pageNum=1, pageSize=20)
    ↓
渲染消息列表
    ↓
用户上滑到底部 → pageNum++ → 加载更多
    ↓
用户下拉刷新 → 重置 pageNum=1 → 重新加载
```

### 6.4 消息已读流程

```
用户点击消息卡片
    ↓
跳转消息详情页
    ↓
调用 GET /messages/{id} 获取详情
    ↓
后端自动标记为已读
    ↓
前端更新角标数（-1）
    ↓
列表中该消息的未读圆点消失
```

### 6.5 全部已读流程

```
点击"全部已读"按钮
    ↓
二次确认（可选，当未读数>50时）
    ↓
调用 PUT /messages/read-all
    ↓
返回受影响条数
    ↓
更新列表中所有消息为已读状态
    ↓
角标数归零
```

### 6.6 公告发送流程

```
管理员创建公告 → 填写表单 → 保存草稿或定时发送
    ↓
草稿状态：可在列表中编辑或发送
待发送状态：等待定时任务触发，可取消
    ↓
点击"立即发送" → 二次确认 → 调用发送接口
    ↓
返回 sentCount → 提示发送成功
    ↓
公告状态变为"已发送"
```

## 8. 性能优化设计

### 8.1 请求优化

| 优化项 | 实现方式 |
|--------|---------|
| 未读数缓存 | 全局 Store 缓存未读数，避免重复请求 |
| 列表分页 | 上滑加载更多，避免一次性加载全部 |
| 防抖处理 | 搜索输入防抖 300ms |
| WebSocket 代替轮询 | 新消息通过 WebSocket 推送，减少轮询请求 |

### 8.2 渲染优化

| 优化项 | 实现方式 |
|--------|---------|
| 列表虚拟化 | 消息量大时使用虚拟列表 |
| 局部更新 | 新消息插入列表顶部，不重新渲染整个列表 |
| 角标动画 | 使用 CSS transform 优化角标动画性能 |

### 8.3 WebSocket 优化

| 优化项 | 实现方式 |
|--------|---------|
| 心跳保活 | 每30秒发送心跳，检测连接状态 |
| 指数退避重连 | 1s → 2s → 4s → 8s → 16s，最多5次 |
| 降级轮询 | 重连失败后降级为每30秒轮询未读数 |
| 页面可见性 | 使用 visibilitychange 事件，页面不可见时降低心跳频率 |
