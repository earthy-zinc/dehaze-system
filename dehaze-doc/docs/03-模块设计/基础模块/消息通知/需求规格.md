# 消息通知模块需求规格

## 1. 模块概述

### 1.1 模块定位

消息通知模块是系统的统一消息分发与触达中心，负责将各业务模块产生的通知事件（会员升级/降级、低分告警、套餐到期预警等）以站内信为主要载体送达目标用户或管理员，并统一管理消息投递、实时提醒与用户消息查阅体验。

### 1.2 核心价值

| 价值维度 | 具体内容 |
|---------|---------|
| **统一触达** | 所有业务通知由消息通知模块统一收发，避免各模块各自实现消息推送造成体验割裂 |
| **消息中心化** | 用户拥有集中的消息收件箱，统一查阅、管理所有历史消息 |
| **实时感知** | 在线用户即时收到新消息提醒与未读角标更新 |
| **通知可控** | 用户可按类型/模块开关 APP 推送、设置免打扰时段 |
| **必达保障** | 站内信持久化留存，即使外部推送通道全部故障，消息仍可查阅 |

### 1.3 业务目标

- 建立统一的消息通知基础设施，供所有业务模块调用
- 提供用户端消息中心（收件箱），实现消息查阅、已读管理、删除、搜索
- 提供通知偏好设置（按类型/模块开关 APP 推送 + 免打扰时段）
- 支持系统公告的创建、定时发送与定向推送
- 支持消息模板的变量渲染
- 建立消息生命周期管理机制（生成→投递→已读→清理）

## 2. 用户角色与权限

### 2.1 主要用户角色

| 角色 | 描述 | 主要职责 |
|------|------|---------|
| 普通用户 | 所有注册用户 | 接收和查阅个人消息、管理通知偏好设置 |
| 管理员 | 系统后台管理人员 | 发送系统公告、查看消息、接收告警通知 |

### 2.2 权限矩阵

| 功能点 | 普通用户 | 管理员 |
|--------|:------:|:-----:|
| 接收站内信 | ✅ | ✅ |
| 查看消息列表 | ✅（仅自己的消息） | ✅（仅自己的消息） |
| 标记已读/全部已读 | ✅ | ✅ |
| 删除消息 | ✅（软删除） | ✅（软删除） |
| 搜索消息 | ✅ | ✅ |
| 设置通知偏好 | ✅ | ✅ |
| 发送系统公告 | ❌ | ✅ |
| 编辑消息模板 | ❌ | ✅ |

### 2.3 多端能力差异

各端受运行环境限制，消息触达方式存在差异；未读数角标全端统一：

| 端 | 触达方式 | 说明 |
|----|---------|------|
| Web / 桌面端 | 站内信 + 实时角标 | 在线时新消息即时提醒；离线期间产生的消息在重新连接后补齐 |
| 移动端 APP | 站内信 + APP 推送 | 前台时即时提醒，后台/离线时依赖 APP 推送 |
| 小程序 | 站内信 + 实时角标 | 实时通道不可用时降级为定时轮询（默认 30s）拉取未读数与最新消息 |

**统一规则**：未读数角标全端一致；站内信为全端必达渠道，无论实时通道是否可用，用户登录后均可查阅历史消息。

## 3. 消息类型

| 消息类型 | 编码 | 适用场景 | 发送对象 | 留存期限 |
|---------|------|---------|---------|------------|
| 站内信 | `inbox` | 所有需在系统内留痕的消息（管理员回复、审核结果等） | 用户/管理员 | 30 天 |
| 系统公告 | `announcement` | 系统维护、功能更新、活动通知、运营公告 | 全体用户/指定范围 | 30 天 |
| 业务通知 | `business` | 业务事件通知（多任务处理完成/订单/反馈等） | 特定用户 | 30 天 |
| 会员通知 | `member` | 等级升级/降级、套餐到期预警 | 特定用户 | 30 天 |
| 告警通知 | `alert` | 低分评价告警 | 管理员 | 7 天 |
| 严重告警 | `critical_alert` | 全局异常（大面积服务不可用、全局低分率超限等） | 管理员 | 90 天 |

## 4. 功能需求

### 4.1 消息接收（F-MN-001）

#### 4.1.1 功能描述

业务事件触发时，消息通知模块生成消息记录并落库为站内信，实时提醒在线用户更新未读角标，同时按用户通知偏好异步分发 APP 推送等外部渠道。使用消息模板时，按模板变量渲染标题与正文；变量缺失时拒绝发送。

#### 4.1.2 消息推送优先级

| 优先级 | 值 | 适用类型 | 说明 |
|--------|-----|---------|------|
| 紧急 | 4 | 严重告警 | 不受免打扰限制 |
| 高 | 3 | 重要公告、紧急告警 | - |
| 中 | 2 | 业务通知、会员通知、普通公告（默认） | - |
| 低 | 1 | 普通通知 | - |

### 4.2 消息列表展示（F-MN-002）

用户/管理员的统一消息收件箱，以列表形式展示所有接收的消息，支持分页加载、类型筛选与搜索。

| 展示字段 | 说明 |
|------|------|
| 消息类型 | 类型标签（站内信/系统公告/业务通知/会员通知/告警/严重告警）+ 类型色条 |
| 消息标题 | 消息标题 |
| 消息摘要 | 消息正文前 50 字符（截断） |
| 发送时间 | 完整时间展示 |
| 已读状态 | 红点/标签区分已读与未读 |

| 筛选与排序 | 说明 |
|------|------|
| 类型筛选 | 全部/站内信/系统公告/业务通知/会员通知/告警/严重告警/未读（单 Tab 切换） |
| 搜索 | 按标题/正文模糊搜索（仅当前用户消息） |
| 排序 | 未读消息优先置顶，同已读状态下按发送时间倒序 |

### 4.3 消息阅读与管理（F-MN-003）

点击消息进入详情，展示完整消息内容（标题、类型标签、发送时间、正文、跳转链接）。

| 功能 | 说明 |
|------|------|
| 标记已读 | 用户查看详情后标记该消息已读（重复标记不产生副作用） |
| 全部标记已读 | 列表页"全部已读"，支持按类型标记 |
| 未读数角标 | 导航栏/菜单消息图标显示未读数量角标；收到新消息实时 +1，已读/删除后同步递减 |
| 离线补偿 | 用户离线期间产生的未读消息在重新连接后补齐，不丢失 |
| 消息删除 | 单条/批量删除（确认弹窗）；用户删除为**软删除**，仅从本人视图移除，消息记录保留 |
| 消息搜索 | 按标题、正文模糊搜索，仅限本人消息，未读优先 + 时间倒序 |

### 4.4 消息设置（F-MN-004）

#### 4.4.1 通知方式偏好

用户可以按消息类型设置 APP 推送渠道偏好：

| 消息类型 | 默认 APP推送 | 说明 |
|---------|:---:|------|
| 系统公告 | 开 | 可关闭 |
| 业务通知 | **关** | 可开启 |
| 会员通知 | 开 | 可关闭 |
| 告警/严重告警 | 开 | 可关闭 |

**规则**：站内信作为基本渠道不可关闭；APP 推送受总开关、类型偏好、模块开关三层控制。

#### 4.4.2 免打扰设置

| 设置项 | 说明 |
|--------|------|
| 免打扰开关 | 开启后，APP 推送在指定时段内不发送 |
| 免打扰时段 | 用户自定义（默认 22:00 - 08:00，支持跨天） |
| 免打扰范围 | 仅 APP 推送渠道生效，站内信不受影响 |
| 例外情况 | 严重告警不受免打扰限制 |
| 延迟补发 | 免打扰期间的 APP 推送在免打扰结束后补发；补发时合并同一用户同一触发模块的消息为一条汇总通知 |
| 推送频率限制 | 单用户单消息类型每小时 ≤ 5 条，超限合并为一条汇总通知；严重告警不受限 |

#### 4.4.3 消息通知开关（按模块）

用户可按触发模块选择是否接收 APP 推送：

| 模块 | 默认状态 | 说明 |
|------|:------:|------|
| 处理任务完成通知 | 开启 | 多任务（去雾/去雨/去雪/低光/超分/去噪/修复）处理完成时通知 |
| 反馈处理进度通知 | 开启 | 反馈被回复/状态变更时通知 |
| 系统公告推送 | 开启 | 建议保持开启，以免错过维护通知 |

会员通知（升级/降级/到期预警）为关键通知，无独立关闭开关。

### 4.5 系统公告管理（F-MN-005）

管理员可创建、编辑、发送和管理系统公告，支持定向发送与定时发送。

#### 4.5.1 公告创建

| 字段 | 必填 | 说明 |
|------|:--:|------|
| 公告标题 | ✅ | 2-50 字符 |
| 公告内容 | ✅ | 公告正文 |
| 公告类型 | ✅ | 系统维护/功能更新/活动通知/运营公告 |
| 重要级别 | ✅ | 普通/重要 |
| 发送范围 | ✅ | 全体用户/按会员等级/指定用户 |
| 发送时间 | ❌ | 支持立即发送和定时发送（定时发送时间必须为未来时间） |
| 过期时间 | ❌ | 公告失效时间 |

#### 4.5.2 公告状态与操作

| 状态 | 可操作 |
|------|--------|
| 草稿 | 编辑、发送、删除 |
| 待发送 | 编辑、发送、取消、删除 |
| 已发送 | 查看（不可编辑/取消） |
| 已取消 | 查看（不可编辑） |

#### 4.5.3 公告发送策略

- 立即发送：管理员点击"发送"直接触发
- 定时发送：到达设定的发送时间后自动发送
- 大范围公告分批投递，单批失败不影响其他批次；未按时发送的公告自动补偿重发，已收到的接收人不重复收到
- 发送成功置状态为"已发送"，记录发送数量

### 4.6 消息模板管理（F-MN-006）

管理员可管理各业务通知消息的模板（模板由系统内置，支持查看与编辑，不支持新增/删除）：

| 能力 | 说明 |
|------|------|
| 模板列表 | 按名称/类型/状态筛选分页查询 |
| 模板详情 | 展示标题模板、内容模板、优先级、渠道配置、变量说明 |
| 模板编辑 | 修改标题模板/内容模板/优先级/渠道配置/启用状态 |
| 变量渲染 | 发送时按 `{变量名}` 占位符替换，缺失必填变量报错 |

## 5. 非功能需求

### 5.1 性能要求

| 指标 | 目标值 | 说明 |
|-----|--------|------|
| 消息生成延迟 | <1s | 业务事件触发到消息记录生成 |
| 消息生成吞吐 | ≥ 1000 条/秒 | 峰值 |
| 站内信送达延迟 | <3s | 消息生成到用户端可见、角标更新 |
| 消息列表查询 | <500ms | 分页查询 |
| 消息搜索 | <500ms | 关键词搜索 |
| 未读数查询 | <50ms | 红点/角标查询 |

### 5.2 安全要求

| 方面 | 措施 |
|-----|------|
| 消息防篡改 | 消息发送后内容不可修改，仅已读状态与用户删除状态可变更 |
| 越权防护 | 用户仅可查看、操作自己的消息，越权访问视为消息不存在 |
| 发送者校验 | 系统公告发送需校验管理员权限 |
| 内容审核 | 系统公告发送前强制敏感词过滤，命中敏感词禁止发送或转人工审核 |

### 5.3 可用性要求

| 方面 | 要求 |
|-----|------|
| 消息不丢失 | 站内信记录持久化留存，与业务操作同事务 |
| 站内信必达 | 站内信为基本渠道，即使外部通道全部故障消息仍可查阅 |
| 未读数降级 | 未读数缓存不可用时降级为实时统计，不影响功能 |
| 推送降级 | APP推送/邮件/短信不可用时降级为仅站内信 |

## 6. 业务规则

### 6.1 消息生成规则

| 规则项 | 说明 |
|--------|------|
| 触发源 | 消息由各业务模块事件触发，不允许用户间直接互发消息 |
| 发送者 | 系统消息的发送者为系统 |
| 接收者 | 支持指定单个用户、批量用户、按范围解析（公告） |
| 幂等 | 携带"业务模块 + 业务 ID"的消息按接收人去重；同一业务事件发给不同接收人不去重；未携带幂等标识的消息不防重 |

### 6.2 消息存储规则

| 规则项 | 说明 |
|--------|------|
| 用户删除 | 软删除，仅从该用户视图移除，消息记录保留 |
| 到期清理 | 消息超过留存期限后由定时任务物理删除，无论是否已读、是否已被用户删除 |

### 6.3 消息生命周期

```
业务事件触发 → 生成消息记录（未读）→ 站内信落库 + 实时提醒
    ↓
用户收到消息 → 角标更新
    ↓
用户查看详情 → 标记已读
    ↓
├─ 用户删除消息 → 软删除（从用户视图移除，记录保留）
│
└─ 超过留存期限 → 定时任务物理删除
```

## 8. 待确认事项

1. **外部推送渠道服务商**：APP 推送、邮件、短信分别选用哪个服务商？
2. **业务模块接入范围**：多任务处理完成、订单支付/退款/续费、反馈状态变更/回复等业务事件是否需要发送通知？
3. **消息归档**：过期消息是物理删除还是归档到冷存储？是否需要消息归档能力以支持合规审计？
4. **消息富文本**：系统公告和消息正文是否需要支持富文本（图片、链接）还是纯文本即可？
5. **免打扰时段时区**：免打扰时段默认值（22:00-08:00）是否需要按用户所在时区自动调整？
6. **公告定向发送规模**：公告定向发送（按等级/指定用户）的受众规模上限是多少？
7. **消息已读同步延迟**：多端同时在线时已读状态的同步延迟容忍度是多少？
