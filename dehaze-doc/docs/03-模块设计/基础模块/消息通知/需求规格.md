# 消息通知模块需求规格

## 1. 模块概述

### 1.1 模块定位

消息通知模块是系统的统一消息分发与触达中心，负责将各业务模块产生的通知事件（会员升级/降级、订单状态变更、反馈处理进度、低分告警、套餐到期预警等）以站内信、APP推送、邮件、短信等多种渠道送达目标用户或管理员。该模块向上对接所有产生通知需求的业务模块，向下统一管理多通道的消息投递与用户消息查阅体验。

### 1.2 核心价值

| 价值维度 | 具体内容 |
|---------|---------|
| **统一触达** | 所有业务通知由消息通知模块统一收发，避免各模块各自实现消息推送造成体验割裂 |
| **多渠道覆盖** | 站内信保证消息必达，APP推送、邮件、短信提供分级触达手段，适配不同紧急程度 |
| **消息中心化** | 用户拥有集中的消息收件箱，统一查阅、管理所有历史消息，无需在各功能页面间查找 |
| **用户留存** | 及时的业务通知（升级提醒、到期预警、反馈回复）提升用户对服务的感知与粘性 |
| **运营效率** | 系统公告等批量消息能力降低运营成本，低分告警等自动通知提升管理员响应速度 |

### 1.3 业务目标

#### 功能目标

- 建立统一的消息通知基础设施，供所有业务模块调用
- 支持站内信、APP推送、邮件、短信四种触达渠道
- 提供用户端消息中心（收件箱），实现消息查阅、搜索、管理
- 提供消息偏好设置，允许用户选择通知方式与免打扰时段
- 支持系统公告的批量发送与定向推送
- 建立消息生命周期管理机制（生成→投递→已读→清理）

#### 性能目标

| 指标 | 目标值 | 说明 |
|-----|--------|------|
| 消息生成延迟 | <1s | 业务事件触发到消息记录生成的延迟 |
| 站内信送达延迟 | <3s | 消息生成到用户端可见的延迟 |
| APP推送延迟 | <10s | 消息生成到推送通道发出的延迟 |
| 消息列表查询 | <500ms | 用户端分页查询响应时间 |
| 消息未读数查询 | <50ms | 红点/角标查询（高频调用，需缓存） |

### 1.4 模块依赖关系

```
┌─────────────┐   ┌─────────────┐   ┌─────────────┐
│  会员管理    │   │  订单管理    │   │  反馈评价    │
│  (升级/降级  │   │  (支付/退款  │   │  (回复/告警  │
│   到期预警)  │   │   续费失败)  │   │   低分通知)  │
└──────┬──────┘   └──────┬──────┘   └──────┬──────┘
       │                 │                 │
       └─────────────────┼─────────────────┘
                         ▼
                 ┌───────────────┐
                 │  消息通知模块   │
                 │   (消息中心)   │
                 └───────┬───────┘
                         │
         ┌───────────────┼───────────────┐
         ▼               ▼               ▼
   ┌──────────┐   ┌──────────┐   ┌──────────┐
   │  站内信   │   │ APP推送   │   │ 邮件/短信 │
   │  (必达)   │   │ (实时触达) │   │ (高级触达)│
   └──────────┘   └──────────┘   └──────────┘
```

消息通知模块作为**被依赖模块**，所有需要向用户/管理员推送通知的业务模块均通过消息通知模块发送消息。消息通知模块自身依赖**用户管理模块**确定消息接收人，依赖**字典管理模块**获取消息类型、渠道等枚举配置。

## 3. 消息类型

### 3.1 消息类型定义

| 消息类型 | 编码 | 适用场景 | 发送对象 | 默认渠道 |
|---------|------|---------|---------|---------|
| 站内信 | `inbox` | 所有需在系统内留痕的消息 | 用户/管理员 | 站内信 |
| 系统公告 | `announcement` | 系统维护通知、功能更新、活动通知等 | 全体用户/指定用户群 | 站内信 + APP推送 |
| 业务通知 | `business` | 订单状态变更、反馈处理进度、处理任务完成等 | 特定用户 | 站内信 |
| 会员通知 | `member` | 等级升级/降级、套餐到期预警、权益变更 | 特定用户 | 站内信 + APP推送 |
| 告警通知 | `alert` | 低分评价告警、系统异常告警 | 管理员 | 站内信 + 邮件 |
| 严重告警 | `critical_alert` | 全局异常（如大面积服务不可用） | 管理员 | 站内信 + 邮件 + 短信 |

### 3.2 各类型应用场景详述

#### 3.2.1 站内信（inbox）

所有消息的基本载体，保证消息必达。其他类型的消息均可在站内信中有对应副本。站内信是用户打开系统即可见的消息，无需额外授权。

**典型场景**：管理员对反馈的回复、订单退款审核结果、会员等级变更通知。

#### 3.2.2 系统公告（announcement）

由管理员主动发送的广播消息，用于系统级通知。

**典型场景**：

| 公告类型 | 示例内容 |
|---------|---------|
| 系统维护 | "系统将于 7月30日 02:00-04:00 进行升级维护，届时服务暂不可用" |
| 功能更新 | "新算法'暗通道先验+'已上线，去雾效果更自然，欢迎体验" |
| 活动通知 | "暑期 VIP 特惠活动，年费套餐限时 7 折" |
| 运营公告 | "因服务器迁移，历史处理记录将保留 30 天后清理" |

#### 3.2.3 业务通知（business）

各业务模块在特定事件发生时自动触发的消息，面向特定用户。

**典型场景**（由其他模块触发）：

| 触发模块 | 触发事件 | 消息内容示例 |
|---------|---------|------------|
| 去雾处理 | 批量处理任务完成 | "您的批量去雾任务（共 15 张）已处理完成，点击查看效果" |
| 订单管理 | 退款审核驳回 | "您的退款申请（订单号 DH20260727143025）已被驳回，原因：已使用权益超过 50%" |
| 订单管理 | 自动续费失败 | "您的 VIP2 自动续费失败（已尝试 3 次），请手动续费以保持会员权益" |
| 反馈评价 | 反馈状态变更 | "您的反馈「希望增加视频去雾」已被管理员回复，点击查看" |
| 反馈评价 | 管理员回复反馈 | "管理员回复了您的反馈，点击查看回复详情" |

#### 3.2.4 会员通知（member）

与会员体系相关的专属通知，用于提升用户对会员价值的感知。

**典型场景**（由会员管理模块触发）：

| 触发事件 | 消息内容示例 |
|---------|------------|
| 升级通知 | "恭喜您升级至 VIP2，已解锁高清图导出、对比报告导出等权益" |
| 降级预警 | "您的 VIP2 套餐将于 7 天后到期，到期后将降至 VIP1，点击续费保持当前等级" |
| 到期提醒（3天） | "您的 VIP2 套餐将于 3 天后到期，降级后每月去雾次数将从 500 次降至 100 次" |
| 到期提醒（1天） | "您的 VIP2 套餐将于明天到期，请及时续费" |
| 次数重置 | "本月去雾和评估次数已刷新，VIP2 本月可用去雾 500 次、评估 500 次" |
| 权益变更 | "VIP2 权益已升级，新增批量打包下载功能，快去体验吧" |

#### 3.2.5 告警通知（alert）

面向管理员的业务异常告警，需管理员关注和处理。

**典型场景**：

| 触发条件 | 告警级别 | 消息内容示例 |
|---------|---------|------------|
| 单条 1 星评价 | 普通 | "用户 xxx 对算法「暗通道先验」提交了 1 星评价，点击查看详情" |
| 24h 内同算法 ≥3 条低分 | 紧急 | "算法「暗通道先验」24 小时内收到 3 条低分评价，请关注算法质量" |
| 24h 内全局低分率 >20% | 严重 | "过去 24 小时全局低分率已达 23%（正常 <10%），请排查是否存在系统问题" |

#### 3.2.6 严重告警（critical_alert）

最高级别的告警，通过所有可用渠道触达管理员。

**典型场景**：支付渠道大面积回调失败、核心服务不可用、数据库连接池耗尽等需立即处理的系统故障。

## 4. 功能需求

### 4.1 消息接收（F-MN-001）

#### 4.1.1 功能描述

当业务事件触发消息生成时，消息通知模块接收消息请求，完成消息记录创建和多渠道投递。

#### 4.1.2 消息生成规则

| 属性 | 说明 |
|------|------|
| 触发方 | 各业务模块调用消息通知模块的消息发送接口 |
| 发送者 | 系统（SYSTEM）或指定管理员 |
| 接收者 | 单个用户、多个用户、全体用户、指定角色 |
| 消息失效 | 默认 30 天后自动清理，告警类消息 7 天后清理 |

#### 4.1.3 消息推送优先级

| 优先级 | 适用类型 | 说明 |
|--------|---------|------|
| 紧急 | 严重告警 | 所有渠道立即推送 |
| 高 | 告警通知、会员降级预警 | APP推送 + 站内信 |
| 中 | 业务通知、会员升级通知、到期提醒 | 站内信 + APP推送（可选） |
| 低 | 系统公告、次数重置通知 | 仅站内信 |

### 4.2 消息列表展示（F-MN-002）

#### 4.2.1 功能描述

用户/管理员的统一消息收件箱，以列表形式展示所有接收的消息，支持分页加载和类型筛选。

#### 4.2.2 列表展示字段

| 字段 | 说明 |
|------|------|
| 消息图标/头像 | 系统默认图标或发送者头像 |
| 消息标题 | 消息摘要标题（如"订单退款结果通知"） |
| 消息摘要 | 消息正文前 50 字符（截断） |
| 消息类型 | 类型标签（系统公告/业务通知/会员通知/告警） |
| 发送时间 | 精确到分钟，当日显示"HH:mm"，非当日显示"MM-DD" |
| 已读状态 | 未读消息左侧显示蓝色圆点 |

#### 4.2.3 消息筛选

| 筛选条件 | 说明 |
|---------|------|
| 全部消息 | 默认视图 |
| 系统公告 | 筛选 announcement 类型 |
| 业务通知 | 筛选 business 类型 |
| 会员通知 | 筛选 member 类型 |
| 未读消息 | 仅显示未读消息 |

#### 4.2.4 消息排序

- 默认按发送时间倒序（最新消息在前）
- 未读消息优先置顶（在时间排序基础上，未读消息排在已读消息之前）

### 4.3 消息阅读与管理（F-MN-003）

#### 4.3.1 消息详情

点击消息进入详情页，展示完整消息内容，包含：

| 展示内容 | 说明 |
|---------|------|
| 消息标题 | 完整标题 |
| 发送者 | 系统 / 管理员名称 |
| 消息类型 | 类型标签 |
| 发送时间 | 完整时间（yyyy-MM-dd HH:mm:ss） |
| 消息正文 | 完整消息内容 |
| 跳转链接 | 关联业务页面链接（如"查看订单详情"→跳转至订单详情页） |

#### 4.3.2 已读/未读状态管理

| 功能 | 说明 |
|------|------|
| 自动标记已读 | 用户点击消息进入详情页时，自动标记该消息为已读 |
| 全部标记已读 | 消息列表顶部提供"全部已读"按钮，一键标记所有未读消息为已读 |
| 未读数角标 | 导航栏/菜单的消息图标上显示未读消息数量角标（红色数字） |
| 角标更新 | 收到新消息时实时更新角标，已读操作后立即减除 |

#### 4.3.3 消息删除

| 功能 | 说明 |
|------|------|
| 单条删除 | 每条消息支持左滑删除或长按删除 |
| 批量删除 | 支持多选后批量删除 |
| 删除规则 | 用户删除消息为单向操作，仅从当前用户视图中移除，不影响消息记录（管理员仍可查看） |
| 到期清理 | 消息到期后（`expires_at < NOW()`）由定时任务物理删除，无论是否已读 |

#### 4.3.4 消息搜索

| 功能 | 说明 |
|------|------|
| 关键字搜索 | 支持按消息标题、正文内容进行模糊搜索 |
| 搜索结果 | 展示匹配的消息列表，高亮匹配的关键字 |
| 搜索范围 | 仅搜索当前登录用户的消息 |

### 4.4 消息设置（F-MN-004）

#### 4.4.1 通知方式偏好

用户可以按消息类型设置接收渠道偏好：

| 消息类型 | 可选渠道 |
|---------|---------|
| 系统公告 | 站内信（默认开启，不可关闭） / APP推送（可选） |
| 业务通知 | 站内信（默认开启，不可关闭） / APP推送（可选） |
| 会员通知 | 站内信（默认开启，不可关闭） / APP推送（默认开启） |
| 告警通知 | 仅管理员可见，站内信 + 邮件（管理员可调整） |

**规则**：站内信作为基本渠道不可关闭，保证至少一种方式可达。APP推送可由用户选择开启或关闭。

#### 4.4.2 免打扰设置

| 设置项 | 说明 |
|--------|------|
| 免打扰开关 | 开启后，APP推送在指定时段内不发送 |
| 免打扰时段 | 用户自定义（默认 22:00 - 08:00） |
| 免打扰范围 | APP推送渠道生效，站内信不受免打扰影响（用户打开系统即可见） |

#### 4.4.3 消息通知开关（按模块）

用户可按触发模块选择是否接收非关键业务通知：

| 模块 | 默认状态 | 说明 |
|------|:------:|------|
| 处理任务完成通知 | 开启 | 去雾/评估任务完成时通知 |
| 反馈处理进度通知 | 开启 | 反馈被回复/状态变更时通知 |
| 系统公告推送 | 开启 | 建议保持开启，以免错过维护通知 |

会员通知（升级/降级/到期预警）为关键通知，不可关闭。

### 4.5 系统公告管理（F-MN-005）

#### 4.5.1 功能描述

管理员可创建、编辑、发送和管理系统公告，支持定向发送和定时发送。

#### 4.5.2 公告创建

| 字段 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| 公告标题 | 文本 | ✅ | 公告标题，2-50 字符 |
| 公告内容 | 富文本 | ✅ | 公告正文，支持纯文本 |
| 公告类型 | 枚举 | ✅ | 系统维护 / 功能更新 / 活动通知 / 运营公告 |
| 重要级别 | 枚举 | ✅ | 普通 / 重要 |
| 发送范围 | 枚举 | ✅ | 全体用户 / 按会员等级 / 指定用户 |
| 发送时间 | 时间 | ❌ | 支持立即发送和定时发送 |
| 过期时间 | 时间 | ❌ | 公告失效时间，到期后不再展示 |

#### 4.5.3 公告列表

管理员可查看已发送和待发送的公告列表，支持按标题、类型、发送时间筛选。

#### 4.5.4 公告展示规则

- 重要公告在用户消息列表顶部置顶展示
- 公告支持在首页/消息中心顶部横幅展示（重要公告）
- 公告过期后自动从横幅移除，消息列表中的公告记录保留

#### 4.5.5 公告发送策略

公告发送采用**分批投递**：按接收人列表分批（默认每批 500 人）批量插入 `sys_message`，每批独立提交事务，避免全体用户公告（数千人）在单事务内长事务锁表。全部批次成功后更新公告状态为已发送并记录 `sentCount`。

### 4.6 消息模板管理（F-MN-006）

#### 4.6.1 功能描述

管理员可管理各业务通知消息的模板，支持变量替换。

#### 4.6.2 模板变量

| 模板 | 变量 | 示例填充内容 |
|------|------|------------|
| 会员升级通知 | `{levelName}`, `{权益列表}` | "VIP2", "高清图导出、对比报告导出" |
| 套餐到期预警 | `{days}`, `{currentLevel}`, `{downgradeLevel}` | "7", "VIP2", "VIP1" |
| 订单退款通知 | `{orderNo}`, `{result}`, `{reason}` | "DH20260727143025", "已驳回", "已使用权益超过50%" |
| 反馈回复通知 | `{title}` | "希望增加视频去雾功能" |

## 5. 非功能需求

### 5.1 性能要求

| 指标 | 要求 |
|-----|------|
| 消息生成吞吐 | 支持峰值 1000 条/秒的消息生成请求 |
| 站内信查询响应 | 分页查询 <500ms，未读数查询 <50ms |
| APP推送延迟 | 消息生成到推送通道发出 <10s |
| 邮件发送延迟 | 消息生成到邮件投递 <30s |
| 未读角标更新 | 收到新消息后 3s 内前端角标更新 |

### 5.2 安全要求

| 方面 | 措施 |
|-----|------|
| 消息防篡改 | 已发送的消息记录不可被用户或第三方修改 |
| 越权防护 | 用户仅可查看、操作自己的消息，不可访问他人消息 |
| 发送者校验 | 系统公告发送需校验管理员权限 |
| 内容过滤 | 系统公告和消息内容需做敏感词过滤 |

### 5.3 可用性要求

| 方面 | 要求 |
|-----|------|
| 消息不丢失 | 消息生成请求一旦受理，保证消息记录持久化，投递失败时有重试机制 |
| 推送降级 | APP推送通道不可用时，自动降级为仅站内信送达 |
| 站内信必达 | 站内信作为基本渠道，即使其他通道全部故障，消息仍可通过站内信查阅 |
| 缓存降级 | 未读数 Redis 缓存不可用时降级为数据库查询 |

### 5.4 易用性要求

| 方面 | 要求 |
|-----|------|
| 消息列表加载 | 首次加载最近 20 条消息，上滑自动加载更多 |
| 未读标识 | 未读消息有明显视觉区分（蓝色圆点），一目了然 |
| 一键操作 | 提供"全部已读"一键操作，减少重复点击 |
| 快捷删除 | 支持左滑删除（移动端）和悬停删除按钮（桌面端） |
| 通知偏好 | 设置页面简洁，开关式操作，修改即时生效 |
| 消息跳转 | 消息详情中的业务跳转链接直达目标页面，减少导航层级 |

## 7. 业务规则

### 7.1 消息生成规则

| 规则项 | 说明 |
|--------|------|
| 触发源 | 消息由各业务模块事件触发，不允许用户间直接互发消息 |
| 发送者 | 系统消息发送者为 SYSTEM，管理员发送的公告发送者为管理员本人 |
| 接收者 | 支持指定单个用户、批量用户、按角色、全体用户 |
| 去重 | 同一业务事件（如同一订单号）不重复生成多条相同消息 |
| 幂等 | 业务模块调用消息发送接口支持幂等，通过业务事件唯一键（如订单号+事件类型）防重。需幂等的业务消息（订单/会员/反馈/告警事件）必须传入 `bizModule` + `bizId`，由 DB 唯一索引 `uk_biz_dedup(biz_module, biz_id, recipient_id)` 兜底防重，同一业务事件发给不同接收人不去重；未传入幂等键的消息（如管理员手动触发的临时通知）不防重，允许重复生成 |

### 7.2 消息推送规则

| 规则项 | 说明 |
|--------|------|
| 渠道选择 | 根据消息优先级和用户通知偏好决定推送渠道 |
| 站内信必达 | 站内信为基本渠道，所有消息均生成站内信记录 |
| APP推送条件 | 用户已开启 APP推送偏好 + 不在免打扰时段 + 消息优先级允许 APP推送 |
| 邮件条件 | 仅告警和严重告警类消息发邮件，且仅向管理员发送 |
| 短信条件 | 仅严重告警类消息发短信，且仅向管理员发送 |
| 推送失败重试 | APP推送失败自动降级为仅站内信；邮件/短信失败重试 3 次，仍失败则仅站内信 |

### 7.3 消息存储规则

| 规则项 | 说明 |
|--------|------|
| 消息留存 | 普通消息保留 30 天，告警消息保留 7 天，严重告警保留 90 天 |
| 清理策略 | 定时任务每日执行过期消息清理，物理删除所有 `expires_at < NOW()` 的消息，无论是否已读 |
| 公告保留 | 系统公告过期后从横幅消失，消息列表中的记录仍保留至消息留存期限 |

### 7.4 消息生命周期

```
业务事件触发
    ↓
生成消息记录（状态：未读）
    ↓
多通道投递（站内信/APP推送/邮件/短信）
    ↓
用户收到消息 → 角标更新
    ↓
用户点击查看 → 自动标记已读（状态：已读）
    ↓
├─ 用户删除消息 → 从用户视图移除
│
└─ 消息到期（expires_at < NOW()）→ 定时任务物理删除（无论是否已读）
```

### 7.5 免打扰规则

| 规则项 | 说明 |
|--------|------|
| 适用范围 | 仅 APP推送受免打扰影响，站内信不受免打扰限制 |
| 免打扰时段 | 用户自定义，默认 22:00-08:00 |
| 例外情况 | 严重告警（critical_alert）不受免打扰限制，始终推送 |
| 延迟发送 | 免打扰时段内产生的 APP推送消息，在免打扰结束后立即补发 |

## 9. 待确认事项

1. **APP推送通道**：APP推送具体使用哪个推送平台（极光推送 / 友盟 / 个推 / FCM / APNs）？是否各端统一？
2. **邮件服务**：邮件发送使用哪个邮件服务商（阿里云邮件推送 / SendCloud / 自建 SMTP）？是否需要支持邮件模板自定义？
3. **短信服务**：短信发送使用哪个服务商（阿里云短信 / 腾讯云短信）？短信通知是否仅限严重告警，还是可能扩展到用户侧（如验证码场景）？
4. **消息持久化**：过期消息清理是物理删除还是归档到冷存储？是否需要消息归档能力以支持合规审计？
5. **消息富文本**：系统公告和消息正文是否需要支持富文本（图片、链接）还是纯文本即可？
6. **消息已读回执**：是否需要消息已读回执功能（发送方可查看消息是否被接收方已读）？
7. **多语言支持**：消息模板是否需要支持多语言？
8. **管理后台消息**：管理员之间是否也需要站内信互通能力（如待办任务分配通知）？
