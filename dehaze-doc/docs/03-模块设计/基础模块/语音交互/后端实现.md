# 语音交互模块 - 后端实现设计

## 1. 文档概述

### 1.1 架构概览

语音交互模块采用 **语音引擎注册表**架构：ASR/TTS 引擎统一注册于数据库（对齐 AI 模型管理的 `sys_ai_provider`/`sys_ai_model` 模式），本地引擎与多家云端引擎共存，按能力维度（asr/tts）选择默认引擎；低配或私有化环境可整体切换为纯云端供给。引擎统一抽象为 `ASRProvider` / `TTSProvider` 接口，应用侧不区分本地/云端。

核心数据流：

1. 前端录音 → WebSocket（业务后端）→ AsrService 代理 → ASRProvider（本地 FunASR / 云端 REST）→ 文本 → AI 对话模块消息管道
2. 后端文本 → TtsService → TTSProvider（本地 Piper / 云端 REST）→ 音频加密落文件管理 → 前端播放

| Provider | 实现要点 |
|----------|---------|
| LocalAsrProvider | 进程内 FunASR（GPU 优先，无 GPU 回退 CPU），流式 SenseVoice-Small / 离线 SeACo-Paraformer-Large，热词进程内表 |
| LocalTtsProvider | 进程内 Piper（zh_CN-huayan-medium），模型自动下载，音频缓存 AES 加密 |
| CloudAsrProvider / CloudTtsProvider | 云端厂商 REST（阿里云/腾讯云/讯飞 ASR、Azure/阿里云 TTS），密钥经 `sys_voice_provider_key` 管理 |

## 2. 模块架构

### 2.1 分层架构

```
Controller 层
├── VoiceController              # 识别结果查询、TTS 合成、服务状态查询
└── VoiceWebSocketController     # 流式 ASR WebSocket 连接管理与代理

Service 层
├── VoiceService                 # 语音能力总入口：录音会话管理、结果查询、服务状态汇总
├── AsrService                   # ASR 编排（经 ASRProvider 路由：WebSocket 流式代理 / HTTP 离线）
└── TtsService                   # TTS 编排（经 TTSProvider 路由 + 缓存管理，缓存不额外拆组件）

Provider 层（引擎抽象，对齐 AI 模型 provider 模式）
├── ASRProvider → LocalAsrProvider（进程内 FunASR）/ CloudAsrProvider（云端 REST）
├── TTSProvider → LocalTtsProvider（进程内 Piper）/ CloudTtsProvider（云端 REST）
└── 引擎注册表（sys_voice_provider / sys_voice_provider_key / sys_voice_model）+ 默认引擎路由

基础设施层
├── FunASR 本地引擎（dehaze-python 进程内）   # 流式/离线推理，torch CUDA 自动检测
└── Piper TTS 本地引擎（dehaze-python 进程内） # 语音合成，onnxruntime CUDA EP 自动检测
```

### 2.3 服务状态监控

管理端服务监控面板查询 ASR/TTS 引擎运行状态，接口见 [API接口.md §2.4](./API接口.md)：

| 维度 | 数据来源 | 说明 |
|------|---------|------|
| ASR 引擎状态 | FunASR 引擎加载状态 + Redis `voice:asr:sessions` 并发计数 | engineStatus（online/offline）、concurrentSessions、maxConcurrentSessions、流式/离线模型加载状态 |
| TTS 引擎状态 | Piper 引擎加载状态 | engineStatus（online/offline）、当前音色模型加载状态 |

- 引擎状态由引擎层上报（模型加载成功/失败、引擎可用性），不依赖 ASR 实时请求
- 并发会话数实时读取 Redis 有序集合 `voice:asr:sessions`（按时间戳剪枝后计数）
- 管理端定时轮询刷新；权限 `voice:service:monitor`（仅管理员），普通用户访问返回 A0301

### 2.4 语音引擎注册表与默认路由

引擎（ASR/TTS）通过 `sys_voice_provider` / `sys_voice_provider_key` / `sys_voice_model` 三表统一注册（对齐 AI 模型管理），配置存数据库，由管理页维护：

| 表 | 职责 | 说明 |
|----|------|------|
| `sys_voice_provider` | 引擎供应商 | `(provider_code, engine_type)` 联合唯一（同一厂商按能力注册多条），`api_base_url`、`auth_type`、`default_headers`、`is_default` |
| `sys_voice_provider_key` | 引擎 API 密钥 | SHA256 哈希查重 + AES 密文，多 Key 轮换与失败冷却 |
| `sys_voice_model` | ASR 模型 / TTS 音色 | `model_id` 业务编码，`model_type`（ASR：stream/offline；TTS：voice），`params` 携带音色/模型参数 |

**`local` 内置引擎**：`provider_code='local'` 进注册表（无 `api_base_url`，走进程内 FunASR/Piper），与云端引擎一同管理，应用侧透明。

**默认引擎（`is_default`）**：asr / tts 各一个默认引擎（每 `engine_type` 维度 `is_default=1` 仅一条），默认指向 `local`；纯云端部署将 `is_default` 指向云端引擎，`local` 仍保留可选。

**运行时路由**：按 `engine_type` 查 `is_default=1` 且 `status=1` 的引擎 → `local` 实例化进程内 Provider，cloud 实例化云端 Provider（厂商 REST + `sys_voice_provider_key` 密钥）→ `AsrService`/`TtsService` 经 Provider 接口调用，应用不感知差异。

**默认引擎冲突校验（纯云端 throw error，不降级）**：部署为纯云端而某能力维度 `is_default` 仍指向 `local` 时属配置错误，由 `VoiceEngineRegistry` 在路由时抛出业务异常（A0500）而非降级，避免静默切换到非预期引擎。

**密钥与健康**：API Key 管理完全复用 `sys_ai_provider_key` 机制（SHA256 哈希查重 + AES 密文、多 Key 轮换、失败冷却 5/15/30min、日/分钟限额），仅表不同；健康熔断对齐 `provider_health_service`，熔断标记走 Redis `voice:provider:{id}:circuit_open`，`voice_asr`/`voice_tts` 状态与 `/health/ready` 反映所选引擎运行时健康。

**引擎切换**：管理端修改 `is_default` 或 `status` 后，`VoiceEngineRegistry` 缓存（Redis `voice:engine:asr` / `voice:engine:tts`，短 TTL）失效即时生效。

## 3. ASR 实现（LocalAsrProvider / CloudAsrProvider）

> ASR 默认引擎为本地 FunASR（`LocalAsrProvider`），纯云端部署为云端（`CloudAsrProvider`，见 §2.4）。本节描述本地实现；云端适配见 §3.6。

### 3.1 FunASR 部署架构

FunASR 以**进程内引擎**运行于 dehaze-python（`app/infrastructure/voice/funasr_engine.py`），作为 `LocalAsrProvider` 实现；GPU 优先推理（torch CUDA 可用时卸载至 GPU，否则纯 CPU），与 GPU 图像处理共享显卡资源。

| 维度 | 说明 |
|------|------|
| 流式识别 | SenseVoice-Small 分段增量识别（每累计 1 秒音频输出一次累计文本） |
| 离线识别 | SeACo-Paraformer-Large（Paraformer-Large 热词增强版，原生热词加权） |
| 热词 | 进程内内存表，注册后对流式/离线推理即时生效 |
| 模型注册表化 | 本地 ASR 模型由 `sys_voice_model` 注册（`engine_type=asr`，`model_type=stream/offline`），`params` 携带 ModelScope `model_id`、下载 URL、推理参数；引擎从注册表解析，可注册/切换多个模型 |
| 懒加载与缓存 | 首个 ASR 请求时加载，进程内单例；首次使用自动从 ModelScope 下载（各约 1GB）；多 Worker 部署时每 Worker 各持一份 |
| 依赖 | funasr/modelscope/torchaudio 为主依赖（延迟导入控制启动成本），`uv sync` 即包含 |

### 3.2 流式 ASR 流程

前端经 WebSocket 连接业务后端，业务后端代理至 FunASR 服务，识别结果经同一通道回推：

1. 前端 `POST /asr/stream-session` 获取 sessionId + wsUrl（业务后端 `/ws/asr`）
2. 前端建立 WebSocket，每 100ms 推送 PCM 音频块（16kHz/16bit/mono）
3. AsrService 代理音频块至 FunASR（`ws://voice-service:8765/ws/asr`）并接收增量文本
4. 业务后端经 WebSocket 推送增量文本至前端实时展示
5. 前端停止录音发送 `EOS` → FunASR 输出最终结果 → 关闭两端 WebSocket

| 方向 | 消息格式 | 说明 |
|------|---------|------|
| 前端→业务后端 | 二进制 PCM 音频块 | 16kHz, 16bit, mono |
| 业务后端→前端 | JSON `{"text": "增量", "isFinal": false}` | 中间结果 |
| 业务后端→前端 | JSON `{"text": "完整文本", "isFinal": true}` | 最终结果 |
| 前端→业务后端 | 文本 `"EOS"` | 结束信号 |

> 下行字段为 `isFinal`（camelCase），与 SDK 契约（`AsrStreamMessage`）一致。

### 3.3 离线 ASR 流程

前端 multipart 直传完整音频文件（WAV/PCM，16kHz/16bit/mono），后端调用 FunASR `POST /api/asr/offline` 以 Paraformer-Large 高精度识别，返回含标点断句的完整文本；音频不落盘，处理完即弃。

### 3.4 热词配置

| 热词类型 | 生效范围 | 管理权限 | 接口归属 |
|---------|---------|---------|---------|
| 全局热词 | 所有用户 | 管理员（`voice:hotword:edit`） | `/api/v1/voice/hotwords/global` |
| 用户级热词 | 当前用户 | 用户本人（`voice:hotword:edit`） | `/api/v1/voice/hotwords` |

**注册时机**：流式会话创建（`POST /asr/stream-session`）时合并全局热词 + 当前用户热词，经 `registerHotWords` 注册到 FunASR；离线 ASR 同理。热词变更后动态更新，无需重启引擎。接口见 [API接口.md §2.3](./API接口.md)。

### 3.5 ASR 结果处理

FunASR 返回原始文本后做后处理：标点修正（中文逗号→英文逗号等）→ 数字规范化（"八十"→"80"）→ 热词后验证（确保热词未被错误转写）→ 返回最终文本。

### 3.6 云端 ASR 适配（CloudAsrProvider）

- **协议适配**：`sys_voice_provider.protocol_type` 标识（`openai_compat` / 厂商原生），`api_base_url` + `auth_type`（bearer / x-api-key / custom）组装请求；密钥经 `sys_voice_provider_key` 多 Key 选取与失败冷却
- **流式/离线**：按厂商能力映射（流式识别 API / 提交完整音频的同步或异步接口）；热词映射到厂商热词 API，无热词 API 的厂商忽略热词并告警
- **结果契约**：统一转换为本地 `{text, isFinal}` 增量协议，Service 层不感知厂商差异
- **计费**：按厂商 API 定价（对齐 `sys_ai_model_cost` 采购价 + 用户售价），区别于本地按 credits 固定单价

## 4. TTS 实现（LocalTtsProvider / CloudTtsProvider）

> TTS 默认引擎为本地 Piper（`LocalTtsProvider`），纯云端部署为云端（`CloudTtsProvider`，见 §2.4）。本节描述本地实现；云端适配见 §4.5。

### 4.1 TTS 引擎部署架构

Piper TTS 以**进程内引擎**运行于 dehaze-python（`app/infrastructure/voice/piper_tts_engine.py`），作为 `LocalTtsProvider` 实现；GPU 优先（onnxruntime 带 CUDAExecutionProvider 时启用，否则纯 CPU），对齐 FunASR 部署形态。

| 维度 | 说明 |
|------|------|
| 模型 | piper-voices 开源库 zh_CN-huayan-medium（约 60MB，CC-BY-4.0） |
| 音色注册表化 | 本地音色由 `sys_voice_model` 注册（`engine_type=tts`，`model_type=voice`），`params` 携带 onnx 路径/下载 URL/语速映射；可注册/切换多个音色 |
| 懒加载与下载 | 首次合成请求时加载，进程内单例；文件缺失时经 hf-mirror 下载（回退 huggingface.co，断点续传 + 跨进程锁）；多 Worker 各持一份 |
| 输出编码 | PCM 重采样（torchaudio sinc 插值）→ WAV 封装 / MP3 编码（lameenc）/ 裸 PCM |

### 4.2 TTS 合成流程

1. TtsService 按 `SHA256(text + voiceId + speed)` 查缓存，命中直接返回音频 URL（不合成、不扣费）
2. 未命中 → 积分余额预校验 → 调用 Piper 引擎（推理线程池），参数：text、voice、speed（映射 `length_scale=1/speed`）、format、sampleRate
3. 音频 AES 加密存文件管理 → 写入缓存 → 实扣积分
4. 返回音频 URL（`GET /api/v1/voice/tts/audio/{cacheKey}` 解密后流式返回）

> 引擎不可用、合成失败或音频存储失败均返回 A0500，不存储不扣费，前端降级纯文本。当前实现为合成完成后返回 audioUrl。

### 4.3 TTS 缓存策略

| 配置项 | 说明 | 值 |
|--------|------|-----|
| 缓存位置 | 文件管理（sys_file） | — |
| 缓存 Key | `SHA256(text + voiceId + speed)` | — |
| TTL | 24 小时 | 过期自动清理 |
| 最大缓存数 | 单用户 100 条 | LRU 淘汰 |

缓存适合 AI 对话常见开场语与系统提示语等重复文本。

### 4.5 云端 TTS 适配（CloudTtsProvider）

- **协议适配**：`api_base_url` + `auth_type` 组装合成请求，密钥经 `sys_voice_provider_key` 管理；音色映射到 `sys_voice_model`（`model_type=voice`）注册的厂商音色 ID
- **输出归一**：厂商返回音频（mp3/wav/pcm）统一落为本地 `{audioUrl, format}` 契约；语速/采样率由 `sys_voice_model.params` 映射
- **缓存复用**：TTS 缓存（§4.3）对本地/云端一致——缓存 Key 含音色，命中不合成不扣费；云端合成仍经 AES 加密存储
- **计费**：按厂商 API 定价，区别于本地按字符固定 credits

## 5. 流式并发控制与资源回收

| 维度 | 设计 | 说明 |
|------|------|------|
| 并发会话上限 | 最大 50 并发 | 超过上限拒绝新会话并提示 |
| 超时回收 | 单会话 60s 空闲超时自动关闭 | 关闭前端与 FunASR 两端 WebSocket |
| 连接复用 | 连接池管理 FunASR WebSocket 连接 | 会话结束后归还池中，避免频繁建连 |
| 异常回收 | 会话异常/客户端断开时主动关闭 FunASR 连接 | 防止连接泄漏，单会话异常不影响其他会话 |

## 6. 安全设计

### 6.1 认证授权

| 防护项 | 说明 |
|--------|------|
| WebSocket 连接鉴权 | 流式 ASR 的 WebSocket 建立时校验登录态，未认证拒绝建连 |
| 会话 ID 绑定用户 | sessionId 与 userId 绑定，建立会话时校验身份，后续操作验证归属 |
| 跨用户访问拦截 | 查询/操作语音数据时校验归属，仅允许操作本人数据 |

### 6.2 音频安全

| 防护项 | 说明 |
|--------|------|
| 音频格式校验 | 流式 ASR 仅接受 16kHz/16bit/mono PCM，离线 ASR 仅接受 WAV/PCM，非合规格式拒绝处理 |
| 时长限制 | 单次录音最长 60 秒（`voice.asr.max-duration`）；结束方式为客户端 `EOS` / 时长上限 / WS 接收空闲 60s 兜底 |
| 文件大小限制 | 离线 ASR 上传音频大小由文件管理模块统一控制 |
| 音频不落盘 | ASR 音频流式处理，处理完即弃，不持久化原始音频 |
| 传输加密 | 前端 ↔ 业务后端、业务后端 ↔ FunASR 均经 HTTPS/WSS；TTS 为进程内调用不经网络 |
| 缓存加密 | TTS 缓存音频经 AES 加密存储，防止缓存文件被直接读取 |

### 6.3 ASR 安全

| 防护项 | 说明 |
|--------|------|
| 热词注入安全 | 热词由管理员/用户配置，存储前转义、注册到引擎前校验内容合法性，防止注入恶意热词 |

## 7. 模块间协作

### 7.1 与 AI 对话模块

| 集成点 | 说明 |
|--------|------|
| 语音输入 | ASR 文本传入 MessageService 的消息输入管道，由 LLM 统一理解意图并执行 |
| 语音回复 | Text → TTS → 音频 URL 返回前端播放 |

### 7.2 与 AI 计费管理

| 能力 | 计费维度 | bill_type | 挂接点 |
|------|---------|-----------|--------|
| ASR | 按音频时长（秒） | `asr` | 流式会话结束 / 离线识别完成时按实际音频时长计量 |
| TTS | 按合成文本字符数 | `tts` | TTS 合成完成时按实际合成字符数计量 |

> 调用前校验用户余额与限额，不足时拒绝并提示；单价与扣费规则由 AI 计费管理模块统一定义。

## 8. 三端一致性声明

Java/Go/Python 三后端对本模块的对外契约一致（Java 权威，Go/Python 对齐）：

| 项 | 一致性要求 |
|---|-----------|
| 对外接口 | 三端均暴露 `VoiceController`，提供相同的 ASR/TTS HTTP 与 WebSocket 接口（见 [API接口.md](./API接口.md)） |
| ASR 逻辑 | Python 端经 `ASRProvider` 路由（本地见 §3.1，云端见 §3.6）；Java/Go 端 ASR 能力调用 Python 语音业务接口 |
| TTS 逻辑 | Python 端经 `TTSProvider` 路由（本地见 §4.1，云端见 §4.5）；Java/Go 端 TTS 能力调用 Python 语音业务接口 |
| 引擎注册表 | 引擎（本地/云端）、API Key、模型/音色统一存 `sys_voice_provider`/`sys_voice_provider_key`/`sys_voice_model` |

## 9. 配置项

| 配置项 | 说明 | 来源 | 默认值 |
|--------|------|------|--------|
| `voice.engine.*` | 引擎注册表（见 §2.4）：引擎/密钥/模型音色均由数据库配置，默认引擎由 `is_default` 驱动，不走环境变量 | 数据库（`sys_voice_provider` / `sys_voice_provider_key` / `sys_voice_model`） | `local` 为 asr/tts 默认引擎 |
| `voice.asr.model` | ASR 本地模型（流式/离线，LocalAsrProvider 默认） | 应用配置（环境变量 `VOICE_ASR_STREAM_MODEL` / `VOICE_ASR_OFFLINE_MODEL`） | `sensevoice`(流式) |
| `voice.asr.inference-threads` | ASR 推理线程池大小（CPU 密集，与 GPU 推理隔离） | 应用配置（环境变量 `VOICE_ASR_INFERENCE_THREADS`） | 2 |
| `voice.asr.max-duration` | 单次录音最大时长（秒） | 应用配置（环境变量 `VOICE_ASR_MAX_DURATION`） | 60 |
| `voice.asr.max-concurrent-sessions` | 流式 ASR 最大并发会话数 | 应用配置（环境变量 `VOICE_ASR_MAX_CONCURRENT_SESSIONS`） | 50 |
| `voice.tts.voice-id` | 默认音色 ID（本地 Piper 音色，LocalTtsProvider 默认） | 应用配置（环境变量 `VOICE_TTS_VOICE_ID`） | `huayan` |
| `voice.tts.inference-threads` | TTS 推理线程池大小（CPU 密集，与 ASR/GPU 推理隔离） | 应用配置（环境变量 `VOICE_TTS_INFERENCE_THREADS`） | 2 |
| `voice.tts.model-path` | 模型文件路径（默认仓库根 `models/piper/` 自动管理） | 应用配置（环境变量 `VOICE_TTS_MODEL_PATH`） | 空（默认） |
| `voice.tts.cache-ttl` | TTS 缓存过期时间（秒） | 应用配置（环境变量 `VOICE_TTS_CACHE_TTL`） | 86400 |
| `voice.tts.max-cache-per-user` | 单用户最大缓存数 | 应用配置（环境变量 `VOICE_TTS_MAX_CACHE_PER_USER`） | 100 |

## 10. 缓存策略

| 缓存对象 | 缓存 Key | TTL | 更新策略 |
|---------|---------|------|---------|
| 语音记录 | `voice:record:{recordId}` | 30 分钟 | 记录变更时失效 |
| 用户记录列表 | 不缓存 | - | 实时分页查询 |
| ASR 会话状态 | `voice:asr:{sessionId}` | 会话期间 | 实时更新，会话结束后自动过期 |
