# 语音交互模块 - 后端实现设计

## 1. 文档概述

### 1.1 架构概览

语音交互模块采用 **ASR + TTS 全本地部署**架构（零外部 API 依赖）。ASR 基于 FunASR 在 Python 微服务中本地运行（CPU），TTS 基于 Piper 引擎在 Python 微服务中本地运行（CPU）。前端不直连引擎，流式 ASR 经业务后端（Java/Go）WebSocket 代理。

```
前端录音 → WebSocket(业务后端) → 业务后端代理 → Python FunASR微服务 → 文本 → AI对话模块消息管道(LLM统一理解意图并执行)

后端文本 → Python Piper TTS 引擎（进程内） → 音频 → 前端播放
```

## 2. 模块架构

### 2.1 分层架构

```
Controller 层
├── VoiceController              # 语音识别结果查询、TTS合成请求
└── VoiceWebSocketController     # 流式 ASR WebSocket 连接管理（前端接入 + 代理至 FunASR）

Service 层
├── VoiceService                 # 语音能力总入口（录音管理、结果查询）
├── AsrService                   # ASR 编排（WebSocket 流式代理 / HTTP 离线）
└── TtsService                   # TTS 编排（本地引擎调用 + 缓存）

基础设施层
├── FunASR 引擎（dehaze-python 进程内）  # 流式/离线 ASR 推理（CPU）
└── Piper TTS 引擎（dehaze-python 进程内） # 语音合成（CPU）
```

### 2.2 核心组件职责

| 组件 | 职责 |
|------|------|
| VoiceService | 录音会话管理、结果查询、ASR/TTS 统一调度 |
| AsrService | 业务后端与 FunASR 间的 WebSocket 代理、流式音频转发、识别结果回推前端 |
| TtsService | 本地 TTS 引擎调用、合成、音频缓存查询（TtsCacheManager 职责并入，不额外拆分） |

## 3. ASR 实现（FunASR 本地部署）

### 3.1 FunASR 部署架构

FunASR 引擎以**进程内引擎**形式运行在 dehaze-python 中（`app/infrastructure/voice/funasr_engine.py`），CPU 推理，与 GPU 图像处理资源隔离：

```
FunASR 本地引擎（dehaze-python 进程内）
├── 流式识别：SenseVoice-Small 分段增量识别（伪流式，每累计 1 秒音频输出一次累计文本）
├── 离线识别：SeACo-Paraformer-Large（Paraformer-Large 热词增强版，原生热词加权）
└── 热词：进程内内存表，注册后对流式/离线推理即时生效
```

- **依赖安装**：funasr/modelscope/torchaudio 为主依赖（延迟导入控制启动成本），`uv sync` 即包含
- **模型懒加载**：首个 ASR 请求时加载，进程内单例；多 Worker 部署时每 Worker 各持一份模型
- **模型缓存**：首次使用自动从 ModelScope 下载（SenseVoice-Small 约 1GB、SeACo-Paraformer 约 1GB）

> FunASR 部署硬件要求见 [需求规格 §7.2](./需求规格.md)。
> Java/Go 后端如需 ASR 能力，可调用 Python 端语音业务接口，或另行决策部署形态（见 §8）。

### 3.2 流式 ASR 流程

前端经 WebSocket 连接业务后端，业务后端代理 WebSocket 至 Python FunASR 服务，识别结果经同一 WebSocket 通道回推前端：

```
前端调用 POST /asr/stream-session → 获取 sessionId + wsUrl（业务后端 /ws/asr）
    ↓
前端经 wsUrl 建立 WebSocket → 推送 PCM 音频块（每 100ms，16kHz）
    ↓
业务后端 AsrService 代理音频块至 FunASR（ws://voice-service:8765/ws/asr）
    ↓
FunASR 实时解码 → 返回增量文本至业务后端
    ↓
业务后端经 WebSocket 推送增量文本至前端实时展示
    ↓
前端停止录音 → 发送 EOS → FunASR 输出最终结果 → 业务后端关闭两端 WebSocket
```

**WebSocket 协议（前端 ↔ 业务后端）**：

| 方向 | 消息格式 | 说明 |
|------|---------|------|
| 前端→业务后端 | 二进制 PCM 音频块 | 16kHz, 16bit, mono |
| 业务后端→前端 | JSON `{"text": "增量", "isFinal": false}` | 中间结果 |
| 业务后端→前端 | JSON `{"text": "完整文本", "isFinal": true}` | 最终结果 |
| 前端→业务后端 | 文本 `"EOS"` | 结束信号 |

> 下行字段为 `isFinal`（camelCase），与 SDK 契约（`dehaze-sdk-js/src/api/voice/model.ts` 的 `AsrStreamMessage`）一致。

### 3.3 离线 ASR 流程

离线 ASR 采用 **multipart 直传**音频文件，不经文件管理持久化（遵循 §6"音频不落盘"安全要求，处理完即弃）：

```
前端上传完整音频文件（multipart/form-data 直传）
    ↓
后端调用 FunASR HTTP: POST /api/asr/offline
  - 传入: 音频文件（WAV/PCM，16kHz/16bit/mono）
  - 模型: Paraformer-Large（高精度）
    ↓
FunASR 返回完整识别文本（含标点、断句）
    ↓
后端返回识别结果给前端（音频不落盘，处理完即弃）
```

### 3.4 热词配置

领域热词提升专业术语识别率。AsrService 通过 `registerHotWords` 接口将热词列表（如 RIDCP、FFA-Net、PSNR、SSIM、去雾、暗通道先验）传递到 FunASR 模型配置中，识别时这些词汇的匹配优先级提升。

热词分两类管理（接口见 [API接口.md §2.3](./API接口.md)）：

| 热词类型 | 生效范围 | 管理权限 | 接口归属 |
|---------|---------|---------|---------|
| 全局热词 | 所有用户 | 管理员（`voice:hotword:edit`） | `/api/v1/voice/hotwords/global` |
| 用户级热词 | 当前用户 | 用户本人（`voice:hotword:edit`） | `/api/v1/voice/hotwords` |

**注册时机**：流式 ASR 会话创建（POST /asr/stream-session）时，将全局热词 + 当前用户热词合并后注册到 FunASR；离线 ASR 同理。热词变更后无需重启 FunASR，`registerHotWords` 动态更新模型配置。

### 3.5 ASR 结果处理

```
FunASR 返回原始文本
    ↓
后处理：
  - 标点修正（中文逗号→英文逗号修正等）
  - 数字规范化（"八十"→"80"）
  - 热词后验证（确保热词未被错误转写）
    ↓
返回最终文本
```

## 4. TTS 实现（Piper 本地引擎）

### 4.1 TTS 引擎部署架构

TTS 引擎以**进程内引擎**形式运行在 dehaze-python 中（`app/infrastructure/voice/piper_tts_engine.py`），CPU 推理，对齐 FunASR 的部署形态：

```
Piper 本地 TTS 引擎（dehaze-python 进程内）
├── 模型：piper-voices 开源库 zh_CN-huayan-medium（约 60MB，CC-BY-4.0）
├── 模型懒加载：首次合成请求时加载，进程内单例；多 Worker 部署时每 Worker 各持一份
├── 模型自动下载：文件缺失时经 hf-mirror 下载（回退 huggingface.co，断点续传 + 跨进程锁）
└── 输出编码：PCM 重采样（torchaudio sinc 插值）→ WAV 封装 / MP3 编码（lameenc）/ 裸 PCM
```

### 4.2 TTS 合成流程

```
后端收到 TTS 请求（文本 + 音色 + 语速）
    ↓
TtsService 查询缓存（Key = SHA256(text + voiceId + speed)）
  - 命中 → 返回缓存音频 URL（不合成、不扣费）
    ↓
未命中 → 余额预校验 → 调用本地 Piper 引擎（推理线程池）
  - 参数: text、voice(huayan)、speed(映射 length_scale=1/speed)、format(mp3/wav/pcm)、sampleRate
    ↓
音频加密存储到文件管理 → 写入缓存 → 实扣积分
    ↓
返回音频 URL（GET /api/v1/voice/tts/audio/{cacheKey}，解密后流式返回）
```

> 流式 TTS（边合成边推送，降低首播延迟）为规划项，当前实现为合成完成后返回 audioUrl。

### 4.3 TTS 缓存策略

| 配置项 | 说明 | 值 |
|--------|------|-----|
| 缓存位置 | 文件管理（sys_file） | — |
| 缓存 Key | `SHA256(text + voiceId + speed)` | — |
| TTL | 24 小时 | 过期自动清理 |
| 最大缓存数 | 单用户 100 条 | LRU 淘汰 |

**缓存适合场景**：
- AI 对话常见开场语（"您好，请上传图片"、"处理完成，请查看结果"）
- 系统提示语（"参数设置完成"、"开始处理"）

### 4.4 TTS 异常处理

| 异常 | 处理 |
|------|------|
| 本地 TTS 引擎不可用（依赖缺失/模型加载失败） | 返回错误提示，前端展示纯文本回复 |
| 合成失败（推理异常/空音频） | 返回错误提示，不存储不扣费 |
| 音频存储失败 | 返回错误提示 |

## 5. 流式并发控制与资源回收

| 维度 | 设计 | 说明 |
|------|------|------|
| 并发会话上限 | 最大 50 并发 | 超过上限拒绝新会话并提示（指标见 [需求规格 §5.2](./需求规格.md)） |
| 超时回收 | 单会话 60s 空闲超时自动关闭 | 超时后业务后端关闭前端与 FunASR 两端 WebSocket |
| FunASR 连接复用 | 连接池管理 FunASR WebSocket 连接 | 避免频繁建连开销，会话结束后连接归还池中 |
| 异常资源回收 | 会话异常/客户端断开时主动关闭 FunASR 连接 | 防止连接泄漏，确保单会话异常不影响其他会话 |

## 6. 安全设计

| 方面 | 设计 |
|------|------|
| 音频不落盘 | ASR 音频流式处理，处理完即弃，不持久化存储原始音频 |
| 传输加密 | 前端 ↔ 业务后端、业务后端 ↔ FunASR 均经 HTTPS/WSS 加密传输；TTS 为进程内调用不经网络 |
| TTS 缓存加密 | TTS 缓存音频内容采用 AES 加密存储，防止缓存文件被直接读取 |
| 会话隔离 | ASR 会话按 userId 维度隔离，会话 ID 绑定用户，不可跨用户访问 |
| 录音授权 | 录音权限申请与授权由前端处理（见 [需求规格 §2.3](./需求规格.md)），后端不涉及 |

### 6.1 认证授权

| 防护项 | 说明 |
|--------|------|
| WebSocket 连接鉴权 | 流式 ASR 的 WebSocket 连接建立时校验用户登录态，未认证请求拒绝建立连接 |
| 会话 ID 绑定用户 | ASR 会话 ID（sessionId）与 userId 绑定，建立会话时校验身份，后续操作验证会话归属 |
| 跨用户访问拦截 | 查询/操作语音记录时校验记录归属，仅允许操作自己的语音数据 |

### 6.2 音频安全

| 防护项 | 说明 |
|--------|------|
| 音频格式校验 | 流式 ASR 仅接受 16kHz/16bit/mono PCM，离线 ASR 仅接受 WAV/PCM，非合规格式拒绝处理 |
| 时长限制 | 单次录音最长 60 秒，超时自动结束；静音 3 秒自动结束，取先到者 |
| 文件大小限制 | 离线 ASR 上传的音频文件大小由文件管理模块统一控制 |

### 6.3 ASR 安全

| 防护项 | 说明 |
|--------|------|
| 识别内容过滤 | ASR 识别结果在返回前端前进行敏感词检测，命中敏感词时脱敏处理 |
| 热词注入安全 | 热词列表由管理员/用户配置，注册到 FunASR 时校验内容合法性，防止注入恶意热词 |

### 6.4 TTS 安全

| 防护项 | 说明 |
|--------|------|
| 合成内容过滤 | TTS 合成前对输入文本进行敏感词检测，违规内容拒绝合成并返回错误提示 |
| 缓存音频保护 | TTS 缓存音频采用 AES 加密存储，防止缓存文件被直接读取（见 §4.3） |

### 6.5 配额控制

| 防护项 | 说明 |
|--------|------|
| 积分校验 | ASR/TTS 调用前校验用户 AI 积分余额，余额不足时拒绝并提示 |
| 积分扣减 | ASR 按音频时长（秒）计费，TTS 按合成文本字符数计费，调用完成后实扣 |
| 计费对接 | 积分计量与扣减委托 AI 计费管理模块统一处理（见 §7.2） |

## 7. 模块间协作

### 7.1 与 AI 对话模块

| 集成点 | 说明 |
|--------|------|
| 语音输入 | ASR 文本传入 MessageService 的消息输入管道，由 LLM 统一理解意图并执行 |
| 语音回复 | Text→TTS→音频 URL 返回前端播放 |

### 7.2 与 AI 计费管理

ASR/TTS 调用计入 AI 积分，调用前校验余额与限额，调用后实扣：

| 能力 | 计费维度 | bill_type | 挂接点 |
|------|---------|-----------|--------|
| ASR | 按音频时长（秒） | `asr` | 流式会话结束 / 离线识别完成时按实际音频时长计量 |
| TTS | 按合成文本字符数 | `tts` | TTS 合成完成时按实际合成字符数计量 |

> 计费单价与扣费规则由 AI 计费管理模块统一定义；调用前校验用户余额与限额，余额不足时拒绝并提示。

## 8. 三端一致性声明

Java/Go/Python 三后端对语音交互模块的对外契约与核心逻辑完全一致（Java 权威，Go/Python 对齐）：

| 项 | 一致性要求 |
|---|-----------|
| 对外接口 | 三端均暴露 `VoiceController`，提供 ASR/TTS 相同的 HTTP 与 WebSocket 接口（见 [API接口.md](./API接口.md)） |
| ASR 逻辑 | Python 端 FunASR 引擎进程内运行（见 §3.1）；Java/Go 端 ASR 能力可调用 Python 语音业务接口，部署形态随 Java/Go 落地另行决策 |
| TTS 逻辑 | Python 端 Piper 引擎进程内运行（见 §4.1）；Java/Go 端 TTS 能力可调用 Python 语音业务接口，部署形态随 Java/Go 落地另行决策 |
| 语音引擎提供方 | Python 作为 FunASR（ASR）与 Piper（TTS）引擎的提供方与部署方（dehaze-python 进程内，CPU 推理） |

### 9.1 Python 端实现说明（已落地）

三端对齐声明（§8）中 Python 端已实现，关键实现决策：

- **FunASR 引擎进程内运行**：`funasr_engine.py` 懒加载模型（进程内单例）+ 专用 CPU 推理线程池；`funasr_client.py` 对 Service 层保持接口不变，内部为本地调用。多 Worker 部署时模型每 Worker 一份（内存成本 = Worker 数 × 约 2GB，部署时按并发评估 Worker 数或接受该成本）。
- **本地 TTS 选型**：Piper 开源引擎（MIT，piper-tts + onnxruntime，进程内 CPU 推理），模型 zh_CN-huayan-medium（约 60MB）自动从 hf-mirror 下载缓存；语速映射 `length_scale = 1/speed`；输出重采样（torchaudio sinc）后按 mp3/wav/pcm 编码（lameenc）。引擎异常抛业务错误 A0500（前端降级纯文本），缓存命中不合成、不扣费；典型合成性能约 0.3 秒/20 字（CPU）。
- **TTS 缓存加密**：AES-256-GCM（密钥由环境变量注入后 SHA256 派生 32 字节），密文经文件管理（`sys_file`）存储；`audioUrl` 指向 `GET /api/v1/voice/tts/audio/{cacheKey}`，按用户维度校验缓存归属后解密流式返回（仅本人可访问）。
- **ASR 会话状态**：Redis `voice:asr:{sessionId}`（含 user_id/status/text，会话结束保留 30 分钟供结果查询）；并发控制用有序集合 `voice:asr:sessions`（按时间戳剪枝后计数）。
- **热词表**：`sys_voice_hotword`（见 [02-系统架构/03-数据库设计.md §4.10](../../../02-系统架构/03-数据库设计.md)）。
- **计费挂接**：`VoiceBillingService` 复用 AI 计费的配额（QuotaService）与余额（BalanceService）双控，`bill_type` 为 `asr`/`tts` 记入 `sys_ai_billing`（ASR 用量秒数/TTS 字符数记入 `input_tokens`）；调用前预校验（ASR 按 10 秒起步预估、TTS 按文本长度预估），完成后实扣并写积分流水。
- **敏感词过滤**（§6.3/§6.4）暂未实现：现有 `guardrail_middleware` 为 deepagents 推理链路专用中间件，无可复用的通用文本过滤实现，待统一内容安全模块承接。
- **静音自动结束**暂未实现：本地引擎未集成 VAD，静音场景由 WebSocket 空闲超时（60 秒）兜底结束。

## 10. 缓存策略

| 缓存对象 | 缓存 Key | TTL | 更新策略 |
|---------|---------|------|---------|
| 语音记录 | `voice:record:{recordId}` | 30 分钟 | 记录变更时失效 |
