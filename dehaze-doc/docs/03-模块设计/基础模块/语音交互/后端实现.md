# 语音交互模块 - 后端实现设计

## 1. 文档概述

### 1.1 架构概览

语音交互模块采用 **ASR 本地部署 + TTS 外部 API** 混合架构。ASR 基于 FunASR 在 Python 微服务中本地运行（CPU），TTS 调用阿里云/腾讯云 API。前端不直连 FunASR，流式 ASR 经业务后端（Java/Go）WebSocket 代理。

```
前端录音 → WebSocket(业务后端) → 业务后端代理 → Python FunASR微服务 → 文本 → AI对话模块消息管道(LLM统一理解意图并执行)

后端文本 → 云 TTS API(阿里云/腾讯云) → 音频流 → 前端播放
```

## 2. 模块架构

### 2.1 分层架构

```
Controller 层
├── VoiceController              # 语音识别结果查询、TTS合成请求
└── VoiceWebSocketController     # 流式 ASR WebSocket 连接管理（前端接入 + 代理至 FunASR）

Service 层
├── VoiceService                 # 语音能力总入口（录音管理、结果查询）
├── AsrService                   # ASR 编排（WebSocket 流式代理 / HTTP 离线）
├── TtsService                   # TTS 编排（云 API 调用 + 缓存）
└── TtsCacheManager              # TTS 音频缓存管理

外部依赖
├── FunASR（Python 微服务）       # 流式 ASR 引擎（业务后端经 WebSocket 代理调用）
└── Cloud TTS API（阿里云/腾讯云） # 语音合成（HTTP API）
```

### 2.2 核心组件职责

| 组件 | 职责 |
|------|------|
| VoiceService | 录音会话管理、结果查询、ASR/TTS 统一调度 |
| AsrService | 业务后端与 FunASR 间的 WebSocket 代理、流式音频转发、识别结果回推前端 |
| TtsService | 云 TTS API 调用、流式/非流式合成、音频缓存查询 |
| TtsCacheManager | TTS 音频缓存读写（key = hash(text + voiceId + speed)） |

## 3. ASR 实现（FunASR 本地部署）

### 3.1 FunASR 部署架构

FunASR 作为独立的 Python 微服务运行，由业务后端经 WebSocket/HTTP 代理调用，前端不直连：

```
FunASR 微服务（Python）
├── 流式 ASR WebSocket: ws://voice-service:8765/ws/asr
│   └── 业务后端代理推送 PCM 音频块 → 实时返回文本增量
└── 离线 ASR HTTP: POST /api/asr/offline
    └── 业务后端提交完整音频文件 → 返回完整识别文本
```

> FunASR 部署硬件要求见 [需求规格 §7.2](./需求规格.md)。

**模型依赖**：
- 流式识别模型：SenseVoice-Small（实时识别，模型体积小）
- 离线高精度模型：Paraformer-Large（完整音频识别，准确率更高）

### 3.2 流式 ASR 流程

前端经 WebSocket 连接业务后端，业务后端代理 WebSocket 至 Python FunASR 服务，识别结果经同一 WebSocket 通道回推前端：

```
前端调用 POST /asr/stream-session → 获取 sessionId + wsUrl（业务后端 /ws/asr）
    ↓
前端经 wsUrl 建立 WebSocket → 推送 PCM 音频块（每 100ms，16kHz）
    ↓
业务后端 AsrService 代理音频块至 FunASR（ws://voice-service:8765/ws/asr）
    ↓
FunASR 实时解码 → 返回增量文本至业务后端
    ↓
业务后端经 WebSocket 推送增量文本至前端实时展示
    ↓
前端停止录音 → 发送 EOS → FunASR 输出最终结果 → 业务后端关闭两端 WebSocket
```

**WebSocket 协议（前端 ↔ 业务后端）**：

| 方向 | 消息格式 | 说明 |
|------|---------|------|
| 前端→业务后端 | 二进制 PCM 音频块 | 16kHz, 16bit, mono |
| 业务后端→前端 | JSON `{"text": "增量", "is_final": false}` | 中间结果 |
| 业务后端→前端 | JSON `{"text": "完整文本", "is_final": true}` | 最终结果 |
| 前端→业务后端 | 文本 `"EOS"` | 结束信号 |

### 3.3 离线 ASR 流程

```
前端上传完整音频文件
    ↓
后端调用 FunASR HTTP: POST /api/asr/offline
  - 传入: 音频文件（WAV/PCM）
  - 模型: Paraformer-Large（高精度）
    ↓
FunASR 返回完整识别文本（含标点、断句）
    ↓
后端返回结果给前端
```

### 3.4 热词配置

领域热词提升专业术语识别率。AsrService 通过 `registerHotWords` 接口将热词列表（如 RIDCP、FFA-Net、PSNR、SSIM、去雾、暗通道先验）传递到 FunASR 模型配置中，识别时这些词汇的匹配优先级提升。

### 3.5 ASR 结果处理

```
FunASR 返回原始文本
    ↓
后处理：
  - 标点修正（中文逗号→英文逗号修正等）
  - 数字规范化（"八十"→"80"）
  - 热词后验证（确保热词未被错误转写）
    ↓
返回最终文本
```

## 4. TTS 实现（云 API 调用）

### 4.1 TTS 调用架构

```
后端收到 TTS 请求（文本 + 音色 + 语速）
    ↓
TtsCacheManager 查询缓存（Key = SHA256(text + voiceId + speed)）
  - 命中 → 返回缓存音频 URL
    ↓
未命中 → 调用云 TTS API（阿里云 nls.aliyuncs.com / 腾讯云 tts.cloud.tencent.com）
  - 参数: text、voice、speed、format(mp3)、sampleRate(16000)
    ↓
接收音频流 → 存储到文件管理 → 写入缓存
    ↓
返回音频 URL（通过 FileService.getUrl() 拼接）
```

### 4.2 流式 TTS

减少首播延迟（不需要完整下载再播放）：

```
调用云 TTS API（流式模式）
    ↓
接收音频块 → 边接收边通过流式 HTTP 响应推送到前端
    ↓
前端边接收边播放
```

### 4.3 TTS 缓存策略

| 配置项 | 说明 | 值 |
|--------|------|-----|
| 缓存位置 | 文件管理（sys_file） | — |
| 缓存 Key | `SHA256(text + voiceId + speed)` | — |
| TTL | 24 小时 | 过期自动清理 |
| 最大缓存数 | 单用户 100 条 | LRU 淘汰 |

**缓存适合场景**：
- AI 对话常见开场语（"您好，请上传图片"、"处理完成，请查看结果"）
- 系统提示语（"参数设置完成"、"开始处理"）

### 4.4 TTS 降级策略

| 异常 | 处理 |
|------|------|
| 云 TTS API 不可用 | 返回错误提示，前端展示纯文本回复 |
| API 额度耗尽 | 返回错误提示 + 提示管理员充值 |
| 网络超时 | 重试 1 次后降级为纯文本 |
| 音频存储失败 | 直接流式推送到前端不缓存 |

## 5. 流式并发控制与资源回收

| 维度 | 设计 | 说明 |
|------|------|------|
| 并发会话上限 | 最大 50 并发 | 超过上限拒绝新会话并提示（指标见 [需求规格 §5.2](./需求规格.md)） |
| 超时回收 | 单会话 60s 空闲超时自动关闭 | 超时后业务后端关闭前端与 FunASR 两端 WebSocket |
| FunASR 连接复用 | 连接池管理 FunASR WebSocket 连接 | 避免频繁建连开销，会话结束后连接归还池中 |
| 异常资源回收 | 会话异常/客户端断开时主动关闭 FunASR 连接 | 防止连接泄漏，确保单会话异常不影响其他会话 |

## 6. 安全设计

| 方面 | 设计 |
|------|------|
| 音频不落盘 | ASR 音频流式处理，处理完即弃，不持久化存储原始音频 |
| 传输加密 | 前端 ↔ 业务后端、业务后端 ↔ FunASR、业务后端 ↔ 云 TTS 均经 HTTPS/WSS 加密传输 |
| TTS 缓存加密 | TTS 缓存音频内容采用 AES 加密存储，防止缓存文件被直接读取 |
| 会话隔离 | ASR 会话按 userId 维度隔离，会话 ID 绑定用户，不可跨用户访问 |
| 录音授权 | 录音权限申请与授权由前端处理（见 [需求规格 §2.3](./需求规格.md)），后端不涉及 |

## 7. 模块间协作

### 7.1 与 AI 对话模块

| 集成点 | 说明 |
|--------|------|
| 语音输入 | ASR 文本传入 MessageService 的消息输入管道，由 LLM 统一理解意图并执行 |
| 语音回复 | Text→TTS→音频 URL 返回前端播放 |

### 7.2 与 AI 计费管理

ASR/TTS 调用计入 AI 积分，调用前校验余额与限额，调用后实扣：

| 能力 | 计费维度 | bill_type | 挂接点 |
|------|---------|-----------|--------|
| ASR | 按音频时长（秒） | `asr` | 流式会话结束 / 离线识别完成时按实际音频时长计量 |
| TTS | 按合成文本字符数 | `tts` | TTS 合成完成时按实际合成字符数计量 |

> 计费单价与扣费规则由 AI 计费管理模块统一定义；调用前校验用户余额与限额，余额不足时拒绝并提示。

## 8. 三端一致性声明

Java/Go/Python 三后端对语音交互模块的对外契约与核心逻辑完全一致（Java 权威，Go/Python 对齐）：

| 项 | 一致性要求 |
|---|-----------|
| 对外接口 | 三端均暴露 `VoiceController`，提供 ASR/TTS 相同的 HTTP 与 WebSocket 接口（见 [API接口.md](./API接口.md)） |
| ASR 逻辑 | 三端流式 ASR 均经 WebSocket 代理至 FunASR，离线 ASR 经 HTTP 调用 FunASR，逻辑一致 |
| TTS 逻辑 | 三端均直接调用云 TTS API（阿里云/腾讯云），缓存策略一致 |
| FunASR 提供方 | Python 作为 FunASR 微服务的提供方与部署方；Java/Go 经 WebSocket/HTTP 代理调用 Python FunASR |

## 9. 配置项

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `voice.asr.model` | ASR 模型（流式/离线） | `sensevoice`(流式) |

| `voice.asr.max-duration` | 单次录音最大时长（秒） | 60 |
| `voice.asr.silence-timeout` | 静音自动结束阈值（秒） | 3 |
| `voice.asr.max-concurrent-sessions` | 流式 ASR 最大并发会话数 | 50 |
| `voice.tts.provider` | TTS 服务商 | `aliyun` |
| `voice.tts.voice-id` | 默认音色 ID | `aixia` |
| `voice.tts.cache-ttl` | TTS 缓存过期时间（秒） | 86400 |
| `voice.tts.max-cache-per-user` | 单用户最大缓存数 | 100 |
