# 语音交互模块 - 后端实现设计

## 1. 文档概述

### 1.1 架构概览

语音交互模块采用 **ASR 本地部署 + TTS 外部 API** 混合架构。ASR 基于 FunASR 在 Python 微服务中本地运行（CPU），TTS 调用阿里云/腾讯云 API。

```
前端录音 → WebSocket音频流 → Python ASR微服务(FunASR) → 文本 → 后端 → AI对话模块消息管道(LLM统一理解意图并执行)

后端文本 → Python TTS管理 → 阿里云/腾讯云API → 音频流 → 前端播放
```

## 2. 模块架构

### 2.1 分层架构

```
Controller 层
├── VoiceController              # 语音识别结果查询、TTS合成请求
├── VoiceWebSocketController     # 流式 ASR WebSocket 连接管理

Service 层
├── VoiceService                 # 语音能力总入口（录音管理、结果查询）
├── AsrService                   # ASR 编排（WebSocket 流式/HTTP 离线）
├── TtsService                   # TTS 编排（云 API 调用 + 缓存）
└── TtsCacheManager              # TTS 音频缓存管理

外部依赖
├── FunASR（Python 微服务）       # 流式 ASR 引擎（WebSocket 推音频流 → 文本流）
└── Cloud TTS API（阿里云/腾讯云） # 语音合成（HTTP API）
```

### 2.2 核心组件职责

| 组件 | 职责 |
|------|------|
| VoiceService | 录音会话管理、结果查询、ASR/TTS 统一调度 |
| AsrService | FunASR 连接管理、流式音频推流、识别结果回调 |
| TtsService | 云 TTS API 调用、流式/非流式合成、音频缓存查询 |
| TtsCacheManager | TTS 音频缓存读写（key = hash(text + voiceId + speed)） |

## 3. ASR 实现（FunASR 本地部署）

### 3.1 FunASR 部署架构

FunASR 作为独立的 Python 微服务运行，提供 WebSocket 流式 ASR 和 HTTP 离线 ASR 两种接口：

```
FunASR 微服务（Python）
├── 流式 ASR WebSocket: ws://voice-service:8765/ws/asr
│   └── 接收 PCM 音频块 → 实时返回文本增量
└── 离线 ASR HTTP: POST /api/asr/offline
    └── 接收完整音频文件 → 返回完整识别文本
```

**依赖安装**：
- 流式识别模型（实时识别，模型体积小）
- 离线高精度模型（完整音频识别，准确率更高）

**硬件要求**：
- CPU: 4 核（流式）/ 8 核（离线）
- 内存: 2GB（流式）/ 4GB（离线）
- 无需 GPU

### 3.2 流式 ASR 流程

```
前端开始录音
    ↓
建立 WebSocket 连接: ws://voice-service:8765/ws/asr
    ↓
实时推送 PCM 音频块（每 100ms 一块，16kHz 采样率）
    ↓
FunASR SenseVoice-Small 实时解码
    ↓
每块返回增量文本（WebSocket 推送给后端）
    ↓
后端通过 SSE 推送给前端实时展示
    ↓
前端停止录音 → 发送 EOS 信号 → FunASR 输出最终结果 → WebSocket 关闭
```

**WebSocket 协议**：

| 方向 | 消息格式 | 说明 |
|------|---------|------|
| 前端→FunASR | 二进制 PCM 音频块 | 16kHz, 16bit, mono |
| FunASR→后端 | JSON `{"text": "增量", "is_final": false}` | 中间结果 |
| FunASR→后端 | JSON `{"text": "完整文本", "is_final": true}` | 最终结果 |
| 前端→FunASR | 文本 `"EOS"` | 结束信号 |

### 3.3 离线 ASR 流程

```
前端上传完整音频文件
    ↓
后端调用 FunASR HTTP: POST /api/asr/offline
  - 传入: 音频文件（WAV/PCM）
  - 模型: Paraformer-Large（高精度）
    ↓
FunASR 返回完整识别文本（含标点、断句）
    ↓
后端返回结果给前端
```

### 3.4 热词配置

领域热词提升专业术语识别率：

```
AsrService.registerHotWords(["RIDCP", "FFA-Net", "PSNR", "SSIM", "去雾", "暗通道先验"])
    ↓
传递到 FunASR 模型配置中
    ↓
识别时这些词汇的匹配优先级提升
```

### 3.5 ASR 结果处理

```
FunASR 返回原始文本
    ↓
后处理：
  - 标点修正（中文逗号→英文逗号修正等）
  - 数字规范化（"八十"→"80"）
  - 热词后验证（确保热词未被错误转写）
    ↓
返回最终文本
```

## 4. TTS 实现（云 API 调用）

### 4.1 TTS 调用架构

```
后端收到 TTS 请求（文本 + 音色 + 语速）
    ↓
TtsCacheManager 查询缓存：
  - Key = SHA256(text + voiceId + speed)
  - 命中 → 返回缓存音频 URL
    ↓
未命中 → 调用云 TTS API：
  - 阿里云: POST nls.aliyuncs.com
  - 腾讯云: POST tts.cloud.tencent.com
  - 参数: {text, voice, speed, format: "mp3", sampleRate: 16000}
    ↓
接收音频流 → 存储到文件管理 → 写入缓存
    ↓
返回音频 URL（通过 FileService.getUrl() 拼接）
```

### 4.2 流式 TTS

减少首播延迟（不需要完整下载再播放）：

```
调用云 TTS API（流式模式）
    ↓
接收音频块 → 边接收边通过 SSE 推送到前端
    ↓
前端边接收边播放（AudioBufferSourceNode 队列）
```

### 4.3 TTS 缓存策略

| 配置项 | 说明 | 值 |
|--------|------|-----|
| 缓存位置 | 文件管理（sys_file） | — |
| 缓存 Key | `SHA256(text + voiceId + speed)` | — |
| TTL | 24 小时 | 过期自动清理 |
| 最大缓存数 | 单用户 100 条 | LRU 淘汰 |

**缓存适合场景**：
- AI 对话常见开场语（"您好，请上传图片"、"处理完成，请查看结果"）
- 系统提示语（"参数设置完成"、"开始处理"）

### 4.4 TTS 降级策略

| 异常 | 处理 |
|------|------|
| 云 TTS API 不可用 | 返回错误提示，前端展示纯文本回复 |
| API 额度耗尽 | 返回错误提示 + 提示管理员充值 |
| 网络超时 | 重试 1 次后降级为纯文本 |
| 音频存储失败 | 直接流式推送到前端不缓存 |

## 5. 模块间协作

### 5.1 与 AI 对话模块

| 集成点 | 说明 |
|--------|------|
| 语音输入 | ASR 文本传入 MessageService 的消息输入管道，由 LLM 统一理解意图并执行 |
| 语音回复 | Text→TTS→音频 URL 返回前端播放 |

## 6. 配置项

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `voice.asr.model` | ASR 模型（流式/离线） | `sensevoice`(流式) |
| `voice.asr.ws-port` | FunASR WebSocket 端口 | 8765 |
| `voice.asr.max-duration` | 单次录音最大时长（秒） | 60 |
| `voice.asr.silence-timeout` | 静音自动结束阈值（秒） | 3 |
| `voice.tts.provider` | TTS 服务商 | `aliyun` |
| `voice.tts.voice-id` | 默认音色 ID | `aixia` |
| `voice.tts.cache-ttl` | TTS 缓存过期时间（秒） | 86400 |
| `voice.tts.max-cache-per-user` | 单用户最大缓存数 | 100 |
