# 语音交互模块测试用例

## 1. 测试目标

验证需求规格 F-VS-001~004 全部功能点，覆盖正常流程、边界条件与异常分支，并验证服务状态监控、AI 计费关联、并发与资源回收（范围见 §3.4）。

---

## 3. 测试前置

### 3.1 测试数据

| 数据类型         | 准备内容                                                                 | 说明                    |
| ---------------- | ------------------------------------------------------------------------ | ----------------------- |
| **短语音**       | 2-3 秒录音（"你好"、"开始处理"、"强度调到80"）                           | 基础功能验证            |
| **长语音**       | 30-55 秒录音（连续对话，含中英混杂专业术语）                             | 长语音连续识别验证      |
| **噪声语音**     | 含环境噪声的录音（风扇/键盘/空调背景）                                   | 噪声鲁棒性验证          |
| **专业术语语音** | 含"RIDCP"、"FFA-Net"、"PSNR"、"SSIM"、"暗通道先验"等术语                 | 热词识别率验证          |
| **静音**         | 1 秒和 5 秒静音录音                                                      | 静音段边界/空闲超时验证 |
| **TTS 文本**     | "处理完成，PSNR 28.5，SSIM 0.92"，"您好，请上传图片"（缓存命中测试文本） | TTS 合成和缓存验证      |
| **长 TTS 文本**  | 500 字 LLM 回复                                                          | 长文本合成验证          |

### 3.2 测试基础设施

| 组件                | 说明                                                                                                                                                                                                                                                               |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `dehaze-voice` 服务 | 独立进程（8993，内网专用）：FunASR（SenseVoice-Small 流式 + Paraformer-Large 离线）与 Piper TTS；只做推理，零 DB/Redis/存储依赖，以 OpenAI Audio 兼容协议对外提供 API                                                                                              |
| 编排侧调用          | `dehaze-python` 经统一模型路由解析 ASR/TTS 模型（`sys_ai_model`），由 `OpenAiAudioAdapter` 调用（HTTP `/v1/audio/transcriptions`、`/v1/audio/speech` + WS `/v1/asr/stream`，`Authorization: Bearer ${INTERNAL_SERVICE_KEY}`）；业务后端不再安装 funasr / piper-tts |
| 就绪判定            | 用例执行前 `GET /ready` 返回 200（依赖可加载即就绪，模型懒加载不阻塞）；服务不可用/未产出结果场景由停止服务或单元测试桩模拟                                                                                                                                        |
| 音频文件            | 预制测试用 WAV 文件（16kHz, 16bit, mono）                                                                                                                                                                                                                          |

### 3.3 数据清理策略

- TTS 缓存清理：测试前清空用户 `test_voice_user` 的 TTS 缓存
- ASR 会话超时后自动清理（无需手动清理）

### 3.4 测试范围

- F-VS-001 语音识别（流式实时、离线高精、热词、标点、噪声鲁棒、静音边界）
- F-VS-002 语音合成（音色切换、语速控制、缓存命中、降级、语音回复开关）
- F-VS-003 多轮语音交互（会话超时 60 秒、语音与文本混合输入、上下文连续性）
- F-VS-004 热词管理（用户级/全局热词 CRUD、生效范围隔离、权限校验）
- 服务状态监控（供应商状态、并发会话数、权限校验）
- AI 计费关联（识别按秒计费、合成按字符计费、余额不足拒绝）
- 两跳链路时序与异常处理：超时归属（空闲/最长/收尾在编排侧）、关闭码语义（引擎不可用 4001、未产出结果 4001 + 会话 failed）、热词会话级下发
