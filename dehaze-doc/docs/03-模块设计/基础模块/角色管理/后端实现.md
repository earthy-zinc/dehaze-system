# 角色管理模块 - 后端实现设计

## 1. 文档概述

本文档描述角色管理模块的后端实现方案，聚焦服务层设计、核心业务流程、缓存策略与数据权限实现等架构层面决策。

> **三后端时序**：Java/Go/Python 三端的缓存与事务时序、数据权限拦截等关键行为必须一致。

> **API 接口契约**：详见 [API接口.md](./API接口.md)
> **数据库表结构**：详见 [02-系统架构/03-数据库设计.md](../../../02-系统架构/03-数据库设计.md)

### 2.2 表单数据对象 (RoleForm)

| 字段 | 类型 | 说明 | 校验规则 |

| status | Integer | 状态 | 默认 1（启用），取值 0-禁用/1-启用 |

> **表单回显三端一致性**：`GET /roles/{id}/form` 三端统一返回 `id/name/code/sort/status/dataScope/dataScopeLabel/createTime/updateTime`。

## 3. 服务层设计

### 3.1 服务接口定义

| 方法名 | 参数 | 返回值 | 说明 |
|--------|------|--------|------|
| getRolePage | RolePageQuery | IPage&lt;RolePageVO&gt; | 分页查询角色 |
| listRoleOptions | - | List&lt;OptionVO&gt; | 获取角色下拉选项 |
| saveRole | RoleForm | boolean | 保存角色（新增/更新） |
| getRoleForm | Long roleId | RoleForm | 获取角色表单数据 |
| updateRoleStatus | Long roleId, Integer status | boolean | 更新角色状态 |
| deleteRoles | String ids | boolean | 删除角色 |
| getRoleMenuIds | Long roleId | List&lt;Long&gt; | 获取角色菜单 ID 集合 |
| assignMenusToRole | Long roleId, List&lt;Long&gt; menuIds | boolean | 分配菜单权限（含菜单/按钮/接口三类，按钮与接口作为菜单树子节点） |
| getEffectiveDataScope | Set&lt;Long&gt; roleIds | Integer | 计算用户多角色的有效数据权限范围（取数值最小者，即范围最大者） |

> **权限分配说明**：菜单权限、按钮权限、接口权限统一通过 `assignMenusToRole` 分配。菜单树中菜单节点（type=menu）对应菜单权限，按钮节点（type=button）对应按钮权限，按钮节点 `perm` 字段存储接口权限标识。保存时按 `menuIds` 批量写入角色-菜单关联表；接口鉴权时依据 `perm` 标识进行校验。

### 3.2 核心业务逻辑

#### 角色新增逻辑

1. **参数校验**：校验必填字段、格式；**dataScope 必填**，缺失返回 `A0400`
2. **唯一性校验**：检查角色名称和编码是否已存在（含已删除记录校验）
3. **保存角色**：插入角色主表

#### 角色更新逻辑

1. **参数校验**：校验必填字段、格式
2. **存在性校验**：检查角色是否存在
3. **唯一性校验**：检查名称是否与其他角色冲突（编码不可修改）
4. **更新角色**：更新角色主表
5. **刷新缓存**：dataScope 或 status 变更时刷新角色权限缓存，并联动认证模块处理在线用户权限传播

#### 角色删除逻辑

1. **参数解析**：解析 ID 列表
2. **前置校验**：检查是否包含内置角色（ROOT/ADMIN，返回 `A0503`）
3. **关联校验**：检查角色是否存在关联用户（返回 `A0502`）
4. **事务删除**（以下操作在同一事务内执行）：
   - 删除角色-菜单关联记录（物理删除 `sys_role_menu` 表）
   - 逻辑删除角色主表记录（`deleted` 写为行 id）
5. **清理缓存**：**事务提交后**（`TransactionSynchronization.afterCommit`）删除对应角色权限缓存，避免回滚后脏缓存

> **逻辑删除说明**：角色主表采用逻辑删除策略，通过 `deleted` 字段标识删除状态（0-正常，1-已删除）。逻辑删除支持数据可恢复、保持关联查询完整性、满足审计合规；所有查询自动过滤已删除数据。

#### 权限分配逻辑

1. **菜单存在性校验**：校验所有待分配的 menuId 在 `sys_menu` 中真实存在，不存在返回 `A0401`
2. **权限提升防护**：操作者（非 ROOT）的权限集合必须覆盖被分配菜单携带的全部权限标识（按钮 perm），否则返回 `A0301`；ROOT 忽略权限判断
3. **删除原有权限**：删除角色原有的菜单关联
4. **插入新权限**：批量插入新的菜单关联（菜单/按钮/接口节点统一处理）
5. **事务提交后**：重新加载角色权限到缓存，并踢出该角色关联活跃用户的全部在线会话（权限传播，见 §4.2）

> 按钮/接口权限复用菜单权限分配链路：按钮节点作为菜单子节点保存，其 `perm` 字段即为接口权限标识，后端依据 `perm` 进行接口鉴权。

### 3.3 事务管理

| 操作类型 | 事务级别 | 缓存处理时机 |
|---------|---------|------|
| 查询操作 | 只读事务 | 不涉及 |
| 新增角色 | 读写事务 | 不涉及缓存 |
| 更新角色 | 读写事务 | 事务提交后刷新缓存（dataScope/status 变更时） |
| 删除角色 | 读写事务 | 事务提交后清理缓存 |
| 权限分配 | 读写事务 | 事务提交后重建权限缓存 |

> **缓存与事务时序**：所有缓存刷新操作统一在事务提交后执行（`TransactionSynchronization.afterCommit`），确保数据库与缓存最终一致，避免事务回滚后缓存仍写入导致的脏读。

## 4. 数据访问层设计

### 4.1 查询优化

分页查询仅返回列表所需字段，菜单权限与关联用户数按需关联加载。

### 4.2 缓存策略

#### 缓存对象

| 缓存对象 | 缓存 Key | 过期时间 | 更新策略 |
|---------|---------|---------|---------|
| 角色权限 | role:perms:{roleCode} | 30 分钟 | 权限变更时删除重建 |
| 角色选项 | role:options | 1 小时 | 角色新增/更新/状态变更/删除/导入成功后删除 |

> **role:options 缓存口径**：缓存全量启用角色（含编码，TTL 1h）；"非 root 隐藏内置角色 ROOT/ADMIN"的可见性过滤在读取时按调用方视角处理（三端一致），避免首个调用者污染缓存。三端均走 CacheService/等价多级缓存删除（禁止裸 Redis 删除绕过 L1）。

#### 在线用户权限传播

角色菜单分配变更后，该角色已登录的在线用户仍持有旧权限快照，需联动认证模块处理：

- **触发点**：`assignMenusToRole`（菜单分配变更）、`update_role_status`（禁用角色时踢出，启用不踢）。角色删除前置校验已确保无活跃用户关联，无需传播
- **方案**：事务提交后反查该角色关联的活跃用户（`sys_user_role` JOIN `sys_user deleted=0`），逐个踢出其全部在线会话（SCAN `session:*` 按 userId 匹配，不依赖多点登录索引），强制重新登录拉取最新权限
- **保护**：超级管理员（`ROLE_ROOT`）会话不可被踢出
- **调用契约**：详见 [认证管理/后端实现.md](../认证管理/后端实现.md)

## 5. 数据权限设计

### 5.1 数据权限范围

数据权限范围取值 0-3 及其语义见 [需求规格.md](./需求规格.md) §3.7.2。

### 5.2 数据权限实现

#### 数据权限 SQL 拦截器

通过 SQL 拦截器在查询业务数据时动态拼接 WHERE 条件：

1. **获取当前用户上下文**：从当前登录用户上下文获取其角色集合及关联的 dataScope，调用 `getEffectiveDataScope` 计算有效数据权限范围
2. **按范围拼接条件**：
   - **全部数据（0）**：不追加条件
   - **部门及子部门（1）**：以当前用户 `deptId` 为基准，通过部门 `treePath` LIKE 查询所有子部门 ID 集合，拼接 `dept_id IN (子部门ID集合)`
   - **仅本部门（2）**：拼接 `dept_id = 当前用户 deptId`
   - **仅本人（3）**：拼接 `create_by = 当前用户 ID`
3. **自定义部门维度**：若角色配置了自定义部门集合，校验当前用户 `deptId` 是否在集合内，并按集合拼接 `dept_id IN (自定义部门集合)` 条件

### 6.2 角色保护

| 策略项 | 说明 |
|--------|------|
| 内置角色不可删除 | `BUILTIN_ROLE_CODES`（ROOT/ADMIN）内编码删除时返回 `A0503` |
| 内置角色不可禁用 | `BUILTIN_ROLE_CODES` 内编码修改状态时返回 `A0503` |
| 导入导出内置角色保护 | 导出不包含内置角色；导入拒绝内置角色编码 |
| 关联用户拦截 | 删除已关联用户的角色时返回 `A0502`，需先解绑或转移用户 |

## 9. 导入导出设计

角色模块的导入导出由通用导入导出框架统一调度，模块侧实现 `RoleExportHandler` 和 `RoleImportHandler`。通用框架负责文件生成/解析、进度回调、结果上传、任务状态管理。

### 9.1 RoleExportHandler

实现 `ExportHandler` 接口，`getModule()` 返回 `"role"`。

| 方法 | 说明 |
|------|------|
| estimateCount | 根据查询条件估算角色数据量 |
| export | 分批查询角色数据，通过 callback 回写进度 |
| getFieldConfigs | 返回导出字段配置：角色名称、角色编码、数据权限范围、状态、创建时间 |

### 9.2 RoleImportHandler

实现 `ImportHandler` 接口，`getModule()` 返回 `"role"`。

| 方法 | 说明 |
|------|------|
| getFieldConfigs | 返回导入字段配置（角色名称、角色编码必填） |
| importBatch | 批量导入角色：校验角色编码唯一性、初始化默认数据权限 |
| getTemplateSampleData | 返回模板示例数据 |
