| getMaximumDataScope | Set&lt;Long&gt; roleIds | Integer | 获取最大数据权限范围 |

### 3.2 核心业务逻辑

#### 角色新增逻辑

1. **参数校验**：校验必填字段、格式
2. **唯一性校验**：检查角色名称和编码是否已存在
3. **保存角色**：插入角色主表

#### 角色更新逻辑

1. **参数校验**：校验必填字段、格式
2. **存在性校验**：检查角色是否存在
3. **唯一性校验**：检查名称和编码是否与其他角色冲突
4. **更新角色**：更新角色主表
5. **刷新缓存**：如编码变更，刷新权限缓存

#### 角色删除逻辑

1. **参数解析**：解析 ID 列表
2. **前置校验**：检查是否包含超级管理员角色
3. **关联校验**：检查角色是否存在关联用户
4. **事务删除**（以下操作在同一事务内执行）：
   - 删除角色-菜单关联记录（物理删除 `sys_role_menu` 表）
   - 逻辑删除角色主表记录（设置 `deleted = 1`）
5. **清理缓存**：清除相关权限缓存

> **逻辑删除说明**：角色主表采用逻辑删除策略，通过 `deleted` 字段标识删除状态（0-正常，1-已删除）。逻辑删除的优势：
> - 数据可恢复，支持误删恢复
> - 保持数据完整性，关联查询可追溯
> - 满足审计合规要求
> - 所有查询自动过滤已删除数据（通过 GORM 作用域实现）

#### 权限分配逻辑

1. **删除原有权限**：删除角色原有的菜单关联
2. **插入新权限**：批量插入新的菜单关联
3. **刷新缓存**：更新 Redis 权限缓存

### 3.3 事务管理

| 操作类型 | 事务级别 | 说明 |
|---------|---------|------|
| 查询操作 | 只读事务 | 优化数据库性能 |
| 新增角色 | 读写事务 | 角色表操作 |
| 更新角色 | 读写事务 | 角色表+缓存更新 |
| 删除角色 | 读写事务 | 角色表+关联表+缓存清理 |
| 权限分配 | 读写事务 | 关联表+缓存更新 |

## 4. 数据访问层设计

### 4.1 查询优化

#### 分页查询

- 分页查询仅返回列表所需字段

#### 关联查询

| 关联数据 | 实现方式 |
|---------|---------|
| 菜单权限 | 关联角色菜单表 |
| 关联用户数 | 聚合统计 |

### 4.2 缓存策略

| 缓存对象 | 缓存 Key | 过期时间 | 更新策略 |
|---------|---------|---------|---------|
| 角色权限 | role:perms:{roleCode} | 30 分钟 | 权限变更时删除重建 |
| 角色选项 | role:options | 1 小时 | 角色变更时删除 |

#### 缓存刷新机制

1. Redis 权限缓存 Key 格式: `role:perms:{roleCode}`
2. 刷新场景
    1. 角色编码变更 → 删除旧 Key，创建新 Key
    2. 菜单权限分配 → 重新加载角色权限到缓存
    3. 角色删除 → 删除对应缓存 Key

1. 获取当前用户角色

## 8. 关键实现要点

### 8.1 核心常量定义

| 常量名 | 值 | 说明 |
|-------|-----|------|
| BUILTIN_ROLE_CODES | {"ROOT", "ADMIN"} | 内置不可删除角色编码集合（ROOT 超级管理员 / ADMIN 管理员） |
| ROLE_PERMS_PREFIX | "role:perms:" | Redis 权限缓存 Key 前缀 |

### 8.2 权限控制实现

- **接口级权限**：使用注解或中间件控制 API 访问权限
- **权限标识格式**：详见 [API接口.md - 权限标识定义](./API接口.md)
- **权限验证逻辑**：通过 AOP 或中间件在请求前验证用户权限

### 8.3 缓存操作规则

**缓存刷新时机**：
1. 角色编码变更：删除旧 Key `role:perms:{oldCode}`，创建新 Key `role:perms:{newCode}`
2. 菜单权限分配：重新加载角色权限到缓存
3. 角色删除：删除对应缓存 Key `role:perms:{roleCode}`

**缓存加载逻辑**：
- 从数据库查询角色的所有菜单权限
- 将权限列表序列化后存入 Redis
- 设置过期时间为 30 分钟

### 8.4 参数化查询要求

**必须使用参数化查询防止 SQL 注入**：
- Java：使用 `PreparedStatement` 或 MyBatis-Plus 参数绑定
- Go：使用 `?` 占位符进行参数绑定
- Python：使用参数化查询或 ORM 框架

**动态字段验证**（如 orderBy、sortBy）：
- 必须使用白名单验证
- 仅允许预定义的字段名和排序方向

### 8.5 实体类设计要点

**必填字段**：
- `id`：主键，自增
- `name`：角色名称
- `code`：角色编码
- `dataScope`：数据权限范围
- `status`：状态（1-启用，0-禁用）
- `sort`：排序
- `createTime`：创建时间（自动填充）
- `updateTime`：更新时间（自动填充）
- `deleted`：逻辑删除标识

> **数据库设计**：详见 `02-系统架构/03-数据库设计.md`

## 9. 导入导出设计

角色模块的导入导出由通用导入导出框架统一调度，模块侧实现 `RoleExportHandler` 和 `RoleImportHandler`。通用框架负责文件生成/解析、进度回调、结果上传、任务状态管理，详见[任务管理/后端实现.md](../任务管理/后端实现.md)。

### 9.1 RoleExportHandler

实现 `ExportHandler` 接口，`getModule()` 返回 `"role"`。

| 方法 | 说明 |
|------|------|
| estimateCount | 根据查询条件估算角色数据量 |
| export | 分批查询角色数据，通过 callback 回写进度 |
| getFieldConfigs | 返回导出字段配置：角色名称、角色编码、数据权限范围、状态、创建时间 |

### 9.2 RoleImportHandler

实现 `ImportHandler` 接口，`getModule()` 返回 `"role"`。

| 方法 | 说明 |
|------|------|
| getFieldConfigs | 返回导入字段配置（角色名称、角色编码必填） |
| importBatch | 批量导入角色：校验角色编码唯一性、初始化默认数据权限 |
| getTemplateSampleData | 返回模板示例数据 |
