# 角色管理模块需求规格

## 1. 模块概述

### 1.1 模块定位

角色管理模块是 AI 图像处理平台权限管理体系的核心组成部分，负责定义和管理系统中的各种角色及其权限。平台支持多任务图像处理（去雾/去雨/去雪/低光增强/超分辨率/去噪/图像修复），覆盖 Web（Vue/React）、Android、Flutter、Taro/UniApp 小程序、Electron 桌面端等多端，落地 VIP 会员商业化体系。角色管理模块为系统提供完整的角色生命周期管理能力，是整个平台 RBAC 权限控制与数据权限控制的基础。

> **三后端契约**：Java/Go/Python 三后端 API 契约完全一致，Java 为权威来源，Go/Python 对齐。

### 1.2 核心价值

| 价值维度 | 具体内容 |
|---------|---------|
| **统一管理** | 提供系统角色的统一管理入口，实现角色全生命周期管理 |
| **权限控制** | 基于 RBAC 模型实现细粒度的权限控制，确保系统安全 |
| **灵活分配** | 支持菜单权限、按钮权限、接口权限与数据权限的灵活配置 |
| **数据安全** | 通过数据权限范围控制用户可访问的数据，保障数据安全 |

### 1.3 业务目标

#### 功能目标

- 实现系统角色的统一管理（CRUD 操作，逻辑删除）
- 提供完善的菜单权限分配体系（含页面权限、按钮权限、接口权限）
- 支持数据权限的细粒度控制（全部数据/部门及子部门/本部门/本人）
- 提供系统预置角色（root/admin/user/vip/guest）
- 保障系统权限控制的安全性和准确性

#### 性能目标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| **列表查询响应** | &lt;500ms | 角色列表分页查询响应时间 |
| **表单提交响应** | &lt;1s | 新增/编辑角色操作响应时间 |
| **角色容量** | ≥1000 | 系统支持的最大角色数量 |
| **权限分配响应** | &lt;1s | 权限分配操作响应时间 |

## 2. 用户角色分析

### 2.1 主要用户角色

| 角色 | 描述 | 主要职责 |
|------|------|---------|
| **超级管理员** | 拥有角色管理模块的所有操作权限 | 角色增删改查、权限分配、状态管理 |
| **系统管理员** | 拥有角色管理操作权限 | 角色增删改查、权限分配 |
| **部门管理员** | 本部门用户管理权限 | 查看角色列表、为本部门用户分配角色 |

### 2.2 权限矩阵

| 功能点 | 超级管理员 | 系统管理员 | 部门管理员 |
|--------|-----------|-----------|-----------|
| 查看角色列表 | ✅ | ✅ | ✅ |
| 新增角色 | ✅ | ✅ | ❌ |
| 编辑角色 | ✅ | ✅ | ❌ |
| 删除角色 | ✅ | ✅ | ❌ |
| 启用/禁用角色 | ✅ | ✅ | ❌ |
| 分配菜单权限 | ✅ | ✅ | ❌ |
| 配置数据权限 | ✅ | ✅ | ❌ |
| 为本部门用户分配角色 | ✅ | ✅ | ✅ |

> **说明**：部门管理员仅可查看角色列表并为本部门用户分配已有角色，不可创建/编辑/删除角色。

### 2.3 预置角色

系统预置角色初始化时创建，不可删除（超级管理员角色），其余预置角色可编辑但不可删除编码：

| 角色 | 编码（code） | 数据权限 | 说明 |
|------|------|---------|------|
| 超级管理员 | `root` | 0 全部数据 | 拥有系统全部权限，不可删除、不可禁用 |
| 系统管理员 | `admin` | 0 全部数据 | 系统管理权限，可管理用户/角色/部门等 |
| 普通用户 | `user` | 3 仅本人 | 注册用户基础角色，可使用图像处理功能 |
| VIP 会员 | `vip` | 3 仅本人 | 按等级细分权限由会员管理模块驱动（VIP1/VIP2/SVIP） |
| 访客 | `guest` | 3 仅本人 | 注册默认分配，仅可见自己的数据 |

> 注册流程默认分配 `guest` 角色，详见 [认证管理/需求规格.md](../认证管理/需求规格.md)。

## 3. 功能需求

### 3.1 角色列表查询 (F-RM-001)

#### 3.1.1 功能描述

提供角色信息的分页展示和关键字筛选能力，支持管理员快速定位目标角色。

#### 3.1.2 查询条件

| 条件类型 | 字段 | 说明 | 匹配方式 |
|---------|------|------|---------|
| **关键字搜索** | 角色名称 | 模糊匹配 | LIKE |

> **默认过滤**：角色列表默认仅展示未删除角色（`deleted = 0`）。

#### 3.1.3 列表展示字段

| 字段 | 显示名称 | 宽度 | 说明 |
|------|---------|------|------|
| id | 编号 | 100px | 角色唯一标识 |
| name | 角色名称 | 150px | 角色显示名称 |
| code | 角色编码 | 150px | 角色唯一编码 |
| dataScopeLabel | 数据权限 | 180px | 数据权限范围标签 |
| status | 状态 | 80px | 启用/禁用标签 |
| sort | 排序 | 100px | 角色排序 |
| createTime | 创建时间 | 180px | 角色创建时间 |
| - | 操作 | 280px | 状态切换/分配权限/编辑/删除 |

#### 3.1.4 分页配置

| 配置项 | 默认值 | 可选值 |
|--------|--------|--------|
| 每页条数 | 10 | 10/20/50/100 |
| 页码显示 | 当前页/总页数 | - |
| 总数显示 | 共 X 条 | - |

### 3.2 角色新增 (F-RM-002)

#### 3.2.1 功能描述

支持创建新角色，包括基本信息设置、数据权限配置。

#### 3.2.2 表单字段

| 字段 | 显示名称 | 类型 | 必填 | 校验规则 |
|------|---------|------|------|---------|
| name | 角色名称 | 输入框 | ✅ | 不能为空，建议唯一 |
| code | 角色编码 | 输入框 | ✅ | 小写字母+下划线，3-32 位，系统唯一，创建后不可修改 |
| dataScope | 数据权限 | 下拉选择器 | ✅ | 不能为空 |
| status | 状态 | 单选框组 | ✅ | 默认启用(1) |
| sort | 排序 | 数字输入框 | ✅ | 必须为数字，默认 1 |

#### 3.2.3 业务规则

1. **角色名称**：不能为空，建议唯一
2. **角色编码唯一性**：系统中角色编码必须唯一，创建时需校验（含已删除记录校验）
3. **角色编码命名规范**：小写字母与下划线组合（如 `sys_admin`、`vip_member`），长度 3-32，创建后不可修改
4. **数据权限**：必须选择数据权限范围
5. **排序值**：用于控制角色在列表中的显示顺序

### 3.3 角色编辑 (F-RM-003)

#### 3.3.1 功能描述

支持修改现有角色的基本信息、数据权限等。

#### 3.3.2 可编辑字段

| 字段 | 是否可编辑 | 说明 |
|------|-----------|------|
| name | ✅ | 可随时修改 |
| code | ❌ | 角色编码创建后不可修改 |
| dataScope | ✅ | 支持数据权限变更 |
| status | ✅ | 支持状态变更 |
| sort | ✅ | 可修改 |

#### 3.3.3 业务规则

1. **角色编码只读**：角色编码一旦创建不可修改
2. **即时生效**：修改保存后立即生效，并刷新角色权限缓存

### 3.4 角色删除 (F-RM-004)

#### 3.4.1 功能描述

支持删除角色，包括单个删除和批量删除。

#### 3.4.2 删除方式

| 方式 | 触发操作 | 说明 |
|------|---------|------|
| **单个删除** | 点击操作列删除按钮 | 删除单个角色 |
| **批量删除** | 勾选多个后点击批量删除 | 删除选中的所有角色 |

#### 3.4.3 业务规则

1. **二次确认**：删除操作需弹窗确认
2. **关联检查**：检查角色是否有关联的用户，如存在则提示无法删除，需先解绑或转移用户角色
3. **超级管理员保护**：超级管理员角色（`root`）不可删除，返回 `A0233` 错误
4. **逻辑删除**：执行逻辑删除（标记 `deleted = 1`），数据保留可追溯

#### 3.4.4 确认提示

- 单个删除："确认删除角色「{name}」吗？"
- 批量删除："确认删除选中的 {count} 个角色吗？"
- 存在关联用户："该角色下已关联用户，无法删除，请先解绑或转移用户角色。"

### 3.5 状态管理 (F-RM-005)

#### 3.5.1 功能描述

支持启用或禁用角色，控制用户是否可以使用该角色对应的权限。

#### 3.5.2 状态说明

> **状态枚举**：详见 [API接口.md - 状态枚举](./API接口.md)

#### 3.5.3 业务规则

1. **状态切换**：可通过状态标签快速切换
2. **即时生效**：状态变更后立即生效，并刷新权限缓存
3. **超级管理员保护**：超级管理员角色（`root`）不可禁用

### 3.6 菜单权限分配 (F-RM-006)

#### 3.6.1 功能描述

支持为角色分配菜单权限，权限分配含三类：菜单权限、按钮权限、接口权限。

#### 3.6.2 权限分类

| 权限类型 | 说明 | 控制维度 |
|---------|------|---------|
| **菜单权限** | 页面可见性，控制前端路由与菜单渲染 | 页面级 |
| **按钮权限** | 操作可见性，控制页面内按钮/操作元素显示 | 元素级 |
| **接口权限** | API 标识 `sys:module:action`（如 `sys:user:add`），后端鉴权 | 接口级 |

> 菜单树中菜单节点（type=menu）对应菜单权限，按钮节点（type=button）对应按钮权限，按钮节点携带 `perm` 字段作为接口权限标识，后端依据该标识进行接口鉴权。

#### 3.6.3 操作流程

点击分配权限 → 打开权限分配弹窗 → 加载菜单权限树 → 回显已分配权限 → 勾选权限 → 保存 → 提示成功

#### 3.6.4 业务规则

1. **树形结构**：菜单权限以树形结构展示，支持展开/收起
2. **全选支持**：支持父节点选择时自动勾选所有子节点
3. **即时保存**：点击确定后立即保存权限分配，并刷新权限缓存
4. **权限覆盖**：每次分配时覆盖原有权限

### 3.7 数据权限配置 (F-RM-007)

#### 3.7.1 功能描述

支持配置角色的数据访问范围，实现数据级别的权限控制。

#### 3.7.2 数据权限选项

| 权限值 | 名称 | 说明 |
|-------|------|------|
| 0 | 全部数据 | 可访问系统所有数据 |
| 1 | 本部门及子部门 | 可访问本部门及下级部门数据 |
| 2 | 仅本部门 | 仅可访问本部门数据（默认） |
| 3 | 仅本人 | 仅可访问自己的数据 |

#### 3.7.3 业务规则

1. **默认值**：新建角色默认为"仅本部门"（2）
2. **取最大范围**：用户拥有多个角色时，取最大权限范围。范围大小排序：0 > 1 > 2 > 3（数值越小优先级越高），多角色取数值最小者（即范围最大者）
3. **生效机制**：在查询业务数据时根据数据权限范围自动过滤

## 5. 安全设计

### 5.1 权限控制

| 规则 | 说明 |
|------|------|
| **创建/删除/编辑角色** | 仅超级管理员/系统管理员可操作，需 `sys:role:add`/`sys:role:edit`/`sys:role:delete` 权限 |
| **部门管理员权限边界** | 部门管理员仅可查看角色列表并为本部门用户分配已有角色，不可创建/编辑/删除角色 |
| **超级管理员保护** | 超级管理员角色（`root`）不可删除、不可禁用，返回 `A0233` |
| **接口鉴权** | 所有角色管理接口后端依据接口权限标识（`sys:role:*`）鉴权 |

### 5.2 数据安全

| 安全措施 | 说明 |
|---------|------|
| **权限验证** | 基于 RBAC 模型实现细粒度权限控制 |
| **数据权限** | 通过数据权限范围控制用户可访问的数据 |
| **传输加密** | HTTPS 加密传输 |
| **防重复提交** | 使用 Token 机制防止重复提交 |
| **操作日志** | 记录关键操作日志 |

### 5.3 输入校验

| 校验类型 | 说明 |
|---------|------|
| **前端校验** | 表单实时校验，提升用户体验 |
| **后端校验** | 进行参数校验 |
| **唯一性校验** | 角色编码唯一性校验（含已删除记录） |
| **长度校验** | 字段最大长度限制 |

## 6. 多端需求

| 端 | 角色管理入口 | 说明 |
|----|-------------|------|
| **Web Vue/React** | 后台管理页面 | 完整角色管理功能 |
| **Electron 桌面端** | 后台管理页面 | 复用 Web 端管理能力 |
| **Android/Flutter/小程序** | - | 不开放后台角色管理入口，仅受角色权限约束 |

**权限申请**：各端登录后获取的角色与权限信息一致，前端按端能力渲染菜单与按钮；角色变更后用户权限立即生效（刷新权限缓存）。
