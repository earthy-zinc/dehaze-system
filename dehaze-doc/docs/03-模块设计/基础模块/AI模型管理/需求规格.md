# AI 模型管理模块需求规格

> 模块定位：平台 AI 模型与供应商的统一管理底座（功能域 F-M08-007），管理平台全部 AI 模型——**对话（chat）**、**文本向量化（embedding）**、**重排序（rerank）**——与模型供应商：供应商管理支撑多供应商、多 API Key 的灵活调度；模型注册表让消费方按需选择模型并享受差异化的积分计费。
>
> **消费方**：AI 对话（会话内模型选择与推理调度）、AI 知识库（embedding 向量化与 rerank 重排序）。

## 2.7 模型供应商管理 (F-M08-007)

### 2.7.1 功能描述

平台接入多个模型供应商（对话：OpenAI、Anthropic、DeepSeek、智谱、通义千问等；向量化/重排序：OpenAI Embedding、ModelScope bge、本地引擎等）。同一供应商可同时提供对话与向量化模型，配置一个供应商即覆盖其全部模型类型；同一供应商可配置多个 API Key 实现负载均衡与 Key 轮换，同一模型可切换不同供应商实现灵活调度。供应商配置由管理员在管理端维护。

供应商管理遵循两项产品原则：

- **配置即接入**：接入新供应商、新模型均为配置操作，不改代码、不重启服务。
- **不可控性治理**：供应商是外部不可控依赖（限流、宕机、涨价、停服），通过多 Key 轮换、供应商熔断、模型降级链将不可控抽象为可控配置层，保证平台持续可用。

### 2.7.2 供应商管理

| 操作 | 说明 | 业务规则 |
|------|------|---------|
| 新增供应商 | 配置供应商编码、名称、API 地址、协议类型、认证方式 | 供应商编码全局唯一且不可复用；保存后自动发起连通性测试，测试结果仅提示、不阻断保存 |
| 连通性测试 | 向 API 地址发送最小探测请求，验证供应商可访问、凭据有效 | 测试不产生业务计费；结果展示连通状态、延迟与错误信息，便于管理员定位配置问题 |
| 供应商列表 | 查询所有供应商 | 管理员可见全部及健康状态；普通用户查询模型时仅返回关联供应商基本信息，不含密钥与配置细节 |
| 更新供应商 | 修改 API 地址、认证方式、默认请求头等 | 更新后对后续调用立即生效；修改 API 地址或认证方式后建议重新连通性测试 |
| 删除供应商 | 逻辑删除 | 校验是否有启用模型引用该供应商；有则提示先禁用模型 |
| 启停供应商 | 启用/禁用供应商 | 禁用后该供应商下的模型不可被选择，进行中的推理不受影响 |
| 健康状态 | 展示供应商近 24h 成功率、限流率、P95 延迟与当前熔断状态 | 数据由调用日志聚合，状态分为健康/可疑/熔断，供管理员决策轮换与扩容 |

### 2.7.3 API Key 管理

每个供应商可配置多个 API Key，实现负载均衡、Key 轮换、故障切换：

| 操作 | 说明 | 业务规则 |
|------|------|---------|
| 新增 API Key | 录入 Key，系统安全存储 | 密钥不可明文存储、不可回显、不进入日志与模型上下文；重复录入需提示 |
| Key 列表 | 按供应商查询 Key 列表 | 只展示前缀；展示 Key 健康度（近期失败率、最近使用时间）便于轮换决策 |
| 启停 Key | 启用/禁用单个 Key | 禁用后不再被选取，进行中的推理不受影响 |
| 删除 Key | 物理删除 | 删除前校验是否为该供应商唯一启用 Key，避免全部不可用 |
| 设置优先级 | 配置 Key 的优先级和权重 | 优先级数字越小越优先；同优先级按权重加权随机选取 |
| 调用限额 | 配置 Key 级分钟调用频率与日调用额度 | 分钟频率控制突发并发，日额度控制单日成本；超限后本轮跳过该 Key，分钟级自动恢复 / 日额度次日恢复 |

**Key 选取与容错**：

| 规则 | 说明 |
|------|------|
| 选取规则 | 优先选取最高优先级组内的 Key，同优先级按权重加权随机；仅选取启用、在有效期内且未超调用限额的 Key |
| 故障切换 | 调用失败（鉴权失败、限流等）时自动切换同供应商下一个 Key 重试；失败的 Key 进入冷却期，冷却期内不参与选取 |
| 冷却恢复 | 冷却期结束后自动参与选取；连续高频失败的 Key 逐步延长冷却时长，防止被持续打爆 |
| 使用记录 | 记录 Key 最近使用时间与调用方，便于排查与轮换决策 |

### 2.7.4 模型与供应商的关系

| 关系 | 说明 |
|------|------|
| 一个供应商提供多个模型 | 如 OpenAI 供应商下有 GPT-4o、GPT-4o-mini、o1 等多个模型 |
| 同一模型标识可关联不同供应商 | 如 `gpt-4o` 可通过 OpenAI 官方或第三方代理接入，通过供应商区分 |
| 模型切换供应商 | 管理员可将模型从供应商 A 切换到供应商 B，切换为配置操作，对调用方透明（用户仍按模型标识选择） |

### 2.7.5 供应商配置项

| 配置项 | 说明 |
|--------|------|
| 供应商编码 | 全局唯一标识，删除后不可复用 |
| API 基础地址 | 供应商 API 端点 |
| 协议类型 | 请求/响应协议（OpenAI 兼容协议、Claude 原生协议等） |
| 认证方式 | 供应商要求的鉴权方式 |
| 默认请求头 | 供应商特有请求头 |
| 排序序号 | 供应商展示顺序，数字越小越靠前 |
| 健康检查配置 | 连通性探测开关、探测间隔、熔断阈值，阈值可调 |
| 用户身份透传 | 是否向供应商透传脱敏用户标识及透传规则（见 §2.7.8） |
| 备注 | 运维备注（账号归属、合同号、商务信息） |

### 2.7.6 供应商健康与容错

**设计目标**：供应商降级、熔断对用户无感——用户按模型标识发起调用，平台自动路由到当前健康可用的 Key 与供应商，仅在全部可用路径均失败时才报错。

供应商健康分三态，指标由调用日志聚合，阈值可配置：

| 状态 | 判定 | 调度行为 |
|------|------|---------|
| 健康 | 错误率、延迟均在阈值内 | 正常参与选取 |
| 可疑 | 错误率升高或延迟明显恶化 | 降低选取权重，仍参与调用；触发运维告警 |
| 熔断 | 错误率或连续失败超过熔断阈值 | 停止选取该供应商全部 Key，该供应商下的模型自动走降级链或同模型备用供应商；进行中的推理不受影响 |

熔断在冷却期结束或管理员手动解除后恢复，恢复初期按"可疑"低权重观察再回归常态。Key 级失败冷却（§2.7.3）解决单 Key 故障，供应商级熔断解决供应商整体不可用，两级叠加形成完整容错；熔断期间模型调用自动降级（§2.8.3），前端可提示"已切换到备用模型"。健康指标对运维呈现健康看板（§2.8.6），不向普通用户暴露。

### 2.7.7 供应商计费规则差异

不同供应商的计费规则存在结构性差异，平台以"供应商价格模型"抽象统一管理，供应商价格体系（成本侧）与用户侧积分定价解耦：

| 差异维度 | 说明 | 示例（DeepSeek V4） |
|---------|------|---------------------|
| 时段定价 | 高峰/空闲时段不同单价 | 输入未命中 3.0（高峰）/ 1.5（空闲）元/百万 token |
| 缓存定价 | 缓存命中/未命中不同单价 | 输入命中 0.10 vs 未命中 3.0 元/百万 token |
| 输入输出定价 | 输入/输出不同单价 | 输入 1.5 vs 输出 4.5 元/百万 token |
| 图片换算 | 图片按尺寸换算 Token 计费 | 单图缩放后计入上限 384 token |
| 并发限制 | 模型级并发上限不同 | v4-pro 500 / v4-flash 2500 |
| 用户隔离 | 支持透传用户标识实现内容安全/缓存/调度隔离 | 每用户标识并发限制，超限触发限流 |

**处理原则**：

- **成本侧完整建模**：供应商价格体系（时段/缓存/输入输出档位、图片换算、价格版本化）在 [AI 计费管理模块](../AI计费管理/需求规格.md) §2.10 完整建模，按调用发生时刻核算真实成本。
- **用户侧档位定价**：面向用户的积分售价为绝对单价（积分/百万 token），以"价格版本 + 档位明细"表达，档位支持 时段（高峰/空闲）× 上下文长度分段 × 输入/输出/缓存 多维组合，价格版本化，高峰时段规则全局可配（见 §2.8.3）。
- **限速与隔离**：供应商模型级并发限制、Key 级调用频率、用户标识隔离统一建模（见 §2.7.9），平台侧限流先行避免触发供应商限流。

### 2.7.8 用户身份透传

部分供应商支持调用方透传用户标识，实现账号维度下的内容安全隔离、缓存隔离与调度隔离。平台以**用户身份透传配置**统一抽象，按供应商能力差异配置：是否启用、注入字段名（按各供应商要求，支持嵌套路径）、透传值最大长度。

透传值由脱敏前缀 + 平台用户标识哈希截断生成，**不透传任何用户隐私信息**（合规要求）。供应商对透传标识的并发限制作为平台 Key 级调用频率（§2.7.3）与模型并发配置的参考值。

### 2.7.9 限速与隔离

供应商对平台调用有并发/频率限制，且支持用户标识级隔离。平台以**三层限速 + 用户隔离**建模，将外部限制抽象为可控配置：

| 层级 | 说明 |
|------|------|
| 供应商级 | 供应商账号总限速参考值，防止打爆账号（可选配置） |
| 模型级 | 模型并发上限参考值（如 DeepSeek v4-flash 2500），平台侧限流 |
| Key 级 | 单 Key 分钟频率与日额度，超限轮换其他 Key |

用户隔离见 §2.7.8。平台侧限流先行避免触发供应商限流；仍被限流时按 Key 冷却（§2.7.3）→ 供应商熔断（§2.7.6）→ 模型降级（§2.8.3）逐级容错，对用户无感。

> 各供应商限流口径不一（部分按 TPM、部分按 RPM/并发），配置项按供应商探测后填写，阈值可调。

## 2.8 模型选择 (F-M08-007)

### 2.8.1 功能描述

模型管理遵循"模型注册表"实践：模型标识与具体供应商、计费、能力配置解耦，模型升级、下线、切换供应商仅调整模型配置，不改变消费方的调用方式。模型按**类型（model_type）**统一注册，消费方按类型选择模型：

| 模型类型（model_type） | 说明 | 消费方 |
|----------------------|------|--------|
| `chat` | 对话/推理模型 | AI 对话（会话内选择与切换，不同模型积分消耗不同） |
| `embedding` | 文本向量化模型，需记录**向量维度（dimension）** | AI 知识库（创建知识库时选择，创建后不可修改） |
| `rerank` | 重排序模型，检索后二次排序 | AI 知识库（知识库可选启用） |

- 对话模型的会话级选择/切换与积分换算由消费方 AI 对话承载；模型列表、生命周期、下线迁移、供应商调度由本模块统一管理
- embedding 模型的 `dimension` 在模型配置中声明，知识库建立向量索引时读取；维度创建后不可修改，变更需重建索引
- embedding/rerank 模型的知识库侧消费规则见 [AI知识库/需求规格](../AI知识库/需求规格.md)

### 2.8.2 模型展示

| 展示信息 | 说明 |
|---------|------|
| 模型名称 | 显示名称（如"GPT-4o"、"Claude 3.5 Sonnet"） |
| 能力标识 | 标识模型能力（多模态、工具调用、流式输出、结构化输出、Prompt Cache），支持按能力筛选 |
| 积分单价 | 输入/输出积分单价（用户侧售价），帮助用户了解成本；供应商成本价对用户不可见 |
| 速度档位 | 相对速度标识（快/中/慢），由实测延迟聚合得出，帮助用户权衡速度与质量 |
| 上下文长度 | 最大上下文 / 最大输出 token 数，超出时提示 |
| 推荐场景 | 简要说明模型适用场景（如"通用对话"、"复杂推理"、"代码生成"） |
| 模型标签 | 能力/成本/场景标签，支持筛选 |
| 降级标识 | 若该模型常作为其他模型的降级目标，在列表中标识，减少用户对"模型变化"的困惑 |
| 模型类型 | 标识 chat/embedding/rerank，管理端列表按类型筛选；embedding 模型展示向量维度 |

### 2.8.3 业务规则

| 规则 | 说明 |
|------|------|
| 模型可用性 | 仅启用状态的模型可选择 |
| VIP 限制 | 部分高端模型仅 VIP 用户可用 |
| 多模态校验 | 附带文件输入时，模型必须支持对应模态（图片需视觉能力、文档需文档理解能力） |
| 切换生效 | 会话中切换模型后，下一条消息使用新模型，历史消息保持原模型记录 |
| 默认模型 | 新建会话使用平台默认模型，用户可在设置中配置偏好默认模型 |
| 上下文校验 | 输入超出模型上下文上限时，先由上下文管理压缩后再调用；压缩仍超限则拒绝发送并提示 |
| 模型降级 | 模型不可用（供应商限流/故障/熔断）时按配置的降级链自动切换到备用模型，用户仅感知响应模型变化 |
| 价格版本化 | 用户售价与成本单价均按价格版本记录，历史消息按调用时刻对应版本计费/核算成本，账单对账有据可查 |
| 图片换算 | 多模态图片输入按供应商换算规则折算 Token，换算上限随模型配置；实扣以供应商返回为准（计量由 AI 计费模块完成） |
| 并发限制 | 模型配置供应商侧并发上限参考值，配合 Key 级调用频率与网关限流，避免触发供应商限流 |
| 多维档位计价 | 用户侧积分售价以档位明细表达：token 类型（输入/缓存/输出）× 上下文长度分段 × 时段档位（高峰/空闲）任意组合；简单模型仅需 3 行档位；**高峰时段规则全局可配**（默认北京时间周一至周五 9:00-12:00、14:00-18:00），随产品定价调整 |

### 2.8.4 模型生命周期管理

模型与供应商一样是长期演进的配置资产，需要完整的生命周期管理，对齐业界"模型下线公告 + 替换模型推荐"的迁移实践：

| 阶段 | 操作 | 业务规则 |
|------|------|---------|
| 上架 | 新增模型并启用 | 配置模型标识、能力标识、计费档位、VIP 门槛、降级链；上架前建议连通性验证 |
| 运行 | 正常提供服务 | 会话级选择、降级路由、按档位计费 |
| 停用 | 禁用模型 | 新会话不可选择、现有会话切换时不可再选；进行中的推理不受影响；使用中的会话提示用户重新选择 |
| 下线 | 逻辑删除模型 | 校验无活跃会话使用后删除；模型标识不可复用；下线前通知使用方并提供替换模型推荐 |
| 替换迁移 | 供应商停服前的用户引导 | 管理员将模型标记"即将下线"，系统向使用中的会话/用户推送替换模型推荐，引导平滑迁移 |

**模型状态**：`启用` → `禁用`（可逆）→ `已下线`（不可逆）。供应商侧模型停服时由降级链与同模型备用供应商自动兜底，管理员在窗口期内完成替换迁移。

生命周期对 `chat`/`embedding`/`rerank` 全部类型生效。embedding 模型下线迁移即"标注下线 → 知识库切换新模型 → 重建索引"，由 AI 知识库模块承接执行，本模块提供模型状态与替换模型推荐。

### 2.8.6 用量与成本分析（运营视角）

面向管理员的供应商/模型运营健康与成本归因视图，数据源为调用日志；积分计量与账单统计由 [AI 计费管理模块](../AI计费管理/需求规格.md) 负责。

| 分析维度 | 说明 |
|---------|------|
| 供应商健康看板 | 各供应商成功率、限流率、P95 延迟、熔断次数与持续时间 |
| 模型用量分布 | 按模型/供应商统计 Token 消耗、调用次数、积分开销与估算成本，识别高成本与热销模型 |
| 降级与故障统计 | 各模型降级频率、Key 失败切换次数，识别不稳定供应商/Key，驱动轮换决策 |
| 成本归因 | 每次调用记录供应商、模型、Token 明细、价格版本、是否降级、错误码、延迟，支撑成本核算与实际账单对账 |

### 2.8.7 待确认事项

| 事项 | 说明 |
|------|------|
| 用量与成本分析范围（§2.8.6） | 完整成本归因是否与计费模块统计并轨，待与计费模块共同评估 |

### 2.9 页面设计（管理端）

#### 2.9.1 设计原则

| 原则 | 说明 |
|------|------|
| **接入-资产-治理分层** | 供应商管理页回答"怎么接入、怎么容错"；模型管理页回答"用什么、怎么定价、怎么演进"；用量成本分析回答"花得对不对"。三层场景拆为独立页面承载，不做能力混装 |
| **类型化组织** | chat/embedding/rerank 三类模型配置差异大，模型列表按类型筛选、表单按类型展示专属字段，避免配错类型导致消费方不可用 |
| **容错可处置** | Key 冷却、供应商熔断、模型降级链三层状态在页面可见可处置（冷却标记、熔断解除、降级链配置），管理员能对故障闭环 |

#### 2.9.2 供应商管理页

**定位**：接入与容错。让管理员快速接入新供应商、可视化管理 API Key 与健康状态。

| 区块 | 内容 | 关联功能点 |
|------|------|-----------|
| ① 供应商列表 | 供应商分页列表：编码/名称/协议类型/Key 数/被引用模型数/健康状态 | §2.7.2 |
| ② 供应商配置表单 | 新增/编辑：编码/API 地址/协议/认证方式/默认请求头/健康检查开关/用户身份透传/备注 | §2.7.2、§2.7.5 |
| ③ API Key 管理 | 供应商下 Key 列表（前缀/状态/优先级/权重/日限额/冷却标记）+ 新增/启停/删除 | §2.7.3 |
| ④ 健康看板 | 成功率/限流率/P95 延迟/熔断次数与持续时间 + 手动解除熔断 | §2.7.6 |

**交互细节**：

- **连通性测试不阻断**：保存供应商后异步触发测试，结果仅提示；手动测试展示状态、延迟与错误信息，便于定位地址或凭据问题
- **Key 安全与查重**：明文不可见（仅前缀）；重复录入即时提示；删除时校验至少保留一个启用 Key
- **多 Key 容错可视化**：Key 冷却状态标记、优先级/权重可配置，并引导轮换流程（新增新 Key → 禁用旧 Key → 删除旧 Key）
- **熔断处置**：熔断状态醒目标识 + 触发条件说明 + 手动解除入口，解除后重新进入探测

#### 2.9.3 模型管理页

**定位**：资产与定价。让管理员上架模型、配置类型专属能力与价格档位、管理生命周期与降级链，并承载用量成本运营视图。

| 区块 | 内容 | 关联功能点 |
|------|------|-----------|
| ① 模型列表 | 按模型类型筛选：模型名称/类型/供应商/状态/积分单价/上下文长度/速度档位/降级标识 | §2.8.2 |
| ② 模型表单 | 类型专属字段：chat（能力标识/上下文/计费档位/VIP 门槛/降级链）、embedding（向量维度，创建后不可修改）、rerank（启用配置）；通用（供应商选择/状态） | §2.8.1、§2.8.3 |
| ③ 价格档位编辑 | 用户售价档位：token 类型 × 上下文分段 × 时段矩阵编辑，调价生成新版本、历史可追溯 | §2.8.3、§2.7.7 |
| ④ 生命周期操作 | 启用/禁用（即"即将下线"并推送替换推荐）/下线（校验无活跃会话）/替换迁移 | §2.8.4 |
| ⑤ 用量与成本分析 | 运营视图：供应商健康看板、模型用量分布、降级与故障统计、成本归因 | §2.8.6 |

**交互细节**：

- **类型化表单**：模型类型决定表单字段集合，embedding 向量维度与模型标识创建后禁止修改并提示原因
- **价格档位矩阵编辑**：按"token 类型 × 上下文分段 × 时段"矩阵填写售价，保存生成新价格版本
- **生命周期引导**：禁用模型醒目标识"即将下线"并推送替换推荐；下线前校验活跃会话并引导用户切换
- **消费方状态可见**：模型状态在列表醒目标识，禁用模型在消费方（对话模型选择、知识库创建向导）不可选

#### 2.9.4 双页联动

两页基于同一注册表：模型页选择供应商，供应商页展示被引用模型数；供应商禁用或熔断时，该供应商下模型在消费方不可选或由降级链兜底。健康看板在供应商页与模型页运营视图均可达，入口分层、不重复实现。

#### 2.9.5 入口规划

| 端 | 入口 | 说明 |
|----|------|------|
| 桌面端 | 系统管理 → AI 模型管理（供应商管理 / 模型管理 两子页） | 完整管理能力 |
| 移动端 | 管理入口 → AI 模型管理（供应商管理 / 模型管理 轻量查看） | 轻量管理，复杂配置建议桌面端 |
