# AI 模型管理模块需求规格

> 模块定位：AI 模型管理模块是平台 AI 模型与供应商的统一管理底座（由原 AI 对话模块 F-M08-007 模型管理功能域独立而来），管理平台全部 AI 模型——**对话（chat）**、**文本向量化（embedding）**、**重排序（rerank）**——与模型供应商：通过供应商管理实现多供应商、多 API Key 的灵活调度，通过模型注册表让消费方按需选择模型并享受差异化的积分计费。涵盖 §2.7 模型供应商管理与 §2.8 模型管理两个子功能。
>
> **消费方**：AI 对话（会话内模型选择与推理调度）、AI 知识库（embedding 向量化与 rerank 重排序）。本模块原为 AI 对话模块的功能域（F-M08-007），因被多模块消费抽离为独立基础模块，功能域标识沿用 F-M08-007。
>
> 本模块涵盖供应商健康与容错（§2.7.6）、模型选择体验增强（§2.8.2）、模型生命周期管理（§2.8.4）、用量与成本分析（§2.8.6）等能力，其中模型分组与智能路由（§2.8.5）为远期演进规划。

## 2.7 模型供应商管理 (F-M08-007)

### 2.7.1 功能描述

平台接入多个模型供应商（对话：OpenAI、Anthropic、DeepSeek、智谱、通义千问等；向量化/重排序：OpenAI Embedding、ModelScope bge、本地引擎等），通过统一的供应商配置管理实现模型调用的灵活调度。供应商不限于对话 LLM，同一供应商可同时提供对话与 embedding 模型（如 OpenAI），配置一个供应商即覆盖其全部模型类型。供应商配置由管理员在前端配置界面管理，存储于数据库，支持同一供应商配置多个 API Key 实现负载均衡和 Key 轮换，支持同一模型切换不同供应商实现灵活调度。

供应商管理遵循两项产品原则：

- **配置即接入**：接入新供应商、新模型均为配置操作（数据库记录 + 协议适配），不改代码、不重启服务。
- **不可控性治理**：LLM 供应商是外部不可控依赖（限流、宕机、涨价、停服），通过多 Key 轮换、供应商熔断、模型降级链将不可控抽象为可控配置层，保证平台持续可用（见 §2.7.6）。

### 2.7.2 供应商管理

| 操作 | 说明 | 业务规则 |
|------|------|---------|
| 新增供应商 | 配置供应商编码、名称、API 地址、协议类型、认证方式 | 供应商编码全局唯一且不可复用；删除前校验是否有模型引用；保存后自动发起连通性测试，测试结果仅提示、不阻断保存 |
| 连通性测试 | 以配置的协议与认证方式向 API 地址发送最小探测请求（如查询模型列表），验证供应商可访问、凭据有效 | 测试不产生业务计费；结果展示连通状态、延迟与错误码，便于管理员定位配置问题 |
| 供应商列表 | 查询所有供应商 | 管理员可见全部及健康状态；普通用户查询模型时返回关联供应商基本信息（不含 Key 与配置细节） |
| 更新供应商 | 修改 API 地址、认证方式、默认请求头等 | 更新后对后续调用立即生效；修改 API 地址或认证方式后建议重新连通性测试 |
| 删除供应商 | 软删除 | 校验是否有启用模型引用该供应商；有则提示先禁用模型 |
| 启停供应商 | 启用/禁用供应商 | 禁用后该供应商下的模型不可被选择，进行中的推理不受影响 |
| 健康状态 | 展示供应商近 24h 成功率、429 限流率、P95 延迟与当前熔断状态 | 数据由调用日志聚合，状态分为健康/可疑/熔断（见 §2.7.6），供管理员决策轮换与扩容 |

### 2.7.3 API Key 管理

每个供应商可配置多个 API Key，实现负载均衡、Key 轮换、故障切换：

| 操作 | 说明 | 业务规则 |
|------|------|---------|
| 新增 API Key | 录入 Key，系统安全存储 | Key 明文不可见、不进入日志、不进入 LLM 上下文；重复录入需提示（按哈希查重） |
| Key 列表 | 按供应商查询 Key 列表 | 只展示前缀，不展示完整 Key；展示 Key 健康度（近期失败率、最近使用时间）便于轮换决策 |
| 启停 Key | 启用/禁用单个 Key | 禁用后不再被选取，进行中的推理不受影响 |
| 删除 Key | 物理删除 | 删除前校验是否为该供应商唯一启用 Key，避免全部不可用 |
| 设置优先级 | 配置 Key 的优先级和权重 | 优先级数字越小越优先；同优先级按权重加权随机选取 |
| Key 轮换 | 新增 Key 后旧 Key 可禁用或删除 | 支持平滑轮换，不影响进行中的推理 |
| 调用限额 | 配置 Key 级分钟调用频率（RPM）与日调用额度 | RPM 控制突发并发，日额度控制单日成本；超限后本轮跳过该 Key，分钟级自动恢复 / 日额度次日恢复 |

**Key 选取与容错**：

| 规则 | 说明 |
|------|------|
| 选取规则 | 优先选取最高优先级组内的 Key，同优先级按权重加权随机；仅选取启用且在有效期内、未超调用限额的 Key |
| 故障切换 | 调用失败（如鉴权失败、限流）时自动切换同供应商下一个 Key 重试，避免单 Key 故障拖垮调用；失败的 Key 进入冷却期（Redis 临时不可用标记，默认 5 分钟） |
| 使用记录 | 记录 Key 最近使用时间与调用方，便于排查与轮换决策 |
| 冷却恢复 | 冷却期结束后 Key 自动参与选取；连续高频失败的 Key 逐步提升冷却时长，防止被持续打爆（与 §2.7.6 供应商熔断形成两级容错） |

### 2.7.4 模型与供应商的关系

| 关系 | 说明 |
|------|------|
| 一个供应商提供多个模型 | 如 OpenAI 供应商下有 GPT-4o、GPT-4o-mini、o1 等多个模型 |
| 同一模型标识可关联不同供应商 | 如 `gpt-4o` 可通过 OpenAI 官方或第三方代理接入，通过供应商区分 |
| 模型切换供应商 | 管理员可将模型从供应商 A 切换到供应商 B，切换为配置操作，对调用方透明（用户仍按模型标识选择） |

### 2.7.5 供应商配置项

| 配置项 | 说明 | 示例 |
|--------|------|------|
| 供应商编码 | 全局唯一标识 | `openai`、`anthropic`、`deepseek` |
| API 基础地址 | LLM API 端点 | `https://api.openai.com/v1` |
| 协议类型 | 请求/响应协议 | OpenAI 兼容协议、Claude 原生协议 |
| 认证方式 | 供应商要求的鉴权方式 | Bearer Token、API Key、自定义请求头 |
| 默认请求头 | 供应商特有请求头 | Claude 协议版本号等 |
| 排序序号 | 供应商展示顺序 | 数字越小越靠前 |
| 健康检查配置 | 连通性探测开关、探测间隔、熔断阈值 | 探测间隔 60s，连续失败 3 次进入熔断 |
| 备注 | 运维备注（账号归属、合同号、商务信息） | — |

### 2.7.6 供应商健康与容错

**设计目标**：供应商降级、熔断对用户无感——用户按模型标识发起调用，平台自动路由到当前健康可用的 Key 与供应商，仅在全部可用路径均失败时才报错。

**健康状态机**：

```
健康（正常参与选取）
  → 错误率升高/延迟恶化 → 可疑（降权观察 + 保留探测流量）
  → 连续失败超过熔断阈值 → 熔断（停止选取该供应商 Key，进入冷却期）
  → 冷却期结束 / 管理员手动解除 → 恢复
```

| 状态 | 触发条件（参考阈值，可配置） | 调度行为 |
|------|---------------------------|---------|
| 健康 | 错误率 < 10% | 正常参与选取 |
| 可疑 | 10% ≤ 错误率 < 30%，或 P95 延迟超基线 2 倍 | 降低选取权重，仍参与调用；触发运维告警 |
| 熔断 | 错误率 ≥ 30% 持续 1 分钟，或连续失败 ≥ 5 次 | 停止选取该供应商全部 Key；该供应商下的模型自动走降级链或同模型备用供应商；进行中的推理不受影响 |
| 恢复 | 冷却期结束（默认 60s）或管理员手动解除 | 重新参与选取，先按"可疑"低权重观察一段时间再恢复常态 |

**与其他机制的关系**：

- Key 级失败冷却（§2.7.3）解决单 Key 故障，供应商级熔断（本节）解决供应商整体不可用，两级叠加形成完整容错。
- 供应商熔断期间模型调用自动降级（§2.8.3），用户仅感知响应模型变化，前端可提示"已切换到备用模型"。
- 健康指标聚合自调用日志（计费记录/消息记录），对运维呈现健康看板（§2.8.6），不向普通用户暴露。

### 2.7.7 供应商计费规则差异

不同供应商的计费规则存在结构性差异（以 DeepSeek V4 为例：高峰/空闲分时定价、缓存命中/未命中分价、图片按尺寸换算 Token、模型级并发限制、支持 user_id 隔离）。平台以"供应商价格模型"抽象统一管理，供应商价格体系（成本侧）与用户侧积分定价解耦，用户侧定价独立决策：

| 差异维度 | 说明 | 示例（DeepSeek V4） |
|---------|------|---------------------|
| 时段定价 | 高峰/空闲时段不同单价 | 输入未命中 3.0（高峰）/ 1.5（空闲）元/百万 token |
| 缓存定价 | 缓存命中/未命中不同单价 | 输入命中 0.10 vs 未命中 3.0 元/百万 token |
| 输入输出定价 | 输入/输出不同单价 | 输入 1.5 vs 输出 4.5 元/百万 token |
| 图片换算 | 图片按尺寸换算 Token 计费 | 单图缩放后计入上限 384 token |
| 并发限制 | 模型级并发上限不同 | v4-pro 500 / v4-flash 2500 |
| 用户隔离 | 支持透传 user_id 实现内容安全/KVCache/调度隔离 | 每 user_id 并发限制，超限返回 429 |

**处理原则**：

- **成本侧完整建模**：供应商价格体系（时段/缓存/输入输出档位、图片换算、价格版本化）在 [AI 计费管理模块](../AI计费管理/需求规格.md) §2.10"模型调用成本管理"完整建模，按调用发生时刻核算真实成本；
- **用户侧档位定价**：面向用户的积分售价为**绝对单价（积分/百万 token）**，以"价格版本 + 档位明细行"表达（`sys_ai_model_price` + `sys_ai_model_price_detail`），档位支持 **时段（高峰/空闲）× 上下文长度分段 × 输入/输出/缓存** 多维组合，价格版本化；**高峰时段规则全局可配**，随产品定价调整不写死（见 §2.8.3）；
- **限速与隔离**：供应商模型级并发限制、Key 级 RPM、user_id 隔离统一建模（见 §2.7.9），平台侧限流先行避免触发供应商 429。

### 2.7.8 用户身份透传（user_id）

部分供应商支持调用方透传用户标识，实现账号维度下的内容安全隔离、KVCache 隔离与调度隔离（如 DeepSeek 每 user_id 独立并发限制、OpenAI `user` 审计字段、Anthropic `metadata.user_id`）。平台以**用户身份透传配置**抽象统一，按供应商能力差异配置：

| 配置项 | 说明 |
|--------|------|
| 透传配置 `user_identity_forward`（JSON） | `{"enabled": true, "field": "user_id", "prefix": "u_", "max_len": 512}`；NULL 表示不启用 |
| `enabled` | 是否向供应商请求透传平台用户标识 |
| `field` | 注入字段名或嵌套路径：OpenAI 兼容 `user`/`user_id`、Anthropic `metadata.user_id`，按供应商能力配置 |
| `prefix` | 透传值脱敏前缀（最终值 = 前缀 + 平台 userId 哈希截断），**不透传任何用户隐私信息**（合规要求） |
| `max_len` | 透传值最大长度（按供应商限制，如 DeepSeek 512 字符） |
| 并发参考 | 供应商对透传标识的并发限制（如 DeepSeek 每 user_id 独立限制）作为平台 Key 级 RPM 配置（§2.7.3）与模型并发配置的参考值 |

### 2.7.9 限速与隔离

供应商对平台调用有并发/频率限制（如 DeepSeek 模型级并发：v4-flash 2500、v4-pro 500），并支持 user_id 级隔离（每 user_id 独立并发限制，超限返回 429）。平台以**三层限速 + 用户隔离**建模，将外部限制抽象为可控配置：

**三层限速**：

| 层级 | 配置载体 | 说明 |
|------|---------|------|
| 供应商级 | 供应商配置（并发/TPM 参考值） | 供应商账号总限速，防止打爆账号（可选配置） |
| 模型级 | `sys_ai_model.concurrency_limit` | 模型并发上限参考值（如 DeepSeek v4-flash 2500），平台侧限流 |
| Key 级 | `sys_ai_provider_key.rpm_limit` / `daily_quota` | 单 Key 分钟频率/日额度，超限轮换其他 Key |

**用户隔离（user_id）**：见 §2.7.8，透传 user_id 实现供应商侧内容安全/KVCache/调度隔离；每 user_id 并发限制超限返回 429 时，走 Key 失败冷却与供应商熔断容错（§2.7.6）。

**429 容错**：平台侧限流先行避免触发供应商限流；仍触发时按 429 处理——Key 冷却（§2.7.3）→ 供应商熔断（§2.7.6）→ 模型降级（§2.8.3），对用户无感。

> 各供应商限流策略不一（部分按 TPM、部分按 RPM/并发），配置项按供应商探测后填写，阈值可调。

## 2.8 模型选择 (F-M08-007)

### 2.8.1 功能描述

模型管理遵循业界"模型注册表"实践：模型标识与具体供应商、计费、能力配置解耦，模型升级、下线、切换供应商仅调整模型配置，不改变消费方的调用方式。模型按**类型（model_type）**统一注册，消费方按类型选择模型：

| 模型类型（model_type） | 说明 | 消费方 |
|----------------------|------|--------|
| `chat` | 对话/推理模型 | AI 对话（会话内选择与切换，不同模型积分消耗不同，按计费档位换算） |
| `embedding` | 文本向量化模型，需记录**向量维度（dimension）**供 ES 索引映射 | AI 知识库（创建知识库时选择，创建后不可修改） |
| `rerank` | 重排序模型（Cross-Encoder），检索后二次排序 | AI 知识库（知识库可选启用） |

- 对话模型的会话级选择/切换与积分换算由消费方 **AI 对话** 承载；模型列表、生命周期、下线迁移、供应商调度由本模块统一管理
- embedding/rerank 模型的知识库消费见 [AI知识库/需求规格](../AI知识库/需求规格.md) §2.1.4 / §2.8.3
- embedding 模型的 `dimension` 在模型配置中声明，知识库创建 ES 索引（dense_vector 维度）时读取；**维度创建后不可修改**，变更需重建索引（见 §2.8.4 下线迁移）

### 2.8.2 模型展示

| 展示信息 | 说明 |
|---------|------|
| 模型名称 | 显示名称（如"GPT-4o"、"Claude 3.5 Sonnet"） |
| 能力标识 | 标识模型能力（多模态、工具调用、流式输出、结构化输出、Prompt Cache），支持按能力筛选 |
| 积分单价 | 输入/输出积分单价（用户侧售价：绝对单价，积分/百万 token，按时段/上下文分段档位），帮助用户了解成本；供应商成本价对用户不可见 |
| 速度档位 | 相对速度标识（快/中/慢），由实测延迟聚合得出，帮助用户权衡速度与质量 |
| 上下文长度 | 最大上下文 / 最大输出 token 数，超出时提示（见 §2.8.3 上下文校验） |
| 推荐场景 | 简要说明模型适用场景（如"通用对话"、"复杂推理"、"代码生成"） |
| 模型标签 | 能力/成本/场景标签，支持筛选（如"多模态"、"低价"、"代码"） |
| 降级标识 | 若该模型常作为其他模型的降级目标，在列表中标识，减少用户对"模型变化"的困惑 |
| 模型类型 | 标识模型类型（chat/embedding/rerank），管理端列表按类型筛选；embedding 模型展示向量维度（dimension） |

### 2.8.3 业务规则

| 规则 | 说明 |
|------|------|
| 模型可用性 | 仅启用状态的模型可选择 |
| VIP 限制 | 部分高端模型仅 VIP 用户可用 |
| 多模态校验 | 附带文件输入时，模型必须支持对应模态（图片需视觉能力、文档需文档理解能力） |
| 切换生效 | 会话中切换模型后，下一条消息使用新模型，历史消息保持原模型记录 |
| 默认模型 | 新建会话使用平台默认模型，用户可在设置中配置偏好默认模型 |
| 上下文校验 | 输入超出模型上下文上限时，先由上下文管理模块压缩后再调用；压缩仍超限则拒绝发送并提示 |
| 价格版本化 | 用户售价（sys_ai_model_price）与成本单价（sys_ai_model_cost）均按价格版本记录，历史消息按调用时刻对应版本计费/核算成本，账单对账有据可查 |
| 图片换算 | 多模态图片输入按供应商换算规则折算 Token（如 DeepSeek 单图上限 384），换算上限随模型配置；预扣估算按"图片数 × 单图上限"计入，实扣以供应商返回为准（计量由 AI 计费模块完成） |
| 并发限制 | 模型配置供应商侧并发上限参考值，配合 Key 级 RPM（§2.7.3）与 API 网关层限流，避免触发供应商 429 |
| 多维档位计价 | 用户侧积分售价（绝对单价，积分/百万 token）以档位明细行表达：token 类型（input/cached/output）× 上下文长度分段（min~max tokens）× 时段档位（peak/idle）任意组合；简单模型仅 3 行档位（不分段、双时段同价）；**高峰时段规则全局可配**（默认北京时间周一至周五 9:00-12:00、14:00-18:00），随产品定价调整，不写死 |

### 2.8.4 模型生命周期管理

模型与供应商一样是长期演进的配置资产，需要完整的生命周期管理，对齐百炼等平台"模型下线公告 + 替换模型推荐"的迁移实践：

| 阶段 | 操作 | 业务规则 |
|------|------|---------|
| 上架 | 新增模型并启用 | 配置模型标识、能力标识、计费比例、VIP 门槛、降级链；上架前建议连通性验证（确认模型在供应商侧真实存在且可调用） |
| 运行 | 正常提供服务 | 会话级选择、降级路由、按计费比例计费 |
| 停用 | 禁用模型 | 新会话不可选择、现有会话切换时不可再选；进行中的推理不受影响；使用中的会话提示用户重新选择 |
| 下线 | 软删除模型 | 校验无活跃会话使用后删除；model_id 不可复用；下线前通知使用方并提供替换模型推荐 |
| 替换迁移 | 供应商停服前的用户引导 | 供应商发布模型停服公告后：管理员将模型标记"即将下线"，系统向使用中的会话/用户推送替换模型推荐（如 `gpt-4o` → `gpt-4o-mini`），引导平滑迁移 |

**模型状态**：`启用` → `禁用`（可逆）→ `已下线`（不可逆，软删除）。供应商侧模型停服时由降级链与同模型备用供应商自动兜底（§2.8.3），管理员在窗口期内完成替换迁移。

**多类型适用**：生命周期对 `chat`/`embedding`/`rerank` 全部模型类型生效。embedding 模型下线迁移即"标注下线 → 知识库切换新 embedding 模型 → 重建索引（向量维度随新模型变化）"，由 AI 知识库模块承接执行（见 [AI知识库/需求规格](../AI知识库/需求规格.md) §2.3.4），本模块提供模型状态与替换模型推荐。

### 2.8.6 用量与成本分析（运营视角）

> 与 [AI 计费管理模块](../AI计费管理/需求规格.md) 协同：计费模块负责积分计量与账单统计，本小节聚焦供应商/模型的运营健康与成本归因，数据同源（调用日志），面向管理员。

| 分析维度 | 说明 |
|---------|------|
| 供应商健康看板 | 各供应商成功率、429 率、P95 延迟、熔断次数与持续时间 |
| 模型用量分布 | 按模型/供应商统计 Token 消耗、调用次数、积分开销（收入侧）与估算成本（成本侧，见 AI 计费管理 §2.10），识别高成本与热销模型 |
| 降级与故障统计 | 各模型降级频率、Key 失败切换次数（识别不稳定供应商/Key，驱动轮换决策） |
| 成本归因 | 每次调用记录 request_id、供应商、模型、Token 明细、售价价格版本、成本单价版本、是否降级、错误码、延迟，支撑成本核算（sys_ai_billing.cost）与实际账单对账 |

### 2.9 页面设计（管理端）

#### 2.9.1 设计原则

| 原则 | 说明 |
|------|------|
| **接入-资产-治理分层** | 供应商管理页回答"怎么接入、怎么容错"；模型管理页回答"用什么、怎么定价、怎么演进"；用量成本分析回答"花得对不对"。三层操作场景独立，拆为独立页面承载，不做能力混装 |
| **一页一角色** | 供应商管理页承载接入与容错（运维向），模型管理页承载资产与定价（配置向）；消费方不操作管理页，仅消费其配置结果（对话按 chat 选择、知识库按 embedding/rerank 取模型） |
| **类型化组织** | chat/embedding/rerank 三类模型配置差异大，模型列表按 `model_type` 筛选、表单按类型展示专属字段（embedding 向量维度、chat 能力标识与计费档位），避免配错类型导致消费方不可用 |
| **配置即接入可视化** | 接入新供应商/模型均为配置操作，页面提供连通性测试（仅提示不阻断）、唯一性校验（编码/Key 哈希查重）、不可变项提示（embedding 维度、model_id），把"外部不可控"治理显性化 |
| **容错可处置** | Key 冷却、供应商熔断、模型降级链三层状态在页面可见可处置（冷却标记、熔断解除、fallback 配置），管理员能对故障闭环 |

#### 2.9.2 供应商管理页

**定位**：接入与容错。让管理员"快速接入新供应商、可视化管理 API Key 与健康状态"。

**入口**：桌面端系统管理 → AI 模型管理 → 供应商管理；移动端管理入口 → 供应商管理（轻量查看）。

**页面结构**：

| 区块 | 内容 | 关联功能点 |
|------|------|-----------|
| ① 供应商列表 | 供应商分页列表：编码/名称/协议类型/Key 数/被引用模型数/健康状态（健康/可疑/熔断） | §2.7.2 |
| ② 供应商配置表单 | 新增/编辑：编码（唯一不可复用）/API 地址/协议/认证方式/默认请求头/健康检查开关/用户身份透传/备注；保存后异步连通性测试仅提示 | §2.7.2/§2.7.5 |
| ③ API Key 管理 | 供应商下 Key 列表（前缀/状态/优先级/权重/日限额/冷却标记）+ 新增/启停/删除 | §2.7.3 |
| ④ 健康看板 | 供应商健康状态：成功率/429 率/P95 延迟/熔断次数与持续时间 + 手动解除熔断 | §2.7.6 |

**交互细节**：

- **连通性测试不阻断**：保存供应商后异步触发测试，结果仅提示；手动测试展示状态码/延迟/错误信息，便于定位地址或凭据问题
- **Key 安全与查重**：明文不可见（仅前缀）；重复录入按明文哈希查重提示；删除校验至少保留一个启用 Key
- **多 Key 容错可视化**：Key 冷却状态标记、优先级/权重可配置，轮换流程引导（新增新 Key → 禁用旧 Key → 删除旧 Key）
- **熔断处置**：熔断状态红色标识 + 触发条件说明（连续失败阈值）+ 手动解除入口，解除后重新进入探测

#### 2.9.3 模型管理页

**定位**：资产与定价。让管理员"上架模型、配置类型专属能力与价格档位、管理生命周期与降级链"，并承载用量成本运营视图。

**入口**：桌面端系统管理 → AI 模型管理 → 模型管理；移动端管理入口 → 模型管理（轻量）。

**页面结构**：

| 区块 | 内容 | 关联功能点 |
|------|------|-----------|
| ① 模型列表 | 按 `model_type` 筛选（全部/chat/embedding/rerank）：模型名称/类型/供应商/状态/积分单价/上下文长度/速度档位/降级标识 | §2.8.2 |
| ② 模型表单 | 类型专属字段：chat（能力标识/上下文/计费档位/VIP 门槛/降级链）；embedding（`dimension` 向量维度，创建后不可修改）；rerank（启用配置）；通用（供应商选择/状态） | §2.8.1/§2.8.3 |
| ③ 价格档位编辑 | 用户售价档位：token 类型 × 上下文分段 × 时段矩阵编辑，价格版本化（调价生成新版本，历史可追溯） | §2.8.3/§2.7.7 |
| ④ 生命周期操作 | 启用/禁用（即"即将下线"并推送替换推荐）/下线（校验无活跃会话）/替换迁移（推荐 fallback 模型） | §2.8.4 |
| ⑤ 用量与成本分析 | 运营视图 Tab：供应商健康看板、模型用量分布、降级与故障统计、成本归因 | §2.8.6 |

**交互细节**：

- **类型化表单**：`model_type` 决定表单字段集合（切换类型即切换字段），embedding 维度与 `model_id` 创建后禁用并提示不可修改
- **价格档位矩阵编辑**：按"token 类型 × 上下文分段 × 时段"矩阵填写售价，保存生成新价格版本，历史版本可查看与追溯
- **生命周期引导**：禁用模型显著标识"即将下线"并推送替换推荐；下线前校验活跃会话并引导用户切换；替换迁移推荐同能力 fallback 模型
- **消费方状态可见**：模型状态（启用/禁用/已下线）在列表显著标识；禁用模型在消费方（对话模型选择、知识库创建向导）不可选
- **运营视图 Tab**：用量与成本分析以 Tab 承载于模型管理页（含供应商健康看板），数据同源调用日志，聚焦定价与轮换决策

#### 2.9.4 双页联动

- 两份页面基于同一注册表：模型页选择供应商，供应商页展示被引用模型数；供应商禁用 → 该供应商下模型在消费方不可选
- 供应商熔断 → 模型降级链自动兜底（模型页配置的 fallback 生效），健康看板与用量分析数据同源（调用日志）
- 供应商页聚焦接入容错、模型页聚焦资产定价，健康看板在模型管理页运营视图与供应商页均可达，入口分层不重复实现

#### 2.9.5 入口规划

| 端 | 入口 | 说明 |
|----|------|------|
| 桌面端 | 系统管理 → AI 模型管理（供应商管理 / 模型管理 两子页） | 完整管理能力 |
| 移动端 | 管理入口 → AI 模型管理（供应商管理 / 模型管理 轻量查看） | 轻量管理，复杂配置建议桌面端 |
