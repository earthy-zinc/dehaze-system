# AI 模型管理模块测试用例

## 1. 测试目标

覆盖 [需求规格.md](./需求规格.md) §2.7（供应商管理）与 §2.8（模型选择）全部功能点：

- 模型配置管理：CRUD、模型类型与 embedding 向量维度、能力标识、不可变字段与不可复用校验
- 模型用户售价：价格版本 CRUD（新增即生成新版本、历史可追溯）、三维档位明细、Decimal 序列化契约
- 供应商与 API Key 管理：连通性测试、明文查重、优先级/权重选取、限速、失败冷却
- 供应商健康与容错：健康状态机、熔断、同模型备用供应商切换
- 模型生命周期：禁用/下线/替换迁移，覆盖 chat/embedding/rerank 全类型
- 模型路由与降级：主模型不可用降级、降级计费、上下文校验
- Prompt Caching 与结构化输出校验
- 运营统计：健康看板、用量分布、降级与故障统计及权限控制

## 2. 测试前置

| 数据类型 | 准备内容 | 说明 |
|---------|---------|------|
| **测试供应商** | openai（健康）、mock-provider（Mock LLM API，可配置返回 429/5xx/超时） | 供应商健康与熔断验证 |
| **测试模型** | gpt-4o-mini（主，fallback=claude-3-5-haiku）、claude-3-5-haiku（降级）、gpt-4o（无降级）、gpt-4o-mini@mock（同模型备用供应商） | 降级链、备用供应商验证 |
| **Mock LLM API** | 模拟 429/5xx/超时等异常响应；支持模型列表接口供连通性测试 | 降级触发与连通性验证 |

### 2.1 数据清理策略

- 测试模型统一前缀 `test_model_`，测试结束后逻辑删除，`model_id` 不复用
- 测试供应商统一前缀 `test_provider_`，测试结束后逻辑删除，`provider_code` 不复用
- 测试 Key 测试结束后物理删除
