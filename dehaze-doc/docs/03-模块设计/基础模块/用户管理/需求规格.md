# 用户管理模块需求规格

## 1. 模块概述

### 1.1 模块定位

用户管理模块是图像去雾系统后台管理系统的核心基础模块之一，负责管理系统中所有用户账户的全生命周期。该模块为系统提供用户身份识别、权限分配和安全控制等基础功能，是整个系统安全体系的基石。

### 1.2 核心价值

| 价值维度     | 具体内容                                           |
| ------------ | -------------------------------------------------- |
| **统一管理** | 提供系统用户的统一管理入口，实现用户全生命周期管理 |
| **权限控制** | 基于 RBAC 模型实现细粒度的权限控制，确保系统安全   |
| **组织关联** | 支持用户与部门、角色的关联管理，符合企业组织架构   |
| **批量操作** | 支持用户信息的批量导入导出，提高管理效率           |
| **安全保障** | 密码加密存储、权限验证、防重复提交等多重安全机制   |

### 1.3 业务目标

#### 功能目标

- 实现系统用户的统一管理（CRUD 操作）
- 提供完善的用户权限控制体系（RBAC）
- 支持用户与组织架构的关联管理（部门、角色）
- 保障系统安全性和数据完整性

#### 性能目标

| 指标             | 目标值  | 说明                         |
| ---------------- | ------- | ---------------------------- |
| **列表查询响应** | &lt;500ms  | 用户列表分页查询响应时间     |
| **表单提交响应** | &lt;1s     | 新增/编辑用户操作响应时间    |
| **用户容量**     | ≥10000  | 系统支持的最大用户数量       |
| **批量导入**     | ≥100 条 | 单次批量导入支持的最大用户数 |

## 2. 用户角色分析

### 2.1 主要用户角色

| 角色           | 描述                           | 主要职责                                   |
| -------------- | ------------------------------ | ------------------------------------------ |
| **系统管理员** | 拥有用户管理模块的所有操作权限 | 用户增删改查、权限分配、批量操作、密码重置 |
| **部门管理员** | 管理本部门及下级部门的用户     | 查看和管理本部门用户、分配部门内角色       |
| **普通用户**   | 仅能管理自己的账户信息         | 查看和修改个人信息、修改个人密码           |

### 2.2 权限矩阵

| 功能点         | 系统管理员 | 部门管理员  | 普通用户 |
| -------------- | ---------- | ----------- | -------- |
| 查看所有用户   | ✅         | ❌          | ❌       |
| 查看本部门用户 | ✅         | ✅          | ❌       |
| 新增用户       | ✅         | ✅ (本部门) | ❌       |
| 编辑用户       | ✅         | ✅ (本部门) | ❌       |
| 删除用户       | ✅         | ❌          | ❌       |
| 重置密码       | ✅         | ✅ (本部门) | ❌       |
| 启用/禁用用户  | ✅         | ❌          | ❌       |
| 批量导入       | ✅         | ❌          | ❌       |
| 批量导出       | ✅         | ✅ (本部门) | ❌       |
| 修改个人信息   | ✅         | ✅          | ✅       |
| 修改个人密码   | ✅         | ✅          | ✅       |

## 3. 功能需求

### 3.1 用户列表查询 (F-UM-001)

#### 3.1.1 功能描述

提供用户信息的分页展示和多条件筛选能力，支持管理员快速定位目标用户。

#### 3.1.2 查询条件

| 条件类型       | 字段               | 说明              | 匹配方式 |
| -------------- | ------------------ | ----------------- | -------- |
| **关键字搜索** | 用户名/昵称/手机号 | 多字段模糊匹配    | LIKE     |
| **部门筛选**   | 部门 ID            | 包含下级部门      | IN       |
| **状态筛选**   | 用户状态           | 启用/禁用         | =        |
| **时间筛选**   | 创建时间范围       | 开始时间~结束时间 | BETWEEN  |

#### 3.1.3 列表展示字段

| 字段       | 显示名称 | 宽度  | 说明               |
| ---------- | -------- | ----- | ------------------ |
| id         | 编号     | 100px | 用户唯一标识       |
| username   | 用户名   | 120px | 登录账号，唯一     |
| nickname   | 昵称     | 120px | 显示名称           |
| gender     | 性别     | 80px  | 字典值显示         |
| deptName   | 部门     | 120px | 所属部门名称       |
| mobile     | 手机号   | 120px | 联系电话           |
| status     | 状态     | 80px  | 启用/禁用标签      |
| createTime | 创建时间 | 180px | 账户创建时间       |
| -          | 操作     | 220px | 重置密码/编辑/删除 |

#### 3.1.4 分页配置

| 配置项   | 默认值        | 可选值       |
| -------- | ------------- | ------------ |
| 每页条数 | 10            | 10/20/50/100 |
| 页码显示 | 当前页/总页数 | -            |
| 总数显示 | 共 X 条       | -            |

### 3.2 用户新增 (F-UM-002)

#### 3.2.1 功能描述

支持创建新用户账户，包括基本信息设置、部门分配和角色授权。

#### 3.2.2 表单字段与校验规则

| 字段     | 显示名称 | 类型       | 必填 | 校验规则           |
| -------- | -------- | ---------- | ---- | ------------------ |
| username | 用户名   | 输入框     | ✅   | 不能为空，系统唯一 |
| nickname | 用户昵称 | 输入框     | ✅   | 不能为空           |
| deptId   | 所属部门 | 树形选择器 | ✅   | 不能为空           |
| gender   | 性别     | 字典选择器 | ✅   | 不能为空           |
| roleIds  | 角色     | 多选下拉框 | ✅   | 不能为空           |
| mobile   | 手机号   | 输入框     | ❌   | 手机号格式校验     |
| email    | 邮箱     | 输入框     | ❌   | 邮箱格式校验       |
| status   | 状态     | 单选框组   | ✅   | 默认启用(1)        |

#### 3.2.3 业务规则

1. **用户名唯一性**：系统中用户名必须唯一，创建时需校验
2. **初始密码**：新用户创建后使用系统默认密码（如 123456），首次登录建议修改
3. **角色分配**：必须至少分配一个角色

### 3.3 用户编辑 (F-UM-003)

#### 3.3.1 功能描述

支持修改现有用户的基本信息、部门和角色。

#### 3.3.2 可编辑字段

| 字段     | 是否可编辑 | 说明                 |
| -------- | ---------- | -------------------- |
| username | ❌         | 用户名创建后不可修改 |
| nickname | ✅         | 可随时修改           |
| deptId   | ✅         | 支持部门调动         |
| gender   | ✅         | 可修改               |
| roleIds  | ✅         | 支持角色变更         |
| mobile   | ✅         | 可修改               |
| email    | ✅         | 可修改               |
| status   | ✅         | 可启用/禁用          |

#### 3.3.3 业务规则

1. **用户名只读**：用户名一旦创建不可修改
2. **即时生效**：修改保存后立即生效
3. **权限变更**：角色变更后，用户权限立即更新

### 3.4 用户删除 (F-UM-004)

#### 3.4.1 功能描述

支持删除用户账户，包括单个删除和批量删除。

#### 3.4.2 删除方式

| 方式         | 触发操作               | 说明               |
| ------------ | ---------------------- | ------------------ |
| **单个删除** | 点击操作列删除按钮     | 删除单个用户       |
| **批量删除** | 勾选多个后点击批量删除 | 删除选中的所有用户 |

#### 3.4.3 业务规则

1. **二次确认**：删除操作需弹窗确认
2. **关联检查**：检查用户是否有关联的业务数据（待定）
3. **管理员保护**：超级管理员账户不可删除
4. **物理删除**：执行物理删除，数据不可恢复

#### 3.4.4 确认提示

- 单个删除："确认删除用户「{username}」吗？删除后不可恢复。"
- 批量删除："确认删除选中的 {count} 个用户吗？删除后不可恢复。"

### 3.5 密码重置 (F-UM-005)

#### 3.5.1 功能描述

管理员可以为用户重置密码，解决用户忘记密码的问题。

#### 3.5.2 操作流程

点击重置密码 → 弹出密码输入框 → 输入新密码 → 确认重置 → 密码更新成功

#### 3.5.3 业务规则

1. **权限控制**：仅具有 `sys:user:password:reset` 权限的用户可操作
2. **密码加密**：新密码需加密存储
3. **即时生效**：密码重置后立即生效，用户下次登录需使用新密码

### 3.6 状态管理 (F-UM-006)

#### 3.6.1 功能描述

支持启用或禁用用户账户，控制用户的系统访问权限。

#### 3.6.2 状态说明

| 状态值 | 显示             | 说明               |
| ------ | ---------------- | ------------------ |
| 1      | 启用（绿色标签） | 用户可正常登录系统 |
| 0      | 禁用（灰色标签） | 用户无法登录系统   |

#### 3.6.3 业务规则

1. **状态切换**：可通过状态列的开关或编辑表单切换状态
2. **即时生效**：状态变更后立即生效
3. **会话处理**：禁用用户后，其当前会话应失效（可配置）

### 3.7 用户导入 (F-UM-007)

#### 3.7.1 功能描述

支持通过 Excel 模板批量导入用户信息，提高批量用户创建效率。

#### 3.7.2 导入流程

下载导入模板 → 按模板填写用户信息 → 选择目标部门 → 上传 Excel 文件 → 系统校验数据 → 导入成功

#### 3.7.3 模板字段

| 列名     | 必填 | 说明                         |
| -------- | ---- | ---------------------------- |
| 用户名   | ✅   | 登录账号，系统唯一           |
| 昵称     | ✅   | 显示名称                     |
| 手机号   | ❌   | 联系电话                     |
| 邮箱     | ❌   | 电子邮箱                     |
| 性别     | ❌   | 男/女/未知                   |
| 角色编码 | ❌   | 默认角色编码，多个用逗号分隔 |

#### 3.7.4 业务规则

1. **文件格式**：仅支持 `.xls` 和 `.xlsx` 格式
2. **部门指定**：导入时需指定目标部门
3. **重复处理**：用户名重复时跳过该条记录（或覆盖，待确认）
4. **默认密码**：导入用户使用系统默认密码
5. **默认角色**：导入用户使用默认角色（或无角色，待确认）

#### 3.7.5 导入结果

| 结果类型     | 处理方式                                             |
| ------------ | ---------------------------------------------------- |
| **全部成功** | 显示"导入成功，共导入 X 条记录"                      |
| **部分失败** | 显示"导入完成，成功 X 条，失败 Y 条"，并下载失败明细 |
| **全部失败** | 显示"导入失败"，并下载失败明细                       |

### 3.8 用户导出 (F-UM-008)

#### 3.8.1 功能描述

支持将用户列表导出为 Excel 文件，便于数据备份和离线查看。

#### 3.8.2 导出范围

- 根据当前筛选条件导出
- 无筛选条件时导出全部用户

#### 3.8.3 导出字段

| 字段       | 列名     |
| ---------- | -------- |
| username   | 用户名   |
| nickname   | 昵称     |
| deptName   | 部门     |
| mobile     | 手机号   |
| email      | 邮箱     |
| gender     | 性别     |
| createTime | 创建时间 |

## 5. 安全设计

### 5.1 数据安全

| 安全措施       | 说明                               |
| -------------- | ---------------------------------- |
| **密码加密**   | 使用 BCrypt 算法加密存储           |
| **数据权限**   | 用户只能操作其数据权限范围内的用户 |
| **传输加密**   | HTTPS 加密传输                     |
| **防重复提交** | 使用 Token 机制防止重复提交        |
| **操作日志**   | 记录关键操作日志                   |

### 5.2 输入校验

| 校验类型     | 说明                             |
| ------------ | -------------------------------- |
| **前端校验** | 表单实时校验，提升用户体验       |
| **后端校验** | 使用 Validation 注解进行参数校验 |
| **格式校验** | 手机号、邮箱格式正则校验         |
| **长度校验** | 字段最大长度限制                 |

## 6. 依赖关系

### 6.1 依赖模块

| 模块             | 依赖说明                       |
| ---------------- | ------------------------------ |
| **部门管理模块** | 用户需要关联到具体部门         |
| **角色管理模块** | 用户需要分配系统角色           |
| **字典管理模块** | 用户性别等信息需要字典数据支持 |

### 6.2 被依赖模块

| 模块                 | 依赖说明                                   |
| -------------------- | ------------------------------------------ |
| **系统所有业务模块** | 依赖用户管理模块提供用户身份验证和权限控制 |
| **登录认证模块**     | 依赖用户信息进行身份验证                   |
| **操作日志模块**     | 记录用户操作信息                           |

## 7. 待确认事项

1. **用户名修改策略**：用户名是否允许修改？当前实现中用户名设置为只读
2. **关联数据检查**：用户删除时是否需要检查关联的业务数据？
3. **登录日志功能**：是否需要增加用户登录日志查看功能？
4. **导入冲突处理**：用户导入时，对于已存在的用户名应如何处理？是覆盖还是跳过？
5. **登录失败限制**：是否需要增加用户登录失败次数限制和锁定机制？
6. **会话管理**：禁用用户后，是否需要强制退出其当前会话？
7. **默认角色分配**：导入用户时，是否需要分配默认角色？
