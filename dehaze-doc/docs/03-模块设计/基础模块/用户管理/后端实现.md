# 用户管理模块 - 后端实现设计

## 1. 文档概述

本文档描述用户管理模块的后端实现方案，包括业务流程、数据传输对象、服务层设计等架构层面要点。

- **API 接口规范**：参见 [API接口.md](./API接口.md)
- **需求规格**：参见 [需求规格.md](./需求规格.md)
- **数据库设计**：参见 [02-系统架构/03-数据库设计.md](../../../02-系统架构/03-数据库设计.md)

> **三端契约**：Java/Go/Python 三后端实现完全对齐，Java 为权威实现，Go/Python 以 Java 契约为准，禁止任一端引入独立逻辑。

## 3. 服务层设计

### 3.1 服务接口定义

| 方法名 | 参数 | 返回值 | 说明 |
|--------|------|--------|------|
| listPagedUsers | UserPageQuery | IPage&lt;UserPageVO&gt; | 分页查询用户 |
| getUserFormData | Long userId | UserForm | 获取用户表单数据 |
| saveUser | UserForm | boolean | 保存新用户 |
| updateUser | Long userId, UserForm | boolean | 更新用户 |
| deleteUsers | String ids | boolean | 逻辑删除用户 |
| updatePassword | Long userId, String password | boolean | 重置密码 |
| updateStatus | Long userId, Integer status | boolean | 更新状态 |
| getCurrentUserInfo | - | UserInfoVO | 获取当前用户信息 |

### 3.2 核心业务流程

#### 用户新增流程

1. **参数校验**：校验必填字段、格式、用户名唯一性
2. **密码处理**：使用默认密码（`default_password`）加密存储
3. **保存用户**：插入用户主表
4. **角色关联**：批量插入用户-角色关联表

#### 用户更新流程

1. **存在性校验**：校验用户是否存在
2. **更新用户**：更新用户主表（用户名只读，不参与更新）
3. **角色更新**：删除原角色关联，插入新关联
4. **缓存失效**：删除 `user:info:{userId}` 与 `user:perms:{userId}`

#### 用户删除流程（逻辑删除）

1. **参数解析**：解析 ID 列表
2. **超管保护**：校验是否包含超级管理员，命中则返回 `A0230`
3. **逻辑删除**：批量更新用户主表 `deleted = 1`，不物理删除用户记录与用户-角色关联，保留数据可追溯
4. **会话清理**：调用认证模块清理被删除用户的所有在线 Session（按 `session:user:{username}` 索引删除）
5. **缓存失效**：删除 `user:info:{userId}` 与 `user:perms:{userId}`
6. **关联数据过滤**：用户主表作为下游模块的数据源，会员/订单/收藏等模块查询用户数据时统一过滤 `deleted = 1`

#### 状态变更流程

1. **超管保护校验**：
   - 目标用户为超级管理员且操作为禁用 → 返回 `A0231`
   - 操作人为超级管理员且目标为自己且操作为禁用 → 返回 `A0232`（防自锁）
2. **状态更新**：更新用户主表 `status` 字段
3. **会话清理**：禁用操作时，调用认证模块清理目标用户所有在线 Session，被禁用用户下次请求返回 401
4. **缓存失效**：删除 `user:info:{userId}` 与 `user:perms:{userId}`

#### 密码重置流程

1. **存在性校验**：校验用户是否存在
2. **密码强度校验**：8-20 位含字母和数字
3. **密码更新**：新密码加密存储
4. **会话清理**：调用认证模块清理目标用户所有在线 Session，强制重新登录
5. **缓存失效**：删除 `user:info:{userId}` 与 `user:perms:{userId}`

### 3.3 事务管理

| 操作类型 | 事务级别 | 说明 |
|---------|---------|------|
| 查询操作 | 只读事务 | 优化数据库性能 |
| 新增用户 | 读写事务 | 用户表+关联表需事务保证 |
| 更新用户 | 读写事务 | 用户表+关联表需事务保证 |
| 逻辑删除 | 读写事务 | 批量更新用户表 |
| 状态变更 | 读写事务 | 更新用户表 |
| 密码重置 | 读写事务 | 更新用户表 |

## 4. 数据访问层设计

### 4.1 查询设计

#### 分页查询

- 分页查询仅返回列表所需字段
- 默认过滤 `deleted = 0`，已逻辑删除用户不展示
- 会员相关字段（memberLevel/memberExpireTime/quotaUsage）通过会员模块查询聚合，非本模块存储

#### 关联查询

| 关联数据 | 实现方式 |
|---------|---------|
| 部门名称 | 关联部门表 |
| 角色名称 | 聚合查询 |
| 性别显示 | 应用层字典翻译 |
| 会员信息 | 调用会员模块查询 |

#### 部门树查询

- 按层级递归查询子部门（或应用层递归获取子部门列表）
- 缓存部门树结构

#### 跨模块数据过滤

- 用户主表作为统一数据源，下游模块（会员/订单/收藏）查询用户数据时必须过滤 `deleted = 1`，避免展示已删除用户

### 4.2 缓存策略

| 缓存对象 | 缓存 Key | 过期时间 | 失效策略 |
|---------|---------|---------|---------|
| 用户信息 | user:info:{userId} | 30 分钟 | 更新/逻辑删除/状态变更/密码重置时删除 |
| 用户权限 | user:perms:{userId} | 30 分钟 | 角色变更/逻辑删除/状态变更/密码重置时删除 |
| 部门树 | dept:tree | 1 小时 | 部门变更时删除 |
| 角色列表 | role:options | 1 小时 | 角色变更时删除 |
| 用户列表 | - | 不缓存 | 查询条件多变（关键字/部门/状态/会员等级/时间范围组合），缓存命中率低 |

> 状态变更、密码重置、逻辑删除三类操作均会改变用户可用性或凭据，必须同步失效 `user:info` 与 `user:perms`，避免脏缓存导致已禁用/已删除用户仍可访问。

## 5. 模块协作

| 协作模块 | 协作内容 | 调用方向 |
|---------|---------|---------|
| 认证管理模块 | 注册用户落库（认证模块创建用户记录时调用本模块 saveUser）；禁用/删除/密码重置后清理目标用户在线 Session（本模块调用认证模块 Session 清理接口） | 双向 |
| 会员管理模块 | 用户列表/详情中会员等级、到期时间、配额使用情况由会员模块查询聚合，本模块不存储 | 本模块 → 会员模块 |
| 部门管理模块 | 用户关联部门、部门树筛选 | 本模块 → 部门模块 |
| 角色管理模块 | 用户分配角色、角色选项加载 | 本模块 → 角色模块 |
| 字典管理模块 | 性别等字典数据 | 本模块 → 字典模块 |
| 操作日志模块 | 用户关键操作日志记录 | 本模块 → 日志模块 |

## 6. 导入导出设计

用户模块的导入导出由通用导入导出框架统一调度，模块侧只需实现 `UserExportHandler` 和 `UserImportHandler` 两个处理器接口。通用框架负责文件生成/解析、进度回调、结果上传、任务状态管理等通用流程，详见[任务管理/后端实现.md](../任务管理/后端实现.md)。

### 6.1 UserExportHandler

实现 `ExportHandler` 接口，`getModule()` 返回 `"user"`。

| 方法 | 说明 |
|------|------|
| estimateCount | 根据查询条件估算导出数据量（用于同步/异步判断） |
| export | 分批查询用户数据（每批 1000 条），通过 callback 回写进度，数据交由通用框架写入 Excel/CSV |
| getFieldConfigs | 返回导出字段配置（字段名、列名、顺序、字典类型、日期格式） |

**导出字段配置**：username（用户名）、nickname（昵称）、userType（用户类型）、deptName（部门）、mobile（手机号）、email（邮箱）、gender（性别，字典 `gender`）、memberLevel（会员等级）、memberExpireTime（会员到期）、status（状态，字典 `status`）、createTime（创建时间）。

### 6.2 UserImportHandler

实现 `ImportHandler` 接口，`getModule()` 返回 `"user"`。

| 方法 | 说明 |
|------|------|
| getFieldConfigs | 返回导入字段配置（含必填、正则、最大长度、默认值） |
| importBatch | 批量导入用户：三字段判重、密码使用默认密码（`default_password`）加密存储、关联部门与角色 |
| getTemplateSampleData | 返回模板示例数据 |

**导入业务规则**：

| 项目 | 设计 |
|------|------|
| 三字段判重 | 同批次及库内已存在用户按 **用户名 / 邮箱 / 手机号** 三重判重，命中任一即跳过该行并记录冲突原因 |
| 唯一性兜底 | 数据库层对 username/email/mobile 三字段施加唯一性约束，作为并发场景下的最终兜底，约束冲突捕获后转为冲突明细 |
| 批次事务边界 | 每批 N 条（配置项 `import.batch-size`，默认 100）独立事务，批内全部成功才提交，部分失败回滚整批并按行记录错误原因 |
| 默认密码 | 使用配置项 `default_password` 加密存储，首次登录强制改密 |
| 默认角色 | 未指定角色编码时分配访客角色（`guest`） |

| 异常类型 | 处理方式 |
|---------|---------|
| 用户名/邮箱/手机号重复 | 跳过该行，记录行号与冲突字段 |
| 必填字段为空 | 返回 A0706 错误 |
| 字段格式错误 | 返回 A0707 错误 |
| 部门不存在 | 跳过该行，记录原因 |

## 7. 安全设计

### 7.1 密码安全

| 策略项 | 配置值 | 说明 |
|--------|--------|------|
| 密码存储 | 加密存储（自带盐值） | 不可明文存储 |
| 最小长度 | 8 位 | 密码最少字符数 |
| 复杂度 | 中 | 至少包含字母和数字 |

### 7.2 防护机制

| 防护项 | 实现方式 |
|--------|---------|
| 防重复提交 | 自定义注解 + Redis 分布式锁，锁定时间 3 秒 |

### 7.3 数据权限与超管保护

| 策略项 | 说明 |
|--------|------|
| 数据隔离 | 用户列表查询基于角色 dataScope 注入部门过滤条件，部门管理员仅可见本部门及下级部门用户 |
| 超级管理员保护 | 不可删除（返回 `A0230`）、不可禁用（返回 `A0231`）、不可修改自己状态防自锁（返回 `A0232`） |
| 会话联动 | 禁用/删除/密码重置后清理目标用户全部在线 Session，确保权限变更即时生效 |

### 7.4 操作审计

| 操作类型 | 审计内容 |
|---------|---------|
| 新增/修改/删除用户 | 记录操作人、时间、目标用户、变更字段与前后值 |
| 密码重置 | 记录操作人、时间、目标用户（不记录密码明文） |
| 状态变更 | 记录操作人、时间、目标用户、变更前后状态 |

> 详细日志设计参见 §8。

### 7.5 批量操作保护

| 策略项 | 说明 |
|--------|------|
| 批量删除上限 | 单次批量删除用户数量受接口参数约束，防止误操作大批量删除 |
| 超管拦截 | 批量删除 ID 列表中包含超级管理员时整体拒绝，返回 `A0230` |
| 事务原子性 | 批量逻辑删除在单事务内执行，全部成功或全部回滚 |

### 7.6 导入安全

| 策略项 | 说明 |
|--------|------|
| 文件类型校验 | 仅支持 `.xls` 和 `.xlsx` 格式，拒绝其他文件类型 |
| 行数限制 | 单次导入支持的最大用户数 ≥100 条 |
| 三字段判重 | 按 用户名/邮箱/手机号 三重判重，命中任一即跳过并记录冲突原因 |
| 默认密码 | 导入用户使用 `default_password` 加密存储，首次登录强制改密 |
