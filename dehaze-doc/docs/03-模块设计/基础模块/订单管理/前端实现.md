# 订单管理模块 - 前端实现设计

## 1. 文档概述

本文档描述订单管理模块的前端实现方案（dehaze-front-vue），聚焦页面结构、数据流、关键交互决策与权限控制。

---

## 2. 页面结构

### 2.1 页面清单

| 页面 | 路径 | 角色 | 说明 |
|------|------|:----:|------|
| 我的订单 | `views/order/my/index.vue` | 用户 | 订单列表（状态 Tab 筛选）+ 支付弹窗 + 取消 + 申请退款 |
| 订单详情 | `views/order/detail/index.vue` | 用户 | 订单状态/套餐/金额明细展示 |
| 订单管理 | `views/order/list/index.vue` | 管理员 | 订单分页 + 详情弹窗（支付流水）+ 订单统计抽屉 |
| 退款管理 | `views/order/refund/index.vue` | 管理员 | 退款审核列表 + 通过/驳回弹窗 |

> **设计决策**：状态标签/订单卡片/支付弹窗/二维码/退款申请弹窗等能力内聚在页面组件内（支付弹窗为 my 页面内嵌，退款申请为 my 页面弹窗），不做子组件拆分。

### 2.2 我的订单（my/index.vue）

| 区域 | 内容 |
|------|------|
| 状态 Tab | 全部/待支付/已支付/已完成/已取消/退款中/已退款（切换触发查询） |
| 订单卡片 | 订单号 + 创建时间、套餐名称 + 等级标签、到期时间、应付金额（¥，原价删除线）、支付方式、状态标签 |
| 操作按钮 | 待支付：去支付/取消订单；已支付：申请退款/查看详情；其余：查看详情 |
| 支付弹窗 | 订单号、支付方式选择（微信/支付宝/余额/组合支付）、余额直付（直接发起）、组合支付（余额+第三方，输入余额抵扣金额）、微信/支付宝展示二维码/链接、取消支付 |
| 取消确认 | 确认弹窗（输入取消原因） |
| 退款申请 | 退款原因下拉 + 自定义补充说明 + 提交（成功提示"退款申请已提交"） |

**支付交互流程**：

```
点击"去支付" → 支付弹窗（展示订单信息）
    ↓
选择支付方式：
  ├─ 微信/支付宝 → 调用发起支付 → 获取 payUrl/qrCode → 展示二维码/新窗口打开支付链接
  ├─ 平台余额 → 调用发起支付 → 直接返回已支付 → 刷新列表
  └─ 组合支付 → 输入余额抵扣金额 → 调用发起支付 → 第三方部分展示二维码/链接
    ↓
支付完成 → 刷新列表（状态变已支付）→ 提示"支付成功"
```

> 二维码支持轮询查询支付状态与倒计时；支付成功跳转订单详情。

### 2.3 订单详情（detail/index.vue）

| 区域 | 内容 |
|------|------|
| 状态卡片 | 订单状态（色带 + 标签）、订单号、创建时间、取消原因（有则展示） |
| 套餐信息 | 套餐名称 + 等级标签、生效时间/到期时间 |
| 金额明细 | 订单原价、折扣优惠（-¥，有则展示）、优惠券抵扣（-¥，有则展示）、实付金额 |
| 操作 | 待支付：去支付/取消订单；已支付：申请退款 |

### 2.4 订单管理（list/index.vue）

| 区域 | 内容 |
|------|------|
| 筛选区 | 订单号、用户名、支付方式、状态、金额范围、支付时间范围 |
| 操作栏 | 订单统计（`order:stats` 权限控制） |
| 表格 | 订单号/用户/套餐/优惠（折扣+券）/应付/实付/支付方式/状态/创建时间/支付时间/操作（详情） |
| 详情弹窗 | 订单信息 + 支付流水列表（流水号/渠道/金额/状态/回调时间）+ 退款信息（退款单号/金额/已使用天数/原因/状态/审核信息，有则展示）+ 成长值变动（支付增加/退款扣减） |
| 统计抽屉 | 总订单数/总收入/总退款/退款率 + 状态分布/支付方式分布/套餐分布（表格）+ 每日趋势（ECharts 折线/柱状图） |

### 2.5 退款管理（refund/index.vue）

| 区域 | 内容 |
|------|------|
| 筛选区 | 状态（退款中/已退款/退款失败）、订单号、用户名、申请时间范围 |
| 表格 | 退款单号/订单号/用户/退款金额/已使用天数/原因/渠道/状态/申请时间/审核时间/审核人/操作（详情、通过、驳回） |
| 详情弹窗 | 完整退款信息（含错误信息、退款单号、审核信息） |
| 审核弹窗 | 通过/驳回标识 + 审核备注（必填校验）→ 提交调用通过/驳回接口 |

## 3. 数据流

### 3.1 我的订单

```
进入页面 → 分页查询（默认全部）
    ↓
切换状态 Tab → 按状态查询
    ↓
操作：
  - 去支付 → 支付弹窗 → 选择方式 → 发起支付 → 展示二维码/直付 → 刷新
  - 取消订单 → 输入原因 → 确认 → 刷新
  - 申请退款 → 原因弹窗 → 提交 → 刷新
  - 查看详情 → 跳转 detail
```

### 3.2 订单详情

```
进入页面（路由 orderNo）→ 查询详情
    ↓
渲染状态/套餐/金额明细
    ↓
操作按钮按状态展示
```

### 3.3 后台订单管理

```
进入页面 → 分页查询
    ↓
筛选 → 重新查询
    ↓
详情 → 弹窗（订单 + 支付流水 + 退款信息 + 成长值变动）
    ↓
统计 → 抽屉 → 加载统计接口 → 渲染图表
```

### 3.4 后台退款管理

```
进入页面 → 分页查询退款记录
    ↓
筛选 → 重新查询
    ↓
审核 → 弹窗（通过/驳回 + 备注）→ 提交 → 刷新列表
```

### 3.5 模块间数据交互

| 交互方向 | 数据 | 说明 |
|---------|------|------|
| 套餐商城 → 订单管理 | packageId | 从套餐卡片发起创建订单 |
| 订单管理 → 套餐管理 | calculate-price | 下单前价格预览 |
| 订单管理 → 会员管理 | 支付事件 | 支付成功激活会员权益（后端） |

---

## 4. 状态管理

订单模块无独立 Store。支付轮询状态（轮询定时器、支付结果）在支付弹窗组件内管理，弹窗关闭时清除定时器；订单列表分页数据、状态 Tab、筛选条件、弹窗显隐在页面组件内局部管理；订单状态机由后端驱动，前端按状态映射操作按钮与标签配色。

---

## 5. 关键交互决策

| 决策点 | 实现方式 |
|--------|---------|
| 状态 Tab 筛选 | 六种状态 + 全部，切换即查询（pageNum 重置） |
| 支付弹窗方式选择 | 微信/支付宝走渠道返回支付参数，余额直付，组合支付（余额+第三方） |
| 金额展示 | 分转元（`amount.toFixed(2)`），原价删除线（有优惠时） |
| 状态标签配色 | 按订单状态映射标签类型（pending 橙色/paid 蓝色等） |
| 退款原因表单 | 下拉预设原因 + 自定义补充说明（reason 为空时禁止提交） |
| 审核备注必填 | 审核弹窗表单校验备注必填 |
| 统计图表 | ECharts 按抽屉打开时初始化，切换维度重渲染 |

---

## 6. 权限控制

| 操作 | 权限标识 | 无权限时 |
|------|---------|---------|
| 退款审核 | order:refund:approve | 按钮隐藏 |
| 订单统计 | order:stats | 按钮隐藏 |

> 订单列表/详情/退款列表查询无权限标识，登录管理员即可访问（后端接口无权限校验）。

---

## 7. 性能优化

| 优化项 | 实现方式 |
|--------|---------|
| 分页查询 | 后端分页，前端仅当前页渲染 |
| 搜索触发 | 点击搜索/回车触发 |
| 订单详情 | 前端不缓存，每次进入实时查询（保证状态时效性） |
| 统计图表 | 抽屉打开时按需加载，关闭销毁 |
