# 订单管理模块 - 前端实现设计

## 1. 文档概述

本文档描述订单管理模块的前端实现方案，聚焦组件架构、状态管理、支付与退款交互等架构决策。

## 2. 组件架构设计

### 2.1 用户端订单组件结构

```
我的订单页面 (MyOrders/index.vue)
├── 状态标签页 (StatusTabs)
│   └── 全部/待支付/已支付/已完成/已取消/退款中/已退款
├── 订单列表
│   └── 订单卡片 (OrderCard)
│       ├── 套餐信息
│       ├── 金额明细
│       ├── 状态标签
│       └── 动态按钮区域
└── 分页组件

订单详情页面 (OrderDetail/index.vue)
├── 状态卡片 (StatusCard)
├── 套餐信息卡片
├── 金额明细卡片
├── 支付信息卡片
├── 权益信息卡片
└── 底部操作栏
```

### 2.2 支付组件

```
支付弹窗 (PaymentDialog)
├── 支付方式选择 (PayMethodSelector)
│   ├── 微信支付
│   ├── 支付宝
│   └── 平台余额
├── 二维码展示 (QRCode)
└── 支付倒计时
```

### 2.3 退款组件

```
退款申请弹窗 (RefundApplyDialog)
├── 退款规则展示
├── 退款金额计算
├── 退款原因选择
└── 提交按钮
```

### 2.4 后台管理组件结构

```
订单管理页面 (OrderManagement/index.vue)
├── 搜索容器
│   └── 多条件筛选表单
└── 数据展示区域
    ├── 订单表格 (OrderTable)
```

## 3. 组件详细设计

### 3.1 订单卡片组件

#### 组件属性

| 属性 | 类型 | 说明 |
|------|------|------|
| order | Object | 订单数据 |

#### 动态按钮逻辑

| 订单状态 | 按钮文案 | 操作 |
|---------|---------|------|
| pending（待支付） | 去支付 + 取消订单 | 唤起支付弹窗 / 取消 |
| paid（已支付） | 申请退款 | 打开退款弹窗 |
| completed（已完成） | 查看详情 | 跳转详情 |
| cancelled（已取消） | 重新购买 | 跳转套餐列表 |
| refunding（退款中） | 退款详情 | 查看退款进度 |
| refunded（已退款） | 查看详情 | 跳转详情 |

#### 状态标签颜色

| 状态 | 颜色 |
|------|------|
| pending | 橙色（提醒） |
| paid | 蓝色（成功） |
| completed | 绿色（完成） |
| cancelled | 灰色（中性） |
| refunding | 黄色（处理中） |
| refunded | 红色（退款） |

### 3.2 支付弹窗组件

#### 交互流程

1. 选择支付方式
2. 点击"确认支付"
3. 调用 `payOrder` 接口获取支付参数
4. 展示二维码（微信/支付宝）或直接扣款（余额）
5. 倒计时（30分钟）
6. 轮询订单状态（每3秒查询一次）
7. 支付成功 → 跳转成功页

#### 组件属性

| 属性 | 类型 | 说明 |
|------|------|------|
| visible | Boolean | 弹窗可见性 |
| orderNo | String | 订单号 |

#### 状态管理

| 状态 | 说明 |
|------|------|
| step | current: 选择支付方式 / qrcode: 二维码 / success: 成功 |
| payMethod | 当前选择支付方式 |
| payUrl | 支付二维码URL |
| countdown | 倒计时秒数 |
| pollingTimer | 轮询定时器 |

## 5. API 调用设计

### 5.1 API 接口封装

使用 `dehaze-sdk-js` 提供的 OrderAPI：

| 方法 | 功能 | 参数 |
|------|------|------|
| OrderAPI.create | 创建订单 | formData |
| OrderAPI.pay | 发起支付 | orderNo, payMethod |
| OrderAPI.cancel | 取消订单 | orderNo, reason |
| OrderAPI.listMy | 我的订单 | queryParams |
| OrderAPI.getDetail | 订单详情 | orderNo |
| OrderAPI.applyRefund | 申请退款 | orderNo, formData |
| OrderAPI.enableAutoRenew | 开启自动续费 | orderId |
| OrderAPI.disableAutoRenew | 关闭自动续费 | packageId |
| OrderAPI.getPage | 后台分页查询 | queryParams |
| OrderAPI.getStats | 订单统计 | queryParams |
| OrderAPI.listRefunds | 退款列表 | queryParams |
| OrderAPI.approveRefund | 退款审核通过 | refundId, formData |
| OrderAPI.rejectRefund | 退款审核驳回 | refundId, formData |

### 5.2 辅助 API

## 6. 交互流程设计

### 6.1 订单创建与支付流程

1. 用户选择套餐，点击"立即开通"
2. 跳转订单确认页（携带 packageId）
3. 调用 `calculatePrice` 计算应付金额
4. 选择优惠券（可选，实时重新计算）
5. 选择支付方式
6. 点击"立即支付"，调用 `createOrder`
7. 获取订单号，调用 `pay` 发起支付
8. 展示支付弹窗（二维码/余额扣款）
9. 轮询订单状态
10. 支付成功 → 跳转成功页 → 刷新订单列表

### 6.2 退款流程

1. 用户在订单详情点击"申请退款"
2. 弹窗展示退款规则与计算
3. 选择退款原因
4. 提交退款申请
5. 订单状态变更为"退款中"
6. 等待后台审核（推送通知）
7. 审核通过 → 渠道退款 → 状态变"已退款"

### 6.3 关键流程说明

| 流程 | 关键点 |
|------|--------|
| 支付轮询 | 每3秒查询一次，支付成功或超时停止 |
| 倒计时 | 30分钟，超时提示订单已取消 |
| 自动续费开启 | 支付成功后弹窗引导开启 |
| 退款金额计算 | 实时根据已用次数计算 |

## 9. 性能优化设计

### 9.1 请求优化

| 优化项 | 实现方式 |
|--------|---------|
| 防抖处理 | 搜索输入防抖 300ms |
| 节流处理 | 支付轮询间隔 3 秒 |
| 并行请求 | 详情页并行加载订单与流水 |
| 请求取消 | 路由切换时取消未完成请求 |

### 9.2 渲染优化

| 优化项 | 实现方式 |
|--------|---------|
| 订单列表 | 虚拟滚动优化大量订单 |
| 状态标签 | 组件缓存，避免重复渲染 |
| 二维码 | 本地生成，减少请求 |
| 倒计时 | requestAnimationFrame |

### 9.3 缓存策略

| 数据类型 | 缓存位置 | 过期策略 |
|---------|---------|---------|
| 订单详情 | 组件状态 | 路由切换时清除 |
| 支付状态 | Pinia Store | 支付完成后清除 |
| 状态字典 | 全局 Store | 登录后加载 |
