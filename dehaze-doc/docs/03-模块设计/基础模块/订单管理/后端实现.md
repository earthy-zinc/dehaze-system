# 订单管理模块 - 后端实现设计

## 1. 文档概述

本文档描述订单管理模块的后端实现方案，包括业务逻辑、数据传输对象、服务层设计、支付回调幂等、退款与自动续费流程、定时任务与缓存策略。该模块在 dehaze-java、dehaze-python、dehaze-go 三端实现，逻辑基本一致（Go 端无订单并发锁，见 §6）。

- **API 接口规范**：参见 [API接口.md](./API接口.md)
- **需求规格**：参见 [需求规格.md](./需求规格.md)
- **数据库设计**：参见 [02-系统架构/03-数据库设计.md](../../../02-系统架构/03-数据库设计.md) §4.5
- **Schema 文件**：`config/sql/schema/sys_order.sql`、`sys_payment_record.sql`、`sys_refund_record.sql`、`sys_auto_renew.sql`

## 4. 核心业务逻辑

### 4.1 订单创建逻辑（create）

1. **参数校验**：payMethod ∈ {wechat, alipay, balance, combined}（否则"不支持的支付方式"）；套餐存在且在售
2. **防重复下单**：Redisson 锁（key `order:lock:{userId}:{packageId}`，waitTime=0、leaseTime=5s），获取失败抛 DUPLICATE_ORDER
3. **价格计算**：调用套餐服务 `calculatePrice(packageId, couponId)`，取 originalPrice/discountAmount/couponAmount/payableAmount
4. **优惠券锁定**：条件 UPDATE `sys_user_coupon SET status=4 WHERE id=? AND status=1`（0 行影响抛 COUPON_ALREADY_USED）；锁定时仅置 status=4，核销时（支付成功）再写 used_order_id
5. **生成订单**：订单号 `DH + yyyyMMddHHmmss + 6位随机数`；套餐信息冗余（name/level/periodDays）；expire_time = NOW()+30min；status=1；is_auto_renew=0
6. **事务保证**：订单创建与优惠券锁定同一事务
7. **职责分离**：create 不触发渠道下单，支付链接由 pay 获取

### 4.2 发起支付（pay）

1. 越权校验：订单归属本人（非本人抛 ORDER_NOT_FOUND）
2. 状态校验：status==1（否则 ORDER_STATUS_INVALID）；未超时（否则 ORDER_EXPIRED）
3. **balance**：直接调用 completePayment（置已支付 + 权益生效），返回 paid=true
4. **wechat/alipay**：调渠道 `unifiedOrder` → 失败抛 CALL_THIRD_PARTY_SERVICE_ERROR → 创建支付记录（status=1 处理中）→ 返回 payUrl/qrCode
5. **combined**：getPaymentChannel 找不到渠道，抛"不支持的支付渠道"（**组合支付未实现**）

> **说明**：**balance 支付无余额校验与扣减**——不检查用户是否有余额、无余额表操作，直接完成支付。

### 4.3 支付回调处理（handlePaymentCallback）

```
渠道回调 → 渠道 verifyCallback（验签；渠道未启用时 mock 直接信任）
    ↓ 验签失败返回 false
查询订单 → 不存在返回 false
    ↓
金额校验：回调金额>0 且 ≠ 应付金额
    ├─ Java：log.error + 返回 false（不抛异常）
    └─ Python：抛 PAYMENT_AMOUNT_MISMATCH
    ↓
Redisson 锁（payment:lock:{orderNo}，waitTime=0、leaseTime=10s）→ 获取失败幂等返回 true
    ↓
状态判断：status ∈ {2,3} 幂等返回 true；status ≠ 1 返回 false
    ↓
completePayment：
  1. 激活会员权益（activateMemberByPackage）：等级→套餐等级、来源=package、到期时间=原到期时间叠加、
     月度配额=套餐等级权益（Python 含套餐覆盖项）、开通时间、累计消费累加
  2. 订单置 paid、paidTime/effectiveTime/packageExpireTime 写入、paidAmount=payableAmount
  3. 创建支付记录（status=2 成功）
  4. 累加套餐销量
  5. 核销优惠券（status 4→2，used_order_id 写入，模板 used_qty+1）
  6. 删除订单详情缓存
```

> **说明**：权益生效**不记录成长值**（`consume` 类型未接入）、**不推送支付成功通知**（早期设计稿内容未实现）。

### 4.4 取消订单（cancel）

1. 越权校验（非本人抛 ORDER_NOT_FOUND）；状态校验（status==1，否则 ORDER_STATUS_INVALID）
2. 置 status=4、写入 cancel_reason
3. 释放优惠券（status 4→1）
4. 删除订单详情缓存

### 4.5 退款申请（applyRefund）

1. 越权校验（非本人抛 ORDER_NOT_FOUND）
2. 状态校验：Java 允许 paid(2)/completed(3)；Python 仅允许 paid(2)
3. **退款时限校验（仅 Python 端）**：`paid_time < NOW() - 7天` 抛 REFUND_TIME_EXCEEDED（Java 端无此校验）
4. **唯一性校验**：已存在退款记录抛 REFUND_ALREADY_EXISTS（+ `uk_order_id` 唯一约束兜底）
5. **退款金额**：全额（`refund_amount = paid_amount`）；`used_quota` 恒为 0（无比例折算）
6. 原因拼接：customReason 非空时 `reason + ":" + customReason` 写入
7. 插入退款记录（refund_no=`RF+时间戳+随机数`、status=1、channel=订单支付方式）
8. 订单置 status=5（refunding）；删除订单详情缓存

> **说明**：**无"已用次数<50%"校验、无"促销套餐不可退"校验**（错误码已定义未使用）；退款金额计算不支持部分退款。

### 4.6 退款审核

**approveRefund**（通过）：
```
校验退款记录存在、status==1
    ↓
非 balance 订单 → 同步调渠道 refund（total=paid_amount, amount=refund_amount）
    ├─ 成功 → 退款记录 status=2、refund_time；订单 status=6（refunded）
    └─ 失败 → 退款记录 status=3（refund_failed）、error_message；订单恢复 status=2/3（按套餐是否到期）
写入 audit_time/auditor_id/audit_remark；删除订单详情缓存
```

**rejectRefund**（驳回）：
```
校验退款记录存在、status==1
    ↓
退款记录 status=3（refund_failed）+ 审核信息
    ↓
订单恢复 status=2/3（按套餐是否到期）；删除订单详情缓存
```

> **说明**：
> - **退款成功不回收会员权益、不扣减成长值**（早期设计稿"回收权益/扣成长值/释放优惠券不退回"未实现）
> - **无退款异步回调**（渠道退款为同步调用，退款结果即时返回）
> - 审核驳回与渠道退款失败共用 status=3（refund_failed），通过 audit_remark/error_message 区分

### 4.7 自动续费

**配置读写**：
- `updateAutoRenewConfig`：校验套餐存在，upsert（`(user_id, package_id)` 唯一）写入 pay_method/status/fail_count=0；**next_renew_time 不设置（NULL）**——首次开启不触发扣款
- `getAutoRenewConfig`：未配置时返回 enabled=false、payMethod=balance

**executeRenewal**（定时任务）：
```
扫描 status=1 且 next_renew_time <= NOW() 的配置
    ↓ 逐条 executeSingleRenewal：
  1. 套餐在售校验（否则抛错触发失败分支）
  2. 价格：payable = sale_price × 0.95（95折），discount = sale_price - payable
  3. 非 balance → 调渠道 autoDeduct（微信实际走统一下单+用户主动支付；失败抛错）
  4. activateMemberByPackage 激活会员（有效期叠加）
  5. 创建已支付订单（status=2、is_auto_renew=1、paidAmount=payable、paidTime/effectiveTime/expireTime）
  6. 创建支付记录（status=2）、累加套餐销量
  7. 更新配置：last_renew_order_id、next_renew_time=新到期时间、fail_count=0
    ↓ 异常时：
  fail_count+1
    ├─ 达 3 次 → status=0、next_renew_time=NULL、close_reason="连续失败超过限制"
    └─ 未达 3 次 → next_renew_time = NOW()+2小时（重试）
```

### 4.8 定时任务（5 个）

| 任务名 | 实现方法 | 执行时机 | 扫描条件 | 处理 |
|--------|---------|---------|---------|------|
| 订单超时取消 | expireOrders | 每 5 分钟 | status=1 且 expire_time < NOW | 渠道关单（失败仅告警）→ status=4 → 释放券 → cancel_reason="系统超时自动取消" |
| 自动续费扣款 | executeRenewal | 每 1 小时 | status=1 且 next_renew_time <= NOW | 见 §4.7 |
| 订单到期归档 | completeExpiredOrders | 每 1 小时 | status=2 且 package_expire_time < NOW | status → 3 |
| 优惠券过期 | expireUserCoupons | 每 1 小时 | status=1 且 expire_time < NOW | status → 3 |
| 退款失败重试 | retryFailedRefunds | 每 30 分钟 | status=3 且 retry_count < 3 | 重新调渠道退款；成功 → status=2、订单 status=6；失败 → retry_count+1、达 3 次标记"已达重试上限，转为最终失败" |

## 6. 三端实现差异说明

| 差异点 | Java | Python | Go |
|--------|------|--------|-----|
| 退款 7 天时限校验 | ❌ 未实现 | ✅ REFUND_TIME_EXCEEDED | ❌ 未实现 |
| 回调金额不一致处理 | 返回 false + 日志 | 抛 PAYMENT_AMOUNT_MISMATCH | - |
| 支付/下单分布式锁 | ✅ Redisson | ✅ Redis 锁 | ❌ 无锁 |
| 订单详情缓存 | ✅ 10min | ✅ 10min | - |

| 退款渠道调用 | ✅ 同步 refund | ✅ 同步 refund | ✅ 同步 refund |

> **说明**：Go 端订单/支付/退款/自动续费均已实现（`internal/service/order`、`internal/service/payment`），但无订单并发锁与退款时限校验；三端差异需在后续改造中统一（见 [需求规格 §9](../../订单管理/需求规格.md)）。

## 7. 安全设计

### 7.1 支付安全

| 防护项 | 实现方式 |
|--------|---------|
| 签名验证 | 渠道验签（wechat 按参数排序+key 签名；渠道未启用时 mock 直接信任） |
| 金额校验 | 回调金额与订单应付金额一致（Java 返回失败 / Python 抛异常） |
| 幂等处理 | 订单级分布式锁 + 状态判断 + 支付流水唯一索引（三重保障） |
| 防重复下单 | 订单级分布式锁（用户+套餐，5 秒） |
| 敏感信息 | 支付流水号脱敏展示，回调原始报文存库不对外 |

### 7.2 权限控制

| 权限标识 | 控制范围 |
|---------|---------|
| order:refund:approve | 退款审核（后端接口校验） |
| order:stats | 订单统计（前端按钮控制，后端无校验） |

> **说明**：后台订单列表/详情/退款列表接口**无权限标识**（登录即可）；早期设计稿的 order:list/order:detail 权限标识不存在。

### 7.3 用户端越权校验

getDetail/cancel/pay/applyRefund 接口校验 `order.userId == 当前用户ID`，非本人操作返回 ORDER_NOT_FOUND（避免泄露订单是否存在）；订单详情缓存命中时同样校验缓存 VO 归属。

## 8. 配置项

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| 订单支付超时时间 | 创建后多少分钟超时 | 30 分钟 |
| 自动续费扣款重试 | 失败重试次数 | 3 |
| 自动续费重试间隔 | 重试间隔 | 2 小时 |
| 自动续费折扣 | 续费价格折扣 | 0.95 |
| 退款时限 | 支付后多少天内可退（仅 Python 端生效） | 7 天 |
| payment.wechat.enabled / payment.alipay.enabled | 渠道是否启用（false 时 mock） | false |

> 超时扫描频率（5 分钟）、续费扫描频率（1 小时）、退款重试频率（30 分钟）为任务调度常量（Java XXL-Job / Python APScheduler / Go cron），非配置文件可调项。
