### 3.4 核心业务逻辑

#### 订单创建逻辑

1. **参数校验**：套餐存在且在售、优惠券可用
2. **防重复下单**：Redis 锁（同一用户+同一套餐，5秒）
3. **价格计算**：调用 `PackageService.calculatePrice`
4. **金额校验**：应付金额 ≥ 0
5. **优惠券锁定**：`UPDATE sys_user_coupon SET status=4 WHERE id=? AND status=1`
6. **生成订单**：插入 `sys_order`，expire_time = NOW() + 30min
7. **事务保证**：订单创建与优惠券锁定同一事务

#### 支付回调处理（核心幂等逻辑）

```
接收渠道回调
    ↓
验签校验（签名+金额）
    ├─ 失败 → 记录日志，返回失败
    └─ 成功 → 继续
    ↓
Redis 分布式锁（key: payment:lock:{orderNo}）
    ├─ 获取失败 → 直接返回成功（重复回调）
    └─ 成功 → 继续
    ↓
查询订单状态
    ├─ paid → 幂等返回成功
    ├─ cancelled → 记录异常，人工处理
    └─ pending → 继续
    ↓
插入支付流水（唯一索引 uk_payment_no 防重）
    ↓
更新订单状态为 paid
    ↓
触发权益生效（同事务）：
    - 更新 sys_member 等级与到期时间
    - 增加成长值（consume 类型）
    - 核销优惠券（status=2, used_order_id）
    - 推送支付成功通知
    ↓
释放分布式锁
    ↓
返回成功
```

#### 订单超时取消（定时任务）

1. **触发时机**：每5分钟
2. **扫描条件**：`status=1 AND expire_time < NOW()`
3. **取消流程**：
   - 调用渠道关单接口（防延迟支付）
   - 更新订单状态为 cancelled
   - 释放优惠券（status=1）
   - 记录 cancel_reason="超时未支付"

#### 退款申请逻辑

1. **时限校验**：支付成功 ≤ 7天
2. **使用次数校验**：已用次数 < 总配额50%
3. **套餐类型校验**：非促销特价套餐
4. **唯一性校验**：uk_order_id 阻止重复申请
5. **退款金额计算**：
   - 未使用权益：全额退款
   - 部分使用：`paid_amount × (1 - used_quota / total_quota)`
6. **订单状态变更**：paid → refunding
7. **创建退款记录**

#### 退款审核逻辑

```
审核通过：
    - 调用渠道退款接口
    - 等待渠道回调（异步）
    - 回调成功 → 订单 refunded，权益回收，扣减成长值
    - 回调失败 → 记录 error_message，人工重试

审核驳回：
    - 订单恢复 paid
    - 记录驳回原因
    - 通知用户
```

#### 自动续费执行（定时任务）

1. **触发时机**：每小时
2. **扫描条件**：`status=1 AND next_renew_time <= NOW()`
3. **续费流程**：
   - 创建新订单（is_auto_renew=1）
   - 调用渠道代扣接口
   - 扣款成功 → 续费订单叠加有效期
   - 扣款失败 → fail_count+1，重试（最多3次，间隔2小时）
   - 3次失败 → status=0，关闭自动续费

### 3.5 事务管理

| 操作类型 | 事务级别 | 说明 |
|---------|---------|------|
| 查询操作 | 只读事务 | 优化性能 |
| 订单创建 | 读写事务 | 订单+优惠券锁定 |
| 支付回调 | 读写事务 | 流水+订单+权益+成长值 |
| 退款执行 | 读写事务 | 退款记录+订单+权益回收 |
| 自动续费 | 读写事务 | 新订单+扣款+有效期叠加 |

**长事务拆分**：支付回调中的外部调用（MinIO 通知、推送）拆出事务外，避免连接池耗尽。

## 4. 数据访问层设计

### 4.1 查询优化

#### 订单列表查询

- 索引 `idx_user_id_status` 优化用户维度查询
- 索引 `idx_create_time` 优化时间范围查询
- 关联 `sys_user` 获取用户名/昵称

#### 支付流水查询

- 唯一索引 `uk_payment_no` 保证幂等
- 索引 `idx_order_id` 关联查询

### 4.2 缓存策略

| 缓存对象 | 缓存 Key | 过期时间 | 更新策略 |
|---------|---------|---------|---------|
| 订单详情 | order:detail:{orderNo} | 10 分钟 | 状态变更时删除 |
| 支付锁 | payment:lock:{orderNo} | 10 分钟 | 回调处理完释放 |
| 防重复下单 | order:lock:{userId}:{packageId} | 5 秒 | 自动过期 |

## 7. 安全设计

### 7.1 支付安全

| 防护项 | 实现方式 |
|--------|---------|
| 签名验证 | 渠道公钥验签 |
| 金额校验 | 回调金额与订单金额一致 |
