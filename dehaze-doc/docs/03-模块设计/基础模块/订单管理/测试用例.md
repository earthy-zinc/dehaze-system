# 订单管理模块测试用例

## 1. 测试目标

验证订单管理模块（平台**统一交易中枢**）符合 [需求规格.md](./需求规格.md) 定义：

- **统一交易中枢**：会员卡 / 积分卡统一经订单管理交易，下单/支付/超时/取消行为对全部商品类型一致（F-OM-001~F-OM-004）
- **履约分流**：支付成功后按商品类型履约（会员卡激活权益 / 积分卡积分到账），成长值所有商品按实付 1:1（F-OM-003）
- **退款兜底策略**：退款为特殊原因兜底（非随意退），售后申请原因类型必选，双审核（F-OM-006~F-OM-008）
- **余额账户**：人民币交易媒介，与 AI 积分账户职责分离（F-OM-015/F-OM-017）
- **后台管理**：订单列表（含商品类型维度）、订单详情、售后审核列表（含原因类型筛选）、订单统计（F-OM-009~F-OM-012）
- **用户端**：我的订单、订单详情（F-OM-013/F-OM-014）
- **非功能**：并发场景（支付回调幂等、优惠券并发）、性能指标（下单 <200ms、回调 <3s）、安全性（验签、金额校验、越权）

## 2. 测试前置

### 2.1 测试数据

| 数据类型 | 准备内容 | 说明 |
|---------|---------|------|
| 商品数据 | 会员卡（多等级/周期）、积分卡（多积分档位）在售商品 | 覆盖两种商品类型下单 |
| 用户数据 | 各等级会员用户、普通用户 | 用于不同场景下单与履约验证 |
| 优惠券 | 不同类型可用券 | 用于订单抵扣测试 |
| 支付配置 | 微信/支付宝沙箱配置、平台余额充值用户 | 用于支付测试 |
| 订单数据 | 各状态订单样本（两种商品类型） | 用于列表查询与状态流转 |
| 积分消耗数据 | 已消耗部分积分的积分卡订单 | 用于按用量折算退款 |

### 2.2 数据清理策略

- 测试订单使用统一前缀 `DHTEST` 标识订单号
- 测试结束按前缀清理订单、支付流水、售后记录、余额与积分流水
- 支付沙箱数据每日重置；测试优惠券使用专用批次，便于回收

### 2.3 测试范围

**包含：**
- 两种商品类型的订单创建与支付（含余额/组合支付）
- 支付回调处理与幂等、履约分流（会员卡激活 / 积分到账 / 成长值）
- 订单超时取消、自动续费（仅会员卡）
- 售后申请（原因类型必选、按类型折算）、双审核、按类型回退履约、退款失败重试
- 余额账户充值/支付/组合支付全链路
- 后台订单管理（含商品类型筛选）、售后审核列表（含原因类型筛选）、订单统计（含商品类型维度）
- 渠道对账（三类差异）

**不包含（属其他模块测试范围）：**
- 商品定义与定价（套餐管理模块）
- 会员等级变更细则（会员管理模块）
- 积分到账/回退的实现细节（AI 计费管理模块）
- 支付渠道接口细节（渠道沙箱测试）

## 4. 关键边界与异常场景

| 场景 | 测试点 | 期望行为 |
|------|--------|---------|
| 退款政策边界 | 主观原因申请退款 | 拦截并提示，不进入售后流程 |
| 退款折算边界 | 会员卡已用完 / 积分卡全部消耗 | 折算金额为 0，不产生实际退款 |
| 售后唯一性 | 同一订单重复提交售后 | 唯一约束阻止 |
| 支付回调并发 | 同一订单多次回调 | Redis 锁保护，仅一次执行业务 |
| 优惠券并发使用 | 多订单同时使用同一券 | 条件 UPDATE / 唯一约束阻止 |
| 自动续费并发 | 同一用户并发扣款 | 逐条处理，异常隔离 |
| 状态机非法流转 | cancelled → paid 等非法流转 | 校验失败，拒绝流转 |
| 商品类型差异 | 积分卡无续费/无归档、支付即完成 | 与会员卡行为区分，互不串扰 |

### 5.2 并发场景

| 场景 | 并发数 | 验证点 |
|------|--------|--------|
| 并发支付回调 | 同一订单 10 次回调 | 幂等，仅一次执行业务 |

## 6. 安全性测试

| 测试项 | 验证方式 | 预期结果 |
|--------|---------|---------|
