# 部门管理模块 - 前端实现设计

## 1. 文档概述

本文档描述部门管理模块的前端实现方案，聚焦组件架构、状态管理、数据流、交互流程等架构决策，为前端开发提供指导。

## 2. 组件架构设计

### 2.1 组件层次结构

```
部门管理页面 (DeptManagement/index.vue)
├── 搜索容器
│   ├── 搜索表单 (SearchForm)
│   │   ├── 部门名称输入框
│   │   ├── 状态选择器
│   │   ├── 搜索按钮
│   │   └── 重置按钮
│   └── 操作按钮区域 (ActionButtons)
│       └── 新增按钮
└── 数据展示区域
    └── 部门表格 (DeptTable)
        └── 树形结构表格组件
```

### 2.2 弹窗组件结构

```
弹窗组件 (DeptDialog)
└── 部门表单弹窗 (DeptFormDialog)
    └── 部门表单 (DeptForm)
        ├── 部门名称输入框
        ├── 上级部门选择器（树形选择）
        ├── 排序输入框
        └── 状态单选框组
```

### 2.3 组件职责划分

| 组件名称 | 职责描述 | 复用性 |
|---------|---------|--------|
| **SearchForm** | 搜索条件输入与提交 | 页面内部组件 |
| **ActionButtons** | 操作按钮区域，统一管理权限控制 | 页面内部组件 |
| **DeptTable** | 部门数据树形表格展示与行操作 | 页面内部组件 |
| **DeptFormDialog** | 部门新增/编辑表单弹窗 | 页面内部组件 |

## 3. 页面布局设计

### 3.1 整体布局

部门管理页面采用**单栏布局**，主要内容区域包含搜索条件、操作按钮和部门数据表格。

| 区域 | 高度 | 说明 |
|------|------|------|
| **搜索区域** | 自适应 | 搜索表单 + 操作按钮 |
| **表格区域** | 自适应填充 | 部门树形数据表格 |

### 3.2 响应式布局

| 屏幕尺寸 | 布局调整 |
|---------|---------|
| **≥1200px** | 完整布局展示 |
| **992px~1199px** | 完整布局展示 |
| **&lt;992px** | 表格支持横向滚动，按钮适当缩小或堆叠显示 |

| 按钮 | 类型 | 图标 | 权限标识 | 禁用规则 |

## 6. 数据流设计

### 6.1 数据交互场景

部门管理通过 `dehaze-sdk-js` 封装的部门接口完成数据交互，页面组件内统一管理请求与状态：

| 数据场景 | 调用方向 | 说明 |
|---------|---------|------|
| 列表查询 | 页面 → 部门列表接口 | 树形结构返回，按查询条件过滤 |
| 下拉选项 | 表单 → 部门选项接口 | 树形下拉，供上级部门选择 |
| 表单回显 | 编辑弹窗 → 表单数据接口 | 加载部门详情 |
| 新增/修改 | 表单提交 → 新增/修改接口 | 提交后刷新列表与下拉选项 |
| 删除 | 删除确认 → 删除接口 | 单个删除，成功后刷新列表 |

## 7. 交互流程设计

### 7.1 页面初始化流程

1. 进入页面，显示加载状态
2. 请求部门树形列表数据
3. 数据加载完成，默认展开所有节点

### 7.2 关键流程说明

| 流程 | 关键点 |
|------|--------|
| 部门新增 | 加载部门下拉选项 → 填写表单 → 提交 → 刷新列表 |
| 新增下级 | parentId 自动填充当前部门 → 填写其他字段 → 提交 → 刷新列表 |
| 部门编辑 | 并行加载下拉选项和详情 → 修改 → 提交 → 刷新列表 |
| 部门删除 | 确认对话框 → 关联用户/子部门检查 → 删除 → 刷新列表 |

#### 删除前校验提示

| 校验结果 | 提示文案 |
|---------|---------|
| 存在关联用户 | 该部门下存在用户，无法删除。 |
| 存在子部门 | 该部门下存在子部门，请先删除子部门。 |
| 根部门 | 根部门不可删除/修改上级。 |
| 无关联数据 | 确认删除部门「{deptName}」吗？ |

## 8. 表单校验设计

### 8.1 格式校验规则

| 字段 | 校验规则 | 说明 |
|------|---------|------|
| parentId | 必填 | 上级部门不能为空（根部门除外） |
| name | 必填，长度限制 | 部门名称不能为空 |
| sort | 必填，正整数 | 排序必须为正整数 |
| 层级深度 | 新增/移动后层级 ≤ 5 级 | 超过 5 级时阻止提交并提示 |

### 8.2 业务校验规则

部门名称唯一性校验由后端执行，前端显示后端返回的错误信息。
