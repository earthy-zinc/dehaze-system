# 部门管理模块 - 后端实现设计

## 1. 文档概述

本文档描述部门管理模块的后端实现方案，包括数据传输对象、核心业务逻辑、缓存与依赖等实现要点。

- **API 接口规范**：参见 [API接口.md](./API接口.md)
- **数据库设计**：参见 [02-系统架构/03-数据库设计.md](../../../02-系统架构/03-数据库设计.md)

## 3. 核心业务逻辑设计

### 3.1 关键流程

#### 部门列表查询流程

```
接收查询参数 → 参数校验 → 查询部门数据 → 构建树形结构 → 返回结果
```

一次性查询全部未删除部门，按 parentId 映射父子关系后递归组装树（根节点 parentId = 0）。

#### 部门新增流程

```
接收表单数据 → 基础校验 → 业务规则校验 → 保存部门 → 清除缓存 → 返回结果
```

#### 部门编辑流程

```
接收表单数据 → 基础校验 → 存在性校验 → 业务规则校验 → 更新部门 → 清除缓存 → 返回结果
```

#### 部门删除流程

```
接收部门ID列表 → 参数解析 → 批量前置校验 → 开启事务并对目标部门加悲观锁 → 事务内重新校验关联 → 逻辑删除 → 清除缓存 → 返回结果
```

**批量删除策略**：采用单事务原子策略——先批量校验所有目标部门的删除前置条件，任一不满足则整体失败并返回失败项明细；全部通过后在同一事务内加锁、重新校验、逻辑删除，保证全部成功或全部回滚，不支持部分成功。

### 3.2 核心业务规则

业务规则（名称唯一性、层级深度、根部门保护、关联用户与子部门检查、逻辑删除、数据权限范围）以 [需求规格.md](./需求规格.md) §3 为准，本节仅列实现侧约束：

| 约束 | 实现要点 |
|------|---------|
| 默认值 | 新增时 sort 默认 1、status 默认 1 |
| 唯一性校验范围 | 名称唯一性校验含已删除记录，避免删除后同名冲突 |
| 循环引用检测 | 基于 treePath 判断目标父节点是否为自身或后代，命中则拒绝 |
| 层级深度计算 | 按目标父节点 treePath 计算新增/移动后的层级，超限则拒绝 |

### 3.3 事务边界

| 操作类型 | 事务级别 | 说明 |
|---------|---------|------|
| 查询操作 | 只读事务 | - |
| 新增/编辑部门 | 读写事务 | 单表写入，保证数据一致性 |
| 删除部门 | 读写事务 | 对目标部门加悲观锁，事务内重新校验关联数据后逻辑删除（防并发 TOCTOU） |

### 3.4 跨模块协作：角色数据权限联动

部门是角色数据权限（dataScope）的引用基础，部门状态变更与删除需联动处理角色配置：

| 场景 | 联动处理 |
|------|---------|
| 部门禁用 | 部门记录保留，角色 dataScope 引用不变；该部门下数据不再产生新业务，提醒管理员评估数据权限范围 |
| 部门删除 | 部门逻辑删除后，数据权限查询自动过滤已删除部门，角色 dataScope 中对该部门的引用随之失效；操作日志记录受影响角色，提醒管理员重新配置数据权限范围 |

## 4. 数据访问与数据依赖

### 4.1 依赖表

| 表名 | 关联方式 | 说明 |
|------|---------|------|
| sys_dept | 主表 | 部门主表 |
| sys_user | 关联表 | 部门删除时需检查是否存在关联用户 |

### 4.2 字段业务约束

表字段定义见 [02-系统架构/03-数据库设计.md](../../../02-系统架构/03-数据库设计.md)；字段业务约束见 §2 与 [需求规格.md](./需求规格.md) §3。

### 4.3 查询设计

- **树形列表**：一次性加载全部未删除部门，应用层按 parentId 组装树形结构
- **子树查询**：基于 treePath 物化路径前缀匹配获取子部门，无需递归查询
- **下拉选项过滤**："仅启用"模式下追加状态过滤条件

## 5. 缓存设计

| 缓存对象 | 缓存 Key | 过期时间 | 更新策略 |
|---------|---------|---------|---------|
| 部门树 | dept:tree | 1 小时 | 部门增删改时删除 |
| 部门下拉选项 | dept:options | 1 小时 | 部门增删改时删除 |

部门新增、编辑、删除成功后清除上述缓存，下次查询重新加载。

## 6. 安全设计

> 权限标识见 [API接口.md - 权限标识汇总](./API接口.md)。

### 6.1 数据权限

查询时自动注入部门过滤条件，基于用户部门与部门树路径判断可访问范围；角色与数据范围矩阵见 [需求规格.md](./需求规格.md) §2.2。三端实现一致（Java 为权威来源，Go/Python 对齐）。

### 6.2 输入校验

参数校验使用 Bean Validation 校验必填、格式与长度；业务校验项见 §3.2。

### 6.3 根部门保护

根部门（id=1）的删除与上级变更由服务端兜底拦截，规则见 [需求规格.md](./需求规格.md) §2.3。

### 6.4 级联删除保护

删除事务内对目标部门加悲观锁并重新校验子部门与关联用户，防止 TOCTOU 并发问题；批量删除单事务原子，不支持部分成功。

## 7. 日志设计

### 7.1 操作日志记录

| 操作类型 | 记录内容 |
|---------|---------|
| 新增部门 | 操作人、操作时间、新增部门名称、上级部门 |
| 编辑部门 | 操作人、操作时间、修改部门 ID、修改字段 |
| 删除部门 | 操作人、操作时间、删除部门 ID 列表、删除部门名称 |

## 8. 导入导出设计

部门模块的导入导出由通用导入导出框架统一调度，模块侧实现 `DeptExportHandler` 和 `DeptImportHandler`。通用框架负责文件生成/解析、进度回调、结果上传、任务状态管理。

### 8.1 DeptExportHandler

实现 `ExportHandler` 接口，`getModule()` 返回 `"dept"`。

| 方法 | 说明 |
|------|------|
| estimateCount | 根据查询条件估算部门数据量 |
| export | 查询部门数据（树形结构导出为扁平结构），通过 callback 回写进度 |
| getFieldConfigs | 返回导出字段配置：部门名称、父级部门、排序、状态、创建时间 |

### 8.2 DeptImportHandler

实现 `ImportHandler` 接口，`getModule()` 返回 `"dept"`。

| 方法 | 说明 |
|------|------|
| getFieldConfigs | 返回导入字段配置（部门名称必填） |
| importBatch | 批量导入部门：校验部门名称唯一性、按父级部门 ID 构建树形关系；导入时校验层级深度不超过 5 级，并通过 treePath 检测循环引用（路径包含自身 ID 则拒绝该记录） |
| getTemplateSampleData | 返回模板示例数据 |

## 9. 配置项与常量

本模块无管理员/运营需动态调整的配置项，以下均为代码常量（Java `static final` / Go `const` / Python 模块常量），非配置文件可调项：

| 常量 | 说明 | 值 |
|------|------|-----|
| 部门层级深度限制 | 部门树最大层级数（批量导入亦校验不超过该层级，见 §8） | 5 |
| 部门树缓存 TTL | `dept:tree` 缓存过期时间（见 §5） | 1 小时 |
| 部门下拉选项缓存 TTL | `dept:options` 缓存过期时间（见 §5） | 1 小时 |
