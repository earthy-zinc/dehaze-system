## 3. 核心业务逻辑设计

### 3.1 关键流程

#### 部门列表查询流程

```
接收查询参数 → 参数校验 → 查询部门数据 → 构建树形结构 → 返回结果
```

**树形结构构建逻辑**：
1. 一次性查询所有部门数据（或按条件过滤）
2. 将部门列表按 parentId 映射为父子关系
3. 递归构建完整树形结构（根节点 parentId = 0）

#### 部门新增流程

```
接收表单数据 → 基础校验 → 业务规则校验 → 保存部门 → 清除缓存 → 返回结果
```

#### 部门编辑流程

```
接收表单数据 → 基础校验 → 存在性校验 → 业务规则校验 → 更新部门 → 清除缓存 → 返回结果
```

#### 部门删除流程

```
接收部门ID列表 → 参数解析 → 批量前置校验 → 开启事务并对目标部门加悲观锁 → 事务内重新校验关联 → 逻辑删除 → 清除缓存 → 返回结果
```

**批量删除策略**：采用单事务原子策略——先批量校验所有目标部门的删除前置条件，任一不满足则整体失败并返回失败项明细；全部通过后在同一事务内加锁、重新校验、逻辑删除，保证全部成功或全部回滚，不支持部分成功。

### 3.2 核心业务规则

#### 部门新增规则

1. **名称唯一性**：同一 parentId 下，部门名称必须唯一
2. **上级部门存在性**：parentId 必须指向已存在的部门
3. **层级深度限制**：新增后部门层级不超过 5 级
4. **默认值**：sort 默认为 1，status 默认为 1（启用）

#### 部门编辑规则

1. **循环引用检测**：不能将部门移动到自身或其子部门下
2. **根部门保护**：系统内置根部门（id=1）不可修改 parentId
3. **名称唯一性**：同一层级下名称必须唯一（编辑时排除自身）

#### 部门删除规则

1. **关联用户检查**：部门下存在关联用户时，禁止删除
2. **子部门检查**：部门下存在子部门时，禁止删除（不级联删除，需先删除子部门）
3. **根部门保护**：系统内置根部门（id=1）不可删除，返回 `A0234`
4. **逻辑删除**：执行逻辑删除（标记 `deleted = 1`），数据保留可追溯，不物理删除
5. **唯一性校验含已删除**：新增/编辑时部门名称唯一性校验需包含已删除记录，避免删除后同名记录冲突

### 3.3 事务边界

| 操作类型 | 事务级别 | 说明 |
|---------|---------|------|
| 查询操作 | 只读事务 | 优化数据库性能 |
| 新增部门 | 读写事务 | 单表插入，需保证数据一致性 |
| 编辑部门 | 读写事务 | 单表更新，需保证数据一致性 |
| 删除部门 | 读写事务 | 对目标部门加悲观锁，事务内重新校验关联数据后逻辑删除（防并发 TOCTOU） |

### 3.4 跨模块协作：角色数据权限联动

部门是角色数据权限（dataScope）的引用基础，部门状态变更与删除需联动处理角色配置：

| 场景 | 联动处理 |
|------|---------|
| 部门禁用 | 部门记录保留，角色 dataScope 引用不变；该部门下数据不再产生新业务，提醒管理员评估数据权限范围 |
| 部门删除 | 部门逻辑删除后，数据权限查询自动过滤已删除部门，角色 dataScope 中对该部门的引用随之失效；操作日志记录受影响角色，提醒管理员重新配置数据权限范围 |

## 4. 数据访问与数据依赖

### 4.1 依赖表

| 表名 | 关联方式 | 说明 |
|------|---------|------|
| sys_dept | 主表 | 部门主表 |
| sys_user | 关联表 | 部门删除时需检查是否存在关联用户 |

### 4.2 字段业务约束

> 主键、审计字段（createBy/updateBy/createTime/updateTime）等通用规范详见 [02-系统架构/03-数据库设计.md](../../../02-系统架构/03-数据库设计.md)，本节仅列部门模块特有的业务约束。

| 字段 | 约束说明 |
|------|---------|
| name | 同一 parentId 下唯一（含已删除记录校验，详见 §3.2） |
| parentId | 指向 sys_dept.id，根部门 parentId=0 |
| treePath | 父节点 ID 路径（逗号分隔），用于子树与祖先链查询 |
| status | 0:禁用; 1:启用 |
| sort | 整数，升序排列 |
| deleted | 逻辑删除标识，0:未删除; 1:已删除，查询默认过滤 |

### 4.3 查询设计

- **树形列表**：一次性加载全部未删除部门，应用层按 parentId 组装树形结构
- **子树查询**：基于 treePath 物化路径前缀匹配获取子部门，无需递归查询
- **下拉选项过滤**："仅启用"模式下追加状态过滤条件

## 5. 缓存设计

| 缓存对象 | 缓存 Key | 过期时间 | 更新策略 |
|---------|---------|---------|---------|
| 部门树 | dept:tree | 1 小时 | 部门增删改时删除 |
| 部门下拉选项 | dept:options | 1 小时 | 部门增删改时删除 |

**缓存一致性策略**：
- 部门新增、编辑、删除操作成功后，清除 `dept:tree` 和 `dept:options` 缓存
- 下次查询时重新加载最新数据

## 6. 安全设计

> **权限标识**：详见 [API接口.md - 权限标识汇总](./API接口.md)

### 6.1 数据权限

系统启用数据权限实现部门数据隔离，三端实现一致（Java 为权威来源，Go/Python 对齐）：查询时自动注入部门过滤条件，基于用户部门与部门树路径进行范围判断。

| 角色类型 | 权限范围 |
|---------|---------|
| 系统管理员 | 全部部门 |
| 部门管理员 | 本部门及下级部门 |
| 普通用户 | 无数据权限 |

### 6.2 输入校验

| 校验类型 | 说明 |
|---------|------|
| 参数校验 | 使用 Bean Validation 校验必填字段、格式、长度 |
| 业务校验 | 部门名称唯一性、上级部门合法性、循环引用检测 |

### 6.3 根部门保护

| 策略项 | 说明 |
|--------|------|
| 不可删除 | 系统内置根部门（id=1）不可删除，返回 `A0234` |
| 不可修改上级 | 根部门 parentId 不可变更，防止破坏树形结构根节点 |
| 层级深度限制 | 部门树最大 5 级，新增/移动后层级超过限制返回 `A0504` |

### 6.4 级联删除保护

| 策略项 | 说明 |
|--------|------|
| 子部门检查 | 部门下存在子部门时禁止删除（返回 `A0502`），需先删除子部门，不支持级联删除 |
| 关联用户检查 | 部门下存在关联用户时禁止删除（返回 `A0502`），需先转移用户 |
| 批量原子性 | 批量删除采用单事务原子策略，全部通过校验后统一逻辑删除，不支持部分成功 |
| 悲观锁防并发 | 删除事务内对目标部门加悲观锁，事务内重新校验关联数据，防止 TOCTOU 并发问题 |

## 8. 导入导出设计

部门模块的导入导出由通用导入导出框架统一调度，模块侧实现 `DeptExportHandler` 和 `DeptImportHandler`。通用框架负责文件生成/解析、进度回调、结果上传、任务状态管理，详见[任务管理/后端实现.md](../任务管理/后端实现.md)。

### 8.1 DeptExportHandler

实现 `ExportHandler` 接口，`getModule()` 返回 `"dept"`。

| 方法 | 说明 |
|------|------|
| estimateCount | 根据查询条件估算部门数据量 |
| export | 查询部门数据（树形结构导出为扁平结构），通过 callback 回写进度 |
| getFieldConfigs | 返回导出字段配置：部门名称、父级部门、排序、状态、创建时间 |

### 8.2 DeptImportHandler

实现 `ImportHandler` 接口，`getModule()` 返回 `"dept"`。

| 方法 | 说明 |
|------|------|
| getFieldConfigs | 返回导入字段配置（部门名称必填） |
| importBatch | 批量导入部门：校验部门名称唯一性、按父级部门 ID 构建树形关系；导入时校验层级深度不超过 5 级，并通过 treePath 检测循环引用（路径包含自身 ID 则拒绝该记录） |
| getTemplateSampleData | 返回模板示例数据 |

## 9. 配置项

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| 部门层级深度限制 | 部门树最大层级数 | 5 |
| 部门缓存过期时间 | 部门树和下拉选项缓存时间 | 1 小时 |
