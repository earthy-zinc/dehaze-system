## 3. 服务层设计

### 3.1 服务接口定义

会员管理涉及两个 Service：`MemberService`（会员信息、等级、成长值、签到、配额）和 `MemberBenefitService`（权益配置）。

| getProfile | - | MemberProfileVO | 当前用户会员信息 |
| getPage | MemberPageQuery | IPage<MemberPageVO> | 分页查询会员 |
| getDetail | Long userId | MemberDetailVO | 会员详情 |
| adjustLevel | Long userId, MemberLevelAdjustForm | void | 等级调整 |
| adjustGrowth | Long userId, MemberGrowthAdjustForm | void | 成长值调整 |
| updateStatus | Long userId, MemberStatusForm | void | 冻结/解冻 |

| resetMonthlyQuota | - | boolean | 月度配额重置（定时任务） |

### 3.2 核心业务逻辑

#### 等级自动升降级

成长值变更/套餐支付成功 → 查询 sys_member_benefit 取各等级 growth_min/growth_max → 比较成长值与新等级区间 → 更新 sys_member.level_code → 同步刷新权益配置（取套餐权益与等级权益较高值）→ 推送升级/降级通知

**保级机制（level_source 校验）**：自动升降级触发等级检查时，仅当 `level_source == "growth"` 才自动调整等级；若 `level_source == "purchase"`（套餐购买未到期）或 `"admin"`（管理员指定）则不自动降级。

#### 成长值变动逻辑

1. **参数校验**：变动值不为0，扣减后余额 >= 0
2. **更新余额**：原子更新 sys_member 表 growth_value，校验扣减后余额
3. **写入流水**：插入 sys_member_growth_log，记录 balance
4. **触发等级检查**：调用 checkAndAdjustLevel（内部校验 level_source == "growth" 才调整）
5. **通知**：等级变更时推送站内信

#### 等级调整（管理员）

1. **参数校验**：调整原因必填
2. **更新等级**：置 `level_code` 为目标等级，`level_source = "admin"`，始终更新 `expire_time`（传入则设置，传 null 则清空）
3. **刷新配额**：按新等级 `sys_member_benefit` 同步刷新 `monthly_dehaze_quota`、`monthly_evaluate_quota`
4. **首次开通**：`become_member_time` 为空时写入当前时间
5. **缓存失效**：删除 `member:level:{userId}`、`member:profile:{userId}`
6. **审计日志**：记录操作人、原等级、新等级、原因

#### 签到逻辑

1. **唯一性校验**：`(user_id, sign_date)` 唯一索引阻止重复签到，预检查命中或并发触发唯一约束冲突均转抛 `SIGN_IN_ALREADY`（Java 显式捕获 `DuplicateKeyException`）
2. **连续天数计算**：查询昨日是否有签到记录
   - 有 → `continuous_days = 昨日连续天数 + 1`
   - 无 → `continuous_days = 1`
3. **成长值计算**：基础3点 + 连续7天奖励20点；返回 SignInVO 中 `growthValue` 为基础值（3），`bonusGrowth` 为连续签到奖励值（三端统一）
4. **事务写入**：签到记录 + 成长值变动流水（同一事务）
5. **触发成长值检查**：调用 `checkAndAdjustLevel`（内部校验 `level_source == "growth"` 才调整）

#### 权益校验与扣减

查询用户会员等级(Redis缓存优先) → 检查会员状态(status != 1 时抛 MEMBER_FROZEN) → 查询当月已用次数 < 配额上限 → Redis DECR 原子扣减 → 异步落库

**冻结状态校验**：deductQuota/checkAndDeductQuota 方法在查询会员后立即校验 member.status != 1，冻结会员直接抛 MEMBER_FROZEN，不进入配额扣减流程。

#### 月度配额重置（定时任务）

1. **触发时机**：每月1日 00:00
2. **幂等保护**：仅扫描 `quota_reset_month IS NULL OR quota_reset_month != currentMonth` 的会员，重复执行不会重复重置
3. **分批处理**：每批500条，采用"始终查询第1页"策略（已重置的会员被条件排除，无需翻页），避免一次性加载全部会员到内存
4. **权益预加载**：批量查询 `sys_member_benefit` 构建 Map 缓存，循环内从 Map 取值，避免 N+1 查询
5. **归档历史数据**：仅当 `quota_reset_month != NULL` 时，将 `sys_member` 当月字段写入 `sys_member_quota`，归档月份使用会员原有的 `quota_reset_month`
6. **重置当月字段**：根据当前等级读取 `sys_member_benefit` 配额，更新 `sys_member` 的 `monthly_*_quota`、`monthly_*_used=0`、`quota_reset_month=currentMonth`
7. **缓存失效**：每批处理完后删除 `member:quota:{userId}:dehaze`、`member:quota:{userId}:evaluate`、`member:profile:{userId}`
8. **失败容错**：单条失败记录日志并跳过，不影响其他会员；无方法级事务（每条记录独立处理）

#### 会员冻结/解冻

1. **冻结**（`status=0`）：写入 `frozen_reason`、`frozen_time`，原因必填
2. **解冻**（`status=1`）：仅设置 `status=1`，**不清空** `frozen_reason`、`frozen_time`，保留冻结历史便于追溯
3. **缓存失效**：删除 `member:profile:{userId}`、`member:level:{userId}`
4. **审计日志**：记录操作人、原状态、新状态、原因

### 3.3 事务管理

| 操作类型 | 事务级别 | 说明 |
|---------|---------|------|
| 查询操作 | 只读事务 | 优化数据库性能 |
| 成长值变动 | 读写事务 | 余额更新+流水写入+等级检查需事务保证 |
| 签到 | 读写事务 | 签到记录+成长值流水需事务保证 |
| 等级调整 | 读写事务 | 等级变更+权益刷新+通知需事务保证 |
| 月度配额重置 | 无方法级事务 | 分批处理，每批500用户，单条独立处理 |

## 4. 数据访问层设计

### 4.1 查询优化

#### 分页查询

- 使用 MyBatis-Plus 分页插件
- 关联 `sys_user` 表获取用户名/昵称/手机号
- 索引覆盖：`idx_level_code`、`idx_status`、`idx_expire_time`

#### 成长值流水查询

- 复合索引 `idx_user_id_create_time` 优化用户维度分页
- 按时间倒序返回

### 4.2 缓存策略

| 缓存对象 | 缓存 Key | 过期时间 | 更新策略 |
|---------|---------|---------|---------|
| 会员等级 | member:level:{userId} | 30 分钟 | 等级变更时删除 |
| 会员档案 | member:profile:{userId} | 10 分钟 | 等级/成长值/状态变更时删除 |
| 权益配置（单等级） | member:benefit:{levelCode} | 60 分钟 | 配置修改时删除 |
| 权益配置（全量） | member:benefit:all | 60 分钟 | 配置修改时删除 |
| 当月配额 | member:quota:{userId}:{quotaType} | 月底失效 | 扣减时 DECR，月初重置 |
| 签到状态 | member:signin:{userId}:{date} | 25 小时 | 签到时写入 |

> **权益配置缓存失效**：修改权益配置（`updateBenefit`）后需同时删除 `member:benefit:{levelCode}` 和 `member:benefit:all` 两个 Key，确保后续请求读取最新配置。

### 4.3 Redis 原子操作

| 场景 | 命令 | 说明 |
|------|------|------|
| 次数扣减 | DECR | 原子扣减，防止并发超扣 |
| 分布式锁 | SETNX | 等级调整、月度重置加锁 |

## 5. 定时任务设计

| 任务名 | 执行时机 | 功能 |
|--------|---------|------|
| monthlyQuotaResetTask | 每月1日 00:00 | 月度配额重置 |
| memberExpireTask | 每日 02:00 | 套餐到期检查与降级 |
| expireReminderTask | 每日 09:00 | 到期前7/3/1天预警通知 |

### 5.1 memberExpireTask 会员过期降级

三端均已实现，CRON 为每日凌晨 2 点。扫描 `expire_time < NOW() AND level_source != 'growth'` 的会员，按当前成长值重新计算目标等级，置 level_source='growth'、清空 expire_time、刷新月度配额、删除 Redis 缓存，等级变化时推送降级通知。

### 5.2 expireReminderTask 会员到期预警

三端均已实现，CRON 为每日 09:00。扫描 expire_time 在未来 7/3/1 天窗口内且 level_source != 'growth' 的会员，通过消息模板推送提醒。使用 bizModule=member 和 bizId=expire_reminder_{days}d:{userId}:{today} 实现幂等控制。

## 7. 安全设计

### 6.1 防护机制

| 防护项 | 实现方式 |
|--------|---------|
| 防重复提交 | 自定义注解 + Redis 分布式锁，锁定时间 3 秒 |
| 签到防刷 | `(user_id, sign_date)` 唯一索引 |
| 成长值防刷 | 行为频率限制（签到每日1次、评价每日5次） |
| 操作审计 | 所有后台调整记录操作人、时间、原因 |

### 6.2 数据一致性

| 场景 | 一致性保证 |
|------|-----------|
| 成长值变更与等级变更 | 同一事务 |
| 配额扣减 Redis 与 DB | Redis 原子扣减后异步落库，失败时补偿 |
| 月度重置失败 | 分批重试，失败告警 |
