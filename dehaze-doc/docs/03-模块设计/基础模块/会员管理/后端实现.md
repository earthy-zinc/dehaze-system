# 会员管理模块 - 后端实现设计

## 1. 文档概述

本文档描述会员管理模块的后端实现方案。本模块定位为商业化体系的**身份与权益中枢**：不定义商品、不承接交易——会员卡商品由套餐管理承接、交易与支付由订单管理承接（支付成功回调触发本模块履约）、AI 限额与赠送积分联动 AI 计费；权益表达采用"后台精细配置、前端按服务类目合并展示"。

- **API 契约**：[API接口.md](./API接口.md)
- **需求规格**：[需求规格.md](./需求规格.md)
- **数据库设计**：[02-系统架构/03-数据库设计.md](../../../02-系统架构/03-数据库设计.md) §4.5

## 2. 架构与模块边界

### 2.1 模块边界

| 职责边界 | 说明 |
|---------|------|
| 本模块负责 | 会员等级、多服务权益配置与校验依据、成长值、生命周期管理、权益前端合并表达、试用引导与状态展示 |
| 套餐管理承接 | 会员卡/积分卡商品定义、定价、营销（体验券 / 新用户专享） |
| 订单管理承接 | 商品交易；支付成功 / 退款成功回调触发本模块履约与成长值变动 |
| AI 计费承接 | AI 积分计量与余额账户、赠送积分到账（source=vip_gift/trial）、AI 限额的读取与执行 |

### 2.2 跨模块协作

| 协同模块 | 协作内容 | 触发方式 |
|---------|---------|---------|
| 订单管理 | 会员卡支付成功：等级变更、权益生效（含 benefit_overrides）、成长值累积（consume） | 同事务调用（completePayment 内） |
| 订单管理 | 积分卡支付成功：仅累积成长值（consume），不改等级与权益 | 同事务调用（completePayment 内） |
| 订单管理 | 退款成功：成长值按退款折算比例扣减（refund_deduct，扣减值=该单消费累积成长值×未使用比例）、会员卡覆盖权益失效回退 | 退款成功同事务调用 |
| AI 计费 | 权益配置提供 AI 限额字段（ai_credits_daily / ai_credits_monthly / multimodal_limit）与 VIP 赠送积分依据（vip_gift_credits）；服务类目聚合查询读取积分余额与今日已用 | 本模块配置，AI 计费读取执行 |
| 套餐管理 | 试用引导读取体验券激活状态、新用户专享可用性 | 同步调用 |
| 图像处理 / 效果对比 | 处理前权益校验，完成后成长值回调（process / evaluate） | 事件 |
| AI 计费 | AI 对话完成成长值激励（ai_consume）：消费 `ai.chat.completed` 事件，每次 AI 对话 +1、每日上限 10（一次对话内的多次 LLM 调用仅计一次） | 事件 |

## 3. 服务层设计

### 3.1 服务划分

本模块由 `MemberService`（会员信息、等级、成长值、签到、配额、权益概览、试用引导、履约回调）与 `MemberBenefitService`（权益配置）两个服务构成。

### 3.2 MemberService

| 方法 | 职责 |
|------|------|
| getProfile | 当前用户会员基础信息（等级、等级来源、成长值、到期时间、状态、进度） |
| getBenefitSummary | 权益概览：按服务类目聚合（图像处理 / 评估剩余次数、AI 积分余额与额度），含类目明细 |
| getTrialStatus | 试用引导状态：体验券激活状态与到期时间、AI 试用积分余额、新用户专享可用性 |
| getPage / getDetail | 后台会员分页列表 / 会员详情 |
| adjustLevel / adjustGrowth / updateStatus | 后台等级调整 / 成长值调整 / 冻结解冻 |
| getGrowthLogs / signIn / getSignInCalendar | 成长值流水 / 每日签到 / 签到日历 |
| checkAndDeductQuota | 权益校验与扣减（供图像处理 / 效果对比等业务模块接入） |
| onOrderPaid / onOrderRefunded | 支付成功 / 退款成功事件处理（履约与成长值） |
| resetMonthlyQuota / processExpiredMembers / sendExpireReminders | 定时任务：月度配额重置 / 到期降级 / 到期预警 |

### 3.3 MemberBenefitService

| 方法 | 职责 |
|------|------|
| listVOs | 权益配置列表（含 AI 限额三字段与 VIP 赠送积分） |
| updateByLevelCode | 修改单等级权益配置，变更后失效缓存并记录操作日志 |

### 3.4 关键数据结构

| 对象 | 字段要点 | 说明 |
|------|---------|------|
| MemberProfileVO | 等级、等级来源、成长值、距下一等级差值、进度百分比、到期时间、状态 | 基础信息；权益配额由权益概览接口提供 |
| BenefitSummaryVO | 图像处理类目（合并剩余 + 各任务明细）、评估类目（剩余）、AI 类目（积分余额、今日已用、日/月限额、消费明细） | 服务类目聚合查询结果 |
| TrialStatusVO | 体验券（激活状态 / 到期时间）、AI 试用积分余额、新用户专享可用性 | 试用引导状态 |

## 4. 核心业务流程

### 4.1 会员卡履约（订单支付回调触发）

订单支付成功（completePayment 事务内）由会员模块同事务处理：

1. **等级与有效期**：按商品关联等级升级（`level_source=purchase`），有效期在原到期时间上叠加（续费叠加，上限 3 年）
2. **权益生效**：已购会员卡的用户，各服务额度取 `benefit_overrides` 覆盖值与等级权益的**较高值**，覆盖项即时生效，未覆盖项取等级权益
3. **配额刷新**：按生效权益同步刷新全部任务类型配额与 AI 限额字段
4. **成长值累积**：按订单实付金额 1:1 写入 `consume`（1 元 = 100 成长值）
5. **通知**：支付成功站内信

> 积分卡支付成功仅累积成长值（consume），不改变会员等级与权益；积分到账由 AI 计费承接（source=recharge）。

### 4.2 成长值变动与等级检查

成长值变动采用**原子自增 + 乐观锁**保证并发安全：签到、处理、评估、消费、AI 对话、退款等多回调并发触发时，CAS 失败重试读取最新余额重算，避免丢失更新；扣减后余额不低于 0（低于 0 按 0 处理，实际变动值按差额计算）。每次变动写入流水（change_type：sign_in / sign_in_bonus / rating / process / evaluate / consume / ai_consume / refund_deduct / admin_adjust），并触发等级检查：

- **自动升级不限来源**：成长值达到更高等级阈值即升级，`level_source` 保持不变
- **自动降级受来源与有效期约束**：仅 `level_source=growth` 或会员卡已到期的会员在成长值低于等级下限时降级

购买商品成长值覆盖会员卡与积分卡两类商品，均按实付金额 1:1 累积。AI 使用激励（`ai_consume`）采用**行为激励**：消费 AI 计费发布的 `ai.chat.completed` 事件，每次 AI 对话完成 +1，**每日上限 10 次**（Redis 计数，与 process 对称；一次对话内的多步推理/子智能体多次 LLM 调用仅发布一次事件）；上限为三端代码常量，不参与退款扣减（非订单消费所得）。

### 4.3 权益前端合并表达（服务类目聚合）

后台按 8 类任务配额 + AI 限额 + 功能开关精细配置不变；用户端权益概览按服务类目合并展示，聚合规则：

| 服务类目 | 聚合规则 | 明细 |
|---------|---------|------|
| 图像处理 | 7 类图像任务（dehaze / derain / desnow / lowlight / super_resolution / denoise / inpaint）各自剩余取**最低值** | 各任务类型 quota / used / 剩余 |
| 评估 | 评估任务剩余 = quota - used | — |
| AI | 积分余额（AI 计费余额账户）、今日已用、日/月限额 | 日/月限额、消费明细 |

实现要点：

- 图像处理 / 评估类目由本模块从会员月度配额字段计算（含会员卡覆盖后的合并额度）
- AI 类目数据由 AI 计费模块提供（余额账户、今日已用），限额字段取自权益配置
- 聚合结果整体缓存（短 TTL），明细随聚合结果一并返回，前端展开展示

### 4.4 试用转化漏斗（F-MM-015）

本模块提供统一试用入口与状态展示，载体逻辑由对应模块承接：

| 试用载体 | 状态数据来源 | 本模块动作 |
|---------|-------------|-----------|
| 体验券 | 套餐管理（体验券激活状态 / 到期时间） | 查询并展示 |
| AI 试用积分 | AI 计费（trial 来源积分余额） | 查询并展示 |
| 新用户专享 | 套餐管理促销（无历史付费订单校验） | 查询可用性并展示 |

试用到期后展示会员卡权益对比与购买入口，衔接付费转化。本模块不重复实现体验券激活 / 收回、试用积分赠送、新用户校验等载体逻辑。

### 4.5 VIP 赠送积分联动

- 权益配置提供 `vip_gift_credits`（各等级差异化，0 表示该等级不赠送）
- 每月发放至 AI 积分余额账户（AI 计费承接到账，source=vip_gift）
- **月额度语义**：赠送积分当月有效，月末清零未用部分，次月重新发放
- AI 限额 / 余额不足时，提示升级会员或加购积分卡（引导由 AI 计费发起，本模块配合权益对比展示）

### 4.6 权益校验与扣减

查询会员等级（缓存优先）→ 检查会员状态（冻结抛 A0511）→ 按请求 taskType 取生效配额（已购会员卡取覆盖值与等级权益较高值）→ 校验当月已用 < 配额 → Redis 原子扣减 → 异步落库。DB 路径使用原子行级条件更新（`used < quota`）防并发超扣，配额回补带 `used > 0` 下限，重复回补不产生负数。

会员记录初始化仅复活软删记录（deleted=1 时重建为 level_0 并清空月度配额、保留累计消费），活跃会员记录不做降级或清零。

### 4.7 月度配额重置（定时任务）

每日 00:00 扫描到达个人重置时点的会员（默认当月 1 日，冻结顺延的会员为当月 1 日 + 顺延天数）：先将上月各任务类型使用情况归档至历史表，再按当前等级（含会员卡覆盖）刷新配额字段并清零已用。幂等由 `quota_reset_month` 条件保证，分批处理（每批 500），单条失败不影响其他会员，处理后失效配额缓存。重置后不推送通知。

### 4.8 冻结 / 解冻

- 冻结：`status=0`，记录冻结原因与时间；冻结期间权益校验拦截（无法使用图像处理、评估、AI 等全部权益）
- 解冻：`status=1`，保留冻结历史便于追溯；会员卡到期时间顺延冻结天数，当月配额重置时点按冻结天数顺延（配额顺延补回）

### 4.9 升级 / 降级 / 保级

- 升级：成长值达标或购买会员卡，立即生效；`level_source` 仅记录来源，不影响自动升级
- 降级：每日 02:00 定时任务扫描到期会员（`expire_time < NOW()` 且来源非 growth），按成长值重算等级，置 `level_source=growth`、清空 `expire_time`、刷新配额；退款扣减成长值触发的降级在回调事务内即时执行
- 保级：会员卡到期但成长值达标，保持等级，来源切换为 growth，到期期间不出现权益空窗
- 到期预警：到期前 7 / 3 / 1 天站内信提醒，3 天提醒含降级后权益对比（降级权益对比由等级权益配置计算）

## 5. 事务管理

| 操作 | 事务要求 |
|------|---------|
| 支付成功履约（等级 / 权益 / 成长值） | 读写事务，同事务完成 |
| 成长值变动 + 流水 + 等级检查 | 读写事务 |
| 签到记录 + 成长值流水 | 读写事务 |
| 后台等级 / 成长值 / 状态调整 | 读写事务 + 审计日志 |
| 月度配额重置 | 无方法级事务，分批独立处理，单条失败不影响其他 |

## 6. 缓存策略

| 缓存对象 | 缓存 Key | TTL | 更新策略 |
|---------|---------|-----|---------|
| 会员档案 | member:profile:{userId} | 10 分钟 | 等级 / 成长值 / 状态变更时删除 |
| 会员等级 | member:level:{userId} | 10 分钟 | 等级变更时删除 |
| 权益配置 | member:benefit:{levelCode} / member:benefit:all | 30-60 分钟 | 配置修改时同时删除两个 Key |
| 当月配额 | member:quota:{userId}:{taskType} | 25 小时 | 扣减时 DECR，重置时删除 |
| 权益概览聚合 | member:benefit-summary:{userId} | 5 分钟 | 等级变更 / 权益配置修改时删除 |

> 成长值不缓存（实时查询数据库，确保数值准确）；签到记录落库由唯一索引防重，不设缓存。

## 7. 定时任务设计

| 任务 | 执行时机 | 功能 |
|------|---------|------|
| monthlyQuotaResetTask | 每日 00:00 | 月度配额重置（按个人重置时点） |
| memberExpireTask | 每日 02:00 | 到期检查与降级 |
| expireReminderTask | 每日 09:00 | 到期前 7 / 3 / 1 天预警 |

> VIP 赠送积分发放与月末清零由 AI 计费模块定时任务承接，本模块仅提供等级与赠送额度依据。

## 8. 三后端一致性约束

Java 权威，Go/Python 对齐：

- `ai_credits_daily` / `ai_credits_monthly` / `multimodal_limit` 三个字段在三端 model/VO 中补全（字段名、类型、含义完全一致），权益配置接口必须返回 AI 限额，数据初始化脚本包含默认值
- 权益校验与配额扣减三端均使用 Redis 原子操作，DB 路径条件更新防超扣
- 成长值变动（原子自增 + 乐观锁）、等级检查规则、change_type 枚举（含 ai_consume）、AI 使用激励行为口径（每次 AI 对话 +1、每日上限 10）三端一致
- 服务类目聚合规则（图像处理取最低剩余）、试用引导状态字段三端一致
- 月度配额重置幂等（quota_reset_month）、冻结顺延补回逻辑三端一致
