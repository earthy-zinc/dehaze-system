### 3.2 核心业务逻辑

#### 等级自动升降级

```
成长值变更 / 套餐支付成功
    ↓
查询 sys_member_benefit 取各等级 growth_min/growth_max
    ↓
比较成长值与新等级区间
    ├─ 成长值 ≥ 当前等级上限 → 升级
    └─ 成长值 < 当前等级下限 → 降级
    ↓
更新 sys_member.level_code
    ↓
同步刷新权益配置（取套餐权益与等级权益较高值）
    ↓
推送升级/降级通知
```

#### 成长值变动逻辑

1. **参数校验**：变动值不为0，扣减后余额 ≥ 0
2. **更新余额**：`UPDATE sys_member SET growth_value = growth_value + ? WHERE user_id = ? AND growth_value + ? >= 0`
3. **写入流水**：插入 `sys_member_growth_log`，记录 balance
4. **触发等级检查**：调用 `checkAndAdjustLevel`
5. **通知**：等级变更时推送站内信

#### 签到逻辑

1. **唯一性校验**：`(user_id, sign_date)` 唯一索引阻止重复签到
2. **连续天数计算**：查询昨日是否有签到记录
   - 有 → `continuous_days = 昨日连续天数 + 1`
   - 无 → `continuous_days = 1`
3. **成长值计算**：基础3点 + 连续7天奖励20点
4. **事务写入**：签到记录 + 成长值变动流水（同一事务）
5. **触发成长值检查**：调用 `checkAndAdjustLevel`

#### 权益校验与扣减

```
查询用户会员等级（Redis 缓存优先）
    ↓
检查会员状态（status=1 正常）
    ↓
查询当月已用次数 < 配额上限
    ├─ 是 → Redis DECR 原子扣减 → 异步落库（更新 sys_member.monthly_*_used）
    └─ 否 → 返回次数不足，引导购买VIP
```

#### 月度配额重置（定时任务）

1. **触发时机**：每月1日 00:00
2. **归档上月数据**：将 `sys_member` 当月字段写入 `sys_member_quota`
3. **重置当月字段**：根据当前等级读取 `sys_member_benefit` 配额，更新 `sys_member`
4. **推送通知**：站内信告知用户次数已刷新
5. **失败重试**：失败记录告警，自动重试

### 3.3 事务管理

| 操作类型 | 事务级别 | 说明 |
|---------|---------|------|
| 查询操作 | 只读事务 | 优化数据库性能 |
| 成长值变动 | 读写事务 | 余额更新+流水写入+等级检查需事务保证 |
| 签到 | 读写事务 | 签到记录+成长值流水需事务保证 |
| 等级调整 | 读写事务 | 等级变更+权益刷新+通知需事务保证 |
| 月度配额重置 | 批量事务 | 分批处理，每批1000用户 |

## 4. 数据访问层设计

### 4.1 查询优化

#### 分页查询

- 使用 MyBatis-Plus 分页插件
- 关联 `sys_user` 表获取用户名/昵称/手机号
- 索引覆盖：`idx_level_code`、`idx_status`、`idx_expire_time`

#### 成长值流水查询

- 复合索引 `idx_user_id_create_time` 优化用户维度分页
- 按时间倒序返回

### 4.2 缓存策略

| 缓存对象 | 缓存 Key | 过期时间 | 更新策略 |
|---------|---------|---------|---------|
| 会员等级 | member:level:{userId} | 30 分钟 | 等级变更时删除 |
| 权益配置 | member:benefit:{levelCode} | 60 分钟 | 配置修改时删除 |
| 当月配额 | member:quota:{userId} | 月底失效 | 扣减时 DECR，月初重置 |
| 签到状态 | member:signin:{userId}:{date} | 25 小时 | 签到时写入 |

### 4.3 Redis 原子操作

| 场景 | 命令 | 说明 |
|------|------|------|
| 次数扣减 | DECR | 原子扣减，防止并发超扣 |
| 分布式锁 | SETNX | 等级调整、月度重置加锁 |

## 6. 导入导出设计

会员模块的导入导出由通用导入导出框架统一调度，模块侧实现 `MemberExportHandler` 和 `MemberImportHandler`。

### 6.1 MemberExportHandler

实现 `ExportHandler` 接口，`getModule()` 返回 `"member"`。

| 方法 | 说明 |
|------|------|
| estimateCount | 根据查询条件估算会员数量 |
| export | 分批查询会员数据（每批 1000 条），关联用户信息 |
| getFieldConfigs | 返回导出字段配置 |

**导出字段配置**：username、nickname、levelName、growthValue、monthlyUsed、expireTime、status、becomeMemberTime。

### 6.2 MemberImportHandler

| 方法 | 说明 |
|------|------|
| getFieldConfigs | 返回导入字段配置（含必填、正则） |
| importBatch | 批量导入会员等级调整记录（不直接创建会员，仅触发等级变更） |

## 7. 安全设计

### 7.1 防护机制

| 防护项 | 实现方式 |
|--------|---------|
| 防重复提交 | 自定义注解 + Redis 分布式锁，锁定时间 3 秒 |
| 签到防刷 | `(user_id, sign_date)` 唯一索引 |
| 成长值防刷 | 行为频率限制（签到每日1次、评价每日5次） |
| 操作审计 | 所有后台调整记录操作人、时间、原因 |

### 7.2 数据一致性

| 场景 | 一致性保证 |
|------|-----------|
| 成长值变更与等级变更 | 同一事务 |
| 配额扣减 Redis 与 DB | Redis 原子扣减后异步落库，失败时补偿 |
| 月度重置失败 | 分批重试，失败告警 |
