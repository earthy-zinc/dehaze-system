### 3.2 核心业务逻辑

#### 等级自动升降级

成长值变更（签到/评价/图像处理/评估/购买套餐/退款扣减等行为触发）→ 查询权益配置表取各等级 growth_min/growth_max → 计算成长值对应的目标等级：

- **自动升级（不限来源）**：目标等级高于当前等级时，更新 `sys_member.level_code`（`level_source` 保持不变，保留原 `expire_time`），同步刷新各任务类型配额，推送升级通知（站内信）
- **自动降级（受来源与有效期约束）**：目标等级低于当前等级时，仅 `level_source == "growth"` 或套餐已到期（`expire_time < NOW()`）的会员触发降级；`level_source == "purchase"`/`"admin"` 且未到期的不降级（套餐期间享受套餐等级）

**套餐到期降级**：定时任务扫描 `expire_time < NOW() AND level_source != 'growth'` 的会员，按当前成长值重算目标等级，置 `level_source='growth'`、清空 `expire_time`、刷新配额、删除缓存，等级变化时推送降级通知。

> **说明**：`level_source` 仅记录来源，不影响自动升级。已购买套餐的用户，各任务类型配额取套餐 `benefit_overrides` 覆盖值与等级权益的较高值（见需求规格 §3.3）。

#### 成长值变动逻辑

1. **参数校验**：变动值不为0（Python 端校验），扣减后余额 >= 0
2. **更新余额**：采用 `growth_value = growth_value + Δ` 原子自增配合 `version` 字段乐观锁 CAS；签到/处理/评估/消费/退款等多回调并发触发时，CAS 失败重试读取最新余额重算，避免丢失更新。扣减后余额 <0 时按 0 处理，实际变动值按差额计算
3. **写入流水**：插入 sys_member_growth_log，记录实际变动值与变动后余额（`change_type` 取 `process`/`evaluate`/`consume`/`refund_deduct` 等）
4. **触发等级检查**：按新成长值计算目标等级——升级不限来源；降级仅 `growth` 来源或套餐已到期触发
5. **通知**：等级变更时推送站内信

> **付费链路接入**：订单支付成功、图像处理/评估完成、退款成功等跨模块回调统一通过 MQ 事件触发（支付/处理/评估/退款模块发布事件，会员模块消费）。订单支付成功写入 `consume`（按消费金额 1:1，1 元 = 100 成长值），图像处理/评估完成写入 `process`/`evaluate`（+1/次），退款成功按未使用比例等量扣减 `refund_deduct`。三后端契约一致。

#### 等级调整（管理员）

1. **参数校验**：调整原因必填
2. **更新等级**：置 `level_code` 为目标等级，`level_source = "admin"`，始终更新 `expire_time`（传入则设置，传 null 则清空）
3. **刷新配额**：按新等级 `sys_member_benefit` 同步刷新全部任务类型配额（`monthly_{taskType}_quota`，覆盖 7 类图像处理 + 评估）
4. **首次开通**：`become_member_time` 为空时写入当前时间
5. **缓存失效**：删除等级/配额相关缓存键（`member:level`、`member:quota:*`，Go/Python 端同时清理 `member:profile`）
6. **审计日志**：记录操作人、原等级、新等级、原因

#### 签到逻辑

1. **唯一性校验**：`(user_id, sign_date)` 唯一索引阻止重复签到，预检查命中或并发触发唯一约束冲突均转抛 `SIGN_IN_ALREADY`（Java 显式捕获 `DuplicateKeyException`）
2. **连续天数计算**：查询昨日是否有签到记录
   - 有 → `continuous_days = 昨日连续天数 + 1`
   - 无 → `continuous_days = 1`
3. **成长值计算**：基础3点 + 连续7天奖励20点；返回 SignInVO 中 `growthValue` 为基础值（3），`bonusGrowth` 为连续签到奖励值（三端统一）
4. **事务写入**：签到记录 + 成长值变动流水（同一事务）
5. **触发成长值检查**：调用 `checkAndAdjustLevel`（自动升级不限来源；降级仅 `growth` 来源或套餐已到期触发，见 §3.2 等级自动升降级）

#### 权益校验与扣减

查询用户会员等级(Redis缓存优先) → 检查会员状态(status != 1 时抛 MEMBER_FROZEN) → 按请求 `taskType` 查询对应配额（已购套餐取 `benefit_overrides` 覆盖值与等级权益的较高值）→ 检查当月该任务类型已用次数 < 配额上限 → Redis DECR 原子扣减 → 异步落库

**冻结状态校验**：deductQuota/checkAndDeductQuota 方法在查询会员后立即校验 member.status != 1，冻结会员直接抛 MEMBER_FROZEN，不进入配额扣减流程（冻结期间无法使用任何权益，见需求规格 §4.5.2）。

#### 月度配额重置（定时任务）

1. **触发时机**：每日 00:00 扫描，对到达个人重置时点的会员执行重置（默认当月1日；冻结顺延的会员为当月1日 + 顺延天数）
2. **幂等保护**：仅扫描 `quota_reset_month IS NULL OR quota_reset_month != currentMonth` 的会员，且当前日期 ≥ 当月1日 + 该会员顺延天数时才执行；重复执行不会重复重置
3. **分批处理**：每批500条，采用"始终查询第1页"策略（已重置的会员被条件排除，无需翻页），避免一次性加载全部会员到内存
4. **权益预加载**：批量查询 `sys_member_benefit` 构建 Map 缓存，循环内从 Map 取值，避免 N+1 查询
5. **归档历史数据**：仅当 `quota_reset_month != NULL` 时，将 `sys_member` 当月字段写入 `sys_member_quota`，归档月份使用会员原有的 `quota_reset_month`
6. **重置当月字段**：根据当前等级读取 `sys_member_benefit` 配额，更新 `sys_member` 的 `monthly_*_quota`、`monthly_*_used=0`、`quota_reset_month=currentMonth`，清零顺延天数
7. **缓存失效**：每批处理完后删除全部任务类型的配额缓存（`member:quota:{userId}:{taskType}`，覆盖 7 类图像处理 + 评估）及 `member:profile:{userId}`
8. **失败容错**：单条失败记录日志并跳过，不影响其他会员；无方法级事务（每条记录独立处理）

#### 会员冻结/解冻

1. **冻结**（`status=0`）：写入 `frozen_reason`、`frozen_time`，原因必填；冻结期间无法使用任何权益
2. **解冻**（`status=1`）：仅设置 `status=1`，**不清空** `frozen_reason`、`frozen_time`，保留冻结历史便于追溯；**配额顺延补回**——套餐 `expire_time` 顺延冻结天数，冻结天数累加到该会员配额重置的顺延天数，下次月度重置时点 = 当月1日 + 顺延天数（重置后清零，见月度配额重置）
3. **缓存失效**：删除 `member:profile:{userId}`、`member:level:{userId}`
4. **审计日志**：记录操作人、原状态、新状态、原因

### 3.3 事务管理

| 操作类型 | 事务级别 | 说明 |
|---------|---------|------|
| 查询操作 | 只读事务 | 优化数据库性能 |
| 成长值变动 | 读写事务 | 余额更新（乐观锁 CAS）+流水写入+等级检查需事务保证 |
| 签到 | 读写事务 | 签到记录+成长值流水需事务保证 |
| 等级调整 | 读写事务 | 等级变更+权益刷新+通知需事务保证 |
| 月度配额重置 | 无方法级事务 | 分批处理，每批500用户，单条独立处理 |

### 4.2 缓存策略

| 缓存对象 | 缓存 Key | 过期时间 | 更新策略 |
|---------|---------|---------|---------|
| 会员档案 | member:profile:{userId} | 10 分钟（Go 端写入） | 等级/成长值/状态变更时删除 |
| 会员等级 | member:level:{userId} | 10 分钟（Go 端写入） | 等级变更时删除 |
| 权益配置（单等级） | member:benefit:{levelCode} | Java 60 分钟 / Go 30 分钟 | 配置修改时删除 |
| 权益配置（全量） | member:benefit:all | Java 60 分钟 / Go 30 分钟 | 配置修改时删除 |
| 当月配额 | member:quota:{userId}:{taskType} | 25 小时（三端统一，略大于每日重置周期） | 扣减时 DECR，重置时删除 |

> **说明**：
> - `member:profile`/`member:level` 由 Go 端写入缓存，Java/Python 端仅执行删除（失效）操作
> - 签到无独立缓存（签到记录落库，唯一索引防重）
> - 成长值不缓存（实时查询数据库，确保数值准确）
> - **权益配置缓存失效**：修改权益配置后需同时删除 `member:benefit:{levelCode}` 和 `member:benefit:all` 两个 Key，确保后续请求读取最新配置

### 4.3 Redis 原子操作

| 场景 | 实现方式 | 说明 |
|------|---------|------|
| 次数扣减 | Java DECR / Python Lua 脚本（get+decr 原子）/ Go DECR | 原子扣减，防止并发超扣 |
| 配额扣减补偿 | 扣减结果 <0 时回滚（Java INCR 补偿 / Lua 返回 -1 不扣减） | 防止超扣后负数残留 |
| 分布式锁 | Go 端月度重置任务 `job:member:quota:reset:lock`（10 分钟 TTL） | 仅 Go 端月度重置加锁，防多实例并发；Java/Python 靠 `quota_reset_month` 条件幂等 |

## 5. 定时任务设计

| 任务名 | 执行时机 | 功能 |
|--------|---------|------|
| monthlyQuotaResetTask | 每日 00:00 | 月度配额重置（按会员个人重置时点） |
| memberExpireTask | 每日 02:00 | 套餐到期检查与降级 |
| expireReminderTask | 每日 09:00 | 到期前7/3/1天预警通知 |

### 5.1 memberExpireTask 会员过期降级

三端均已实现，CRON 为每日凌晨 2 点。扫描 `expire_time < NOW() AND level_source != 'growth'` 的会员，按当前成长值重新计算目标等级，置 level_source='growth'、清空 expire_time、刷新月度配额、删除 Redis 缓存，等级变化时推送降级通知。

### 5.2 expireReminderTask 会员到期预警

三端均已实现，CRON 为每日 09:00。扫描 expire_time 在未来 7/3/1 天窗口内且 level_source != 'growth' 的会员，通过消息模板推送提醒。使用 bizModule=member 和 bizId=expire_reminder_{days}d:{userId}:{today} 实现幂等控制。

## 6. 安全设计

### 6.1 防护机制

| 防护项 | 实现方式 |
|--------|---------|
| 防重复提交 | 自定义注解 + Redis 分布式锁，锁定时间 3 秒 |
| 签到防刷 | `(user_id, sign_date)` 唯一索引 |
| 成长值防刷 | 行为频率限制（签到每日1次、评价每日5次） |
| 操作审计 | 所有后台调整记录操作人、时间、原因 |

### 6.2 数据一致性

| 场景 | 一致性保证 |
|------|-----------|
| 成长值变更与等级变更 | 同一事务 |
| 配额扣减 Redis 与 DB | Redis 原子扣减后异步落库，失败时补偿 |
| 月度重置失败 | 分批重试，失败告警 |

### 6.3 成长值与等级安全

| 防护项 | 实现方式 |
|--------|---------|
| 成长值并发安全 | 原子自增 `growth_value = growth_value + Δ` 配合 version 字段乐观锁 CAS；签到/处理/评估/消费/退款等多回调并发触发时，CAS 失败重试读取最新余额重算，避免丢失更新 |
| 等级变更通知 | 等级变化时推送站内信（升级/降级模板）；跨模块回调通过 MQ 事件触发（支付/处理/评估/退款模块发布事件，会员模块消费） |
| 权益即时刷新 | 等级变更后同步刷新各任务类型配额（monthly_{taskType}_quota）；删除等级/配额相关缓存键 |
| 权益时效性校验 | 权益校验时检查会员状态（冻结抛 MEMBER_FROZEN）；套餐到期后按成长值重算等级（定时任务每日 02:00），到期期间不出现权益空窗 |
| 数据隔离 | 用户端 getProfile/getGrowthLogs 仅返回当前登录用户的会员信息；后台管理接口需管理员权限 |

## 7. 日志设计

### 7.1 操作日志记录
