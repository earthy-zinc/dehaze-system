# 字典管理模块 - 后端实现设计

## 1. 文档概述

### 1.1 文档目的

本文档描述字典管理模块的后端实现方案，包括数据传输对象、核心业务逻辑、数据访问策略等实现要点。字典管理模块采用两级管理结构（字典类型+字典数据），为系统提供统一的基础数据管理能力。

## 3. 核心业务逻辑设计

### 3.1 关键流程

#### 字典类型新增流程

```text
1. 校验表单数据（名称、编码非空，编码格式）
2. 检查编码唯一性（查询 sys_dict_type 表）
3. 保存字典类型记录
4. 返回新增成功
```

#### 字典类型删除流程（逻辑删除）

```text
1. 解析 ID 列表，校验系统预置字典类型不可删除
2. 根据 force 参数决定删除策略：
   - force=false（默认）：检查每个类型是否存在关联字典数据，如存在数据，抛出业务异常
   - force=true：在同一事务内级联逻辑删除关联的字典数据（deleted=1）
3. 逻辑删除字典类型记录（UPDATE deleted=1，非物理 DELETE），与级联删除在同一事务内提交
4. 事务提交后（afterCommit）：删除对应缓存并发布 Redis Pub/Sub 通知三后端失效
5. 返回删除成功
```

#### 字典数据新增流程

```text
1. 校验表单数据（标签、键值、类型编码非空）
2. 检查类型编码有效性（查询 sys_dict_type 表）
3. 检查键值唯一性（同类型下，查询 sys_dict 表）
4. 保存字典数据记录
5. 清除相关缓存（如启用缓存）
6. 返回新增成功
```

#### 字典下拉选项查询流程

```text
1. 校验类型编码非空
2. 查询缓存（如启用缓存）
   - 缓存命中，直接返回
3. 查询数据库：
   - 条件：typeCode = ?
   - 排序：sort ASC, create_time DESC
4. 构建 OptionVO 对象列表
5. 写入缓存（如启用缓存）
6. 返回选项列表
```

### 3.2 核心业务规则

| 规则类型 | 规则说明 |
|---------|---------|
| **编码唯一性** | 字典类型编码在系统中全局唯一 |
| **编码不可变** | 字典类型编码（code）创建后不可修改 |
| **键值唯一性** | 字典键值在同一类型下必须唯一 |
| **删除约束** | `force=false`（默认）禁止删除存在关联数据的字典类型；`force=true` 级联逻辑删除关联字典数据 |
| **排序规则** | 字典数据按 sort 字段升序，相同 sort 按创建时间降序 |
| **默认值** | 新增字典类型/数据默认状态为启用，排序默认为 1，默认值标记默认为否 |

### 3.3 事务边界

| 操作类型 | 事务级别 | 说明 |
|---------|---------|------|
| 查询操作 | 只读事务 | 优化数据库性能 |
| 字典类型新增 | 读写事务 | 单表插入 |
| 字典类型更新 | 读写事务 | 单表更新 |
| 字典类型删除 | 读写事务 | force=false 仅校验；force=true 级联逻辑删除类型表+数据表，同一事务内完成 |
| 字典数据新增 | 读写事务 | 单表插入 |
| 字典数据更新 | 读写事务 | 单表更新 |
| 字典数据删除 | 读写事务 | 单表删除 |

> 缓存失效统一在事务提交后（afterCommit）执行，详见 §5.2。

## 5. 缓存设计

### 5.1 缓存对象

| 缓存对象 | 缓存 Key | 数据类型 | TTL | 更新策略 |
|---------|---------|---------|-----|---------|
| 字典数据/下拉选项 | `dict:data:{typeCode}` | List&lt;OptionVO&gt; | 1 小时 | 字典数据增删改、字典类型状态变更/删除时删除 |
| 字典类型 | `dict:type:{code}` | DictType | 1 小时 | 字典类型增删改/状态变更时删除 |

### 5.2 缓存一致性策略

- **主动失效**：字典数据新增、修改、删除时，主动删除对应缓存 Key `dict:data:{typeCode}`
- **类型状态联动失效**：字典类型 status 变更（如禁用）时，联动失效 `dict:data:{typeCode}` 缓存，避免类型禁用后下拉选项命中脏缓存
- **失效时机**：缓存失效统一在数据库事务提交后（afterCommit）执行，避免事务回滚后缓存被误删
- **Redis Pub/Sub 通知**：变更后发布 Redis Pub/Sub 消息（频道 `dict:invalidate`），通知 Java/Go/Python 三后端失效本地与 Redis 缓存，确保三端缓存一致；消息体结构如下

| 字段 | 类型 | 说明 |
|------|------|------|
| typeCode | String | 字典类型编码 |
| op | String | 操作类型：create/update/delete/statusChange |

三后端订阅 `dict:invalidate` 频道，收到消息后按 `typeCode` 失效本地与 Redis 中 `dict:data:{typeCode}` 缓存。

- **多端读缓存**：各端经业务后端读取缓存，缓存未命中时回源数据库并回写缓存
- **加载策略**：缓存不存在时从数据库加载并写入缓存，防穿透（空值缓存 + 布隆/SingleFlight）

### 5.3 缓存注意事项

- 字典类型列表和字典数据列表（分页查询）不缓存，采用实时查询
- 字典下拉选项接口响应时间要求高（&lt;200ms），必须启用缓存，目标缓存命中率 ≥95%、QPS ≥500
- 缓存 Key 命名规范：`dict:data:{typeCode}`

## 6. 安全设计

> **权限矩阵**：详见 [需求规格.md](./需求规格.md) 第 5.1 节

### 6.1 输入校验

| 校验类型 | 校验项 |
|---------|--------|
| **必填校验** | 类型名称、类型编码、字典标签、字典键值、类型编码 |
| **唯一性校验** | 类型编码全局唯一，字典键值同类型下唯一 |
| **格式校验** | 排序字段为正整数 |
| **长度校验** | 名称、编码、备注等字段最大长度限制 |
| **状态校验** | status 字段只能为 0 或 1 |

### 6.2 防护机制

| 防护项 | 实现方式 |
|--------|---------|
| 防重复提交 | 前端防抖 + 后端幂等性校验（根据业务场景可选） |
| SQL 注入防护 | 参数化查询（通用约束） |
| XSS 防护 | 输出编码，输入过滤危险标签（通用约束） |

### 6.3 权限与删除约束

| 安全措施 | 说明 |
|---------|------|
| 管理权限 | 字典类型/数据的增删改需对应权限标识：`sys:dict:type:add/edit/delete`、`sys:dict:data:add/edit/delete`（权限矩阵详见 [需求规格.md](./需求规格.md) §5.1）；下拉选项接口登录即可访问 |
| 缓存一致性 | 字典变更后通过 Redis Pub/Sub（频道 `dict:invalidate`）通知三后端失效缓存（见 §5.2） |
| 删除约束 | `force=false`（默认）禁止删除存在关联数据的字典类型；`force=true` 级联逻辑删除关联数据（见 §3.1） |
| 预置数据保护 | 系统预置字典类型不可删除 |

## 8. 导入导出设计

字典模块的导入导出由通用导入导出框架统一调度，模块侧实现 `DictExportHandler` 和 `DictImportHandler`。通用框架负责文件生成/解析、进度回调、结果上传、任务状态管理。

### 8.1 DictExportHandler

实现 `ExportHandler` 接口，`getModule()` 返回 `"dict"`。

| 方法 | 说明 |
|------|------|
| estimateCount | 根据查询条件估算字典数据量 |
| export | 查询字典类型与字典数据，通过 callback 回写进度 |
| getFieldConfigs | 返回导出字段配置：字典类型编码、字典标签、字典键值、排序、状态 |

### 8.2 DictImportHandler

实现 `ImportHandler` 接口，`getModule()` 返回 `"dict"`。

| 方法 | 说明 |
|------|------|
| getFieldConfigs | 返回导入字段配置（字典类型编码、字典标签必填） |
| importBatch | 批量导入字典：校验字典类型存在性、字典键值唯一性 |
| getTemplateSampleData | 返回模板示例数据 |
