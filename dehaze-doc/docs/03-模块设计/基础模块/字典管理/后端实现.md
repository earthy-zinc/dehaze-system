# 字典管理模块 - 后端实现设计

## 1. 文档概述

### 1.1 文档目的

本文档描述字典管理模块的后端实现方案，包括数据传输对象、核心业务逻辑、数据访问策略等实现要点。字典管理模块采用两级管理结构（字典类型+字典数据），为系统提供统一的基础数据管理能力。

- **API 接口规范**：参见 [API接口.md](./API接口.md)

## 3. 核心业务逻辑设计

### 3.1 关键流程

#### 字典类型新增流程

```text
1. 校验表单数据（名称、编码非空，编码格式）
2. 检查编码唯一性（查询 sys_dict_type 表）
3. 保存字典类型记录
4. 返回新增成功
```

#### 字典类型删除流程

```text
1. 解析 ID 列表
2. 根据 force 参数决定删除策略：
   - force=false（默认）：检查每个类型是否存在关联字典数据，如存在数据，抛出业务异常
   - force=true：级联删除关联的字典数据，并清除对应的下拉选项缓存
3. 批量删除字典类型记录
4. 返回删除成功
```

#### 字典数据新增流程

```text
1. 校验表单数据（标签、键值、类型编码非空）
2. 检查类型编码有效性（查询 sys_dict_type 表）
3. 检查键值唯一性（同类型下，查询 sys_dict 表）
4. 保存字典数据记录
5. 清除相关缓存（如启用缓存）
6. 返回新增成功
```

#### 字典下拉选项查询流程

```text
1. 校验类型编码非空
2. 查询缓存（如启用缓存）
   - 缓存命中，直接返回
3. 查询数据库：
   - 条件：typeCode = ?
   - 排序：sort ASC, create_time DESC
4. 构建 OptionVO 对象列表
5. 写入缓存（如启用缓存）
6. 返回选项列表
```

### 3.2 核心业务规则

| 规则类型 | 规则说明 |
|---------|---------|
| **编码唯一性** | 字典类型编码在系统中全局唯一 |
| **键值唯一性** | 字典键值在同一类型下必须唯一 |
| **删除约束** | 存在关联字典数据的字典类型禁止删除 |
| **排序规则** | 字典数据按 sort 字段升序，相同 sort 按创建时间降序 |
| **默认值** | 新增字典类型/数据默认状态为启用，排序默认为 1，默认值标记默认为否 |

### 3.3 事务边界

| 操作类型 | 事务级别 | 说明 |
|---------|---------|------|
| 查询操作 | 只读事务 | 优化数据库性能 |
| 字典类型新增 | 读写事务 | 单表插入，需事务保护 |
| 字典类型更新 | 读写事务 | 单表更新，需事务保护 |
| 字典类型删除 | 读写事务 | 单表删除+校验，需事务保护 |
| 字典数据新增 | 读写事务 | 单表插入+缓存清除，需事务保护 |
| 字典数据更新 | 读写事务 | 单表更新+缓存清除，需事务保护 |
| 字典数据删除 | 读写事务 | 单表删除+缓存清除，需事务保护 |

## 4. 数据访问与数据依赖

### 4.1 数据依赖

| 依赖表 | 关联字段 | 说明 |
|--------|---------|------|
| sys_dict_type | - | 字典类型主表 |
| sys_dict | type_code → sys_dict_type.code | 字典数据主表，外键关联类型 |

### 4.2 数据约束

| 约束类型 | 约束说明 |
|---------|---------|
| **唯一性约束** | sys_dict_type.code 全局唯一 |
| **唯一性约束** | sys_dict.value 在同一 type_code 下唯一 |
| **状态字段语义** | status: 1=启用, 0=禁用 |
| **默认值字段语义** | defaulted: 1=是, 0=否 |
| **父子关系** | sys_dict 依赖 sys_dict_type，删除父表需检查子表数据 |
| **排序字段** | sort 为正整数，默认 1 |

### 4.3 索引要求

| 索引类型 | 索引字段 | 用途 |
|---------|---------|------|
| 主键索引 | sys_dict_type.id | 记录唯一标识 |
| 唯一索引 | sys_dict_type.code | 保证编码唯一性 |
| 主键索引 | sys_dict.id | 记录唯一标识 |
| 普通索引 | sys_dict.type_code | 优化按类型查询性能 |
| 复合索引 | sys_dict.(type_code, value) | 优化类型下键值唯一性校验 |

### 4.4 查询优化要点

- **分页查询**：使用分页插件，避免全表扫描，只查询需要的字段
- **关联检查**：删除字典类型时（force=false），使用 `SELECT COUNT(*) FROM sys_dict WHERE type_code IN (...)` 批量检查关联数据；force=true 时使用 `DELETE FROM sys_dict WHERE type_code IN (...)` 级联删除
- **下拉选项查询**：使用索引覆盖 `type_code`，排序使用索引

## 5. 缓存设计

### 5.1 缓存对象

| 缓存对象 | 缓存 Key | 数据类型 | TTL | 更新策略 |
|---------|---------|---------|-----|---------|
| 字典下拉选项 | dict:options:{typeCode} | List&lt;OptionVO&gt; | 1 小时 | 字典数据增删改时删除 |

### 5.2 缓存一致性策略

- **失效策略**：主动失效（更新/删除操作时清除缓存）
- **失效范围**：只清除受影响的 typeCode 对应的缓存
- **加载策略**：缓存不存在时从数据库加载并写入缓存

### 5.3 缓存注意事项

- 字典类型列表和字典数据列表不缓存，采用实时查询
- 字典下拉选项接口响应时间要求高（&lt;200ms），必须启用缓存
- 缓存 Key 命名规范：`dict:options:{typeCode}`

## 6. 安全设计

> **权限矩阵**：详见 [需求规格.md](./需求规格.md) 第 5.1 节

### 6.1 输入校验

| 校验类型 | 校验项 |
|---------|--------|
| **必填校验** | 类型名称、类型编码、字典标签、字典键值、类型编码 |
| **唯一性校验** | 类型编码全局唯一，字典键值同类型下唯一 |
| **格式校验** | 排序字段为正整数 |
| **长度校验** | 名称、编码、备注等字段最大长度限制 |
| **状态校验** | status 字段只能为 0 或 1 |

### 6.2 防护机制

| 防护项 | 实现方式 |
|--------|---------|
| 防重复提交 | 前端防抖 + 后端幂等性校验（根据业务场景可选） |
| SQL 注入防护 | 使用参数化查询，ORM 框架自动转义 |
| XSS 防护 | 输出编码，输入过滤危险标签（通用框架处理） |
