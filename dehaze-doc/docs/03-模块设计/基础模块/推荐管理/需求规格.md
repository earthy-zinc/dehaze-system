## 1. 模块概述

### 1.1 模块定位

推荐管理模块根据图像特征分析结果为用户推荐合适的图像处理算法，并提供推荐规则配置与推荐效果度量能力。该模块为算法选择页面提供"算法推荐"面板入口。

> **说明**：早期需求稿描述"根据用户偏好、算法表现等多维信息推荐"并"替代样例图片的静态推荐"，**当前未实现**——实际仅基于图像特征（场景规则匹配）推荐，样例图片仍为静态配置。

### 1.2 核心价值

| 价值维度 | 具体内容 | 状态 |
|---------|---------|------|
| **降低选择门槛** | 用户无需了解算法差异，上传图片即可获得 Top 3 推荐 | ✅ 已实现 |
| **场景匹配** | 基于图像特征（场景类型）匹配预设规则，推荐理由可解释 | ✅ 已实现 |
| **规则可配置** | 管理员可配置场景→算法的映射规则及权重 | ✅ 已实现 |
| **效果可度量** | 推荐采纳率、覆盖率等基础指标统计 | ✅ 已实现（简化） |
| **数据飞轮** | 用户使用、评价、收藏行为反哺推荐引擎 | ⏳ 规划中 |
| **可扩展** | 推荐能力从算法扩展到参数方案、数据集、增强策略 | ⏳ 规划中 |

### 1.3 业务目标

#### 功能目标

- 基于图像特征分析，推荐 Top N 最合适的算法 ✅ 已实现
- 支持推荐理由的可解释性展示 ✅ 已实现
- 推荐结果随用户反馈和使用数据持续优化 ⏳ 规划中（当前反馈仅记录不参与匹配）
- 支持管理员配置推荐规则和权重 ✅ 已实现

#### 性能目标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 图像特征分析 | < 2s | 上传图片到完成特征提取 |
| 推荐结果生成 | < 500ms | 特征分析完成后生成推荐列表 |
| 端到端推荐 | < 3s | 用户上传图片到看到推荐结果 |
| 推荐准确率 | ≥ 70% | 用户采纳推荐算法且满意度 ≥ 4 星的比例 |

> **说明**：当前图像特征分析为**确定性 Mock 实现**（见 §4.1），以上耗时目标为整体推荐链路目标；"推荐准确率"依赖采纳/评分数据，当前未采集。

## 4. 功能需求

### 4.1 图像特征分析 (F-REC-001)

#### 4.1.1 功能描述

对用户选择的图像进行多维特征分析，输出结构化的图像特征向量，作为推荐匹配的输入。**已实现**（当前为确定性 Mock 实现，不执行真实图像分析）。

> **实现说明**：当前 analyze 接口基于 **imageUrl 的 MD5 生成确定性伪随机特征**（同一 URL 多次分析结果一致，不同 URL 结果不同），不下载图片、不调用算法服务提取真实特征。`imageId` 方式**暂不支持**（返回业务异常）。真实图像特征分析待算法服务提供特征提取能力后落地。

#### 4.1.2 分析维度

| 维度 | 说明 | 状态 |
|------|------|:----:|
| 雾霾浓度 | 轻度/中度/重度 + 置信度 | ✅ 已实现（Mock） |
| 场景类型 | 城市/风景/建筑/夜景/逆光/室内 + 置信度 | ✅ 已实现（Mock） |
| 光照条件 | 明亮/正常/偏暗/极暗/逆光 | ✅ 已实现（Mock） |
| 图像复杂度 | 0-1 数值（纹理/边缘/色彩） | ✅ 已实现（Mock） |
| 颜色分布 | 色温 + 饱和度 | ✅ 已实现（Mock） |
| 分辨率 | 标清/高清/超清 | ✅ 已实现（Mock） |
| 噪声水平 | 低/中/高 | ✅ 已实现（Mock） |

> 早期需求稿中的**维度权重（30%/20%/15%/10%/10%/5%/10%）无对应实现**——当前推荐匹配仅使用"场景类型"维度。

#### 4.1.3 分析结果展示

| 字段 | 说明 |
|------|------|
| 雾霾浓度 | 轻度/中度/重度 + 置信度 |
| 场景类型 | 城市/风景/建筑/夜景/逆光/室内 + 置信度 |
| 光照条件 | 明亮/正常/偏暗/极暗/逆光 |
| 复杂度 | 0-1 数值（进度条可视化） |
| 分辨率 | 标清/高清/超清 |
| 噪声水平 | 低/中/高 |
| 颜色分布 | 色温、饱和度（原始数据） |

> 前端折叠面板（"图像特征分析"）展开即展示全部维度，**无用户角色分级展示**（早期需求稿的普通用户/进阶用户分级未实现）。

### 4.2 算法推荐 (F-REC-002)

#### 4.2.1 功能描述

基于图像特征分析结果，匹配推荐规则表，输出 Top 3 推荐算法列表，包含推荐理由和匹配度。**已实现**。

#### 4.2.2 推荐策略（已实现）

推荐算法为**场景规则匹配**：

```
确定场景类型（analysisId 历史 → imageMd5 历史 → 默认 urban）
    ↓
加载启用的规则（sys_recommendation_rule，enabled=1）
    ↓
按场景类型匹配规则（scene_type 相同）→ 按权重降序
    ↓
聚合候选算法（规则 algorithm_ids 并集）→ 过滤已发布算法（status=4）
    ↓
匹配度 = 该算法在匹配规则中的最高权重（归一化 0-100）
    ↓
按匹配度降序 → 截取 Top 3
```

**推荐理由模板**（按场景类型，`算法名 + 理由`）：

| 场景类型 | 推荐理由模板 |
|---------|-------------|
| urban（城市） | 处理速度快，对城市雾霾效果出色 |
| landscape（风景） | 在自然场景下表现稳定，色彩还原度高 |
| building（建筑） | 深度模型，对建筑场景处理能力强 |
| night（夜景） | 低光照增强组合，避免过度暗化 |
| backlight（逆光） | HDR预处理提升暗部细节 |
| indoor（室内） | 室内场景适配，细节保留好 |

> **说明**：
> - 早期需求稿中按"轻度/中度/重度雾霾 + 具体算法倾向（DCP/CAP/AOD-Net 等）"的策略表**不成立**——推荐由管理员配置的规则表驱动，候选算法随规则变化
> - "高噪声图像→去噪预处理"场景**未实现**（噪声维度不参与匹配）
> - 无论是否有匹配结果，均写入 `sys_recommendation` 推荐记录（供反馈关联）

#### 4.2.3 推荐结果展示（已实现）

每个推荐算法展示：

| 字段 | 说明 |
|------|------|
| 算法名称 | 已发布算法的名称 |
| 匹配度 | 百分比（0-100，按规则权重计算） |
| 推荐理由 | 场景模板生成的一句话理由 |
| 算法评分 | **固定 3.5 星**（硬编码，非综合评分） |
| 预期效果 | 预计耗时**固定 5000ms** + 效果描述模板"该算法在xx场景下表现稳定" |
| 操作 | 一键使用（`select` 事件，跳转去雾处理） |

> 早期需求稿中的"查看详情、加入对比"操作**未实现**。

### 4.3 推荐反馈 (F-REC-003)

#### 4.3.1 功能描述

用户对推荐结果进行显式反馈，反馈数据记录用于推荐效果度量。**已实现**（显式反馈）。

#### 4.3.2 反馈方式（已实现）

| 反馈方式 | 说明 | 状态 |
|---------|------|:----:|
| 显式反馈 | "有用"/"无用"按钮，写入 `sys_recommendation.feedback`（1=有用；2=无用） | ✅ 已实现 |
| 采纳推荐 | 用户使用推荐算法完成处理（`adopted_algorithm_id` 字段已建但**未写入**） | ⏳ 规划中 |
| 效果评价 | 处理结果评分（1-5星）关联推荐记录（`sys_rating` 未关联推荐 ID） | ⏳ 规划中 |
| 收藏行为 | 收藏推荐的处理结果作为强正向信号 | ⏳ 规划中 |

> 早期需求稿中"反馈数据用于优化推荐模型"——当前反馈仅记录用于报表统计，**不参与后续推荐匹配**。

### 4.4 推荐规则管理 (F-REC-004)

#### 4.4.1 功能描述

管理员可配置推荐规则（场景→算法映射）及权重。**已实现**（规则 CRUD + 启用/禁用）。

#### 4.4.2 可配置项

| 配置项 | 说明 | 状态 |
|--------|------|:----:|
| 场景匹配规则 | 新增/编辑/禁用场景→算法映射（rule_name/scene_type/algorithm_ids/weight/enabled） | ✅ 已实现 |
| 规则权重 | 0-100 数值，控制匹配优先级 | ✅ 已实现 |
| 特征维度权重 | 调整 7 个分析维度的权重 | ⏳ 规划中（Mock 分析无权重） |
| 算法评分权重 | 用户评分 vs 处理成功率 vs 处理速度 | ⏳ 规划中（评分硬编码 3.5） |
| 推荐数量 Top N | 默认 3（TOP_N 硬编码常量） | ⏳ 规划中 |
| 冷启动策略 | 新上线算法的推荐曝光策略 | ⏳ 规划中 |

**规则管理细节**：
- 删除操作实际为**禁用**（`enabled=false`，规则保留可追溯）
- 规则变更后刷新内存缓存（Java 端 CopyOnWriteArrayList，写时复制；Python 端每次实时查询启用规则）
- 权重校验：0-100，超出返回业务异常

## 5. 推荐效果度量

### 5.1 核心指标（已实现，简化）

| 指标 | 实际计算方式 | 说明 |
|------|---------|------|
| 推荐采纳率 | 有用反馈数 / 有反馈总数（useful/feedbackTotal） | 早期需求稿"使用推荐算法次数/展示次数"未实现（采纳未记录） |
| 推荐满意度 | = 推荐采纳率（简化，有用即满意） | 早期需求稿"采纳且评分≥4"未实现 |
| 推荐覆盖率 | 被推荐采纳的不同算法数 / 已发布算法数 | 依赖 `adopted_algorithm_id`，该字段未写入 → 当前恒为 0 |
| 冷启动成功率 | **固定 0.0**（硬编码） | 冷启动策略未实现 |
| 趋势 | 按日聚合采纳率（date + adoptionRate） | ✅ 已实现 |

### 5.2 报表（接口已实现，前端未接入）

管理员可通过 `GET /api/v1/recommendations/report` 查询效果报表，包含：推荐总量、采纳率、满意度、覆盖率、冷启动成功率、按日采纳率趋势。

> 早期需求稿中的"各场景类型的推荐准确率、各算法的被推荐次数和采纳率、用户反馈分布（有用/无用占比）"**未实现**。前端**无报表页面**（接口与权限已就绪）。

## 7. 待确认事项

> 早期需求稿"推荐模型选择"一项已定论：当前采用**规则匹配**方案（代码注释明确"后续可演进为机器学习模型"，预留架构扩展点），以下为尚未确认/未实现的规划项：

4. **离线分析**：批量图片分析是否在规划范围内？
5. **真实特征分析**：是否接入 Python 算法服务的图像特征提取能力（替换 Mock）？
