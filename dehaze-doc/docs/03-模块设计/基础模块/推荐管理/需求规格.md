# 推荐管理模块需求规格

## 1. 模块概述

### 1.1 模块定位

推荐管理模块根据图像特征分析结果，按用户当前处理的任务类型（去雾/去雨/去雪/低光增强/超分辨率/去噪/图像修复）为用户推荐合适的图像处理算法，并提供推荐规则配置与推荐效果度量能力。该模块为算法选择页面提供"算法推荐"面板入口。

### 1.2 核心价值

| 价值维度 | 具体内容 |
|---------|---------|
| **降低选择门槛** | 用户无需了解算法差异，上传图片即可获得 Top 3 推荐 |
| **场景匹配** | 基于图像特征（场景类型）匹配预设规则，推荐理由可解释 |
| **规则可配置** | 管理员可配置场景→算法的映射规则及权重 |
| **效果可度量** | 推荐采纳率、覆盖率等基础指标统计 |

### 1.3 业务目标

#### 功能目标

- 基于图像特征分析，推荐 Top N 最合适的算法
- 支持推荐理由的可解释性展示
- 支持管理员配置推荐规则和权重

#### 性能目标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 图像特征分析 | < 2s | 上传图片到完成特征提取 |
| 推荐结果生成 | < 500ms | 特征分析完成后生成推荐列表 |
| 端到端推荐 | < 3s | 用户上传图片到看到推荐结果 |
| 推荐覆盖率 | ≥ 80% | 有推荐结果的请求占比（推荐结果非空的请求数 / 总请求数） |
| 推荐采纳率 | ≥ 40% | 采纳数 / 展示数 |

## 2. 用户角色分析

| 角色 | 描述 | 主要职责 |

## 4. 功能需求

### 4.1 图像特征分析 (F-REC-001)

#### 4.1.1 功能描述

对用户选择的图像进行多维特征分析，输出结构化的图像特征向量，作为推荐匹配的输入。（Java/Go 端通过 HTTP 调用 Python 图像特征分析服务提取真实特征）。

> **实现说明**：Java 端 `RecommendationServiceImpl.analyze` 通过 `PythonAlgorithmClient.analyzeImage`（复用算法服务 HTTP 客户端的重试/熔断/幂等机制）调用 Python `/api/v1/recommendations/analyze`，由 Python 端基于 PyTorch 场景分类 + OpenCV 暗通道/边缘/直方图提取真实 7 维特征；Go 端通过 `pkg/algorithm.Client.AnalyzeImage` 调用同一接口。Python 服务不可用时返回明确错误（Java: C0001 / Go: B0001），不降级为伪特征。`imageId` 方式**暂不支持**（返回业务异常）。

#### 4.1.2 分析维度

| 维度 | 说明 |
|------|------|
| 雾霾浓度 | 轻度/中度/重度 + 置信度 |
| 场景类型 | 城市/风景/建筑/夜景/逆光/室内 + 置信度 |
| 光照条件 | 明亮/正常/偏暗/极暗/逆光 |
| 图像复杂度 | 0-1 数值（纹理/边缘/色彩） |
| 颜色分布 | 色温 + 饱和度 |
| 分辨率 | 标清/高清/超清 |
| 噪声水平 | 低/中/高 |

> 当前推荐匹配仅使用"场景类型"维度。

#### 4.1.3 分析结果展示

| 字段 | 说明 |
|------|------|
| 雾霾浓度 | 轻度/中度/重度 + 置信度 |
| 场景类型 | 城市/风景/建筑/夜景/逆光/室内 + 置信度 |
| 光照条件 | 明亮/正常/偏暗/极暗/逆光 |
| 复杂度 | 0-1 数值（进度条可视化） |
| 分辨率 | 标清/高清/超清 |
| 噪声水平 | 低/中/高 |
| 颜色分布 | 色温、饱和度（原始数据） |

> 前端折叠面板（"图像特征分析"）展开即展示全部维度，无用户角色分级展示。

### 4.2 算法推荐 (F-REC-002)

#### 4.2.1 功能描述

基于图像特征分析结果，匹配推荐规则表，输出 Top 3 推荐算法列表，包含推荐理由和匹配度。

#### 4.2.2 推荐策略

推荐算法为**场景规则匹配**：

```
确定场景类型（analysisId 历史 → imageMd5 历史 → 默认 urban）
    ↓
加载启用的规则（sys_recommendation_rule，enabled=1）
    ↓
按场景类型匹配规则（scene_type 相同）→ 按权重降序
    ↓
聚合候选算法（规则 algorithm_ids 并集）→ 过滤已发布算法（status=4）
    ↓
匹配度 = 该算法在匹配规则中的最高权重（归一化 0-100）
    ↓
按匹配度降序 → 截取 Top 3
```

**推荐理由模板**（按场景类型，`算法名 + 理由`）：

| 场景类型 | 推荐理由模板 |
|---------|-------------|
| urban（城市） | 处理速度快，对城市雾霾效果出色 |
| landscape（风景） | 在自然场景下表现稳定，色彩还原度高 |
| building（建筑） | 深度模型，对建筑场景处理能力强 |
| night（夜景） | 低光照增强组合，避免过度暗化 |
| backlight（逆光） | HDR预处理提升暗部细节 |
| indoor（室内） | 室内场景适配，细节保留好 |

> 推荐由管理员配置的规则表驱动，候选算法随规则变化。无论是否有匹配结果，均写入 `sys_recommendation` 推荐记录（供反馈关联）。

#### 4.2.3 推荐结果展示

每个推荐算法展示：

| 字段 | 说明 |
|------|------|
| 算法名称 | 已发布算法的名称 |
| 匹配度 | 百分比（0-100，按规则权重计算） |
| 推荐理由 | 场景模板生成的一句话理由 |
| 算法评分 | 暂不展示（标注"暂无数据"，待真实评分数据采集后展示） |
| 预期效果 | 暂不展示（待真实耗时数据采集后展示） |
| 操作 | 一键使用（`select` 事件，跳转图像处理） |

> 算法评分与预期耗时当前不展示，待真实评分/耗时数据采集后恢复展示。推荐列表仅按匹配度（matchScore）排序，无"按评分/按使用频率"排序选项。

### 4.3 推荐反馈 (F-REC-003)

#### 4.3.1 功能描述

用户对推荐结果进行显式反馈，反馈数据记录用于推荐效果度量。

#### 4.3.2 反馈方式

| 反馈方式 | 说明 |
|---------|------|
| 显式反馈 | "有用"/"无用"按钮，写入 `sys_recommendation.feedback`（1=有用；2=无用） |

> 当前反馈仅记录用于报表统计，不参与后续推荐匹配。

### 4.4 推荐规则管理 (F-REC-004)

#### 4.4.1 功能描述

管理员可配置推荐规则（场景→算法映射）及权重。（规则 CRUD + 启用/禁用）。

#### 4.4.2 可配置项

| 配置项 | 说明 |
|--------|------|
| 场景匹配规则 | 新增/编辑/禁用场景→算法映射（rule_name/scene_type/algorithm_ids/weight/enabled） |
| 规则权重 | 0-100 数值，控制匹配优先级 |

**规则管理细节**：
- 删除操作实际为**禁用**（`enabled=false`，规则保留可追溯）
- 规则变更后刷新内存缓存（Java 端 CopyOnWriteArrayList，写时复制；Python 端每次实时查询启用规则）
- 权重校验：0-100，超出返回业务异常

## 5. 推荐效果度量

### 5.1 核心指标

| 指标 | 实际计算方式 | 说明 |
|------|---------|------|
| 推荐覆盖率 | 有推荐结果的请求数 / 总请求数 | 基于 sys_recommendation 记录 |
| 推荐满意度 | 有用反馈数 / 有反馈总数（useful/feedbackTotal） | 简化，有用即满意 |
| 趋势 | 按日聚合采纳率（date + adoptionRate） | 按日聚合 |

### 5.2 报表

管理员可通过 `GET /api/v1/recommendations/report` 查询效果报表，包含：推荐总量、覆盖率、采纳率、满意度、冷启动成功率、按日采纳率趋势。
