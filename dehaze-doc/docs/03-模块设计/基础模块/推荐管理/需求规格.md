# 推荐管理模块需求规格

## 1. 模块概述

### 1.1 模块定位

推荐管理模块是图像去雾系统的智能中枢，负责根据图像特征、用户偏好、算法表现等多维信息，为用户推荐最合适的去雾算法、参数方案和数据集。该模块替代当前分散在各核心模块中的推荐逻辑（算法选择的智能推荐、样例图片的静态推荐算法等），提供统一的推荐能力。

### 1.2 核心价值

| 价值维度 | 具体内容 |
|---------|---------|
| **降低选择门槛** | 用户无需了解 29 种算法差异，上传图片即可获得 Top 3 推荐 |
| **提升处理质量** | 基于图像特征与算法历史表现智能匹配，推荐准确率持续优化 |
| **数据飞轮** | 用户的使用、评价、收藏行为反哺推荐引擎，推荐效果持续提升 |
| **可扩展** | 推荐能力从算法扩展到参数方案、数据集、图像增强策略等 |

### 1.3 业务目标

#### 功能目标

- 基于图像特征分析，智能推荐 Top N 最合适的去雾算法
- 支持推荐理由的可解释性展示（为什么推荐这个算法）
- 推荐结果随用户反馈和使用数据持续优化
- 支持管理员配置推荐规则和权重

#### 性能目标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 图像特征分析 | < 2s | 上传图片到完成特征提取 |
| 推荐结果生成 | < 500ms | 特征分析完成后生成推荐列表 |
| 端到端推荐 | < 3s | 用户上传图片到看到推荐结果 |
| 推荐准确率 | ≥ 70% | 用户采纳推荐算法且满意度 ≥ 4 星的比例 |

## 2. 用户角色分析

### 2.1 主要用户角色

| 角色 | 描述 | 主要职责 |
|------|------|---------|
| **普通用户** | 需要去雾处理但不懂算法选择的用户 | 上传图片获取推荐，一键使用推荐算法 |
| **进阶用户** | 了解算法差异，需要参考建议的用户 | 查看推荐理由和详细分析，结合自身判断选择 |
| **系统管理员** | 管理推荐规则和权重的运营人员 | 配置推荐策略、调整算法评分权重、查看推荐效果报表 |

### 2.2 权限矩阵

| 功能点 | 普通用户 | 进阶用户 | 管理员 |
|--------|:------:|:------:|:------:|
| 获取算法推荐 | ✅ | ✅ | ✅ |
| 查看推荐理由 | ✅ | ✅ | ✅ |
| 反馈推荐效果 | ✅ | ✅ | ❌ |
| 查看特征分析详情 | ❌ | ✅ | ✅ |
| 配置推荐规则 | ❌ | ❌ | ✅ |
| 查看推荐效果报表 | ❌ | ❌ | ✅ |

## 3. 推荐对象类型

| 类型编码 | 类型名称 | 当前阶段 | 说明 |
|---------|---------|:------:|------|
| `algorithm` | 算法推荐 | 实现 | 根据图像特征推荐最合适的去雾算法 |
| `preset` | 参数方案 | 规划 | 根据图像特征推荐最佳参数组合 |
| `dataset` | 数据集 | 规划 | 根据研究方向推荐合适的数据集 |
| `enhance` | 增强策略 | 规划 | 推荐预处理/后处理策略组合 |

## 4. 功能需求

### 4.1 图像特征分析 (F-REC-001)

#### 4.1.1 功能描述

对用户上传/选择的图像进行多维特征分析，输出结构化的图像特征向量，作为推荐匹配的输入。

#### 4.1.2 分析维度

| 维度 | 权重 | 说明 |
|------|:----:|------|
| 雾霾浓度 | 30% | 轻度/中度/重度，影响算法强度选择 |
| 场景类型 | 20% | 城市场景/自然风景/建筑/夜景/逆光/室内 |
| 光照条件 | 15% | 明亮/正常/偏暗/极暗/逆光 |
| 图像复杂度 | 10% | 纹理丰富度、边缘密度、色彩分布 |
| 颜色分布 | 10% | 色温、饱和度、直方图分布 |
| 分辨率 | 5% | 标清/高清/超清，影响算法可处理性 |
| 噪声水平 | 10% | 低噪/中噪/高噪，影响预处理需求 |

#### 4.1.3 分析结果展示

| 字段 | 说明 | 面向用户 |
|------|------|:------:|
| 雾霾浓度 | 轻度/中度/重度 + 置信度 | 普通用户 |
| 场景类型 | 城市场景/自然风景 + 置信度 | 普通用户 |
| 光照条件 | 明亮/偏暗/逆光 | 进阶用户 |
| 技术指标 | 噪声水平、分辨率、复杂度 | 进阶用户 |
| 原始特征数据 | 各维度数值 | 管理员/调试 |

### 4.2 算法推荐 (F-REC-002)

#### 4.2.1 功能描述

基于图像特征分析结果，匹配算法知识库，输出 Top 3 推荐算法列表，包含推荐理由和匹配度。

#### 4.2.2 推荐策略

| 场景特征 | 推荐算法倾向 | 推荐理由模板 |
|---------|-------------|-------------|
| 轻度城市雾霾 | DCP/CAP/AOD-Net | "处理速度快，对轻度雾霾效果出色" |
| 中度自然风景 | AOD-Net/FFA-Net/GridDehazeNet | "在自然场景下表现稳定，色彩还原度高" |
| 重度城市建筑 | DehazeFormer/GridDehazeNet/MSBDN | "深度模型，对高浓度雾霾处理能力强" |
| 夜景/低光照 | Retinex+去雾/Restormer | "低光照增强组合，避免过度暗化" |
| 逆光场景 | HDR预处理+去雾 | "HDR 预处理提升暗部细节" |
| 高噪声图像 | 去噪预处理+轻量去雾 | "先降噪再处理，避免噪声放大" |

#### 4.2.3 推荐结果展示

每个推荐算法展示：

| 字段 | 说明 |
|------|------|
| 算法名称 | 支持中英文 |
| 匹配度 | 百分比或星级（0-100% 或 1-5 星） |
| 推荐理由 | 一句话说明为什么推荐 |
| 算法评分 | 基于用户评价的综合评分 |
| 预期效果 | 处理耗时预估、效果风格描述 |
| 操作 | 一键使用、查看详情、加入对比 |

### 4.3 推荐反馈 (F-REC-003)

#### 4.3.1 功能描述

用户对推荐结果进行反馈，反馈数据用于优化推荐模型。

#### 4.3.2 反馈方式

| 反馈方式 | 说明 |
|---------|------|
| 采纳推荐 | 用户使用推荐算法完成处理，隐式正向反馈 |
| 效果评价 | 处理完成后对结果的评分（1-5星），关联到推荐记录 |
| 显式反馈 | "推荐有用"/"推荐不准确"按钮 |
| 收藏行为 | 收藏推荐的处理结果，作为强正向信号 |

### 4.4 推荐规则管理 (F-REC-004)

#### 4.4.1 功能描述

管理员可配置推荐策略的规则、权重和算法评分计算方式。

#### 4.4.2 可配置项

| 配置项 | 说明 |
|--------|------|
| 特征维度权重 | 调整 7 个分析维度的权重 |
| 场景匹配规则 | 新增/修改/禁用场景→算法映射关系 |
| 算法评分权重 | 用户评分 vs 处理成功率 vs 处理速度的权重 |
| 推荐数量 | Top N 的 N 值（默认 3） |
| 冷启动策略 | 新上线算法的推荐曝光策略 |

## 5. 推荐效果度量

### 5.1 核心指标

| 指标 | 计算方式 | 目标值 |
|------|---------|:------:|
| 推荐采纳率 | 使用推荐算法次数 / 展示推荐次数 | ≥ 40% |
| 推荐满意度 | 采纳推荐且评分 ≥ 4 的次数 / 采纳推荐次数 | ≥ 70% |
| 推荐覆盖率 | 被推荐过的算法数 / 已发布算法总数 | ≥ 60% |
| 冷启动成功率 | 新算法 7 日内被推荐采纳次数 | ≥ 3 次 |

### 5.2 报表

管理员可查看：
- 推荐效果趋势图（日/周/月）
- 各场景类型的推荐准确率
- 各算法的被推荐次数和采纳率
- 用户反馈分布（有用/无用）

## 6. 依赖关系

### 6.1 依赖模块

| 模块 | 依赖说明 |
|------|---------|
| **算法管理** | 获取已发布算法列表、算法详情、算法评分数据 |
| **文件管理** | 获取用户上传的图像进行分析 |
| **会员管理** | VIP 用户优先推荐更高质量的算法（如 experimental 类型） |
| **收藏管理** | 收藏行为作为推荐训练的正向信号 |
| **反馈评价** | 用户对处理结果的评分作为推荐效果反馈 |

### 6.2 被依赖模块

| 模块 | 依赖说明 |
|------|---------|
| **算法选择** | 推荐结果作为算法选择的默认入口 |
| **去雾处理** | 推荐策略指导默认参数方案 |
| **图像输入** | 样例图片的推荐算法由推荐引擎动态生成（替代当前静态配置） |

## 7. 待确认事项

1. **推荐模型选择**：当前采用规则匹配还是需要引入机器学习模型？规则匹配可快速上线但有天花板
2. **冷启动策略**：新上线算法如何获得推荐曝光机会？
3. **A/B 测试框架**：是否需要支持推荐策略的 A/B 测试能力？
4. **推荐历史**：用户是否需要查看历史推荐记录？
5. **离线分析**：批量图片分析是否在规划范围内？
