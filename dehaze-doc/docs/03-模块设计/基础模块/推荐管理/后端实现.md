## 2. 架构设计

### 2.1 模块分层架构

```
Controller 层（dehaze-java / dehaze-python）
└── RecommendationController / recommendation router
    ├── POST   /api/v1/recommendations/analyze     # 图像特征分析
    ├── GET    /api/v1/recommendations/algorithms  # 获取算法推荐
    ├── POST   /api/v1/recommendations/feedback    # 推荐反馈
    ├── GET    /api/v1/recommendations/rules       # 规则查询（管理员）
    ├── PUT    /api/v1/recommendations/rules       # 规则新增/更新（管理员）
    └── GET    /api/v1/recommendations/report      # 效果报表（管理员）

Service 层
└── RecommendationServiceImpl / RecommendationService（单服务类承载全部逻辑）
    ├── analyze()                 # Mock 特征分析（URL MD5 确定性伪随机）
    ├── getAlgorithmRecommendations()  # 场景规则匹配 + 推荐记录落库
    ├── submitFeedback()          # 显式反馈写入
    ├── getRules() / updateRule() # 规则查询/新增/更新 + 缓存刷新
    └── getReport()               # 推荐效果统计
```

> **说明**：早期设计稿中的 ImageAnalysisService / RuleMatchEngine / RecommendRankService / FeedbackCollectService 等拆分**不存在**，当前由单一服务类完成全部逻辑；图像特征分析为 Mock，不调用 Python 算法服务。

### 2.2 核心组件职责

| 组件 | 职责描述 | 关键能力 |
|------|---------|---------|
| analyze | 图像特征分析（Mock） | 校验 imageUrl 格式、基于 URL MD5 生成确定性 7 维特征 |
| getAlgorithmRecommendations | 算法推荐 | 已发布算法候选池、启用规则匹配、匹配度计算、推荐记录落库、回填 recommendationId |
| submitFeedback | 推荐反馈 | 校验推荐记录、写入 feedback（1 有用/2 无用） |
| getRules/updateRule | 规则管理 | 规则查询（weight 升序）、新增（id=0）/更新、权重校验、内存缓存刷新 |
| getReport | 效果度量 | 推荐总量/采纳率/满意度/覆盖率/冷启动成功率/按日趋势统计 |

## 3. 数据模型设计

> 表结构权威定义详见 [03-数据库设计.md](../../../02-系统架构/03-数据库设计.md) 及 `config/sql/schema/sys_recommendation.sql`

### 3.1 推荐记录表（sys_recommendation）

**设计决策**：推荐记录为只追加，不使用逻辑删除，过期数据通过定时任务物理清理。`top_algorithms` 和 `analysis_result` 使用 JSON 存储避免拆子表。

| 字段 | 类型 | 实际写入情况 |
|------|------|------|
| id | BIGINT | 主键，自增 |
| user_id | BIGINT | 当前登录用户 ID（未登录回退系统用户） |
| image_md5 | CHAR(32) | 分析接口返回的 URL MD5 |
| target_type | VARCHAR(32) | **固定 "algorithm"** |
| top_algorithms | JSON | 推荐算法列表（Top 3：algorithmId/algorithmName/matchScore） |
| analysis_result | JSON | **当前未写入**（Mock 特征分析结果不入库） |
| feedback | TINYINT | 0=未反馈；1=有用；2=无用 |
| adopted_algorithm_id | BIGINT | **当前未写入**（采纳逻辑未实现） |

**索引设计**：idx_user_id（用户历史）、idx_image_md5（特征缓存关联）、idx_create_time（报表统计）。

### 3.2 推荐规则表（sys_recommendation_rule）

| 字段 | 类型 | 说明 |
|------|------|------|
| rule_name | VARCHAR(64) | 规则名称 |
| scene_type | VARCHAR(32) | 场景类型（urban/landscape/building/night/backlight/indoor） |
| algorithm_ids | JSON | 候选算法 ID 列表 |
| weight | INT | 规则权重（0-100，越大越优先） |
| enabled | TINYINT | 0=禁用；1=启用 |
| deleted | TINYINT | 逻辑删除标识（当前未使用，删除=禁用） |

**缓存策略（Java 端）**：启用规则加载到内存 `CopyOnWriteArrayList`（写时复制保证线程安全），`updateRule` 后刷新缓存；Python 端每次实时查询启用规则，无内存缓存。

## 4. 核心业务流程

### 4.1 图像特征分析（analyze）

```
接收 AnalyzeForm（imageId / imageUrl）
    ↓
resolveImageUrl：
  - imageId > 0 → 抛业务异常"imageId方式暂不支持，请使用imageUrl"（A0401）
  - imageUrl 为空 → 抛参数错误（A0400）
    ↓
validateImageFormat：校验扩展名（jpg/jpeg/png/webp/bmp/tiff/tif，忽略 query string）
  - 不合法 → 抛 A0701 文件格式不支持
    ↓
Mock 特征生成：md5 = MD5(imageUrl)，seed = |md5.hashCode()|
  - hazeLevel/hazeConfidence/sceneType/sceneConfidence/lighting/complexity/
    colorDistribution(temperature/saturation)/resolution/noiseLevel 均由 seed 确定性生成
    ↓
返回 ImageFeatureAnalysisVO（imageMd5 = md5）
```

> **说明**：特征基于 URL 生成，同一 URL 结果确定一致；**不下载图片、不调用算法服务**。生产环境接真实特征提取后，本流程替换为算法服务调用（见需求规格 §7 待确认事项）。

### 4.2 算法推荐（getAlgorithmRecommendations）

```
输入 analysisId / imageMd5
    ↓
1. 候选池：已发布算法（status=4）
2. 启用规则：Java 从内存缓存加载（无缓存则查询 enabled=1）；Python 实时查询
3. 场景确定：
   - analysisId > 0 → 查推荐记录 analysis_result.sceneType（当前未写入，落空）
   - imageMd5 → 查最近推荐记录 analysis_result.sceneType（当前未写入，落空）
   - 默认 "urban"
4. 规则匹配：scene_type 相同 → 按 weight 降序 → 聚合 algorithm_ids 候选集
5. 候选过滤：候选集 ∩ 已发布算法
6. 匹配度：该算法在匹配规则中的最高权重（min(100, maxWeight)）
7. 构建 VO：algorithmId/algorithmName/matchScore/reason（场景模板）/rating(3.5)/estimatedTime(5000)/effectDescription(模板)
8. 排序：matchScore 降序 → 截取 TOP_N（3）
9. 落库：写入 sys_recommendation（target_type="algorithm"、top_algorithms、feedback=0）
10. 回填 recommendationId 到各 VO
    ↓
返回推荐列表
```

**推荐理由模板**（`算法名 + 场景理由`）：

| sceneType | 理由模板 |
|-----------|---------|
| urban | 处理速度快，对城市雾霾效果出色 |
| landscape | 在自然场景下表现稳定，色彩还原度高 |
| building | 深度模型，对建筑场景处理能力强 |
| night | 低光照增强组合，避免过度暗化 |
| backlight | HDR预处理提升暗部细节 |
| indoor | 室内场景适配，细节保留好 |

### 4.3 推荐反馈（submitFeedback）

```
接收 recommendationId + useful
    ↓
查询推荐记录
  - 不存在 → 抛 A0401
  - （Java 兼容逻辑）按 recommendationId 匹配 topAlgorithms 中 algorithmId 的最近记录
    ↓
feedback = useful ? 1 : 2
更新记录
```

> **说明**：Java 端存在按 algorithmId 匹配最近未反馈记录的 fallback；Python 端严格按推荐记录 ID。**采纳（adopted_algorithm_id）写入未实现**。

### 4.4 规则管理（getRules / updateRule）

**getRules**：查询全部规则，按 weight 升序返回。

**updateRule**：
```
id 为 0 → 新增（ruleName/sceneType/algorithmIds/weight/enabled）
id 非 0 → 更新（规则不存在 → A0401）
权重校验：null 或 <0 或 >100 → A0500"规则权重必须在0-100之间"
Java 端刷新内存规则缓存
```

### 4.5 效果报表（getReport）

```
输入 startDate / endDate（yyyy-MM-dd，可空）
    ↓
统计：
- totalRecommendations = COUNT(全部推荐记录)
- usefulCount = COUNT(feedback=1)
- feedbackTotal = COUNT(feedback!=0)
- adoptedDistinct = COUNT(DISTINCT adopted_algorithm_id)（当前恒 0）
- publishedCount = COUNT(已发布算法)
    ↓
指标：
- adoptionRate = usefulCount / feedbackTotal（无反馈则 0）
- satisfactionRate = adoptionRate（简化，有用即满意）
- coverageRate = adoptedDistinct / publishedCount（当前恒 0）
- coldStartSuccessRate = 0.0（硬编码）
- trend = 按日采纳率（date + adoptionRate）
```

## 7. 推荐效果度量

| 指标 | 实际计算方式 | 目标值 | 说明 |
|------|---------|--------|------|
| 推荐采纳率 | useful / feedbackTotal | ≥ 40% | 以"有用"反馈近似采纳 |
| 推荐满意度 | = 采纳率（简化） | ≥ 70% | 有用即满意 |
| 推荐覆盖率 | adoptedDistinct / publishedCount | ≥ 60% | 当前恒 0（采纳未记录） |
| 冷启动成功率 | 0.0（硬编码） | ≥ 3 次 | 未实现 |
| 趋势 | 按日采纳率 | - | 报表趋势图数据 |

## 8. 缓存设计

| 缓存对象 | 实现 | 更新策略 |
|---------|------|---------|
| 启用规则（Java 端） | `CopyOnWriteArrayList` 内存缓存（enabled=1） | updateRule 后 `refreshRuleCache()` 全量刷新 |
| 启用规则（Python 端） | 无缓存，实时查询 | - |

> 早期设计稿中的 `recommend:feature:{imageMd5}` 特征缓存、`recommend:algo:score:{algorithmId}` 评分缓存、`recommend:user:profile:{userId}` 用户偏好画像 **均未实现**（`sys_recommendation.image_md5` 为关联预留字段）。

## 9. 配置项

| 配置项 | 说明 | 实际值 |

| TOP_N | 推荐算法数量 | 3（Java/Python 常量，不可配置） |
