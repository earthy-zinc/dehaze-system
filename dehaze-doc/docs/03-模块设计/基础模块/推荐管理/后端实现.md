## 2. 架构设计

### 2.1 模块分层架构

推荐管理模块是系统的智能中枢，负责根据图像特征和用户偏好推荐最合适的去雾算法。当前阶段采用规则匹配引擎，后续可演进为机器学习模型。

| 层级 | 组件 | 职责 |
|------|------|------|
| Controller 层 | RecommendController | 推荐请求/反馈收集 |
| Service 层 | RecommendService | 推荐编排服务，串联图像分析→规则匹配→排序→推荐结果构建 |
| Service 层 | ImageAnalysisService | 图像特征分析，调用 Python 算法服务提取图像特征向量 |
| Service 层 | RuleMatchEngine | 规则匹配引擎，基于场景→算法映射规则匹配候选算法集 |
| Service 层 | RecommendRankService | 推荐排序服务，基于综合得分对候选算法排序 |
| Service 层 | FeedbackCollectService | 推荐反馈收集，记录采纳/拒绝/评分反馈，更新推荐效果统计 |

### 2.2 依赖模块

| 依赖模块 | 调用接口 | 用途 |
|---------|---------|------|
| SysAlgorithmService（算法管理） | listPublished() | 获取推荐候选算法池 |
| PredictionService（算法管理） | Python 服务调用 | 图像特征分析 |
| FavoriteService（收藏管理） | 收藏数据查询 | 收藏行为作为训练信号 |
| RatingService（反馈评价） | sys_rating 聚合 | 评分作为训练信号 |
| MemberService（会员管理） | 会员等级查询 | VIP 算法推荐优先级 |

### 2.3 核心组件职责

| 组件 | 职责描述 | 关键能力 |
|------|---------|---------|
| RecommendService | 推荐编排服务 | 串联图像分析→规则匹配→排序→推荐结果构建 |
| ImageAnalysisService | 图像特征分析 | 调用 Python 算法服务提取 7 维图像特征向量（雾霾浓度、场景类型、光照条件、图像复杂度、颜色分布、分辨率、噪声水平） |
| RuleMatchEngine | 规则匹配引擎 | 基于场景→算法映射规则，匹配候选算法集 |
| RecommendRankService | 推荐排序服务 | 基于特征匹配度、用户评分、处理成功率、推荐采纳率计算综合得分排序 |
| FeedbackCollectService | 反馈收集 | 记录推荐采纳/拒绝/评分反馈，更新推荐效果统计 |

## 3. 数据模型设计

> 表结构权威定义详见 [03-数据库设计.md](../../../02-系统架构/03-数据库设计.md) 及 `config/sql/schema/sys_recommendation.sql`

### 3.1 推荐记录表（sys_recommendation）

**设计决策**：推荐记录为只追加，不使用逻辑删除，过期数据通过定时任务物理清理。`top_algorithms` 和 `analysis_result` 使用 JSON 存储避免拆子表，`image_md5` 用于关联图像特征分析缓存，相同图片复用分析结果。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| user_id | BIGINT | 用户 ID |
| image_md5 | CHAR(32) | 图像 MD5（关联特征分析缓存） |
| target_type | VARCHAR(32) | 推荐对象类型（algorithm/preset/dataset/enhance） |
| top_algorithms | JSON | 推荐算法列表（Top 3：算法 ID 及匹配度） |
| analysis_result | JSON | 图像特征分析结果（7 维特征向量） |
| feedback | TINYINT | 推荐反馈（0=未反馈；1=有用；2=无用） |
| adopted_algorithm_id | BIGINT | 用户采纳的算法 ID（null=未采纳） |
| create_time | DATETIME | 推荐时间 |

**索引设计**：

| 索引名 | 字段 | 用途 |
|--------|------|------|
| idx_user_id | user_id | 用户推荐历史查询 |
| idx_image_md5 | image_md5 | 图像特征分析缓存命中查询 |
| idx_create_time | create_time | 推荐效果报表按时间范围统计 |

### 3.2 推荐规则存储

**设计决策**：推荐规则存储于 `sys_recommendation_rule` 表，支持管理员通过 API 动态增删改查。理由如下：

| 考量 | 说明 |
|------|------|
| 管理员可配置 | 需求规格 F-REC-004 要求管理员可通过 API 配置规则，落库才能支持 CRUD |
| 可审计性 | 规则变更需记录操作人和时间，配置文件无法满足 |
| 缓存加速 | 规则加载后缓存到内存，匹配时零 IO 开销，变更时刷新缓存 |
| 扩展性 | 未来规则数量增长或需要条件组合时，表结构可平滑扩展 |

**表结构**：`sys_recommendation_rule`（rule_name、scene_type、algorithm_ids(json)、weight、enabled、deleted）

**缓存策略**：服务启动时全量加载到内存规则引擎，管理员修改规则后触发缓存刷新。

规则配置通过管理员 API（`PUT /api/v1/recommendations/rules`）修改，修改后刷新内存规则缓存。

## 4. 核心业务流程

### 4.1 推荐生成流程

| 步骤 | 说明 | 输出 |
|------|------|------|
| 1. 图像特征分析 | ImageAnalysisService 调用 Python 算法服务，提取 7 维图像特征向量 | 特征向量（含雾霾浓度/场景类型/光照条件/复杂度/颜色分布/分辨率/噪声） |
| 2. 规则匹配 | RuleMatchEngine 根据场景特征匹配候选算法集 | 候选算法列表（按场景→算法映射规则） |
| 3. 综合排序 | RecommendRankService 计算 4 维综合得分，排序候选算法 | Top N 推荐算法列表（默认 Top 3） |
| 4. 冷启动注入 | 若存在新算法未获曝光，随机插入 1 个新算法 | 最终推荐列表 |
| 5. 记录推荐 | 写入 `sys_recommendation` 表，记录特征向量、推荐算法、用户 ID | 推荐记录 ID（供后续反馈关联） |

### 4.2 图像特征分析

调用 Python 算法服务提取 7 维图像特征向量：

| 特征维度 | 权重 | 说明 |
|---------|:----:|------|
| 雾霾浓度 | 30% | 轻度/中度/重度，影响算法强度选择 |
| 场景类型 | 20% | 城市场景/自然风景/建筑/夜景/逆光/室内 |
| 光照条件 | 15% | 明亮/正常/偏暗/极暗/逆光 |
| 图像复杂度 | 10% | 纹理丰富度、边缘密度、色彩分布 |
| 颜色分布 | 10% | 色温、饱和度、直方图分布 |
| 分辨率 | 5% | 标清/高清/超清，影响算法可处理性 |
| 噪声水平 | 10% | 低噪/中噪/高噪，影响预处理需求 |

### 4.3 规则匹配引擎

**设计决策**：当前阶段采用规则匹配引擎而非机器学习模型，理由如下：

| 考量 | 说明 |
|------|------|
| 快速上线 | 规则匹配满足 MVP 需求，无需训练数据 |
| 可解释性 | 推荐理由清晰，用户和管理员可理解 |
| 可配置 | 管理员可通过配置界面调整规则，无需重新训练模型 |
| 可演进 | 后续可演进为机器学习模型，当前架构预留扩展点 |

**场景→算法映射规则**：

| 场景特征 | 推荐算法 | 推荐理由 |
|---------|---------|---------|
| 轻度城市雾霾 | DCP, CAP, AOD-Net | 处理速度快，对轻度雾霾效果出色 |
| 中度自然风景 | AOD-Net, FFA-Net, GridDehazeNet | 在自然场景下表现稳定，色彩还原度高 |
| 重度城市建筑 | DehazeFormer, GridDehazeNet, MSBDN | 深度模型，对高浓度雾霾处理能力强 |
| 夜景/低光照 | Retinex+去雾, Restormer | 低光照增强组合，避免过度暗化 |
| 逆光场景 | HDR预处理+去雾 | HDR 预处理提升暗部细节 |
| 高噪声图像 | 去噪预处理+轻量去雾 | 先降噪再处理，避免噪声放大 |

### 4.4 排序权重计算

综合得分 = 特征匹配度 × 0.4 + 用户评分归一化 × 0.25 + 处理成功率 × 0.2 + 推荐采纳率 × 0.15

| 权重因子 | 权重 | 数据来源 | 计算方式 |
|---------|:----:|---------|---------|
| 特征匹配度 | 40% | 规则匹配引擎 | 根据场景特征与算法的适配程度计算 |
| 用户评分归一化 | 25% | sys_rating 聚合 | AVG(score) / 5.0 |
| 处理成功率 | 20% | sys_pred_log 聚合 | COUNT(status=1) / COUNT(*) |
| 推荐采纳率 | 15% | sys_recommendation 聚合 | 采纳次数 / 展示次数 |

### 4.5 替代算法推荐

当用户对当前处理结果不满意时，提供排除当前算法的替代推荐：

| 步骤 | 说明 |
|------|------|
| 1. 复用特征分析 | 复用图像特征分析结果（缓存命中），避免重复调用 Python 服务 |
| 2. 排除当前算法 | 规则匹配时排除用户指定的 excludeAlgorithmId |
| 3. 返回替代推荐 | 返回 Top 3 替代算法 |

## 5. 推荐策略

### 5.1 冷启动策略

新上线算法缺乏使用数据和评分，通过冷启动策略获得推荐曝光机会：

| 策略 | 说明 |
|------|------|
| 初始评分 | 新算法赋予默认评分（3.5 星），避免因无评分被排除 |
| 随机曝光 | 在推荐结果中随机插入 1 个新算法（与 Top N 结果不重叠） |
| 曝光加权 | 新算法首次曝光时提升匹配度权重 20%，7 天后恢复正常 |
| 曝光上限 | 每日曝光次数上限（默认 50 次），避免过度曝光低质量算法 |

## 6. 模块间协作

### 6.1 与算法管理模块的集成

| 调用场景 | 调用接口 | 说明 |
|---------|---------|------|
| 已发布算法列表 | SysAlgorithmService.listPublished() | 获取推荐候选算法池 |
| 算法评分数据 | 查询 sys_rating 聚合 | 作为排序权重因子 |
| 算法性能数据 | 查询 sys_pred_log 聚合 | 获取成功率和处理速度数据 |
| 图像特征分析 | PredictionService 或直接调用 Python 服务 | 提取图像特征向量 |

### 6.2 与 Python 算法服务的集成

图像特征分析需要调用 Python 算法服务进行图像处理：

| 调用方式 | 说明 |
|---------|------|
| 协议 | HTTP/REST |
| 接口 | 图像特征分析端点 |
| 超时 | 5 秒 |
| 重试 | 1 次 |

### 6.3 与收藏管理模块的集成

收藏行为作为推荐引擎的训练信号：

| 信号类型 | 权重 | 说明 |
|---------|------|------|
| 用户收藏某算法 | 正向信号 | 表明用户偏好该算法类型 |
| 用户收藏某处理结果 | 正向信号 | 表明该算法对类似图像效果良好 |

推荐引擎定期（每日）查询用户收藏分布，更新用户偏好画像。

### 6.4 与反馈评价模块的集成

用户评分作为推荐效果的核心反馈信号：

| 信号类型 | 处理方式 |
|---------|---------|
| 高评分（4-5 星） | 强化该算法在类似场景的推荐权重 |
| 低评分（1-2 星） | 降低该算法在类似场景的推荐权重 |

### 6.5 与会员管理模块的集成

| 集成点 | 说明 |
|--------|------|
| VIP 推荐优先级 | VIP 用户推荐时，experimental 类型算法可进入候选池，且排序权重提升 10% |
| 普通用户过滤 | 普通用户推荐时，experimental 类型算法从候选池中移除 |

## 7. 推荐效果度量

### 7.1 核心指标

| 指标 | 计算方式 | 目标值 | 采集方式 |
|------|---------|--------|---------|
| 推荐采纳率 | 使用推荐算法次数 / 展示推荐次数 | ≥ 40% | 推荐展示/采纳事件打点 |
| 推荐满意度 | 采纳推荐且评分 ≥ 4 的次数 / 采纳推荐次数 | ≥ 70% | 评分事件关联推荐记录 |
| 推荐覆盖率 | 被推荐过的算法数 / 已发布算法总数 | ≥ 60% | 推荐日志统计 |
| 冷启动成功率 | 新算法 7 日内被推荐采纳次数 | ≥ 3 次 | 按算法创建时间统计 |

### 7.2 满意度计算

推荐满意度 = (采纳推荐且评分 ≥ 4 的次数) / (采纳推荐总次数)

| 数据来源 | 说明 |
|---------|------|
| 采纳事件 | 前端调用推荐反馈接口记录，写入 `sys_recommendation.adopted_algorithm_id` |
| 评分事件 | 反馈评价模块的 `sys_rating` 表关联推荐记录 ID |

## 8. 缓存设计

| 缓存对象 | 缓存 Key | TTL | 更新策略 |
|---------|---------|------|---------|
| 图像特征分析结果 | `recommend:feature:{imageMd5}` | 1 小时 | 图像变更时失效 |
| 算法评分缓存 | `recommend:algo:score:{algorithmId}` | 10 分钟 | 评分更新时失效 |
| 规则配置缓存 | `recommend:rules` | 30 分钟 | 规则变更时失效 |
| 用户偏好画像 | `recommend:user:profile:{userId}` | 1 小时 | 用户行为变更时更新 |
