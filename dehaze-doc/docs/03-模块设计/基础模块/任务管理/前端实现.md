# 任务管理模块 - 前端实现设计

## 1. 文档概述

本文档描述任务管理模块的前端实现方案，聚焦组件架构、状态管理、轮询策略等架构决策。

## 2. 组件架构设计

### 2.1 组件层次结构

```
任务管理页面 (TaskManagement/index.vue)
├── 页面头部
│   ├── 页面标题
│   └── 状态筛选器 (StatusFilter)
└── 任务列表区域
    ├── 任务列表 (TaskList)
    │   └── 任务卡片 (TaskCard)
    │       ├── 任务信息区域
    │       ├── 进度条 (ProgressBar)
    │       └── 操作按钮
    └── 分页组件 (Pagination)
```

### 2.2 弹窗组件结构

```
任务详情弹窗 (TaskDetailDialog)
├── 任务基本信息
├── 进度详情
├── 错误信息（失败时）
└── 操作按钮（取消/下载）
```

### 2.3 组件职责划分

| 组件名称 | 职责描述 | 复用性 |
|---------|---------|--------|
| **StatusFilter** | 任务状态筛选器 | 页面内部组件 |
| **TaskList** | 任务列表展示 | 页面内部组件 |
| **TaskCard** | 单个任务展示卡片 | 可复用组件 |
| **ProgressBar** | 任务进度条 | 可复用组件 |
| **TaskDetailDialog** | 任务详情弹窗 | 页面内部组件 |

## 3. 组件详细设计

### 3.1 状态筛选器组件

| 筛选项 | 值 | 说明 |
|--------|-----|------|
| 全部 | null | 显示所有任务 |
| 待执行 | PENDING | 仅显示待执行任务 |
| 执行中 | PROCESSING | 仅显示执行中任务 |
| 已完成 | COMPLETED | 仅显示已完成任务 |
| 失败 | FAILED | 仅显示失败任务 |
| 已取消 | CANCELLED | 仅显示已取消任务 |

### 3.2 任务卡片组件

#### 展示字段

| 字段 | 说明 | 特殊处理 |
|------|------|---------|
| taskId | 任务 ID | 可复制 |
| type | 任务类型 | 类型名称翻译 |
| status | 状态 | 状态标签（带颜色） |
| progress | 进度 | 进度条 + 百分比 |
| createdAt | 创建时间 | 相对时间显示 |
| completedAt | 完成时间 | 相对时间显示 |

#### 状态样式

| 状态 | 标签颜色 | 背景色 |
|------|---------|--------|
| PENDING | 蓝色 | #1890ff |
| PROCESSING | 蓝色 | #1890ff |
| COMPLETED | 绿色 | #52c41a |
| FAILED | 红色 | #ff4d4f |
| CANCELLED | 灰色 | #8c8c8c |

#### 操作按钮

| 状态 | 可用操作 |
|------|---------|
| PENDING | 取消 |
| PROCESSING | 取消 |
| COMPLETED | 下载 |
| FAILED | 查看错误 |
| CANCELLED | - |

### 3.3 进度条组件

| 属性 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| progress | Number | 0 | 进度百分比 (0-100) |
| status | String | 'active' | 进度条状态 |
| showInfo | Boolean | true | 是否显示百分比文字 |

## 5. API 调用设计

### 5.1 SDK 接口

通过 `dehaze-sdk-js` 的 TaskAPI 进行调用：

| 方法 | 功能 |
|------|------|
| TaskAPI.create | 创建任务（支持幂等键） |
| TaskAPI.getStatus | 查询任务状态 |
| TaskAPI.cancel | 取消任务 |
| TaskAPI.retry | 重试失败任务 |
| TaskAPI.download | 下载任务结果 |
| TaskAPI.getPage | 任务列表分页查询 |

### 5.2 请求错误处理

| 错误类型 | 处理方式 |
|---------|---------|
| 任务不存在 | 从列表移除，提示任务已不存在 |
| 无权操作 | 提示无权限 |
| 结果已过期 | 提示结果已过期，禁用下载按钮 |
| 网络错误 | 显示网络连接失败提示 |

## 6. 交互流程设计

### 6.1 页面初始化流程

1. 进入页面，显示加载状态
2. 请求任务列表数据
3. 数据加载完成，渲染列表
4. 启动轮询检测（针对 PENDING/PROCESSING 状态任务）

### 6.2 任务状态轮询机制

```
页面加载 → 获取任务列表
    ↓
筛选出 PENDING/PROCESSING 状态任务
    ↓
每 3 秒轮询更新状态
    ↓
状态变为终态(COMPLETED/FAILED/CANCELLED) → 停止轮询该任务
    ↓
列表中无需轮询任务 → 停止全局轮询
```

#### 轮询配置

| 配置项 | 值 | 说明 |
|--------|-----|------|
| 轮询间隔 | 3000ms | 每 3 秒查询一次 |
| 最大轮询时间 | 30分钟 | 超时后停止轮询 |
| 页面不可见时 | 暂停轮询 | 使用 visibilitychange 事件 |

### 6.3 任务创建流程

任务创建通常由业务模块触发（如数据集导出），任务管理模块负责展示：

```
业务模块调用 TaskAPI.create → 返回 taskId
    ↓
跳转/提示查看任务 → 任务管理页面
    ↓
自动开始轮询任务状态
```

### 6.4 任务取消流程

```
点击取消按钮 → 弹出确认框："确认取消该任务吗？"
    ↓ 确认
调用取消接口 → 更新任务状态为 CANCELLED
    ↓
停止该任务的轮询
```

### 6.5 结果下载流程

```
点击下载按钮
    ↓
检查任务状态是否为 COMPLETED
    ↓ 是
检查结果是否过期
    ↓ 未过期
触发文件下载（新标签页或直接下载）
```

## 7. 性能优化设计

### 7.1 请求优化

| 优化项 | 实现方式 |
|--------|---------|
| 轮询节流 | 控制轮询间隔，避免频繁请求 |
| 批量查询 | 多个任务状态可批量查询（如支持） |
| 页面不可见暂停 | 页面切换到后台时暂停轮询 |
| 离开页面清理 | 组件卸载时清除所有定时器 |

### 7.2 渲染优化

| 优化项 | 实现方式 |
|--------|---------|
| 列表虚拟化 | 大量任务时使用虚拟列表 |
| 状态局部更新 | 轮询返回后仅更新变化的任务 |

### 7.3 用户体验优化

| 优化项 | 实现方式 |
|--------|---------|
| 进度动画 | 进度条平滑动画过渡 |
| 操作反馈 | 取消/下载操作即时反馈 |
| 空状态提示 | 无任务时显示引导信息 |
| 错误重试 | 网络错误时提供重试按钮 |

## 8. 任务创建集成
