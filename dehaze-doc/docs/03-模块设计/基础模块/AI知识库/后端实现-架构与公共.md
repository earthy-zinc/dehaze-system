## 2. 架构设计

### 2.1 模块分层架构

```
Controller 层
├── KnowledgeBaseController    # 知识库 CRUD、配置管理
├── DocumentController         # 文档上传/列表/删除/重新处理
└── SearchController           # 检索接口（内部 + API）

Service 层
├── KnowledgeBaseService       # 知识库生命周期管理
├── DocumentService            # 文档上传、解析编排、状态管理
├── ChunkingEngine             # 分块引擎（多策略）
├── EmbeddingService           # 向量化服务（多模型切换）
├── IndexService               # ES 索引管理（创建/更新/删除）
├── SearchService              # 检索编排（混合检索 + 重排序 + 过滤）
└── SyncService                # 算法管理文档自动同步

依赖模块
├── FileService（文件管理）     # 文件上传/下载/URL拼接
├── AlgorithmService（算法管理）# 算法文档自动同步
└── Elasticsearch              # 向量检索 + 全文检索
```

### 2.2 核心组件职责

| 组件 | 职责 |
|------|------|
| KnowledgeBaseService | 知识库 CRUD、分块/检索策略配置、统计信息维护 |
| DocumentService | 文档上传、解析编排（文档→纯文本）、异步处理状态管理 |
| ChunkingEngine | 多策略分块（固定/语义/递归/问答对/表格感知）、chunk重叠管理 |
| EmbeddingService | 文本向量化、多 embedding 模型切换、批量向量化 |
| IndexService | ES 索引管理：dense_vector 字段 + 全文检索字段 + 元数据字段的索引 CRUD |
| SearchService | 混合检索编排（向量+关键词）、Rerank 重排序、MMR 去重、元数据过滤 |
| SyncService | 监听算法管理模块的变更事件，自动同步更新关联的算法文档 |

## 3. 数据模型

> 表结构与索引定义见 [02-系统架构/03-数据库设计.md](../../../02-系统架构/03-数据库设计.md)（AI 知识库相关表），此处仅说明数据组织决策：

- **知识库/文档/分块** 由三张表构成（知识库配置、文档记录、分块记录），分块记录只追加、文档更新时整批替换
- **向量索引** 按知识库分索引隔离（`kb_chunks_{knowledgeBaseId}`），与分块记录同步写入，供混合检索使用
- 知识库状态（启用/处理中/禁用）与文档处理状态（待处理/处理中/已完成/失败）驱动异步处理流水线

## 4. 异步处理流程

文档上传后，解析/分块/向量化/索引写入全部异步处理：

```
用户上传文档
    ↓
DocumentService.upload(kbId, fileId)
    ↓
创建 sys_knowledge_document（processing_status=pending + file_id）
    ↓
更新 sys_knowledge_base.status=2（处理中）
    ↓
提交异步任务到队列
    ↓
异步工作流：
  1. document.processing_status = processing
  2. FileService.download(fileId) → 原始文件
  3. DocumentParser.parse(file) → 纯文本（OCR/文本提取/表格提取）
  4. ChunkingEngine.chunk(text, strategy) → List<Chunk>
  5. EmbeddingService.batchEmbed(chunks) → List<Vector>
  6. IndexService.batchIndex(chunks + vectors + metadata) → ES
  7. document.processing_status = completed; chunk_count/total_tokens 更新
  8. sys_knowledge_base.status=1; document_count/chunk_count/total_tokens 更新
    ↓
失败处理：
  - 任一步骤失败 → document.processing_status = failed + error
```

**文件内容获取**：通过 `file_id` 关联 `sys_file`，调用 `FileService.getObjectName(fileId)` 获取存储路径，从存储系统读取文件内容。URL 不落库，遵循文件管理规范。

## 5. 缓存策略

| 缓存对象 | 缓存 Key | TTL | 更新策略 |
|---------|---------|------|---------|
| 知识库配置 | `kb:config:{kbId}` | 10 min | 知识库更新时失效 |
| 检索结果 | `kb:search:{kbId}:{queryHash}` | 5 min | 文档/分块变更时失效 |
| embedding 模型实例 | 本地内存 | 应用生命周期 | 启动时加载 |

## 6. 配置项

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `kb.chunk.default-size` | 默认分块大小（token） | 800 |
| `kb.chunk.default-overlap` | 默认分块重叠（token） | 80 |
| `kb.chunk.max-tokens` | 最大分块 token 数 | 2000 |
| `kb.chunk.min-tokens` | 最小分块 token 数 | 50 |
| `kb.search.default-top-k` | 默认检索 Top-K | 5 |
| `kb.search.max-top-k` | 最大检索 Top-K | 50 |
| `kb.search.default-threshold` | 默认相似度阈值 | 0.5 |
| `kb.search.hybrid-rank-constant` | RRF 混合检索 rank_constant | 60 |
| `kb.search.hybrid-rank-window` | RRF 混合检索 rank_window_size | 20 |
| `kb.index.batch-size` | ES 批量索引条数 | 100 |
| `kb.async.max-retry` | 异步处理最大重试次数 | 3 |
