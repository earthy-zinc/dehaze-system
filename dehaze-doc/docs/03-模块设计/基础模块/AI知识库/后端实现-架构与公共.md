## 2. 架构设计

### 2.1 模块分层架构

```
Controller 层
├── KnowledgeBaseController    # 知识库 CRUD、配置管理
├── DocumentController         # 文档上传/列表/删除/重新处理
└── SearchController           # 检索接口（内部 + API）

Service 层
├── KnowledgeBaseService       # 知识库生命周期管理
├── DocumentService            # 文档上传、解析编排、状态管理
├── ChunkingEngine             # 分块引擎（多策略）
├── EmbeddingService           # 向量化服务（多模型切换）
├── IndexService               # ES 索引管理（创建/更新/删除）
└── SearchService              # 检索编排（混合检索 + 重排序 + 过滤）

依赖模块
├── FileService（文件管理）     # 文件上传/下载/URL拼接
└── Elasticsearch              # 向量检索 + 全文检索

被调用方
└── AlgorithmService（算法管理）# 算法文档变更时调用知识库 API 入库（source=algorithm_sync）
```

### 2.2 核心组件职责

| 组件 | 职责 |
|------|------|
| KnowledgeBaseService | 知识库 CRUD、分块/检索策略配置、统计信息维护 |
| DocumentService | 文档上传、解析编排（文档→纯文本）、异步处理状态管理 |
| ChunkingEngine | 多策略分块（固定/语义/递归/问答对/表格感知）、chunk重叠管理 |
| EmbeddingService | 文本向量化、多 embedding 模型切换、批量向量化 |
| IndexService | ES 索引管理：dense_vector 字段 + 全文检索字段 + 元数据字段的索引 CRUD |
| SearchService | 混合检索编排（向量+关键词）、Rerank 重排序、MMR 去重、元数据过滤 |

## 3. 数据模型

> 表结构与索引定义见 [02-系统架构/03-数据库设计.md](../../../02-系统架构/03-数据库设计.md)（AI 知识库相关表），此处仅说明数据组织决策：

- **知识库/文档/分块** 由三张表构成（知识库配置、文档记录、分块记录），分块记录只追加、文档更新时整批替换
- **向量索引** 按知识库分索引隔离（`kb_chunks_{knowledgeBaseId}`），与分块记录同步写入，供混合检索使用
- 知识库状态（启用/处理中/禁用）与文档处理状态（待处理/处理中/已完成/失败）驱动异步处理流水线

## 4. 异步处理流程

文档上传后，解析/分块/向量化/索引写入全部异步处理：

```
用户上传文档
    ↓
DocumentService.upload(kbId, fileId)
    ↓
创建 sys_knowledge_document（processing_status=pending + file_id）
    ↓
提交异步任务（Python：asyncio.create_task + get_db_session 后台协程，持有 task 引用防 GC）
    ↓
异步工作流：
  1. document.processing_status = processing（WebSocket 向知识库 owner 推送）
  2. FileService.download(fileId) → 原始文件（manual/url 直接用 content，跳过解析）
  3. DocumentParser.parse(file) → 纯文本（OCR/文本提取/表格提取，线程池运行不阻塞事件循环）
  4. ChunkingEngine.chunk(text, strategy) → List<Chunk>
  5. EmbeddingService.batchEmbed(chunks) → List<Vector>
  6. IndexService.batchIndex(chunks + vectors + metadata) → ES（doc 含 create_time 支撑时间过滤）
  7. document.processing_status = completed; chunk_count/total_tokens 更新
  8. sys_knowledge_base.status=1; document_count/chunk_count/total_tokens 更新（CAS 原子累加）
    ↓
失败处理：
  - 任一步骤失败 → document.processing_status = failed + error（重试 KB_ASYNC_MAX_RETRY 次后置 failed）
```

**文件内容获取**：通过 `file_id` 关联 `sys_file`，调用 `FileService.getObjectName(fileId)` 获取存储路径，从存储系统读取文件内容。URL 不落库，遵循文件管理规范。

## 5. 缓存策略

| 缓存对象 | 缓存 Key | TTL | 更新策略 |
|---------|---------|------|---------|
| 知识库配置 | `kb:config:{kbId}` | 10 min | 知识库更新时失效 |
| 检索结果 | `kb:search:{kbId}:{queryHash}`；多知识库检索时 `{kbId}` 取排序后的库 ID 列表哈希 | 5 min | 文档新增/删除/重建索引时按 kbId 失效对应缓存 |
| embedding 模型实例 | 本地内存 | 应用生命周期 | 启动时加载 |
| 知识库列表 | `kb:list:{userId}` | 10 分钟 | 知识库创建/删除时失效 |
| 知识库详情 | `kb:detail:{kbId}` | 30 分钟 | 知识库更新时失效 |
| 向量索引 | 持久化存储（ES） | 不缓存 | ES 索引为持久化存储，非缓存层 |

## 7. 权限与可见性控制

| 可见性 | 访问控制 | 校验范围 |
|--------|---------|---------|
| 公开（public） | 全员可检索（只读）；仅管理员可创建/编辑/删除 | 检索不限制用户；写操作校验管理员角色 |
| 私有（private） | 仅 owner 可读写；其他用户不可见、不可检索 | 所有文档管理与检索接口校验 `owner_id = 当前用户` |

- **所有权校验贯穿全流程**：知识库详情、文档上传/列表/删除/重新处理、检索接口均校验当前用户对私有库的所有权
- **检索过滤**：检索接口按当前用户身份过滤可见知识库——私有库仅返回 owner 自己的库，公共库对所有登录用户可见
- 公共知识库不受个人配额限制

## 8. 容量配额管理

按会员等级校验容量上限，权益配置复用会员管理模块：

| 配额项 | 校验时机 | 超出处理 |
|--------|---------|---------|
| 可建私有知识库数（普通 3 / VIP1 10 / VIP2 30 / SVIP 100） | 创建私有知识库时 | 拒绝创建并提示升级会员 |
| 单库文档数上限（500） | 文档上传时 | 拒绝上传 |
| 单库分块数上限（10,000） | 索引构建时 | 拒绝构建并告警 |

- **权益查询**：校验时调用会员管理模块查询当前用户会员等级对应的配额字段，配额字段配置复用会员管理权益配置功能
- 公共知识库不受个人配额限制，由管理员独立管理
- ES 索引大小监控：单库索引超过阈值（默认 1GB）触发告警，管理员可调整分块策略或清理低价值文档

## 9. 并发与事务设计

### 9.1 统计字段原子更新

知识库的 `document_count` / `chunk_count` / `total_tokens` 在文档处理完成时并发更新，采用乐观锁 CAS（compare-and-set）方式原子递增，避免并发覆盖：

- 更新语句携带原值快照，仅当快照与当前值一致时更新；冲突时重试
- 文档处理完成时一次性累加三个字段，不分多次更新

### 9.2 并发重处理与批量上传幂等

| 场景 | 幂等设计 |
|------|---------|
| 同文档并发重处理 | 文档状态锁——仅 `processing_status=failed` 的文档允许重处理，进入处理时先置为 `processing`，处理中再次触发重处理则拒绝 |
| 批量上传重复文件 | 基于 `file_id` 去重，同一知识库下已存在相同 `file_id` 的文档拒绝重复创建 |

### 9.3 跨存储一致性（MySQL ↔ ES）

分块记录写入 MySQL 与 ES 索引跨存储，采用"先写 MySQL 再写 ES + 失败补偿"策略：

1. 分块记录先批量写入 `sys_knowledge_chunk`（MySQL）
2. 再批量写入 ES 索引 `kb_chunks_{kbId}`
3. ES 写入失败时记录补偿任务，由对账任务周期性扫描并重试 ES 索引写入
4. 对账任务以 `document_id` 为单位比对 MySQL 分块记录与 ES 索引文档数，差异项补偿

## 10. 跨模块协作

| 协作模块 | 协作内容 |
|---------|---------|
| 会员管理 | 创建私有知识库、上传文档、索引构建时调用会员模块查询配额，按会员等级校验上限（详见 §8） |
| AI 计费管理 | RAG 检索注入的 Top-K 片段 Token 消耗计入 AI 积分，`bill_type=kb_inject`，随对话输入 Token 计量；知识库管理操作（上传/检索测试）不计费 |
| MCP 能力网关 | 知识库检索注册为 MCP tool `kb_search`，AI 对话及第三方 Agent 经 MCP 网关认证后调用检索能力（详见需求规格 §2.7） |
| 语音交互模块 | 语音问答链路注入知识库检索：ASR 转文本 → 知识库检索 → 注入 LLM prompt → TTS 合成回复 |
| AI 对话模块 | 对话时调用检索注入接口，检索结果按 LLM prompt 格式注入并附带引用溯源 |
| 文件管理 | 文档上传前先经文件管理模块上传文件获取 `file_id`；处理时通过 `file_id` 获取存储路径下载文件 |
| 算法管理 | 算法文档变更时由算法管理模块主动调用知识库文档创建 API 入库（`source=algorithm_sync`），知识库不主动监听算法变更 |

## 11. 非功能需求达成设计

| 指标 | 要求 | 达成设计 |
|------|------|---------|
| 检索延迟 P99 | ≤ 500ms | ES 索引优化（dense_vector + 全文检索字段合理 mapping）+ 检索结果缓存（5min，详见 §5）+ Rerank 仅对 Top-K×2 候选执行 |
| 索引构建吞吐 | ≥ 100 chunks/s | 异步流水线（解析/分块/向量化/索引写入各阶段解耦）+ ES 批量写入（batch-size=100）+ Embedding 批量向量化 |
| 并发检索 | ≥ 50 QPS | 检索线程池隔离 + ES 客户端连接池配置 + 检索缓存命中直接返回 |
| 异步处理可靠性 | 失败自动重试 3 次 | 解析/分块/向量化/索引任一步骤失败重试，耗尽后标记 failed 并保留错误信息 |

## 12. 三端一致性约束

Java/Go/Python 三后端 API 契约完全一致，**Java 为权威实现**，Go/Python 对齐：

- 检索注入接口（内部 `SearchService.search` 与对外 `/api/v1/kb/search`）三端请求/响应结构一致
- ES 索引 mapping、分块策略实现、RRF 混合检索参数（rank_constant/rank_window）三端一致
- 异步处理流水线状态机（pending/processing/completed/failed）三端一致
- 权限与可见性过滤逻辑三端一致（私有库仅创建者可见，公共库全员只读）

## 13. Embedding 模型下线迁移

当 embedding 模型供应商下线模型时的迁移设计：

| 步骤 | 说明 |
|------|------|
| 标注下线 | 标注该模型为"已下线"，禁止新建使用该模型的知识库 |
| 切换模型 | 已有知识库需切换至新 embedding 模型（向量维度随新模型变化） |
| 重建索引 | 批量重新向量化所有分块 + 重建 ES 索引 mapping（dense_vector 维度更新） |
| 迁移工具 | 选择目标 embedding 模型 -> 批量重新向量化 -> 重建 ES 索引 mapping |

## 14. 安全设计

> 权限与可见性控制详见 [§7 权限与可见性控制](#7-权限与可见性控制)，本节补充其他安全维度。

### 14.1 文档安全

| 防护项 | 说明 |
|--------|------|
| 上传格式校验 | 支持 PDF/Word/Excel/PPT/Markdown/TXT/图片，非白名单格式拒绝上传 |
| 文件大小限制 | 单文档大小上限由文件管理模块统一控制 |
| 文档来源校验 | `source` 字段标识文档来源（manual/upload/url/algorithm_sync/experience），URL 导入时校验 URL 合法性与可达性 |

### 14.2 向量数据安全

| 防护项 | 说明 |
|--------|------|
| ES 索引隔离 | 向量索引按知识库分索引隔离（`kb_chunks_{kbId}`），不同知识库的向量数据物理隔离 |
| 索引访问控制 | ES 索引的读写通过知识库 Service 层统一控制，不暴露直接的 ES 访问接口 |
| 索引删除安全 | 知识库删除时同步删除 ES 索引，文档删除时清除关联分块索引，避免残留向量数据 |

### 14.3 管理权限

| 操作 | 权限标识 | 说明 |
|------|---------|------|
| 知识库管理（创建/编辑/删除） | `kb:manage` | 公共知识库管理需管理员角色 + `kb:manage` 权限 |
| 文档管理（上传/删除/重新处理） | `kb:document:manage` | 校验知识库所有权（私有库）或管理员角色（公共库） |
| 检索使用 | 登录用户 | 检索接口按可见性过滤，无需特殊权限标识 |

## 15. 部署要求

### 15.1 Elasticsearch 版本

知识库向量检索（`kb_chunks_{kbId}` 索引）、RRF 混合检索依赖 ES retriever API，需 **ES ≥ 8.14**（retriever/RRF API GA 版本）。

### 15.2 中文全文检索分词

中文全文检索采用 **analysis-ik 插件**（已纳入 docker-compose 编排，见下），`content` / `doc_title` 字段的索引 mapping 使用 ik 推荐组合：

- `analyzer: ik_max_word`（索引侧最大粒度切分，提高召回）
- `search_analyzer: ik_smart`（查询侧粗粒度切分，减少噪声）
- 检索查询无需显式指定 analyzer，`multi_match` 自动使用字段定义的 `search_analyzer`。

**analysis-ik 插件安装（docker-compose 编排）**：docker-compose.yml 中新增 `es-plugin-init` 一次性初始化容器，挂载共享卷 `es-plugins`，首次 `docker compose up` 时自动下载 analysis-ik 8.18.2（与 elasticsearch 版本严格匹配）并解压到 `/usr/share/elasticsearch/plugins/analysis-ik`（幂等：已安装则跳过）；`elasticsearch` 通过 `depends_on: es-plugin-init: condition: service_completed_successfully` 确保插件就绪后再启动。

> 安装生效动作由运维执行 `docker compose up -d elasticsearch`（涉及 ES 重启，开发/部署阶段由人工触发），代码侧不触发。

**旧索引说明**：已有旧索引的 mapping 不可原地修改 analyzer，开发阶段可直接删除旧索引（`delete_kb_index`），新建知识库自动按 ik mapping 生效。向量检索（kNN）与 RRF 融合不受 analyzer 影响，analyzer 仅作用于关键词（standard retriever）检索质量。

> **范围说明**：`ai_memory` 记忆索引未在本期切换 ik 分词范围（如需同样受益属记忆模块后续任务）。
