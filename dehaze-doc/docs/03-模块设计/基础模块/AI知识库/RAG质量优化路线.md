# RAG 质量优化路线（检索质量工程基准）

> 状态：已评审，按阶段推进（2026-09-12 制定）。当前基线：父子分块已实施、
> 本地 Qwen3-Reranker-0.6B 已接入。本路线是后续所有检索质量工作的决策基准，
> 每阶段以 kb_eval 实测数据为推进/终止依据。

## 1. 现状基线（2026-09-12，kb_eval 四代实测）

### 1.1 检索质量演进（Recall@5 / MRR，39 用例 × 4 策略，threshold=0.5）

| 策略 | v1 原始硬剁 | v2 原子独立 | v3 装箱 | **v4 父子分块（现行）** |
|---|---|---|---|---|
| fixed | 0.712 / 0.450 | 0.464 / 0.391 | 0.659 / 0.479 | **0.725 / 0.433** |
| recursive | 0.594 | 0.594 | 0.621 | **0.720 / 0.434** |
| semantic | 0.305 | 0.318 | 0.332 | **0.479 / 0.451** |
| table | 0.548 | 0.486 | 0.547 | **0.585 / 0.521** |

四代 raw 数据归档于 `dehaze-test/kb_eval/reports/`（raw_before_fix /
raw_atomic_split / raw_packed_v1 / raw），可随时离线重放对比。

### 1.2 架构能力清单（已具备）

- 分块：结构感知装箱（围栏/表格原子、字符边界对齐防乱码）+ 父子分块
  （[父子分块设计.md](父子分块设计.md)，child=装箱块检索、parent=小节注入）
- 检索：vector / keyword / hybrid（库级 `hybrid_weight`）+ rerank 开关
  （本地 Qwen3-Reranker-0.6B 已接入，打分单调性实测 0.9989/0.0039/0.0002）
- 模型：本地三模型全 Qwen3-0.6B 家族（chat/embedding/rerank）零外部依赖；
  模型注册表支持外部 embedding/rerank 供应商热切换
- 评估：kb_eval 两阶段体系（collect 真实链路 / evaluate 秒级重放），
  评估发现→引擎修复→硬性不变量沉淀 pytest 的闭环已验证四轮

### 1.3 对标业界的差距（口径声明：自建口径 vs BEIR 不可直接横比）

| 差距 | 性质 | 追赶路径 |
|---|---|---|
| embedding 规模（0.6B vs 4B~8B/商用，通常差 5~15pt） | 产品约束的主动选择 | 注册表接外部模型即享（架构已就绪），值不值由 kb_eval 实测决定 |
| query 形态单一（测试集全是标题式；无 query 改写） | 评估盲区 + 能力缺口 | **阶段 1 先量化**，数据决定改写是否立项 |
| 混合权重静态 | 能力缺口 | **阶段 2 规则版**先行（见 §3 决策依据） |
| rerank 未全量验证 | 待验证 | 阶段 1 合并跑 |
| 无公共基准锚点 | 可比性缺口 | 阶段 4 |

## 2. 决策原则（贯穿所有阶段）

1. **数据先行**：任何能力立项前，先有能量化其收益的评估（P1 是 P2/P3 的前置）
2. **证据边界**：方案复杂度不得超过当前证据支撑（39 条单一形态用例支撑不了 LTR
   训练——规则版是证据边界内能做的最大事，同时是完整版的探路者与数据采集器）
3. **成本纪律**：检索链路有成本的执行（collect ~7 分钟/两策略）只做一次，
   调参/改判定全部走 evaluate 秒级重放
4. **硬性不变量沉淀**：评估发现的确定性规则（乱码=0、coverage=100%、围栏不切断）
   固化进 `tests/service/test_kb_chunking.py`，不留在评估侧当长期断言

## 3. 阶段路线图

### 阶段 1：评估体系扩展（P1，一切的前置）

**目标**：补齐"单一标题式 query"盲区，量化 rerank 真实收益。

1. **多形态测试集**（testset_builder 扩展，~60 条新增）：
   - 模糊口语型（~20 条）："为什么我的文档搜不到"式——真实用户形态
   - 关键词碎片型（~20 条）："配额 不足"式——无语法结构
   - 自然问题句型（~20 条）："如何配置私有库数量上限"式
   - 每条含 query 形态标签，报表按形态分层输出
2. **rerank 对比轮**：同一 collect 窗口跑 rerank 开/关（fixed 策略即可），
   量化 rerank 收益与延迟成本（CPU 节内容单对 1~2s，全量约 10 分钟）
3. **顺带观察项**（父子分块设计预留可调点）：节代表分排序质量（MRR 0.433 vs
   装箱版 0.479 的回退是否在多形态 query 下加剧）、超长节截断频率

**验收**：多形态分层报表 + rerank 收益/延迟数据。**产出决定后续分支走向**。

### 阶段 2：混合检索规则版自适应（P2）

**触发条件**：阶段 1 完成（没有多形态 query 就无法验证自适应价值）。

**为什么规则版先行而不是 LTR 完整版**：
- 训练数据约束：39→约 100 条用例仍远低于 LTR 所需（数千条标注）；
  没有数据的模型版是过拟合随机数，且线上不可解释
- 规则版三重角色：验证问题结构（规则拿到 ≥80% 收益 → 问题本就简单）/ 完整版的
  特征侦察（规则失效处即信号所在）/ 线上数据采集器（每次检索积累
  (query 特征, 权重, 结果质量)，用户点踩是天然标注）

**实现**：检索前按 query 特征分类——含编号/标题实体/代码标识 → 偏关键词
（hybrid_weight 下调）；自然语言疑问句 → 偏向量。分类规则与权重参数由阶段 1
多形态数据校准。落地位置 search_service 检索入口，规则常量化。

**验收与分支**：
- 规则版拿到预期收益 ≥80% → 规则版即终态
- 收益不足或某形态判反 → 信号复杂，凭阶段 1 评估 + 线上积累数据**有证据地**
  立项模型版（LTR/学习融合）

### 阶段 3：数据驱动演进（视阶段 1/2 数据触发，当前不预支）

| 候选项 | 触发证据 | 实现要点 |
|---|---|---|
| query 改写 | 阶段 1 显示模糊 query 召回显著低 | 复用本地 chat 模型做检索前改写；改写结果缓存防重复推理；延迟预算内联 vs 异步预取 |
| embedding 外部供应商实测 | 需要量化"模型规模差距值多少点" | 注册表现有配置能力，接入商用模型跑一轮 kb_eval 对比即可，零代码 |
| 节代表分加权（可调点 A） | 阶段 1 显示 MRR 劣化在多形态下加剧 | 组内 max + 命中数加权，参数由重放调优 |
| LTR 完整版 | 阶段 2 规则失效 + 线上数据积累到位 | 特征工程以规则版失效模式为起点 |

### 阶段 4：公共基准锚点（P3）

选取 C-MTEB 中文检索任务（T2Retrieval / CMedQA）2-3 个 + BEIR 一个子集，
语料移植到 kb_eval 格式走同链路评估——建立"本项目 vs 公共榜"的对外可比数字。
报告必须标注口径差异（任务/语料/判定均非原生口径，仅作方向性锚点）。

## 4. 成本与节奏

| 阶段 | 工作量 | 检索链路执行成本 |
|---|---|---|
| 1 测试集扩展 | 1 天 | collect 2 轮（多形态 + rerank 对比）约 25 分钟 |
| 2 规则版自适应 | 1 天 | evaluate 重放为主，collect 1 轮验证 |
| 3 按触发逐项 | 每项 0.5~2 天不等 | 各自评估 |
| 4 锚点移植 | 1 天 | 语料规模而定 |

## 5. 风险与不变量守护

- 每阶段收尾跑 kb_eval 全量回归（四策略 × 现行测试集），任何指标回退 >0.02
  需定位原因后才合入——**基线只升不降**
- CPU 环境延迟红线：单 query 检索链路（含可选 rerank）P95 ≤ 10s，
  超线先查 rerank 截断与候选量，而非砍功能
- 测试集演进时旧用例不删（追加式），保证四代基线数据永远可重放对比
