# AI 知识库模块 - 后端实现设计（文档管理）

## 1. 文档概述

本文档描述 F-KB-001 知识库管理、F-KB-002 文档管理、F-KB-003 分块与索引的后端实现。

## 2. 知识库管理

### 2.1 创建知识库

```
管理员创建知识库
    ↓
KnowledgeBaseService.create(name, description, config)
    ↓
校验：
  - 权限：公开库需管理员角色，私有库校验会员配额（私有库数上限，按会员等级）
  - embedding 模型是否可用（检查模型供应商配置）
  - 知识库名称不重复（同用户下）
    ↓
创建 sys_knowledge_base 记录
    ↓
初始化 ES 索引（kb_chunks_{kbId}）：
  - 创建索引 mapping（dense_vector + text + keyword + date）
  - dense_vector 维度 = embedding 模型维度
    ↓
返回知识库 ID
```

### 2.2 知识库编辑

可编辑项：名称、描述、检索策略（search_strategy/hybrid_weight/top_k/score_threshold/enable_rerank）
不可编辑：分块策略、embedding 模型（创建后不可修改，否则已有向量不兼容）

### 2.3 删除知识库

```
删除知识库
    ↓
软删除 sys_knowledge_base（deleted=1）
    ↓
软删除关联的所有 sys_knowledge_document（deleted=1）
    ↓
删除 ES 索引（整个 kb_chunks_{kbId} 索引）
    ↓
保留 sys_knowledge_chunk 记录（关联的 document 已软删除，自然不参与检索）
```

## 3. 文档管理

### 3.1 文档上传

```
用户上传文档
    ↓
前置：调用文件管理模块上传文件 → 获取 fileId
    ↓
DocumentService.upload(kbId, fileId, title)
    ↓
校验：
  - 知识库存在且 status != 0
  - 权限：私有库校验 owner_id = 当前用户
  - 配额：单库文档数上限（按会员等级）
  - 文件类型支持（PDF/Word/Excel/PPT/Markdown/TXT/图片）
  - 文件大小不超过限制（默认 100MB）
    ↓
创建 sys_knowledge_document：
  - knowledge_base_id = kbId
  - file_id = fileId
  - title = 文件名（或用户手动指定）
  - parsing_strategy = auto（自动根据文件类型选择）
  - processing_status = pending
    ↓
提交异步处理任务（见 §4 异步处理流程）
    ↓
返回文档 ID + processing_status
```

### 3.2 批量上传与自定义创建

除单文件上传外，支持批量上传、导入网页、自定义文本三种创建方式，均复用 §3.1 的校验与异步处理流水线，差异仅在文档来源与初始内容获取：

| 创建方式 | source 标识 | 内容获取 | 说明 |
|---------|------------|---------|------|
| 批量上传 | upload | 多文件分别调用文件管理上传，逐个创建文档记录 | 基于 `file_id` 去重，同一知识库下已存在相同 `file_id` 的文档拒绝重复创建（幂等） |
| 导入网页 | url | 根据 URL 抓取网页正文（去除导航/广告等噪声），清洗后存为 `content` | 抓取失败时返回错误，不创建文档记录 |
| 自定义文本 | manual | 直接将用户粘贴的文本作为 `content` | 无需文件上传，跳过解析步骤，直接进入分块与向量化 |

### 3.3 文档解析

根据文档格式自动选择解析策略：

| 文件格式 | 解析策略 | 解析工具 |
|---------|---------|---------|
| .pdf（扫描件） | OCR | Tesseract/PaddleOCR → 文字 + 表格区域检测 |
| .pdf（电子档） | 文本提取 | PyMuPDF/PDFPlumber → 文字 + 表格 |
| .docx | 文档解析 | python-docx → 段落 + 表格 |
| .xlsx | 表格感知 | openpyxl → 单元格矩阵 → 结构化文本 |
| .pptx | 幻灯片解析 | python-pptx → 文字 + 备注 |
| .md | 纯文本 | 直接读取 |
| .txt | 纯文本 | 直接读取 |
| .jpg/.png | OCR | Tesseract/PaddleOCR → 文字 |

**OCR 策略**：
- 优先尝试直接文本提取（fast path），提取为空时回退到 OCR
- OCR 结果包含文字和位置信息，支撑引用溯源时的页码/段落定位

### 3.4 表格提取

Excel 和 PDF 表格提取为结构化文本，保留行列语义：

```
原始表格：
| 算法 | PSNR | SSIM | 适用场景 |
| RIDCP | 28.5 | 0.92 | 非均匀雾霾 |
| FFA-Net | 27.1 | 0.89 | 通用去雾 |

→ 提取为结构化文本（携带 metadata 字段: table_rows: 2, table_cols: 4）：
"算法: RIDCP, PSNR: 28.5, SSIM: 0.92, 适用场景: 非均匀雾霾\n
 算法: FFA-Net, PSNR: 27.1, SSIM: 0.89, 适用场景: 通用去雾"
```

## 4. 分块引擎

### 4.1 分块策略实现

#### 固定长度分块 (fixed)

```
按 token 数固定切分：
  - 使用 tiktoken 或 embedding 模型的 tokenizer 计数
  - chunk_size 个 token 一切
  - overlap 个 token 重叠
  - 在换行符或句号处微调边界（不切断句子）
```

#### 语义分块 (semantic)

```
按段落 + 句子语义切分：
  - 先按双换行分段（大块）
  - 段落 token > chunk_size → 在最近句子边界处切分
  - 段落 token < min_tokens → 与下一段合并
  - overlap 只在切分边界处添加
```

#### 递归分块 (recursive)

```
递归按分隔符优先级切分：
  分隔符优先级: "\n\n" → "\n" → "。" → "，" → " "
  - 先尝试最高优先级分隔符
  - 如果 chunk 太大，使用下一级分隔符继续切分
  - overlap 在切分边界添加
```

#### 问答对分块 (qa)

```
按 Q: ... A: ... 模式切分：
  - 识别 Q: 和 A: 标记
  - Q 和 A 分别独立为两个 chunk，chunk_index 相邻
  - metadata 标记 type: "question" / "answer"
  - 检索时问题 chunk 优先匹配，答案 chunk 作为上下文注入
```

#### 表格感知分块 (table)

```
表格作为整体不分块：
  - 检测 <table> / |表头| 模式
  - 整个表格作为单个 chunk（不切分）
  - metadata 标记 {type: "table", rows: N, cols: M}
  - 提取为结构化文本 + 行列元数据
```

### 4.2 分块后处理

| 处理步骤 | 说明 |
|---------|------|
| 最小长度过滤 | chunk token < 50 的片段丢弃或与相邻 chunk 合并 |
| 最大长度限制 | chunk token > 2000 的强制切分 |
| 空白清理 | 去除多余空格和空行 |
| 元数据附加 | 每条 chunk 附加 `{document_id, chunk_index, page, paragraph, type}` |

## 5. 异步处理流水线

### 5.1 处理流程

```
异步任务启动（文档处理）
    ↓
Step 1: 文档状态更新 → processing
    ↓
Step 2: 获取文件内容
  - fileId → sys_file → object_name
  - 调用文件存储下载文件
    ↓
Step 3: 文档解析
  - 根据文件格式/parsing_strategy 选择解析器
  - 提取纯文本 content
  - 提取结构化 raw_content（含表格/代码块）
  - 更新 sys_knowledge_document.content / raw_content
    ↓
Step 4: 文本清洗
  - 去除噪声（HTML 标签、多余空白、不可见字符）
  - 统一编码和换行符
    ↓
Step 5: 分块
  - 根据知识库 chunking_strategy 选择分块器
  - 生成 List<Chunk>，每条含 content + metadata
  - 写入 sys_knowledge_chunk（batch insert）
    ↓
Step 6: 向量化
  - 批量调用 Embedding 模型 API
  - batch-size = 100（可配置）
  - 更新 sys_knowledge_chunk.embedding 和 token_count
    ↓
Step 7: ES 索引
  - 批量写入 ES 索引 kb_chunks_{kbId}
  - 写入 dense_vector + content + metadata + tags
    ↓
Step 8: 统计更新
  - 更新 sys_knowledge_document: processing_status=completed, chunk_count, total_tokens
  - 更新 sys_knowledge_base: document_count+1, chunk_count+N, total_tokens+N
  - 更新 sys_knowledge_base.status=1
    ↓
完成
```

### 5.2 失败处理

| 失败步骤 | 处理 |
|---------|------|
| Step 3 解析失败 | 标记 document.processing_status=failed, error="文档解析失败: {原因}" |
| Step 5 分块失败 | 标记 document.processing_status=failed, error="分块失败: {原因}" |
| Step 6 向量化失败 | 重试 3 次后标记 failed |
| Step 7 ES 索引失败 | 回滚 sys_knowledge_chunk 记录 + 重试索引写入 |

### 5.3 重新处理

```
用户点击"重新处理"失败文档
    ↓
重置 document.processing_status = pending
    ↓
删除该文档旧的 sys_knowledge_chunk 记录
    ↓
删除 ES 中该文档旧的 chunk 索引（by document_id）
    ↓
重新提交异步处理任务
```

## 6. 模块间协作

### 6.1 与文件管理模块

| 集成点 | 说明 |
|--------|------|
| 文件上传 | 文档上传前先通过文件管理模块上传文件，获取 fileId |
| 文件下载 | 文档处理时通过 fileId 获取 object_name，从存储系统下载文件 |
| URL 拼接 | 不落库 URL，需要时通过 FileService.getUrl(fileId) 运行时拼接 |

### 6.2 与算法管理模块

| 集成点 | 说明 |
|--------|--------|
| 算法文档入库 | 算法管理模块在算法新增/更新时，**主动调用知识库文档创建 API** 入库（source=algorithm_sync），知识库不主动监听算法变更，避免双向耦合 |
| 入库边界 | 算法文档变更**触发新增知识库文档**（非重建现有文档），同一算法的多次变更产生多个文档或由算法管理模块自行管理版本 |
| 算法关联 | 算法文档知识通过 metadata.algorithm_id 关联算法 |

**算法文档入库流程（由算法管理模块驱动）**：

```
算法管理模块：算法新增/更新
    ↓
算法管理模块生成算法文档的文本描述：
  - 算法名称、适用场景、参数说明、典型指标、优劣对比
    ↓
算法管理模块调用知识库 API：POST /api/v1/kb/{id}/documents/text
  - source=algorithm_sync
  - metadata.algorithm_id 关联算法
    ↓
知识库 DocumentService 创建 sys_knowledge_document（source=algorithm_sync）
    ↓
触发异步处理流水线（解析/分块/向量化/索引）
```

## 7. 文档版本管理

文档更新保留历史版本，支持回溯（对应需求规格 §2.2.4）：

| 机制 | 说明 |
|------|------|
| 版本递增 | 编辑文档（重新上传文件 / 更新自定义文本）时 `version` +1 |
| 旧版本归档 | 旧版本分块索引归档（不立即删除），不参与默认检索，支持回滚 |
| 版本保留 | 保留最近 5 个版本，超出后清理最旧版本的分块索引（MySQL 记录 + ES 索引） |
| 版本回溯 | 历史版本可通过管理界面查看与恢复，恢复时将对应版本重新设为当前版本并重建索引 |

**版本更新流程**：文档更新触发 → `version`+1 且旧版本分块标记归档 → 新版本走异步处理流水线（解析/分块/向量化/索引）→ 新版本索引就绪后参与检索，旧版本仅可回溯查看 → 版本数超 5 时清理最旧版本分块索引。
