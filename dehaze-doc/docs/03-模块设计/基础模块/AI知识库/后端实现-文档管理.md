# AI 知识库模块 - 后端实现设计（文档管理）

## 1. 文档概述

本文档描述 F-KB-001 知识库管理、F-KB-002 文档管理、F-KB-003 分块与索引的后端实现。

## 2. 知识库管理

### 2.1 创建知识库

```
管理员创建知识库
    ↓
KnowledgeBaseService.create(name, description, config)
    ↓
校验：
  - 权限：公开库需管理员角色，私有库校验会员配额（私有库数上限，按会员等级）
  - embedding 模型是否可用（从 [AI模型管理模块](../AI模型管理/后端实现.md) 注册表校验 `model_type=embedding` 且启用，读取向量维度）
  - 知识库名称不重复（同用户下）
    ↓
创建 sys_knowledge_base 记录
    ↓
初始化 ES 索引（kb_chunks_{kbId}）：
  - 创建索引 mapping（dense_vector + text + keyword + date）
  - dense_vector 维度 = embedding 模型维度
    ↓
返回知识库 ID
```

### 2.2 知识库编辑

可编辑项：名称、描述、检索策略（search_strategy/hybrid_weight/top_k/score_threshold/enable_rerank）
不可编辑：分块策略、embedding 模型（创建后不可修改，否则已有向量不兼容）

### 2.3 删除知识库

```
删除知识库
    ↓
软删除 sys_knowledge_base（deleted=1）
    ↓
软删除关联的所有 sys_knowledge_document（deleted=1）
    ↓
删除 ES 索引（整个 kb_chunks_{kbId} 索引）
    ↓
保留 sys_knowledge_chunk 记录（关联的 document 已软删除，自然不参与检索）
```

## 3. 文档管理

### 3.1 文档上传

```
用户上传文档
    ↓
前置：调用文件管理模块上传文件 → 获取 fileId
    ↓
DocumentService.upload(kbId, fileId, title)
    ↓
校验：
  - 知识库存在且 status != 0
  - 权限：私有库校验 owner_id = 当前用户
  - 配额：单库文档数上限（按会员等级）
  - 文件类型支持（PDF/Word/Excel/PPT/Markdown/TXT/图片）
  - 文件大小不超过限制（默认 100MB）
    ↓
创建 sys_knowledge_document：
  - knowledge_base_id = kbId
  - file_id = fileId
  - title = 文件名（或用户手动指定）
  - parsing_strategy = auto（自动根据文件类型选择）
  - processing_status = pending
    ↓
提交异步处理任务（见 §5 异步处理流水线）
    ↓
返回文档 ID + processing_status
```

### 3.2 批量上传与自定义创建

除单文件上传外，支持批量上传、导入网页、自定义文本三种创建方式，均复用 §3.1 的校验与异步处理流水线，差异仅在文档来源与初始内容获取：

| 创建方式 | source 标识 | 内容获取 | 说明 |
|---------|------------|---------|------|
| 批量上传 | upload | 多文件分别调用文件管理上传，逐个创建文档记录 | 基于 `file_id` 去重，同一知识库下已存在相同 `file_id` 的文档拒绝重复创建（幂等） |
| 导入网页 | url | 根据 URL 抓取网页正文（去除导航/广告等噪声），清洗后存为 `content` | 抓取失败时返回错误，不创建文档记录 |
| 自定义文本 | manual | 直接将用户粘贴的文本作为 `content` | 无需文件上传，跳过解析步骤，直接进入分块与向量化；入口校验：空内容（仅空白）拒绝、字符数超过 `KB_MAX_TEXT_CHARS`(1,000,000) 上限拒绝，正常文档不受影响 |

### 3.3 文档解析

根据文档格式自动选择解析策略：

| 文件格式 | 解析策略 | 解析工具 |
|---------|---------|---------|
| .pdf（扫描件） | OCR | Tesseract/PaddleOCR → 文字 + 表格区域检测 |
| .pdf（电子档） | 文本提取 | PyMuPDF/PDFPlumber → 文字 + 表格 |
| .pdf（复杂文档） | 版面感知（hi_res） | 版面检测 + 阅读顺序恢复 + 区域级解析（见 §3.5） |
| .docx | 文档解析 | python-docx → 段落 + 表格 |
| .xlsx | 表格感知 | openpyxl → 单元格矩阵 → 结构化文本 |
| .pptx | 幻灯片解析 | python-pptx → 文字 + 备注 |
| .md | 纯文本 | 直接读取 |
| .txt | 纯文本 | 直接读取 |
| .jpg/.png | OCR | Tesseract/PaddleOCR → 文字 |

**解析策略分级**：`parsing_strategy` 支持 `fast` / `hi_res` / `ocr_only` 三档，按文档复杂度自动选择：

| 策略 | 说明 | 选择逻辑 |
|------|------|---------|
| `fast` | 快速文本提取，不做版面分析 | 纯文本为主、无复杂表格的文档（默认） |
| `hi_res` | 版面感知解析（见 §3.5） | 算法论文、技术手册、含表格/公式/图片的复杂文档（推荐优先） |
| `ocr_only` | 纯 OCR 识别 | 扫描件、图片型 PDF（兜底） |

**OCR 策略**：
- 优先尝试直接文本提取（fast path），提取为空时回退到 OCR
- OCR 结果包含文字和位置信息，支撑引用溯源时的页码/段落定位

### 3.4 表格提取

Excel 和 PDF 表格提取为结构化文本，保留行列语义：每行输出为"列名: 值"形式的文本行，并携带 `metadata.table_rows` / `table_cols` 记录行列数。

**表格双态入库**：hi_res 解析下表格同时输出 Markdown 文本（供文本检索）与原图（供视觉检索），原图通过文件管理模块存储并记录 `file_id` 到 chunk 的 `metadata.image_file_id`，支撑"以文搜表"与引用跳转原文。

### 3.5 版面感知解析（hi_res）

对复杂 PDF 执行"版面检测 → 阅读顺序恢复 → 区域级解析"链路（对齐 RAGFlow DeepDoc 思路）：

```
PDF → 逐页转图像 → 版面检测（text/table/figure/formula 区域 + bbox）
    → 阅读顺序恢复（多栏检测，按 left→right, top→bottom 排序）
    → 区域级解析：
        ├─ 文本区域 → 文本抽取
        ├─ 表格区域 → 表格结构识别 + 单元格 OCR → Markdown 表格 + 原图
        ├─ 公式区域 → 公式 OCR → LaTeX 文本
        └─ 图片区域 → 图片描述（caption）→ "[Image: 描述]" 文本 + 原图
    → 输出结构化 blocks（每块携带 page/order/type/bbox 元数据）
```

| 区域类型 | 解析方式 | 输出 |
|---------|---------|------|
| 文本 | 直接抽取 | 文本 |
| 表格 | 表格结构识别 + 单元格 OCR | Markdown 表格 + 原图（双态入库） |
| 公式 | 公式 OCR | LaTeX 文本（`$$...$$`） |
| 图片 | 图片描述模型 | `[Image: caption]` 文本 + 原图 |

## 4. 分块引擎

### 4.1 分块策略实现

| 策略 | 切分逻辑 | 写入的元数据 |
|------|------|------|
| 固定长度 (fixed) | 按 embedding 模型的 tokenizer 计数，每 chunk_size 个 token 一切，overlap 个 token 重叠；在换行符或句号处微调边界（不切断句子） | — |
| 语义分块 (semantic) | 先按双换行分段；段落 token > chunk_size 时在最近句子边界切分；段落 token < min_tokens 时与下一段合并；overlap 只在切分边界添加 | — |
| 递归分块 (recursive) | 按分隔符优先级 "\n\n" → "\n" → "。" → "，" → " " 递归切分，chunk 过大则降级到下一级分隔符；overlap 在切分边界添加 | — |
| 问答对 (qa) | 识别 Q: / A: 标记，Q 与 A 各自独立为 chunk 且 chunk_index 相邻；检索时问题 chunk 优先匹配，答案 chunk 作为上下文注入 | `type: question / answer` |
| 表格感知 (table) | 检测 `<table>` / `\|表头\|` 模式，整个表格作为单个 chunk 不切分 | `type: table`、`rows`、`cols` |

### 4.2 分块后处理

| 处理步骤 | 说明 |
|---------|------|
| 最小长度过滤 | chunk token < 50 的片段丢弃或与相邻 chunk 合并 |
| 最大长度限制 | chunk token > 2000 的强制切分 |
| 空白清理 | 去除多余空格和空行 |
| 元数据附加 | 每条 chunk 附加 `{document_id, chunk_index, page, paragraph, type}` |

### 4.3 分块元数据

分块的 `metadata` 承载检索过滤与引用溯源所需的维度：

| 字段 | 说明 |
|------|------|
| `page` / `paragraph` | 原始文档页码与段落，支撑引用溯源定位 |
| `type` | 分块类型（text / table / question / answer） |
| `algorithm_id` / `tags` | 关联算法与标签，支撑元数据过滤 |
| `image_file_id` / `table_rows` / `table_cols` | 版面解析产出的原图与表格行列结构 |
| `entities` / `relations` | 知识图谱关系底座：`entities` 为 `{type, name, ref_id, value}`，`relations` 为 `{type, from, to}`；检索时按 `metadata.entities` / `metadata.relations` 按关系维度过滤，支撑"只看关联 RIDCP 的分块"等关系查询 |

`entities.type` 取值：Algorithm / Paper / Task / Scene / Metric / Dataset / CodeModule / Experience；`relations.type` 取值：SUITABLE_FOR / ACHIEVES / REQUIRES / CITES / COMPARES / EVALUATED_ON / IMPLEMENTS / DEPENDS_ON / RECOMMENDS。

### 4.4 分块预览确认

上传文档时支持在入库前预览分块效果，用户确认后再提交异步处理：

- 调用分块预览接口，输入 `fileId` + 分块配置（chunking_strategy/chunk_size/chunk_overlap），输出分块预览列表（每块 content + token_count + 序号）
- 前端展示分块效果，用户可调整分块配置后重新预览，确认后携带配置提交文档创建
- 分块预览仅做解析 + 分块，不向量化、不写索引，成本可控
- 未确认时按知识库默认分块配置直接入库（不阻塞上传流程）
- 预览接口复用 §3.3 解析与 §4.1 分块引擎，与正式处理链路一致，保证预览即所得

## 5. 异步处理流水线

### 5.1 处理流程

```
异步任务启动（文档处理，非阻塞提交并持有 task 引用防止被提前回收）
    ↓
Step 1: 文档状态更新 → processing（WebSocket 向知识库 owner 推送）
    ↓
Step 2: 获取文件内容
  - fileId → sys_file → object_name（URL 不落库，需访问时运行时拼接）
  - 调用文件存储下载文件（manual/url 来源直接用 content，跳过）
    ↓
Step 3: 文档解析
  - 根据文件格式/parsing_strategy 选择解析器
  - 提取纯文本 content
  - 提取结构化 raw_content（含表格/代码块）
  - 更新 sys_knowledge_document.content / raw_content
    ↓
Step 4: 文本清洗
  - 去除噪声（HTML 标签、多余空白、不可见字符——含 BOM/零宽字符，避免脏字符进入分块与向量索引）
  - 统一编码和换行符
    ↓
Step 5: 分块
  - 根据知识库 chunking_strategy 选择分块器
  - 生成 List<Chunk>，每条含 content + metadata
  - 写入 sys_knowledge_chunk（batch insert）
    ↓
Step 6: 向量化
  - 批量调用 Embedding 模型 API，batch-size = 100（可配置）
  - 更新 sys_knowledge_chunk.token_count（向量仅写入 ES，不落 MySQL）
    ↓
Step 7: ES 索引
  - 批量写入 ES 索引 kb_chunks_{kbId}
  - 写入 dense_vector + content + metadata + tags（含 create_time 支撑时间过滤）
    ↓
Step 8: 统计更新
  - 更新 sys_knowledge_document: processing_status=completed, chunk_count, total_tokens
  - 更新 sys_knowledge_base: document_count+1, chunk_count+N, total_tokens+N（CAS 原子累加，见架构与公共 §9.1）
  - 更新 sys_knowledge_base.status=1
    ↓
完成
```

### 5.2 失败处理

| 失败步骤 | 处理 |
|---------|------|
| Step 3 解析失败 | 标记 document.processing_status=failed, error="文档解析失败: {原因}" |
| Step 5 分块失败 | 标记 document.processing_status=failed, error="分块失败: {原因}" |
| Step 6 向量化失败 | 重试 3 次后标记 failed |
| Step 7 ES 索引失败 | 回滚 sys_knowledge_chunk 记录 + 重试索引写入 |

### 5.3 重新处理

```
用户点击"重新处理"失败文档
    ↓
重置 document.processing_status = pending
    ↓
删除该文档旧的 sys_knowledge_chunk 记录
    ↓
删除 ES 中该文档旧的 chunk 索引（by document_id）
    ↓
重新提交异步处理任务
```

## 6. 模块间协作

| 协作模块 | 集成点 |
|---------|--------|
| 文件管理 | 上传前经文件管理获取 `fileId`；处理时由 `fileId` 取 `object_name` 下载文件；URL 不落库，经 `FileService.getUrl(fileId)` 运行时拼接 |
| 算法管理 | 算法新增/更新时由算法管理模块主动调用文档创建 API 入库（`source=algorithm_sync`），本模块不监听算法变更；入库边界为**新增文档**（非重建现有文档），同一算法的多次变更产生多个文档或由算法管理模块自行管理版本；算法知识通过 `metadata.algorithm_id` 关联算法 |

**算法文档入库流程（由算法管理模块驱动）**：算法管理模块将算法名称、适用场景、参数说明、典型指标、优劣对比组织为文本描述，调用 `POST /api/v1/kb/{id}/documents/text`（`source=algorithm_sync` + `metadata.algorithm_id`）；本模块创建文档记录后触发 §5 异步处理流水线。

## 7. 文档版本管理

文档更新保留历史版本，支持回溯：

| 机制 | 说明 |
|------|------|
| 版本递增 | 编辑文档（重新上传文件 / 更新自定义文本）时 `version` +1 |
| 旧版本归档 | 旧版本分块索引归档（不立即删除），不参与默认检索，支持回滚 |
| 版本保留 | 保留最近 5 个版本，超出后清理最旧版本的分块索引（MySQL 记录 + ES 索引） |
| 版本回溯 | 历史版本可通过管理界面查看与恢复，恢复时将对应版本重新设为当前版本并重建索引 |
| 更新一致性 | 文档更新生成新版本时，旧版本分块从检索索引中移除（仅保留归档记录供回溯），避免残留旧分块干扰检索 |
