| listRolePerms | Set&lt;String&gt; roles | Set&lt;String&gt; | 获取角色权限集合 |

### 4.2 核心业务逻辑

#### 菜单树构建逻辑

**实现思路**:
1. 查询所有菜单数据（根据查询条件过滤）
2. 识别根节点: parentId 不存在于所有 id 集合中
3. 递归构建树形结构: 遍历根节点,查找子节点挂载到 children 字段
4. 按 sort 字段升序排列

**性能优化**:
- 一次性查询所有数据,避免 N+1 查询
- 内存中递归构建,避免多次数据库查询
- 限制菜单层级深度 ≤ 5 层

#### 菜单保存逻辑

**实现步骤**:
1. **参数校验**: 校验必填字段、格式、唯一性
2. **类型处理**:
   - 目录类型: 根目录补全路径前缀,设置 component 为 "Layout"
   - 外链类型: 清空 component
   - 按钮类型: 校验 perm 必填
3. **生成 treePath**: 查询父菜单 treePath,拼接当前 ID（生成规则见下文）
4. **保存数据**: 新增或更新菜单记录
5. **默认授权**: 新增菜单时自动分配给超级管理员角色（ROOT），向 `sys_role_menu` 插入 `(ROOT角色ID, 新菜单ID)` 记录，确保管理员立即可见；其他角色仍需手动分配
6. **刷新缓存**: 清除路由缓存,按受影响角色定向刷新权限缓存（见 5.3）

#### treePath 字段生成规则

**字段作用**：用于快速查询所有子孙节点，支持级联删除。

**生成规则**:
- 根节点：`,{当前ID},`（例如：`,1,`）
- 子节点：`{父节点treePath}{当前ID},`（例如：`,1,2,`）
- 孙节点：`{父节点treePath}{当前ID},`（例如：`,1,2,3,`）

**安全性保障**：treePath 由系统自动生成，不接收用户输入；级联查询使用参数化查询，占位符由数据库驱动自动转义，无 SQL 注入风险。

#### 菜单删除逻辑（逻辑删除）

**实现步骤**:
1. **存在性校验**: 过滤掉已逻辑删除（`deleted=1`）的传入ID，仅对未删ID做存在性校验；存在未删ID在数据库中不存在时抛"菜单不存在"错误。已删ID（如已被级联删除的子孙）直接跳过，避免误报错。
2. **预置数据校验**: 校验待删菜单是否为系统预置菜单，预置菜单不可删除
3. **级联查询**: 一次性查询所有传入ID及其子孙节点（合并去重），通过 treePath 前缀匹配定位子孙（对每个 id 做 OR 条件）
4. **清理角色关联**: 删除所有待删菜单（目标 + 子孙）对应的 `sys_role_menu` 记录，避免孤儿引用
5. **逻辑删除**: 一次性将所有待删菜单标记为 `deleted=1`（UPDATE，非物理 DELETE）
6. **刷新缓存**: 清除路由缓存,按受影响角色定向刷新权限缓存（见 5.3）

**批量删除处理机制**:
- Controller 接收路径参数 `{ids}`（逗号分隔）后整体传入 Service，禁止在循环中逐个调用
- Service 一次性合并传入ID及子孙ID并去重，避免父级删除时级联子孙，后续重复删除时报"菜单不存在"
- 单次事务包装：先删角色关联（依赖子查询定位子孙菜单），再逻辑删除菜单（含子孙）

**安全性**:
- 使用参数化查询,防止 SQL 注入
- treePath 字段提前生成,用户输入不参与 SQL 拼接

#### 路由列表构建逻辑

**实现步骤**:
1. **查询路由数据**: 左连接角色表,获取菜单关联的角色权限
2. **过滤按钮菜单**: 排除 type=4 的按钮类型
3. **递归构建路由树**: 同菜单树构建逻辑
4. **对象转换**: 转换为 RouteVO 对象
   - 路由名称: path 转驼峰命名（如 /user-center → UserCenter）
   - hidden: visible=0 时为 true
   - roles: 逗号分隔的角色编码转数组
   - keepAlive: 菜单类型且 keepAlive=1 时为 true
   - alwaysShow: 目录类型且 alwaysShow=1 时为 true
   - component: 目录类型默认为 "Layout"
5. **缓存结果**: 使用 Redis 缓存,过期时间 1 小时

#### 角色权限查询逻辑

**实现步骤**:
1. 关联查询 sys_menu、sys_role_menu、sys_role 三表
2. 过滤按钮类型菜单（type=4）且 perm 不为空
3. 根据角色编码集合过滤
4. 返回去重后的权限标识集合

### 4.3 事务管理

| 操作类型 | 事务级别 | 说明 |
|---------|---------|------|
| 查询操作 | 只读事务 | 优化数据库性能 |
| 新增菜单 | 读写事务 | 菜单表 + 缓存清除 |
| 更新菜单 | 读写事务 | 菜单表 + 缓存清除 |
| 删除菜单 | 读写事务 | 菜单表 + 关联表 + 缓存清除 |

## 5. 数据访问层设计

### 5.1 Mapper 接口定义

| 方法名 | 参数 | 返回值 | 说明 |
|--------|------|--------|------|
| listRoutes | - | List&lt;RouteBO&gt; | 查询路由列表（关联角色） |
| listRolePerms | Set&lt;String&gt; roles | Set&lt;String&gt; | 查询角色权限集合 |

### 5.2 SQL 设计

#### 查询路由列表（关联角色权限）

**功能**: 查询所有菜单,左连接角色表获取权限信息。

**SQL 逻辑**: 以 `sys_menu` 为主表，左连接 `sys_role_menu` 和 `sys_role`，过滤 `type != 4`（排除按钮类型），按 `sort` 升序返回。多条 role_code 通过 ResultMap 聚合或多值函数合并为 roles 数组。

#### 查询角色权限集合

**功能**: 根据角色编码查询按钮权限标识。

**SQL 逻辑**: `sys_menu` 内连接 `sys_role_menu` 和 `sys_role`，过滤 `type = 4`（仅按钮类型）且 `perm` 非空，按角色编码集合过滤，返回去重的权限标识。

### 5.3 缓存策略

| 缓存对象 | 缓存 Key | 过期时间 | 更新策略 |
|---------|---------|---------|---------|
| 路由列表 | menu:routes | 1 小时 | 菜单变更时删除 |
| 角色权限 | role:perms:{roleCode} | 30 分钟 | 菜单/角色变更时重建 |

**缓存刷新机制**:
1. 菜单新增/修改/删除 → 删除路由缓存 `menu:routes`
2. 菜单新增/修改/删除 → 查询 `sys_role_menu` 获取关联该菜单的角色编码，定向刷新对应角色的权限缓存（`role:perms:{roleCode}`），避免全量刷新
3. 角色菜单分配 → 刷新指定角色权限缓存

## 7. 安全设计

> **权限标识**：详见 [API接口.md - 权限标识汇总](./API接口.md)

### 7.1 防护机制

| 防护项 | 实现方式 | 说明 |
|--------|---------|------|
| SQL 注入防护 | 参数化查询 | 所有用户输入使用参数化占位符 |
| 防重复提交 | Redis 分布式锁 | 新增/修改操作加锁 3 秒 |
| XSS 防护 | 输入过滤 + 输出编码 | 过滤危险标签,HTML 实体编码 |

**treePath 安全性说明**:
- treePath 字段由系统自动生成,不接收用户输入
- 删除时使用参数化查询,基于 treePath 前缀匹配定位子孙菜单
- 占位符由数据库驱动自动转义,无 SQL 注入风险

### 7.2 参数化查询三端实现

| 端 | 占位符 | 说明 |
|----|--------|------|
| Java | MyBatis `#{}` | MyBatis 预编译占位符 |
| Go | `?` | database/sql 标准占位符 |
| Python | SQLAlchemy 参数绑定 / `%s` | 依据 ORM 或驱动选择 |

## 9. 导入导出设计

菜单模块的导入导出由通用导入导出框架统一调度，模块侧实现 `MenuExportHandler` 和 `MenuImportHandler`。通用框架负责文件生成/解析、进度回调、结果上传、任务状态管理，详见[任务管理/后端实现.md](../任务管理/后端实现.md)。

### 9.1 MenuExportHandler

实现 `ExportHandler` 接口，`getModule()` 返回 `"menu"`。

| 方法 | 说明 |
|------|------|
| estimateCount | 根据查询条件估算菜单数据量 |
| export | 查询菜单数据（树形结构导出为扁平结构），通过 callback 回写进度 |
| getFieldConfigs | 返回导出字段配置：菜单名称、父级菜单、类型、路由路径、权限标识、排序、状态 |

### 9.2 MenuImportHandler

实现 `ImportHandler` 接口，`getModule()` 返回 `"menu"`。

| 方法 | 说明 |
|------|------|
| getFieldConfigs | 返回导入字段配置（菜单名称、类型必填） |
| importBatch | 批量导入菜单：校验菜单名称唯一性、按父级菜单 ID 构建树形关系、校验权限标识格式 |
| getTemplateSampleData | 返回模板示例数据 |
