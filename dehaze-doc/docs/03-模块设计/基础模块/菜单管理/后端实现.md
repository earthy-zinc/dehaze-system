# 菜单管理模块 - 后端实现设计

## 1. 文档概述

本文档描述菜单管理模块的后端设计方案，包括核心数据对象、业务逻辑、数据访问与缓存策略。Java / Go / Python 三端实现逻辑一致，Java 为权威来源。

## 2. API 接口设计

接口路径、权限标识与业务错误码见 [API接口.md](./API接口.md)。

## 3. 核心数据对象

查询参数（keywords / perm / path / type / visible）与接口契约一致；列表对象返回菜单树（`children` 递归嵌套），下拉选项返回 `value` / `label` / `children` 级联结构。

### 3.1 表单对象 (MenuForm)

| 字段 | 类型 | 说明 | 校验规则 |
|------|------|------|---------|
| id | Long | 菜单 ID | 更新时必填 |
| parentId | Long | 父菜单 ID | 必填，默认 0 |
| name | String | 菜单名称 | 必填，2-50 字符 |
| type | Integer | 菜单类型 | 必填 |
| path | String | 路由路径 | 菜单/外链类型必填 |
| component | String | 组件路径 | 菜单类型必填 |
| perm | String | 权限标识 | 按钮类型必填 |
| visible | Integer | 显示状态 | 默认 1 |
| sort | Integer | 排序 | 默认 1 |
| icon | String | 菜单图标 | - |
| redirect | String | 跳转路径 | - |
| keepAlive | Integer | 页面缓存 | 默认 0 |
| alwaysShow | Integer | 始终显示 | 默认 0 |

### 3.2 路由对象 (RouteVO)

各端路由生成的统一数据结构，由 `/menus/routes` 返回。

| 字段 | 类型 | 说明 |
|------|------|------|
| path | String | 路由路径 |
| component | String | 组件路径 |
| redirect | String | 跳转路径 |
| name | String | 路由名称 |
| meta | Meta | 路由元信息：title、icon、hidden、roles、keepAlive、alwaysShow |
| children | List&lt;RouteVO&gt; | 子路由 |

## 4. 服务层设计

### 4.1 服务接口定义

| 方法名 | 参数 | 返回值 | 说明 |
|--------|------|--------|------|
| listMenus | MenuQuery | List&lt;MenuVO&gt; | 菜单列表（树形结构） |
| listMenuOptions | - | List&lt;Option&gt; | 菜单下拉选项 |
| listRoutes | - | List&lt;RouteVO&gt; | 路由列表 |
| getMenuForm | Long id | MenuForm | 获取菜单表单数据 |
| saveMenu | MenuForm | boolean | 保存菜单（新增/更新） |
| updateMenuVisible | Long menuId, Integer visible | boolean | 更新菜单显示状态 |
| deleteMenu | Long id | boolean | 删除菜单（级联） |
| listRolePerms | Set&lt;String&gt; roles | Set&lt;String&gt; | 获取角色权限集合 |

### 4.2 核心业务逻辑

#### 菜单树构建逻辑

一次性查询符合条件的全部菜单（避免逐层查询），在内存中按 parentId 递归挂载 `children`，同级按 sort 升序；根节点判定为 parentId 不存在于结果 id 集合中。菜单层级深度限制为 5 层。

#### 菜单保存逻辑

1. **参数校验**：必填字段、格式、名称与权限标识唯一性
2. **类型规范化**：按菜单类型补全或清空路径、组件等字段，并校验该类型的必填项
3. **生成 treePath**：查询父菜单 treePath 拼接当前 ID
4. **保存数据**：新增或更新菜单记录
5. **默认授权**：新增菜单自动分配给超级管理员角色（ROOT），向 `sys_role_menu` 插入 `(ROOT角色ID, 新菜单ID)`，确保管理员立即可见；其他角色仍需手动分配
6. **刷新缓存**：清除路由缓存，按受影响角色定向刷新权限缓存

#### treePath 字段生成规则

用于快速定位子孙节点，支撑级联删除。规则为 `{父节点treePath}{当前ID},`，根节点为 `,{当前ID},`（如 `,1,` → `,1,2,` → `,1,2,3,`）。

#### 菜单删除逻辑（逻辑删除）

1. **存在性校验**：仅对未删除 ID 做存在性校验，缺失时抛"菜单不存在"；已逻辑删除的 ID（如已随父级级联删除的子孙）直接跳过
2. **预置数据校验**：系统预置菜单不可删除
3. **级联查询**：一次性查询所有传入 ID 及其子孙节点（treePath 前缀匹配，合并去重）
4. **清理角色关联**：删除目标菜单及子孙对应的 `sys_role_menu` 记录，避免孤儿引用
5. **逻辑删除**：一次性将待删菜单标记 `deleted=1`，不物理删除
6. **刷新缓存**：清除路由缓存，按受影响角色定向刷新权限缓存

**批量删除策略**：Controller 将逗号分隔的 ID 集合整体传入 Service，Service 在单次事务内合并去重目标与子孙 ID 后统一处理（先清角色关联，再逻辑删除），不在循环中逐个调用。

#### 路由列表构建逻辑

1. 查询菜单并左连接角色关联表，获取每个菜单可见的角色编码
2. 排除按钮类型菜单
3. 递归构建路由树并转换为 RouteVO：
   - 路由名称：path 转驼峰命名（如 `/user-center` → `UserCenter`）
   - hidden：visible=0 时为 true
   - roles：角色编码由逗号分隔字符串转数组
   - keepAlive / alwaysShow：分别在菜单类型、目录类型且对应字段为 1 时为 true
   - component：目录类型默认为 `Layout`

#### 角色权限查询逻辑

关联菜单、角色菜单、角色三表，按角色编码集合过滤出按钮类型且 perm 非空的记录，返回去重后的权限标识集合。

### 4.3 事务管理

| 操作类型 | 事务级别 | 说明 |
|---------|---------|------|
| 查询操作 | 只读事务 | 优化数据库性能 |
| 新增/更新菜单 | 读写事务 | 菜单表 + 缓存清除 |
| 删除菜单 | 读写事务 | 菜单表 + 角色菜单关联表 + 缓存清除 |

## 5. 数据访问层设计

### 5.1 数据访问职责

路由列表与角色权限集合两类跨表查询下沉到数据访问层（Mapper/DAO），其余菜单操作均为单表 CRUD。

### 5.2 查询设计

| 查询 | 设计 |
|------|------|
| 路由列表 | 以 `sys_menu` 为主表左连接 `sys_role_menu`、`sys_role`，排除按钮类型，按 sort 升序；多条 role_code 聚合为 roles 数组 |
| 角色权限集合 | `sys_menu` 内连接 `sys_role_menu`、`sys_role`，仅取按钮类型且 perm 非空，按角色编码集合过滤并去重 |
| 子孙菜单 | 基于 treePath 前缀匹配定位子树，无需递归查询 |

### 5.3 缓存策略

| 缓存对象 | 缓存 Key | 过期时间 | 更新策略 |
|---------|---------|---------|---------|
| 路由列表 | menu:routes | 1 小时 | 菜单变更时删除 |
| 角色权限 | role:perms:{roleCode} | 30 分钟 | 菜单/角色变更时重建 |

**缓存刷新机制**：菜单新增/修改/删除后删除 `menu:routes`；同时查询 `sys_role_menu` 获取关联该菜单的角色编码，仅定向刷新对应角色的 `role:perms:{roleCode}`，避免全量刷新。角色菜单分配时刷新指定角色的权限缓存。

## 7. 安全设计

### 7.1 防护机制

| 防护项 | 实现方式 | 说明 |
|--------|---------|------|
| 防重复提交 | Redis 分布式锁 | 新增/修改操作加锁 3 秒 |
| 越权保护 | 接口级鉴权 | 增删改接口依据菜单模块权限标识校验 |

### 7.2 treePath 与参数化查询

treePath 由系统自动生成，不接收用户输入；级联删除时以参数化占位符做前缀匹配（Java MyBatis `#{}`、Go `?`、Python 参数绑定），用户输入不参与 SQL 拼接。

### 7.3 菜单类型校验

| 类型 | 约束 | 说明 |
|------|------|------|
| 目录 | component 自动设为 `Layout`，补全路径前缀 | 组织菜单结构，无具体页面 |
| 菜单 | path、component 必填 | 对应页面路由，缺失时返回 `A0503` |
| 外链 | path 须为完整 URL，清空 component | 跳转外部系统 |
| 按钮 | perm 必填 | 仅用于权限标识，不参与路由生成 |
| 父级类型限制 | 上级菜单仅可选目录或菜单类型，按钮/外链不可作为父级（返回 `A0503`） | - |

### 7.4 权限标识唯一性

| 策略项 | 说明 |
|--------|------|
| 系统唯一 | perm 在系统内全局唯一，新增/编辑时校验，重复返回 `A0501` |
| 接口鉴权依据 | 后端依据 perm 进行接口级鉴权，perm 变更后定向刷新受影响角色的权限缓存 |

## 9. 导入导出设计

菜单模块的导入导出由通用导入导出框架统一调度，框架负责文件生成/解析、进度回调、结果上传、任务状态管理。模块侧实现两个 Handler，`getModule()` 均返回 `"menu"`。

| Handler | 方法 | 说明 |
|---------|------|------|
| MenuExportHandler | estimateCount | 根据查询条件估算菜单数据量 |
| MenuExportHandler | export | 查询菜单数据（树形结构导出为扁平结构），通过 callback 回写进度 |
| MenuExportHandler | getFieldConfigs | 导出字段：菜单名称、父级菜单、类型、路由路径、权限标识、排序、状态 |
| MenuImportHandler | getFieldConfigs | 导入字段配置（菜单名称、类型必填） |
| MenuImportHandler | importBatch | 批量导入：校验菜单名称唯一性与权限标识格式，按父级菜单 ID 构建树形关系 |
| MenuImportHandler | getTemplateSampleData | 返回模板示例数据 |
