## 4. 服务层设计

### 4.1 服务接口定义

| 方法名 | 参数 | 返回值 | 说明 |
|--------|------|--------|------|
| listMenus | MenuQuery | List&lt;MenuVO&gt; | 菜单列表（树形结构） |
| listMenuOptions | - | List&lt;Option&gt; | 菜单下拉选项 |
| listRoutes | - | List&lt;RouteVO&gt; | 路由列表 |
| getMenuForm | Long id | MenuForm | 获取菜单表单数据 |
| saveMenu | MenuForm | boolean | 保存菜单（新增/更新） |
| updateMenuVisible | Long menuId, Integer visible | boolean | 更新菜单显示状态 |
| deleteMenu | Long id | boolean | 删除菜单（级联） |
| listRolePerms | Set&lt;String&gt; roles | Set&lt;String&gt; | 获取角色权限集合 |

### 4.2 核心业务逻辑

#### 菜单树构建逻辑

**实现思路**:
1. 查询所有菜单数据（根据查询条件过滤）
2. 识别根节点: parentId 不存在于所有 id 集合中
3. 递归构建树形结构: 遍历根节点,查找子节点挂载到 children 字段
4. 返回构建好的菜单树

**性能优化**:
- 一次性查询所有数据,避免 N+1 查询
- 内存中递归构建,避免多次数据库查询

#### 菜单保存逻辑

**实现步骤**:
1. **参数校验**: 校验必填字段、格式、唯一性
2. **类型处理**:
   - 目录类型: 根目录补全路径前缀,设置 component 为 "Layout"
   - 外链类型: 清空 component
   - 按钮类型: 校验 perm 必填
3. **生成 treePath**: 查询父菜单 treePath,拼接当前 ID
4. **保存数据**: 新增或更新菜单记录
5. **刷新缓存**: 清除路由缓存,刷新角色权限缓存

#### 菜单删除逻辑

**实现步骤**:
1. **级联查询**: 使用 treePath 字段查询所有子孙节点
   - SQL: `WHERE id = ? OR CONCAT(',', tree_path, ',') LIKE CONCAT('%,', ?, ',%')`
2. **批量删除**: 一次性删除父菜单及所有子菜单
3. **删除关联**: 删除角色-菜单关联关系
4. **刷新缓存**: 清除路由缓存和角色权限缓存

**安全性**:
- 使用参数化查询,防止 SQL 注入
- treePath 字段提前生成,用户输入不参与 SQL 拼接

#### 路由列表构建逻辑

**实现步骤**:
1. **查询路由数据**: 左连接角色表,获取菜单关联的角色权限
2. **过滤按钮菜单**: 排除 type=4 的按钮类型
3. **递归构建路由树**: 同菜单树构建逻辑
4. **对象转换**: 转换为 RouteVO 对象
   - 路由名称: path 转驼峰命名（如 /user-center → UserCenter）
   - hidden: visible=0 时为 true
   - roles: 逗号分隔的角色编码转数组
   - keepAlive: 菜单类型且 keepAlive=1 时为 true
   - alwaysShow: 目录类型且 alwaysShow=1 时为 true
5. **缓存结果**: 使用 Redis 缓存,过期时间 1 小时

#### 角色权限查询逻辑

**实现步骤**:
1. 关联查询 sys_menu、sys_role_menu、sys_role 三表
2. 过滤按钮类型菜单（type=4）且 perm 不为空
3. 根据角色编码集合过滤
4. 返回去重后的权限标识集合

### 4.3 事务管理

| 操作类型 | 事务级别 | 说明 |
|---------|---------|------|
| 查询操作 | 只读事务 | 优化数据库性能 |
| 新增菜单 | 读写事务 | 菜单表 + 缓存清除 |
| 更新菜单 | 读写事务 | 菜单表 + 缓存清除 |
| 删除菜单 | 读写事务 | 菜单表 + 关联表 + 缓存清除 |

## 5. 数据访问层设计

### 5.1 Mapper 接口定义

| 方法名 | 参数 | 返回值 | 说明 |
|--------|------|--------|------|
| listRoutes | - | List&lt;RouteBO&gt; | 查询路由列表（关联角色） |
| listRolePerms | Set&lt;String&gt; roles | Set&lt;String&gt; | 查询角色权限集合 |

### 5.2 SQL 设计

#### 查询路由列表（关联角色权限）

**功能**: 查询所有菜单,左连接角色表获取权限信息。

**SQL 逻辑**:
```sql
SELECT 
    m.id, m.parent_id, m.name, m.type, m.path, 
    m.component, m.icon, m.sort, m.visible, 
    m.redirect, m.keep_alive, m.always_show,
    r.code AS role_code
FROM sys_menu m
LEFT JOIN sys_role_menu rm ON m.id = rm.menu_id
LEFT JOIN sys_role r ON rm.role_id = r.id
WHERE m.type != 4  -- 排除按钮类型
ORDER BY m.sort ASC
```

**返回处理**:
- 使用 ResultMap 将多条 role_code 聚合为 roles 数组
- 或使用 GROUP_CONCAT 将角色编码拼接为逗号分隔字符串

#### 查询角色权限集合

**功能**: 根据角色编码查询按钮权限标识。

**SQL 逻辑**:
```sql
SELECT DISTINCT m.perm
FROM sys_menu m
INNER JOIN sys_role_menu rm ON m.id = rm.menu_id
INNER JOIN sys_role r ON r.id = rm.role_id
WHERE m.type = 4              -- 仅查询按钮类型
  AND m.perm IS NOT NULL
  AND r.code IN (#{roles})    -- 参数化查询
```

**安全性**: 使用 `#{}` 参数化查询,防止 SQL 注入。

### 5.3 缓存策略

| 缓存对象 | 缓存 Key | 过期时间 | 更新策略 |
|---------|---------|---------|---------|
| 路由列表 | menu::routes | 1 小时 | 菜单变更时删除 |
| 角色权限 | role:perms:{roleCode} | 30 分钟 | 菜单/角色变更时重建 |

**缓存刷新机制**:
1. 菜单新增/修改/删除 → 删除路由缓存 `menu::routes`
2. 菜单新增/修改/删除 → 刷新所有角色权限缓存
3. 角色菜单分配 → 刷新指定角色权限缓存

## 7. 安全设计

> **权限标识**：详见 [API接口.md - 权限标识汇总](./API接口.md)

### 7.1 防护机制

| 防护项 | 实现方式 | 说明 |
|--------|---------|------|
| SQL 注入防护 | 参数化查询 | 所有用户输入使用 `#{}` 占位符 |

- treePath 字段由系统自动生成,不接收用户输入
- 删除时使用参数化查询: `CONCAT(',', tree_path, ',') LIKE CONCAT('%,', #{id}, ',%')`
- #{id} 会被数据库驱动自动转义,无 SQL 注入风险

## 9. 关键实现要点

### 9.1 核心常量定义

| 常量名 | 值 | 说明 |
|-------|-----|------|
| MENU_TYPE_CATALOG | 1 | 目录类型 |
| MENU_TYPE_MENU | 2 | 菜单类型 |
| MENU_TYPE_EXTLINK | 3 | 外链类型 |
| MENU_TYPE_BUTTON | 4 | 按钮类型 |
| ROUTE_CACHE_KEY | "menu::routes" | 路由缓存 Key |
| ROLE_PERMS_PREFIX | "role:perms:" | 角色权限缓存前缀 |

### 9.2 菜单树构建规则

**递归构建逻辑**：
1. 一次性查询所有菜单数据（根据查询条件过滤）
2. 识别根节点：parentId 不存在于所有 id 集合中
3. 递归查找子节点：遍历根节点，查找 parentId 匹配的子节点
4. 按 sort 字段升序排列

**性能优化要点**：
- 避免 N+1 查询：一次性加载所有数据，内存中构建树
- 使用 Stream API 或循环过滤，避免重复查询数据库
- 限制菜单层级深度 ≤ 5 层

### 9.3 treePath 字段生成规则

**字段作用**：用于快速查询所有子孙节点，支持级联删除。

**生成规则**：
- 根节点：`,{当前ID},`（例如：`,1,`）
- 子节点：`{父节点treePath}{当前ID},`（例如：`,1,2,`）
- 孙节点：`{父节点treePath}{当前ID},`（例如：`,1,2,3,`）

**级联删除 SQL 条件**：
```sql
WHERE id = ? OR CONCAT(',', tree_path, ',') LIKE CONCAT('%,', ?, ',%')
```

**安全性保障**：
- treePath 由系统自动生成，不接收用户输入
- 使用参数化查询，#{id} 会被数据库驱动自动转义

### 9.4 路由对象转换规则

**关键字段转换**：
- **路由名称**：path 转驼峰命名（`/user-center` → `UserCenter`）
- **hidden**：`visible=0` 时为 `true`
- **roles**：逗号分隔的角色编码转数组
- **keepAlive**：菜单类型且 `keepAlive=1` 时为 `true`
- **alwaysShow**：目录类型且 `alwaysShow=1` 时为 `true`
- **component**：目录类型默认为 `"Layout"`

**缓存策略**：
- 使用 Redis 缓存路由列表，Key: `menu::routes`
- 过期时间：1 小时
- 刷新时机：菜单新增/修改/删除时删除缓存

### 9.5 缓存刷新规则

**路由缓存刷新**：
- 触发时机：菜单新增/修改/删除
- 操作：删除 Redis Key `menu::routes`
- 下次查询时自动重建缓存

**角色权限缓存刷新**：
- 触发时机：菜单新增/修改/删除、角色菜单分配
- 操作：刷新所有受影响角色的权限缓存
- Key 格式：`role:perms:{roleCode}`

### 9.6 参数化查询要求

**必须使用参数化查询防止 SQL 注入**：
- Java：使用 MyBatis `#{}` 占位符
- Go：使用 `?` 占位符
- Python：使用 SQLAlchemy 参数绑定或 `%s` 占位符

**treePath 级联查询安全性**：
```sql
-- 正确示例（参数化查询）
WHERE CONCAT(',', tree_path, ',') LIKE CONCAT('%,', #{id}, ',%')

-- 错误示例（字符串拼接，有 SQL 注入风险）
WHERE CONCAT(',', tree_path, ',') LIKE '%,' + id + ',%'
```

## 10. 性能优化要点

### 10.1 缓存优化

| 缓存项 | 缓存时长 | 失效策略 |
|--------|---------|---------|
| 路由列表 | 1 小时 | 菜单变更时删除 |
| 角色权限 | 30 分钟 | 菜单/角色变更时重建 |

### 10.2 查询优化

- **树形结构构建**：一次性查询所有数据，内存中递归构建，避免 N+1 查询
- **索引优化**：在 `parent_id`、`sort`、`type` 字段上建立索引
- **字段裁剪**：只查询需要的字段，减少网络传输
- **深度限制**：菜单树深度限制在 5 层以内
