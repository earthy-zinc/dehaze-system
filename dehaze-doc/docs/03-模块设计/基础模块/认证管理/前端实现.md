# 认证管理模块 - 前端实现设计

## 1. 文档概述

本文档描述认证管理模块的前端实现方案，包括登录页面组件设计、状态管理、Token 存储等实现要点。

- **API 接口规范**：参见 [API接口.md](./API接口.md)
- **需求规格**：参见 [需求规格.md](./需求规格.md)
- **UI-UX 设计规范**：参见 [01-产品设计/02-UI-UX设计规范.md](../../../01-产品设计/02-UI-UX设计规范.md)

## 2. 组件架构设计

### 2.1 组件层次结构

```
登录页面 (Login/index.vue)
├── 页面容器
│   ├── 系统标题区域
│   ├── 登录表单组件 (LoginForm)
│   │   ├── 用户名输入框
│   │   ├── 密码输入框
│   │   ├── 验证码区域
│   │   │   ├── 验证码输入框
│   │   │   └── 验证码图片 (可点击刷新)
│   │   └── 登录按钮
│   └── 版权信息区域
```

### 2.2 组件职责划分

| 组件名称 | 职责描述 | 复用性 |
|---------|---------|--------|
| **LoginForm** | 登录表单展示与提交 | 页面内部组件 |
| **CaptchaImage** | 验证码图片展示与刷新 | 可复用组件 |

## 3. 组件详细设计

### 3.1 登录表单组件

#### 表单字段

| 字段 | 类型 | 占位符 | 说明 |
|------|------|--------|------|
| username | 输入框 | "请输入用户名" | 自动获取焦点 |
| password | 密码框 | "请输入密码" | 支持密码可见切换 |
| captchaCode | 输入框 | "请输入验证码" | 4位字符 |

#### 表单校验规则

| 字段 | 校验规则 | 错误提示 |
|------|---------|---------|
| username | 必填 | 请输入用户名 |
| password | 必填 | 请输入密码 |
| captchaCode | 必填 | 请输入验证码 |

### 3.2 验证码组件

| 属性 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| captchaBase64 | String | - | 验证码图片 Base64 数据 |
| loading | Boolean | false | 加载状态 |

| 事件 | 说明 |
|------|------|
| @refresh | 点击图片时触发，刷新验证码 |

## 4. 状态管理设计

### 4.1 页面状态

| 状态字段 | 类型 | 初始值 | 说明 |
|---------|------|--------|------|
| loading | Boolean | false | 登录按钮加载状态 |
| captchaLoading | Boolean | false | 验证码加载状态 |
| captchaKey | String | '' | 验证码缓存键 |
| captchaBase64 | String | '' | 验证码图片数据 |

### 4.2 表单状态

| 状态字段 | 类型 | 初始值 | 说明 |
|---------|------|--------|------|
| username | String | '' | 用户名 |
| password | String | '' | 密码 |
| captchaCode | String | '' | 验证码 |

### 4.3 全局认证状态（Store）

| 状态字段 | 类型 | 持久化 | 说明 |
|---------|------|--------|------|
| accessToken | String | 是 | 访问令牌 |
| user | Object | 否 | 当前用户信息 |
| roles | Array | 否 | 用户角色列表 |
| perms | Array | 否 | 用户权限标识列表 |

## 5. API 调用设计

### 5.1 API 接口封装

使用 `dehaze-sdk-js` 提供的 AuthAPI 进行接口调用：

| 方法 | 功能 | 参数 |
|------|------|------|
| AuthAPI.login | 用户登录 | username, password, captchaKey, captchaCode |
| AuthAPI.logout | 用户注销 | - |
| AuthAPI.getCaptcha | 获取验证码 | - |
| AuthAPI.refreshToken | 刷新令牌 | refreshToken |
| AuthAPI.getCurrentUser | 获取当前用户信息 | - |

### 5.2 请求错误处理

| 错误类型 | 处理方式 |
|---------|---------|
| 验证码错误 | 显示错误提示，自动刷新验证码 |
| 用户名/密码错误 | 显示错误提示，清空密码和验证码 |
| 账户已禁用 | 显示账户禁用提示 |
| Token 过期 | 自动刷新 Token 或跳转登录页 |
| 网络错误 | 显示网络连接失败提示 |

## 6. 交互流程设计

> **交互规范**：详见 [需求规格.md](./需求规格.md) 第 4 节

### 6.1 页面初始化流程

1. 进入登录页
2. 检查是否已登录（Token 有效）
3. 若已登录，跳转首页
4. 若未登录，请求验证码并显示

### 6.2 登录流程

```
用户输入信息 → 点击登录
    ↓
表单校验
    ↓ 校验通过
显示 loading → 调用登录接口
    ↓ 成功
存储 Token → 获取用户权限信息 → 跳转首页
    ↓ 失败
显示错误提示 → 刷新验证码 → 清空验证码输入
```

### 6.3 注销流程

```
点击退出登录 → 弹出确认框
    ↓ 确认
调用注销接口 → 清除 Token 和用户信息 → 跳转登录页
```

### 6.4 Token 自动刷新流程

```
请求拦截器检测 Token 即将过期（剩余 5 分钟内）
    ↓
调用刷新接口获取新 Token
    ↓ 成功
更新本地 Token → 继续原请求
    ↓ 失败
跳转登录页
```

## 7. Token 存储策略

### 7.1 存储位置

| 环境 | 存储方式 | 说明 |
|------|---------|------|
| 开发环境 | localStorage | 方便调试 |
| 生产环境 | 内存 + sessionStorage | 防止 XSS 攻击 |

### 7.2 Token 携带方式

所有需认证的请求在请求头中携带 Token：

```
Authorization: Bearer {accessToken}
```

### 7.3 Token 过期处理

| 场景 | 处理方式 |
|------|---------|
| Token 即将过期 | 自动调用刷新接口 |
| Token 已过期 | 清除本地状态，跳转登录页 |
| 刷新失败 | 清除本地状态，跳转登录页 |

## 8. 权限控制设计

### 8.1 路由守卫

| 检查项 | 处理方式 |
|--------|---------|
| 无 Token | 跳转登录页 |
| Token 无效 | 清除状态，跳转登录页 |
| 无页面权限 | 跳转 403 页面 |

### 8.2 权限信息加载

登录成功后立即调用 `getPermissions` 接口获取：
- 用户基本信息
- 角色列表
- 权限标识列表
- 菜单树（用于动态路由）

## 9. 性能优化设计

### 9.1 请求优化

| 优化项 | 实现方式 |
|--------|---------|
| 防重复提交 | 登录按钮 loading 状态防护 |
| 验证码预加载 | 页面加载时立即请求验证码 |
| Token 刷新队列 | 并发请求时只刷新一次 Token |

### 9.2 用户体验优化

| 优化项 | 实现方式 |
|--------|---------|
| 自动聚焦 | 页面加载后自动聚焦用户名输入框 |
| 回车提交 | 支持回车键提交表单 |
| 错误自动清理 | 重新输入时清除错误提示 |
| 验证码点击刷新 | 验证码图片可点击刷新 |
