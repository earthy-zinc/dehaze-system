# 认证管理模块 - 前端实现设计

## 1. 文档概述

本文档描述认证管理模块的前端实现方案，聚焦登录/注册、API Key 管理、登录日志、多端会话管理等功能的组件架构、状态管理、Session 感知策略与路由设计等架构决策。

## 2. 组件架构设计

### 2.1 功能与组件总览

| 功能点 | 页面/组件 | 说明 |
|--------|----------|------|
| F-AM-001 用户登录 | Login | 登录表单 + 验证码 |
| F-AM-002 用户注销 | 全局布局 | 退出登录入口 |
| F-AM-003 获取验证码 | CaptchaImage | 登录/注册复用 |
| F-AM-005 获取权限信息 | 路由守卫 / Store | 应用启动时加载 |
| F-AM-006 创建 API Key | ApiKeyManagement | 创建弹窗 + 明文一次性展示 |
| F-AM-007 查询 API Key 列表 | ApiKeyManagement | 列表展示（前缀脱敏） |
| F-AM-008 删除/吊销 API Key | ApiKeyManagement | 吊销操作 |
| F-AM-009 用户注册 | Register | 注册表单 + 验证码，成功自动登录 |
| F-AM-010 登录日志查询 | LoginLog | 列表 + 筛选 + 导出 |
| F-AM-011 多端会话管理 | OnlineSession | 会话列表 + 踢出 |

## 3. 组件详细设计

### 3.1 登录表单组件

#### 表单字段

| 字段 | 类型 | 占位符 | 说明 |
|------|------|--------|------|
| username | 输入框 | "请输入用户名" | 自动获取焦点 |
| password | 密码框 | "请输入密码" | 支持密码可见切换 |
| captchaCode | 输入框 | "请输入验证码" | 4位字符 |
| rememberMe | 复选框 | 默认勾选 | 控制会话保持时长 |

#### 表单校验规则

| 字段 | 校验规则 | 错误提示 |
|------|---------|---------|
| username | 必填 | 请输入用户名 |
| password | 必填 | 请输入密码 |
| captchaCode | 必填 | 请输入验证码 |

### 3.2 验证码组件

| 属性 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| captchaBase64 | String | - | 验证码图片 Base64 数据 |
| loading | Boolean | false | 加载状态 |

| 事件 | 说明 |
|------|------|
| @refresh | 点击图片时触发，刷新验证码 |

### 3.3 用户注册组件

#### 表单字段与校验

| 字段 | 类型 | 校验规则 | 错误提示 |
|------|------|---------|---------|
| username | 输入框 | 3-32 位，仅字母、数字、下划线 | 用户名只能包含字母、数字、下划线，3-32位 |
| password | 密码框 | 8-20 位，至少包含字母和数字 | 密码必须包含字母和数字，8-20位 |
| confirmPassword | 密码框 | 与密码一致 | 两次输入的密码不一致 |
| nickname | 输入框 | 1-64 位，不允许纯空格 | 请输入昵称 |
| captchaCode | 输入框 | 必填 | 请输入验证码 |

#### 交互决策

- 注册成功后接口返回会话与用户信息，前端无需再次登录，直接加载权限并跳转首页。
- 登录页与注册页互相提供入口链接，支持用户切换。

### 3.4 API Key 管理组件

#### 列表字段

| 字段 | 列名 | 说明 |
|------|------|------|
| name | 名称 | Key 用途标识 |
| keyPrefix | Key 前缀 | 仅前缀，明文脱敏 |
| expiresAt | 过期时间 | 空表示永不过期 |
| createTime | 创建时间 | - |

#### 创建表单字段

| 字段 | 类型 | 必填 | 校验规则 |
|------|------|------|---------|
| name | 输入框 | ✅ | 不能为空 |
| expiresAt | 日期时间选择器 | ❌ | 不传则永不过期 |

#### 交互决策

- **明文仅展示一次**：创建成功后弹出明文展示弹窗，提供复制按钮并强提示"明文仅此一次展示，请妥善保存"，用户确认关闭后无法再查询明文。
- 列表仅展示 Key 前缀，不展示明文。
- 吊销操作需二次确认，吊销后立即生效并刷新列表。

### 3.5 登录日志组件

#### 搜索条件

| 字段 | 类型 | 说明 |
|------|------|------|
| username | 输入框 | 用户名模糊匹配 |
| loginTime | 日期范围 | 登录时间区间 |
| ip | 输入框 | IP 精确匹配 |
| status | 下拉选择 | 成功/失败 |
| deviceType | 下拉选择 | web/android/flutter/miniprogram |

#### 列表字段

| 字段 | 列名 | 说明 |
|------|------|------|
| username | 用户名 | 登录账号 |
| ip | IP 地址 | 登录来源 IP |
| loginTime | 登录时间 | 登录发生时间 |
| status | 状态 | 成功/失败标签 |
| message | 提示信息 | 失败原因等 |
| deviceType | 设备类型 | 登录端类型 |

#### 交互决策

- 数据范围由后端按角色过滤：管理员查看全量日志，普通用户仅查看本人日志。
- 支持按当前筛选条件导出 Excel。

### 3.6 在线会话管理组件

#### 搜索条件

| 字段 | 类型 | 说明 |
|------|------|------|
| username | 输入框 | 用户名精确匹配 |

#### 列表字段

| 字段 | 列名 | 说明 |
|------|------|------|
| sessionId | 会话标识 | - |
| deviceType | 设备类型 | 登录端类型 |
| loginTime | 登录时间 | - |
| ip | 登录 IP | - |

## 4. 状态管理设计

### 4.1 登录页状态

| 状态字段 | 类型 | 初始值 | 说明 |
|---------|------|--------|------|
| loading | Boolean | false | 登录按钮加载状态 |
| captchaLoading | Boolean | false | 验证码加载状态 |
| captchaKey | String | '' | 验证码缓存键 |
| captchaBase64 | String | '' | 验证码图片数据 |
| rememberMe | Boolean | true | 记住我（默认勾选） |

### 4.2 全局认证状态（Store）

| 状态字段 | 类型 | 持久化 | 说明 |
|---------|------|--------|------|
| user | Object | 否 | 当前用户信息 |
| roles | Array | 否 | 用户角色列表 |
| perms | Array | 否 | 用户权限标识列表 |

> Session 模式下前端不存储任何 Token，认证由会话凭证自动管理。

## 5. 数据流设计

### 5.1 数据获取与操作

登录、注销、注册、验证码、权限信息、API Key 增删查、登录日志查询导出、在线会话查询踢出均通过 SDK 封装的认证接口调用，各页面组件内完成请求与状态管理；登录/注册成功后由 Store 统一加载并缓存权限信息（用户、角色、权限标识、菜单树），供路由守卫与按钮级权限使用。

### 5.2 请求错误处理

| 错误类型 | 处理方式 |
|---------|---------|
| 验证码错误 | 显示错误提示，自动刷新验证码 |
| 用户名/密码错误 | 显示错误提示，清空密码和验证码 |
| 账户已禁用/锁定 | 显示对应提示 |
| 网络错误 | 显示网络连接失败提示 |
| 业务错误 | 显示后端返回的错误信息 |

> 会话失效（401）处理见 §7 Session 感知策略。

## 6. 交互流程设计

### 6.1 应用初始化流程

1. 进入应用
2. 路由守卫检查 Store 中是否已有权限信息
3. 有权限信息 → 直接放行
4. 无权限信息 → 调用权限信息接口验证会话
5. 成功 → 动态生成路由 → 进入系统
6. 失败（401） → 跳转登录页
7. 登录页加载时请求验证码并显示

### 6.2 登录流程

1. 用户输入信息并点击登录
2. 表单校验通过后显示 loading，调用登录接口
3. 成功 → 加载权限信息 → 动态生成路由 → 跳转首页
4. 失败 → 显示错误提示 → 刷新验证码 → 清空验证码输入

### 6.3 注销流程

1. 点击退出登录，弹出确认框
2. 确认后调用注销接口
3. 清空 Store 登录上下文 → 跳转登录页

### 6.4 注册流程

1. 用户填写注册信息并点击注册
2. 表单校验（含确认密码一致性）
3. 校验通过后调用注册接口
4. 成功（返回会话与用户信息）→ 加载权限信息 → 跳转首页（无需再次登录）
5. 失败 → 显示错误提示 → 刷新验证码

### 6.5 API Key 创建流程

1. 点击创建，打开创建弹窗，填写名称/过期时间
2. 调用创建接口
3. 成功（返回明文，仅此一次）→ 弹出明文展示弹窗 → 用户复制保存 → 确认关闭
4. 刷新列表（列表仅展示前缀）

### 6.6 会话踢出流程

1. 查询用户在线会话，点击踢出
2. 二次确认（被踢出端将立即下线）
3. 确认后调用踢出接口 → 刷新列表

## 7. Session 感知策略

### 7.1 登录状态感知

- 前端通过全局 Store 中的用户信息、角色、权限标识感知登录状态，Session 模式下不存储任何 Token。
- 应用启动时路由守卫调用权限信息接口验证会话有效性：成功则加载权限并放行，401 则判定未登录或会话过期。

### 7.2 会话过期处理

| 场景 | 前端处理 |
|------|---------|
| Session 过期（401） | 清空 Store 登录上下文 → 跳转登录页 |
| 主动注销 | 调用注销接口 → 清空 Store → 跳转登录页 |
| 被管理员踢出 | 下次请求收到 401 → 同过期处理 |
| 账户被禁用/删除 | 下次请求收到 401 → 同过期处理 |

### 7.3 凭证携带与续期策略

- Web 端请求需携带 Cookie 凭证，移动端/小程序通过请求头传递会话标识；前端不手动管理凭证。
- 会话续期由后端滑动完成，对前端透明；前端不主动刷新，仅通过 401 响应感知会话失效。
- "记住我"控制会话保持时长（勾选跨会话保留，未勾选关闭浏览器即失效），前端仅通过表单字段传递选择，不感知后端凭证生命周期细节。

## 8. 权限控制设计

### 8.1 路由守卫

| 检查项 | 处理方式 |
|--------|---------|
| 无权限信息且权限接口返回 401 | 跳转登录页 |
| 无页面权限 | 跳转 403 页面 |

### 8.2 权限信息加载

登录或注册成功后立即调用权限信息接口获取：用户基本信息、角色列表、权限标识列表、菜单树（用于动态路由渲染）。

### 8.3 功能权限控制

| 功能 | 权限标识 | 说明 |
|------|---------|------|
| 登录日志查询 | sys:auth:log:list | 管理员全量、普通用户仅本人（后端过滤） |
| 登录日志导出 | sys:auth:log:export | 控制导出按钮可见性 |
| 在线会话查询 | sys:auth:session:list | 控制菜单/页面访问 |
| 在线会话踢出 | sys:auth:session:kick | 控制踢出按钮可见性 |
| API Key 管理 | 需登录态 | 创建/查询/吊销均需登录 |

## 9. 性能优化设计

### 9.1 请求优化

| 优化项 | 实现方式 |
|--------|---------|
| 防重复提交 | 登录/注册按钮 loading 状态防护 |
| 验证码预加载 | 登录/注册页加载时立即请求验证码 |
| 权限信息缓存 | Store 缓存，避免重复加载 |

### 9.2 用户体验优化

| 优化项 | 实现方式 |
|--------|---------|
| 自动聚焦 | 页面加载后自动聚焦用户名输入框 |
| 回车提交 | 支持回车键提交表单 |
| 错误自动清理 | 重新输入时清除错误提示 |
| 验证码点击刷新 | 验证码图片可点击刷新 |
| 记住我默认勾选 | 减少用户操作，提升体验 |
