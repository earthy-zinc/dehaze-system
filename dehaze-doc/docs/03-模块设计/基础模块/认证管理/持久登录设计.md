# 持久登录设计

## 1. 问题分析

### 1.1 现状

当前系统用户每次打开网站或启动 Electron 应用都需要重新登录。

### 1.2 根因

后端已完整实现双 Token 机制（accessToken 2h + refreshToken 7d），但前端未充分利用：无启动时主动刷新、React 缺失刷新机制。

## 2. 方案概述

### 2.1 核心思路

```
登录成功
  ├─ accessToken（2h）-> localStorage / sessionStorage（根据"记住我"选择）
  └─ refreshToken（7d）-> httpOnly Cookie（JavaScript 无法访问，防 XSS 窃取）
       ├─ 勾选"记住我" -> Max-Age=604800（7天，跨会话保留）
       └─ 未勾选 -> Max-Age=-1（会话级，关闭浏览器后清除）

应用启动
  └─ accessToken 不存在 -> 调用 /auth/refresh（浏览器自动携带 Cookie）
       ├─ 成功 -> 获取新 accessToken -> 直接进入系统
       └─ 失败 -> 跳转登录页
```

### 2.2 改动范围

| 层 | 改动内容 |
|----|---------|
| **后端（dehaze-java）** | AuthController 设置/读取/清除 httpOnly Cookie；LoginForm 添加 rememberMe；RefreshTokenForm 放宽校验 |
| **SDK（dehaze-sdk-js）** | axios 实例设置 `withCredentials: true`；`AuthAPI.refreshToken` 参数可选 |
| **Vue/React 前端** | auth.ts 仅管理 accessToken；路由守卫启动时尝试刷新；登录页添加"记住我"复选框 |

## 3. 详细设计

### 3.1 Token 存储策略

| Token | 存储位置 | 安全特性 | 说明 |
|-------|---------|---------|------|
| **accessToken** | localStorage / sessionStorage | JavaScript 可访问 | 短期令牌（2h），根据"记住我"选择存储位置 |
| **refreshToken** | httpOnly Cookie | JavaScript **无法**访问 | 长期令牌（7d），彻底防范 XSS 窃取 |

#### Cookie 属性

| 属性 | 值 | 作用 |
|------|-----|------|
| `HttpOnly` | `true` | JavaScript 无法读取，防 XSS |
| `SameSite` | `Lax` | 防止跨站请求携带（CSRF 防护） |
| `Path` | `/` | 所有 API 端点均可携带 |
| `Max-Age` | `604800`（勾选记住我）/ `-1`（未勾选） | 控制持久化 vs 会话级 |
| `Secure` | 生产环境 `true` | 仅 HTTPS 传输 |

#### "记住我"机制

- **勾选"记住我"**：Cookie `Max-Age=604800`（7天持久化），accessToken 存入 localStorage
- **未勾选**：Cookie `Max-Age=-1`（会话级，关闭浏览器清除），accessToken 存入 sessionStorage
- 通过额外的非 httpOnly Cookie `rememberMe` 记录用户偏好，刷新时据此设置新 Cookie 的 Max-Age

### 3.2 后端改动

#### AuthController

| 端点 | 改动 |
|------|------|
| `POST /login` | 登录成功后设置 `refreshToken` + `rememberMe` 两个 Cookie |
| `POST /refresh` | 优先从 `@CookieValue` 读取 refreshToken，兜底从请求体读取；刷新后设置新 Cookie |
| `POST /logout` | 清除 `refreshToken` + `rememberMe` 两个 Cookie |

#### LoginForm

新增 `rememberMe` 字段（Boolean），控制 Cookie 的 Max-Age。

#### RefreshTokenForm

`refreshToken` 字段移除 `@NotBlank` 约束（使用 Cookie 时请求体可为空）。

### 3.3 前端改动

#### auth.ts（Vue/React 共用）

```typescript
// 仅管理 accessToken
function getAccessToken(): string | null
function setAccessToken(accessToken: string, rememberMe: boolean): void
function clearAccessToken(): void
```

#### 路由守卫

应用启动时，若无 accessToken，直接尝试调用刷新接口（浏览器自动携带 httpOnly Cookie）：

```typescript
let hasToken = getAccessToken();
if (!hasToken) {
  try {
    await userStore.refreshAccessToken(); // Cookie 自动携带
    hasToken = getAccessToken();
  } catch {
    userStore.resetToken();
  }
}
```

#### 请求拦截器 401 处理

accessToken 过期收到 401 时，调用 `refreshAccessToken()`（Cookie 自动携带），成功后重试原请求。

### 3.4 注销流程

```
点击退出登录 -> 确认
  ↓
调用 POST /api/v1/auth/logout
  ├─ 后端将 accessToken 加入 Redis 黑名单
  └─ 后端清除 refreshToken + rememberMe Cookie（Max-Age=0）
  ↓
前端清除 localStorage/sessionStorage 中的 accessToken
  ↓
跳转登录页
```

## 4. 安全设计

### 4.1 安全措施

| 措施 | 说明 |
|------|------|
| **refreshToken httpOnly** | JavaScript 完全无法访问，彻底防范 XSS 窃取 |
| **RefreshToken 轮换** | 每次刷新生成新 refreshToken，旧的立即加入黑名单 |
| **SameSite=Lax** | 防止跨站请求携带 Cookie，抵御 CSRF |
| **Token 类型标识** | refreshToken 包含 `type=refresh`，防止用 accessToken 刷新 |
| **黑名单机制** | 注销/刷新时将旧 token 的 jti 加入 Redis 黑名单 |
| **CORS 白名单** | 后端仅允许白名单 Origin 携带凭证（`allowCredentials=true`） |

### 4.2 风险评估

| 风险 | 等级 | 缓解措施 |
|------|------|---------|
| refreshToken 被盗（XSS） | **低** | httpOnly Cookie，JavaScript 无法读取 |
| CSRF 攻击 | 低 | SameSite=Lax + 后端 CORS 白名单 |
| 用户忘记退出登录 | 低 | refreshToken 7 天后自动过期 |
| accessToken 被盗（XSS） | 中 | 有效期仅 2 小时，影响有限 |

## 5. 后端实现确认

后端（dehaze-java）已实现以下能力：

| 能力 | 实现位置 | 说明 |
|------|---------|------|
| 生成 refreshToken | `JwtUtils.createRefreshToken()` | 包含 `type=refresh`，TTL=7天 |
| 刷新接口 | `POST /api/v1/auth/refresh` | permitAll，支持 Cookie 和请求体两种方式 |
| Token 轮换 | `AuthServiceImpl.refreshToken()` | 旧 refreshToken 加入黑名单 |
| Cookie 设置/清除 | `AuthController` | httpOnly + SameSite=Lax |
| CORS 凭证 | `CorsConfig` | `allowCredentials=true` + Origin 白名单 |

## 6. 验证清单

- [ ] 勾选"记住我"登录 -> 关闭浏览器 -> 重新打开 -> 直接进入系统（7天内）
- [ ] 不勾选"记住我"登录 -> 关闭浏览器 -> 重新打开 -> 跳转登录页
- [ ] accessToken 过期（2h后）-> 自动刷新 -> 无感继续使用
- [ ] refreshToken 过期（7d后）-> 刷新失败 -> 跳转登录页
- [ ] 主动退出登录 -> Cookie 被清除 -> 跳转登录页
- [ ] JavaScript 控制台无法读取 refreshToken（httpOnly 验证）
