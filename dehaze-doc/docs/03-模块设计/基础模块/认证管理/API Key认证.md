## 2. 功能定位

### 2.1 什么是 API Key

API Key 是面向**机器对机器（M2M）调用**与**第三方系统集成**场景的长期身份凭证。与登录签发的 Session 不同，API Key 由用户主动创建并自行保管，**默认永不过期**，适用于脚本调用、定时任务、外部系统对接等无法走交互式登录流程的场景。

### 2.2 与 Session 的对比

| 维度 | Session | API Key |
|------|-----------|---------|
| **签发方式** | 用户名密码登录后自动创建 | 用户在系统中主动创建 |
| **有效期** | 默认 7 天（滑动续期） | 默认永不过期，可选设置过期时间 |
| **适用场景** | 浏览器/客户端交互式会话 | 脚本、定时任务、第三方系统集成 |
| **凭证前缀** | 无固定前缀（UUID） | 固定前缀 `dhak_` |
| **携带方式** | `Cookie: X-Session-Id={sessionId}` | `Authorization: Bearer dhak_xxx` |
| **失效方式** | 过期或注销时删除 | 用户主动删除/吊销 |

### 2.3 核心价值

| 价值维度 | 具体内容 |
|---------|---------|
| **长期凭证** | 默认永不过期，免去频繁登录续期的成本 |
| **机器友好** | 适用于无交互的自动化调用场景 |
| **可吊销** | 用户可随时删除/吊销 Key，立即失效 |
| **跨端统一** | 同一 Key 可在 Java / Go / Python 三个后端服务通用 |

## 3. API Key 管理接口

> 接口遵循全局统一响应格式，详见 [02-系统架构/04-API规范.md](../../../02-系统架构/04-API规范.md)。基础路径为 `/api/v1/auth`。

### 3.1 接口清单

| 路径 | 方法 | 功能描述 | 访问控制 |
|------|------|---------|---------|
| `/api/v1/auth/api-keys` | POST | 创建 API Key | 需登录态 |
| `/api/v1/auth/api-keys` | GET | 查询当前用户的 API Key 列表 | 需登录态 |
| `/api/v1/auth/api-keys/{id}` | DELETE | 删除/吊销指定 API Key | 需登录态 |

### 3.2 创建 API Key

**请求参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| name | String | 是 | API Key 名称，用于标识用途 |
| expiresAt | String | 否 | 过期时间；不传则默认永不过期 |
| dailyQuota | Long | 否 | Key 级日调用配额；不传或 0 表示不限制（Python 端兼容 API 治理已支持，详见 [第三方兼容 §2.3](../../03-模块设计/核心模块/AI对话/后端实现-第三方兼容.md)） |
| monthlyQuota | Long | 否 | Key 级月调用配额；不传或 0 表示不限制 |
| rpmLimit | Integer | 否 | 每分钟调用频率上限；不传或 0 表示不限制 |
| modelWhitelist | Array&lt;String&gt; | 否 | 模型白名单（启用模型 ID 列表）；不传表示继承用户可见模型 |

**响应要点**：创建成功后返回 Key 明文（`apiKey`，前缀 `dhak_`）及其 ID、名称、过期时间。

> **治理说明**：`dailyQuota`/`monthlyQuota`/`rpmLimit`/`modelWhitelist` 为 F-M08-010 第三方兼容接入治理扩展字段，仅影响兼容 API（`/api/v1/chat/completions`、`/api/v1/messages`、`/api/v1/models`）调用：配额计数走 Redis 固定窗口、超限返回官方语义 429、白名单外模型返回 403；计数与用户积分配额双轨独立。

> **重要**：`apiKey` 明文仅在创建成功时返回**一次**，服务端只存储其哈希值，无法再次查询。请务必妥善保存，丢失后只能删除并重新创建。

### 3.3 查询 API Key 列表

**响应要点**：返回当前用户的 Key 列表，仅包含 Key 前缀（`keyPrefix`，如 `dhak_a1b2`）用于辨识，**不返回明文 Key**。

### 3.4 删除/吊销 API Key

**说明**：删除后该 Key 立即失效，使用该 Key 的后续请求将被拒绝。删除操作不可恢复。

## 4. 使用 API Key 进行认证

创建 API Key 后，在请求头中通过 `Authorization: Bearer dhak_xxx` 携带凭证调用各业务接口。服务端由独立的 API Key 认证过滤器/中间件识别 `dhak_` 前缀的凭证，走 API Key 校验分支：计算凭证的哈希值并与库中存储的哈希比对，校验通过后以 Key 所属用户身份继续后续鉴权流程。

### 4.1 哈希缓存策略

为降低高频 M2M 调用下的数据库哈希查询压力，认证通过后缓存哈希到 userId 的映射：

| 缓存对象 | 缓存 Key | 数据类型 | 过期时间 | 更新策略 |
|---------|---------|---------|---------|---------|
| API Key 哈希映射 | `apikey:hash:{hash}` | String (userId) | 10 分钟 | 首次认证写入；Key 删除/吊销时主动删除 |

认证时优先查询缓存，命中则跳过 DB 查询；未命中时回源数据库并回写缓存。Key 被删除或吊销时同步清理缓存，确保失效即时生效。

### 4.2 AI 计费配额协作

API Key 认证通过后，userId 随 `SecurityContext` 注入请求上下文。AI 计费模块在处理 M2M 调用时，从上下文提取 userId 校验调用配额，配额超限时拒绝请求。此约定确保 M2M 调用既完成身份认证又受配额约束，三端后端在认证通过后均以相同方式注入 userId。

## 5. 跨后端支持

API Key 认证在 **Java / Go / Python** 三个后端服务中通用，三端共享同一份 API Key 存储（数据库），校验逻辑保持一致：

| 后端 | 校验入口 | 说明 |
|------|---------|------|
| **Java** | `ApiKeyAuthenticationFilter`（独立 Filter） | 识别 `dhak_` 前缀后走 API Key 校验分支 |
| **Go** | `ApiKeyAuthMiddleware`（独立中间件） | 与 Java 共享数据库，校验逻辑一致 |
| **Python** | `ApiKeyAuthMiddleware`（独立 ASGI 中间件） | 算法服务复用同一 Key 体系 |

> **说明**：用户只需创建一个 API Key，即可在任意后端服务发起的接口调用中使用，无需为不同后端分别创建凭证。

## 6. 安全设计

| 安全措施 | 说明 |
|---------|------|
| **明文仅展示一次** | API Key 明文仅在创建成功时返回一次，之后无法再查询 |
| **哈希存储** | 服务端仅存储 API Key 的哈希值，不存储明文 |
| **可吊销** | 用户可随时删除/吊销 Key，删除后立即失效 |
| **可选过期时间** | 支持创建时设置 `expiresAt`，到期后自动失效 |
| **归属隔离** | 用户只能查询和删除自己创建的 API Key |
| **前缀辨识** | 列表仅返回 Key 前缀，避免明文泄露 |

### 6.1 使用建议

| 建议项 | 说明 |
|--------|------|
| **妥善保存** | 创建后立即保存明文 Key，丢失只能重建 |
| **按需设过期** | 临时用途的 Key 建议设置 `expiresAt` |
| **最小化创建** | 不同用途创建独立 Key，便于单独吊销 |
| **及时吊销** | 不再使用或疑似泄露时立即删除 |
| **HTTPS 传输** | 生产环境强制使用 HTTPS，避免凭证被截获 |

## 7. 业务错误码

| 错误码 | 说明 | 触发场景 |
|--------|------|---------|
| `A0301` | 访问未授权 | API Key 无效、已吊销或已过期 |
| `A0400` | 用户请求参数错误 | 创建时缺少 `name` 等必填参数 |
| `A0401` | 请求资源不存在 | 删除的 API Key ID 不存在或不属于当前用户 |
