## 3. 组件详细设计

### 3.1 评分卡片组件

#### 触发时机

- 处理完成后首次进入对比页
- 底部弹出评分卡片
- 用户可点击"跳过"或"评价"

#### 组件属性

| 属性 | 类型 | 说明 |
|------|------|------|
| predLogId | Long | 处理记录ID |
| algorithmName | String | 算法名称 |
| visible | Boolean | 可见性 |

#### 表单字段

| 字段 | 类型 | 必填 | 校验规则 |
|------|------|------|---------|
| rating | 星级选择 | ✅ | 1-5 |
| comment | 文本域 | ❌ | 最多500字符 |
| tags | 标签多选 | ❌ | 最多5个 |
| imageUrls | 图片上传 | ❌ | 最多3张，≤5MB |
| isAnonymous | 开关 | ❌ | 默认关闭 |

#### 交互流程

1. 进入对比页，检查是否有评价
2. 未评价则弹出评分卡片（可关闭）
3. 选择星级（鼠标悬停预览）
4. 可选：选择标签、输入文字、上传图片
5. 点击"提交评价"
6. 成功 → 卡片消失，Toast 提示"评价成功"
7. 失败 → 显示错误信息

### 3.2 标签选择组件

#### 标签预设

| 评分 | 可选标签 |
|------|---------|
| 4-5星（正面） | 去雾彻底、色彩自然、细节清晰、处理快速、效果显著 |
| 1-2星（负面） | 残留雾气、色彩失真、细节丢失、处理缓慢、无明显效果 |
| 3星（中性） | 两类标签均可选 |

#### 交互

- 点击标签切换选中/取消
- 选中样式：填充背景色
- 取消样式：边框样式

### 3.3 图片上传组件

#### 组件属性

| 属性 | 类型 | 说明 |
|------|------|------|
| maxCount | Number | 最大数量（默认3） |
| maxSize | Number | 单张大小MB（默认5） |
| accept | String | 接受的文件类型 |

#### 交互

- 拖拽上传：支持拖拽文件到上传区域
- 点击上传：点击区域选择文件
- 预览：上传成功后显示缩略图
- 删除：点击缩略图右上角删除按钮
- 进度：上传中显示进度条

#### 校验

| 校验项 | 规则 | 错误提示 |
|--------|------|---------|
| 文件类型 | image/jpeg, image/png, image/webp | "仅支持 JPG/PNG/WEBP 格式" |
| 文件大小 | ≤5MB | "单张图片不超过5MB" |
| 数量 | ≤maxCount | "最多上传3张图片" |

### 3.4 反馈表单组件

#### 表单字段

| 字段 | 类型 | 必填 | 校验规则 |
|------|------|------|---------|
| feedbackType | 下拉选择 | ✅ | 功能建议/问题报告/体验反馈/投诉 |
| title | 输入框 | ✅ | 5-50字符 |
| content | 文本域 | ✅ | 10-1000字符 |

#### 提示

- 联系方式字段提示："仅管理员可见"
- 内容字段实时字符计数

### 3.5 处理时间线组件

#### 时间线节点

| 节点 | 显示内容 |
|------|---------|

#### 交互

- 点击节点可定位到详情
- 回复内容支持图片预览

## 6. 交互流程设计

### 6.1 评价提交流程

1. 处理完成，用户进入对比页
2. 检查是否已评价（调用 `getRatingByPrediction`）
3. 未评价 → 弹出评分卡片
4. 用户选择星级、标签、文字、图片
5. 点击"提交评价"
6. 调用 `createRating`
7. 成功 → 卡片消失，Toast 提示
8. 失败 → 显示错误信息，保留输入

### 6.2 反馈提交流程

1. 用户点击"反馈"入口
2. 填写反馈表单
3. 实时字符计数
4. 上传图片（可选）
5. 点击"提交"
6. 校验通过 → 调用 `createFeedback`
7. 成功 → 跳转反馈列表，Toast 提示
8. 失败 → 显示错误信息

### 6.3 关键流程说明

| 流程 | 关键点 |
|------|--------|
| 评价提交 | 校验 → 提交 → 成长值获取 → Toast |
| 反馈补充 | 已回复反馈 → 补充 → 状态重开 |
| 评价隐藏 | 二次确认 → 提交 → 刷新列表 |
| 评价回复 | 富文本编辑 → 提交 → 通知用户 |
| 反馈分配 | 选择处理人 → 提交 → 状态变更 |
| 反馈关闭 | 选择关闭原因 → 提交 → 状态变更 |

## 9. 性能优化设计

### 9.1 请求优化

| 优化项 | 实现方式 |
|--------|---------|
| 防抖处理 | 搜索输入防抖 300ms |
| 节流处理 | 评价/反馈提交节流 3000ms |
| 并行请求 | 详情页并行加载评价与回复 |
| 请求取消 | 路由切换时取消未完成请求 |
| 统计缓存 | 评价/反馈统计缓存 10 分钟 |

### 9.2 渲染优化

| 优化项 | 实现方式 |
|--------|---------|
| 评价列表 | 虚拟滚动优化大量数据 |
| 图片懒加载 | IntersectionObserver |
| 星级组件 | 纯CSS实现，避免JS计算 |
| 标签组件 | 静态配置，无请求 |

### 9.3 缓存策略

| 数据类型 | 缓存位置 | 过期策略 |
|---------|---------|---------|
| 评价统计 | Pinia Store | 10 分钟 |
| 反馈统计 | Pinia Store | 10 分钟 |
| 标签预设 | 静态配置 | 永久 |
| 算法列表 | Pinia Store | 30 分钟 |
