# 反馈评价模块 - 后端实现设计

### 3.3 低分告警服务 (LowRatingAlertService)

| 方法名 | 参数 | 说明 |
|--------|------|------|
| checkAndAlert | Rating | 触发低分告警判断 |
| sendNormalAlert | Rating | 普通告警（评分≤2） |
| sendUrgentAlert | Long algorithmId | 紧急告警（评分=1 且同算法 24h 低分≥3） |
| sendSevereAlert | - | 严重告警（当日评价数≥10 且全局低分率>20%） |

#### MQ 队列与路由

三端统一使用队列名/路由键 `feedback.low_rating`。评价创建时若 `rating ≤ 2`，异步发布评价 ID 到该队列，由低分告警消费者消费并执行告警判断（消息体仅携带 ratingId，消费时重新查询评价）。

#### 告警接收人

低分告警通知接收人为 `ROOT` 和 `ADMIN` 角色用户（通过 `sys_role.code IN (root, ADMIN)` 关联 `sys_user_role` 查询用户ID去重）。

#### 告警消息字段（MessageService.send 站内信）

| 字段 | 普通告警 | 紧急告警 | 严重告警 |
|------|---------|---------|---------|
| bizModule | `feedback` | `feedback` | `feedback` |
| bizId | `{ratingId}:normal` | `{algorithmId}:urgent` | `{日期}:severe` |
| type | `alert` | `critical_alert` | `critical_alert` |
| priority | 3 | 1 | 2 |
| title | 低分评价提醒 | 算法低分紧急告警 | 全局低分率严重告警 |

> priority 数字越小越紧急：紧急=1，严重=2，普通=3。紧急和严重告警统一使用 `critical_alert` 类型。bizId 携带唯一标识用于消息去重。消息队列未启用时跳过告警发送，不影响评价提交。

### 3.4 核心业务逻辑

#### 评价创建逻辑

1. **图片安全**：校验 URL 为 MinIO 域名（`file.baseUrl` 前缀）、数量 ≤3、扩展名 jpg/jpeg/png/webp
2. **处理记录校验**：根据 `predLogId` 查询处理记录，不存在抛 `A0566`
3. **状态校验**：处理记录状态必须为已完成（`status == COMPLETED`），否则抛 `A0567`
4. **归属校验**：处理记录必须属于当前用户（`predLog.createBy == 当前用户ID`），否则抛 `A0567`
5. **唯一性校验**：预测日志ID 唯一约束 + 计数校验防止重复评价，已评价抛 `A0560`
6. **时限校验**：基于处理记录的 `update_time`（完成时间），距今超过 30 天抛 `A0562`
7. **写入评价**：插入 `sys_rating`（rating/comment/tags/image_urls/is_anonymous/is_hidden=0）
8. **失效统计缓存**：删除全局/算法统计缓存键
9. **成长值奖励**：`tryGrantGrowth`——先对 `rating:daily:{userId}:{date}` 原子 INCR（25h TTL），再判断计数是否 ≤ 上限：未超限则调用 `memberService.adjustGrowth(+5)`（成长值日志 `change_type=rating`），超限则 DECR 回退并跳过发放。成长值调整为评价创建事务外的独立操作，失败仅记日志，不回滚评价
10. **触发低分告警**：`rating ≤ 2` 时通过 RabbitMQ 发布 `feedback.low_rating` 消息（MQ 未启用时跳过）

> **跨用户越权**：评价归属校验不通过时抛 `A0567`（处理记录非本人）。

#### 评价修改逻辑

1. **图片安全**：同创建逻辑
2. **评价存在校验**：根据 `id` 查询评价，不存在抛 `A0561`
3. **归属校验**：评价必须属于当前用户，不通过抛 `A0561`（不暴露评价是否存在）
4. **更新写入**：更新 rating/comment/tags/image_urls/is_anonymous 字段
5. **失效统计缓存**：删除全局/算法统计缓存键

> 评价修改**不校验 30 天时限**（时限仅约束创建）、**不发放成长值**、**不触发低分告警**。

#### 反馈创建逻辑

1. **图片安全**：校验 URL 为 MinIO 域名、数量 ≤5、扩展名 jpg/jpeg/png/webp
2. **频率限制**：每用户每日 ≤5 条（Redis `feedback:daily:{userId}:{date}` 计数，先 INCR 再判断是否 >5，25h TTL），超限则 DECR 回退并抛 `A0565`
3. **写入反馈**：插入 `sys_feedback`，默认 status=pending(1)、priority=1
4. **失效统计缓存**：删除反馈统计缓存键

> **说明**：创建反馈无通知推送。

#### 反馈回复/分配/关闭/补充/标签

- **回复**：插入 `sys_feedback_reply`（replier_type=2 管理员），状态置 replied(3)；未分配时自动分配给自己并记录分配时间；已关闭反馈抛 `A0564`
- **分配**：写入 assignee_id/assigned_time；仅当 status=pending(1) 时置为 processing(2)，其余状态仅更新分配字段不回退
- **关闭**：置 status=closed(4)、写入 close_reason；已关闭抛 `A0564`
- **补充**：插入回复记录（replier_type=1 用户、reply_type=info）；已关闭抛 `A0564`；当状态为 replied(3) 时回退为 processing(2)（重新打开）
- **标签**：更新 tags JSON 数组（自由文本，无预设约束）

#### 反馈状态流转

```
pending(1) → processing(2)（分配）→ replied(3)（回复）→ closed(4)（关闭）
     ↕                 ↑（用户补充回退）
  replied(3) ←（回复）
```

> `assignFeedback` 仅在 `status==1`（pending）时才置为 `2`（processing）；`supplementFeedback` 在 `status==3`（replied）时回退为 `2`（processing）。

> **用户侧通知能力边界**：反馈状态变更（回复/分配/关闭/补充）当前仅更新状态，不推送用户侧通知。消息通知接口（`MessageService.send`）已封装（低分告警已使用），反馈状态流转未接入用户侧通知推送。

#### 数据隔离与越权处理统一规范

| 接口 | 越权场景 | 统一错误码 | 说明 |
|------|---------|-----------|------|
| 修改评价 `PUT /ratings/{id}` | 评价属于其他用户 | `A0561` | 不暴露评价是否存在 |
| 按处理记录查评价 `GET /ratings/by-prediction/{id}` | 处理记录属于其他用户 | `A0567` | 防止枚举他人评价 |
| 反馈详情 `GET /feedback/{id}` | 反馈属于其他用户（非管理员） | `A0563` | 不暴露反馈是否存在 |
| 补充说明 `POST /feedback/{id}/supplement` | 反馈属于其他用户 | `A0563` | 不暴露反馈是否存在 |

> 越权场景统一返回 `NOT_FOUND` 类错误码，避免通过错误码差异探测资源是否存在。反馈详情中非管理员（含反馈所有者）**不返回** `contact` 字段（联系方式仅管理员可见）。

### 3.5 事务管理

| 操作类型 | 事务说明 |
|---------|---------|
| 评价创建 | 主事务仅写入评价；成长值调整为事务外独立操作（失败仅记日志，不回滚评价） |
| 评价修改/隐藏/回复 | 单表更新 |
| 反馈创建/回复/分配/关闭/补充/标签 | 写入 + 状态更新 |
| 低分告警 | 异步消息队列处理，无事务 |

## 4. 数据访问层设计

> 表结构与索引定义见 [03-数据库设计.md](../../../02-系统架构/03-数据库设计.md) §4.5，此处仅说明查询优化关注点：评价/反馈/回复表均建立覆盖查询条件的索引（防重、筛选、时间范围、归属），分页查询走索引。

### 4.1 缓存策略

| 缓存对象 | 缓存 Key | 过期时间 | 说明 |
|---------|---------|---------|------|
| 评价统计（全局） | rating:stats:global | 10 分钟 | 无时间范围查询时缓存；创建/修改评价时删除 |
| 评价统计（算法） | rating:stats:algorithm:{id} | 10 分钟 | 预留键，创建/修改评价时删除（当前仅删除未读取） |
| 算法评价聚合 | algorithm:rating:{id} | 30 分钟 | 预留键，创建/修改评价时删除（当前仅删除未读取） |
| 反馈统计 | feedback:stats | 10 分钟 | 无时间范围查询时缓存；反馈创建/回复/分配/关闭/补充时删除 |
| 评价成长值日计数 | rating:daily:{userId}:{date} | 25 小时 | 自动过期 |
| 反馈日计数 | feedback:daily:{userId}:{date} | 25 小时 | 自动过期 |
| 评价状态 | `rating:status:{userId}:{targetId}` | 30 分钟 | 创建/修改评价时失效 |
| 反馈列表 | - | 不缓存 | - |

> **缓存失效范围**：评价创建、评价修改改变评价统计（评分值/标签/总数），需删除评价统计缓存；`hideRating`、`replyRating` 仅影响展示/回复，不改变评价统计聚合字段，不删除评价统计缓存。反馈创建、回复、分配、关闭、补充改变反馈统计（总数/状态分布/响应时效），需删除反馈统计缓存；`updateTags` 不影响反馈统计聚合字段，不删除反馈统计缓存。

## 5. 文件上传设计

评价截图与反馈图片由**文件管理模块统一管理**：前端通过通用上传接口上传至对象存储，评价/反馈接口仅校验 URL（来源域名 + 扩展名），不直接承接上传。

> **说明**：无专用存储桶，评价/反馈记录删除时不级联删除关联图片。
