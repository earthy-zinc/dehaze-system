### 3.4 核心业务逻辑

#### 评价创建逻辑

1. **唯一性校验**：`uk_pred_log_id` 唯一索引防止重复评价
2. **时限校验**：处理完成时间 ≤ 30天
3. **状态校验**：处理记录状态为已完成
4. **归属校验**：处理记录属于当前用户
5. **参数校验**：评分1-5、图片≤3张、文字≤500字符
6. **图片安全**：校验URL为MinIO域名，文件类型为图片
7. **写入评价**：插入 `sys_rating`
8. **发放成长值**：调用 `MemberService.adjustGrowth`（+5，change_type=rating）
9. **每日上限校验**：用户当日评价成长值获取 ≤5次
10. **触发低分告警**：异步消息队列发送告警判断

#### 反馈创建逻辑

1. **频率限制**：每用户每日 ≤5条（Redis 计数）
2. **参数校验**：标题5-50字符、内容10-1000字符、图片≤5张且≤5MB
3. **图片安全**：类型校验+大小校验
4. **写入反馈**：插入 `sys_feedback`，默认 status=pending
5. **通知**：推送管理员待处理提醒

#### 低分告警判断逻辑

```
评价创建成功（rating ≤ 2）
    ↓
异步消息队列发送评价事件
    ↓
判断评分：
    ├─ rating=2 → 触发普通告警
    └─ rating=1 → 触发普通告警 + 进一步判断
    ↓
查询同算法24小时内低分评价数量：
    ├─ ≥3条 → 触发紧急告警（站内信+邮件）
    └─ <3条 → 仅普通告警
    ↓
查询当日全局低分率：
    ├─ >20% → 触发严重告警（站内信+邮件+短信）
    └─ ≤20% → 不触发
    ↓
告警延迟 <10s
```

#### 反馈状态流转

```
pending（待处理）
    ├─ assignFeedback → processing（处理中）
    └─ closeFeedback → closed（已关闭）

processing（处理中）
    ├─ replyFeedback → replied（已回复）
    └─ closeFeedback → closed

replied（已回复）
    ├─ supplementFeedback → processing（重新打开）
    └─ closeFeedback → closed
```

## 4. 数据访问层设计

### 4.1 查询优化

#### 评价分页查询

- 索引 `idx_algorithm_id` 优化按算法筛选
- 索引 `idx_rating` 优化按评分筛选
- 索引 `idx_create_time` 优化时间范围
- 关联 `sys_user` 获取用户信息（匿名时跳过）

#### 反馈分页查询

- 复合索引 `idx_priority_status` 优化优先级+状态筛选
- 索引 `idx_assignee_id` 优化处理人维度查询

#### 统计聚合查询

- 按算法分组聚合平均评分
- 按时间分组聚合评分趋势
- 缓存统计结果（10分钟）

### 4.2 缓存策略

| 缓存对象 | 缓存 Key | 过期时间 | 更新策略 |
|---------|---------|---------|---------|
| 评价统计（全局） | rating:stats:global | 10 分钟 | 定时刷新 |
| 评价统计（算法） | rating:stats:algorithm:{id} | 10 分钟 | 新评价时删除 |
| 反馈统计 | feedback:stats | 10 分钟 | 新反馈时删除 |
| 算法评价聚合 | algorithm:rating:{id} | 30 分钟 | 新评价时删除 |
| 用户评价频率 | rating:daily:{userId}:{date} | 25 小时 | 自动过期 |
| 用户反馈频率 | feedback:daily:{userId}:{date} | 25 小时 | 自动过期 |

## 6. 文件上传设计

### 6.1 图片上传流程

1. 前端调用文件上传接口
2. 后端校验文件类型（image/jpeg, image/png, image/webp）
3. 校验文件大小（≤5MB）
4. 上传至 MinIO，bucket: `feedback-images`
5. 返回访问URL
6. 前端在创建评价/反馈时携带URL

### 6.2 文件清理

- 评价/反馈删除时，关联图片从 MinIO 删除
- 定时任务清理无引用的孤立文件（每日）

## 7. 安全设计

### 7.1 防护机制

| 防护项 | 实现方式 |
|--------|---------|
| 评价防刷 | `uk_pred_log_id` 唯一索引 |
| 反馈频率限制 | Redis 计数（每用户每日 ≤5条） |
| 图片安全 | 类型校验+大小限制+MinIO存储 |
| 内容过滤 | 敏感词过滤（评价/反馈/回复） |
| 敏感信息保护 | 联系方式仅管理员可见 |
| 数据隔离 | 用户查询仅返回自己的评价/反馈 |
