# 反馈评价模块需求规格

## 1. 模块概述

### 1.1 模块定位

反馈评价模块负责收集用户对去雾处理结果的评分与评价，以及用户对产品功能的意见反馈。该模块是系统数据飞轮的核心环节——用户评价数据反哺算法迭代决策，功能反馈驱动产品优化，形成"使用→反馈→改进"的闭环。

### 1.2 核心价值

| 价值维度 | 具体内容 |
|---------|---------|
| **数据飞轮** | 用户评分为算法效果评估提供真实数据，支撑算法迭代决策 |
| **质量监控** | 低分评价自动告警，帮助发现算法异常或质量问题 |
| **用户倾听** | 反馈渠道畅通，提升用户参与感和满意度 |
| **改进闭环** | 反馈从收集到处理到回复的全流程跟踪，确保用户声音被响应 |

### 1.3 业务目标

#### 功能目标

- 建立针对处理结果的 1-5 星评分体系
- 提供结构化的用户反馈收集机制
- 支持后台反馈处理全流程（分类→分配→处理→回复→关闭）
- 提供评分数据统计分析能力

#### 性能目标

| 指标 | 目标值 | 说明 |
|-----|--------|------|
| 评价提交响应 | <500ms | 评分和评价提交接口响应时间 |
| 反馈列表查询 | <500ms | 后台分页查询响应时间 |
| 评价统计聚合 | <2s | 算法维度评分统计查询 |

### 1.4 模块依赖关系

```
┌─────────────┐     ┌─────────────┐
│  去雾处理    │────▶│  反馈评价    │
│    模块     │     │    模块     │
└─────────────┘     └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │ 会员管理  │ │ 算法管理  │ │ 系统管理  │
        │ (成长值)  │ │ (效果统计)│ │ (通知)   │
        └──────────┘ └──────────┘ └──────────┘
```

## 2. 评分体系

### 2.1 结果评分 (F-FE-001)

#### 2.1.1 功能描述

用户在去雾处理完成、查看效果对比后，可对处理结果进行 1-5 星评分并提交文字评价。

#### 2.1.2 评分维度

| 维度 | 星级范围 | 说明 |
|------|---------|------|
| 综合评分 | 1-5 星 | 用户对处理结果的整体满意度 |

**星级含义**：

| 星级 | 标签 | 含义 |
|------|------|------|
| 5 星 | 非常满意 | 去雾效果超出预期 |
| 4 星 | 满意 | 去雾效果符合预期 |
| 3 星 | 一般 | 去雾效果可接受但有改进空间 |
| 2 星 | 不满意 | 去雾效果不理想 |
| 1 星 | 非常不满意 | 去雾效果极差或出现负面效果 |

#### 2.1.3 评价内容

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| rating | 整数 | ✅ | 1-5 星评分 |
| comment | 文本 | ❌ | 文字评价，最多 500 字符 |
| tags | 多选 | ❌ | 预设标签（见下表） |
| imageUrl | 图片 | ❌ | 截图上传（最多 3 张） |

#### 2.1.4 预设标签

| 正面标签 | 负面标签 |
|---------|---------|
| 去雾彻底 | 残留雾气 |
| 色彩自然 | 色彩失真 |
| 细节清晰 | 细节丢失 |
| 处理速度快 | 处理速度慢 |
| 整体提升明显 | 无明显改善 |

#### 2.1.5 评价时机与入口

| 入口 | 触发时机 | 说明 |
|------|---------|------|
| 效果对比页 | 处理完成后首次进入对比页 | 底部弹出评分卡片，可关闭 |
| 处理历史 | 历史记录列表 | 每条记录可补评或修改 |
| 个人中心 | 我的评价入口 | 查看已提交的评价列表 |

#### 2.1.6 业务规则

1. 每条处理记录仅可评价一次，提交后可修改（修改不增加成长值）
2. 评价需在处理完成后 30 天内提交，超期不可评价
3. 提交评价后获得 5 成长值（每日上限 5 次）
4. 匿名评价不展示用户信息，但后台可查看
5. 1-2 星评价触发低分告警，通知管理员

### 2.2 评价展示 (F-FE-002)

#### 2.2.1 处理结果页评价展示

在效果对比页底部展示当前处理的评价信息（如已评价），包括星级、评价文字、标签、评价时间。未评价时展示"去评价"按钮。

#### 2.2.2 算法评价聚合展示

在算法选择页的算法详情中，展示该算法的评分统计：

| 展示项 | 说明 |
|--------|------|
| 平均评分 | 所有评价的平均星级（保留 1 位小数） |
| 评分分布 | 5/4/3/2/1 星各占比 |
| 评价总数 | 该算法收到的评价总数 |
| 热门标签 | 出现频次最高的 5 个标签 |

## 3. 用户反馈

### 3.1 反馈提交 (F-FE-003)

#### 3.1.1 功能描述

用户可提交对产品功能、使用体验、问题报告等方面的反馈意见。

#### 3.1.2 反馈类型

| 类型 | 编码 | 说明 | 示例 |
|------|------|------|------|
| 功能建议 | `suggestion` | 对产品功能的改进建议 | 希望增加视频去雾功能 |
| 问题报告 | `bug` | 使用中遇到的问题 | 处理结果无法保存 |
| 体验反馈 | `experience` | 对使用体验的评价 | 页面加载太慢 |
| 投诉 | `complaint` | 对服务的不满 | VIP 权益未生效 |

#### 3.1.3 反馈表单

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| feedbackType | 下拉选择 | ✅ | 反馈类型 |
| title | 输入框 | ✅ | 反馈标题，5-50 字符 |
| content | 文本域 | ✅ | 反馈内容，10-1000 字符 |
| contact | 输入框 | ❌ | 联系方式（手机/邮箱） |
| images | 图片上传 | ❌ | 截图（最多 5 张，单张 ≤5MB） |
| relatedModule | 下拉选择 | ❌ | 相关模块（去雾处理/效果对比/会员中心等） |

#### 3.1.4 反馈入口

| 入口 | 位置 |
|------|------|
| 个人中心 | "意见反馈"菜单项 |
| 设置页 | "帮助与反馈"入口 |
| 全局 | 侧边栏/底部导航的反馈图标 |

#### 3.1.5 业务规则

1. 每用户每日最多提交 5 条反馈（防止刷屏）
2. 反馈提交后 3 个工作日内首次回复
3. 反馈状态变更时推送通知给用户
4. 提交反馈不获得成长值（避免为成长值而提交无意义反馈）

### 3.2 我的反馈 (F-FE-004)

#### 3.2.1 功能描述

用户可查看自己提交的反馈记录和处理进度。

#### 3.2.2 反馈列表

| 字段 | 说明 |
|------|------|
| 反馈标题 | 截断显示 |
| 反馈类型 | 类型标签 |
| 状态 | 待处理/处理中/已回复/已关闭 |
| 提交时间 | 反馈提交时间 |
| 最后回复 | 管理员最后回复时间 |
| 操作 | 查看详情/补充说明/关闭 |

#### 3.2.3 反馈详情

展示反馈完整内容、图片附件、处理时间线（提交→分配→处理→回复→关闭）、管理员回复内容。用户可在已回复的反馈中补充说明，重新打开反馈。

## 4. 后台管理功能

### 4.1 评价管理 (F-FE-005)

#### 4.1.1 评价列表查询

| 查询条件 | 字段 | 说明 |
|---------|------|------|
| 用户信息 | 用户名/昵称 | 模糊匹配 |
| 算法名称 | 模糊匹配 | 按算法筛选评价 |
| 评分范围 | 1-5 星 | 按星级筛选 |
| 评价时间 | 时间范围 | BETWEEN |
| 标签 | 多选 | 按标签筛选 |
| 是否有文字 | 布尔 | 筛选有/无文字评价 |

#### 4.1.2 列表展示字段

| 字段 | 说明 |
|------|------|
| 用户名 | 评价用户 |
| 算法名称 | 被评价的算法 |
| 评分 | 星级展示 |
| 评价内容 | 文字内容（截断） |
| 标签 | 评价标签 |
| 处理记录 | 关联的处理记录链接 |
| 评价时间 | 提交时间 |
| 操作 | 查看/隐藏/回复 |

#### 4.1.3 评价处理

| 操作 | 说明 |
|------|------|
| 查看详情 | 查看完整评价、图片、关联处理记录 |
| 隐藏评价 | 不当评价可隐藏，用户端不再展示 |
| 回复评价 | 管理员可回复用户评价 |
| 标记处理 | 将低分评价标记为"已处理"/"需关注" |

### 4.2 反馈管理 (F-FE-006)

#### 4.2.1 反馈列表查询

| 查询条件 | 字段 | 说明 |
|---------|------|------|
| 用户信息 | 用户名/昵称 | 模糊匹配 |
| 反馈类型 | 精确匹配 | = |
| 反馈状态 | 精确匹配 | = |
| 相关模块 | 精确匹配 | = |
| 提交时间 | 时间范围 | BETWEEN |
| 关键字 | 标题/内容 | 模糊匹配 |

#### 4.2.2 列表展示字段

| 字段 | 说明 |
|------|------|
| 反馈标题 | 截断显示 |
| 用户名 | 提交用户 |
| 反馈类型 | 类型标签 |
| 相关模块 | 关联模块 |
| 状态 | 反馈状态标签 |
| 优先级 | 普通/紧急/高优 |
| 提交时间 | 反馈提交时间 |
| 处理人 | 分配的处理人 |
| 操作 | 详情/分配/处理/关闭 |

#### 4.2.3 反馈处理流程

```
用户提交反馈
    ↓
状态：待处理
    ↓
管理员查看反馈 → 评估优先级
    ↓
分配处理人（或自行处理）
    ↓
状态：处理中
    ↓
├─ 需补充信息 → 回复用户请求补充 → 等待用户补充
│
├─ 可直接回复 → 编写回复内容
│   ↓
│   状态：已回复
│   ↓
│   通知用户查看回复
│   ↓
│   用户确认/补充/关闭
│   ↓
│   状态：已关闭
│
└─ 无法解决 → 标记为"暂不支持" → 关闭
```

#### 4.2.4 反馈回复

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| replyContent | 文本域 | ✅ | 回复内容，10-2000 字符 |
| replyType | 下拉选择 | ✅ | 回复类型（信息补充/已解决/暂不支持/转开发） |
| attachments | 文件上传 | ❌ | 回复附件（截图/文档） |

#### 4.2.5 反馈标签管理

管理员可为反馈打标签，便于分类统计：

| 预设标签 | 说明 |
|---------|------|
| 高频问题 | 多用户反馈的同类问题 |
| 已知问题 | 已确认的 bug 或限制 |
| 已排期 | 已纳入开发计划 |
| 已解决 | 问题已修复 |
| 不予处理 | 不在产品规划范围内 |

### 4.3 低分告警 (F-FE-007)

#### 4.3.1 功能描述

当收到 1-2 星低分评价时，自动触发告警通知。

#### 4.3.2 告警规则

| 条件 | 告警级别 | 通知方式 |
|------|---------|---------|
| 单条 1 星评价 | 普通 | 后台待办提醒 |
| 24 小时内同一算法 ≥3 条低分 | 紧急 | 站内信 + 邮件通知管理员 |
| 24 小时内全局低分率 >20% | 严重 | 站内信 + 邮件 + 短信通知 |

#### 4.3.3 告警处理

- 管理员在后台查看低分评价详情和关联处理记录
- 判断是算法质量问题、特定图片问题还是用户误评
- 标记处理结果：算法问题→转算法团队、图片问题→记录已知限制、误评→忽略

### 4.4 评价统计分析 (F-FE-008)

#### 4.4.1 统计维度

| 维度 | 指标 |
|------|------|
| 全局评分 | 平均评分、评分分布、评价总数、评价率（评价数/处理数） |
| 按算法 | 各算法平均评分、评分趋势、低分率、热门标签 |
| 按时间 | 日/周/月评分趋势，识别评分波动 |
| 按用户等级 | 不同会员等级的评分分布差异 |
| 标签分析 | 正面/负面标签出现频次排行 |

#### 4.4.2 反馈统计分析

| 维度 | 指标 |
|------|------|
| 按类型 | 各类型反馈数量占比 |
| 按模块 | 各模块反馈数量排行（定位问题模块） |
| 按状态 | 待处理/处理中/已回复/已关闭 数量分布 |
| 响应时效 | 平均首次响应时间、平均关闭时间 |
| 高频关键词 | 反馈内容关键词词云 |

## 5. 非功能需求

### 5.1 性能需求

| 指标 | 要求 |
|-----|------|
| 评价提交 | <500ms，含图片上传 |
| 评价统计聚合 | 算法维度统计 <2s，全局统计 <5s |
| 低分告警触发 | 评价提交后 10s 内完成告警判断 |
| 反馈列表查询 | 分页查询 <500ms |

### 5.2 安全需求

| 方面 | 措施 |
|-----|------|
| 评价防刷 | 同一处理记录仅可评价一次，基于 prediction_log_id 唯一索引 |
| 反馈频率限制 | 每用户每日 ≤5 条反馈 |
| 图片安全 | 上传图片做类型校验和大小限制，存储到 MinIO |
| 敏感信息 | 反馈中的联系方式仅管理员可见 |
| 内容过滤 | 评价和反馈内容做敏感词过滤 |

### 5.3 可用性需求

| 方面 | 要求 |
|-----|------|
| 评价降级 | 评价功能不可用时不影响核心去雾流程 |
| 统计缓存 | 评分统计数据 Redis 缓存，TTL 10 分钟 |
| 告警可靠 | 低分告警采用异步消息队列，确保不丢消息 |
| 通知送达 | 反馈状态变更通知至少保证站内信送达 |

## 7. 待确认事项

1. **评价公开展示**：是否在算法选择页公开展示用户评价？若展示，是否需要审核机制？
2. **评价激励**：除了成长值，是否需要其他评价激励（如评价抽奖、评价积分）？
3. **社区展示墙**：用户授权后展示优质处理结果（规划中的 P2 功能），是否与评价模块联动？
4. **反馈转工单**：高优反馈是否需要自动转为开发工单，对接项目管理工具？
5. **评价修改限制**：用户修改评价的次数是否需要限制？修改后成长值如何处理？
6. **AI 辅助分析**：是否需要引入 AI 对反馈内容做自动分类和情感分析？
