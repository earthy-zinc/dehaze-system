# 反馈评价模块需求规格

## 1. 模块概述

### 1.1 模块定位

反馈评价模块负责收集用户对去雾处理结果的评分与评价，以及用户对产品功能的意见反馈。该模块是系统数据飞轮的核心环节——用户评价数据反哺算法迭代决策，功能反馈驱动产品优化，形成"使用→反馈→改进"的闭环。

### 1.2 核心价值

| 价值维度 | 具体内容 |
|---------|---------|
| **数据飞轮** | 用户评分为算法效果评估提供真实数据，支撑算法迭代决策 |
| **质量监控** | 低分评价自动告警，帮助发现算法异常或质量问题 |
| **用户倾听** | 反馈渠道畅通，提升用户参与感和满意度 |
| **改进闭环** | 反馈从收集到处理到回复的全流程跟踪，确保用户声音被响应 |

### 1.3 业务目标

- 建立针对处理结果的 1-5 星评分体系
- 提供结构化的用户反馈收集机制
- 支持后台反馈处理全流程（分配→处理→回复→关闭）
- 提供评分数据统计分析能力

## 2. 评分体系

### 2.1 结果评分 (F-FE-001)

#### 2.1.1 功能描述

用户在去雾处理完成后，可对处理结果进行 1-5 星评分并提交文字评价。

#### 2.1.2 评分维度

评价仅设综合评分一个维度（1-5 星），表示用户对处理结果的整体满意度。各星级含义：

| 星级 | 标签 | 含义 |
|------|------|------|
| 5 星 | 非常满意 | 去雾效果超出预期 |
| 4 星 | 满意 | 去雾效果符合预期 |
| 3 星 | 一般 | 去雾效果可接受但有改进空间 |
| 2 星 | 不满意 | 去雾效果不理想 |
| 1 星 | 非常不满意 | 去雾效果极差或出现负面效果 |

#### 2.1.3 评价内容

| 字段 | 必填 | 说明 |
|------|------|------|
| 关联处理记录 | ✅ | 本次评价针对的处理记录 |
| 评分 | ✅ | 1-5 星 |
| 评价文字 | ❌ | 最多 500 字符 |
| 效果标签 | ❌ | 预设标签，最多 5 个（按评分动态切换，见 §2.1.4） |
| 截图 | ❌ | 最多 3 张，JPG/PNG/WEBP，单张 ≤5MB，须为系统文件服务地址 |
| 匿名评价 | ❌ | 开启后评价不展示用户信息 |

#### 2.1.4 预设标签

按评分动态展示标签组：评分 ≥4 展示正面标签，≤2 展示负面标签，=3 展示全部；切换评分档位时清空已选标签。

| 正面标签 | 负面标签 |
|---------|---------|
| 去雾彻底 | 残留雾气 |
| 色彩自然 | 色彩失真 |
| 细节清晰 | 细节丢失 |
| 处理速度快 | 处理速度慢 |
| 整体提升明显 | 无明显改善 |

#### 2.1.5 评价入口

| 入口 | 说明 |
|------|------|
| 我的评价页 | 查看已提交的评价列表（含管理员回复），只读 |
| 后台评价列表 | 管理员查看/隐藏/回复评价 |

#### 2.1.6 业务规则

| 规则 |
|------|
| 1. 每条处理记录仅可评价一次（防重校验） |
| 2. 提交后可修改（仅限本人，修改**不增加**成长值） |
| 3. 评价需在处理完成后 30 天内提交，超期不可评价 |
| 4. 提交评价后获得 5 成长值（每日最多 5 次），需会员记录存在 |
| 5. 匿名评价**用户端与后台均不展示用户信息**，评价记录保留 |
| 6. 1-2 星评价触发低分告警（见 §4.3） |
| 7. 评价提交前校验处理记录存在、状态已完成、归属本人 |

## 3. 用户反馈

### 3.1 反馈提交 (F-FE-003)

#### 3.1.1 功能描述

用户可提交对产品功能、使用体验、问题报告等方面的反馈意见。

#### 3.1.2 反馈类型

| 类型 | 说明 | 示例 |
|------|------|------|
| 功能建议 | 对产品功能的改进建议 | 希望增加视频去雾功能 |
| 问题报告 | 使用中遇到的问题 | 处理结果无法保存 |
| 体验反馈 | 对使用体验的评价 | 页面加载太慢 |
| 投诉 | 对服务的不满 | VIP 权益未生效 |

#### 3.1.3 反馈表单

| 字段 | 必填 | 说明 |
|------|------|------|
| 反馈类型 | ✅ | 下拉选择 |
| 标题 | ✅ | 5-50 字符 |
| 内容 | ✅ | 10-1000 字符 |
| 联系方式 | ❌ | 手机/邮箱，**仅管理员可见** |
| 截图 | ❌ | 最多 5 张，单张 ≤5MB，JPG/PNG/WEBP |
| 相关模块 | ❌ | 去雾处理/效果对比/会员中心等 |

#### 3.1.4 反馈入口

| 入口 | 位置 |
|------|------|
| 个人中心 | "我的反馈"页面（列表 + 新建反馈对话框） |

#### 3.1.5 业务规则

| 规则 |
|------|
| 1. 每用户每日最多提交 5 条反馈，超限返回业务错误 |
| 2. 提交反馈不获得成长值 |
| 3. 反馈状态：待处理/处理中/已回复/已关闭 |
| 4. 反馈关闭需填写关闭原因 |

### 3.2 我的反馈 (F-FE-004)

#### 3.2.1 功能描述

用户可查看自己提交的反馈记录和处理进度。

#### 3.2.2 反馈列表

| 字段 | 说明 |
|------|------|
| 反馈标题 | 完整标题 + 内容摘要 |
| 反馈类型 | 类型标签 |
| 状态 | 待处理/处理中/已回复/已关闭（彩色标签） |
| 相关模块 | 模块标签 |
| 处理人 | 分配的处理人名称（未分配显示"暂未分配"） |
| 提交时间 | 反馈提交时间 |
| 操作 | 查看详情 |

#### 3.2.3 反馈详情

展示反馈完整内容、图片附件、标签、处理时间线（用户提交→管理员回复/分配，按时间升序）、管理员回复内容（回复人/类型/内容/附件）。用户可在**未关闭**的反馈中补充说明（追加回复记录；若状态为"已回复"则回退为"处理中"）。

## 4. 后台管理功能

### 4.1 评价管理 (F-FE-005)

#### 4.1.1 评价列表查询

| 查询条件 | 说明 |
|---------|------|
| 用户信息 | 用户名/昵称模糊匹配 |
| 算法 | 按算法精确筛选 |
| 评分范围 | 1-5 星区间筛选 |
| 评价时间 | 起止时间范围 |
| 标签 | 多选标签筛选 |
| 是否有文字 | 布尔筛选 |

#### 4.1.2 列表展示字段

| 字段 | 说明 |
|------|------|
| 用户名/头像 | 评价用户（匿名评价置空） |
| 算法名称 | 被评价的算法 |
| 评分 | 星级展示 |
| 评价内容 | 文字内容 |
| 标签 | 评价标签 |
| 处理记录 | 关联的处理记录 ID |
| 评价时间 | 提交时间 |
| 操作 | 隐藏/回复 |

#### 4.1.3 评价处理

| 操作 | 说明 |
|------|------|
| 查看详情 | 查看完整评价、图片、关联处理记录 |
| 隐藏评价 | 不当评价可隐藏，用户端不再展示 |
| 回复评价 | 管理员可回复用户评价 |

### 4.2 反馈管理 (F-FE-006)

#### 4.2.1 反馈列表查询

| 查询条件 | 说明 |
|---------|------|
| 关键字 | 标题/内容模糊，或按用户名/昵称匹配用户 |
| 反馈类型 | 精确匹配 |
| 反馈状态 | 待处理/处理中/已回复/已关闭 |
| 相关模块 | 精确匹配 |
| 优先级 | 普通/紧急/高优 |
| 处理人 | 按处理人筛选 |
| 提交时间 | 起止时间范围 |

#### 4.2.2 列表展示字段

| 字段 | 说明 |
|------|------|
| 反馈标题 | 截断显示 |
| 用户名 | 提交用户 |
| 反馈类型 | 类型标签 |
| 相关模块 | 关联模块 |
| 状态 | 反馈状态标签 |
| 优先级 | 普通/紧急/高优标签 |
| 处理人 | 分配的处理人 |
| 提交时间 | 反馈提交时间 |
| 操作 | 详情/分配/回复/关闭/标签 |

#### 4.2.3 反馈处理流程

```
用户提交反馈 → 状态：待处理
    ↓
管理员分配处理人（或自行回复，回复时自动分配给自己）
    ↓
状态：处理中
    ↓
管理员回复（回复类型：信息补充/已解决/暂不支持/转开发）
    ↓
状态：已回复
    ↓
用户补充说明（状态回退为处理中）或管理员关闭（需填关闭原因）
    ↓
状态：已关闭
```

#### 4.2.4 反馈回复

| 字段 | 必填 | 说明 |
|------|------|------|
| 回复内容 | ✅ | 最多 2000 字符 |
| 回复类型 | ✅ | 信息补充/已解决/暂不支持/转开发 |
| 附件 | ❌ | 回复附件 |

#### 4.2.5 反馈标签管理

后台可对反馈设置标签（自由文本，无预设约束），标签随详情/列表展示。

### 4.3 低分告警 (F-FE-007)

#### 4.3.1 功能描述

当收到 1-2 星低分评价时，自动触发告警通知。

#### 4.3.2 告警规则

| 条件 | 告警级别 | 说明 |
|------|---------|------|
| 单条评分 ≤2 星 | 普通 | 通知全体管理员，含算法名/评分/处理记录 ID |
| 评分 =1 星 且 24 小时内同一算法低分（≤2 星）≥3 条 | 紧急 | 紧急告警仅在 1 星评价时检查 |
| 当日（当天 0 点起）全局低分率 >20% | 严重 | 低分率 = 当日 ≤2 星评价数 / 当日评价总数 |

> **说明**：
> - 通知方式**仅站内信**（消息通知模块）
> - 告警为**异步发送**，不影响评价提交
> - 紧急/严重告警按算法/日期去重，避免重复通知

#### 4.3.3 告警处理

- 管理员在后台查看低分评价详情和关联处理记录（告警站内信携带处理记录 ID）
- 判断是算法质量问题、特定图片问题还是用户误评
- 通过隐藏/回复评价处理

### 4.4 评价统计分析 (F-FE-008)

#### 4.4.1 统计维度

| 维度 | 指标 |
|------|------|
| 全局评分 | 平均评分、评分分布（1-5 星计数）、评价总数 |
| 标签分析 | 正面/负面标签频次排行（Top 5） |
| 按算法 | 各算法平均评分、评价总数、低分率 |

> 评价统计支持时间范围筛选。

#### 4.4.2 反馈统计分析

| 维度 | 指标 |
|------|------|
| 按类型 | 各类型反馈数量占比 |
| 按模块 | 各模块反馈数量排行（定位问题模块） |
| 按状态 | 待处理/处理中/已回复/已关闭 数量分布 |
| 响应时效 | 平均首次响应时间、平均关闭时间 |
| 高频关键词 | 标题+内容分词统计 Top 10 |

## 5. 非功能需求

### 5.1 性能需求

| 指标 | 要求 |
|-----|------|
| 评价提交 | <500ms（含图片校验） |
| 反馈列表查询（分页） | <500ms |
| 评价统计聚合 | 算法维度 <2s，全局 <5s |
| 低分告警触发 | 评价提交后 10s 内完成告警判断 |

### 5.2 安全需求

| 方面 | 措施 |
|------|------|
| 图片安全 | 来源、格式、数量与大小校验 |
| 敏感信息 | 反馈联系方式仅管理员可见 |
| 数据隔离 | 我的评价/我的反馈仅本人可见；评价归属校验（非本人视为不存在） |

### 5.3 可用性需求

| 方面 | 要求 |
|------|------|
| 评价降级 | 评价功能不可用时不影响核心去雾流程 |
| 告警可靠 | 低分告警异步发送，不丢消息 |
| 通知送达 | 反馈状态变更通知至少保证站内信送达 |

## 7. 待确认事项

1. **评价公开展示**：是否在算法选择页公开展示算法评分与用户评价？
2. **评价激励**：除了成长值，是否需要其他评价激励（如评价抽奖、评价积分）？
3. **社区展示墙**：用户授权后展示优质处理结果，是否与评价模块联动？
4. **反馈转工单**：高优反馈是否需要自动转为开发工单，对接项目管理工具？
5. **评价修改限制**：用户修改评价的次数是否需要限制？修改后成长值如何处理？
6. **AI 辅助分析**：是否需要引入 AI 对反馈内容做自动分类和情感分析？
7. **敏感词过滤**：评价/反馈内容是否需要接入敏感词过滤？
8. **评价时限差异化**：评价提交的 30 天时限是否需要按任务类型差异化？
9. **低分告警去重周期**：紧急告警的 24 小时去重周期是否合理？是否需要按算法维度调整？
10. **反馈 SLA 考核**：是否需要建立反馈首次回复超时升级机制？
11. **反馈附件保留期限**：反馈截图附件的保留期限与清理策略？
