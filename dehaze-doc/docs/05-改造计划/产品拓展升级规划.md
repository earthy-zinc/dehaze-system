## 产品拓展方向：AI 图像处理平台

### 扩展可行性评估

当前系统的核心基础设施（文件管理、任务队列、算法管理、用户权限、VIP 体系）是**通用的**，不是去雾专用的。Python 端的模型推理框架只需替换模型权重和预处理逻辑，即可支持其他图像处理任务，扩展边际成本低。

| 扩展方向 | 与现有用户重叠度 | 技术复用度 | 推荐优先级 | 代表模型 |
|---------|---------------|---------|------|------|
| **去雨 / 去雪** | 高 | 极高（同类大气退化问题） | ⭐⭐⭐ 最优先 | MPRNet、DerainNet |
| **低光增强** | 高 | 高 | ⭐⭐⭐ | RetinexNet、Zero-DCE |
| **图像超分辨率** | 高 | 高 | ⭐⭐ | Real-ESRGAN、SwinIR |
| **图像去噪** | 高 | 高 | ⭐⭐ | DnCNN、NAFNet |
| **图像修复（Inpainting）** | 中 | 中 | ⭐ | LaMa、MAT |
| **风格迁移** | 低 | 低 | ⭐ | — |

**去雨/去雪**与去雾属于同一类图像退化问题（大气散射模型），算法结构几乎一致，是风险最低的第一步扩展，且能显著扩大用户场景覆盖（不再局限于雾霾天气）。

### 与现有系统的兼容性判断

**结论：现有架构天然支持扩展，改造成本可控。**

当前系统的任务队列、文件管理、用户权限、VIP 体系均与具体算法无关，属于通用基础设施。扩展新图像处理类型，主要改动集中在三处：

- **Python 算法服务**：现有推理入口针对去雾单任务硬编码，需改造为按任务类型分发的路由机制。各算法模型遵循统一接口规范，新增算法类型不影响已有逻辑，改造工作量小且风险可控。模型权重按需加载，避免多模型同时占用 GPU 显存。
- **后端任务系统**：任务表当前隐含"去雾"语义，需新增任务类型字段使任务系统与具体算法解耦。改动范围仅限任务创建和分发逻辑，不涉及核心业务流程重构。
- **前端页面**：「去雾处理」页面抽象为通用「图像处理」页面，通过任务类型参数区分不同处理场景（上传提示、参数配置、效果评估指标各自独立配置）。新增任务类型时前端只需新增一份配置，无需改动核心处理流程。

### 3.3 扩展前提条件

**必须先完成**：
1. 去雾核心体验补全（处理历史、进度反馈、用户评分）
2. VIP 体系后端实现（会员/套餐/订单管理模块）
3. 后端稳定承接基础 CRUD

### 3.4 分阶段扩展路径

**阶段一（当前 → 近期）：做深去雾**，目标是去雾体验达到生产级别。补齐处理历史、进度反馈、用户评分；完善 VIP 体系

**阶段二（近期 → 中期）：横向扩展同类退化**，目标是覆盖更广泛的图像增强场景。增加去雨、去雪、低光增强；算法管理框架新增任务类型维度；产品名可调整为「图像增强系统」。

**阶段三（中期）：AI 图像处理平台**，目标是具备平台规模效应。增加超分辨率、去噪、图像修复；引入模型市场，支持第三方算法接入；OpenAPI 对外开放，自动生成多端 SDK。

**阶段四（中期 → 远期）：AI 工作平台**，目标是从工具集合升级为智能工作流。在图像处理能力基础上叠加多模态功能，构建"专业图像处理 + 多模态增强"的差异化定位。

### 3.5 阶段四：AI 工作平台扩展规划

#### 3.5.1 战略定位

**核心定位**：以专业图像处理能力为核心，以多模态交互为增强层，构建智能图像处理工作流平台。

**与通用 AI 助手的差异化**：

| 维度 | 本平台 | 通用 AI 助手 |
|------|--------|--------------|
| 核心能力 | 专业图像处理（20+自研算法，专业指标评估） | 文本生成为主，图像处理为辅助 |
| 用户体验 | 自动推荐 + 多模态增强 | 纯对话式交互 |
| 技术深度 | 深度学习模型 + PSNR/SSIM 量化评估 | 通用模型，效果一般 |
| 目标用户 | 摄影爱好者、开发者、企业客户 | 大众用户 |

#### 3.5.2 多模态功能分层架构

多模态作为图像处理能力的增强层，按以下三个层次逐步落地：

**输入层（语音 / 文档理解）**：
- 语音指令控制：上传、选算法、调参数等操作可通过语音完成
- 自然语言描述处理需求：如"帮我把这张夜景照片变亮"
- 文档理解：读取处理需求说明书，解析为可执行的处理任务

**交互层（多模态融合）**：
- 上传图片 + 文字描述的组合交互
- 处理参数的自然语言调整（如"再调亮一点"）
- 处理过程中的智能对话引导

**输出层（智能反馈）**：
- 处理结果的智能解读（自动生成处理报告、指标分析）
- 批量处理结果的摘要总结
- 处理建议的自然语言反馈

#### 3.5.3 实施时序

**为什么在阶段三之后引入多模态**：

1. **基础设施成熟**：阶段三完成后，文件管理、任务队列、算法管理等核心模块已稳定，可承载多模态交互的复杂性。
2. **用户基数增长**：阶段三的平台化运营后，用户量和数据量增加，多模态功能可显著提升用户粘性。
3. **数据飞轮形成**：阶段三积累的处理数据（用户行为、参数选择、效果反馈）可为多模态模型提供训练素材。

**分步骤实施路径**：

| 步骤 | 时间窗口 | 核心交付物 | 优先级 |
|------|----------|------------|--------|
| 1 | 阶段四早期 | 语音指令控制、智能算法推荐（自然语言→算法选择） | P1 |
| 2 | 阶段四中期 | 智能报告生成、批量处理摘要、参数自动优化 | P1 |
| 3 | 阶段四后期 | AI 工作流编排（多任务串联、条件分支、定时执行）、企业级解决方案 | P2 |

#### 3.5.4 用户价值场景

**核心场景**：

1. **批量处理场景**：用户上传多张图片后，通过自然语言描述统一处理需求，减少重复操作
2. **专业报告生成**：处理完成后自动生成包含技术指标、处理参数、效果对比的专业报告
3. **新手引导场景**：通过对话式交互引导新手完成图像处理流程，降低学习成本
4. **企业自动化场景**：通过工作流编排实现"定时拉取图片→自动处理→自动分发"的端到端自动化

**预期价值**：
- 降低专业图像处理门槛，让非专业用户也能完成复杂任务
- 提升批量处理效率，减少人工操作成本
- 增强平台差异化竞争力，与通用 AI 助手形成区隔

#### 3.5.5 与现有功能的融合点

- **算法选择模块**：在"多模态推荐"基础上（需求规格 §4.1），叠加自然语言交互
- **去雾处理模块**：在"语音控制"基础上（需求规格 §5.3），扩展为完整的语音工作流
- **效果对比模块**：处理完成后自动生成自然语言解读的对比报告
- **任务管理模块**：支持工作流编排，将多任务串联为自动化流程

## 4. 爬虫数据集功能

### 4.1 可行性结论

**建议实现，但需严格合规管控，优先对接授权数据源。**

| 维度 | 评估 |
|------|------|
| **技术可行性** | 高。Python 端已有图像处理能力，爬虫框架（Scrapy/Playwright）成熟 |
| **业务价值** | 高。自动扩充训练数据集，降低人工标注成本 |
| **合规风险** | 中高。需遵守 robots.txt、版权法、数据隐私法规 |
| **与现有架构契合度** | 高。可复用数据集管理模块、文件管理模块、任务队列 |

### 4.2 数据源分级与选择策略

按合规风险从低到高分为三级，优先实现低风险数据源：

#### Tier 1：官方 API / 授权数据集（优先实现，零法律风险）

| 数据源 | 获取方式 | 图片规模 | 适用场景 |
|--------|---------|---------|--------|
| **Unsplash API** | 官方免费 API，CC0 协议 | 300万+ | 自然风景、城市场景 |
| **Flickr API** | 官方 API，可过滤 CC 授权 | 亿级 | 多样化场景，含雾霾图 |
| **Wikimedia Commons** | MediaWiki API | 千万级 | 地理、自然场景 |
| **RESIDE 数据集** | 学术直链下载 | 13990张 | 去雾标准 benchmark |
| **O-HAZE / Dense-Haze** | 学术直链下载 | 百级 | 真实雾图 benchmark |
| **COCO / ImageNet 子集** | 官方下载 | 百万级 | 清晰图底图，用于合成雾图 |

**实现方式**：调用官方 API，无需爬虫，直接 HTTP 请求 + 分页拉取，接入现有任务队列异步执行。

#### Tier 2：遵守 robots.txt 的受控爬取（谨慎实现，需人工审核）

| 数据源 | 说明 | 风险点 |
|--------|------|-------|
| **500px 公开图库** | 允许非商业爬取，需遵守 ToS | 商业使用需授权 |
| **Pixabay** | 有官方 API，但爬取违反 ToS | 优先用官方 API |
| **气象局/环保局公开图片** | 政府数据，通常可公开使用 | 需确认具体条款 |

**实现方式**：Scrapy + 速率限制（≤1 req/s），严格遵守 robots.txt，爬取前人工确认目标站点条款。
