# 预测评估异步化改造方案

> 将模型预测（去雾处理）和效果评估从同步阻塞改为异步任务模式，从根本上解决计算密集型任务的超时问题。

---

## 1. 问题背景

### 1.1 现状

当前预测和评估 API 采用**全链路同步阻塞**模式：

```
Client (SDK 30s) ──HTTP──> Java/Go (RestTemplate 30s) ──HTTP──> Python (实际计算 10s~120s+)
```

POST 请求在 Java/Go 后端阻塞等待 Python 算法服务返回，整个调用链路任何一层超时都会导致请求失败。

### 1.2 问题

| 问题 | 说明 |
|------|------|
| **超时不可预测** | 不同图片尺寸、算法复杂度、硬件性能导致耗时从几秒到几分钟不等，固定超时值无法覆盖所有场景 |
| **连接资源浪费** | HTTP 连接在整个计算期间被占用，高并发时耗尽连接池 |
| **重试放大** | `PythonAlgorithmClient` 配置 3 次重试 + 指数退避，超时触发重试会重新执行整个计算 |
| **用户体验差** | 前端长时间等待无反馈，无法展示进度 |

### 1.3 已有基础设施

系统已具备异步化的基础条件，但未被预测/评估模块利用：

- **日志先于计算保存**：`SysEvalLogServiceImpl` 和 `SysPredLogServiceImpl` 在调用 Python 前先 `save(log)` 拿到 `logId`，POST 时即可返回
- **已有状态查询端点**：`GET /api/v1/prediction/{taskId}` 和 `GET /api/v1/evaluation/{taskId}` 已存在，但目前仅返回部分字段
- **已有线程池**：Java `AsyncConfig.datasetTaskExecutor`（core=4, max=8, queue=50）
- **已有 MQ 基础设施**：三端 RabbitMQ 配置完整，Python 端消费者已完整实现
- **已有任务管理模块**：`sys_task` 表 + 策略模式 + MQ 消费 + 重试/死信/进度追踪，仅用于数据集导出

## 2. 改造目标

```
改造前（同步）：
  POST /prediction  -> [阻塞等待 10s~120s+] -> 返回结果

改造后（异步）：
  POST /prediction  -> 保存日志(status=processing) -> 提交异步任务 -> 立即返回 { logId, status: "processing" }
  GET  /prediction/{taskId} -> 轮询 -> status 为 completed/failed 时返回完整结果
```

### 2.1 设计原则

| 原则 | 说明 |
|------|------|
| **POST 立即返回** | 提交任务后毫秒级响应，不阻塞客户端 |
| **DB 状态追踪** | 日志表增加 `status` 字段，作为任务状态的唯一权威来源 |
| **复用现有线程池** | Java 使用 `datasetTaskExecutor`，Go 使用 goroutine，不引入新依赖 |
| **SDK 内置轮询** | 封装轮询逻辑，调用方使用方式与同步几乎一致 |
| **向前兼容** | 历史日志 `status` 默认为 `completed`，不影响已有数据查询 |

## 5. 后端实现

### 5.1 Java 后端

#### 5.1.1 实体变更

`SysPredLog` 和 `SysEvalLog` 实体新增：

```java
private String status;
private String errorMessage;
```

#### 5.1.2 SysPredLogServiceImpl.predict() 改造

```java
public PredictionResultVO predict(PredictionForm form) {
    // 1. 校验算法
    SysAlgorithm algorithm = algorithmService.getById(form.getAlgorithmId());
    if (algorithm == null) {
        throw new BusinessException(ResultCode.RESOURCE_NOT_FOUND, "算法不存在");
    }

    // 2. 解析图片 URL（同步完成，POST 阶段需要）
    String imageUrl = resolveImageUrl(form);

    // 3. 保存日志，状态为 processing
    SysPredLog predLog = new SysPredLog();
    predLog.setAlgorithmId(form.getAlgorithmId());
    predLog.setOriginFileId(form.getFileId());
    predLog.setOriginUrl(imageUrl);
    predLog.setStatus("processing");
    this.save(predLog);

    // 4. 提交异步任务
    asyncPredict(predLog.getId(), form.getAlgorithmId(), imageUrl, form.getParams());

    // 5. 立即返回
    PredictionResultVO vo = new PredictionResultVO();
    vo.setLogId(predLog.getId());
    vo.setStatus("processing");
    return vo;
}

@Async("datasetTaskExecutor")
public void asyncPredict(Long logId, Long algorithmId, String imageUrl, String params) {
    long startTime = System.currentTimeMillis();
    try {
        JSONObject result = pythonClient.predict(algorithmId, imageUrl, params);
        int elapsed = (int) (System.currentTimeMillis() - startTime);

        SysPredLog update = new SysPredLog();
        update.setId(logId);
        update.setTime(elapsed);
        update.setPredUrl(result.getStr("resultUrl"));
        update.setPredMd5(result.getStr("resultMd5"));
        update.setStatus("completed");
        this.updateById(update);
    } catch (Exception e) {
        int elapsed = (int) (System.currentTimeMillis() - startTime);
        SysPredLog update = new SysPredLog();
        update.setId(logId);
        update.setTime(elapsed);
        update.setStatus("failed");
        update.setErrorMessage(e.getMessage());
        this.updateById(update);
    }
}
```

#### 5.1.3 Controller getTaskStatus() 改造

```java
@GetMapping("/{taskId}")
public Result<PredictionResultVO> getTaskStatus(@PathVariable Long taskId) {
    var predLog = predLogService.getById(taskId);
    if (predLog == null) {
        return Result.failed("预测任务不存在");
    }
    PredictionResultVO vo = new PredictionResultVO();
    vo.setLogId(predLog.getId());
    vo.setStatus(predLog.getStatus());
    if ("completed".equals(predLog.getStatus())) {
        vo.setResultUrl(predLog.getPredUrl());
        vo.setTime(predLog.getTime());
    } else if ("failed".equals(predLog.getStatus())) {
        vo.setErrorMessage(predLog.getErrorMessage());
        vo.setTime(predLog.getTime());
    }
    return Result.success(vo);
}
```

#### 5.1.4 @Async 方法依赖注入问题

`@Async` 方法不能直接在同类中通过 `this` 调用（Spring AOP 代理限制）。解决方案：将异步方法拆到独立的 `PredLogAsyncTask` 类中，通过依赖注入调用。

```java
@Component
@RequiredArgsConstructor
public class PredLogAsyncTask {
    private final SysPredLogService predLogService;
    private final PythonAlgorithmClient pythonClient;

    @Async("datasetTaskExecutor")
    public void execute(Long logId, Long algorithmId, String imageUrl, String params) {
        // ... 异步执行逻辑，更新日志状态
    }
}
```

评估同理，新建 `EvalLogAsyncTask`。

#### 5.1.5 @Async 方法事务问题

`@Async` 方法需要独立事务。在异步方法内部，`updateById` 每次调用都是独立短事务（MyBatis-Plus 默认行为），不需要额外 `@Transactional`。

### 5.2 Go 后端

Go 端使用 goroutine 实现异步，模式与 Java 一致：

```go
func (s *PredictionService) Predict(form *PredictionForm) (*PredictionResultVO, error) {
    // 校验算法、解析 URL ...
    predLog.Status = "processing"
    s.predLogRepo.Create(predLog)

    logId := predLog.ID
    go func() {
        result, err := s.pythonClient.Predict(algorithmId, imageUrl, params)
        if err != nil {
            s.predLogRepo.UpdateStatus(logId, "failed", err.Error(), 0)
        } else {
            s.predLogRepo.UpdateResult(logId, "completed", result.ResultUrl, result.ResultMd5, elapsed)
        }
    }()

    return &PredictionResultVO{LogId: logId, Status: "processing"}, nil
}
```

> Go 端 goroutine 进程重启后丢失，但 DB 中的 `processing` 状态记录仍在，可通过定时任务扫描超时 `processing` 记录标记为 `failed`。

### 5.3 Python 后端

Python 端的预测/评估路由同样改为异步：

```python
@router.post("/api/v1/prediction")
async def predict(form: PredictionForm):
    # 保存日志 status=processing
    pred_log = await pred_log_service.create(form, status="processing")
    # 提交异步任务
    asyncio.create_task(pred_log_service.execute_async(pred_log.id, form))
    return {"logId": pred_log.id, "status": "processing"}
```

> Python 端已有 `TaskTracker` 和 MQ fallback 机制，可直接复用。若 MQ 可用，优先通过 MQ 发布以获得持久化保障。

### 5.4 僵尸任务恢复

服务重启后可能存在 `status=processing` 的僵尸记录。新增定时任务（Java `@Scheduled` / Go cron / Python APScheduler）：

- 每 60 秒扫描 `status='processing' AND update_time < NOW() - INTERVAL 10 MINUTE` 的记录
- 标记为 `status='failed', error_message='任务执行超时，服务可能已重启'`

## 6. SDK 改造 (dehaze-sdk-js)

### 6.1 类型定义变更

```typescript
export type TaskStatus = 'processing' | 'completed' | 'failed';

export interface PredictionResultVO {
  logId: number;
  status: TaskStatus;
  resultUrl?: string;
  resultThumbnailUrl?: string;
  time?: number;
  errorMessage?: string;
}

export interface EvaluationResultVO {
  logId: number;
  status: TaskStatus;
  metrics?: Record<string, number>;
  time?: number;
  errorMessage?: string;
}

export interface PollOptions {
  intervalMs?: number;   // 轮询间隔，默认 2000ms
  timeoutMs?: number;    // 最大等待时间，默认 120000ms
  onPoll?: (status: TaskStatus) => void;  // 每次轮询回调
}
```

### 6.2 ModelAPI 方法变更

```typescript
class ModelAPI {
  // POST 仍返回 PredictionResultVO，但 status 为 "processing"
  async predict(form: PredictionForm): Promise<PredictionResultVO> { ... }

  // GET 查询状态
  async getPredTaskStatus(taskId: number): Promise<PredictionResultVO> { ... }

  // 新增：提交预测并等待结果（封装轮询逻辑）
  async predictAndWait(form: PredictionForm, options?: PollOptions): Promise<PredictionResultVO> {
    const result = await this.predict(form);
    if (result.status !== 'processing') return result;
    return this.pollPredTask(result.logId, options);
  }

  // 轮询预测任务直到终态
  private async pollPredTask(logId: number, options?: PollOptions): Promise<PredictionResultVO> {
    const interval = options?.intervalMs ?? 2000;
    const timeout = options?.timeoutMs ?? 120000;
    const deadline = Date.now() + timeout;
    while (Date.now() < deadline) {
      await sleep(interval);
      const result = await this.getPredTaskStatus(logId);
      options?.onPoll?.(result.status);
      if (result.status === 'completed' || result.status === 'failed') return result;
    }
    throw new Error(`预测任务 ${logId} 超时`);
  }

  // 评估同理
  async evaluateAndWait(form: EvaluationForm, options?: PollOptions): Promise<EvaluationResultVO> { ... }
  private async pollEvalTask(logId: number, options?: PollOptions): Promise<EvaluationResultVO> { ... }
}
```

### 6.3 调用方使用方式

```typescript
// 方式一：自动轮询（推荐，使用方式与同步几乎一致）
const result = await sdk.model.predictAndWait(form, {
  intervalMs: 2000,
  timeoutMs: 120000,
  onPoll: (status) => console.log(`当前状态: ${status}`),
});

// 方式二：手动轮询（需要更细粒度控制时）
const { logId } = await sdk.model.predict(form);
// ... 做其他事
const status = await sdk.model.getPredTaskStatus(logId);
if (status === 'completed') { /* 使用结果 */ }
```

## 11. 风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| `@Async` / goroutine 进程重启丢失任务 | 中 | DB `status=processing` 作为恢复点，定时任务扫描超时记录标记 `failed` |
| 轮询增加服务端压力 | 低 | 默认 2s 间隔，后续可升级为 WebSocket 推送 |
| 前端改造范围大 | 中 | SDK 封装 `predictAndWait`，前端调用方式变化最小 |
| 历史数据兼容 | 低 | `status` 默认 `completed`，历史记录无需迁移 |
