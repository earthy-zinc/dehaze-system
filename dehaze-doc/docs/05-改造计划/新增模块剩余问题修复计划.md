## 剩余问题

### 1. Go/Java 退款失败时订单状态恢复逻辑不一致（原批次4 - 4.9）

**状态**：部分修复

**现状**：渠道退款失败时，订单状态恢复逻辑三端不一致：

| 端 | approveRefund 退款失败 | rejectRefund 拒绝退款 |
|----|----------------------|----------------------|
| Python | 动态：套餐未过期恢复为 `3`(completed)，已过期恢复为 `2`(paid) | 动态：同左 |
| Go | 固定恢复为 `2`(paid) | 动态：套餐未过期恢复为 `3`，已过期恢复为 `2` |
| Java | 固定恢复为 `2`(paid) | 固定恢复为 `2`(paid) |

**问题**：Go 自身的 `RejectRefund` 已使用动态恢复逻辑，但 `ApproveRefund` 退款失败分支未同步。Java 两个方法均固定恢复为 `2`。

**文件**：
- Go `dehaze-go/internal/service/order/order_service.go:721-737`（approveRefund 退款失败分支）
- Java `dehaze-java/.../service/impl/OrderServiceImpl.java:561-565`（approveRefund 退款失败分支）
- Java `dehaze-java/.../service/impl/OrderServiceImpl.java:592-597`（rejectRefund）

**参考**：Python `dehaze-python/app/service/order_service.py:649-655` 的动态恢复逻辑。

**修复**：Go/Java 的 approveRefund 退款失败分支改为动态恢复逻辑，与 Python 和自身的 rejectRefund 保持一致：套餐未过期（`package_expire_time > now`）恢复为 `3`(completed)，已过期恢复为 `2`(paid)。

### 3. Python 消息摘要按 char 截断（原批次6 - 6.15）

**状态**：部分修复

**现状**：
- Java 已改用 `codePoints().toArray()` 按代码点截断（`MessageServiceImpl.java:333-342`）
- Go 已用 `[]rune` 按码点截断（`helper.go:89-95`）
- Python 仍使用 `content[:50]` 按 UTF-16 码元截断（`message_service.py:194,287`），可能截断多字节字符（如 emoji）导致乱码

**修复**：Python 改用代码点截断。可使用 `[c for c in content][:50]`（Python 3 字符串迭代按 Unicode 字符）或 `list(content)` 转 list 后切片。
