# UI/UX 设计规范

## 1. 设计原则

### 1.1 核心设计原则

#### 平台无关性

- 基于 Web 标准技术，确保跨平台一致性
- 使用响应式设计，自适应不同设备和屏幕
- 避免平台特定的 UI 模式，采用通用交互范式
- 通过渐进增强策略，在各平台提供最佳体验

#### 简洁高效

- 界面简洁清晰，避免冗余元素
- 操作流程简短，减少用户学习成本
- 信息层级分明，重点突出
- 单页应用架构，页面切换流畅无刷新

#### 专业可靠

- 专业的视觉呈现，采用现代渐变和阴影系统
- 准确的数据展示，支持多维度指标评估（PSNR、SSIM）
- 可靠的功能体验，完整的错误处理和状态反馈

#### 友好易用

- 符合用户习惯的交互，支持触控和鼠标操作
- 清晰的操作反馈，视觉、触觉多维度反馈
- 友好的错误提示，提供解决方案和重试机制
- 智能设备检测，自动优化交互方式

#### 美观现代

- 现代化的视觉风格，借鉴主流设计语言
- 流畅的动画效果，基于性能分级优化
- 精致的细节处理，圆角、阴影、渐变统一规范

### 1.2 设计目标

| 目标 | 描述 |
|-----|------|
| 效率优先 | 让用户快速完成任务，单页应用架构减少页面跳转 |
| 体验流畅 | 提供流畅的操作体验，60fps 动画性能目标 |
| 信息清晰 | 信息展示清晰易懂，采用卡片式布局和视觉层级 |
| 视觉统一 | 保持视觉风格统一，模块化 CSS 架构确保一致性 |
| 全平台兼容 | 在 Web、iOS、Android、桌面端等平台提供一致体验 |
| 性能优化 | 根据设备性能自动调整动画复杂度和渲染策略 |

### 1.3 可用性原则

- **一致性原则**：统一的视觉风格和交互模式
- **可用性原则**：界面简洁明了，操作流程清晰
- **可访问性原则**：遵循 WCAG 2.1 AA 标准，支持屏幕阅读器
- **响应式原则**：适配不同屏幕尺寸，支持移动端触控操作

## 3. 字体规范

### 3.1 字体家族

#### 统一字体栈

```css
font-family: -apple-system, BlinkMacSystemFont, 'Segoe UI', 
             'PingFang SC', 'Hiragino Sans GB', 
             'Microsoft YaHei', sans-serif;
```

#### 平台回退策略

| 平台 | 字体 | 说明 |
|-----|------|------|
| iOS/Mac | -apple-system (San Francisco) | 苹果系统默认字体 |
| Android | Roboto | 通过 BlinkMacSystemFont 加载 |
| Windows | Segoe UI | 微软系统字体 |
| 中文优先 | PingFang SC → Microsoft YaHei | 中文字体回退链 |
| 通用回退 | sans-serif | 最终回退 |

| 头像 | 50% | 圆形头像 |

### 5.2 阴影规范

| 层级 | 阴影值 | 用途 |
|-----|-------|------|
| Level 1 | 0 2px 8px rgba(0,0,0,0.08) | 卡片、按钮 |
| Level 2 | 0 4px 12px rgba(0,0,0,0.15) | 悬浮卡片、工具栏 |
| Level 3 | 0 8px 24px rgba(0,0,0,0.12) | 对话框、侧边菜单 |
| Level 4 | 0 12px 24px rgba(0,0,0,0.15) | 悬停增强效果 |
| Level 5 | 0 16px 32px rgba(0,0,0,0.16) | 模态框、顶层元素 |

#### 响应式阴影策略

- **移动端**：使用较浅阴影（Level 1-2），避免视觉过重
- **PC 端**：使用较深阴影（Level 2-4），增强层次感
- **悬停效果**：PC 端悬停时阴影加深，提升交互反馈
- **性能优化**：低性能设备减少阴影复杂度

#### 特殊阴影

| 场景 | 阴影值 | 说明 |
|-----|-------|------|
| 底部导航 | 0 -2px 8px rgba(0,0,0,0.1) | 向上投影 |
| 顶部 Header | shadow-lg | 固定定位增强 |

## 7. 交互设计

### 7.1 手势操作

| 手势 | 操作 | 说明 |
|-----|------|------|
| 点击 | 选择、确认 | 单次点击 |
| 双击 | 放大/缩小 | 快速双击 |
| 长按 | 显示菜单 | 长按 1 秒 |
| 滑动 | 滚动、切换 | 单指滑动 |
| 拖动 | 移动元素 | 长按后拖动 |
| 捏合 | 缩放 | 双指捏合 |
| 旋转 | 旋转图片 | 双指旋转 |

### 7.2 反馈机制

#### 视觉反馈

| 状态 | 反馈 |
|-----|------|
| 按钮按下 | 颜色变深 10% |
| 悬停状态 | 显示阴影（PC 端） |
| 禁用状态 | 透明度 50% |
| 选中状态 | 显示选中标识 |

#### 触觉反馈

| 场景 | 反馈类型 | 时长 |
|-----|---------|------|
| 按钮点击 | 轻微震动 | 10ms |
| 长按触发 | 中等震动 | 20ms |
| 操作成功 | 成功震动 | 30ms |
| 操作失败 | 错误震动 | 50ms |

### 7.3 加载状态

#### 加载样式

| 类型 | 特点 | 使用场景 |
|-----|------|---------|
| 全屏加载 | 半透明遮罩 + 居中动画 + 文字提示 | 页面切换、重要操作 |
| 局部加载 | 骨架屏占位 + 小型动画 | 数据加载、列表更新 |
| 进度加载 | 进度条 + 百分比 + 预估时间 | 文件上传、图像处理 |

#### 加载组件使用建议

| 等待时间 | 推荐组件 |
|---------|---------|
| 0-2 秒 | 无需显示 |
| 2-5 秒 | 圆形加载动画 |
| 5-30 秒 | 进度条 + 百分比 |
| 30 秒以上 | 骨架屏 + 进度条 |

#### 空状态

| 类型 | 内容 |
|-----|------|
| 无数据 | 空状态图标 + 提示文字 + 引导按钮 |
| 无网络 | 无网络图标 + 提示文字 + 重试按钮 |
| 错误状态 | 错误图标 + 错误说明 + 解决方案 + 重试按钮 |

### 7.4 提示与通知

#### Toast 提示

- 样式：圆角矩形，半透明背景，白色文字
- 位置：底部居中
- 时长：短提示 2 秒，长提示 3.5 秒
- 用途：操作成功提示、简单错误提示

#### Snackbar 提示

- 样式：底部弹出，可包含操作按钮
- 特点：可手动关闭
- 用途：需要用户操作的提示、可撤销的操作

#### Dialog 对话框

| 类型 | 用途 |
|-----|------|
| 确认对话框 | 删除确认、退出确认 |
| 选择对话框 | 选项选择 |

## 10. 性能优化规范

### 10.1 性能分级策略

#### 性能检测指标

```javascript
const cores = navigator.hardwareConcurrency || 2;
const memory = navigator.deviceMemory || 4;
```

#### 分级标准

| 等级 | 条件 | 优化策略 |
|-----|------|---------|
| 高性能 | PC 端 + 4 核+ + 8GB+ | 完整动画效果 |
| 中等性能 | 2 核+ + 4GB+ | 简化动画 |
| 低性能 | 其他设备 | 最小化动画 |

### 10.2 动画优化

#### 高性能设备

```css
.feature-card {
  transition: all 0.3s cubic-bezier(0.4, 0, 0.2, 1);
}
.feature-card:hover {
  transform: translateY(-8px);
}
```

#### 低性能设备

```css
.reduce-animations * {
  animation-duration: 0.1s !important;
  transition-duration: 0.1s !important;
}
```

### 10.3 加载优化

#### 资源加载策略

- 关键 CSS inline
- 首屏内容优先渲染
- 骨架屏占位
- 延迟加载非关键资源
- 图片懒加载

#### 滚动优化

- 虚拟滚动（大列表）
- 防抖处理
- 节流处理
- 无限滚动分页

### 10.4 响应时间目标

| 操作类型 | 目标时间 | 用户感知 |
|---------|---------|---------|
| 点击反馈 | &lt;100ms | 即时响应 |
| 页面切换 | &lt;300ms | 流畅切换 |
| 数据加载 | &lt;1s | 可接受等待 |
| 图像处理 | &lt;30s | 需要进度提示 |

### 10.5 60fps 动画目标

- 使用 transform 和 opacity
- 避免布局抖动（Layout Thrashing）
- 使用 will-change 提示
- GPU 加速动画
