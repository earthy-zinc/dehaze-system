# 创建型模式

## 工厂方法模式

工厂方法模式定义一个用于创建对象的接口，让子类决定实例化哪一个类。工厂方法使一个类的实例化延迟到其子类实现，目的是使创建对象和使用对象分离。使用者总是引用抽象工厂和抽象产品，而不是具体的类。

假设需要绘制圆形、三角形、长方形等几何物体，首先抽象出一个形状接口，然后让具体几何图形实现该接口，再利用形状工厂创建各个几何图形。

```java
// 创建Shape接口，它是几何图形的抽象，具有draw()绘制图形的方法
public interface Shape {
    void draw();
}

// 创建接口的实现类，几何图形——长方形的具体实现
public class Rectangle implements Shape {
    @Override
    public void draw() {
        System.out.println("绘制长方形的具体方法");
    }
}

// 正方形实现类
public class Square implements Shape {
    @Override
    public void draw() {
        System.out.println("绘制正方形的具体方法");
    }
}

// 圆形实现类
public class Circle implements Shape {
    @Override
    public void draw() {
        System.out.println("绘制圆形的具体方法");
    }
}

// 创建工厂类，负责根据传入的参数创建具体的几何图形对象
public class ShapeFactory {
    public Shape getShape(String shapeType) {
        if (shapeType == null) return null;
        if (shapeType.equalsIgnoreCase("CIRCLE")) {
            return new Circle();
        } else if (shapeType.equalsIgnoreCase("RECTANGLE")) {
            return new Rectangle();
        } else if (shapeType.equalsIgnoreCase("SQUARE")) {
            return new Square();
        }
        return null;
    }
}
```

通过该工厂，调用工厂类的getShape方法并传入想要的几何图形名称，工厂会创建对应的对象。使用接口类型接收返回值，无需为每个具体类分别指定对象类型，提高了扩展性。

```

### 应用场景

1. 日志记录器：程序运行产生的日志可能需要输出到不同的地方，如本地硬盘、系统事件、远程服务器等。通过对这些具体对象抽象出接口，创建工厂类，在记录日志的代码中调用工厂类并传入相应参数，即可指定日志输出位置。

2. 数据库访问：数据库有多种具体实现，如MySQL等。在编写数据库访问类库时，可能不清楚应用程序员最终会使用哪款数据库产品。因此对数据库的各种实现抽象出接口，创建工厂方法，当应用程序员指定数据库时，只需传入数据库名称作为参数，工厂类会创建对应的数据库对象。之后如需更换数据库会更加方便。

### 优点

1. 调用者创建对象时只需知道其名称即可。工厂方法可以管理多个类似对象，创建这些对象无需针对每种类型分别创建，只需用一个接口类型接收，然后调用工厂方法即可。

2. 扩展性高，如需增加产品，只需扩展一个工厂类。

3. 向调用者屏蔽产品的具体实现，调用者不会直接创建子类，而只关心子类依赖的接口。

### 缺点

1. 每增加一个产品时，都需要增加一个具体类和对象工厂，使得系统种类个数过多，增加了系统的复杂度。

工厂方法是一种创建型模式，适用于创建对象。对于有多种类似对象、需要生成复杂对象的场景，可以使用工厂模式。

## 抽象工厂模式

抽象工厂模式是其他工厂的工厂，用于负责创建工厂。在工厂数量变多的情况下，抽象工厂能够帮助在这些工厂中做出选择。

```java
// 之前已经创建过几何图形的抽象类和具体实现类，本次不再赘述

// 为颜色创建接口
public interface Color {
    void fill();
}

// 创建颜色接口的实现类：红、绿、蓝
public class Red implements Color {
    @Override
    public void fill() {
        System.out.println("填充为红色");
    }
}

public class Green implements Color {
    @Override
    public void fill() {
        System.out.println("填充为绿色");
    }
}

public class Blue implements Color {
    @Override
    public void fill() {
        System.out.println("填充为蓝色");
    }
}

// 创建抽象工厂
public abstract class AbstractFactory {
    public abstract Color getColor(String color);
    public abstract Shape getShape(String shape);
}

// 创建抽象工厂的具体实现类，用来创建具体的实体对象
public class ShapeFactory extends AbstractFactory {
    @Override
    public Shape getShape(String shapeType) {
        if (shapeType == null) {
            return null;
        }
        if (shapeType.equalsIgnoreCase("CIRCLE")) {
            return new Circle();
        } else if (shapeType.equalsIgnoreCase("RECTANGLE")) {
            return new Rectangle();
        } else if (shapeType.equalsIgnoreCase("SQUARE")) {
            return new Square();
        }
        return null;
    }
    
    @Override
    public Color getColor(String color) {
        return null;
    }
}

public class ColorFactory extends AbstractFactory {
    @Override
    public Shape getShape(String shapeType) {
        return null;
    }
    
    @Override
    public Color getColor(String color) {
        if (color == null) {
            return null;
        }
        if (color.equalsIgnoreCase("RED")) {
            return new Red();
        } else if (color.equalsIgnoreCase("GREEN")) {
            return new Green();
        } else if (color.equalsIgnoreCase("BLUE")) {
            return new Blue();
        }
        return null;
    }
}

// 创建工厂的工厂——根据传入的参数决定具体创建哪一个工厂类
public class FactoryProducer {
    public static AbstractFactory getFactory(String choice) {
        if (choice.equalsIgnoreCase("SHAPE")) {
            return new ShapeFactory();
        } else if (choice.equalsIgnoreCase("COLOR")) { 
            return new ColorFactory();
        }
        return null;
    }
}
```

应用程序员可以通过调用工厂创建者创建对应工厂，再通过工厂创建相关产品。

## 建造者模式

使用多个简单的对象一步步构建成一个复杂的对象，通过一个Builder类实现。

例如食物套餐类Meal的创建需要Item对象逐层参与，可以使用MealBuilder类逐步创建最终需要的meal对象。

```java
// 创建表示食品条目和食品包装的接口
public interface Item {
    public String name();
    public Packing packing();
    public float price();
}

public interface Packing {
    public String pack();
}

// 创建实现包装接口的实现类
public class Wrapper implements Packing {
    @Override
    public String pack() {
        return "已用纸盒包装";
    }
}

public class Bottle implements Packing {
    @Override 
    public String pack() {
        return "已用瓶子包装";
    }
}

// 创建食品Item接口的抽象类
public abstract class Burger implements Item {
    @Override 
    public Packing packing() {
        return new Wrapper();
    }
    
    @Override
    public abstract float price();
}

public abstract class ColdDrink implements Item {
    @Override
    public Packing packing() {
       return new Bottle();
    }
 
    @Override
    public abstract float price();
}

// 创建扩展了Burger和ColdDrink的实体类
public class VegBurger extends Burger {
    @Override
    public float price() {
        return 25.0f;
    }
    
    @Override 
    public String name() {
        return "蔬菜汉堡";
    }
}

public class ChickenBurger extends Burger {
    @Override
    public float price() {
        return 50.5f;
    }
    
    @Override
    public String name() {
        return "鸡肉汉堡";
    }
}

public class Coke extends ColdDrink {
    @Override
    public float price() {
        return 30.0f;
    }
    
    @Override 
    public String name() {
        return "可乐";
    }
}

public class Pepsi extends ColdDrink {
    @Override
    public float price() {
        return 35.0f;
    }
 
    @Override
    public String name() {
        return "百事可乐";
    }
}

// 创建Meal类，包含定义的Item对象
public class Meal {
    private final List<Item> items = new ArrayList<Item>();
    
    public void addItem(Item item) {
        items.add(item);
    }
    
    public float getCost() {
        float cost = 0.0f;
        for (Item item : items) {
            cost += item.price();
        }
        return cost;
    }
    
    public void showItems() {}
}

// 创建Builder类，负责创建Meal对象
public class MealBuilder {
    public Meal prepareVegMeal() {
        Meal meal = new Meal();
        meal.addItem(new VegBurger());
        meal.addItem(new Coke());
        return meal;
    }
    
    public Meal prepareNonVegMeal() {
        Meal meal = new Meal();
        meal.addItem(new ChickenBurger());
        meal.addItem(new Pepsi());
        return meal;
    }
}
```

通过Builder类可以创建Meal对象，而无需手动组装。

### 优点

1. 建造者Builder独立，易于扩展

### 缺点

1. 产品必须有共同点，范围有限制

## 原型模式

原型模式适用于创建重复的对象，同时保证性能。用原型实例指定创建对象的种类，并且通过拷贝这些原型创建新的对象。也就是说在创建新对象时，需要根据现有的原型来创建。

```java
@Getter
public abstract class Shape implements Cloneable {
    private String id;
    protected String type;
    
    abstract void draw();
    
    public void setId(String id) {
        this.id = id;
    }
    
    public Object clone() {
        Object clone = null;
        try {
            clone = super.clone();
        } catch (CloneNotSupportedException e) {}
        return clone;
    }
}

// 创建实现了Shape抽象类的实体类：长方形、正方形、圆形
// 创建一个从数据库获取的实体类，并存储在HashTable中
public class ShapeCache {
    private static final Hashtable<String, Shape> shapeMap = new Hashtable<>();
    
    public static Shape getShape(String shapeId) {
        Shape cachedShape = shapeMap.get(shapeId);
        return cachedShape.clone();
    }
    
    public static void loadCache() {
        Circle circle = new Circle();
        circle.setId("1");
        shapeMap.put(circle.getId(), circle);
    }
}
```

使用一个特定的原型实例指定创建什么样的对象，并且通过拷贝这些原型对象创建新的对象，新对象和原型对象是一样的。

当系统应该独立于产品创建、构成和表示时；当要实例化的类是在运行时指定时；为避免创建一个与产品类层次平行的工厂类层次时，可以利用已有的原型对象快速生成和原型对象一样的实例。

具体操作是实现克隆操作，在Java中实现Cloneable接口，重写clone()方法。

### 应用场景

1. 资源优化场景
2. 类的初始化需要消耗非常多的资源，包括数据、硬件资源等
3. 性能和安全要求的场景
4. 通过new产生一个对象需要非常繁琐的数据准备或者访问权限
5. 一个对象有多个修改者
6. 一个对象需要提供给其他对象访问，并且各个调用者可能都要修改其值
7. 浅拷贝通过实现Cloneable接口，深拷贝需要实现Serializable接口读取二进制流

## 单例模式

单例模式确保一个类只有一个实例，并提供一个全局访问点。该类负责创建自己的对象，同时确保只有单个对象被创建，可以直接访问该唯一对象而无需实例化类。

```java
// 饿汉式实现
public class SingleObject {
    private static final SingleObject instance = new SingleObject();
    
    private SingleObject() {}
    
    public static SingleObject getInstance() {
        return instance;
    }
}
```

通过类的getInstance方法获取这个类的唯一可用对象，并调用对象的方法。

### 单例模式的实现方式

#### 懒汉式（线程不安全）

```java
public class Singleton {
    private static Singleton instance;
    private Singleton() {}
    
    public static Singleton getInstance() {
        if (instance == null) instance = new Singleton();
        return instance;
    }
}
```

#### 懒汉式（线程安全）

在getInstance方法中添加synchronized关键字，第一次调用时才初始化，可以避免内存浪费。

#### 饿汉式

常用实现方式，但容易产生垃圾对象。
